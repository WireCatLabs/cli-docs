# Homepage exploration contract

Mode: Persuade. Goal: help existing AI-agent users start using tg/max. User explicitly requested six built variants, with local URLs for comparison. All six are built directly in HTML/CSS/JavaScript within the existing WireCat visual system; selecting one direction or generating raster comps is unnecessary for this exploration.

Established visual language: the WireCat monogram, purple accent, pale green light surface, dark green alternative, self-hosted Unbounded display type and Onest body. The preview navigation is separate from product navigation. Each page has a complete ending and a concrete setup path. No fabricated customer numbers, benchmarks or testimonials.

| Approach | First viewport | Signature interaction | Content order |
|---|---|---|---|
| Direct | Concrete Telegram/MAX headline alongside a completed contextual draft | Find/brief/reply example tabs with evidence | Hero demo, outcomes, audiences, control, extended workflow, setup, FAQ |
| Memory | Centered memory promise and recognizable things people forget | Meaning-oriented retrieval example with inspectable message | Hero, retrieval evidence, actions, control, audiences, setup |
| Context | Large context promise leading into source fragments and a useful brief | Brief/reply transition retains source evidence | Hero mechanism, outcomes, brief demo, audiences, extended workflow, control, setup |
| Audiences | Three audience names and a compact equal overview | Each audience selects its own corresponding example | Hero, audience overview, three example types, control, admin detail, setup, FAQ |
| Workflow | Messaging as the start of a broader connected workflow | Four stages: messages, email, note, follow-up | Hero, workflow stages, explanation, audiences, control, setup |
| Minimal | Short ask-led promise and agent compatibility | Three compact examples, with sources expandable | Hero, demo, three concise reasons, setup |

Motion: one brief change-of-result transition for demonstration panels; reduced motion disables it. Content is visible without entrance animations. Tabs support arrows/Home/End and update selected state. Copy actions confirm success or provide a readable fallback. Theme choice persists locally. Installation choices update both command and guide destination.

Product boundaries: local archive is distinct from model processing. Semantic search requires builds and embeddings. A bot's access differs from a personal account. Monitoring and recurring tasks require configuration. Himalaya is the third-party email CLI, and Obsidian is the existing notes tool. The previews show illustrative results and never invoke live messaging actions.

Preview server: http://localhost:4325, loopback only, noindex. Production landing files are outside this exploration's write scope.
