Подключите свой сайт на WordPress один раз, и дальше ИИ-агент читает ваши посты и пишет новые черновики, а вам не
нужно открывать wp-admin. WordPress пускает программу только по паролю приложения, который вы создаете в своем
профиле. Создать пароль, установить `wordpress` и войти можно примерно за пять минут.

Когда все готово, агент на этом компьютере читает ваши посты и страницы, когда вы просите, и пишет черновики в
пределах ваших разрешений.

## Что нужно

- Свой сайт на WordPress версии 5.7 или новее, открытый по https. Только там WordPress создает пароли приложений.
  Сайты на WordPress.com не поддерживаются.
- Пользователь на сайте. Для полной копии это должен быть администратор. Редактор получает все посты и страницы, но
  всех пользователей и их e-mail WordPress отдает только администратору: редактор получает авторов с опубликованными
  постами. Автор или участник получает только свои посты и не получает страниц: WordPress не отдает им список
  страниц. Участник получает только свои черновики и посты на проверке.
- Для командной строки: Node.js 22.16 или более поздний 22.x, либо Node.js 24 и новее. Node 23 не поддерживается.

## В WireCat Desktop

1. Создайте пароль приложения, как показано в разделе
   [создайте пароль приложения в WordPress](#make-an-application-password-in-wordpress).
2. На странице **Инструменты** нажмите **Установить** в строке WordPress.
3. Нажмите **Управление**, введите имя аккаунта, например `blog`, и нажмите **Войти здесь**.
4. Заполните **Адрес сайта**, **Имя пользователя** и **Пароль приложения**. Desktop проверяет их на вашем сайте,
   прежде чем сохранить.

Desktop еще и дает вашим ИИ-агентам навык инструмента, так что шаги в терминале не нужны.

## Установите инструмент

Установите `wordpress` один раз на каждый компьютер, где с ним работаете вы или агент.

```sh
npm install -g @wirecat/wordpress-cli
wordpress --version
wordpress skill install   # the agent skill, for Claude Code, Codex, Gemini CLI and OpenClaw
wordpress doctor
```

Команда называется `wordpress`, а не `wp`: `wp` уже занята официальным WP-CLI, и оба инструмента могут стоять на
одном компьютере.

`doctor` не ходит в сеть и не открывает связку ключей. Он показывает версию, где лежат настройки, какие есть профили
и могут ли другие пользователи компьютера читать настройки.

Агент без терминала, например Claude Desktop или Cursor, работает с `wordpress` через [MCP](./mcp.md), а не через
навык.

## Создайте пароль приложения в WordPress

WordPress описывает эти шаги в своем
[руководстве по паролям приложений](https://make.wordpress.org/core/2020/11/05/application-passwords-integration-guide/).

1. Войдите в wp-admin своего сайта.
2. Откройте **Пользователи → Профиль**, а если вы не администратор, **Профиль**.
3. Прокрутите до раздела **Пароли приложений**.
4. Введите имя нового пароля, например `WireCat`, и нажмите **Добавить новый пароль приложения**.
5. Скопируйте пароль, который покажет WordPress. Он показывает его только один раз.

Пароль может то же, что ваш пользователь, и не больше. Он работает, пока вы не отзовете его там же.

Если раздела нет, сайт открыт не по https, или пароли приложений выключил плагин или хостинг. Спросите
администратора сайта.

## Войдите

Профиль это имя, которое вы выбираете для одного сайта и одного пользователя, например `blog`. Оно стоит первым
словом в каждой команде, которой нужен аккаунт. Ни одна команда не выбирает профиль за вас.

```sh
wordpress blog session start --site blog.example.com --login anna
```

`--site` это адрес вашего сайта, с `https://` или без. `--login` это ваше имя пользователя в WordPress. `wordpress`
спрашивает пароль приложения, не показывая его, проверяет его на вашем сайте и сохраняет вместе с сайтом в связке
ключей системы. Пароль, который сайт не принял, не сохраняется. Пароль уходит только на этот сайт и никогда на
другой сайт того же хостинга.

На компьютере без связки ключей добавьте `--credential-storage file`, чтобы хранить пароль в закрытом файле. Агент
или скрипт может передать пароль через stdin. Пароль никогда не передается аргументом, поэтому он не попадает в
историю команд.

## Проверьте, что все работает

```sh
wordpress blog session status --check   # asks your site whose password it is
wordpress blog sync                     # copies your posts, pages, tags and authors
wordpress blog posts list status:draft
```

Первая синхронизация читает все посты и страницы, поэтому на большом сайте она идет долго. Следующие читают только
изменения. Если что-то не работает, смотрите [если что-то не работает](./troubleshooting.md).

## Выйдите или смените пароль

```sh
wordpress blog session end
```

`session end` забывает пароль на этом компьютере. Сам пароль работает на вашем сайте, пока вы его не отзовете:
Пользователи → Профиль → Пароли приложений, **Отозвать**. Чтобы сменить пароль, снова выполните `session start` с
новым паролем.
