Найдите пост, напишите черновик или запланируйте его одной короткой командой, той же, которую выполняет ваш агент.
API WordPress говорит числовыми номерами, сырой разметкой блоков и кодами статусов, а `wordpress` дает вам вместо
этого Markdown и понятные слова статусов.

Посты прошлого месяца, забытый черновик или текст страницы вы находите одной строкой. Агент делает то же по вашей
просьбе.

Каждая команда начинается с профиля, имени, которое вы дали входу на один сайт. `sync` копирует ваши посты и страницы
в локальное хранилище WireCat, где их находят команды чтения. Нужен профиль, в который выполнен вход:
[установка](./installation.md) его настраивает.

## Профиль идет первым

Профиль это имя, которое вы выбираете для одного сайта и одного пользователя. Оно стоит первым словом в каждой
команде, которой нужен аккаунт:

```sh
wordpress blog config show
```

`WCWP_PROFILE=blog` делает то же для одного сеанса оболочки. Профиль никогда не подставляется сам, даже
единственный: команда без него останавливается с кодом выхода 2 и показывает профили на этом компьютере. Два сайта
это два профиля, у каждого свой пароль.

## Синхронизация

Команды чтения отвечают по локальному хранилищу WireCat. `sync` обновляет его:

```sh
wordpress blog sync              # what changed since the last sync
wordpress blog sync --rescan     # everything again, dropping a sync that stopped half way
```

`sync` копирует посты и страницы с любым статусом (опубликованные, запланированные, черновики, на утверждении,
личные и в корзине), метки и рубрики, а также пользователей, которые пишут. Текст поста хранится в Markdown. Первая
синхронизация читает все. Следующие спрашивают у WordPress только посты, измененные с прошлого раза. Раз в день
синхронизация также находит посты, которые сайт удалил навсегда. Пост в корзине остается в копии со своим статусом.

Синхронизация может закончиться неполной и все равно пройти успешно: она называет каждый пробел. При входе автора
или участника WordPress не отдает список страниц, поэтому посты остаются неполными, и изменения на сайте не доходят
до копии. Участник к тому же видит только свои посты. Список пользователей получает только администратор, поэтому в
копии редактора есть все посты и страницы, но нет пользователей. Для полной копии войдите как администратор.

`--max-pages` ограничивает число запросов за один запуск. Следующая синхронизация продолжит с того места, где эта
остановилась.

## Чтение постов и страниц

```sh
wordpress blog posts list status:draft
wordpress blog posts list type:page
wordpress blog posts list status:published "published:[2026-10-01 TO 2026-10-31]"
wordpress blog posts list tag:12 author:3
wordpress blog posts search "pricing change"
wordpress blog posts show 41
```

`posts list` показывает сначала последние изменения. Он отбирает по этим полям:

| Поле | Значения | Пример |
|---|---|---|
| `status` | `draft`, `pending`, `scheduled`, `published`, `private`, `trashed` | `status:scheduled` |
| `type` | `post` или `page` | `type:page` |
| `tag` | номер метки или рубрики, как его показывает `tags list` | `tag:12` |
| `author` | номер пользователя, как его показывает `users list` | `author:3` |
| `published` | время, промежуток или `>`, `>=`, `<`, `<=` и время | `published:>=2026-01-01` |

Условия соединяются через AND. `--limit` и `--page` листают длинный список.

`posts search` находит посты по словам заголовка и текста. Должно совпасть каждое слово, и начало слова из трех букв
и длиннее тоже совпадает. `posts show` дает один пост с текстом в Markdown, авторами и метками по именам и его
прежними версиями.

`posts stats` показывает числа поста такими, какими их прочитала каждая синхронизация. WordPress сам не ведет
счетчики просмотров, поэтому для сайта на WordPress показывать почти нечего.

`--offline` отвечает по копии и никогда не подключается к сайту.

## Метки и авторы

```sh
wordpress blog tags list       # tags and categories, with their ids
wordpress blog users list      # the users who write
wordpress blog channels list   # the site this profile copies
```

`posts create --tags` и фильтр `tag:` принимают номера, которые показывает `tags list`. `users list` также называет
человека, которого хранилище знает по тому же адресу почты из других ваших инструментов WireCat.

## Черновик

```sh
wordpress blog posts create --title "Version 3" --text-file notes.md --description "What changed" --tags 12,14
cat notes.md | wordpress blog posts create --title "Version 3" --text-file -
wordpress blog posts update 63 --title "Version 3 is out"
wordpress blog posts update 63 --text-file notes-v2.md --slug version-3
```

`posts create` всегда создает черновик. Публикация это отдельный шаг. Текст пишется в Markdown, из файла или из
stdin с `--text-file -`. `--description` задает отрывок, короткий текст, который показывают списки. `--tags`
принимает номера меток и рубрик и заменяет те, что были у поста. `--slug` это последняя часть адреса поста.

`posts update` меняет поля, которые вы назвали. Изменение опубликованного или запланированного поста видно всем,
поэтому команда проверяет и `posts.publish`.

## Публикация

```sh
wordpress blog posts publish 63                                # now
wordpress blog posts publish 63 --at-time 2026-12-01T09:00:00Z  # at that time
wordpress blog posts publish 63 --at-time 3d                    # in three days
wordpress blog posts unpublish 63                              # back to a draft
wordpress blog posts delete 63                                 # to the trash
wordpress blog posts delete 63 --allow-delete                  # for good, past the trash
```

`--at-time` принимает время в ISO 8601, день или срок от текущего момента, например `3d`. Время должно быть в
будущем. Уже опубликованный пост нельзя запланировать: сначала снимите его с публикации. Пост из корзины
восстанавливается в корзине в wp-admin. `--allow-delete` удаляет пост навсегда и проверяет ключ `posts.delete.force`.

В терминале каждое изменение сначала спрашивает. Смотрите [разрешения](./permissions.md).

## Когда изменение останавливается

- **Пост поменяли на сайте.** Перед изменением `wordpress` сравнивает версию поста с копией. Если кто-то поменял его
  на сайте после последней синхронизации, изменение останавливается с `content.conflict`. Выполните `sync`,
  посмотрите на пост еще раз и повторите.
- **В посте есть блоки, которые Markdown не сохранит.** Галереи, колонки, встраивания и iframe не переживают
  перевод в Markdown. Такой пост помечается как теряющий разметку, и `posts update` отказывается писать его текст с
  `content.lossy-body`. Заголовок, отрывок, метки и статус по-прежнему можно менять. Чтобы все равно записать текст и
  упростить эти блоки, добавьте `--replace-body`.

## API WordPress

`wordpress blog api` выполняет любую операцию REST API WordPress (`wp/v2`), по команде на каждую, со своими флагами и
справкой. Так вы достаете то, у чего нет своей команды: медиафайлы, комментарии, меню, пользователей, настройки и
другое. В группе 147 операций, взятых из чистого WordPress 6.9.4.

```sh
wordpress blog api list                               # every operation, without calling WordPress
wordpress blog api show postWpV2PostsById             # one operation's parameters and body
wordpress blog api media-list                         # the media library
wordpress blog api posts-update --id 63 --body '{"sticky":true}'
```

Изменение принимает тело запроса в JSON в `--body` или из файла через `--body-file`. Полей плагинов, например
SEO-плагинов или плагинов произвольных полей, нет в описании API, поэтому их отправляют в сыром `--body`. Пакетный
маршрут WordPress никогда не предлагается. Что нужно каждому изменению, описано в [разрешениях](./permissions.md).

## Вывод для скриптов

Каждая команда, кроме `mcp serve` на stdin и stdout, принимает `--json` и печатает одно значение JSON в stdout.
`--json=external_id,title` оставляет только эти поля. Ошибки приходят в JSON в stderr, с кодом и причиной, по
которым можно ветвиться. Коды выхода перечислены в [справочнике команд](./commands.md).

## Агенты

`wordpress skill install` кладет навык инструмента туда, где его ищут Claude Code, Codex, Gemini CLI и OpenClaw.
`wordpress skill install --for hermes` также добавляет эту папку в собственные настройки Hermes Agent, так что
простой `skill install` Hermes не затрагивает.

Агент с терминалом после этого сам запускает `wordpress`. Просите обычными словами:

> *"Используй wordpress. Какие черновики я не трогал уже месяц?"*
> *"Используй wordpress. Сделай черновик из notes.md с меткой release."*
> *"Используй wordpress. Что наша страница О нас говорит о ценах?"*

Для Claude Desktop, Cursor, ChatGPT и других приложений, которые не умеют запускать команды,
`wordpress blog mcp serve` отдает те же команды через MCP. Через MCP изменение с уровнем `ask` выполняется,
публикация тоже. Смотрите [MCP](./mcp.md).
