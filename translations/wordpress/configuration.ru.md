title: "Настройки"

Меняйте, как `wordpress` работает для одного сайта или для всех сайтов на этом компьютере, одной командой и
смотрите, откуда взялось каждое значение. Вы меняете только то немногое, что важно вам, а остальное остается по
умолчанию.

Вы решаете, например, что агент может публиковать, сколько элементов показывает список или сохраняет ли запуск
слова, которые вы ввели. Ослабить разрешение можете только вы: агенту, который пытается это сделать, отказывают.

Настройки лежат в одном файле, `config.json`, в папке, которую показывает `wordpress doctor`. У каждого профиля своя
часть, а `defaults` действуют на все профили. `wordpress blog config` показывает и меняет их, где `blog` это
профиль, имя, которое вы выбрали.

## Посмотреть и поменять настройку

```sh
wordpress blog config show
wordpress blog config set limit 50
wordpress blog config unset limit
```

`config show` перечисляет каждую настройку с ее значением и тем, откуда оно взялось: из файла, из переменной или по
умолчанию. Самые частые:

| Настройка | По умолчанию | Что делает |
|---|---|---|
| `limit` | `20` | Сколько элементов за раз показывает список группы `api`. `posts list`, `tags list` и `users list` показывают 50, передайте `--limit`. |
| `permissions` | не задано | Что может делать каждая команда. Смотрите [Разрешения](#permissions). |
| `record` | `true` | Сохранять каждый запуск. `false` сохраняет только неудачные. |
| `record_input` | `true` | Сохранять слова, которые вы ввели при запуске. |
| `keep_runs_for_days` | `30` | Сколько хранится запуск. |
| `keep_successful_runs_for_days` | `7` | Сколько хранится запуск, который удался. |
| `update_check` | `true` | Раз в день проверять, нет ли новой версии. |

## Разрешения

`permissions` решает, что команда может делать для этого профиля: `allow`, `ask`, `readonly` или `deny`, для каждого
ключа разрешения. Каждое изменение `posts` по умолчанию стоит на `ask`. Через MCP `ask` не спрашивает: изменение
выполняется, публикация тоже. Ключи, их встроенные уровни и то, как оставить публикацию за собой, описаны на странице
[Разрешения](./permissions.md).

```sh
wordpress blog config set permissions.posts.publish deny
```

## Переменные

| Переменная | Что делает |
|---|---|
| `WCWP_PROFILE` | Профиль для этой оболочки вместо первого слова. |
| `WCWP_READ_ONLY` | `1` отклоняет любое изменение. |
| `WCWP_CONFIG_DIR`, `WCWP_STATE_DIR` | Переносят настройки или состояние в другую папку. |

`wordpress blog session status` говорит, откуда взят пароль: из связки ключей или из файла, но никогда не показывает
сам пароль.

## Записи запусков

Команда, которая не удалась, сохраняется как запуск, для `wordpress runs list` и `runs show`. Команда, которая
обращается к WordPress, например `sync`, изменение `posts`, операция `api` или `session status --check`, сохраняется
и при успехе, если только `record` не равен `false` (тогда сохраняются только неудачи) или она не запущена с
`--no-record`. `record_input` решает, сохраняет ли запуск слова, которые вы ввели. Секреты скрываются в любом случае.
Смотрите [Безопасность](./security.md#run-records).
