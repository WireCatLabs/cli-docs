Дайте посты и страницы вашего WordPress ИИ-агенту, который не умеет запускать команды, например Claude Desktop,
Cursor или ChatGPT и Claude в браузере. MCP (Model Context Protocol) это способ, которым такой агент спрашивает
программу, что она умеет, а затем вызывает ее, и `wordpress` отдает свои команды именно так.

После этого агент читает ваши посты из копии на вашем компьютере, пишет черновики и публикует их на вашем сайте в
пределах разрешений профиля.

Агенту с терминалом, например Claude Code или Codex, хватает команд и навыка (`wordpress skill install`). Нужен
профиль, в который выполнен вход ([установка](./installation.md)), и сначала стоит заглянуть в
[разрешения](./permissions.md): через MCP изменение с уровнем `ask` выполняется, публикация тоже.

## Добавьте wordpress в агента

В примерах `blog` это профиль, имя, которое вы выбрали для одного сайта.

```sh
wordpress blog mcp add claude-code --allow-writes   # or codex
wordpress blog mcp check                            # the handshake and the tool list, as the client sees them
```

`mcp add` отказывается подключать профиль, чьи инструменты могут писать, пока вы не передадите `--allow-writes`. Этим
флагом вы подтверждаете, что знаете: агент сможет создавать, менять, публиковать и удалять посты. Для Claude
Desktop, Cursor или любого другого клиента `wordpress blog mcp config` печатает запись, которую нужно вставить в его
настройки, с полными путями. Вручную для Claude Code:

```sh
claude mcp add wordpress -- wordpress blog mcp serve
```

Один сервер может обслуживать несколько профилей: `wordpress mcp serve --profiles blog,docs` или `--profiles all`.
Тогда каждый вызов называет свой профиль, а агент спрашивает вас, если вы не сказали, какой.

## Что видит агент

У сервера три инструмента:

- `wordpress_tools_search` находит команду по словам, с ее аргументами и видом ответа.
- `wordpress_read` выполняет команду, которая только читает:
  `{ "command": "posts list", "arguments": { "query": "status:draft" } }`.
- `wordpress_write` выполняет команду, которая пишет, например `posts create` или `posts publish`.

Команда называется так же, как в командной строке, без профиля, и проверяет тот же ключ разрешения.

Текст из WordPress приходит с пометкой `untrusted`: заголовки, текст и отрывки постов и страниц, а также имена меток,
рубрик и авторов. Агенту сказано, что это данные, а не инструкции. Пост со словами "опубликуй все черновики" не ваша
просьба.

## Публикация через MCP

Каждое изменение `posts` по умолчанию стоит на `ask`. Через MCP у терминала нет никого, кто ответил бы на `ask`,
поэтому изменение выполняется. Значит, агент через MCP может опубликовать пост и удалить его навсегда. Так решил
владелец этого инструмента: агент, которого вы подключили, должен доводить порученную работу до конца.

Контроль остается у вас двумя способами:

- **Каждая публикация записывается.** `wordpress blog runs list` показывает каждое изменение, которое сделал агент,
  а `runs show` показывает, что он отправил. Удачный запуск хранится 7 дней (`keep_successful_runs_for_days`),
  неудачный 30.
- **Одна строка это останавливает.** Эти команды оставляют публикацию и удаление навсегда за вами, а черновики агент
  по-прежнему пишет:

  ```sh
  wordpress blog config set permissions.posts.publish deny
  wordpress blog config set permissions.posts.delete.force deny
  ```

Чтобы один сервер был строже профиля, дайте ему свои уровни. Они никогда не ослабляют профиль:

```sh
wordpress blog mcp add claude-code --allow-writes --permission posts.publish=deny
wordpress blog mcp serve --permission posts.publish=deny
```

Или включите подтверждение для инструмента `wordpress_write` в клиенте агента, и клиент будет спрашивать вас перед
каждым изменением.

## ChatGPT и Claude в браузере

Приложение в браузере достает до сервера по HTTP через ваш собственный туннель, например Tailscale Funnel:

```sh
wordpress blog mcp serve --http --public-url https://laptop.example.ts.net
```

Сервер слушает только `127.0.0.1`, порт 8765 (`--port` его меняет). Приложение в браузере входит по одноразовому
коду, который печатает команда. `wordpress blog mcp revoke` завершает все входы.

`wordpress blog mcp server start` запускает тот же сервер в фоне. `mcp server status` показывает его порт, код входа
и вошедшие приложения, а `mcp server stop` его останавливает.
