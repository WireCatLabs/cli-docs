Верните `wordpress` в рабочее состояние по симптому, который вы видите. Чаще всего сбой идет от пароля приложения,
вашей роли в WordPress или разрешений профиля, и для каждой причины есть проверка, которая ее называет.

Найдите свой симптом в таблице, выполните проверку, которую она дает, и повторите команду. Если не помогло, у вас уже
готовы код ошибки и имя профиля для обращения в поддержку.

**На этой странице:**

2. [Симптомы и что делать](#symptoms-and-what-to-do)

## Первые проверки

В примерах `blog` это профиль, имя, которое вы выбрали для одного сайта.

```sh
wordpress doctor                         # the version, the settings, the profiles, without the network
wordpress blog session status --check    # asks your site whose password it is
```

## Симптомы и что делать

| Симптом | Что делать |
| --- | --- |
| Непонятно, что настроено | Выполните `wordpress doctor`. Он не читает связку ключей и не ходит в сеть. |
| `wordpress` не находится | Откройте новый терминал и проверьте, что глобальная папка npm есть в `PATH`. |
| Вы ввели `wp` | Это официальный WP-CLI. Этот инструмент называется `wordpress`. |
| "name a profile" | Поставьте профиль первым, как в `wordpress blog config show`, или задайте `WCWP_PROFILE`. |
| "not signed in" | Выполните `wordpress blog session start --site blog.example.com --login anna` со своим сайтом и именем пользователя. Смотрите [вход](./installation.md#sign-in). |
| Сайт не принимает пароль | Пароль отозван, введен с ошибкой или принадлежит другому пользователю. Создайте новый ([как](./installation.md#make-an-application-password-in-wordpress)) и снова выполните `session start` с правильным `--login`. |
| В профиле нет раздела **Пароли приложений** | Сайту нужен WordPress 5.7 или новее по https, а раздел может выключить плагин или хостинг. Спросите администратора сайта. |
| Адрес на WordPress.com | Сайты на WordPress.com не поддерживаются, только свой WordPress. |
| `posts list` пуст | Сначала выполните `wordpress blog sync`. Посты читаются из копии, которую он делает. |
| `sync` заканчивается неполной или нет страниц | Автор или участник не может получить список страниц, а участник видит только свои посты. Список пользователей получает только администратор. Для полной копии войдите как администратор, а для всех постов и страниц как редактор. |
| Изменения на сайте нет в копии | Выполните `sync`. Если она все равно неполная, смотрите предыдущую строку. |
| `content.conflict` | Пост поменяли на сайте после последней синхронизации. Выполните `sync`, посмотрите на пост еще раз и повторите. |
| `content.lossy-body` | В посте есть галереи, колонки, встраивания или iframe, которые Markdown не сохранит. Меняйте только заголовок, отрывок, метки или статус либо добавьте `--replace-body`, чтобы все равно записать текст и упростить эти блоки. Смотрите [когда изменение останавливается](./usage.md#when-a-write-stops). |
| `content.schedule-past` | Время в `--at-time` должно быть в будущем. |
| `content.already-published` | Опубликованный пост нельзя запланировать. Сначала выполните `posts unpublish`. |
| `content.empty` | Изменение не называет ни одного поля. Добавьте `--title`, `--text-file` или другое поле. |
| `posts publish` падает с `permission_error` (WordPress ответил HTTP 403) | Вашей роли в WordPress нельзя публиковать. Участник не может. Попросите редактора или войдите как редактор. |
| `posts stats` не показывает просмотров | WordPress сам не ведет счетчики просмотров, а статистика Jetpack не поддерживается. |
| У поля плагина, например SEO-заголовка, нет флага | Полей плагинов нет в описании API. Отправьте их в сыром `--body` через `wordpress blog api`. |
| Файл настроек не читается | `doctor` перечисляет каждую проблему в файле под `config.issues`. Выполните `config unset`, который дает каждая из них, или исправьте файл вручную. |
| `doctor` показывает `files.problems` | Другие пользователи компьютера могут читать `config.json` или заходить в его папку. Выполните каждую команду `chmod`, которую `doctor` печатает после "to make it private:". Сам `doctor` никогда не меняет права файлов. |
| "the OS keyring did not answer" | На компьютере не запущена связка ключей. Войдите с `--credential-storage file`. |
| Изменение отклонено | Его останавливают разрешения профиля или `WCWP_READ_ONLY`. Смотрите [разрешения](./permissions.md). |

## Как попросить помощи

Спросите в [Discord](https://discord.gg/DebENqbRrJ) или откройте
[issue](https://github.com/WireCatLabs/wordpress-cli/issues) с кодом ошибки, именем профиля и командой. Никогда не
вставляйте в обращение пароль, токен или личные данные.
