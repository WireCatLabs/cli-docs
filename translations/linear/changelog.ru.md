Заметные изменения `@wirecat/linear-cli`. Один раздел на версию, новые сверху.

## 0.5.0 — 25.11.2026

### Изменено — может сломать скрипты

- **linear построен на cli-core 1.0.0 и cli-base 1.0.0.** После первого запуска хранилище переходит на версию 73, и
  открывают его только инструменты на cli-core 1.0, поэтому обновляйте все CLI WireCat на этом компьютере вместе.
  Миграция сохраняет копию для отката и не запускается, если не может ее записать.
- **`sync --rescan` больше не дает синхронизации отметить удаленными большую часть тикетов или документов.** Он
  только заново перечисляет все. Когда защита придерживает проход, `sync --allow-deletions <count>` разрешает отметить
  удаленными не больше этого числа. Этот флаг для владельца в терминале, сервер MCP его не предлагает.
- **Вызов MCP, который называет запрещенную папку, отвечает `permission_error`**, а не `validation_error`.

## 0.4.1 — 25.11.2026

### Исправлено

- Агент, который читает `linear skill show`, теперь узнает основные действия: синхронизацию, поиск тикетов по ключевым словам, фильтры по id, запись тикетов и то, где в группе `api` лежат архивация, связи, вложения и вехи. Раньше там была заглушка из шаблона.

## 0.4.0 — 25.11.2026

### Добавлено

- **Циклы Linear как спринты.** `sync` копирует циклы каждой команды, `sprints list` показывает их с номером, началом
  и концом, а `issues list sprint:<id>` (или `sprint:none`) сужает список тикетов. Цикл без названия показан как
  `Sprint <number>`.
- **Тикет, перенесенный в корзину Linear, уходит из локальной копии.** Перенос в корзину не меняет время правки
  тикета, поэтому синхронизация, которая читает только изменения, его не видела. Ежедневная проверка удаленных
  тикетов теперь не считает тикеты из корзины, поэтому они и их комментарии уходят из копии. Тикет, восстановленный
  из корзины, возвращается при следующей ежедневной проверке. Ответ `sync` говорит, когда эта проверка шла в
  последний раз и когда пойдет снова (`deletions`).
- **Документ, восстановленный из корзины Linear, возвращается без `--rescan`.** Раз в неделю `sync` полностью
  обходит выбранные папки и возвращает его.

### Исправлено

- **Тикеты в статусе Duplicate сохраняются.** Их статус терялся, и они ссылались на статус, которого в копии не было.
  Теперь `issues list type:duplicate` показывает их, а задача из такого тикета закрывается.
- **`sync` без новых данных так и говорит.** Его счетчики называют только изменившиеся строки, поэтому Desktop
  показывает, что все актуально. Вид данных, который ключ не может прочитать, назван в `meta.issues`.

## 0.3.1 — 24.11.2026

### Исправлено

- **Документ, перенесенный в корзину Linear, уходит из локальной копии при следующей синхронизации.** Перенос в
  корзину не меняет время правки документа, поэтому обычный `sync` пропускал его до `sync --rescan`. Теперь
  синхронизация читает и журнал аудита рабочего пространства с удаленными документами. Если Linear не дает вашему
  ключу журнал аудита (нужен доступ к нему), синхронизация все равно проходит и предупреждает
  `source.deletions-unchecked`. Тогда документы из корзины находит `sync --rescan`. Документ, восстановленный из
  корзины, возвращается только с `sync --rescan`.

## 0.3.0 — 23.11.2026

### Добавлено

- **Документы Linear синхронизируются рядом с тикетами.** Тот же `sync` копирует их в локальное хранилище, а общие
  команды документов из cli-core читают их без интернета: `folders` выбирает проекты (`linear:all` для всех проектов
  и документов вне их), `documents list|show|export|history|context`, `search`, `status`, `changes`, `catalog`, а
  также группы `tags`, `notes`, `memories`, `facts`, `relationships` и `identities`. `linear <profile> search` находит
  их по словам и по смыслу, а `search all` из memo находит их в разделе заметок с видом `document`. Удаляется только
  документ, который Linear перенес в корзину. Архивный, скрытый или больше не видимый документ сохраняет свой текст.
- **Тикеты, проекты и комментарии находятся по смыслу.** `sync --embed` индексирует их уже скачанной моделью, и
  тогда `search all` из memo находит их и по смыслу, и по словам (cli-core 0.730.0).
- **Тикеты находятся по другим формам слова и по его началу.** `search all` и `issues search` находят "invoices" по
  "invoice" и "export" по "exp…" (от четырех букв). Комментарии находятся по смыслу вместе с ключом и названием их
  тикета, а два входа в одно рабочее пространство показывают каждый тикет один раз (cli-core 0.736.0).
- **Создание, изменение и комментарии к тикетам Linear.** `linear <profile> issues create --title …`,
  `issues update <issue>` и `issues comments create <issue> --text …`, на основе записи в трекер из cli-core. Команду, статус, метку,
  проект или пользователя называют по id или по имени, которое есть только у одной строки локальной копии. Каждая
  запись проверяет свой ключ (`issues.create`, `issues.update`, `issues.comments.create`) и ключ операции API.
  `--dry-run` показывает запись и ничего не отправляет. Если тикет отдается не вам, проверяется еще
  `issues.assign-others`, который запрещен, пока ваш профиль его не разрешит.

## 0.2.0 — 21.11.2026

### Добавлено

- **Тикеты Linear, назначенные на вас, становятся вашими задачами WireCat.** После каждого `sync` каждый открытый
  тикет, назначенный на вошедшего пользователя, становится задачей в общем хранилище с ключом и названием тикета
  (`ENG-12 Fix login`), и ее видят страница Tasks в WireCat Desktop и ваш агент. Задача закрывается, когда тикет
  выполнен, отменен, в архиве, удален, снят с вас или назначен на другого, и открывается снова, когда тикет
  возвращается к вам. Задача, которую вы закрыли сами, остается закрытой, а открытая вами снова не закрывается
  повторно. Ответ синхронизации говорит, что она сделала, в `tasks`. В Linear ничего не записывается.

### Изменено — может сломать скрипты

- **`issues assign` дает задаче ключ и название тикета**, и каждая синхронизация держит их актуальными. Раньше задача
  не копировала текст тикета. Если назначить тикет, из которого синхронизация уже сделала задачу, задача становится
  вашей и открывается снова, если была закрыта, а переход тикета к другому больше ее не закрывает.
- **Вызов `api`, ключ разрешения которого `deny` (или `readonly` для записи), отказывает до чтения тела запроса**, с
  `permission_error` (код 5). Раньше отсутствующее или неверное тело сначала отвечало `validation_error` (код 2).

### Исправлено

- **Справка группы `api` называет схему GraphQL Linear**, а не документ OpenAPI.
- **`api show` принимает операцию по ее имени в кавычках, по старому имени или по id операции.**
- **Шаги входа называют правильную страницу.** Персональный API-ключ Linear создается в Settings → Account → Security
  & access, а в шагах не хватало Account.
- **Страницы безопасности и настроек больше не упоминают пример из шаблона.** В них были выдуманный адрес и команда
  `comments`, которой в linear нет.

## 0.1.0 — 18.11.2026

### Добавлено

- Создан из `@wirecat/cli-template` 0.31.0.
- Собран из одного файла, `wirecat.config.ts`, без хуков.
- **`linear <profile> sync` копирует ваше рабочее пространство Linear в локальное хранилище WireCat**: команды,
  пользователей, статусы, метки, проекты, тикеты и комментарии, архивные с пометкой. После первого запуска он читает
  только то, что изменилось, а раз в день находит то, что удалили в Linear. Копия принадлежит пользователю, чей
  персональный API-ключ использован для входа, потому что Linear показывает каждому участнику свой набор команд.
- **`linear <profile> issues`, `projects`, `teams`, `users`, `states` и `labels` читают копию**, в том числе без
  интернета. `issues assign ENG-12` делает тикет вашей задачей: задача ссылается на тикет и не копирует его текст.
- **`linear <profile> api` достает до каждого запроса и каждой мутации схемы GraphQL Linear**, по команде на каждую.
  Запись спрашивает свой ключ разрешения, удаление или архивация спрашивает `linear.delete`.
- Вход по персональному API-ключу Linear через stdin: `linear <profile> session start`. Ключ хранится в связке ключей
  системы и никогда не передается аргументом.
