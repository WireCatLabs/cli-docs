Поручите агенту полную задачу: импортировать проект, подготовить справку, сохранить вопросы
для проверки или вспомнить решение с источниками. Каждый сценарий связывает запрос с командами
и проверкой результата. Примеры используют `personal`; замените его профилем подключённого аккаунта.

Выберите, можно ли обновлять данные Google, менять только локальный контекст или изменять файл
Google. [Импорт и хранение](./usage.md) объясняет содержимое сохранённой копии.

## Выбрать сценарий

| Задача | Использует Google | Меняет локальные данные | Меняет файлы Google |
| --- | --- | --- | --- |
| Импортировать или обновить проект | Да | Индекс и снимки | Нет |
| Подготовить справку по сохранённой копии | Нет | Нет | Нет |
| Собрать контекст проекта через Memo | Синхронизация обращается к Google; сбор читает сохранённую копию | Индекс и снимки при синхронизации | Нет |
| Просмотреть и организовать сохранённое дерево папок | Нет | Теги/заметки по запросу | Нет |
| Добавить теги, заметки или связи для следующих действий | Нет | Да | Нет |
| Предложить записи памяти с ИИ-провайдером | Отправляет кешированный текст настроенному провайдеру | Только с `--yes` или подтверждением | Нет |
| Посмотреть комментарии или историю | Да | Без автоматического импорта | Нет |
| Создать или изменить Google Doc | Да | Импортируется при следующей синхронизации | Да |
| Прочитать или изменить ячейки таблицы | Да | Импортируется при следующей синхронизации | Только при явном изменении ячеек |
| Организовать листы и форматирование таблицы | Да | Импортируется при следующей синхронизации | Да |

## Первая папка для поиска без лишних экспортов

```text prompt
Use drive CLI with profile personal to index the project folder I select.
Import supported documents, report skipped files and finish any pending sync batches.
Find one passage about the budget and show its original source link. Do not export extra files.
```

```sh
drive personal folders add FOLDER_ID
drive personal sync --json
drive personal status --json
drive personal search 'budget' --exact --json
drive personal documents show DOC_ID --json
```

Замените `DOC_ID` идентификатором Google найденного источника из `documents list`. Продолжайте
sync, пока остались задания. Точный поиск не требует модели векторов. Без экспортов нет
дополнительных копий; база и управляемые снимки всё равно сохраняются.

## Обновить проект и подготовиться к встрече

```text prompt
Use drive CLI with profile personal. Refresh my selected folders, then find the latest budget
and launch decisions. Prepare a short meeting brief with open questions and source links.
Tell me about skipped sources and unfinished sync work. Do not change Google files.
```

```sh
drive personal sync --json
drive personal status --json
drive personal search 'budget OR launch' --exact --json
drive personal documents context DOC_ID --json
```

Прочитайте сохранённые фрагменты и метаданные для проверки решений. Откройте ссылки Google,
когда нужна актуальная версия. Обзор не охватывает неподдерживаемые или
неимпортированные источники. `documents get` читает доступный Google Doc напрямую без импорта;
возвращает Docs JSON и не добавляет документ в поиск.

## Собрать контекст проекта через Memo

Этот сценарий подходит, когда сведения о проекте распределены между документами Drive и другими
источниками, которые агент читает через Memo. Drive сохраняет выбранные документы локально, а Memo
находит в них основания для ответа о проекте со ссылками на источники. Оба инструмента должны
использовать одну базу WireCat. Сначала подключите профиль Drive по
[инструкции установки](./installation.md) и при необходимости установите
[Memo](https://wirecat.dev/en/docs/memo/installation).

```text prompt
Используй профиль Drive personal и Memo, чтобы собрать контекст проекта Cobalt Orchard. Сначала
покажи выбранные папки Drive и дай мне выбрать отдельную папку проекта. Синхронизируй её, сообщи
о пропущенных файлах и незавершённой работе, затем собери основания из этого профиля Drive за
последние 60 дней. Покажи исходные ссылки на документы, даты источников и пробелы в охвате.
Не меняй файлы Google и не создавай связи с проектом.
```

Для ручного запуска замените `FOLDER_ID` идентификатором или URL папки проекта в Google. Будут
включены и вложенные папки, поэтому выберите папку проекта, а не весь аккаунт:

```sh
drive personal folders list --json
drive personal folders add FOLDER_ID
drive personal sync --limit 50 --json
drive personal status --json
drive personal documents list --json
memo projects list --json
memo projects evidence COB --source drive:personal --json
```

Замените `COB` ключом, названием или псевдонимом существующего проекта из `memo projects list`.
Можно также искать по новому названию, не создавая проект. Если профиль Drive называется иначе,
замените `personal` в командах обоих инструментов. Успешная синхронизация регистрирует профиль
для выбора локального источника; `drive:personal` указывает Memo, какую импортированную учётную
запись читать.

`--limit 50` ограничивает чтение содержимого за один запуск синхронизации, но не ограничивает
рекурсивный обход 50 записями. Ранее выбранные корневые папки остаются в охвате. Сначала проверьте
`folders list`, затем результат синхронизации и `status`: осталась ли работа, какие файлы
пропущены. Повторите синхронизацию, чтобы продолжить сохранённую работу. Завершённая порция
не означает, что прочитаны все типы файлов.

Memo по умолчанию ищет за 60 дней. Для более широкого периода используйте:

```sh
memo projects evidence COB --source drive:personal --since-time 365d --json
```

Для импортированных документов Google используется время изменения источника в Google, если
оно известно; иначе — время обновления локальной записи. Импорт старого документа сегодня
не меняет известную дату источника на сегодняшнюю. Дата изменения также не устанавливает,
когда было принято описанное решение. Проверьте `time_kind`, URL и текст каждого совпадения,
прежде чем считать его основанием. Если Memo вернул контрольную точку, продолжите с теми же
параметрами и её значением `--cursor`. Ошибки чтения и непрочитанные источники остаются пробелами
в охвате. Сбор использует сохранённое содержимое и не обновляет данные из Google.

Чтение файла через подключённое приложение Google Drive или живой `documents get` не выполняет
эту локальную синхронизацию. После обычной синхронизации Drive не нужны экспорт Markdown или
повторный импорт. Оба инструмента по умолчанию используют общую базу; если переопределяете
`MESSAGING_STORE`, укажите один путь в обоих. Разные файлы баз не разделяют ссылки на документы.

Ожидаемый результат — совпадения из выбранного аккаунта со ссылками на оригиналы Google и
явными ограничениями. Импорт и поиск не создают принадлежность к проекту, факты или задачи.
Проверяйте их отдельно через [связи документов](#link-a-document-to-a-person-or-project) или
[сценарии проектов Memo](https://wirecat.dev/en/docs/memo/recipes).

### Искать в Memo только документы Drive

`memo search notes` ищет в ваших заметках и импортированных документах вместе. `--source` оставляет только
документы одного профиля Drive:

```sh
memo search notes "budget decision" --source drive:personal --json
```

Документы каждого аккаунта Google лежат в общей базе в своём аккаунте, не вместе с вашими заметками.
`drive:personal` называет этот аккаунт по профилю drive; `google-drive:<id>` называет тот же аккаунт по его
Google ID — значению `principal`, сохранённому для профиля в `config.json`. Несколько профилей перечисляются
через запятую, например `--source drive:personal,drive:work`. Профиль, который ещё не синхронизировался,
отклоняется со списком профилей, которые есть в базе. `memo search all`
ранжирует сообщения, почту и заметки вместе и не фильтрует по источнику; `drive personal search` находит
те же документы с собственными полями Drive.

## Подготовить справку полностью без сети

```text prompt
Use drive CLI with profile personal and --offline. Find budget and launch decisions in the saved
project documents. Prepare a brief with exact passages, source titles and links, and the last sync
information. Do not contact Google or an AI extraction provider through the CLI.
```

```sh
drive personal --offline status --json
drive personal --offline search 'budget OR launch' --exact --json
drive personal --offline documents show DOC_ID --json
drive personal --offline documents context DOC_ID --json
```

Результат использует последнюю сохранённую копию. Нельзя выдавать её дату за новую проверку
Google. `--offline` управляет CLI; облачный агент всё равно может передавать возвращённые
основания своему провайдеру. Для полностью локальной работы проверьте настройки самого агента.

## Сохранить полные доступные метаданные для работы без сети

```text prompt
Use drive CLI with profile personal. Fetch all metadata Google exposes for the file I select,
save the JSON locally, and explain its fields. Read that saved file for later questions instead
of contacting Google again. Do not download its binary contents or change Google files.
```

```sh
drive personal files get FILE_ID --json > ./file-metadata.json
drive personal files list --parent FOLDER_ID --json > ./folder-metadata.json
```

Команды запрашивают все доступные поля метаданных файлов Google. Первая сохраняет ответ одного
файла; вторая — страницу непосредственных детей папки, включая метаданные форматов, содержимое
которых не индексируется. Продолжите по токену следующей страницы для полного списка. Доступные
поля определяются ролями и правилами Google.

Агент может читать сохранённый JSON без Google. Это отдельный снимок под вашим управлением;
он автоматически не импортируется в базу и не становится доступным через `drive search`.
Списки разрешений, комментарии и история — отдельные действия API. Обновляйте или удаляйте
дополнительные JSON-файлы, когда сохранённая версия больше не нужна.

Sync также сохраняет доступный ответ метаданных файла в локальном каталоге. Используйте
`catalog show FILE_ID --offline` без дополнительного JSON-файла. Старые записи содержат только
прежний набор полей до повторного обхода. Разрешения, комментарии и история остаются отдельными API-операциями.

## Просмотреть папки и назначить теги без Google

```text prompt
Use drive CLI with profile personal and only local data. Show the imported folder tree,
find the PDFs last edited by Rin, and show their source links and content availability.
Tag the folder I choose follow-up and save my memo beside it. Do not download or export files.
```

```sh
drive personal catalog import --offline
drive personal catalog tree --depth 3 --offline --json
drive personal catalog list 'mime:"application/pdf" AND person:Rin*' --offline --json
drive personal catalog tags add FOLDER_ID follow-up --offline
drive personal notes add FOLDER_ID 'Check the final version with Rin' --offline
drive personal catalog list 'tag:follow-up' --offline --json
drive personal documents context FOLDER_ID --offline --json
```

`catalog import` переносит прежний кеш в базу; обычный sync заполняет её при новых импортах.
Замените `FOLDER_ID` идентификатором из дерева. Проверьте, что контекст папки содержит тег и заметку.
Тег относится к папке, а не всем потомкам. Файлы с одними метаданными доступны до завершения
скачивания содержимого. Для цитаты убедитесь, что текст индексирован, и используйте `documents show`:
метаданные сами по себе не доказывают содержимого. См. [навигацию и фильтры каталога](./usage.md#browse-and-organize-the-local-catalog).

## Хранить вопросы рядом с источниками

```sh
drive personal tags add DOC_ID follow-up budget
drive personal notes add DOC_ID 'Confirm whether tax is included' --title 'Budget review'
drive personal documents list tag:follow-up --json
drive personal search 'budget AND tag:follow-up' --exact --json
drive personal notes list DOC_ID --json
```

Список документов и поиск принимают `tag:` внутри запроса.
Прочитайте список заметок, чтобы проверить запись. Меняется локальный контекст, не документ Google.

## Связать документ с человеком или проектом

```text prompt
Use drive CLI with profile personal to show observed editors and existing document links.
Link the document to the stored project and person I select, then show its saved context.
Do not merge people merely because their names match.
```

```sh
drive personal identities list DOC_ID --json
drive personal relationships add DOC_ID project:PROJECT_ID --kind related-to
drive personal relationships add DOC_ID person:PERSON_ID --kind about
drive personal documents context DOC_ID --json
```

Используйте ссылки из той же базы. Drive связывает существующие записи, но не создаёт проекты
и задачи. Наблюдаемые владельцы/последние редакторы не дают полного списка участников изменений.
Для связи с данными мессенджера используйте один `MESSAGING_STORE` во всех инструментах, если меняете стандартный путь. Разные базы
не разделяют ID. См. [настройки](./configuration.md) и
[организацию источников](https://wirecat.dev/en/docs/organize).

## Сохранить заметки при смене базы

Перенесите старый архив Drive в общее локальное хранилище вместе с тегами, заметками, памятью,
решениями и связями документов. Предыдущая база останется доступной. Файлы Google не меняются.

```text prompt
Используй drive CLI с профилем personal и покажи выбранную базу и базу контрольной точки.
Подготовь предварительный просмотр переноса контекста из предыдущей базы в выбранное общее хранилище.
Покажи неразрешённые ссылки до применения проверенного fingerprint. Сохрани исходный файл,
затем проверь заметки и поиск документов без сети в выбранной базе.
```

1. Выполните `drive personal status --json`. `store.selected` — база назначения из
   `MESSAGING_STORE` или общее хранилище WireCat по умолчанию. `store.checkpoint` — база, к которой
   относятся ссылки кешированного профиля. Если `MESSAGING_STORE` указывает на старый файл,
   сначала выберите нужную базу назначения. Обе следующие команды должны использовать одну базу.
2. Проверьте старый файл. Замените `SOURCE_DB` его путём:

   ```sh
   drive personal store check SOURCE_DB --offline --json
   ```

3. Прочитайте количества записей, `missing_bindings` и `conflicts`. Если `ready` равно true,
   подставьте полученный `fingerprint` в команду переноса:

   ```sh
   drive personal store import SOURCE_DB --fingerprint FINGERPRINT --offline --json
   drive personal documents context DOC_ID --offline --json
   drive personal search 'tag:YOUR_TAG' --exact --offline --json
   ```

Замените `DOC_ID` и `YOUR_TAG` документом и тегом из переносимой базы.
Успех подтверждают `checkpoint_updated: true` и `source_retained: true`. Профиль теперь использует
выбранную базу, а ссылки документов указывают на её ID. Заметки сохраняют версии, память — область
и статус, принятые решения остаются принятыми. Совпадение имён не объединяет людей. Другие
инструменты WireCat должны выбирать ту же базу, чтобы читать эти записи.

Для неразрешённой ссылки на проект, задачу или другой объект явно выберите ссылку назначения.
Необязательный JSON-файл задаёт соответствия, например `{"project:1":"project:7"}`. Передайте
его последним позиционным аргументом обеим командам: `store check SOURCE_DB bindings.json` и
`store import SOURCE_DB bindings.json --fingerprint FINGERPRINT`. Каждый раз проверяйте новый
fingerprint. Противоречия в людях, словаре меток или содержимом документов надо разрешить до переноса.

Если копия сохранена, но запись контрольной точки не удалась, повторите `store check` и перенос
с новым fingerprint. `already_transferred: true` использует готовую копию без дублирования.
На время перехода остановите другие записи в старую базу. Это разовое копирование снимка, а не
постоянная синхронизация. Изменение исходной базы после завершения блокирует новый перенос вместо
перезаписи правок назначения. Файлы не удаляются. Свыше 1 000 документов/аннотаций или 16 MiB
перенос отклоняется; индексы поиска по смыслу и кешированные изображения создаются заново явно.
Об отсутствующем кеше и старой схеме см.
[восстановление хранилища](./troubleshooting.md#the-store-upgrade-reports-existing-annotations).

## Запомнить решение с источником

```text prompt
Use drive CLI with profile personal to propose reusable facts from this imported document.
Show exact supporting quotes. Let me review them before saving or confirming anything.
```

После [настройки ИИ-провайдера](./configuration.md#optional-ai-extraction):

```sh
drive personal memories extract DOC_ID --scope work
drive personal memories extract DOC_ID --scope work --yes
drive personal memories list DOC_ID scope:work --json
drive personal facts list DOC_ID status:proposed --json
drive personal memories confirm DOC_ID memory:MEMORY_ID
drive personal facts confirm DOC_ID fact:FACT_ID
```

Извлечение по умолчанию показывает предварительный результат. `--yes` создаёт новую подборку
и сохраняет все её корректные предложения, а не предыдущий предварительный результат. Проверьте
сохранённые предложения перед подтверждением.
Заменяйте `MEMORY_ID` полученной ссылкой только после проверки. Изменение или удаление источника
помечает активную память устаревшей. Извлечение отправляет выбранный кешированный текст провайдеру;
локальный поиск по векторам — другая операция. Можно записать факт вручную:
`memories add DOC_ID 'Your fact' --scope work`.

## Обновить решение

Сохраните прежнее решение и его источник, когда договорённость меняется. Эти команды
изменяют локальные факты импортированного документа; они не редактируют Google Drive.

```sh
drive personal facts list DOC_ID kind:decision --json
drive personal facts add DOC_ID 'Move the launch to November' --type decision --scope work --supersedes fact:OLD_ID --occurred-time 2026-10-16T10:00:00Z
drive personal facts show DOC_ID fact:OLD_ID --json
```

Вместо `fact:OLD_ID` подставьте ссылку на прежнее решение из ответа команды. Новое решение
сразу принимается, а прежнее получает статус `superseded`; оба остаются видны. Необязательный
`--occurred-time` указывает время самого решения, а не его сохранения.
Замена, предложенная агентом, остаётся предложением до вашего подтверждения; до этого прежнее
решение сохраняет силу. Перед подтверждением проверьте источник.

Если решение больше не действует и замены нет:

```sh
drive personal facts reverse DOC_ID fact:DECISION_ID
drive personal facts list DOC_ID status:reversed --json
```

Отменять можно принятые решения. Другие виды фактов отменять нельзя. Факт должен принадлежать
выбранному документу и аккаунту. Операции работают без сети и соблюдают `--read-only`.
Параметр `--dry-run` показывает действие без изменения локальных фактов.

## Посмотреть версии или дополнительную историю

```sh
drive personal documents history DOC_ID --json
drive personal comments list DOC_ID --json
```

Это чтение непосредственно из Google. Версии и комментарии используют Drive API. Для событий
и участников включите Drive Activity API и подключитесь снова с дополнительным разрешением:

```sh
drive personal session start --client-file /path/to/desktop-client.json --grant activity
drive personal documents history DOC_ID --activity --json
```

Для продолжения передайте `page.next_cursor` в `--cursor` той же команды. Видимые Google
версии/события могут быть неполными; это не посимвольная история правок. Комментарии доступны
для просмотра, но не входят в поиск документов.

## Передать Markdown другому инструменту

```sh
drive personal documents export DOC_ID --output ./decision.md
```

Откройте файл или передайте путь инструменту на том же компьютере. Экспорт читает локальный
Markdown: сначала синхронизируйте, если нужна актуальность. Файл не загружается удалённому
агенту. Ненужную дополнительную копию можно удалить после работы; управляемый кеш останется.

## Создать Google Doc и включить в поиск

Используйте этот сценарий, только если хотите изменить Google Drive. Подключитесь с `--grant write`,
создайте документ и переместите его в выбранную папку:

```sh
drive personal session start --client-file /path/to/desktop-client.json --grant write
drive personal documents create --title 'Project review'
drive personal documents update NEW_DOC_ID --body '{"requests":[{"insertText":{"endOfSegmentLocation":{},"text":"Review notes\n"}}]}'
drive personal files get NEW_DOC_ID --json
drive personal files move NEW_DOC_ID --parent FOLDER_ID --old-parent OLD_PARENT_ID
drive personal sync --json
```

Замените `NEW_DOC_ID` значением `document_id` ответа создания. Docs создаёт его в корне My Drive.
Прочитайте `parents` через `files get` и замените `OLD_PARENT_ID` этим ID; `--old-parent` удаляет прежнего
родителя при добавлении нового. У файла Google один родитель; см.
[официальную инструкцию перемещения](https://developers.google.com/workspace/drive/api/guides/folder#move-files-between-folders).
Проверьте папку и поиск нового текста.
Для правок существующего документа используйте проверку версии Docs `writeControl`, доступную
в [схеме обновления](./commands.md#drive-documents-update).
Чтобы загрузить существующий локальный PDF, документ Office или медиафайл, используйте
`drive personal files upload ./report.pdf --parent FOLDER_ID`. Нужен тот же доступ на запись.
Команда возвращает ID загруженного файла; повторный запуск продолжает прерванную загрузку.
Запустите sync, чтобы индексировать поддерживаемые файлы в выбранных папках. Загрузка сохраняет
исходный формат; она не превращает локальный Markdown в оформленный Google Doc.

## Использовать локальный MCP-клиент

Добавьте `--read-only`, если сервер должен запрещать запись.

Для агента без терминала задайте исполняемый файл `drive` и аргументы `personal mcp`.
Подключённый аккаунт должен находиться на компьютере, где работает сервер.

```sh
drive personal mcp --tools --json
drive personal mcp
```

Сервер предлагает три инструмента: `drive_tools_search` находит команду и показывает её аргументы,
а `drive_read` или `drive_write` выполняет её с `{ command, arguments }`. Первая команда выше
перечисляет доступные команды: проверьте вывод перед запуском stdio-сервера. Имена аргументов MCP
записаны в snake_case, например `file_id`; соответствующий параметр CLI — `--file-id`.
Сервер использует то же дерево команд, профиль и ограничения. Запрещённые команды и их аргументы
остаются видны: `availability.available: false` сопровождается причиной и нужным ключом разрешения.
Инструмент записи остаётся в списке, даже если запись заблокирована. Команды, которым не хватает
разрешений Google, помечены как недоступные: войдите с `--grant write`, `activity` или `apps` по задаче
и перезапустите сервер. Изменение настроек и установка навыка требуют разрешения владельца
`permissions.mcp.authority`; агент не может менять это ограничение сам. Экспорт и скачивание
принимают имя файла внутри папки экспорта в кеше профиля. Для ChatGPT или Claude в браузере
или на телефоне см. [удалённое MCP](./remote.md). Остальные операции — в [полном справочнике](./commands.md).

## Найти документ и разговор, где им поделились

После импорта папки найдите её документы вместе с сохранёнными сообщениями и заметками через
Memo, Telegram или MAX. Попросите агента:

```text prompt
Используй Drive CLI: синхронизируй выбранные папки профиля personal. Найди документ с бюджетом
в общем поиске WireCat, покажи Google-ссылку и сохранённые разговоры, где им делились.
```

Синхронизация Drive связывает импортированные документы с видимыми Google-ссылками в сообщениях,
уже сохранённых инструментами мессенджеров. Следующие синхронизации связывают новые сообщения и
Google-ссылки, добавленные при редактировании старых сохранённых сообщений, даже если документ не
изменился. Инструмент мессенджера должен сначала сохранить отредактированное сообщение локально.
История мессенджера не скачивается, сообщения не помечаются
прочитанными. Ссылки, скрытые за форматированным текстом без видимого Google URL, не определяются.

Для точных команд замените `CHAT_ID` чатом, выбранным в вашем профиле Telegram:

```sh
drive personal sync
tg personal search all budget --exact
tg personal chats documents list CHAT_ID
```

Собственный поиск Drive содержит ссылку на запись документа, Google URL и время последнего изменения
в Google. В списке чата появляется название импортированного документа, когда связь установлена.
Пустой результат может означать, что нужные документы или сообщения ещё не импортированы.

## Читать и менять ячейки таблицы

Используйте актуальные команды Sheets, когда нужны текущие ячейки или формулы. Импорт делает
сохранённый текст доступным поиску; чтение диапазона не импортирует таблицу, а изменение появится
в локальном индексе после следующей синхронизации. Для актуальных команд нужен Google Sheets API
в OAuth-проекте приложения. Для своего приложения [включите Google Sheets API](https://console.cloud.google.com/apis/library/sheets.googleapis.com)
в его проекте; настройкой общего приложения занимается WireCat.

```text prompt
Используй drive CLI с профилем personal. Посмотри вкладки выбранной мной таблицы, затем прочитай
Budget!A1:C4. Покажи текущие значения и формулы, прежде чем предлагать изменение. Если я попрошу
применить его, измени только согласованные ячейки, покажи возвращённый диапазон и обнови копию для поиска.
```

Начните с подключения для чтения:

```sh
drive personal sheets info SHEET_ID --json
drive personal sheets show SHEET_ID 'Budget!A1:C4' --json
drive personal sheets show SHEET_ID 'Budget!C1:C4' --render formula --json
```

Замените `SHEET_ID` идентификатором таблицы или её URL Google Sheets. Нотация A1 задаёт вкладку
и ячейки: `Budget!A1:C4` — столбцы A–C и строки 1–4. Если в имени вкладки есть пробел, передайте
`"'Quarter 1'!A1:C4"`. `--render unformatted` возвращает исходные значения; по умолчанию Google
возвращает форматированные значения для показа. Пустые строки и ячейки в конце могут отсутствовать в ответе.

Чтобы менять ячейки, подключитесь с явным разрешением записи:

```sh
drive personal session start --grant write
drive personal sheets update SHEET_ID 'Budget!A2:B2' --values '[["Travel",250]]' --json
drive personal sheets update SHEET_ID 'Budget!C2' --input user-entered --values '[["=B2*1.2"]]' --json
drive personal sheets add SHEET_ID 'Budget!A1:C20' --values '[["Supplies",40,48]]' --json
drive personal sheets clear SHEET_ID 'Budget!A3:C3' --json
```

По умолчанию обновления воспринимают строки буквально, включая строки с начальным `=`.
Выберите `--input user-entered` для формул и разбора чисел/дат с учётом локали таблицы Google.
Передавайте длинные идентификаторы строками в кавычках. Значения — JSON-строки ячеек из строк,
конечных чисел, логических значений или `null`, не более 10 000 переданных ячеек. `null` пропускает
ячейку; `""` очищает её значение. Переданные строки должны помещаться в выбранный прямоугольник;
неуказанные ячейки остаются без изменений.

Удобные команды записи требуют вкладку и конечный прямоугольник ячеек. Добавление использует
этот прямоугольник для поиска существующей таблицы Google, затем вставляет строки **после найденной
таблицы**; новые строки могут оказаться за пределами диапазона поиска. Проверяйте
`updates.updated_range` и возвращённые значения, а не считайте диапазон местом вставки.
Очистка удаляет значения и формулы, сохраняя форматирование. Обновление/добавление возвращает
изменённые значения; отдельное чтение даёт независимую проверку. Между командами таблицу могут менять соавторы.

`--dry-run` показывает метод и диапазон без обращения к Google; `--read-only` запрещает запись,
а `--offline` — актуальные операции Sheets. Запись с `outcome_unknown` нужно проверить в Google
до повтора, особенно добавление, которое может продублировать строки. CLI не повторяет такие
операции автоматически. Выполните `sync`, чтобы обновить локальную копию импортированной таблицы.

Для создания вкладок, вставки и ограниченного форматирования см.
[управление вкладками и форматирование ячеек](#organize-tabs-and-format-selected-cells) ниже.
Для других операций или нескольких диапазонов в одном запросе используйте сгенерированные команды
Sheets API из [справочника команд](./commands.md). Они используют JSON-схемы Google и те же проверки
разрешений, offline и read-only, но не ограничения удобных команд на конечный диапазон и 10 000
ячеек. Запись через `api call` дополнительно требует `--allow-writes`. Повторяющиеся `--ranges`
передаются через запятую; если запятая есть в имени вкладки, передайте JSON-массив через `api call --params`.
Некоторые POST-методы поиска требуют более широкого разрешения Drive, хотя только читают данные;
проверьте контракт метода и требования Google перед повторным подключением.

## Управлять вкладками и форматировать выбранные ячейки

Используйте идентификаторы вкладок из `sheets info`, чтобы изменить конкретную вкладку существующей
таблицы. Команды используют то же явное разрешение записи, что и обновление ячеек. Они меняют
данные Google; обновите импортированную копию через `sync`, когда поиску нужен актуальный источник.

```text prompt
Используй drive CLI с профилем personal. Посмотри вкладки выбранной таблицы. Создай вкладку
Quarter 2, переименуй указанную мной вкладку и сделай полужирной только её строку заголовков A1:C1.
Покажи возвращённые идентификаторы вкладок и изменённый диапазон. Сохрани значения и другое форматирование.
```

```sh
drive personal sheets info SHEET_ID --json
drive personal sheets create SHEET_ID 'Quarter 2' --json
drive personal sheets rename SHEET_ID 101 'Quarter 1' --json
drive personal sheets insert SHEET_ID 101 rows 1 3 --json
drive personal sheets insert SHEET_ID 101 columns 0 1 --json
drive personal sheets format SHEET_ID 101 A1:C1 --body '{"textFormat":{"bold":true}}' --json
drive personal sheets format SHEET_ID 101 B2:B10 --body '{"numberFormat":{"type":"NUMBER","pattern":"0.00"}}' --json
```

`create` добавляет пустую вкладку существующей таблицы, а не новый файл таблицы.
Замените `101` числовым идентификатором вкладки, возвращённым Google. После переименования он
сохраняется; меняется только заголовок. Имя должно содержать 1–100 символов; Google также проверяет
допустимость и уникальность имени.

Вставка принимает `rows` или `columns`, **индекс с нуля, перед которым вставлять**, и количество
от 1 до 1 000. Индекс `0` — первая строка/столбец; индекс строки `1` вставляет перед второй строкой.
Последующие элементы сдвигаются. Google проверяет текущие границы сетки и ограничения таблицы;
для добавления измерений в конце используйте сгенерированный API. Команда наследует форматирование
от измерения после места вставки.

Форматирование использует явный идентификатор вкладки и конечный диапазон **без префикса вкладки**,
например `A1:C4`. Можно выбрать не более 10 000 ячеек. JSON поддерживает полужирный/курсивный/
подчёркнутый/зачёркнутый текст, семейство и размер шрифта, цвет текста/фона, горизонтальное/вертикальное
выравнивание, перенос текста и числовой формат. Имена полей соответствуют JSON `CellFormat` Google.
Неизвестные поля, пустые объекты, значения ячеек и формулы отклоняются.

В маску запроса включаются только переданные свойства форматирования. `textFormat.bold`
сохраняет курсив, числовой формат и значения ячеек; `false` снимает полужирное начертание.
Поддерживаются цветовые каналы (`red`, `green`, `blue`, `alpha`) и стили цвета темы.
Для других полей или нескольких операций в одном запросе используйте сгенерированную команду
`api sheets-spreadsheets-batch-update`. У общего пакетного запроса шире возможные изменения;
ограничения удобной команды на 10 000 ячеек и допустимые поля к нему не относятся.

Все пути сохраняют политику профиля, разрешение OAuth на запись, offline/read-only, dry-run и
обработку неопределённого результата записи. Запрет профиля, например `sheets.rename`, действует
и на эквивалентный сырой/сгенерированный пакетный запрос. Перед повтором неопределённого изменения
структуры проверьте текущие ячейки: иначе можно создать дубликаты вкладок или вставить лишние строки.
Между отдельными командами возможны изменения соавторов.
