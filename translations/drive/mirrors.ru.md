---
title: "Синхронизировать локальные файлы с Google"
---

Зеркало связывает локальную папку с папкой Google: вы храните Markdown или таблицы на компьютере,
а коллеги работают с ними в Google Документах или Таблицах. Синхронизация отправляет локальные
изменения и возвращает поддерживаемые правки из Google. При конфликте она предлагает выбрать сторону.

## Подключить папку

Войдите в профиль с разрешением Google на запись, затем выберите локальную папку и назначение:

```sh
drive personal session start --grant write
drive personal mirrors add ./notes --parent FOLDER_ID
drive personal mirrors list
drive personal mirrors status
drive personal mirrors sync
```

Замените `personal` именем подключённого профиля. `FOLDER_ID` — ID или URL папки Google Drive.
Добавление зеркала проверяет назначение и сохраняет связь локально. Первая синхронизация создаёт
Google Документы для `.md` и `.markdown` и Google Таблицы для `.csv`, `.tsv` и `.xlsx`.
Локальные подпапки становятся папками Google. Другие типы файлов учитываются как неподдерживаемые.

`mirrors status` проверяет локальные файлы и сохранённое состояние без обращения к Google.
Он не показывает, изменил ли коллега документ в интернете. `mirrors list` показывает ID зеркал и папки.
Передайте ID зеркала в `status` или `sync`, чтобы выбрать одно зеркало; без ID выбраны все зеркала профиля.

## Синхронизировать в обе стороны

После редактирования снова запустите `mirrors sync`. Для Markdown Drive сравнивает блоки документа
с последней синхронизацией: изменения разных частей можно объединить, а неизменённый текст
сохраняет комментарии Google. Правки ячеек Google возвращаются в CSV или TSV. Локальные изменения
XLSX отправляются в Google Таблицы, но правки из Таблиц не записываются обратно в XLSX.

Зеркало таблицы управляет диапазоном, который записало сначала. Оно обновляет его, сохраняя соседние
ячейки и посторонние листы. Первая строка становится закреплённым полужирным заголовком.
Проверяйте результат, если важны формулы, оформление или структура книги: зеркало не заменяет
полную резервную копию документа Google.

## Локальные изображения

Google Документы копируют изображение только с публичного веб-адреса, поэтому локальное изображение, например
`![chart](pics/chart.png)`, остаётся в Документе этим текстом, если не передать синхронизации адрес вашего туннеля:

```sh
drive personal mirrors sync --public-url https://<name>.ts.net
```

Тогда Drive сам отдаёт каждое новое локальное изображение через туннель по случайному адресу, который работает
только пока Google копирует изображение, и сразу после этого закрывает его. Ничего в вашем Google Диске не
открывается для доступа, а Google хранит собственную копию внутри Документа. Это тот же туннель, что и для
[удалённого MCP](./remote.md); он должен перенаправлять на `--port` этого компьютера (по умолчанию 8765). Если
порт занят `drive mcp --http`, остановите его на время синхронизации или передайте другой `--port` и направьте
туннель туда; пока порт занят, синхронизация не запускается.

Вставляются только файлы PNG, JPEG и GIF меньше 50 МБ внутри зеркалируемой папки. Любое другое изображение
остаётся текстом с предупреждением. Если Google не может получить изображение, остальной Документ всё равно
записывается, изображение остаётся текстом с предупреждением, а следующая синхронизация с `--public-url`
пробует снова. Изображение, уже вставленное в Документ, остаётся там при следующих синхронизациях без
`--public-url`. `mirrors watch` принимает те же два параметра.

## Выбрать сторону после конфликта

Если одна часть изменилась с обеих сторон, синхронизация сообщает о конфликте и завершается
с частичным результатом. Перед выбором проверьте локальный файл и документ Google:

```sh
drive personal mirrors sync MIRROR_ID --keep local
drive personal mirrors sync MIRROR_ID --keep google
drive personal mirrors sync MIRROR_ID --keep both
```

`--keep local` выбирает локальное содержимое конфликта. `--keep google` выбирает содержимое Google,
если его можно записать обратно: Markdown, CSV или TSV. Для Markdown `--keep both` сохраняет обе
конфликтующие версии; затем проверьте объединённый текст. Для одних и тех же ячеек Таблицы нельзя
сохранить обе версии: выберите локальную или Google. Если Таблица зеркала XLSX изменилась,
нужно выбрать `--keep local`.

Документ с непринятыми предложениями правок отклоняется даже с `--keep`: сначала примите или
отклоните их в Google, затем повторите команду. Правки вне поддерживаемых блоков Markdown
может потребоваться проверить вручную.

## Удаление и остановка

Удаление локального файла не отправляет его копию Google в корзину. Удаление файла Google
не удаляет локальный источник; синхронизация не создаёт его заново без вашего решения.
Проверив удалённое, запустите:

```sh
drive personal mirrors sync MIRROR_ID --replace
```

`--replace` выбирает локальную сторону и заново создаёт отсутствующие файлы Google.
Он несовместим с `--keep google` и `--keep both`. После переименования или переноса может остаться
старая копия Google: проверяйте отчёт об оставшихся копиях, не ожидая переноса удалений между системами.

Чтобы остановить зеркало, не удаляя локальные файлы и файлы Google:

```sh
drive personal mirrors remove MIRROR_ID
```

Зеркало не импортирует назначение в поиск. Для поиска этих файлов Google без подключения отдельно
выберите папку через `folders add` и выполните `sync`, как описано в [импорте и организации](./usage.md).
О доступе агента только на чтение см. [разрешения](./security.md#google-access-and-command-permissions).
