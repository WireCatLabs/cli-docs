Каждый сценарий — частая задача по шагам: какие команды выполнить, зачем нужна каждая и на что смотреть в ответе. Те же сценарии есть в терминале: `drive guide` показывает список, а `drive guide <name>` — один сценарий.

Команды, которые работают с аккаунтом, начинаются с профиля — имени, которое вы дали аккаунту при входе: `drive <profile> …`.

<a id="agent-access" />

## Дать агенту доступ к документам только на чтение

Агент ищет и читает импортированные документы, но ничто из запущенного им не может изменить локальные данные или данные Google.

1. ```sh
   drive skill install
   ```

   кладёт инструкции drive туда, где их ищут Claude Code, Codex и Gemini CLI

2. ```sh
   drive mcp --tools --read-only
   ```

   показывает команды, которые MCP-сервер предложит под запретом изменений; ни одна из них ничего не записывает

3. ```sh
   drive mcp --read-only
   ```

   запускает три инструмента на stdio — drive_tools_search, затем drive_read; drive_write не предлагается

На что смотреть:

- DRIVE_READ_ONLY=1 в окружении агента действует как --read-only для каждой его команды
- команды, которым нужно разрешение Google, не выданное при входе, не предлагаются

Текст, который агент читает в документах, — это данные, а не инструкции.

В терминале: `drive guide agent-access`

## Разобраться в документе перед встречей

Узнайте, о чём документ, что о нём уже записано и какие факты в нём есть, с цитатой для каждого.

1. ```sh
   drive sync
   ```

   загружает последнюю версию перед чтением

2. ```sh
   drive documents context DOC_ID
   ```

   документ с тегами, заметками, записями памяти и редакторами в одном ответе

3. ```sh
   drive memories extract DOC_ID --scope work
   ```

   отправляет текст выбранной модели и показывает предложенные записи памяти, каждую с точной цитатой; --yes сохраняет их

4. ```sh
   drive notes add DOC_ID "ask about the Q3 numbers"
   ```

   ваша заметка, которая остаётся с документом при синхронизациях

5. ```sh
   drive documents export DOC_ID --output brief.md
   ```

   документ в Markdown в новом файле; существующий файл никогда не перезаписывается

На что смотреть:

- предложенные записи памяти, которые цитата не подтверждает; не сохраняйте их
- заметки и записи памяти, устаревшие после новой версии документа

Только memories extract отправляет текст документа модели, выбранной через models set; больше ничто этого не делает.

В терминале: `drive guide brief-document`

<a id="find-decision" />

## Найти, где было принято решение

Найдите документ с решением, прочитайте нужный фрагмент и посмотрите, кто его менял.

1. ```sh
   drive search "budget decision"
   ```

   все импортированные документы, по словам и по смыслу, каждый результат со ссылкой Google

2. ```sh
   drive documents show DOC_ID
   ```

   текст документа со вкладками, чтобы прочитать фрагмент целиком

3. ```sh
   drive documents context DOC_ID
   ```

   его теги, заметки, записи памяти и редакторы из локального хранилища

4. ```sh
   drive documents history DOC_ID --activity
   ```

   кто что с ним делал, по данным Drive Activity; нужен вход с --grant activity

На что смотреть:

- ссылку Google из результата, чтобы на неё сослаться
- последних редакторов и когда они его меняли
- пустой результат означает, что в импортированных папках совпадений нет, а не что такого документа нет в Drive

Поиск читает только импортированные папки выбранного профиля. Если документ новый, сначала выполните sync.

В терминале: `drive guide find-decision`

<a id="set-up" />

## Импортировать выбранные папки и искать по ним

Войдите один раз, выберите папки Drive и загрузите их документы в локальное хранилище как текст для поиска.

1. ```sh
   drive session start
   ```

   выполняет вход в Google в браузере, только на чтение; команды drive начинаются с профиля, например drive personal session start

2. ```sh
   drive folders add https://drive.google.com/drive/folders/FOLDER_ID
   ```

   импортируются только добавленные папки и всё, что в них

3. ```sh
   drive models download e5-small
   ```

   локальная модель для поиска по смыслу, один раз на компьютер; её используют все WireCat CLI

4. ```sh
   drive sync --embed
   ```

   импортирует изменения в этих папках и индексирует текст для поиска по смыслу

5. ```sh
   drive status
   ```

   сколько документов импортировано, что ещё ждёт и что пропущено

На что смотреть:

- пропущенные файлы и причину для каждого, например неподдерживаемый тип или превышение размера
- незавершённую работу; повторяйте sync, пока ничего не останется
- следующая синхронизация читает только изменения

С компьютера ничего не уходит, кроме запросов синхронизации к Google; поиск и чтение работают без сети.

В терминале: `drive guide set-up`
