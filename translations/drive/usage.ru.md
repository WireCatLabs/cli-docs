title: "Импортировать и организовать"
---

Превратите выбранные папки Google в локальную копию, которую агент может искать и читать без
обращения к Drive для каждого вопроса. Здесь вы выберете область импорта, проверите сохранённое,
обновите копию и экспортируете документ для другого инструмента. Примеры используют профиль
`personal`; замените его именем подключённого профиля.

**Синхронизация** загружает поддерживаемое содержимое и обновляет локальный индекс. **Снимок** —
сохранённое содержимое и метаданные источника. **Экспорт** — дополнительный файл по вашему
запросу; для поиска он не нужен.

## Выбрать нужную операцию

| Задача | Команда | Откуда данные | Что сохраняется |
| --- | --- | --- | --- |
| Посмотреть папку до импорта | `drive personal files list --parent FOLDER_ID` | Google, сразу | Документы не импортируются |
| Прочитать Google Doc сейчас | `drive personal documents get DOC_ID` | Google, сразу | Без импорта; выводится Docs JSON |
| Сохранить папку для поиска | `drive personal folders add FOLDER_ID`, затем `drive personal sync` | Папка Google с потомками | Индекс, снимки и контрольная точка |
| Прочитать импортированный источник | `drive personal documents show DOC_ID` | Локальный снимок | Ничего нового |
| Передать Markdown другому инструменту | `drive personal documents export DOC_ID --output ./decision.md` | Локальный снимок | Запрошенный файл |

Перенаправление вывода в файл тоже сохраняет его. Просмотр папки или чтение непосредственно
из Google не добавляет документ в локальный поиск. Для поиска нужен импорт; экспорт необязателен.

## Какие типы документов доступны для поиска

| Тип в Google Drive | Действие sync | Результат для поиска/экспорта |
| --- | --- | --- |
| Google Doc | Получает содержимое Docs и Markdown Google | Текст всех вкладок для поиска; экспорт Markdown Google |
| Загруженный Markdown или TXT | Скачивает текст в управляемый кеш | Поиск и экспорт текста |
| Папка Google | Хранит метаданные и родителей в базе; обходит потомков | `catalog tree`, поиск метаданных, локальные теги и заметки |
| Google Sheet | Экспортирует книгу как `.xlsx` и читает каждый лист | Лист — заголовок; строки вида `Row 2: Column: value`, первая текстовая строка задаёт имена столбцов |
| Загруженные PDF, Word (`.docx`), Excel (`.xlsx`), CSV или TSV | Скачивает и читает текст | Текст PDF/Word, каждый лист Excel, строки CSV |
| Сканированный PDF без текстового слоя | Сохраняет название с причиной | Без OCR; поиск по названию |
| Изображения с включённым `picture_search` | Сохраняет название, скачивает до 25 МБ при разрешении Google, вычисляет вектор и не хранит файл | Поиск содержимого в `pictures`; см. [поиск изображений](./search.md#search-images-by-what-they-show) |
| Google Slides, презентации, `.xlsm`, изображения, аудио, видео, JSON или код | Сохраняет название с причиной | Без извлечения, OCR и расшифровки; поиск по названию |
| Ярлык Drive | Пропускает | Не переходит к цели ярлыка |
| Google запретил скачивание | Сохраняет название с причиной | Метаданные не гарантируют доступа к тексту; поиск по названию |

`drive personal config set picture_search true` включает поиск изображений для профиля
(см. [настройки](./configuration.md)). Следующий `drive personal sync` скачивает изображения
и считает обработанные в `pictures`. `pictures_too_large` — изображения больше 25 МБ, для которых
сохраняется название. `pictures_skipped` сообщает об отсутствии модели: остальная синхронизация
завершается, а изображения обрабатываются следующим sync после подготовки модели.

Markdown/TXT определяются по текстовому MIME или суффиксам `.md`, `.markdown`, `.txt`.
Экспорт Google ограничен 10 МБ: более крупная Sheet пропускается с причиной. Файлы больше 50 МБ
пропускаются до скачивания, как и текст длиной 2 000 000 символов и больше (уменьшить предел можно
[настройкой `max_text_chars`](./configuration.md#saved-settings)). Файлы, пропущенные старой версией
только из-за формата, читаются при следующем sync. Переименование не превращает бинарный файл
в текст. Docs включает основной текст, таблицы и сноски; не включает колонтитулы, комментарии,
изображения и предложенные правки. Текст поиска и Markdown Google — разные представления:
проверьте экспорт, если важны оформление или вкладки. Проверяйте причину каждого пропуска.

Нечитаемый файл всё равно сохраняется с названием, типом, размером, владельцами и ссылкой, без текста.
`drive personal sync` считает такие файлы в `names_only` и показывает причины в `skipped`. `search` находит
их по названию, а `not_read` содержит причину: открывайте `source_url`, не цитируйте отсутствующий
текст. Поиск по смыслу их игнорирует. Они уходят из индекса при удалении, переносе за выбранные корни
или попадании в корзину. Когда формат или предел позволяют чтение, следующий sync заменяет запись текстом.

## Импортировать папку и проверить охват

```text prompt
Use drive CLI with profile personal. Import the Google folder I select and its subfolders.
Show how many documents were imported, what was skipped and whether work remains.
Do not create extra export files or change anything in Google Drive.
```

Для ручного запуска замените `FOLDER_ID` идентификатором или полным URL папки:

```sh
drive personal files list --parent FOLDER_ID --json
drive personal folders add https://drive.google.com/drive/folders/FOLDER_ID
drive personal sync --limit 200 --json
drive personal status --json
drive personal documents list --json
```

Успешный импорт показывает документы со стабильными Google ID и исходными ссылками.
Если есть незавершённые операции, снова выполните `drive personal sync`: сохранённая работа
продолжится. Прерванный первый обход папок тоже возобновляется по сохранённой контрольной точке.
`sync --rescan` начинает обход заново. Обработанные файлы сохраняются пакетами; после аварийного
завершения последний пакет может быть обработан повторно. Первый обход рекурсивный; `files list --parent` показывает только непосредственных
детей. Если есть следующая страница, её токен находится в `page.next_cursor`; передайте его в `files list --cursor TOKEN`.

`folders list` показывает выбранные корни. `catalog tree` — сохранённую иерархию,
а `catalog list "parent:FOLDER_ID"` — непосредственных детей без Google. Документы в текстовом
индексе сгруппированы по аккаунту; перемещение в Google не меняет локальную ссылку.
Одинаковые названия безопасны: выбирайте источник по ID.

Эти же импортированные документы доступны для [поиска оснований о проекте через Memo](./recipes.md#gather-project-context-with-memo).
Сначала синхронизируйте выбранные папки: просмотр файла через подключённое приложение сам по себе
не сохраняет его в Memo. Используйте одну общую базу в обоих инструментах и явно выберите
импортированный профиль Drive.

## Читать содержимое и метаданные без сети

После импорта эти команды читают локальную копию и не обращаются к Google:

```sh
drive personal --offline documents list --json
drive personal --offline documents show DOC_ID --json
drive personal --offline documents context DOC_ID --json
drive personal --offline identities list DOC_ID --json
drive personal --offline search 'budget' --exact --json
```

`documents list` возвращает сохранённые названия, ID, исходные ссылки, типы MIME, родительские ID,
владельцев и последнего редактора, а также даты и версии, если их предоставил Google.
`documents show` добавляет индексированный текст и ID/названия вкладок. `documents context`
добавляет локальные метки, заметки, связи и память. Читайте сохранённое содержимое напрямую;
открывать ссылку Google необязательно.

Без сети доступна последняя сохранённая версия, а не новая проверка Google. `status` показывает
последний sync и незавершённую/пропущенную работу. Полные списки разрешений, комментарии, ревизии,
действия и произвольные ответы API не кешируются автоматически. `files get` и `documents get`
читают Google, в отличие от сохранённой `documents show`; `--offline` их запрещает.

Sync запрашивает все доступные поля метаданных файла и сохраняет ответ в `provider_metadata`
записи каталога. Google показывает только разрешённые аккаунту поля. Старые записи сохраняют
прежний нормализованный набор; `sync --rescan` обновляет метаданные из Google.

## Просмотреть и организовать каталог

**Каталог** — сохранённый список файлов и папок Google, их метаданных и родительских связей. Он помогает найти источник, даже если содержимое ещё не скачано или не читается. Sync заполняет каталог после обнаружения файлов, перед обработкой ограниченной порции содержимого.

Для прежнего импорта перенесите метаданные из кеша без Google и дополнительных скачиваний:

```sh
drive personal catalog import --offline
drive personal catalog tree --offline
drive personal catalog list 'parent:FOLDER_ID' --offline --json
drive personal catalog show FILE_ID --offline --json
drive personal catalog search 'budget AND kind:file' --offline --json
drive personal catalog list 'person:Rin* AND mime:"application/pdf"' --offline --json
```

`catalog import` копирует метаданные из контрольной точки синхронизации: не обнаруживает новые файлы Google и не продвигает курсор sync. Он включает незавершённые источники и исключает ожидающие удаления. Если `entries` равно нулю и папка ещё не синхронизирована, сначала импортируйте её выше. Для свежих или более полных метаданных выполните `sync --rescan` с сетью.

`tree` начинает с выбранных корней или принимает ID папки. `--depth 3` ограничивает глубину потомков; `truncated: true` означает, что у ветки есть ещё дети. Узлы компактные; полные метаданные показывает `show`. Списки принимают `--limit` и `--page`, а `has_more` сообщает о продолжении. Общий язык запросов поддерживает `kind:folder`, `parent:FOLDER_ID`, `tag:follow-up`, `mime:"application/pdf"` и операторы `AND`, `OR`, `NOT`. `person:Rin*` ищет префикс имени, адреса почты или Google ID наблюдаемого владельца либо последнего редактора; полное имя для точного совпадения заключите в кавычки. Обычные слова ищут названия, описания и типы. Это отдельный поиск метаданных, а не поиск текста/смысла и не `documents list person:PERSON_UID`, который выводит документы, связанные с сохранённым человеком.

Запись возвращает стабильную ссылку `document:<id>`, в том числе для папки Google: это не означает, что у папки есть текст документа. Проверяйте `kind` и `content`: `metadata` — без индексированного текста, `indexed` — текст сохранён, `unreadable` — сохранены название и причина неудачного чтения. Эти состояния не обещают полного извлечения.

Папке можно назначить тег, сохранить рядом заметку или связать с существующим проектом:

```sh
drive personal catalog tags add FOLDER_ID project follow-up --offline
drive personal catalog list 'tag:follow-up' --offline --json
drive personal notes add FOLDER_ID 'Ask Rin which files are final' --offline
drive personal relationships add FOLDER_ID project:PROJECT_ID --kind related-to --offline
drive personal documents context FOLDER_ID --offline --json
```

Используйте Google ID или URL и ссылки проектов из той же локальной базы. Теги, заметки и связи используют общие записи знаний. Теги папки не переходят к детям и не меняют метки либо разрешения Google. Переименование и перемещение сохраняют ссылку. Источники вне выбранной области уходят из активного каталога; сверка метаданных сохраняет их идентичность и аннотации. Обычные задания удаления содержимого по-прежнему удаляют исходный текст и теги документа по правилам индекса.

Каталог каждого аккаунта изолирован. Завершённая область содержит не больше 10 000 записей; метаданные и вывод дерева ограничены. Если обход превышает предел, выберите более узкие корни.

## Поддерживать индекс актуальным

```sh
drive personal sync --json
drive personal status --json
```

Sync опрашивает ленту изменений Google. Повторяйте его после правок или перед ответом, требующим
актуальных данных; фонового наблюдателя нет. `--limit` ограничивает операции текущего запуска,
а не итоговый размер папки. `--rescan` заново сверяет папки со свежим токеном изменений.
Неизменившийся текст сохраняет идентичность и векторы. Переименование сохраняет ID; выход
за выбранные корни или удаление в Google исключает документ из поиска после сверки.
Изменение или удаление источника помечает активную память устаревшей.

Один sync читает не больше 10 000 записей выбранных папок и 10 000 изменений. Если изменений
больше, повторный обход с `--rescan` помогает, пока папки укладываются в 10 000 записей;
иначе выберите меньше папок или более узкие корни.

## Диск: индекс без каталога экспортов

Обычная синхронизация не создаёт пользовательскую папку скачанных файлов. Она хранит:

- поисковый текст, фрагменты и необязательные векторы в локальной базе;
- JSON-снимок с метаданными/вкладками и Markdown-снимок каждого документа;
- родителей папок, контрольные точки и незавершённые задания в состоянии профиля.

Снимки нужны для локального чтения, экспорта и проверки доказательств памяти. Они сохраняются:
режима скачать→проиндексировать→удалить и автоматической очистки снимков пока нет.
Ручное удаление ломает эти сценарии, даже если текст ещё доступен в поиске.
Чтобы избежать дополнительных копий, читайте кеш и экспортируйте только нужное другому инструменту.

База по умолчанию общая с другими инструментами WireCat. `DRIVE_STATE_DIR` определяет
снимки и контрольные точки, `MESSAGING_STORE` — базу. `DRIVE_CACHE_DIR` не перемещает снимки.
См. [настройки хранения](./configuration.md). Без экспортов текст и векторы всё равно занимают диск;
сохранить поисковое содержимое без локального хранения нельзя. При смене базы сначала
[проверьте и скопируйте контекст](./recipes.md#keep-notes-when-changing-databases), а не удаляйте старый
файл. Структурированные связи и аннотации сохраняются; ссылки внутри обычного текста не переписываются.

## Добавить теги и заметки

Замените `DOC_ID` идентификатором Google импортированного источника:

```sh
drive personal tags add DOC_ID budget follow-up
drive personal notes add DOC_ID 'Ask Rin to confirm the revised totals'
drive personal search 'budget AND tag:follow-up' --exact --json
drive personal documents context DOC_ID --json
```

Теги, заметки и связи — локальный контекст; они не меняют Google-оригинал и переживают обычное
переименование и повторную синхронизацию. `documents context` объединяет заметки, метки, связи,
память и наблюдаемых редакторов. Проверенные факты и связи с людьми/проектами описаны в [сценариях](./recipes.md).

## Экспортировать или прекратить импорт

```sh
drive personal documents export DOC_ID --output ./decision.md
drive personal folders remove FOLDER_ID
drive personal sync --json
```

Экспорт не перезаписывает существующий файл. Удаление корня сверяет снимки и индексированные
источники при следующем sync; источники в другом выбранном корне сохраняются.
Оригиналы Google и самостоятельные экспорты остаются. Сверка не обещает уменьшение SQLite-файла
или удаление каждой отдельно созданной заметки.

Убедитесь, что список и поиск соответствуют выбранным источникам. Продолжите с
[поиском](./search.md) либо [полными сценариями](./recipes.md).

## Структурированный вывод

JSON и JSONL позволяют другому инструменту читать результаты без разбора текста терминала.
Можно оставить только нужные ему поля, сохранив сведения о страницах и полноте результата.

Ответы команд в машинном формате используют оболочку: `item` для одного или составного результата,
либо `items` с `page` для списка; `meta` содержит идентификатор вызова, его длительность
и статус `complete`. Ключи Drive записаны в snake_case. Метаданные провайдера и пользовательские
словари сохраняют свои ключи. Фрагменты поиска находятся в `item.hits`, счётчики sync/status — в `item`.
Справка и дополнение оболочки остаются текстовыми; `commands --json` использует общее дерево
команд с контрактом `3`. Поле `effects` описывает чтение и запись удалённых и локальных данных,
а `api_operation` указывает сгенерированный метод Google. Локальные списки используют `page.mode: "page"`
и возвращают `next_page`, если остались результаты. Списки Google
(`files list`, `comments list`, `permissions list`, `revisions list`, `shared-drives`, `documents history`)
используют `page.mode: "cursor"` и возвращают `next_cursor`. Поиск и списки заметок используют `--page`,
а не `--offset`. JSONL выводит записи `{"type":"item","data":…}`, затем одну запись
`{"type":"end",…}` со статусом `complete` и метаданными страницы. Ошибки содержат `error.retry.safe`, а код
завершения процесса называет вид ошибки (`2` неверный ввод, `4` вход не выполнен, `5` действие не разрешено,
`6` не найдено, `9` истекло время; полная таблица — в разделе [коды завершения](./commands.md#exit-codes));
если исход удалённой записи неизвестен, проверьте его до повтора. MCP явно показывает управляющие
символы.

Для нескольких полей каталога используйте `--json=id,name` вместо `--json`. Точечные пути выбирают вложенные объекты и массивы: `--json=hits.ref,hits.excerpt` оставляет
фрагменты поиска в `item.hits`. Пути отсчитываются от данных ответа. Оболочка, страницы,
охват источников, следующие шаги, отсутствующие данные и сведения о выполнении сохраняются.
Выбор полей уменьшает вывод, а не объём просмотренных данных.
Такой же выбор работает с `--jsonl`. Неизвестное поле верхнего уровня вызывает ошибку со списком
доступных полей. Для записи без объявленных полей результата используйте обычный `--json`;
выбор полей отклоняется до выполнения записи.

В интерактивном терминале команды с объявленными полями результата просят назвать поля при запросе
JSON. Для обычного чтения не указывайте `--json` или выберите поля явно. Агенты и каналы вывода
могут использовать обычный `--json` для полного результата.

Аргументы операций и параметры вывода приведены в [справочнике команд](./commands.md).
