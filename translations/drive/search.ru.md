---
title: "Найти документ"
---

Найдите решение, фрагмент или вопрос для проверки в импортированных документах. Руководство
поможет искать по словам и смыслу, сужать результаты локальными тегами и читать основания без
открытия каждого файла Google. Поиск использует локальную копию; для свежих правок нужна синхронизация.

Результат — фрагмент индексированного источника со ссылкой на запись, названием и исходной
ссылкой. **Поиск по словам** сопоставляет слова запроса; **поиск по смыслу** использует локальные
эмбеддинги для близких формулировок. Ни один режим не расширяет импорт и не загружает файлы Google.

```text prompt
Use drive CLI with profile personal to find the budget decision in my imported project documents.
Show the matching passage and original Google link. Tell me which selected sources were skipped.
```

## Выбрать поиск

| Что вы помните | Как искать |
| --- | --- |
| Характерное слово | `drive personal search 'budget' --exact --json` |
| Одну из двух тем | `drive personal search 'budget OR launch' --exact --json` |
| Помеченный вопрос для проверки | `drive personal search 'budget AND tag:follow-up' --exact --json` |
| Вопрос, а не точную формулировку | Подготовьте локальные эмбеддинги и ищите обычным вопросом |
| Человека, связанного с источником | Используйте `documents list --person person:PERSON_ID`, затем прочитайте источники |

Метаданные доступны в деталях и списках документов; это не универсальный API поиска по полям.
Используйте локальные теги и поддерживаемые фильтры людей/списков, а не выдуманные поля Google
в текстовом запросе. Поиск не индексирует комментарии, разрешения и историю ревизий Google.

Для ручного использования:

```sh
drive personal search 'budget decision' --exact --json
drive personal search 'budget AND tag:follow-up' --exact --json
drive personal documents show DOC_ID --json
drive personal tags list DOC_ID --json
```

Замените `DOC_ID` идентификатором Google из результата. `--exact` ищет слова. Документ содержит
ID, заголовки и текст вкладок, таблицы и сноски. Колонтитулы, комментарии, изображения
и предлагаемые правки не индексируются. `tag:follow-up` ищет локальные метки отдельно либо со
словами. У `drive personal search` нет флага `--tag`; поля только для сообщений не поддерживаются.

## Искать по смыслу

Drive использует общий кеш локальной поисковой модели. Если используете Telegram или MAX,
подготовьте модель этим инструментом и создайте векторы импортированного текста:

```sh
tg personal models text download e5-small
drive personal sync --embed
drive personal search 'what did we agree to spend?' --json
```

Модель скачивается через сеть; векторы создаются локально. Drive не скачивает отсутствующую
модель автоматически. Поиск по словам работает без неё. Пустой результат означает отсутствие
совпадения среди импортированного, а не отсутствие документа в Google Drive.
См. [проблемы синхронизации](./troubleshooting.md).

## Проверить, что участвовало в поиске

`--limit` ограничивает число результатов, `--offset` пропускает указанное количество;
охват источников не расширяется. Поиск не загружает файлы из Google. Для свежего ответа
выполните `drive personal sync` и проверьте `drive personal status --json`. Для чтения кеша без сети:

```sh
drive personal --offline search 'budget' --exact --limit 10 --offset 0 --json
drive personal --offline documents show DOC_ID --json
```

Прочитайте сохранённый фрагмент и метаданные перед выводом о решении. Для свежей версии откройте
исходную ссылку Google. Если видите `meaningSkipped`, проверьте причину: смысловой поиск мог не
выполняться. Сканированные PDF, Slides, изображения и другие нечитаемые форматы не имеют текста;
по названию они находятся, но `not_read` содержит причину (для прочитанного файла `null`).
Открывайте `source_url`, не цитируйте отсутствующий текст. См. [форматы](./usage.md#which-document-types-are-searchable)
и [сценарии](./recipes.md#refresh-a-project-and-prepare-a-meeting-brief).

## Искать изображения по содержимому

Если в профиле включён `pictureSearch`, команда `drive personal search "cat on a sofa"`
возвращает также `pictures`: изображения, ближайшие по содержимому к запросу, с `ref`, `score`,
`title` и `source_url`. Это отдельный список, не часть `hits`. При выключенной настройке поля `pictures` нет.

Запросы изображений пишите по-английски: модель понимает только английский; агент сначала
переводит вопрос. Если модель не скачана, `pictures_skipped` сообщает об отсутствии модели;
обычные `hits` не меняются.

Перед включением следуйте [подготовке общей модели](./configuration.md#change-and-check-a-value).
