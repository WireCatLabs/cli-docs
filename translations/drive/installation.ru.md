Настройте Drive на компьютере, где вы или ваш ИИ-агент будете им пользоваться. В результате
аккаунт Google будет подключён, а небольшая папка сохранена локально для поиска по документам.
Drive — инструмент командной строки: его можно запускать в терминале самостоятельно или поручать агенту.

Пройдите три шага: [установите Drive](#install-the-tool), [подключите Google](#connect-your-account),
затем [импортируйте папку и проверьте поиск](#check-your-first-result). Уже установили? Начните с шага 2.
Уже вошли в аккаунт? Начните с шага 3.

Нужны аккаунт Google с доступом к папке и компьютер с Windows, macOS или Linux.
Установка, вход в браузере и команды агента должны выполняться на одном компьютере.
Агенту, который помогает с настройкой, нужен доступ к терминалу на нём.

## 1. Установить Drive

**Выберите один из двух вариантов ниже.** Оба устанавливают один и тот же инструмент;
когда он заработает, переходите к шагу 2. Установка пакета не входит в Google и не скачивает файлы.

### Вариант A: попросить агента

Скопируйте этот запрос агенту с доступом к терминалу:

```text prompt
Use drive CLI. Установи @wirecat/drive-cli из npm на этом компьютере.
Сначала проверь Node.js и npm; если нужно, помоги установить поддерживаемую версию Node.js.
Проверь, что drive --version и drive --help работают, затем сообщи, что установка завершена.
```

Когда агент подтвердит, что команда работает, **пропустите вариант B и переходите к
[шагу 2](#connect-your-account)**. Агент может выполнять команды шагов 2 и 3 за вас;
аккаунт Google выбираете вы и сами подтверждаете доступ в браузере.

### Вариант B: установить самостоятельно

Откройте Terminal в macOS/Linux или PowerShell в Windows. Если PowerShell блокирует `npm.ps1`,
используйте `npm.cmd` вместо `npm` в командах ниже. Проверьте Node.js и npm:

```sh
node --version
npm --version
```

Нужен **Node.js 22.16+ в ветке 22.x или Node.js 24+**. Если команды нет или Node.js старее,
[установите Node.js](https://nodejs.org/en/download), откройте терминал заново и повторите проверку.
Node.js запускает Drive, а npm скачивает и устанавливает пакет.

Установите пакет и проверьте его:

```sh
npm install -g @wirecat/drive-cli
drive --version
drive --help
```

Должны появиться версия и справка с доступными командами. Пакет npm готов к запуску;
собирать исходники не нужно. Если `drive` не находится, откройте терминал или агента заново
и повторите проверку;
если не помогло, см. [проблемы установки](./troubleshooting.md).

Когда проверки пройдут, переходите к [шагу 2](#connect-your-account).

## 2. Подключить аккаунт

**Приложение Google от WireCat уже готово к использованию.** Для этого варианта не нужно создавать
проект Google Cloud или скачивать файл учётных данных. Каждый пользователь разрешает доступ
к своему аккаунту в браузере.

Если предпочитаете своё приложение Google, сначала пройдите [необязательную настройку приложения](#prepare-google-sign-in).
Её последняя команда запускает вход с вашим клиентским файлом и возвращает к подтверждению
в браузере ниже. Если файл уже есть, переходите сразу к [последнему шагу настройки](#sign-in-with-your-own-client).

### Запустить вход через приложение WireCat

Выберите **профиль** — локальное имя для этого аккаунта. В примерах используется `personal`;
замените его везде, если предпочитаете другое имя, например `work`. Каждая команда для аккаунта
указывает профиль.

Выполните команду сами или попросите агента. Пока подтверждаете вход, оставьте процесс в терминале открытым:

```sh
drive personal session start
```

### Подтвердить доступ в браузере

1. В открывшемся браузере выберите аккаунт Google, который хотите подключить.
2. Проверьте запрашиваемые разрешения и подтвердите доступ. По умолчанию запрашивается
   только чтение Drive; разрешения редактировать файлы Google этот вход не даёт.
3. Дождитесь подтверждения в браузере и вернитесь в терминал. Вход завершён, когда команда
   показывает `signed_in: true` для `personal` и возвращает приглашение терминала.
   Одного согласия в браузере для окончательной проверки недостаточно.

### Проверить сохранённый профиль

```sh
drive personal session list --json
```

Найдите `personal` в списке профилей. Команда показывает локальную конфигурацию без токенов;
она не обращается к Google и не проверяет, действителен ли прежний вход. Импорт на шаге 3
проверит доступ к выбранной папке. Переходите к [шагу 3](#check-your-first-result).

Если браузер не открылся, повторите вход с `--no-browser` и откройте выведенную ссылку
на том же компьютере. Если команда сообщает об отсутствии ключницы, см.
[восстановление подключения](#connection-repairs) ниже. Не вставляйте токены доступа или содержимое
файла учётных данных в разговор с агентом.

## 3. Импортировать папку и проверить поиск

Выберите небольшую папку Google Drive с Google Doc или файлом Markdown/TXT, текст которого знаете.
Так проще проверить импорт и поиск, прежде чем добавлять больше файлов. Сам вход в аккаунт
не импортирует весь Drive.

1. **Выберите папку.** Откройте её в Google Drive и скопируйте URL из адресной строки. Замените
   пример ниже своим адресом и выполните:

   ```sh
   drive personal folders add https://drive.google.com/drive/folders/FOLDER_ID
   ```

2. **Импортируйте выбранную папку и её подпапки.** Выполните команды по порядку:

   ```sh
   drive personal sync --json
   drive personal status --json
   drive personal documents list --json
   ```

   В списке должен появиться ожидаемый документ, а статус должен показать `pending: 0`.
   Если осталось задание, повторите sync. Импорт сохраняет содержимое, метаданные и структуру
   папок локально; файлы Google не редактируются. См. [форматы и хранение](./usage.md), чтобы
   узнать, что сохраняется для каждого формата.

3. **Найдите знакомое слово.** Замените `budget` словом из импортированного документа:

   ```sh
   drive personal search 'budget' --exact --json
   ```

   Поиск должен вернуть фрагмент и ссылку на оригинал. Эта первая проверка ищет по тексту,
   сохранённому на этом компьютере. Если ничего не найдено, проверьте список документов
   и незавершённые задания, затем попробуйте другое слово; см. [пустые результаты поиска](./troubleshooting.md).

Теперь подключение работает, а локальная папка доступна для поиска. Продолжите со
[сценариями для агента](./recipes.md) или [чтением и организацией сохранённых документов](./usage.md).
Разделы ниже — необязательная настройка и обслуживание, а не продолжение первого импорта.

## Восстановить подключение

Учётные данные обычно хранятся в системной ключнице — приватном хранилище паролей.
Если она недоступна, добавьте `--credential-storage file` к команде входа, чтобы явно выбрать
приватное хранение в файле. Для второго аккаунта повторите шаг 2 с другим профилем, например `work`.

Если Google блокирует вход, проверьте показанную ошибку и правила администратора Workspace.
Для своего приложения в Testing убедитесь, что аккаунт добавлен как тестовый пользователь.
Выберите свой симптом в [решении проблем подключения](./troubleshooting.md); для приложения
по умолчанию не нужно изменять проект Google Cloud.

## Необязательно: своё приложение Google

Этот вариант нужен, если вы хотите входить через приложение под вашим управлением.
Приложение Google — регистрация, которая запрашивает разрешение; это не сам аккаунт Google.
JSON Desktop-клиента определяет приложение, а согласие в браузере предоставляет доступ к аккаунту.
Ключ API или сервисного аккаунта не заменяет этот файл.

Откройте шаги ниже либо переходите к [входу со своим клиентом](#sign-in-with-your-own-client),
если уже скачали JSON Desktop-клиента.

### 1. Выбрать проект и включить API

Откройте [Google Cloud Console](https://console.cloud.google.com/). Через выбор проекта в верхней
панели откройте существующий проект либо нажмите **New Project**, задайте имя и создайте его.
На всех следующих экранах оставляйте выбранным этот же проект.

Если API уже включены, переходите к Branding. Иначе откройте **☰ → APIs & Services → Library**.
Найдите каждый API, откройте страницу и нажмите **Enable**. Проверьте **Enabled APIs & services**:

| API | Что даёт | Когда нужен |
| --- | --- | --- |
| [Google Drive API](https://console.cloud.google.com/apis/library/drive.googleapis.com) | Папки, файлы, экспорт, комментарии, версии и разрешения | Всегда |
| [Google Docs API](https://console.cloud.google.com/apis/library/docs.googleapis.com) | Все вкладки документов, создание и редактирование Google Docs | Всегда |
| [Google Sheets API](https://console.cloud.google.com/apis/library/sheets.googleapis.com) | Чтение актуальных вкладок/диапазонов и изменение ячеек/формул | Необязательные команды Sheets; не нужен для импорта через XLSX |
| [Google Drive Activity API](https://console.cloud.google.com/apis/library/driveactivity.googleapis.com) | События и участники изменений | Необязательный `--grant activity`; включите для всех функций общего приложения |

Включение API делает его доступным проекту, но не предоставляет доступ пользователю.
Sheets использует существующие разрешения Drive на чтение и запись. Текущий коннектор не использует API Slides, People и Gmail.

### 2. Настроить экран согласия: Branding

Откройте **☰ → Google Auth platform → Branding** либо
[прямую ссылку на Branding](https://console.cloud.google.com/auth/branding). Здесь определяется,
что люди увидят, когда Google предложит разрешить доступ вашему приложению.

Если платформа не настроена, нажмите **Get Started**. Заполните экраны: имя приложения
(например, Personal Drive), адрес поддержки, аудитория **External** для аккаунтов вне вашей
организации Workspace и контактный адрес. Завершите шаг с политикой Google и создайте
конфигурацию. Если она уже есть, измените поля в Branding. Используйте имя и контактные данные своего приложения. Общедоступная публикация и требования
проверки Google — отдельная задача; при публикации для других пользователей следуйте официальной
инструкции. Чтобы подключиться через существующее приложение WireCat, не нужно настраивать его
домены или оформление.

[Официальная инструкция экрана согласия Google](https://developers.google.com/workspace/guides/configure-oauth-consent)
объясняет Branding, Audience и Data Access.

### 3. Разрешить тестовый вход своему аккаунту

Откройте **Google Auth platform → Audience**
([прямая ссылка](https://console.cloud.google.com/auth/audience)). Для External-приложения в
Testing нажмите **Test users → Add users**, добавьте подключаемый аккаунт и сохраните.
Для первой проверки достаточно Testing. Общедоступная публикация — отдельная задача владельца.
Тестовые разрешения обычно истекают через семь дней; подключитесь снова по запросу Google.

### 4. Объявить разрешения

Откройте **Google Auth platform → Data Access**
([прямая ссылка](https://console.cloud.google.com/auth/scopes)). Нажмите **Add or Remove Scopes**,
выберите нужные разрешения ниже и обновите/сохраните список. Если разрешения нет в таблице,
используйте поле ручного ввода scope.

| Разрешение | Для чего в CLI |
| --- | --- |
| `https://www.googleapis.com/auth/drive.readonly` | Импорт папок и чтение по умолчанию |
| `https://www.googleapis.com/auth/drive` | Создание/редактирование/управление в Google с `--grant write` |
| `https://www.googleapis.com/auth/drive.activity.readonly` | Необязательная история с `--grant activity` |
| `https://www.googleapis.com/auth/drive.apps.readonly` | Метаданные установленных приложений Drive с `--grant apps` |

Для личной проверки чтения достаточно первого scope. Общее приложение объявляет и те
необязательные разрешения, которые будет предлагать; CLI запрашивает их только с нужными
флагами. Текущие методы принимают разрешения Drive, отдельный Docs scope не нужен.
Выбор папок ограничивает локальный импорт; разрешение Google на чтение охватывает Drive аккаунта.
См. [разрешения Drive](https://developers.google.com/workspace/drive/api/guides/api-specific-auth)
и [разрешения Docs](https://developers.google.com/workspace/docs/api/auth).

### 5. Создать Desktop-клиент и скачать JSON

Откройте **Google Auth platform → Clients**
([прямая ссылка](https://console.cloud.google.com/auth/clients)). Нажмите **Create Client**,
выберите **Application type → Desktop app**, задайте понятное имя и нажмите **Create**.

В окне созданного клиента нажмите **Download JSON**. Если закрыли его, вернитесь в Clients,
откройте Desktop-клиент и используйте кнопку скачивания JSON. Имя файла обычно начинается с
`client_secret_`. Сохраните его вне репозитория и запишите полный путь, например
`/home/YOUR_USER/Downloads/client_secret_…json`. Можно переименовать его в
`wirecat-drive-desktop.json`, чтобы путь был удобнее.

Desktop-клиент использует временный localhost callback CLI. Не создавайте Web application
и не добавляйте веб-адрес перенаправления для этого входа. См.
[официальную инструкцию Desktop OAuth](https://developers.google.com/workspace/guides/create-credentials#desktop-app).
Скачанный JSON содержит раздел приложения `installed`. Это не токен доступа.
Передавайте агенту только путь, а не содержимое.

### Войти со своим клиентом

Замените путь полным путём к скачанному JSON-файлу. Выберите имя профиля, как на шаге 2,
и выполните:

```sh
drive personal session start --client-file /absolute/path/to/desktop-client.json
```

Вернитесь к разделу [Подключить аккаунт](#connect-your-account), начиная с
[подтверждения в браузере](#approve-access-in-your-browser), затем проверьте сохранённый профиль
и пройдите шаг 3. Теперь используется ваше приложение вместо приложения WireCat.

## Другие способы установки

Это альтернативы npm из варианта B, а не дополнительные шаги. Если уже используете pnpm,
установите так:

```sh
pnpm add -g @wirecat/drive-cli
```

Если используете Bun как менеджер пакетов, установите так:

```sh
bun add -g @wirecat/drive-cli
```

Затем проверьте `drive --version` и `drive --help` и переходите к шагу 2. Чтобы посмотреть справку
без глобальной установки, используйте `npx @wirecat/drive-cli --help`; шаги выше предполагают глобальную установку.

[Официальное руководство репозитория](https://github.com/WireCatLabs/drive-cli/blob/main/docs/installation.md)
служит источником этих инструкций.

## Обновить или удалить

Эти команды нужны для уже установленного инструмента. Для обновления:

```sh
npm install -g @wirecat/drive-cli
drive --version
```

Для выхода из профиля выполните `drive personal session end`. Чтобы удалить команду:

```sh
npm uninstall -g @wirecat/drive-cli
```

Выход и удаление оставляют локальную конфигурацию и импортированные данные на месте. Прежде
чем перемещать или удалять их, см. [где хранятся файлы](./configuration.md#where-the-files-live).
