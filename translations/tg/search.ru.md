---
title: "Поиск сообщений"
---

`tg messages search` находит сообщения в локальном архиве — копии ваших чатов, которую tg хранит на этом
компьютере, — а также обращается к поиску Telegram ([ниже](#asking-telegram-too---backend)). Команда не помечает сообщения прочитанными.

## Сначала подготовьте архив

Для полноценного поиска нужно загрузить ваши чаты. Поиск Telegram находит сообщение по словам, даже если tg
его ещё не загрузил, но все остальные возможности работают только с архивом: подсчёт через `stats`, поиск по темам, `has:`,
`filename:`, регулярные выражения, предустановки, теги и ранжирование словоформ. Начните с загрузки всех чатов:

```sh
tg store fetch --all --background     # the last 90 days of every chat, as a background job
tg store jobs show                    # how far it got
```

По умолчанию каждый запуск загружает не более 1 000 сообщений из каждого чата; повторите его, чтобы продолжить загрузку активных чатов.
Добавьте `--since-time 365d`, чтобы загрузить более старую историю, или загрузите один чат командой `tg store fetch "Book club"`
([архив](./archive.md)). Затем `tg serve` поддерживает архив в актуальном состоянии.

Каждый поиск сообщает, какие данные он проверил. В терминале, если в архиве может не хватать данных или ничего не
найдено, одна строка показывает число проверенных сообщений и чатов, число чатов, которые ещё ни разу не загружались или
отстают от актуального состояния, и команду для исправления ситуации:

```text
searched 12,430 messages in 37 chats — 5 never fetched; `tg store fetch --all --background` fetches them
```

С `--json` поле `coverage` содержит те же сведения: `messages`, `chats`, до десяти чатов в `attention` и `next`.
Если агент ничего не нашёл, но поле `next` заполнено, он должен выполнить указанную в нём команду или спросить вас, прежде чем утверждать,
что сообщение не существует.

Здесь описан повседневный поиск. Ещё три страницы идут дальше:

- [Поиск по теме](./topic-search.md) — найти обсуждение по тому, о чём оно было, если вы не помните
  слов.
- [Язык запросов](./query-language.md) — все поля, операторы, лимиты и JSON-ответ.
- [Как устроен поиск](https://wirecat.dev/en/docs/search-architecture) — техническая страница: словарный
  индекс, граф разговоров, векторы и ранжирование результатов.

Заключайте запрос в одинарные кавычки, чтобы оболочка не трогала его кавычки и скобки. Имена ниже —
примеры; подставляйте свои чаты и людей.

## Слова и фразы

```sh
tg messages search invoice
tg messages search '"invoice paid"'              # words together
tg messages search 'cafe OR library'
tg messages search '(cafe OR library) NOT loud'
tg messages search 'invoic*'                     # every word that starts with "invoic"
```

Все слова, записанные рядом в запросе, должны присутствовать в сообщении. Поиск учитывает словоформы согласно
языковым настройкам архива: `piso` может найти `pisos`. Кавычки сохраняют слова вместе, но также допускают
словоформы. Используйте `exact:piso` или добавьте `--exact` для слов без явно указанного поля. Явное
`text:` по-прежнему учитывает словоформы. Регистр и диакритические знаки
игнорируются. Опечатки автоматически не исправляются.

## Люди и чаты

```sh
tg messages search 'from:"Alice Synthetic" invoice'
tg messages search 'from:("Alice Synthetic" OR "Bob Synthetic") library'
tg messages search 'from:me date:7d'             # what you wrote this week
tg messages search 'chat:"Book club" library'
tg messages search library --chat "Book club"    # the same, as an option
tg messages search 'passport kind:private'       # one-to-one chats only
```

`kind:` принимает `private`, `group`, `channel`, `saved` («Избранное») и `bot`. `topic:` ограничивает поиск одной
темой форума в группе; для него нужна эта группа в `chat:` или `--chat`.

## Даты

```sh
tg messages search 'date:today'
tg messages search 'library date:yesterday'
tg messages search 'invoice date:7d'             # from 7 days ago until now; also 30m, 2h
tg messages search 'invoice date:[2026-01-01 TO 2026-02-01}' --timezone Europe/Madrid
```

`today`, `yesterday` и календарные даты — это дни в часовом поясе вашего компьютера; `--timezone` выбирает
другой. В диапазоне `[` и `]` включают этот день, `{` и `}` — исключают.

## Файлы и ссылки

```sh
tg messages search 'has:file'
tg messages search 'filename:*.pdf'
tg messages search 'filename:*contract*'         # part of the name
tg messages search 'size>10MB'
tg messages search 'mime:image'                  # any picture sent as a file
tg messages search 'mime:"application/pdf"'      # quote a full type
tg messages search 'has:photo chat:"Book club"'
tg messages search 'has:link AND "github.com"'   # a link to a site
```

Файл находится по имени, размеру и типу, даже если в сообщении нет текста. `filename:` сравнивает
имя целиком, без учёта регистра и диакритических знаков. Размеры — в KB, MB и GB по 1024. `has:` также принимает `attachment`,
`video`, `audio`, `voice`, `sticker`, `contact`, `location` и `poll`. Ссылка учитывается, если она есть в
тексте или только в карточке предпросмотра.

## Пароли, коды и карты

```sh
tg messages search 'preset:secret kind:saved'    # something that looks like a password or token
tg messages search 'preset:card'
```

Пресет находит сообщения, которые *похожи* на пароль, код входа, ключ API, номер карты или IBAN,
паспорт, телефон, адрес почты или ссылку. Проверяется только вид: пресет не доказывает, что пароль
работает или карта настоящая. Полный список — в [языке запросов](./query-language.md#presets).

## Метки

```sh
tg tags add work --chat "Book club"
tg tags add work --contact "Bob Synthetic"
tg tags list --tag work --type chat
tg messages search 'tag:work invoice'
tg messages search 'invoice NOT tag:work'
tg tags remove work --chat "Book club"
```

Метка — ваша собственная пометка на чате, человеке или одном сообщении (`--message <id> --chat <chat>`). Она хранится
только в локальном архиве и никогда не отправляется в Telegram. `tag:work` находит сообщения с меткой `work`,
сообщения в чате с меткой `work` и сообщения от человека с меткой `work`. Метка — от 1 до 32 символов: буквы a–z,
цифры и дефисы.

Группам и каналам можно автоматически назначать теги по их названию, имени пользователя и описанию — без чтения сообщений
и без модели:

```sh
tg metadata refresh --chat "Book club"   # read the chat's description from Telegram; the chat is not changed
tg tags auto --dry-run                   # what it would tag, without writing
tg tags auto                             # write the automatic tags
tg tags list --source auto               # only the automatic ones
```

Автоматические теги не затрагивают ваши: повторный запуск удаляет только устаревшие автоматические теги. Если вы добавите тег,
который уже был назначен автоматически, он станет вашим.

## Сохранённые поиски и история

```sh
tg searches create meetings 'library OR cafe' --chat "Book club"
tg messages search --saved meetings
tg messages search --saved meetings 'date:today'  # extra words are added with AND
tg stats messages show --saved meetings --by day
tg searches list
tg searches history --limit 10
tg messages search --saved 42                    # a row of the history, by its number
```

`searches create` сохраняет запрос с его параметрами и ничего не запускает; для существующего имени нужен `--replace`.
Параметры, указанные вместе с `--saved`, заменяют сохранённые. Сохранённый текст читается заново при каждом запуске, поэтому
`date:7d` всегда означает последние 7 дней. `searches show` выводит один поиск, `searches delete` удаляет его.

Каждый успешный поиск и подсчёт записывается в историю: запрос и его параметры, но никогда не найденные
сообщения. Хранятся 1000 последних запусков. `--no-record` исключает из истории один запуск; в MCP
`tg mcp --no-record` или `record` со значением `false` исключает вызовы сервера; `searches clear` очищает историю и оставляет сохранённые поиски. Эта
история отделена от записей запусков `tg runs`.

Сохранённые поиски и история хранятся в базе, общей для tg и max: оба видят одни и те же записи, и
`delete` или `clear` в одном меняет другой. Метки остаются при своём аккаунте.

## Подсчёт: `stats messages show`

```sh
tg stats messages show invoice                        # how many in each chat
tg stats messages show 'date:7d' --by sender
tg stats messages show 'from:me' --by day --timezone Europe/Madrid
tg stats messages show --by hour                      # every stored message
```

`stats messages show` подсчитывает сообщения, которые нашла бы команда `messages search` с тем же запросом, каждое ровно один раз.
`--by chat` (по умолчанию) и `--by sender` выводят сначала наибольшие значения; `--by day` и `--by hour` выводят результаты
в хронологическом порядке. Если некоторые чаты сохранены не полностью, эти числа — нижняя граница, а stderr сообщает,
сколько таких чатов.

## Поиск также в Telegram: `--backend`

Telegram может искать в своей копии ваших чатов, включая сообщения, которые tg ещё не загрузил. По умолчанию tg обращается
к Telegram и архиву за один запуск (`--backend both`). `--backend server` показывает только результаты Telegram, а
`--backend archive` ищет только в архиве.

```sh
tg messages search 'invoice' --backend both
tg messages search 'invoice chat:"Book club" from:Olga' --backend both
tg messages search 'invoice date:2026-09' --backend server --server-time 10s
```

Telegram сам решает, что соответствует слову, и не документирует эти правила. Поэтому tg рассматривает его ответ как
кандидатов: сохраняет их в архиве и применяет к ним ваш запрос по правилам самого архива.
`exact:`, `-word`, кавычки и ранжирование работают так же, как без `--backend`, а сообщение никогда не
выводится дважды. Если Telegram вернул сообщение, которое не соответствует вашему запросу, оно не показывается, но остаётся в архиве.

Telegram получает только обязательные слова вашего запроса, один чат, отправителя вместе с чатом и даты.
`OR` создаёт до трёх поисковых запросов. Отрицания, подстановочные знаки, `has:`, `tag:` и предустановки tg применяет
после этого. Запрос без слов не обращается к Telegram. tg ждёт не более 5 секунд (`--server-time`,
до 60 с) и получает до 100 сообщений на поисковый запрос; более поздний ответ отбрасывается. Сообщения не помечаются прочитанными.

С `--json` каждое сообщение указывает свой источник (`source`: `archive`, `server` или `both`), а
блок `server` сообщает, что вернул Telegram и какие операции завершились ошибкой. `--backend both` не завершается ошибкой из-за
Telegram: без сети, разрешения или слов команда отвечает из архива и объясняет причину.
`--backend server` в таких случаях отказывается выполнять поиск. Разрешение — `messages.server-search`; профиль только для чтения
отвечает из архива. `stats messages show` подсчитывает только архив: Telegram считает по своим
правилам, а не по вашему запросу.

## Если ничего не найдено

Пустой ответ означает «нет в архиве, где вы искали», а не «никогда не отправлялось». Проверьте сохранённое через
`tg store status` и загрузите больше через `tg store fetch`. С `--json` ответ сообщает, в каких чатах
искали и насколько они полны, даже если совпадений нет. Если tg просит выполнить `tg store migrate`, словарный
индекс ещё строится; поиск без слов (`has:file`, `date:today`) уже работает.

Чтобы искать по всем аккаунтам в базе, добавьте `--source all`. `--newest` сортирует по времени, а не по
релевантности, а `--context 2` показывает по два сообщения вокруг каждого найденного.

## Для скриптов и агентов

`--json` возвращает один объект с сообщениями и сведениями о проверенных данных; `--jsonl` передаёт потоком
только сообщения. В MCP `tg_read` (`command: "messages search"`) и `tg_read` (`command: "stats messages show"`) принимают те же запросы, а команды `tags` и
`searches` через `tg_read`/`tg_write` управляют тегами и сохранёнными поисками. Поля ответа,
старый режим `--language legacy` и `--regex` описаны в разделе [язык запросов](./query-language.md).

По умолчанию поиск по словам обращается к Telegram и локальному архиву; `--backend archive` ограничивает поиск локальными данными.
`--sync-first` явно загружает новые сообщения перед поиском и
не помечает их прочитанными: не более 5 чатов, 500 сообщений и 30 секунд. Измените эти ограничения с помощью `--max-chats`,
`--max-messages`, `--sync-time`. При неудачном или неполном обновлении сохраняются локальные результаты со сведениями об устаревшем охвате и
подробностями обновления.

`content:invoice` ищет в проиндексированном тексте, извлечённом из вложений или переданном агентом. Извлечение поддерживает
обычный текст, Word и PDF с текстовым слоем; для сканов и фотографий текст должен передать агент. Если вложений несколько,
выберите одно через `--attachment`, начиная с 1.

Обычно агент читает изображения и сканы своими инструментами OCR или анализа изображений и записывает текст в этот
индекс. `attachments list --needs-text` возвращает путь к сохранённому файлу, адрес сообщения и номер вложения.
Проверьте сохранение текста поиском `content:`. Путь на сервере MCP не передаёт файл
удалённому агенту: для чтения агенту нужен доступ к самому файлу.

```sh
tg attachments extract --chat "Book club" --download --output-dir ./files
tg messages search 'content:invoice'
tg attachments list --chat "Book club" --needs-text
tg attachments text set "Book club" 204 --text-file ./scan.txt
```

`--download` требует `--output-dir`; без них извлечение читает сохранённые файлы. `list` показывает пути сохранённых файлов и состояние текста, но не сам текст.

Для массовой обработки явно выберите стандартный API шлюза моделей. Настройте доступную модель
для анализа изображений в `models.ocr` и используйте обычную команду для учётных данных `models text key set`. Замените
`your-vision-model` в примере именем вашей модели.

```sh
tg config set models.ocr.provider openai
tg config set models.ocr.model your-vision-model
tg models text key set openai
tg attachments extract --chat "Book club" --ocr --concurrency 4 --limit 100 --json
```

`--ocr` отправляет изображения в этот API; без него модель не вызывается. Число параллельных операций — 1–8, по умолчанию 4;
лимит файлов — 1–500, по умолчанию 100. Передайте полученный курсор, чтобы продолжить сканирование с ограничениями.
Для сканированных PDF нужны необязательные зависимости `unpdf` и `@napi-rs/canvas`; обрабатывается не более 20 страниц на документ.
Страницы с текстовым слоем обрабатываются локально. Повторные запуски используют хеш файла и идентификатор модели. Текст агента и ранее
проиндексированный текст сохраняются при неудачном или отменённом OCR. Проверьте число ошибок и статусы отдельных файлов;
ограничение частоты запросов у провайдера останавливает дальнейшие вызовы API в этом запуске. `--offline` несовместим с `--ocr`.

`--thread` следует по сохранённому графу ответов; в `messages context` он заменяет соседние по времени сообщения. По умолчанию —
8 переходов, 50 сообщений, 65 536 байт и один день вокруг каждого совпадения. Это меняют `--thread-hops`,
`--thread-messages`, `--thread-bytes`, `--thread-within`. Без графа используется контекст по времени;
устаревшие связи отмечаются и не обходятся.

Для извлечения из PDF нужен необязательный `unpdf`, для Word — необязательный `mammoth`, установленные там же, где `tg`. При глобальной установке через npm:
`npm install -g unpdf mammoth`. Об отсутствующих модулях сообщается; вместо них текст может передать агент.

## Файлы, подготовка и пробелы в архиве

`tg attachments extract --chat <chat> --from-dir ./files` читает явно указанный каталог, не
заходя в подкаталоги. Для файла нужно уникальное исходное имя или полный набор имён, присвоенных загрузчиком.
Не сочетайте `--from-dir` с `--download` или `--output-dir`.
`tg messages download <chat> <id> --extract` извлекает текст только из файлов, загруженных этим вызовом;
`--all --extract` применяет то же правило ко всему пакету. Извлечение проверяет изменение байтов по хешу и
сохраняет текст, написанный агентом. Извлечение с ограничениями через MCP возвращает `cursor` для продолжения и метаданные
без текста файлов. Найдите `attachments extract` через `tg_tools_search` и выполните через `tg_write`.

`tg store fetch <chat> --catch-up` после загрузки подготавливает только граф этого чата и установленные локальные векторы.
По умолчанию подготовка выключена; настройка профиля `searchCatchUp: true` включает её, а
`--no-catch-up` переопределяет настройку для одного запуска. Ограничения:
`--catch-up-chunks 500 --catch-up-messages 10000 --catch-up-time 30s`. Команда никогда не загружает модель
и не обращается к удалённому провайдеру. Отдельный результат `prepared` сообщает о неполной подготовке, при этом
загруженная история остаётся сохранённой.

`tg store gaps plan <chat>` локально проверяет пробелы между записанными диапазонами охвата, включающими обе границы.
Отсутствующие идентификаторы сообщений и периоды без активности сами по себе не доказывают нехватку истории; края архива остаются
в состоянии `unknown`. Проверьте план, затем явно запустите `tg store gaps repair <chat> --fingerprint <hash>`.
По умолчанию ограничения — пять пробелов, 500 сообщений и 30 секунд; используйте `--max-gaps`, `--limit`, `--repair-time`,
`--page-size` и `--pause`, чтобы задать ограничения. Повторный запуск устраняет оставшиеся пробелы, не удаляя сообщения,
которые не встретились при загрузке. Страницы с неоднозначными временными метками остаются в ожидании. `--background` использует `store jobs show`, `store jobs list` и `store jobs cancel`.
Те же команды доступны через поиск инструментов MCP и `tg_read` или `tg_write`; метаданные заданий
ограничены профилем. Устранение пробелов требует разрешения на запись `store.gaps.repair` и доступа на чтение сообщений.
Необязательная подготовка использует оставшееся время из лимита устранения пробелов.
