Для входа нужны две составляющие:

- **Приложение**: `api_id` и `api_hash` с [my.telegram.org](https://my.telegram.org/apps). Они идентифицируют программу в Telegram. `tg` сохраняет их в системном хранилище ключей.
- **Сессия**: данные, которые Telegram выдаёт после входа. Они хранятся файлом в каталоге состояния и дают такой же доступ, как пароль.

`tg setup` проводит первый запуск через оба шага, проверяет пять чатов и предлагает skill для агента. Отведите около пяти минут; история загружается отдельно. Запустите команду в терминале. `tg setup --app browser` выбирает ручную регистрацию приложения, `--method phone` — вход по телефону. `tg session start` остаётся командой только для входа, включая продолжение прерванного входа. Настройка проверяет существующую сессию и не выполняет незаметно новый вход, если Telegram её отклонил.

## Приложение с my.telegram.org

Каждый пользователь регистрирует своё приложение. Telegram выдаёт одно приложение на номер телефона, поэтому общий идентификатор не включён в `tg`. Данные нужны один раз для каждого профиля; `tg session start` запрашивает их только при отсутствии.

Есть два способа получить данные:

- **`--app browser`** (по умолчанию) открывает [my.telegram.org/apps](https://my.telegram.org/apps). Войдите, создайте приложение, если его нет (любые название и короткое имя, платформа Desktop), и вставьте `App api_id` и `App api_hash` по запросу `tg`. Хеш при вводе скрыт.
- **`--app auto`** заполняет сайт за вас. Команда запрашивает телефон и код, который my.telegram.org присылает сообщением в Telegram, затем получает существующее приложение или создаёт новое. У сайта нет API: `tg` работает с веб-формой. Изменения сайта могут сломать этот способ; в таком случае используйте `--app
  browser`.

Данные приложения сохраняются только после успешного входа в Telegram.

## Безопасность входа

```sh
tg session start           # a QR code in the terminal
tg session start phone     # a phone number, the code Telegram sends, and your 2FA password
```

**QR-код:** в приложении Telegram откройте Настройки → Устройства → Подключить устройство и отсканируйте код. Пока вы ждёте, код обновляется.

**Телефон:** введите номер в международном формате, затем код входа. Если настроен облачный пароль (2FA), `tg` запросит его со скрытым вводом. При `--app auto` номер спрашивается только один раз.

После входа любым способом в списке сессий Telegram появляется новое устройство.

```text
Logged in as <your name> (@<username>, id <id>) — profile default.
Session:  ~/.local/share/tg-cli/sessions/default.session
App keys: in the keyring
Next:     tg chats list · tg server install to keep the archive current
```

### Если вход запускает агент

У агента может не быть терминала для отображения QR-кода. `--qr-file` сохраняет его в PNG, который агент может показать вам:

```sh
tg session start --qr-file login.png
```

При обновлении кода файл заменяется, а после завершения входа удаляется независимо от результата. Без терминала способ работает только тогда, когда у профиля уже есть данные приложения, а у аккаунта нет пароля 2FA. Иначе нужен ввод пользователя.

## Проверка и выход

```sh
tg account show              # who this profile is logged in as
tg account sessions list     # every device and app logged in to the account; ends nothing
tg session end               # log out on Telegram's side, and delete the session file here
```

`tg session end` завершает сессию **и на стороне Telegram**: устройство исчезает из списка в приложении. Идентификатор и хеш приложения остаются в хранилище ключей, локальная база не меняется.

## Срок действия сессии

Сессия действует до завершения через `tg session end`, список устройств Telegram или самим Telegram при превышении срока неактивности аккаунта (`authorization_ttl_days` в [API Telegram](https://core.telegram.org/method/account.setAuthorizationTTL)). Этот срок настраивается в списке устройств приложения. Профиль, используемый ежедневно, его не достигает. После завершения сессии любая команда сообщает «вход не выполнен или сессия завершена» с кодом `4`; войдите снова через `tg session start` ([Решение проблем](./troubleshooting.md#not-logged-in-or-the-session-was-ended--run-tg-session-start)).

## Профили

Профиль — отдельный вход со своими сессией, приложением, настройками, получателями и записями запусков. Имя указывается **первым словом**, а не параметром:

```sh
tg chats list              # profile "default"
tg work chats list         # profile "work"
export TG_PROFILE=work     # the same for the whole shell session
```

**Первое слово считается профилем, если это не команда.** Поэтому профиль нельзя назвать `chats`, `messages` или другим словом команды; `tg session start` отклоняет такое имя. Разрешены буквы, цифры, точки, дефисы и подчёркивания; первый символ — буква или цифра.

Приоритет: первое слово команды, `TG_PROFILE`, `defaultProfile` в конфигурации, затем `default`.

Слово, которое не является командой и за которым нет команды, вызывает поясняющую ошибку:

```text
"nonsense" is not a command, so it was read as a profile name — and no command followed it.
```

**`TG_PROFILE_LOCK` фиксирует процесс на одном профиле.** Задайте его в окружении агента: другой профиль первым словом или через `TG_PROFILE` будет отклонён с кодом `5`. Без этой переменной агент может выбрать профиль с меньшими ограничениями.

## Где хранятся данные входа

| Данные | Место хранения |
|---|---|
| сессия | `sessions/<profile>.session` в каталоге состояния |
| идентификатор и хеш приложения | системное хранилище ключей, сервис `tg-cli`, запись `<profile>:api` |
| идентификатор и хеш без хранилища ключей | `credentials.json` в каталоге настроек |
| идентификатор и хеш для CI | `TG_API_ID` и `TG_API_HASH`; приоритет над хранилищем ключей |

Пути каталогов: [Установка](./installation.md#where-files-go).

Если хранилища ключей нет (часто в контейнерах), данные приложения сохраняются в `credentials.json` рядом с настройками. `tg` один раз сообщает об этом в stderr.

> ⚠ **`TG_CONFIG_DIR`, `TG_STATE_DIR` и `TG_CACHE_DIR` также меняют запись хранилища ключей.** При любой из этих переменных имя сервиса включает каталог настроек. Сессия, созданная без переменных, не видна с ними, и наоборот. Задавайте их всегда или не задавайте вовсе.

> ⚠ **В Linux доступ к хранилищу ключей зависит от `XDG_RUNTIME_DIR`.** cron, ssh и некоторые MCP-клиенты запускают `tg` без этой переменной. Тогда команды сообщают, что данные приложения не найдены, хотя вход на компьютере уже выполнен. **Не входите повторно**: это добавит устройство, но не исправит окружение. Задайте `XDG_RUNTIME_DIR` ([Решение проблем](./troubleshooting.md#no-telegram-app-credentials-found--although-it-has-logged-in-on-this-machine)).
