Прочтите эту страницу, когда вы подключаете `tg` к своему аккаунту Telegram в первый раз, когда вы добавляете второй аккаунт или когда `tg` сообщает, что вы не вошли в систему. В конце вы узнаете, как войти в систему, как проверить, под кем вы вошли в систему, как выйти из системы и где `tg` хранит все, что ему нужно, чтобы оставаться в системе.

Во-первых, слова, которые используются на этой странице:

- **Сессия**: логин `tg` на этом компьютере. Telegram выдает его при входе в систему и указывает в приложении Telegram как еще одно устройство. `tg` сохраняет его в файле. Тот, у кого есть этот файл, может читать ваши чаты, поэтому относитесь к нему как к паролю.
- **Приложение** (`api_id` и `api_hash`): два значения из [my.telegram.org](https://my.telegram.org/apps), которые идентифицируют программу в Telegram. Каждый пользователь регистрирует свое приложение один раз; `tg` может сделать это за вас.
- **Связка ключей**: хранилище паролей вашей операционной системы. `tg` сохраняет там значения приложения.
- **Профиль**: имя для одного входа на этом компьютере с собственной сессией, приложением и настройками. Без имени `tg` использует профиль `default`. Второй профиль нужен только для второго аккаунта или для отдельных лимитов ([профили](#profiles)).

Не путайте `tg session` с `tg account sessions`. `tg session` — это логин самого `tg`; `tg account sessions` перечисляет все остальные устройства и приложения, на которых выполнен вход в ваш аккаунт.

## Первый запуск

`tg setup` помогает при первом запуске приложения и сессии, проверяет пять чатов и предлагает навыки агента. Подождите около пяти минут; Загрузка истории — это отдельный шаг. Запустите его в терминале. Используйте `tg setup --app browser` для регистрации приложения вручную или `--method phone` для входа в систему по телефону. `tg session start` остается командой только для входа в систему, включая возобновление прерванного входа в систему. Программа установки проверяет существующую сессию и не выполняет повторный вход в автоматическом режиме, если он отклонен.

## Приложение с my.telegram.org

Каждый пользователь регистрирует своё приложение. Telegram выдаёт одно приложение на номер телефона, поэтому общий идентификатор не включён в `tg`. Данные нужны один раз для каждого профиля; `tg session start` запрашивает их только при отсутствии.

Есть два способа получить данные:

- **`--app browser`** открывает [my.telegram.org/apps](https://my.telegram.org/apps). Войдите туда, создайте приложение, если у вас его нет (любое название и краткое имя, платформа Desktop), и вставьте `App api_id` и `App api_hash`, когда `tg` спросит. Хэш не отображается при вводе. Это значение по умолчанию для `tg session start`.
- **`--app auto`** заполняет сайт за вас. Он запрашивает ваш номер телефона, а my.telegram.org отправляет вам код сообщением в Telegram, затем читает ваше приложение или создает его, если у вас его нет. На сайте нет API, поэтому `tg` соответствует его веб-форме; изменение на стороне Telegram может сломать это. Тогда `--app
  browser` все еще работает. Это значение по умолчанию для `tg setup`.

Данные приложения сохраняются только после успешного входа в Telegram.

## Вход в систему

```sh
tg session start           # a QR code in the terminal
tg session start phone     # a phone number, the code Telegram sends, and your 2FA password
tg session start phone --sms   # the same, asking Telegram for the code by SMS
```

**QR:** отсканируйте код в приложении Telegram: «Настройки» → «Устройства» → «Привязать настольное устройство». Код обновляется, пока вы ждете.

**Телефон:** введите номер в международном формате, а затем код для входа. Если у аккаунта есть облачный пароль (2FA), `tg` запрашивает его, не показывая, что вы вводите. При использовании `--app auto` номер телефона запрашивается только один раз. Код обычно приходит в приложение Telegram; `--sms` вместо этого запрашивает SMS, но Telegram выбирает, а `tg` сообщает, каким способом оно было отправлено. Когда в Telegram нет СМС для аккаунта, `tg` говорит об этом и запрашивает код из приложения.

После этого Telegram добавляет новое устройство в список сессий приложения.

```text
Logged in as <your name> (@<username>, id <id>) — profile default.
Session:  ~/.local/share/tg-cli/sessions/default.session
App keys: in the keyring
Next:     tg chats list · tg server install to keep the archive current
```

### Если вход запускает агент

Ваш ИИ-агент может запустить для вас вход в систему, но у него нет терминала для показа QR-кода. Вместо этого `--qr-file` записывает код в виде изображения (PNG), и агент показывает его вам для сканирования:

```sh
tg session start --qr-file login.png
```

Файл заменяется, когда Telegram обновляет код, и удаляется, когда завершается вход в систему, независимо от того, сработало это или нет. Без терминала это работает только в том случае, если в профиле уже есть приложение, а у аккаунта нет пароля 2FA: все остальное вам придется вводить самостоятельно. `tg setup` использует ту же опцию `--qr-file`.

## Проверка и выход

```sh
tg account show              # who this profile is logged in as
tg account list              # every profile on this computer, and the account each is logged in as
tg account sessions list     # every device and app logged in to the account; ends nothing
tg session end               # log out on Telegram's side, and delete the session file here
```

`tg session end` завершает сессию **и на стороне Telegram**: устройство исчезает из списка в приложении. Идентификатор и хеш приложения остаются в хранилище ключей, локальная база не меняется.

## Срок действия сессии

Сессия действует, пока её не завершат: `tg session end`, из списка устройств в приложении Telegram или самим Telegram, если сессия не используется дольше, чем лимит аккаунта для неактивных сессий (`authorization_ttl_days` в [Telegram API](https://core.telegram.org/method/account.setAuthorizationTTL)), который приложения позволяют вам установить в списке устройств. Профиль, который запускается каждый день, никогда не достигает его. Когда сессия завершена, каждая команда отвечает «не вошел в систему или сессия завершена» с кодом выхода `4`; войдите снова с помощью `tg session start` ([что делать, когда сессия завершилась](./troubleshooting.md#not-logged-in-or-the-session-was-ended--run-tg-session-start)).

## Профили

Профиль — отдельный вход со своей сессией, приложением, настройками, получателями и записями запусков. Имя указывается **первым словом**, а не параметром:

```sh
tg chats list              # profile "default"
tg work chats list         # profile "work"
export TG_PROFILE=work     # the same for the whole shell session
```

**Первое слово считается профилем, если это не команда.** Поэтому профиль нельзя назвать `chats`, `messages` или другим словом команды; `tg session start` отклоняет такое имя. Разрешены буквы, цифры, точки, дефисы и подчёркивания; первый символ — буква или цифра.

Приоритет: первое слово команды, `TG_PROFILE`, `defaultProfile` в конфигурации, затем `default`.

Слово, которое не является командой и за которым нет команды, вызывает поясняющую ошибку:

```text
"nonsense" is not a command, so it was read as a profile name — and no command followed it.
```

**`TG_PROFILE_LOCK` фиксирует процесс на одном профиле.** Задайте его в окружении агента: другой профиль первым словом или через `TG_PROFILE` будет отклонён с кодом `5`. Без этой переменной агент может выбрать профиль с меньшими ограничениями.

Для чего нужен каждый профиль и как профиль работает с ботом: [профили и боты](./profiles.md).

## Где хранятся данные входа

| Данные | Место хранения |
|---|---|
| сессия | `sessions/<profile>.session` в каталоге состояния |
| идентификатор и хеш приложения | системное хранилище ключей, сервис `tg-cli`, запись `<profile>:api` |
| идентификатор и хеш без хранилища ключей | `credentials.json` в каталоге настроек |
| идентификатор и хеш для CI | `TG_API_ID` и `TG_API_HASH`; приоритет над хранилищем ключей |

Каталоги перечислены в [куда идут файлы](./installation.md#where-files-go).

Если хранилища ключей нет (часто в контейнерах), данные приложения сохраняются в `credentials.json` рядом с настройками. `tg` один раз сообщает об этом в stderr.

> ⚠ **`TG_CONFIG_DIR`, `TG_STATE_DIR` и `TG_CACHE_DIR` также меняют запись хранилища ключей.** При любой из этих переменных имя сервиса включает каталог настроек. Сессия, созданная без переменных, не видна с ними, и наоборот. Задавайте их всегда или не задавайте вовсе.

> ⚠ **В Linux доступ к связке ключей осуществляется через `XDG_RUNTIME_DIR`.** cron, ssh и некоторые клиенты MCP запускают `tg` без него, и каждая команда затем говорит, что учетные данные приложения не найдены, «хотя вход выполнен в систему на этом компьютере». **Не входите повторно**: это добавляет еще одно устройство и не исправляет среду. Установите `XDG_RUNTIME_DIR` > ([учетные данные приложения не найдены после входа в систему](./troubleshooting.md#no-telegram-app-credentials-found--although-it-has-logged-in-on-this-machine)).
