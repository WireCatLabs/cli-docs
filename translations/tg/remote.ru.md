`tg mcp --http` предоставляет те же инструменты на `127.0.0.1` через ваш HTTPS-туннель. У HTTP-сервера есть собственный вход OAuth для одного владельца; отдельный прокси для аутентификации не нужен. Локальное подключение через stdin/stdout работает как раньше. Владелец подтвердил чтение и отправку через Claude web 7 октября 2026 года. Веб-клиенты OpenAI и эти инструкции настройки для разных платформ ещё требуют сквозной проверки на каждой платформе.

## Запустите туннель и сервер

Сначала установите CLI и войдите в мессенджер ([установка](./installation.md)). Для настройки и MCP-сервера используйте одного пользователя ОС и один профиль. При необходимости укажите профиль перед командой: `tg work mcp`. Tailscale устанавливается отдельно; эта настройка поддерживается и `tg`, и `max`.

Установите [Tailscale](https://tailscale.com/download), войдите и включите [Funnel](https://tailscale.com/docs/features/tailscale-funnel): в вашей сети tailnet должны быть включены MagicDNS, сертификаты HTTPS и разрешение Funnel. Первая команда Funnel может вывести ссылку для одобрения. Держите открытыми два окна терминала. Когда потребуется, скопируйте во второе окно выведенный HTTPS-адрес без `/mcp` и других путей. Сохраните явно указанный публичный порт, например `:8443`. Сервер слушает `127.0.0.1:8765` и выводит одноразовый код входа; ему не нужны права администратора. Повышение прав может понадобиться только туннелю. Эти команды разрешают отправку для данного процесса сервера через `--permission messages.send=allow`; см. права ниже.

### Windows (PowerShell)

Установите приложение Tailscale для Windows и войдите через его меню в области уведомлений. После установки Node.js, CLI и Tailscale откройте новое окно PowerShell, чтобы оно увидело обновлённый PATH. Используйте `.cmd` для npm-команд, чтобы избежать ошибок политики выполнения PowerShell. Если настройка ещё не выполнена, запустите `tg.cmd setup --agent none` в обычном окне PowerShell.

Первое окно: запустите PowerShell от имени администратора для Funnel. Оператор вызова `&` обрабатывает пробел в стандартном пути установки; измените путь, если Tailscale установлен в другом месте.

```powershell
& "$env:ProgramFiles\Tailscale\tailscale.exe" funnel 8765
```

Второе окно: обычный PowerShell от пользователя, вошедшего в Telegram:

```powershell
$mcpPublicUrl = Read-Host 'Paste the HTTPS origin printed by Funnel (no /mcp)'
tg.cmd mcp --http --port 8765 --public-url $mcpPublicUrl --permission messages.send=allow
```

Запускайте оба процесса непосредственно в Windows. WSL — отдельная среда: нельзя считать, что туннель Windows, направленный на локальный адрес Windows, достигнет сервера внутри WSL.

### macOS (Терминал)

Установите приложение Tailscale и войдите в него. CLI входит в состав приложения; используйте этот путь, если `tailscale` отсутствует в PATH ([руководство CLI](https://tailscale.com/docs/reference/tailscale-cli?tab=macos)). Первое окно Терминала:

```sh
TAILSCALE_BE_CLI=1 /Applications/Tailscale.app/Contents/MacOS/Tailscale funnel 8765
```

Второе окно Терминала — от того же пользователя, который запускал `tg setup --agent none`. Это работает и в zsh, и в bash:

```sh
printf 'Paste the HTTPS origin printed by Funnel (no /mcp): '
IFS= read -r mcpPublicUrl
tg mcp --http --port 8765 --public-url "$mcpPublicUrl" --permission messages.send=allow
```

### Linux (Терминал)

Установите Tailscale по [инструкции для Linux](https://tailscale.com/download/linux), затем войдите с помощью `sudo tailscale up`. Первое окно терминала:

```sh
sudo tailscale funnel 8765
```

Второе окно терминала: используйте обычного пользователя без `sudo`, чтобы `tg` нашёл сессию, созданную через `tg setup --agent none`:

```sh
printf 'Paste the HTTPS origin printed by Funnel (no /mcp): '
IFS= read -r mcpPublicUrl
tg mcp --http --port 8765 --public-url "$mcpPublicUrl" --permission messages.send=allow
```

## Запустить MAX и Telegram вместе

Каждому серверу нужны собственный локальный порт и публичный HTTPS-адрес. Например, оставьте Telegram на локальном `8765` и публичном `443`; запустите вторую команду Funnel с `--https=8443 8766`, а MAX — с `--port 8766`. Используйте второй адрес Funnel вместе с `:8443` для `--public-url` MAX и адреса подключения с окончанием `/mcp`. Запускайте вторую команду Funnel способом, указанным выше для вашей платформы. Funnel поддерживает публичные порты `443`, `8443` и `10000` ([справочник](https://tailscale.com/docs/reference/tailscale-cli/funnel)).

## Подключите приложение

Добавьте адрес туннеля с `/mcp`, например `https://<device>.<network>.ts.net/mcp`, как удалённое подключение MCP. См. инструкции приложения: [свои MCP-серверы OpenAI](https://developers.openai.com/plugins/quickstart) или [свои подключения Claude](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp). Страница входа запрашивает код из вашего терминала. Он действует десять минут; после каждого входа выводится новый код. Пять неверных кодов блокируют вход до перезапуска сервера.

Настройка `permissions` профиля определяет доступные команды. `deny` и `readonly` блокируют запись; `ask` и `allow` разрешают запрошенную запись через MCP без формы сервера. Одобрение самого приложения отдельно и зависит от его настроек.

## Права для этого процесса сервера

Повторяйте `--permission key=level`, чтобы переопределить права только для этого процесса сервера. Например, добавьте `--permission messages.send=allow`, чтобы разрешить отправку в профиле только для чтения. `--permission messages=allow` переопределяет сохранённые права для ресурса сообщений; удаление можно разрешить отдельно через `--permission messages.delete=allow`. Сохранённая конфигурация, ограничения получателей и почасовые лимиты не меняются. Чтобы отменить запрет чтения, укажите ресурс или команду с уровнем `allow`. Ключи прав см. в [настройке](./configuration.md).

В ChatGPT / Codex web откройте **Plugins**, выберите **+ Add custom MCP server** и создайте плагин с адресом `/mcp` и OAuth. Подключитесь с кодом из терминала, установите плагин и включите его в чате Work (или упомяните через `@`). Локальный `config.toml` Codex не настраивает это веб-подключение. Доступность может зависеть от аккаунта или рабочего пространства. Если предлагается динамическая регистрация клиента (DCR), используйте её; сервер объявляет поддержку DCR и проверки кода S256. Три инструмента работают без MCP-промптов, ресурсов и запросов ввода. Следуйте [руководству подключения OpenAI](https://developers.openai.com/plugins/quickstart) и [требованиям OAuth](https://developers.openai.com/plugins/build/auth).

## Остановка и отзыв доступа

Нажмите Ctrl-C в обоих терминалах с процессами на переднем плане, чтобы остановить сервер и этот туннель. Запускайте их снова теми же командами; существующие входы в браузере сохраняются после обычного перезапуска сервера. Если Funnel запущен с `--bg`, Ctrl-C не останавливает фоновый маршрут: проверьте `tailscale funnel status` и отключите только его публичный порт, например `tailscale funnel --https=443 off`. Используйте способ запуска для вашей платформы из инструкций выше и повышенные права, если нужны. Не используйте `funnel reset`, когда другой сервер тоже использует Funnel: он удаляет все маршруты. Остановка только MCP оставляет маршрут настроенным, но инструменты становятся недоступны. Отзыв доступа браузера — отдельное действие от остановки процесса. Чтобы забыть все входы в браузере для профиля:

```sh
tg mcp --revoke --json
```

Этим приложениям придётся войти снова. Ваша сессия Telegram при этом не завершается.

## Проверка подключения

`tg mcp doctor` проверяет локальное MCP-подключение и список инструментов; вход в Telegram и туннель он не проверяет.
Подключение к аккаунту проверяет явная сетевая команда, например `tg account show`.
Записи запусков доступны через `tg runs list`: успешные вызовы сохраняются, только если включена запись;
неудачные сохраняются по умолчанию, если запись не отключена явно.
