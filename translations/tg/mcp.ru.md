title: "MCP-сервер"
---

`tg mcp` предоставляет агенту доступ к профилю по [MCP](https://modelcontextprotocol.io) по умолчанию через stdin и stdout; `--http --public-url` открывает его на локальном порту за вашим HTTPS-туннелем. Сервер входит в `tg`; отдельная установка не нужна.

**Когда нужен MCP.** В Claude Code, Codex и других агентах с терминалом достаточно `tg`: возможности и расход токенов те же. MCP нужен клиентам без терминала, например Claude Desktop или чату Cursor, и для подтверждения отправок в интерфейсе клиента. Для ChatGPT или Claude **в браузере** используйте `tg mcp --http`: [Удалённый доступ](./remote.md).

Личные инструменты используют общий каталог мессенджеров. Telegram также поддерживает темы.

## Подключение

Сначала выполните `tg setup --agent none` в локальном терминале: эта команда настраивает аккаунт Telegram. `tg mcp setup` отдельно подключает клиент. `tg skill show` объясняет оба шага до входа. Сам MCP-сервер не выполняет вход за вас.

**Codex или Claude Code на этом компьютере:**

```sh
tg mcp doctor                # check that MCP starts and lists tools
tg mcp setup codex          # add it to Codex
tg mcp setup claude-code    # or add it to Claude Code
```

Укажите профиль первым, например `tg work mcp setup codex`. Настройка использует собственную команду клиента и не меняет другие серверы. Если сервер с таким именем уже есть, удалите его запись в клиенте перед повторной настройкой. Стандартный профиль tg предлагает инструменты изменения данных, поэтому настройка просит проверить разрешения и повторить команду с `--allow-writes`. Этот флаг подтверждает установку, но не меняет разрешения. Чтобы ограничить действия агента, сначала задайте `permissions` профиля ([ниже](#what-an-agent-may-do)).

`mcp doctor` не читает сообщения и не входит в Telegram. Успешная проверка означает, что подключение MCP и список инструментов работают; она не подтверждает действительность сессии аккаунта. `potentialWrites` считает инструменты без объявления «только чтение». Если сервер не запускается, ошибка показывает последние строки, которые он записал в stderr; домашний каталог, длинные числа и токены в них скрыты. Для браузера и мобильных чатов требуется отдельное удалённое подключение ([инструкция](./remote.md)).

**Claude Code:**

```sh
claude mcp add tg -- tg mcp
```

С профилем — имя ставится первым, как в обычной команде:

```sh
claude mcp add tg-work -- tg work mcp
```

**Claude Desktop, Cursor и другие:** `tg` выводит запись для файла настроек клиента:

```sh
tg mcp config
tg work mcp config                  # another profile
```

Проверьте права профиля перед подключением агента.


```json
{
  "mcpServers": {
    "tg": {
      "type": "stdio",
      "command": "/usr/bin/node",
      "args": ["/usr/lib/node_modules/@leemour/tg-cli/dist/bin/tg.js", "mcp"],
      "env": { "XDG_RUNTIME_DIR": "/run/user/1000" }
    }
  }
}
```

Вставьте запись в `mcpServers`: Claude Desktop использует `~/Library/Application Support/Claude/claude_desktop_config.json` в macOS и `%APPDATA%\Claude\claude_desktop_config.json` в Windows; Cursor — `~/.cursor/mcp.json`. Команда сама не записывает файл.

Пути абсолютные: приложение, запущенное с рабочего стола, не видит `PATH` терминала. В Windows `tg` — файл `tg.cmd`, который клиент без оболочки не может запустить напрямую. Запись копирует заданные `TG_CONFIG_DIR`, `TG_STATE_DIR`, `TG_CACHE_DIR`, `MESSAGING_STORE`, `XDG_RUNTIME_DIR`, но никогда `TG_API_ID`, `TG_API_HASH` или сессию.

Если Node установлен через nvm, fnm или Volta, путь привязан к его версии: после смены повторите `tg mcp config`. Запуск из `npx` отклоняется, поскольку очистка кеша npx удалит путь.

⚠ **`TG_CONFIG_DIR`, `TG_STATE_DIR` и `TG_CACHE_DIR` меняют место поиска сессии.** Разные значения в терминале и MCP-клиенте приводят к сообщению «нет сессии», хотя `tg` работает в терминале. Задайте одинаковые значения в обоих окружениях или не задавайте нигде.

⚠ **В Linux доступ к данным приложения в хранилище ключей зависит от `XDG_RUNTIME_DIR`.** Клиент с сокращённым окружением может убрать переменную; тогда инструменты сообщают о недоступном хранилище. `tg mcp config` включает её в запись.

## Разрешения агента

Доступ определяют `permissions` профиля ([справочник](./configuration-reference.md#what-a-profile-may-do)). `deny` запрещает команду, `readonly` разрешает чтение, а `ask` или `allow` разрешает запрошенную запись через MCP. На сервере нет форм подтверждения: настройте одобрение в приложении агента. Команды CLI с уровнем `ask` по-прежнему требуют подтверждения; JSON и `--no-input` отключают вопросы.


```sh
tg agent config set permissions.messages readonly
tg agent config set permissions.messages.send allow
```

При записи сохраняются ограничения получателей, часовые лимиты и журнал отправок (`tg sends list`). Отметка прочитанного — отдельная запись с правом `chats.mark-read`. Удаление через MCP действует только для владельца и не более чем для десяти сообщений; для каналов и супергрупп без такой операции оно отклоняется. Старые флаги `--confirm-send`, `--allow-send`, `--allow-mark-read`, `--allow-delete`, `--allow-dangerous` и `--http-confirmation` принимаются с предупреждением и не меняют политику MCP. Удалите их из сохранённых настроек клиента. Временные переопределения `--permission key=level` остаются доступны.


## Инструменты

| Инструмент | Назначение |
|---|---|
| `tg_tools_search` | Найти команду, схему её аргументов и последствия вызова |
| `tg_read` | Выполнить доступную команду чтения |
| `tg_write` | Выполнить доступную команду записи |

Оба инструмента выполнения принимают `{command, arguments}`. Используйте путь команды, возвращённый поиском:


```json
{"command":"stats chats show","arguments":{"chat":"123"}}
```

Прежние инструменты для отдельных команд, например `tg_messages_list` и `tg_status`, удалены. Читайте `status` через `tg_read`. Серверы ботов используют `tg_bot_tools_search`, `tg_bot_read`, `tg_bot_write`; пути команд в них не содержат `bot`. Результаты поиска учитывают права профиля и поддержку провайдера.


Ответы содержат структурированный JSON: списки сохраняют пагинацию, идентификаторы остаются строками. Ошибки содержат `{error:{code,message,retryable,...}}`; при неоднозначной цели возвращаются кандидаты. После неизвестного исхода записи проверьте журнал отправок и состояние у провайдера, прежде чем повторять действие. Схемы, ограничения и правила повторов описаны в [контракте CLI](./cli-contract.md).


## Готовые запросы и чаты через `@`

Сервер предлагает шесть готовых запросов; в Claude Code это команды `/`:


| Запрос | Аргумент | Действие агента |
|---|---|---|
| `catch-up` | `kind`, `mode` — необязательные | вызывает `tg_read` (`command: "inbox"`); `mode` — `unread` (по умолчанию), `new` или время; `kind` выбирает типы чатов; отметка прочитанного требует отдельного одобренного вызова инструмента |
| `reply` | `chat` | чтение чата, черновик, отправка только после вашего согласия с текстом |
| `find` | `text` | поиск человека или слов с контекстом сообщений; без отправки |
| `link-conversations` | нет | сообщить стоимость и запросить согласие, затем прочитать пакеты, сохранить связи и пересобрать |
| `review` | `since`, `groups` — необязательные | один раз вызывает `tg_read` (`command: "review"`) и разделяет результат на ваши обязательства, обязательства других и вопросы для уточнения; готовит напоминания, отправляет только после вашего согласия |
| `open-tasks` | `chat` — необязательный | вызывает review для обновления задач, показывает ожидающие задачи и предлагает черновики; закрывает задачу только после одобрения владельца; ничего не отправляет |

`reply` и `review` отправляют через `tg_write` (`command: "messages send"`), поэтому при уровне `readonly` для `messages.send` агент только показывает черновики.


Чаты доступны как ресурсы `tg://chat/<id>`; в Claude Code их можно упоминать через `@`. Ресурс содержит чат и недавние сообщения. Список читается из базы без подключения к Telegram и пуст, пока ничего не прочитано. Подключение требуется при чтении конкретного чата.

## Работа соединения

Первый вызов подключается к Telegram, следующие используют соединение. Оно закрывается после двух минут без вызовов и в любом случае через пять минут после открытия, чтобы длительная сессия не читала устаревшие данные. Следующий вызов подключается заново. Вызовы выполняются по одному даже при одновременной отправке клиентом.

При закрытии stdin клиентом сервер завершается и закрывает подключение к Telegram.

`tg_read` (`command: "messages link"`) возвращает `{ locator, url, access, reason }` без содержимого сообщения. Проверка аккаунта и ограничения аудитории такие же, как у `messages link`; приватная ссылка не даёт членства в чате.


MCP личного аккаунта проверяет аргументы по обнаруженной схеме команды и отклоняет неизвестные поля до подключения или действия. Для планирования используйте `at_time`. Неизвестный исход нужно проверить перед повтором. Контрольные точки inbox/review в MCP отделены от контрольных точек CLI `--new`.


Связывание разговоров использует запрос `link-conversations`. Сообщите стоимость обработки партии и получите согласие владельца до чтения партий; сохранение связей требует `conversations.links`, затем перестроения. Настройки удалённых эмбеддингов могут отправлять текст запроса настроенному сервису. Команды вложений показывают сохранённые пути и статус текста; извлечение текста доступно только в CLI.
