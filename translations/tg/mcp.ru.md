Эта страница полезна, если вы хотите, чтобы приложение агента без терминала работало с вашим Telegram, например Claude Desktop или чат в Cursor. Это также помогает, когда вы хотите, чтобы само приложение спрашивало вас перед каждым действием. Прочитав эту страницу, вы сможете подключить приложение к своему аккаунту, выбирать, что может делать агент, а также использовать готовые готовые запросы и упоминания в чате.

Сначала несколько терминов:

- **MCP** ([Протокол контекста модели](https://modelcontextprotocol.io)) — это стандартный способ использования сторонними инструментами приложением ИИ. Приложение является **клиентом MCP**; `tg mcp` — это **сервер MCP**.
- **Инструмент** — это одно действие, которое сервер предлагает агенту, например «чтение» или «запись».
- **Готовый запрос** — это готовая задача, которую приложение отображает в виде команды, например «Просмотреть непрочитанные чаты».
- **Ресурс** — это данные, которые приложение может прикрепить к разговору, например один чат.
- **Профиль** — это один набор настроек и один логин в `tg`; см. [профили](./profiles.md).

Сервер поставляется с `tg`; больше нечего устанавливать. По умолчанию он обращается к приложению через стандартный ввод и вывод. Вместо этого `tg mcp --http --public-url` передает его через локальный порт за вашим туннелем HTTPS.

## Нужен ли вам MCP?

ИИ-агент, который может запускать команды в терминале (например, Claude Code, Codex, агент Cursor или Gemini CLI), не нуждается в MCP. Он напрямую вызывает `tg`, с теми же затратами токенов и может делать те же самые действия; он узнает, как это сделать, благодаря навыку, который печатает `tg skill show`. MCP предназначен для:

- приложения без терминала, такие как Claude Desktop или чат Cursor;
- всем, кто хочет, чтобы приложение спрашивало перед каждой отправкой.

Для ChatGPT или Claude **в браузере** используйте `tg mcp --http` — см. [подключение браузера или приложения для телефона](./remote.md).

## Что дает сервер

| Что | Что он делает |
|---|---|
| [Три инструмента](#tools) | Найдите команду, затем запустите ее для чтения или записи |
| [Шесть готовых запросов](#prompts-and-chats-by-) | Узнавайте, отвечайте, находите, просматривайте, открывайте задачи, связывайте беседы |
| [Чаты `@`](#prompts-and-chats-by-) | Прикрепить чат и его последние сообщения к беседе |
| Навык, `tg://skill` | Тот же текст, что и у `tg skill show` |
| [Диаграммы](#statistics-charts) | Статистика чата в формате JSON или PNG |
| [Разрешения](#what-an-agent-may-do) | Профиль решает, какие команды видит агент |

Персональные инструменты используют тот же каталог, что и `max`. В Telegram тоже есть темы.

## Подключение

Сначала запустите `tg setup --agent none` в локальном терминале. Он входит в ваш аккаунт Telegram. Сервер MCP никогда не входит в систему вместо вас. Затем `tg mcp setup` подключает приложение в качестве отдельного шага. Агент может прочитать `tg skill show` до того, как вы войдете в систему; это объясняет оба шага.

**Codex или Claude Code на этом компьютере:**

```sh
tg mcp doctor                # check that MCP starts and lists tools
tg mcp setup codex          # add it to Codex
tg mcp setup claude-code    # or add it to Claude Code
```

Сначала поставьте профиль, например `tg work mcp setup codex`. Программа установки использует собственную команду приложения и не трогает другие серверы. Если запись с таким именем уже существует, удалите ее в приложении, прежде чем снова запускать установку. Профиль по умолчанию предлагает инструменты для записи. Поэтому программа установки попросит вас просмотреть разрешения профиля и запустить его снова с помощью `--allow-writes`. Этот флаг только подтверждает установку; он не меняет разрешения. Чтобы ограничить возможности агента, сначала установите `permissions` профиля ([ниже](#what-an-agent-may-do)).

`mcp doctor` не читает сообщения и не авторизуется в Telegram. Хороший результат означает, что согласование MCP и список инструментов работают. Это не означает, что сессия аккаунта действительна. `potentialWrites` подсчитывает инструменты, не помеченные как доступные только для чтения. Когда сервер не запускается, ошибка показывает последние строки, записанные в stderr, с замаскированными домашним каталогом, длинными числами и токенами. Приложениям браузера и телефона требуется отдельное удаленное подключение ([подключение приложения браузера или телефона](./remote.md)).

**Claude Code, вручную:**

```sh
claude mcp add tg -- tg mcp
```

С профилем — имя ставится первым, как в обычной команде:

```sh
claude mcp add tg-work -- tg work mcp
```

**Claude Desktop, Cursor и другие приложения:** `tg` печатает запись для своего файла настроек:

```sh
tg mcp config
tg work mcp config                  # another profile
```

```json
{
  "mcpServers": {
    "tg": {
      "type": "stdio",
      "command": "/usr/bin/node",
      "args": ["/usr/lib/node_modules/@wirecat/tg-cli/dist/bin/tg.js", "mcp"],
      "env": { "XDG_RUNTIME_DIR": "/run/user/1000" }
    }
  }
}
```

Прежде чем подключать агента, просмотрите разрешения профиля. Затем вставьте запись под `mcpServers` в файл настроек приложения. Для Claude Desktop это `~/Library/Application Support/Claude/claude_desktop_config.json` в macOS и `%APPDATA%\Claude\claude_desktop_config.json` в Windows; для курсора `~/.cursor/mcp.json`. Сама команда ничего не пишет.

Пути заполнены, поскольку приложение, запущенное с рабочего стола, не видит `PATH` терминала. В Windows `tg` — это файл `tg.cmd`, который приложение без оболочки не может запустить. Запись копирует `TG_CONFIG_DIR`, `TG_STATE_DIR`, `TG_CACHE_DIR`, `MESSAGING_STORE` и `XDG_RUNTIME_DIR`, когда они установлены; никогда `TG_API_ID`, `TG_API_HASH` или сессия.

Если Node произошел от nvm, fnm или Volta, его путь принадлежит одной версии Node. Запустите `tg mcp config` еще раз после его изменения. При запуске из `npx` команда отказывается: npx очищает свой кеш, и путь перестает существовать.

⚠ **`TG_CONFIG_DIR`, `TG_STATE_DIR` и `TG_CACHE_DIR` меняют место поиска логина.** Если они установлены в терминале, а не для приложения MCP, или наоборот, сервер отвечает «нет сессии», хотя `tg` работает в терминале. Установите их одинаковыми в обоих случаях или ни в одном.

⚠ **В Linux учетные данные приложения находятся в связке ключей, доступ к которой осуществляется через `XDG_RUNTIME_DIR`.** Приложение, которое запускает серверы с обрезанной средой, игнорирует их, и каждый инструмент затем отвечает, что связка ключей, вероятно, недоступна. Запись из `tg mcp config` включает его.

У бота есть собственный сервер `tg <name> bot mcp`; см. [бот для агента](./bot.md#the-bot-for-an-agent-mcp).

## Разрешения агента

`permissions` профиля определяет доступ ([что профиль может делать](./configuration-reference.md#what-a-profile-may-do)). `deny` блокирует команду, `readonly` разрешает только чтение, а `ask` или `allow` разрешает запись, запрошенную агентом. Сервер не показывает запросы подтверждения: настройте одобрение в приложении агента. В терминале команда `ask` все еще требует вашего подтверждения. С JSON или `--no-input` вопросов нет, поэтому запись будет запрещена, если вы не добавите `--yes`.

```sh
tg agent config set permissions.messages readonly
tg agent config set permissions.messages.send allow
```

Здесь `agent` — имя профиля. При записи сохраняются лимиты получателей, почасовые лимиты и журнал отправки (`tg sends list`). Маркировка чтения — это отдельная запись под `chats.mark-read`. Удаление через MCP удаляет сообщения только для вас, максимум десять за раз; каналы и супергруппы, не позволяющие этого, получают отказ. `--permission key=level` изменяет уровень только для этого серверного процесса.

Старые флаги `--confirm-send`, `--allow-send`, `--allow-mark-read`, `--allow-delete`, `--allow-dangerous` и `--http-confirmation` принимаются с предупреждением и не меняют действий агента. Удалите их из сохраненных записей приложения.

## Инструменты

| Инструмент | Что он делает |
|---|---|
| `tg_tools_search` | Найдите команду, ее аргументы и ее эффекты |
| `tg_read` | Запустите команду чтения, предложенную поиском |
| `tg_write` | Запустите команду записи, предложенную поиском |

Оба инструмента запуска используют `{command, arguments}`. Используйте путь к команде, который вернул поиск:

```json
{"command":"stats chats show","arguments":{"chat":"123"}}
```

`status` считывает состояние профиля через `tg_read`. Поиск показывает только то, что позволяют разрешения профиля и Telegram. Прежние названия «один инструмент на команду», такие как `tg_messages_list` и `tg_status`, больше не существуют. Бот-серверы используют `tg_bot_tools_search`, `tg_bot_read` и `tg_bot_write`; их пути команд не включают `bot`.

Ответы структурированы в формате JSON: списки сохраняют свои страницы, а идентификаторы остаются строками. Ошибка — `{error:{code,message,retryable,...}}`; Для цели, соответствующей нескольким чатам, возвращаются кандидаты. Сервер проверяет аргументы на соответствие схеме команды и отклоняет неизвестные поля перед подключением или действием. Используйте `at_time` для планирования. Если результат записи неизвестен, проверьте журнал отправки и Telegram, прежде чем думать о повторной попытке. Текст сообщения — это данные, а не инструкции для агента. Схемы, ограничения и правила повтора находятся в [как tg ведет себя в скриптах](./cli-contract.md).

## Готовые запросы и чаты через `@`

Сервер предлагает шесть готовых запросов; в Claude Code это команды `/`:

| Готовый запрос | Аргумент | Чем занимается агент |
|---|---|---|
| `catch-up` | `kind`, `mode` — опционально | вызывает `tg_read` (`command: "inbox"`); `mode` — `unread` (по умолчанию), `new` или время; `kind` выбирает виды чата; для маркировки чтения требуется отдельный утвержденный вызов инструмента |
| `reply` | `chat` | читает чат, пишет черновик и отправляет его только после того, как вы одобрите этот текст |
| `find` | `text` | ищет человека или слова и показывает сообщения вокруг каждого попадания; ничего не отправляет |
| `link-conversations` | нет | сообщает стоимость и запрашивает ваше согласие, затем читает батчи, сохраняет ссылки и перестраивает ([ниже](#linking-conversations)) |
| `review` | `since`, `groups` — опционально | вызывает `tg_read` (`command: "review"`) один раз и сортирует его на то, что вы должны, что должны другие и что нужно уточнить; создает черновики напоминаний, отправляет одно только после вашего «да» |
| `open-tasks` | `chat` — опционально | вызывает проверку для обновления задач, перечисляет открытые задачи и предлагает черновики; закрывает задачу только после вашего одобрения; ничего не отправляет |

`reply` и `review` отправляются через `tg_write` (`command: "messages send"`). Таким образом, если `messages.send` — `readonly`, агент показывает только черновики.

Чаты — это ресурсы `tg://chat/<id>` — в Claude Code их можно упоминать с помощью `@`. Ресурс — это чат и его недавние сообщения. Список создается из локальной копии ваших сообщений и никогда не подключается к Telegram; пока что-то не было прочитано, оно пусто. Подключается только чтение одного чата.

`tg_read` (`command: "messages link"`) возвращает `{ locator, url, access, reason }` без текста сообщения. Аккаунт и аудиторию проверяет так же, как `messages link`; частная ссылка никого не делает участником. Контрольные точки «Входящие» и «Проверка» в MCP отделены от контрольных точек `--new` терминала.

## Диаграммы статистики

`tg_read` (`command: "stats charts"`) считывает статистику чата из локальной копии и возвращает `chart` в формате JSON. Для изображения добавьте `format: "png"`: ответ — темный PNG плюс JSON с данными `chart` и размером `image`. Без `format` ответ останется JSON. Инструмент не подключается к Telegram и не записывает файлы; для этого требуется разрешение `messages`. Вступления и выходы (`membership`) здесь недоступны.

## Связывание разговоров

Приглашение `link-conversations` позволяет агенту связывать ответы с беседами. Агент сначала сообщает размер работы с `tg_read` (`command: "conversations batches status"`) и ждет вашего согласия. Затем он считывает пакеты с помощью `tg_read` (`command: "conversations batches next"`), сохраняет ответы с помощью `tg_write` (`command: "conversations links add"`) и перестраивает с помощью `tg_write` (`command: "conversations build"`). `tg_write` (`command: "conversations links clear"`) удаляет ответы агента; восстанавливать после этого тоже. Для сохранения требуется разрешение `conversations.links`. Если вы настроили внешнюю службу для векторов поиска, поиск MCP также отправляет текст запроса в эту службу.

## Файлы и сохраненные сообщения

`tg_read` (`command: "attachments list"`) показывает пути к сохраненным файлам и то, был ли извлечен их текст. `tg_write` (`command: "attachments text set"`) сохраняет текст, прочитанный агентом, из файла. Извлечение текста выполняется только в терминале. `tg_read` с `command: "messages context"` и `arguments: { offline: true }` считывает только локальную копию.

## Работа соединения

Первый вызов, которому нужен Telegram, открывает соединение; последующие используют его повторно. Он закрывается через 2 минуты без вызова и в любом случае через 5 минут после открытия, поэтому при длительной сессии агента никогда не считывается устаревший снимок. Следующий вызов снова подключается. Вызовы выполняются по одному, даже если приложение отправляет их вместе.

Через стандартный ввод и стандартный вывод сервер завершает работу, как только приложение закрывает стандартный ввод, и закрывает соединение с Telegram. По HTTP он работает до нажатия Ctrl-C. `tg mcp --revoke` завершает каждый вход в систему в браузерном приложении и сохраняет сессия Telegram. См. [подключение браузера или приложения для телефона](./remote.md).
