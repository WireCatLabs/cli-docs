Используйте эту страницу, когда команда ожидает, останавливается из-за ошибки ограничения скорости или когда вы планируете загрузить большой объем истории или выполнить несколько команд одновременно. Здесь объясняется, как быстро `tg` общается с Telegram, почему он иногда ждет и что делать, когда он останавливается. К концу вы узнаете, какие ожидания являются нормальными, как изменить темп и когда попробовать еще раз.

Слова, которые используются на этой странице:

- **Скорость**: сколько запросов профиль может отправлять в Telegram в минуту. `tg` ограничивает эту скорость отдельно для каждого профиля.
- **FLOOD_WAIT**: ответ Telegram «подождите N секунд». Если вы продолжаете спрашивать во время ожидания, время ожидания увеличивается.
- **Лимит спама** (PEER_FLOOD): Telegram ограничивает аккаунт, который пишет слишком большому количеству незнакомцев.
- **Фоновое задание**: загрузка, которая продолжается после завершения команды, которая ее запустила.

`tg` выполняет короткие ожидания от Telegram и останавливается, когда ожидание длительное.

## Частота запросов: общий лимит для профиля

Каждый запрос `tg` для профиля — из команды, `tg personal mcp`, `tg personal serve` или фонового задания —
попадает в общую для этого профиля очередь с ограничением частоты:

- пакет из **20 запросов** выполняется сразу, поэтому обычные команды не ждут;
- после пакета — **один запрос в секунду** (60 в минуту), пока доступный запас не восполнится во время простоя.

**Две команды, выполняемые одновременно, используют общий лимит частоты.** Очередь хранится в файле в папке состояния
(`pace/<profile>.json`), поэтому два терминала, несколько заданий `messages sync --background` и `serve` ждут
своей очереди, вместо того чтобы каждое выполнялось на полной скорости. Пять параллельных загрузок не быстрее
пяти последовательных и не создают большего риска. Разные профили — разные
аккаунты Telegram — имеют отдельные лимиты частоты.

Если команде приходится ждать своей очереди более 5 секунд, она сообщает об этом в stderr:

```text
waiting 12 s to keep this profile's pace with Telegram
```

Измените частоту запросов в файле конфигурации или для одной оболочки с помощью переменной окружения:

```json
{ "defaults": { "requestsPerMinute": 30 } }
```

```sh
TG_REQUESTS_PER_MINUTE=30 tg personal messages sync "Book club"
```

`0` отключает ограничение частоты. Делайте это только для профиля, для которого вы готовы допустить ограничения со стороны Telegram.

## Когда Telegram просит подождать

| Сколько Telegram просит ждать | Что делает `tg` |
|---|---|
| до 10 с, в разовой команде | ждёт не более двух раз и сообщает об этом в stderr |
| до 2 мин, в `serve` и `watch` | ждёт не более трёх раз |
| дольше | останавливается с кодом выхода `8` (`rate_limited`) и `retryAfterMs` в JSON |

`messages sync` и `messages download --all` выдерживают ожидание до 5 минут между страницами и продолжают работу;
более долгое ожидание останавливает запуск, а следующий запуск продолжает с уже сохранённых данных. `messages sync --all`
также пережидает короткие ожидания Telegram, пока получает список чатов.

**Ожидание приостанавливает весь профиль.** Пока оно не закончится, следующий запрос каждого процесса ждёт его окончания; запрос,
которому пришлось бы ждать более 5 минут, сразу завершается с кодом выхода `8`, не обращаясь к Telegram.
`tg personal doctor` и `tg personal server status` показывают в `flood`, что приостановлено. После окончания ожидания ничего
делать не нужно; `tg personal flood clear` снимает его раньше, если вы знаете, что Telegram больше не ограничивает аккаунт.

## Операции записи

- **30 отправок в час** для каждого профиля по умолчанию (`sendsPerHour`), учитываются по процессам; см. [защиту отправки](./security.md#the-send-guard).
- **Лимит спама (PEER_FLOOD)** и замороженный аккаунт блокируют каждую запись; чтение все еще работает. См. [устранение неполадок](./troubleshooting.md).
- Отправка, которая могла прийти, а могла и не прийти, никогда не повторяется `tg`; см. [когда результат неизвестен](./usage.md#when-the-outcome-is-unknown).

## Массовое чтение

- `messages sync`: страницы до 100 сообщений, `--pause` между страницами (по умолчанию 1 с), 1000 сообщений за
  запуск, если `--limit` не задаёт другое значение. `--estimate` сначала подсчитывает запросы, не отправляя ни одного.
- `messages download --all`: один запрос на страницу и на файл; частота запросов к файлам также ограничивается.
- `messages sync --all` получает список чатов страницами по 100, каждая страница — один шаг темпа.
- `chats list --all` читает все чаты за один шаг: один запрос на 100 чатов, подряд.
- `chats members list --all`: страницы по 200 участников с паузой 1 с, до предела Telegram в 10 000.
- Устранение пробелов читает страницу за страницей с паузой 1 с, как `messages sync`.

## Фоновые задания

`messages sync --background` и `store gaps repair --background` запускают задание, которое переживет команду: одно задание на каждый чат за раз, каждое в своем собственном процессе, все в одном темпе профиля. `tg personal store jobs
list` показывает их, `tg personal store jobs cancel <job>` останавливает одно задание после текущей страницы. См. [загрузка в фоновом режиме](./archive.md#in-the-background).

## Боты

Собственные ограничения API бота отличаются от ограничений аккаунта. `tg` выполняет паузы `retry_after`, которые возвращает Telegram; длительное ожидание останавливает запуск. См. [боты](./bot.md).

## Один вход, несколько процессов

Каждый процесс `tg` открывает своё соединение, используя вход в аккаунт из профиля. Несколько процессов могут работать одновременно, но каждый
из них отправляет запросы от одного и того же аккаунта, поэтому они используют общее ограничение частоты.
