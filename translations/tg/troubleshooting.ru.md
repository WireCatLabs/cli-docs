Используйте эту страницу, когда `tg` показывает ошибку или не делает то, что вы ожидали. Найдите сообщение, которое вы видите, или его код выхода, и страница расскажет вам, что оно означает и что делать дальше. Большинство решений требует одной команды.

Несколько слов, которые используются на этой странице:

- **Код выхода** — это число, которое команда возвращает по завершении: `0` означает, что все сработало, любое другое число обозначает тип сбоя. Его читают скрипты и ИИ-агенты; В таблице ниже каждый из них сопоставлен с его разделом.
- **`tg doctor`** проверяет установку без подключения к Telegram. Сначала запустите его.
- **`--trace`** показывает каждый запрос к Telegram в том виде, в каком он происходит, без текста сообщения ([диагностика](./diagnostics.md)).

В выводе `--json` каждая ошибка представляет собой одну строку в stderr, `{"error":{"code":"…","message":"…"}}`, и код выхода говорит то же самое, что и `code`. Каждый код также находится в [справке по кодам выхода](./commands.md#exit-codes).

## Сначала: `tg doctor`

```sh
tg doctor
```

Без подключения показывает зависимости команд: версию, среду выполнения, конфигурацию, сессию, данные приложения, переменные `TG_*_DIR`, базу, журнал отправок и записи запусков. **Работает даже при неисправности остальных команд.** Отсутствие сессии отображается в результате, а не как ошибка: код остаётся `0`. Сессия и хеш не выводятся, только наличие.

```sh
tg doctor --online
```

`--online` тоже один раз подключается и читает аккаунт. Он ничего не отправляет и ничего не отмечает как прочитанное. Без него логин отображается как `not checked`: только `--online` говорит вам, что Telegram по-прежнему принимает сессию. `--online` также сообщает о неправильных часах на этом компьютере и о том, заморозил ли Telegram или закрыл аккаунт ([что показывает `tg doctor`](./diagnostics.md#check-the-installation-tg-doctor)).

## Установка

### `tg` не найден после установки

Каталог команд npm отсутствует в `PATH`.

- **Linux и macOS.** Каталог — `$(npm prefix -g)/bin`. Добавьте его в `PATH` через `~/.zshrc` или `~/.bashrc`: `export PATH="$(npm prefix -g)/bin:$PATH"`.
- **Windows.** Каталог показывает `npm prefix -g`, обычно `%APPDATA%\npm`. Проверьте наличие в `$env:Path`. Терминал, открытый до установки Node, не видит обновлённый `PATH`: откройте новый.
- **PowerShell сообщает «running scripts is disabled on this system».** npm устанавливает `tg.ps1` рядом с `tg.cmd`, а PowerShell по умолчанию запрещает скрипты. Используйте `tg.cmd` или разрешите скрипты своему пользователю: `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`.
- **Другая `tg` находится первой.** Другая программа тоже может называться `tg`. `which -a tg` (или
  `Get-Command tg -All` в PowerShell) показывает все; вызовите нашу по полному пути или поставьте её папку
  первой.

Без установки доступна команда `npx @wirecat/tg-cli doctor`.

<a id="npx-leemourtg-cli-использует-старую-версию" />

### `npx @wirecat/tg-cli` использует старую версию

npx сохраняет скачанное. Запросите новую версию: `npx @wirecat/tg-cli@latest`.

## Вход и профили

### "нет сессии для профиля "по умолчанию" — запустите `tg setup`"

Код выхода `4`. Этот профиль ещё не входил в систему на этом компьютере или вышел из системы. Проверьте, какой профиль вы имели в виду: первое слово команды или `TG_PROFILE` ([profiles](./sessions.md#profiles)).

```sh
tg setup                    # guided first run
tg work chats list          # or name the profile you logged in to
```

Если вход выполнен, проверьте различия `TG_CONFIG_DIR`, `TG_STATE_DIR`, `TG_CACHE_DIR` между входом и запуском, например в разных терминалах. Они меняют место хранения входа. `tg config show` показывает заданные переменные; `env | grep TG_` — все.

При первом запуске без ключей приложения ошибка предлагает `tg setup` (или `tg work setup` для рабочего профиля). Варианты входа описаны в `tg setup --help`. Агент может прочитать `tg skill show` до входа. Прерванная или истёкшая сессия требует `tg session start`, затем повторной проверки настройкой.

### «Учетные данные приложения Telegram не найдены… хотя вход в систему был выполнен на этом компьютере»

Код `4`. Файл сессии есть, но хранилище ключей недоступно. Это бывает в cron, ssh, службах и MCP-клиентах с сокращённым окружением `tg`.

**Не входите повторно:** это добавит устройство и не исправит окружение. В Linux задайте `XDG_RUNTIME_DIR` (обычно `/run/user/` и номер из `id -u`):

```sh
XDG_RUNTIME_DIR=/run/user/$(id -u) tg chats list
```

Подробнее о cron см. [работа по расписанию](./recipes.md#running-on-a-schedule). Системное хранилище ключей также может быть зазаблокировано до тех пор, пока вы не войдете в компьютер.

### "не авторизован или сессия завершена — запустите `tg session start`"

Код `4`. Telegram больше не принимает сессию: её завершили с другого устройства (Настройки → Устройства) или через `tg session end`. Войдите через `tg session start`.

### "`tg session start` задает вопросы — запустите его в терминале"

Код выхода `2`. Для входа в систему необходимо, чтобы человек отсканировал код или набрал его. Запустите его в терминале. Для агента `--qr-file login.png` вместо этого записывает QR-код в файл ([когда агент выполняет вход в систему](./sessions.md#when-an-agent-runs-the-login)).

### "my.telegram.org сообщает, что приложение было создано, но на его странице ничего не отображается"

Код выхода `13`, во время `tg session start --app auto`. На сайте нет API, поэтому `tg` следует за веб-формой, а форма изменилась или неожиданно ответила. Другие ошибки с сайта — это код выхода `11`, как указано на сайте. Вместо этого используйте способ по умолчанию: `tg session start` открывает сайт в вашем браузере, и вы вставляете идентификатор и хэш приложения ([приложение из my.telegram.org](./sessions.md#the-app-from-mytelegramorg)).

### Ответ пришел не из того профиля

`tg config show` показывает профиль и источник выбора. `TG_PROFILE` выбирает профиль, `TG_PROFILE_LOCK` запрещает другие. Опечатка в команде может быть прочитана как профиль ([выше](#error-unknown-command-)).

### "ошибка: неизвестная команда '…'"

Код `1`, справка в stderr вместо JSON. Первое слово, не являющееся командой, считается профилем, поэтому опечатка может стать именем профиля:

```text
tg chat list
error: unknown command 'list'
```

Здесь `chat` считается профилем, а `list` не является командой. Правильно — `chats`, во множественном числе. Список: `tg --help`.

## Настройки и значения опций

### «… недопустимая конфигурация»

Код выхода `3`. `config.json` имеет настройку, которую `tg` не знает, или значение неправильного типа. В ошибке указывается параметр и профиль, в котором он находится. Это намеренный отказ: молчаливо игнорируемая настройка стоит полдня. Исправьте вручную или удалите с помощью `tg config unset <setting>` ([опечатка — ошибка](./configuration-reference.md#a-typo-is-an-error-not-a-default)).

### "--limit принимает целое число от 1 и выше"

Код `2`. `--page` тоже требует целое положительное число. Иначе неверное значение могло бы молча вернуть пустой список.

### "--after-time принимает время ISO 8601 или 30 минут, 2 часа, 1 день назад"

Код `2`. То же для `--since-time`. Нужен ISO 8601 (`2026-09-20T09:00`) или период назад (`30m`, `2h`, `1d`). Для идентификатора сообщения используйте `--after-id` или `--before-id`.

### "--at-time принимает время, например 2026-09-25T09:00, или задержку, например 30 м, 2 часа, 1 д"

Код `2`. `--at-time` принимает локальное время или задержку в минутах, часах, днях, не секундах. Минимум минута от текущего момента, максимум год.

### "--timeout принимает время с единицей измерения — 500 мс, 30 с, 2 м, 4 ч или 1 д"

Код `2`. `--timeout` и `TG_TIMEOUT` требуют число с единицей `ms`, `s`, `m`, `h`, `d`; число без единицы запрещено.

### "--all и --page запрашивают разные вещи; используйте одно или другое"

Код `2`. `--all` запрашивает все строки, `--page` — одну страницу. Команда отклоняет сочетание, а не выбирает молча один параметр.

## Поиск чата

### "… соответствует 3 чатам — назовите один по его идентификатору"

Код `2`. Название подходит нескольким чатам. Ошибка перечисляет их идентификаторы, JSON — `candidates`. Повторите с идентификатором. `tg` не угадывает получателя.

### "нет совпадений в чате..."

Код `6`. Ни одно название не содержит введённый текст. Попробуйте `tg chats list --search <part of it>`, идентификатор, `@username` или `me` для «Избранного». Личный чат называется именем собеседника в вашем Telegram.

### «Telegram этого не знает (…)»

Код `6`. Чат, пользователь, имя или сообщение недоступны аккаунту: `PEER_ID_INVALID`, `USERNAME_NOT_OCCUPIED`, `MSG_ID_INVALID` и подобные ошибки. Сообщение могло быть удалено, идентификатор — относиться к другому чату. `contacts lookup` не находит человека, скрывающего номер или не имеющего аккаунта.

## Ограничения и разрешения

### "Telegram просит подождать N секунд до следующего запроса"

Код `8`. Ограничение Telegram (FLOOD_WAIT). Подождите указанный срок; JSON содержит `retryAfterMs`. Обычно возникает после серии запросов, например `chats list --all` или долгого `store fetch`. Для `store fetch` и `messages download --all` увеличьте `--pause`.

Команда сама выжидает запрос до 10 секунд, не больше двух раз, и сообщает об этом в stderr: «Telegram asks to wait 3 s before … — waiting, then going on». `serve` и `watch` ждут до 2 минут. Более долгое ожидание завершает команду этой ошибкой. `tg` также запоминает ожидание: пока оно не закончится, та же команда сразу завершается ошибкой, не обращаясь к Telegram снова, а `tg doctor` и `tg server status` показывают его в `flood`.

Как сочетаются темп, ожидания и параллельные команды: [ограничения и ожидания](./limits.md).

### «Telegram ограничил сообщения этого аккаунта как спам (PEER_FLOOD)»

Код `5`. Telegram ограничивает аккаунт, который написал слишком многим людям не из своих контактов. Читать он по-прежнему может. Напишите @SpamBot в приложении Telegram: он скажет, до какого срока. Новые отправки только ухудшают положение, поэтому `tg` задерживает все отправки на час и сообщает об этом; каждый новый отказ начинает час заново. `tg doctor` показывает задержку в `flood.sendBlock`. Когда @SpamBot скажет, что ограничение снято, `tg flood clear` снимет задержку вместе с любым ожиданием, которое запомнил `tg`. Отказ замороженного аккаунта задерживает отправки так же — до даты, названной Telegram; `tg doctor --online` устанавливает и снимает эту задержку.

### "профиль... отправил N сообщений за час..."

Код `8`. Лимит профиля — `sendsPerHour`, по умолчанию 30. Ошибка показывает время следующей отправки. Увеличивайте лимит только намеренно: `tg config set sendsPerHour <n>`.

### «чат… нет в списке получателей профиля…»

Код `7`. Список получателей включён, чат отсутствует. Добавьте его сами при необходимости: `tg recipients add <chat>`. Агент должен остановиться и спросить вас.

### "профиль... не дает... писать" или "профиль... запрещает..."

Код выхода `5`, прежде чем что-либо будет отправлено в Telegram. `permissions` профиля отказался: `deny` тоже прекращает чтение, `readonly` останавливает изменение. В ошибке указано, какой ключ, где он был установлен, и команда, которая это позволяет ([что может делать профиль](./configuration-reference.md#what-a-profile-may-do)). Агент должен остановиться и спросить вас, а не менять настройку.

### «…спрашивает, прежде чем действовать»

Код `7`. Уровень команды — `ask`, но ответить некому: нет терминала или указан `--json`, `--jsonl`. Ошибка укажет подтверждающий параметр: `--allow-dangerous` для удаления, `--yes` для остальных изменений. Добавляйте его только осознанно. Агент должен спросить вас.

### Запомнил ожидание

Когда Telegram сообщает, сколько времени ждать, `tg` запоминает это время для операции и чата. Повторная попытка до ее завершения сразу же завершается неудачно с кодом выхода `8` без другого запроса. Отказ из-за того, что аккаунт заморожен или ограничен из-за спама, также может приостановить отправку.

`tg flood clear` забывает об этих ожиданиях и удержаниях на этом компьютере. В Telegram это ничего не меняет, поэтому запускайте его только после снятия ограничения. У него нет инструмента MCP: агент не должен снимать блокировку только для того, чтобы попытаться еще раз. Только `tg doctor --online` проверяет логин, состояние аккаунта и часы; `tg doctor` без него не доказывает, что вход работает.

## Telegram и сеть

### «Телеграм отказался:…»

Код `5`, если аккаунту запрещено действие, `11` — остальные отказы. Имя причины приходит от Telegram и содержится в JSON как `providerError`; введённые аргументы не повторяются. Некоторые причины объясняются отдельно:

- **Telegram распознаёт речь только для Premium** — код `5`. Используйте локальную модель: `tg models audio download parakeet-v3`, затем `tg messages transcribe <chat> <id> --local`.
- **Сообщение не является голосовым или видеозаметкой** — код `2`: указан другой тип сообщения.
- **Telegram не смог распознать речь** — код `11`; попробуйте `--local`.

### «Ошибка Telegram: …»

Код `12`. Ошибка на стороне Telegram. `tg` ничего не изменил; повторите через минуту. Если отправляли сообщение, сначала проверьте чат.

### «невозможно связаться с Telegram (…)»

Код выхода `10`. Соединение не удалось установить или оно оборвалось: нет сети, брандмауэра, прокси-сервера или DNS. Код в скобках говорит какой (`ECONNREFUSED`, `ENOTFOUND`, `ETIMEDOUT`). Команды, отвечающие из архива, работают без сети: `tg --offline chats list`. Там, где Telegram заблокирован, установите прокси ([настройка прокси](./configuration-reference.md#through-a-proxy)).

### «прокси… недоступен» или «… отказано»

Код `3`. Проблема в прокси, а не в Telegram: до Telegram ничего не дошло, поэтому даже отправка не ушла. `tg` останавливается на первом неудачном подключении, а не ждёт истечения срока.

- **недоступен (`ECONNREFUSED`, `ENOTFOUND`, `ETIMEDOUT`)** — прокси не работает или указаны неверные адрес или порт.
- **refused: … auth …** или **refused the tunnel (HTTP 407)** — неверные имя пользователя или пароль. Задайте их снова: `tg config set proxy -`.
- **refused the tunnel (HTTP 403 или 502)** — прокси не хочет или не может подключиться к Telegram.

`tg doctor` показывает используемый прокси, откуда он взят (`TG_PROXY` или настройки) и идёт ли через него Bot API. Чтобы попробовать без прокси: `tg config unset proxy`. MTProxy с неверным секретом обычно выглядит как зависание, а не как отказ: ограничьте время через `--timeout 30s`.

### Команда зависает

Одноразовые команды закрывают соединение и выходят. Без ответа Telegram команда завершается с кодом `9` и `timeout`. Чтобы ограничить время и увидеть место остановки:

```sh
tg --timeout 30s --trace chats list
```

`--timeout` охватывает всю команду, включая вход в систему, и завершает ее кодом выхода `9` после закрытия соединения. В `--trace` строка `→` без `←` после нее - это запрос, который ушел и больше не вернулся: сеть или Telegram, а не `tg` ([чтение трассировки](./diagnostics.md#show-it---trace)).

Если результат выведен, но команда не выходит, это сбой. Через пять секунд `tg` перечисляет открытые ресурсы (`tg: finished, but … stayed open`) и выходит. Приложите эту строку к обращению. `watch`, `serve`, `mcp` должны работать до остановки.

## После отправки

### `outcome_unknown` после отправки

Код `14`. Соединение оборвалось после отправки, и сообщение могло уйти. **Не отправляйте его повторно без изменений.** Используйте `--send-id` из ошибки: Telegram исключит дубликат.

```sh
tg messages send <chat> "<the same text>" --send-id <id from the error>
```

После `--at-time` проверьте `tg messages scheduled <chat>`: отложенная отправка никогда не повторяется.

Закрепление, открепление, реакция, отметка о прочтении, удаление, голос, закрытие опроса, изменения папок и контактов завершаются так же, когда Telegram не отвечает. Сообщение говорит, безопасно ли повторять. Создание папки повторять небезопасно: сначала посмотрите `tg chats folders list`, иначе появится вторая папка.

### Ctrl-C

Код `130`. Команда остановлена и соединение закрыто. При остановке отправки сначала проверьте чат (`tg messages list <chat> --limit 3`): сообщение могло уйти. Фоновый `store fetch` продолжит работу; остановите через `tg store jobs cancel <job>`.

Ответ кроме `y` на запрос подтверждения даёт тот же код; действие не выполнено.

## Локальный архив и поиск

### "хранилище сообщений написано более новой версией..."

Код выхода `3`. Другой CLI или более новый `tg` обновил локальное хранилище таким образом, что эта версия не может его прочитать. Запустите `tg upgrade`. Ничего в архиве не пропадает ([архив и другие версии](./archive.md#the-store-and-other-versions)).

### "для профиля пока ничего не записано — запустите команду один раз без --offline"

Код `6`. `--offline`, `store status`, `store export` читают только локальную базу, а профиль ещё ничего не сохранил. Сначала выполните онлайн-команду, например `tg chats list`.

### `search messages` ничего не находит

Поиск в архиве (`--backend archive`, `--offline` или `--discover`) читает только то, что сохранила эта машина. Без этих параметров обычный поиск по словам может также обращаться к Telegram. Пустой результат в неполной истории не доказывает, что сообщение никогда не отправляли. Прочитайте чат (`tg messages list <chat>`) или получите его историю с помощью `tg store fetch`, затем повторите поиск ([поиск в архиве](./archive.md#search)). `tg store check` показывает, какие чаты требуют обновления.

### Чат читается как полученный полностью, но старые сообщения отсутствуют

Снова выполните `tg store fetch <chat>`. Команда читает сообщения старше самого старого в базе, независимо от того, считался ли чат полным, и доходит до первого сообщения чата; для длинного чата увеличьте `--limit`. Держите `--page-size` не больше 100: Telegram возвращает до 100 сообщений за запрос.

## Фоновый сервер

### "tg serve уже запущен для профиля..."

Код `2`. Разрешён один `serve` на профиль. `tg server status` показывает процесс и время запуска; `tg server stop` останавливает запущенный через `server start` или службу.

### `serve` остановился сам по себе

Причина находится в `tg server logs`. Если Telegram завершил вход, пока работал `serve`, он примерно в течение 15 минут выходит с кодом `4` и не перезапускается: выполните `tg session start`, затем `tg server start`. Если обновления Telegram перестали приходить по другой причине, он выходит с кодом `12`, и systemd запускает его снова.

### Фоновый сервер не запускается

`tg server status --json` включает `stopped` и `unit.exitCode`, когда последний нормальный выход был таким, при котором служба не перезапускается. Для выхода 4 возобновите сессию с помощью `tg session start`, затем `tg server start`. `tg server logs` говорит, почему. В службе обычной причиной является связка ключей: служба запускается до открытия связки ключей или без `XDG_RUNTIME_DIR`. После перемещения Node или `tg` запустите `tg server install` еще раз: служба использует пути, с которыми её установили ([запускается как служба](./archive.md#as-a-service)).

## Сообщить о проблеме

```sh
tg doctor report           # what a report holds, and what it never holds; writes nothing
tg doctor report create    # write it to a file, and say where to send it
tg doctor report create --run <id>    # about another run; ids from tg runs list
```

`create` записывает `tg-report-<time>.json` в текущую папку (или `--output`), доступную для чтения только вам. Он содержит версию, среду выполнения и операционную систему, ответ `tg doctor`, последний неудачный запуск — операцию каждого запроса, продолжительность и код ошибки — и только последние 20 попыток отправки, результат и длину. Каждый идентификатор чата, сообщения и аккаунта заменяется меткой, которая ничего не значит за пределами файла. Он не содержит текста сообщения, заголовков чатов, имен, номеров телефонов, учетных данных сессии или приложения. Неудачный запуск сохраняется отдельно, даже без `--record` ([неудачные запуски](./diagnostics.md#a-failed-run-is-always-kept)).

Создайте обращение на [GitHub](https://github.com/WireCatLabs/tg-cli/issues/new): опишите действия и результат, приложите файл. Обращение и файл публичные: сначала прочитайте его.

⚠ Не прикладывайте каталог состояния, файл сессии или `~/.local/share/cli-messaging/`: они содержат доступ к аккаунту и ваши сообщения.
