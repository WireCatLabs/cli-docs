Используйте эту страницу, если вы хотите, чтобы ваш ИИ-агент (например, Claude Code, Codex, Cursor или Gemini CLI) выполнял регулярную работу с вашим Telegram: утреннюю сводку, отчет по чату, кто что должен, на что вы не ответили. Каждый сценарий дает вам запрос на копирование, команды, которые может выполнять агент, и пишет ли он что-нибудь в Telegram. Вы сможете запускать агента по расписанию, с ограничениями, которые он не может обойти.

Термины на этой странице:

- **Агент** — ИИ-агент, который выполняет за вас команды на вашем компьютере.
- **Skill** — файл, который сообщает агенту, как использовать `tg`. `tg skill install` помещает его туда, где его ищет агент.
- **Клиент MCP** — приложение агента без терминала, например Claude Desktop. Он обращается к `tg` через сервер MCP `tg mcp` вместо выполнения команд.
- **Headless mode** — агент принимает один запрос, выполняет его и выходит без разговора. Claude Code называет это режимом `-p`; Codex называет его `codex exec`.
- **cron** — планировщик, встроенный в Linux и macOS. Он запускает команду в установленное время.

## Подготовка

1. Установите `tg` и войдите в систему: см. [установка](./installation.md) и [вход и сессии](./sessions.md).
2. Дайте агенту skill:

   ```sh
   tg skill install
   ```

Навык находится в папках Claude Code (`~/.claude/skills/tg-cli/`) и Codex и Gemini CLI (`~/.agents/skills/tg-cli/`). `tg skill show` печатает тот же текст, если ваш агент хранит skillи где-то еще.
3. Сохраните приведенные ниже запросы в файлы, например в `~/tg-recipes/`. Команды расписания читают запрос из файла.

Клиенту MCP не нужен skill. Подключите MCP-сервер (`tg mcp config` выводит запись для его настроек) и используйте готовые запросы: `catch-up`, `review`, `reply`, `find`. См. [запросы MCP-сервера](./mcp.md#prompts-and-chats-by-).

## Что может делать агент

Агент по расписанию работает без вас, поэтому лимиты ставьте в настройках, а не в запросе. Агент может неправильно прочитать фразу «ничего не отправлять». Он не может обойти настройку, которую нельзя изменить.

**Ограничить возможности запуска агента.** Это настройка агента. Например, Claude Code в режиме `-p` выполняет только команды из `--allowedTools`. Если в списке нет `tg messages send`, агент не сможет его вызвать:

```sh
claude -p "$(cat ~/tg-recipes/morning.md)" --allowedTools "Bash(tg inbox:*)"
```

В Codex такого списка нет. Его песочница по умолчанию запрещает сеть и запись файлов, а `tg` нужно и то, и другое: он подключается к Telegram и сохраняет то, что читает, в свою локальную копию. Таким образом, Codex работает с `--sandbox danger-full-access`, а приведённые ниже настройки `tg` ограничивают отправку.

**Ограничьте возможности профиля.** Это работает для каждого агента:

```sh
for key in messages reactions polls topics chats contacts account conversations tags searches replies attachments bot; do
  tg config set permissions.$key readonly
done
tg config show                       # check the permissions in force
tg config set sendsPerHour 5         # or: at most five sends an hour
tg recipients add "Book club"        # and only to the chats on this list
```

`readonly` на одном ресурсе не распространяется на остальные: `messages` сам по себе позволяет агенту реагировать, голосовать или менять чаты. Вот почему цикл устанавливает каждый ресурс. Более точный ключ, например `permissions.messages.send: allow`, выигрывает у своего ресурса: удаляйте такие ключи, если профиль нужно только читать.

`permissions` также ограничивает ваши собственные команды, пока вы не измените их обратно: `tg config unset permissions.messages`. Чтобы ограничить только агента, дайте ему собственный профиль. Все попытки отправки, включая отклоненные, записываются в `tg sends list`. См. [защиту отправки](./security.md#the-send-guard) и [что может делать профиль](./configuration-reference.md#what-a-profile-may-do).

**Чтение незаметно для собеседников.** Ни одна команда в сценариях ниже не отмечает прочитанное: никто не увидит, что агент открыл чат.

## Работа по расписанию

- **Запланированные задачи Claude Desktop.** Задача запускается на вашем компьютере, поэтому она имеет `tg` и ваш логин. Запуск, пропущенный во время сна компьютера, выполняется один раз при его пробуждении. См. [Запланированные задачи Claude](https://code.claude.com/docs/en/desktop-scheduled-tasks).
- **cron и `claude -p`.** Приложение не требуется, на любом компьютере, который в данный момент включен:

  ```cron
  30 8 * * * claude -p "$(cat ~/tg-recipes/morning.md)" --allowedTools "Bash(tg inbox:*)" >> ~/tg-recipes/morning.log 2>&1
  ```

cron запускает задания с почти пустой средой. В Linux это ломает `tg` двумя способами:

- **`node: not found`, код выхода 127.** Node из nvm, fnm или Volta отсутствует в системном `PATH`, и cron знает только его.
- **«Учётные данные приложения Telegram не найдены… хотя он вошел в систему на этом компьютере», код выхода 4.** `tg` не может получить доступ к связке ключей (системному хранилищу паролей). **Не входите повторно**: логин в порядке, среда — нет.

Поместите обе строки вверху `crontab -e` со своими значениями. Папка `dirname "$(which node)"`, номер `id -u`:

  ```cron
  PATH=/home/you/.nvm/versions/node/v24.0.0/bin:/usr/local/bin:/usr/bin:/bin
  XDG_RUNTIME_DIR=/run/user/1000
  ```

Системное хранилище ключей открыто, пока вы вошли в систему. Запустите первое задание вручную и прочитайте журнал. См. [Неинтерактивный режим Claude](https://code.claude.com/docs/en/headless).

- **cron и `codex exec`.** То же для Codex:

  ```cron
  30 8 * * * codex exec --sandbox danger-full-access "$(cat ~/tg-recipes/morning.md)" >> ~/tg-recipes/morning.log 2>&1
  ```

См. [Неинтерактивный режим Codex](https://learn.chatgpt.com/docs/non-interactive-mode).
- **Внутри открытой сессии Claude Code**: `/loop` или «Напомни мне в 15:00». Это работает, пока сессия открыта. См. [Запланированные задачи Claude Code](https://code.claude.com/docs/en/scheduled-tasks).

Облачные процедуры Claude не подходят: они запускаются на другом компьютере, где нет ни `tg`, ни вашего логина.

## Утренняя сводка

Изменения в Telegram: **нет**. Разрешите: `Bash(tg inbox:*)`.

> Запустите `tg inbox --new --json`. Группируйте сообщения по чату. Для каждого чата одна строка: кто пишет и чего хочет. Поставьте на первое место то, что требует ответа сегодня. Сложите рекламу и сервисные уведомления в одну строку в конце.

`--new` показывает каждое сообщение один раз. `tg` запоминает, где он остановился в каждом чате, и следующий запуск начинается там. При первом запуске читаются последние 24 часа.

### От какого момента считается новое

- `tg inbox` — непрочитанное, как считает Telegram: то, что вы не открывали ни на одном устройстве.
- `tg inbox --new` — с момента последнего запуска `--new`. Только `tg` знает эту точку; никто больше этого не видит.
- `tg inbox --since-time 2d` — последние два дня; сохраненная точка остается там, где она была.

Ни одна из этих команд не отмечает ничего прочитанным. Для этого добавьте `--mark-read` или включите `catchUpMarksRead` в [настройках](./configuration.md). Другая сторона увидит, что вы это прочитали.

### Прямые чаты, группы и каналы отдельно

`--kind` поддерживает только такие чаты: `dialog` (один на один), `group`, `channel`. Сводка новостей каналов и сводка ваших чатов могут запускаться в разное время. В каждом чате есть своя точка, поэтому один запуск никогда не скрывает то, что еще не показал другой.

```cron
30 8 * * * claude -p "$(cat ~/tg-recipes/morning.md)" --allowedTools "Bash(tg inbox:*)"
0 19 * * * claude -p "$(cat ~/tg-recipes/news.md)" --allowedTools "Bash(tg inbox:*)"
```

В `morning.md`, `tg inbox --new --kind dialog,group --json`; в `news.md`, `tg inbox --new --kind
channel --json` и просьба выбрать самое важное. Без `--kind`, все вместе.

## Еженедельный отчет по чату

Изменения в Telegram: **нет**. Разрешите: `Bash(tg messages list:*)`.

> Читайте последние 7 дней чата "Книжный клуб": `tg messages list "Book club" --after-time 7d --limit 200
> --json`. Если в ответе написано `"hasMore": true`, читайте дальше. Напишите отчет: что решено, кто что взял на себя и к какому сроку, какие вопросы еще открыты. Укажите каждому пункту дату и автора.

## Кто что должен

Изменения в Telegram: **нет**. Разрешите: `Bash(tg review:*)`, `Bash(tg messages context:*)`, `Bash(tg search messages:*)`.

> Запустите `tg review --new --transcribe --json` (первый раз, последние 3 дня; затем с последнего `--new`, точка отсчёта для каждого чата). Разложите его на три списка: что я должен, чего жду от других, что требует уточнения. Присвойте каждой точке свой чат, дату и идентификаторы сообщений, на которых она основана; крайний срок только в том случае, если он был назван. Прежде чем назвать что-то просроченным, проверьте, было ли это сделано позже или в рабочей группе. Если в ответе написано `"complete": false`, скажите мне, чего не хватает. В конце перечислите открытые пункты.

`--transcribe` сначала преобразует голосовые сообщения в текст; это может занять несколько минут. Следующий просмотр — это тот же запрос плюс открытые пункты из предыдущего: агент проверяет их в первую очередь. Чат, прочитанный не полностью, сохраняет свою точку отсчёта и возвращается в следующем запуске. В клиенте MCP это запрос `review`.

## Что осталось без вашего ответа

Самая короткая форма — `tg review --since-time 7d --unanswered --json`: вопросы, на которые никто не ответил — вам в личных чатах, вам или администраторам в группах. Сценарий ниже шире: он также ловит запросы без вопросительного знака.

Изменения в Telegram: **нет**. Разрешите: `Bash(tg chats list:*)`, `Bash(tg messages list:*)`.

> Запустите `tg chats list --kind dialog --limit 30 --json`. Для каждого чата, последнее сообщение которого было получено за последние 7 дней, прочитайте `tg messages list <chat id> --limit 5 --json`. Показать чаты, где последнее сообщение не мое и задает вопрос или делает запрос: кто, о чем и сколько дней назад.

## Найдите то, что было сказано

Изменения в Telegram: **нет**. Разрешите: `Bash(tg search messages:*)`, `Bash(tg messages context:*)`.

> Найдите «счет-фактуру» с помощью `tg search messages invoice --json`. Для каждого попадания прочитайте `tg messages context <locator> --json` и скажите мне, кто, что сказал и когда.

По умолчанию поиск ищет как копию на этом компьютере, так и на сервере Telegram. Локальная копия содержит только то, что сохранил `tg`. Чтобы выполнить локальный поиск по всей истории чата, сначала скачайте ее. Это запрос от вашего аккаунта, поэтому сделайте это сами: `tg store fetch <chat>`. См. [получение истории чата](./archive.md#fetch-a-chats-history).

## Составьте ответ

Изменения в Telegram: **только после вашего согласия**. Это для разговора с агентом, а не для расписания.

> Прочитайте последние 20 сообщений чата с @example_user и предложите ответ на его последний вопрос. Не отправляйте — покажите мне текст.

Как только вы согласитесь, агент отправит его: `tg messages send @example_user "…"`. Клиент MCP подключается к `tg mcp`. Оставьте `tg_write` неутвержденным в клиенте, и он будет спрашивать вас перед каждой отправкой. Разрешения профиля по-прежнему ограничивают то, что он может писать. См. [сервер MCP](./mcp.md).

## Группа, которую вы возглавляете

Изменения в Telegram: **только если правила группы это позволяют**. Разрешите: `Bash(tg review:*)`, `Bash(tg chats events:*)`, `Bash(tg chats members list:*)`, `Bash(tg chats moderate:*)`.

> Запустите `tg review --chat "Hiking" --unanswered 4h --json`, `tg chats events "Hiking" --since-time 7d
> --json` и `tg chats moderate "Hiking" --dry-run --json`. Кратко: какие вопросы ждут ответа, от кого и с каких пор; кто присоединился или был добавлен на этой неделе и кем; что проверка выявила против правил группы и что она предполагает. Не отвечайте и не удаляйте никого — перечислите команды, которые сделают это, если я согласен.

С `--dry-run` команда `chats moderate` только составляет план. Без него он действует настолько, насколько позволяют правила группы, поэтому оставьте `Bash(tg chats moderate:*)` вне списка, если агент никогда не должен действовать. Каждый сценарий для группы: [группы, которыми вы управляете](./groups.md).

## Похожие коллекции

Сценарии других авторов для Telegram и агента. Их запросы работают с `tg`, если вы замените инструменты командами:

- [Telegram MCP: полное руководство](https://mcp.directory/blog/telegram-mcp-complete-guide-2026) — утренний просмотр входящих, черновики ответов, дайджест канала, поиск по нескольким чатам.
- [pioh/tg](https://github.com/pioh/tg) — ИИ-агент с личным аккаунтом в Telegram: дайджест каждые N минут, «напомни, если я не ответил маме за 15 минут», просмотр людей и чатов.
- [Кулинарная книга Gorgias MCP](https://github.com/gorgias/mcp-cookbook) — рецепты для поддержки клиентов, но сделаны хорошо: в каждом написано, пишет ли что-нибудь, и что изменить под себя.
