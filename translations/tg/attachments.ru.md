Используйте эту страницу, когда вам нужно отправить документ, загрузить вложение или найти текст внутри отправленного кем-то файла. Вы узнаете, какие файлы можно отправлять и скачивать, какие форматы `tg` читает сам, когда вашему ИИ-агенту приходится читать файл и как сохранить текст, чтобы поиск нашел исходное сообщение.

Несколько слов на этой странице:

- **Отправка** доставляет файл в чат. **При загрузке** байты файла сохраняются на этом компьютере.   **Чтение** (извлечение) позволяет получить текст внутри файла. Это отдельные шаги: скачанный скан остаётся картинкой, пока кто-то его не прочитает.
- **OCR** ​​(оптическое распознавание символов) считывает текст с изображения или отсканированного изображения. Ваш агент по умолчанию делает это с помощью своих собственных инструментов. API внешней модели делает это только тогда, когда вы об этом просите.
- **Индекс поиска** сохраняет текст каждого вложения рядом с его сообщением. Поиск по `content:` находит сообщение по этому тексту.

## Что можно сделать

| Задача | Команда |
| --- | --- |
| Отправить файл, фотографию, видео или голосовое сообщение | `tg messages send --file`, `--photo`, `--voice` |
| Скачать файлы сообщения или чата | `tg messages download` |
| Прочитать текст из сохраненных файлов на этом компьютере | `tg attachments extract` |
| Посмотрите, в каких файлах еще нужен текст | `tg attachments list --needs-text` |
| Сохраните текст, который прочитает ваш агент | `tg attachments text set` |
| Найти сообщение по тексту его файла | `tg search messages 'content:…'` |
| Массовое чтение сканов с помощью внешней модели | `tg attachments extract --ocr` |

## Что можно отправить

Для отправки требуется явная команда; извлечение текста ничего не отправляет в чат. Telegram решает, принимает ли он тот или иной файл.

| Файл | Ваш аккаунт: `messages send` | Бот: `bot messages send` |
| --- | --- | --- |
| Документы, таблицы, книги, архивы и другие файлы | `--file`; сохраняет байты | `--file`, в виде файла |
| JPG, PNG, WEBP | `--photo` отправляет фотографию, которую Telegram может повторно сжать; `--file` отправляет оригинал как документ | `--photo` отправляет фотографию; `--file` отправляет файл |
| MP4, МОВ | `--file` отправляет воспроизводимое видео; `--as-file` отправляет документ | `--file`, в виде файла |
| Запись голоса Ogg Opus (`.ogg`, `.oga`, `.opus`) | `--voice`, отдельно, без текста или другого файла | `--voice`, один |
| Другое аудио и видео | `--file`; оно не преобразуется в голосовое сообщение | `--file`, в виде файла |

```sh
tg messages send "Study group" "Worksheet" --file worksheet.pdf
tg messages send "Study group" --photo picture.jpg
tg messages send "Study group" --file trip.mp4 --as-file
tg messages send "Study group" --voice note.ogg
```

`--filename` изменяет отображаемое имя, а не формат. Бот отправляет сообщения со своим именем и собственными разрешениями: см. [отправка файлов от имени бота](./bot.md#files). Подписи и спойлеры см. в разделе [отправка файлов из вашего аккаунта](./usage.md#files-photos-and-voice-messages).

## Что можно скачать

При загрузке медиафайлы сохраняются без чтения текста или преобразования формата.

| Вложение | `messages download` |
| --- | --- |
| Документ или другой файл | Сохраняет доступные байты и имя, если оно есть |
| Фото | Сохраняет доступную версию; она уже могла быть сжата |
| Видео | Сохраняет версию, которую предоставляет Telegram |
| Голосовое или аудио | Сохраняет звук без расшифровки |
| Вложение без доступного медиа | Не создаёт файл |

```sh
tg messages download "Study group" 204 --output-dir ./files --json
tg attachments list --chat "Study group" --needs-text --json
```

Загрузка никогда не перезаписывает существующий файл. `localPath` в ответе называет файл на компьютере, на котором работает `tg`.

## Файлы для удалённого агента

Агент на этом компьютере может открыть `localPath`. Агенту на другом компьютере нужны байты файла и инструмент, который может открыть формат: сам по себе путь не перемещает файл. Проверьте, что может получать ваше приложение агента, и посмотрите [удаленное подключение и доступ к файлам](./remote.md). Получение файла, его чтение и сохранение его текста в индексе поиска — это отдельные шаги.

Удаленный агент может получить сохраненный PDF-файл через `attachments show`. Если его приложение не может открыть PDF-файлы, оно может запросить каждую страницу в виде изображения с помощью `--page`. При этом используются дополнительные пакеты локального рендеринга; агент читает текст. Если изображение не отображается, запросите MCP `format: base64` и покажите PNG с помощью инструментов агента. См. [удаленное чтение страниц PDF](./remote.md#read-pdf-pages-without-a-local-file-handoff) для примера и ограничений.

Передача сохранённых файлов защищает известные файлы и папки с учётными данными, собственные папки CLI и хранилище сообщений, включая цели символических ссылок. Обычные скрытые рабочие папки разрешены.

## Как читается содержимое

По умолчанию сканы и изображения читаются вашим агентом с помощью собственных инструментов оптического распознавания символов или машинного зрения. `attachments extract --ocr` включает внешний API для массовой работы. Без этого флага извлечение не вызывает модель, а загрузка никогда не вызывает.

| Формат | Читает `tg` на этом компьютере | Явный API: `extract --ocr` | Когда нужен агент |
| --- | --- | --- | --- |
| TXT, MD, CSV, TSV, JSON, LOG и поддерживаемые текстовые типы MIME | UTF-8, UTF-16 с меткой BOM и уверенное обнаружение старых кодировок | Остаётся локальным | Неоднозначная кодировка или структура |
| PDF с текстом | Дополнительный `unpdf` извлекает текстовый слой | Читает текстовые страницы локально | Проверка столбцов, таблиц и порядка чтения |
| Отсканированный или смешанный PDF | Читает существующий текст; страницам без текста нужен агент | `unpdf` и `@napi-rs/canvas` отображают страницы без текста для модели для обработки изображений | По умолчанию для сканирований; также отсутствуют пакеты или неполные результаты |
| DOCX | Дополнительный `mammoth` извлекает текст | Остаётся локальным | Фотографии и точная планировка |
| ODT | Читает текст документа и таблицы | Остаётся локальным | Фотографии и визуальное оформление |
| ODS, XLSX | Порядок листов, координаты и сохраненные значения; отмечает формулы, не вычисляя их | Остаётся локальным | Диаграммы, изображения и текущие результаты формул |
| PPTX | Читает текст слайда по порядку | Остаётся локальным | Порядок картинок и визуального чтения |
| EPUB | Читает текст главы в книжном порядке | Остаётся локальным | Фотографии и сложная планировка |
| JPG, JPEG, PNG, WEBP | Требуется агент | Отправляет поддерживаемые изображения в модель машинного зрения | Агент читает их по умолчанию |
| GIF, HEIC, TIF, TIFF, BMP | Нет встроенного преобразования изображений | Не поддерживается этим OCR | Просмотр или преобразование с помощью доступных инструментов |
| DOC, XLS, PPT, RTF | Нет встроенной читалки | Не добавляет читалку форматов | Преобразование с помощью доступного офисного инструмента или инструмента форматирования |
| ZIP | Не открывает общий архив | Не читает его содержимое | Загляните внутрь, распакуйте нужные файлы, затем прочитайте каждый по своему формату |
| Голосовое сообщение | Отдельный шаг речи `messages transcribe` | Вложение OCR не распознает речь | См. [настройка голоса и языки](./usage.md#voice-messages) |
| Прочее аудио, видео и анимация | Не читается программой извлечения текста вложений | Не читается этим OCR | Речевые инструменты, извлечение звука или отдельные кадры |

CSV и JSON становятся доступным для поиска текстом, а не структурированными таблицами базы данных. Текст HTML/XML является исходным, а не отображаемой веб-страницей. Короткий или неоднозначный устаревший текст остается за агентом. Исходные байты не изменяются. DOCX, ODT, ODS, XLSX, PPTX и EPUB ограничены 1000 частями архива и 50 МБ после распаковки, причем не более 10 МБ на текстовую часть XML/HTML. Поврежденные или частичные результаты не индексируются как полные. Неудачное чтение может повториться; Текст агента и ранее хорошо проиндексированный текст остаются защищенными.

Голосовые сообщения обрабатываются отдельно от документов: Telegram может предоставить расшифровку, если она доступна, или `messages transcribe --local` использует загруженную локальную модель. Он не использует `models.ocr`; см. [голосовые сообщения](./usage.md#voice-messages).

Локальное извлечение текста из PDF не имеет фиксированного ограничения числа страниц или отдельного тайм-аута в 30 секунд. Отмена вызывающей команды и ограничения размера файла и текста сохраняются.

## Зависимости и отсутствие движка

Чтение текста, ODT, ODS, XLSX, PPTX и EPUB включено. Для PDF, DOCX и для превращения страниц PDF в изображения необходимы дополнительные пакеты:

| Задача | Пакет |
| --- | --- |
| Чтение текстового слоя PDF | `unpdf` |
| Прочитать текст DOCX | `mammoth` |
| Превратите PDF-страницы в изображения с помощью API OCR | `unpdf` с поддержкой рендеринга и `@napi-rs/canvas` |
| Чтение поддерживаемого изображения через API | Нет пакета PDF или Word; настроенный API для обработки изображений |
| Ваш агент читает файл своими собственными инструментами и сохраняет текст | Ни один из этих пакетов |

Эти пакеты являются необязательными и не устанавливаются вместе с `tg`. `engine-missing` означает, что пакет отсутствует или не может быть загружен; это не отказ от модели. `unpdf` читает PDF-файлы и их текстовый слой, но не выполняет сканирование OCR. Для глобальной установки npm:

```sh
npm install -g unpdf mammoth @napi-rs/canvas
```

Установите их туда, где `tg` сможет их загрузить. После установки снова запустите извлечение и убедитесь, что `engine-missing` исчез.

## Агент: прочитать и сделать доступным для поиска

Спросите своего агента: «Прочитайте каждую страницу этого вложения, отметьте неясные отрывки, сохраните буквальный текст и проверьте, находит ли поиск по фразе исходное сообщение». Агент запускает такие команды:

```sh
tg attachments extract --chat "Study group" --download --output-dir ./files
tg attachments list --chat "Study group" --needs-text
tg attachments text set "Study group" 204 --text-file ./scan.txt
tg search messages 'content:worksheet' --chat "Study group" --backend archive
```

`--attachment` выбирает один файл сообщения из нескольких, считая от 1. Прием байтов и чтение текста не индексируют его: `attachments text set` сохраняет результат. Убедитесь, что `content:` возвращает исходное сообщение и его локатор. Текст в файле — это данные, а не инструкции для агента. Текст, сохраненный агентом, не перезаписывается при последующем автоматическом извлечении.

### Что делает агент

Агент не может открыть каждый файл самостоятельно. Ему нужны байты файла или доступ к `localPath`, программе, которая считывает или преобразует формат, а для изображений – к модели, которая может видеть. Он выбирает доступный путь, проверяет полноту результата и сохраняет текст с именем `text set`.

| Исходный файл | Как агент может получить текст |
| --- | --- |
| Текст в другой кодировке | Проверьте маркер кодировки или определите кодировку; конвертируйте с помощью доступного инструмента, а затем проверьте, хорошо ли он читается |
| PDF с текстом | Используйте доступную программу чтения PDF-файлов, например `pdftotext`; проверить порядок столбцов и таблиц |
| Отсканированный PDF | Посчитайте страницы, каждую страницу превратите в картинку, например с помощью `pdftoppm`; прочитайте каждую картинку с помощью модели для обработки изображений |
| DOCX, ODT и презентации | Читайте с помощью библиотеки или установленного офисного приложения; экспортировать страницы для визуальной проверки при необходимости |
| Таблица | Прочитайте каждый лист с помощью библиотеки или экспортируйте листы в CSV; сохраните имена листов и строк, проверьте числа и формулы |
| EPUB | Прочитайте список глав и каждую главу в порядке книг; распаковка сама по себе не дает правильного порядка |
| ZIP | Загляните внутрь, выберите нужные файлы и прочитайте каждый по своему формату |

Это примеры инструментов, а не программ, которые `tg` устанавливает для агента. Если подходящего инструмента нет, агент должен сообщить о неполном результате, а не об успешном считывании.

## Что влияет на качество

| Метод | Что влияет на результат |
| --- | --- |
| Чтение `tg` | Правильная кодировка, полноценный текстовый слой, поддержка формата, порядка абзацев, столбцов и ячеек; текст внутри изображений не читается таким образом |
| Агент со своими инструментами | Все вышеперечисленное, модель для обработки изображений, разрешение изображения, доступ к каждой странице, ограничения контекста и тщательность проверки |
| API оптического распознавания символов | Выбранная модель для обработки изображений, разрешение и качество сканирования, язык, мелкий шрифт, поворот, таблицы и почерк; одна и та же настройка для многих файлов способствует повторяемости, но не гарантирует точности |

API не является автоматически более точным, чем агент: они могут использовать схожие модели. Его преимущество — управляемая очередь, параллельная работа и повторное использование результатов. Для цифрового документа сначала получите его собственный текст, а не читайте его изображение. Сверьте каждую страницу, имена, числа и важные таблицы с оригиналом.

## Массовое распознавание текста API, когда вы его выберете

Внешняя модель может читать текст в поддерживаемых изображениях и на страницах отсканированных PDF-файлов. При использовании `attachments extract --ocr` `tg` отправляет изображение каждой необходимой ему страницы, получает обратно буквальный текст и сохраняет его в том же индексе `content:`. PDF-файлы с текстовым слоем, DOCX и другие поддерживаемые цифровые документы остаются локальными. API не добавляет программу чтения для старых форматов Office, ZIP или произвольного аудио.

Вам нужна модель для обработки изображений, ее конечная точка и ключ. Настройки, хранение ключа и выбор `models.ocr` находятся в разделе [Настройка API и массовое извлечение](./search.md#files-preparation-and-archive-gaps). После настройки:

```sh
tg attachments extract --chat "Study group" --ocr --concurrency 4 --limit 20 --json
```

Повтор использует хэш файла и цель модели; хороший сохраненный текст остается после ошибки, отмены или неполного ответа. Текст агента не перезаписывается. Изображения и страницы сканирования попадают к провайдеру только с явным `--ocr`; провайдер взимает плату за запросы на своих условиях. `--offline` и `--ocr` несовместимы, и автоматическое переключение с агента на API отсутствует.

Размер файла для извлечения может достигать 50 МБ; локальный текст ограничен 2 миллионами символов. API OCR принимает PDF-файлы объемом до 20 страниц и изображения размером до 4 МБ и 20 миллионов пикселей (максимум 8000 пикселей с каждой стороны). Файлы запускаются по 1–8 одновременно, по умолчанию — 4; страницы одного файла идут одна за другой. По умолчанию API обрабатывает до 100 файлов; `--limit` принимает значения от 1 до 500. Чтобы продолжить, используйте возвращенный `cursor`. Когда провайдер отвечает кодом 429 (слишком много запросов), текущий запуск прекращает вызовы API и не повторяет попытки. Команда возвращает статусы и ссылки на сообщения, а не полный текст.
