Каждый сценарий описывает частую задачу по шагам: какие команды выполнить, зачем нужна каждая и на что смотреть в ответе. Те же сценарии есть в терминале: `b24 guide` показывает список, а `b24 guide <name>` выводит один сценарий.

Команды, которые работают с аккаунтом, начинаются с профиля, то есть имени, которое вы дали аккаунту при входе: `b24 <profile> …`.

## Первая синхронизация и доска воронки

Скопируйте свои сделки и лиды в локальное хранилище и посмотрите, на какой стадии каждая.

1. ```sh
   b24 session start
   ```

   вставьте адрес входящего вебхука портала, он проверяется на портале и сохраняется в связке ключей

2. ```sh
   b24 session status --check
   ```

   сотрудник, от имени которого действует вебхук, и является ли он администратором Битрикс24

3. ```sh
   b24 users list
   ```

   ваш собственный id пользователя и id коллег, чьи сделки вам нужны

4. ```sh
   b24 config set crm.bitrix24:example.bitrix24.ru.unassigned 1
   ```

   чьи сделки и лиды копировать, по id пользователей через запятую, с адресом вашего портала вместо example.bitrix24.ru. Пока вы не выберете, синхронизация ничего не копирует

5. ```sh
   b24 sync
   ```

   копирует сделки и лиды выбранных пользователей и их клиентов, а следующая синхронизация берет только изменения

6. ```sh
   b24 pipelines show Sales
   ```

   воронка в виде доски: сколько сделок стоит на каждой стадии и сколько до нее дошло

7. ```sh
   b24 deals list status:open
   ```

   открытые сделки со стадией, суммой и ответственным, из хранилища, в том числе без интернета

На что смотреть:

- scope в ответе sync, он говорит, чьи сделки и лиды скопированы
- issues в ответе sync, например пользователь, которого нельзя взять, или право, которого нет у вебхука
- стадию, на которой ждет больше всего сделок

`example.bitrix24.ru` здесь означает адрес вашего портала, а `1` означает выбранные вами id. Вебхук часто
принадлежит коллеге, поэтому b24 никогда сам не выбирает, чьи сделки копировать.

В терминале: `b24 guide first-sync`

## Держать копию свежей

Пусть локальное хранилище само следует за порталом, а искать в нем можно рядом с другими инструментами WireCat.

1. ```sh
   b24 schedule command crm --every 1h -- sync
   ```

   таймер на этом компьютере, который запускает sync каждый час и читает только то, что изменилось

2. ```sh
   b24 schedule list
   ```

   расписание, когда следующий запуск и как прошел последний

3. ```sh
   b24 store status
   ```

   насколько продвинулась синхронизация каждого вида записей, сколько записей сохранено и когда был последний запуск

4. ```sh
   b24 search all kitchen
   ```

   сохраненные сделки и лиды рядом с вашими сообщениями, заметками и встречами из других инструментов WireCat

На что смотреть:

- расписание, последний запуск которого не удался
- вид записей в store status, который скопирован не полностью, его продолжит следующая синхронизация

В терминале: `b24 guide keep-in-sync`

## Дать агенту менять CRM без сюрпризов

Дайте агенту доступ к CRM через MCP, а записи, которые доходят до клиентов или которые нельзя отменить, оставьте за собой.

1. ```sh
   b24 config set permissions.deals.move readonly
   ```

   смена стадии может запустить роботов портала, а они пишут клиентам. Через MCP ask ничего не спрашивает, поэтому там ask ничего не останавливает

2. ```sh
   b24 config set permissions.deals.delete deny
   ```

   ни один агент не удалит сделку, о чем бы его ни попросили

3. ```sh
   b24 mcp add claude-code --permission leads.delete=deny --allow-writes
   ```

   подключает этот профиль к Claude Code. Этот сервер также отклоняет удаление лидов, а --allow-writes подтверждает записи, которые он еще предлагает

4. ```sh
   b24 config show
   ```

   каждое право с его уровнем и тем, откуда он взялся

5. ```sh
   b24 runs list
   ```

   что запускал агент, в том числе отклоненные записи

На что смотреть:

- уровни deals.move, deals.delete и leads.delete в config show
- отклоненные запуски в runs list и команду, которая их запросила

В терминале `ask` по-прежнему спрашивает перед записью. Через MCP ответить некому, поэтому запись на уровне `ask`
выполняется. Задайте `readonly` или `deny` или включите подтверждение `b24_write` в клиенте агента.

В терминале: `b24 guide safe-agent-writes`
