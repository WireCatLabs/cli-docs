title: "Звонки"

Прочитайте эту страницу, если телефоны вашей компании работают через телефонию Битрикс24. Здесь описано, как
скопировать звонки портала в локальное хранилище WireCat, превратить их записи в текст на этом компьютере и найти
звонки клиента рядом с его сделками, сообщениями и почтой. В итоге `memo context` покажет звонки клиента в его
истории.

Слова, которые использует эта страница:

- **История звонков**: список звонков, который портал хранит в разделе «Телефония → Детализация звонков». b24 читает его
  методом `voximplant.statistic.get`.
- **Профиль**: имя входа на один портал, например `work`. Это первое слово команды.

## Перед первой синхронизацией

Вебхуку нужно право `telephony`, кроме `crm`, `user_basic` и `department`. Измените вебхук в разделе «Разработчикам →
Интеграции», отметьте «Телефония» и сохраните. Локальному приложению нужно то же право в его карточке.
Сотруднику, который создал вебхук, также нужно право портала на просмотр статистики звонков.

Копирование звонков только читает. Ни одна команда не звонит и не меняет линию. На портал пишет только
`calls export`, и он выключен, пока вы его не включите. Подробнее в разделе
[Записать звонки других телефонных систем в Битрикс24](#write-other-phone-systems-calls-into-bitrix24).

## Скопировать звонки

`b24 work sync` копирует звонки после CRM и пишет их число в своем ответе. Если звонки скопировать не удалось,
например у вебхука нет права на телефонию, он объясняет причину в заметке, а синхронизация CRM все равно проходит.
Чтобы `sync` не копировал звонки, выполните `b24 work config set sync_calls false`. `meetings sync` копирует только
звонки:

```sh
b24 work meetings sync                                   # calls since the last sync; the first reads 30 days
b24 work meetings sync --since-time 2026-11-01T00:00:00Z # calls from a date on
b24 work meetings list                                   # newest first, from the store, offline too
b24 work meetings show 12                                # one call: who, when, how it ended
```

Каждый звонок хранится как встреча вида «звонок». У него есть направление (входящий или исходящий), номер клиента,
сотрудник, длительность разговора и то, чем звонок закончился: отвечен, не отвечен, занято или ошибка. Еще он хранит
контакт, компанию или лид CRM, к которым портал привязал звонок, и дело CRM этого звонка, в виде номеров для поиска.

Первая синхронизация на загруженной линии читает много страниц, прежде чем что-то сохранить. Если она останавливается
по лимиту времени, дайте ей окно короче или больше времени: `meetings sync --since-time 7d` или `--timeout 5m`.

Каждая синхронизация снова читает три часа перед прошлой, поэтому звонок, который еще шел, найдется в следующий раз.
Таймер, который запускает `sync`, тоже держит звонки в актуальном виде.

### Чьи звонки

Правило то же, что для сделок: копия никогда не бывает всем порталом. `meetings sync` копирует звонки пользователя,
который вошел, или пользователей, которых вы выбрали в `crm.bitrix24:<portal>.unassigned`
(см. [Чьи сделки и лиды](./usage.md#whose-deals-and-leads)).
Профиль, у которого `scope` равен `all`, отказывается синхронизировать звонки, пока вы не зададите `mine`.

## Клиент и сотрудник

Сотрудник в звонке это тот же человек, что и пользователь портала в вашей копии: его звонки видны у этого человека.

Клиента находят по номеру. Номер, который портал пишет с `+`, читается как есть. Номеру без `+`, например
`79000000001`, нужна страна:

```sh
b24 work config set phone_region ru        # or several: ru,kz
b24 work meetings sync --rescan            # read the calls again with it
```

Без `phone_region`, или когда две его страны читают номер по-разному, номер хранится как написан и ни с кем не
связывается. С ним звонок с мобильного номера связывается с контактом, с аккаунтом WhatsApp или Telegram или со
звонками из другой телефонной системы с тем же номером. Городской номер сам по себе ни с кем не связывается: офисная
линия принадлежит всем, кто там работает.

```sh
memo context person:12        # the client's history: messages, mail and calls, newest first
```

## Записи разговоров

Записи остаются на портале, пока вы их не запросите:

```sh
b24 work config set download_recordings true
b24 work meetings sync         # downloads the recording of each new call
```

Каждая запись сохраняется в папке состояния b24, в `recordings/<profile>/`, и читать ее можете только вы.
`meetings show` выдает ее путь как `local_path`, а WireCat Desktop ее проигрывает. Запись может занимать несколько
мегабайт на звонок: проверьте свободное место, прежде чем включать это для загруженной линии.

Ссылка, которую портал дает на запись, содержит токен доступа. b24 переходит по ней только на собственный адрес
портала, сразу после чтения, и никогда ее не сохраняет и не печатает.

## Превратить звонки в текст

Текст создается на этом компьютере локальной моделью речи: ни одна запись его не покидает.

```sh
b24 models download gigaam-v3        # once, a few hundred megabytes
b24 work meetings transcribe         # calls of five seconds or more with no text yet, newest first
b24 work meetings transcript 12      # one call's text
```

Запись, сохраненная через `download_recordings`, читается с этого компьютера. Любая другая скачивается для
расшифровки и остается только при включенном `download_recordings`. Битрикс24 не сообщает, какая сторона
стереозаписи сотрудник, поэтому в тексте каналы называются "Channel 1" и "Channel 2". Звонок длиннее часа
пропускается.

## Разрешения

У каждой команды свой ключ: `meetings.sync`, `meetings.transcribe`, `meetings.list` и другие. Чтобы агенты не
копировали звонки:

```sh
b24 work config set permissions.meetings.sync deny
```

`api call voximplant.statistic.get` остается запрещенным: в его ответе есть ссылки на записи с их токенами. Подробнее
на странице [Разрешения](./permissions.md).

## Записать звонки других телефонных систем в Битрикс24

Звонки из другой телефонной системы, например pbx, могут попадать в контакт клиента в Битрикс24, и тогда CRM
показывает их рядом с собственными звонками портала. Это выключено, пока вы это не включите, и каждый звонок
записывается один раз.

Битрикс24 разрешает записывать звонок только приложению, а не вебхуку. Сначала войдите в профиль как локальное
приложение:
`b24 work session start --portal <portal> --client-id <id>`. Затем включите запись и разрешите два ее метода:

```sh
b24 work config set export_calls true
b24 work config set permissions.api.telephony.externalcall.register allow
b24 work config set permissions.api.telephony.externalcall.finish allow
b24 work calls export --since-time 7d --dry-run   # each call, the fields it would send, where it would land
b24 work calls export --since-time 7d
```

Звонок попадает в портал, только когда его клиент связан ровно с одним контактом этого портала, а его сотрудник с
одним пользователем портала (их связывает `memo people link`). Любой другой звонок попадает в список пропущенных с
причиной. Собственные звонки портала пропускаются: они уже есть в Битрикс24.

Каждый звонок регистрируется и завершается через `telephony.externalCall.register` и `telephony.externalCall.finish`,
без новой записи CRM, без карточки звонка и без сообщения в чате. b24 хранит записанные звонки в своей папке
состояния, в `calls-export/<portal>.json`, поэтому повторный запуск никогда не запишет звонок снова. Сам Битрикс24
замечает повтор только в течение 30 минут.

Чтобы остановить, выполните `b24 work config set export_calls false`. Ничего из записанного на портал не удаляется.
