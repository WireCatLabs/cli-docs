Подключите рабочее пространство Slack один раз, и дальше ИИ-агент читает и ищет ваши каналы, личные сообщения и ветки
от вашего имени. Slack дает программе читать сообщения только через приложение, установленное в пространстве,
поэтому небольшое приложение для `slk` вы создаете сами. Создать приложение, установить `slk` и войти можно примерно
за десять минут.

Когда закончите, агент на этом компьютере видит то же, что вы в Slack, находит сообщения собственным поиском Slack и
отправляет только то, что вы попросите. Нужно право устанавливать приложения в пространстве или администратор,
который одобрит приложение.

## Коротко

1. [Создайте приложение](#создайте-свое-приложение-slack) по ссылке, которая заполняет его настройки.
2. [Установите его](#установите-приложение-и-скопируйте-токен) в пространство и скопируйте **User OAuth Token**.
3. Установите инструмент, и `setup` попросит токен:

```sh
npm install -g @wirecat/slack-cli
slk personal setup
```

## Что нужно

- Рабочее пространство Slack, где вам можно устанавливать приложения. В некоторых пространствах это может только
  администратор. Тогда Slack предложит отправить запрос, и вы установите приложение, когда администратор его одобрит.
- Node.js 22.16 или новее в ветке 22.x, либо Node.js 24 или новее. Node 23 не поддерживается.

## Почему свое приложение

Slack дает программе доступ к сообщениям только через приложение, и от приложения зависит, как быстро программа
читает. С мая 2025 года приложение, которое другая компания публикует вне Slack Marketplace, может читать историю
канала [по одной странице из 15 сообщений в минуту](https://docs.slack.dev/changelog/2025/05/29/rate-limit-changes-for-non-marketplace-apps).
Приложение, созданное в вашем собственном пространстве, сохраняет обычные лимиты. И оно принадлежит вам: его токен
ни у кого больше нет, и пользуетесь им только вы.

Приложение просит только то, что нужно командам: читать каналы, личные сообщения, людей, файлы, реакции и
закрепленные сообщения, искать и отправлять от вашего имени.

   Slack откроет **Create New App**, где настройки `slk` уже заполнены.
3. Выберите свое пространство в списке и нажимайте **Next**, пока не появится **Create**, затем нажмите **Create**.
   По пути ничего менять не нужно.
4. Slack откроет страницу приложения **Basic Information**. Client ID, Client Secret, Signing Secret и Verification

Если ссылка не открывает форму, перейдите на [api.slack.com/apps](https://api.slack.com/apps), нажмите

## Установите приложение и скопируйте токен

1. На странице приложения, в меню слева, нажмите **OAuth & Permissions**. Если страница потерялась, откройте
   [api.slack.com/apps](https://api.slack.com/apps) и нажмите **WireCat slk**.
2. Нажмите **Install to Workspace**. Вместо слова Workspace Slack может показать название вашего пространства. Он
   перечислит, что приложение может делать от вашего имени: читать и отправлять сообщения, видеть людей и файлы.
   Нажмите **Allow**.
3. Вы снова на **OAuth & Permissions**. В разделе **OAuth Tokens** найдите **User OAuth Token**. Он начинается с
   `xoxp-`. Нажмите **Copy**.

Если вместо установки Slack предлагает отправить запрос, приложения в этом пространстве устанавливает только
администратор. Отправьте запрос. Когда администратор его одобрит, снова откройте **OAuth & Permissions** и нажмите
**Install to Workspace**.

Копируйте только токен, который начинается с `xoxp-`. Токен бота (`xoxb-`) не подойдет, потому что бот видит только
каналы, в которые его добавили, а `slk` читает от вашего имени.

## Установите slk

Установите `slk` один раз на каждый компьютер, где им пользуетесь вы или агент:

```sh
npm install -g @wirecat/slack-cli
slk --version
slk doctor
```

Команда называется `slk`, а не `slack`, потому что `slack` - это имя собственного CLI Slack для разработчиков.
`doctor` не ходит в сеть и не открывает связку ключей. Он показывает версию, где лежат настройки, какие профили есть и
могут ли другие пользователи компьютера читать настройки.

Дайте агенту в терминале навык инструмента, короткое руководство по его командам. Приложение, которое подключается к
MCP-серверам, использует инструмент через MCP, как показано в разделе [как пользоваться](./usage.md#agents).

```sh
slk skill install
```

## Войдите

Профиль - имя, которое вы выбираете для одного пространства Slack, например `personal` или `work`. С него начинается
каждая команда, которой нужен аккаунт. Войдите в профиль с токеном:

```sh
slk personal setup
```

`setup` показывает те же шаги, что эта страница, по одному и затем просит токен. `slk personal session start` просит
его сразу. Обе команды читают токен скрытым вводом или из stdin, никогда как аргумент, поэтому он не попадает в
историю оболочки. Сначала токен проверяется в Slack. Потом он попадает в связку ключей системы, а где она не
работает, в файл, доступный только вам, с `--credential-storage file`.

## Проверьте, что все работает

```sh
slk personal session status --check
slk personal chats list
slk personal inbox
```

`session status --check` спрашивает Slack, чей это токен. `chats list` показывает каналы, личные и групповые
сообщения, где вы участвуете, а `inbox` показывает непрочитанное.

## Выход

`slk personal session end` забывает токен на этом компьютере. Сам токен в Slack действует, пока приложение
установлено. Чтобы отозвать его, удалите приложение из пространства.
