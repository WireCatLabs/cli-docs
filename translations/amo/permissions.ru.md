title: "Разрешения"

Пусть ИИ-агент работает в вашей CRM через `amo`, а решение о том, что он меняет, остается за вами. Токен несет права
администратора, который его создал, поэтому без ваших собственных ограничений агент мог бы сделать многое из того,
что может этот администратор.

Для каждого профиля, то есть имени, которое вы дали входу в один аккаунт, вы решаете, что агент может только читать,
что сначала спрашивает вас и что выполняется сразу. Вы можете запретить агенту двигать или закрывать сделки и знаете,
какие проверки действуют, что бы ни говорили настройки.

У каждой команды есть ключ разрешения, например `deals.move`, и у каждой операции API amoCRM тоже. У каждого ключа
есть уровень: `allow`, `ask`, `readonly` или `deny`. Уровни задаются через `amo work config set`, и ослабить уровень
можете только вы: агенту, который пытается это сделать, отказывают.

## Уровни

- `allow` выполняет команду.
- `ask` спрашивает вас в терминале перед записью. В скрипте ответить некому, поэтому запись останавливается с кодом 7,
  если у команды нет `--yes`. Через MCP запись выполняется.
- `readonly` пропускает чтение по ключу и отклоняет его записи.
- `deny` отклоняет ключ, чтение тоже.

```sh
amo work config set permissions.deals.close deny   # this profile closes no deal
amo work config show                               # each permission with its level and where it came from
```

Групповой ключ покрывает все ключи под ним, а более длинный ключ побеждает: `api.leads` покрывает все операции со
сделками, а `api.leads.id.get` все равно может от него отличаться. `--dry-run` на записи показывает каждый ключ,
который она проверяет, с его уровнем, и ничего не отправляет.

## Что разрешает новый профиль

- **Разрешено:** то, что читают собственные команды `amo`, например сделки, контакты, компании, воронки, поля,
  пользователи, задачи и события, а также создание, изменение, перемещение и закрытие сделок, контактов и компаний.
- **Сначала спрашивает:** любое другое чтение, например примечания или неразобранное, другие записи и любое удаление.
- **Запрещено, чтение тоже:** беседы, чаты, Salesbot, вебхуки, виджеты, кнопки на сайте, звонки, а также включение и
  отключение пользователей.
- **Запрещенные записи:** добавление пользователей и запись задач, ролей и источников сделок. `crm.assign-others`
  тоже запрещен, поэтому ни одна запись не передает сделку, задачу или контакт другому пользователю.

## Операции API

Ключ операции состоит из слов пути и метода: `GET /api/v4/leads/{id}` это `api.leads.id.get`.
`amo work api list` показывает все операции с их ключами и уровнями, а `amo work api show "PATCH /api/v4/leads"` одну
из них.

`api call` проверяет еще и ключ команды, которая делает то же самое, например `deals.update` для
`PATCH /api/v4/leads`, поэтому прямой вызов не может обойти уровень команды. `api call` никогда не предлагается через
MCP.

## Агенты и MCP

Через MCP в терминале никого нет, чтобы ответить на `ask`, поэтому запись выполняется. Перемещение и закрытие сделок
для нового профиля и так стоят на `allow`, а смена этапа может запустить автоматизацию самого аккаунта, например
Salesbot, который пишет клиенту.

Прежде чем агент получит профиль через MCP, выберите одно:

- Поставьте `readonly` или `deny` каждой записи, которую агент делать не должен:

  ```sh
  amo work config set permissions.deals.move readonly
  amo work config set permissions.deals.close readonly
  ```

- Или оставьте уровни и включите подтверждение для инструмента `amo_write` в клиенте агента, чтобы клиент спрашивал
  вас перед каждой записью.

`mcp serve --permission deals.close=deny` и `mcp add … --permission …` делают уровень строже для одного этого
сервера. Профиль они никогда не ослабляют. См. [MCP](./mcp.md).

## Проверки, которые действуют независимо от разрешений

- **`AMO_READ_ONLY=1`** отклоняет любую запись в этой оболочке или в этом таймере. Агент, которого запускает
  `schedule agent`, работает с ним.
- **Удаляет и очищает только администратор.** Если пользователь входа не администратор amoCRM, `amo` отклоняет любое
  удаление, запись, которая делает поле пустым, и отвязку записей (причина `employee.*`).
- **Чтение контактов, компаний, примечаний, событий и неразобранного через `api call`** доступно только администратору: в них
  телефоны и почта клиентов.
- **Телефоны и почта** клиентов, которых нет в собственных сделках пользователя: не больше 100 таких контактов и
  компаний в день через `people show` и `organizations show`, для пользователя, который не администратор, и его
  агентов вместе. Счетчик хранится на этом компьютере: он остановит случайность или агента, но не того, кто хочет
  забрать базу.
- **Чьи сделки копирует синхронизация и приходят ли с ними задачи и звонки**
  (`crm.amocrm:<address>.unassigned`, `activities`, `stage-tasks`): это задаете только вы. Агенту отказывают.
- **Права доступа самой amoCRM.** Токен действует как пользователь, которому он принадлежит, и amoCRM отклоняет то,
  что этому пользователю нельзя (`amo.access-denied`).

Если вы вошли через интеграцию в браузере, а не по токену, `amo` действует как пользователь, который вошел, и каждое
правило выше про пользователя входа относится к этому пользователю.
