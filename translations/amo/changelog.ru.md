Заметные изменения в `@wirecat/amo-cli`. По одному разделу на версию, новые сверху.

## 0.1.1 — 18.11.2026

### Исправлено

- Опубликован из GitHub Actions с подписью npm (provenance), поэтому WireCat Desktop его устанавливает: Desktop
  отказывается ставить выпуск встроенного инструмента, который собрал не workflow его репозитория, а 0.1.0 был
  опубликован с компьютера.
- Документация для пользователей не уступает документации bitrix24-cli: страницы MCP и прав, полная стартовая страница,
  `amo <profile> setup` в быстром старте README, переменные окружения на странице настройки и больше строк в разделе
  решения проблем.

## 0.1.0 — 17.11.2026

### Добавлено

- Начало от `@wirecat/cli-template` 0.24.0.
- Настройка профиля `host` и шаги подключения WireCat Desktop для долгосрочного токена на английском, русском и
  испанском (`amo setup`, `src/setup/`). `session start` тоже сохраняет `host`.
- На cli-core 0.676.0: профиль без интернета читает только сделки своего пользователя из копии, которую сделал другой
  профиль того же аккаунта (администратор по-прежнему читает все), `organizations create|update --email|--phone`
  записывают собственные поля компании или отказывают, если в аккаунте их нет, а
  `pipelines show --since-time|--until-time` показывают воронку за период.
- На cli-core 0.681.0 и cli-base 0.106.0: `setup apply --dry-run` никогда не открывает связку ключей, а части навыка
  отдаются рядом с ним.
- На cli-core 0.683.0: `changes list` и сводка работают на Node 22.16, примечание показывается в `changes list` один
  раз, а `config set crm.amocrm:<host>.self` отклоняется (пользователя копии задает только синхронизация после входа).
- С `config set crm.amocrm:<host>.activities on` команда `sync` копирует задачи, комментарии и звонки по вашим сделкам
  и их клиентам (в первый раз за 90 дней). `activities list` их показывает, `changes list` показывает, что поменялось,
  а `schedule command crm-digest --at 08:30 -- changes list --format report` присылает утреннюю сводку. Задача,
  удаленная в amoCRM, уходит из копии при следующей синхронизации. Звонок не хранит номер телефона и запись, а в
  сводке нет текста примечаний.
- `session start --host <address>` входит в аккаунт amoCRM или Kommo с долгосрочным токеном, который читается скрыто
  или из stdin и хранится в связке ключей вместе с адресом. `session status --check` показывает аккаунт и
  пользователя.
- `api list`, `api show` и `api call` дают доступ к каждой операции справочника amoCRM API v4, у каждой свой ключ
  разрешения, параметры запроса в `--params`, тело в `--body`. Собственное чтение и изменения сделок, контактов и
  компаний разрешены, другое чтение, записи и удаления спрашивают. Беседы, чаты, Salesbot, вебхуки, виджеты, звонки,
  добавление пользователей и запись задач запрещены, пока вы их не разрешите.
- Только администратор аккаунта удаляет, очищает поле, отвязывает записи и читает контакты, компании, примечания и
  события через `api call`, что бы ни говорили разрешения.
- `sync` копирует сделки, где ответственный вы или коллеги, которых выбрал администратор, с их воронками, историей
  этапов и удалениями, и только контакты и компании этих сделок. Если в аккаунте есть дополнение amoCRM с фильтрами
  API, синхронизация сужает с ним запросы.
- `deals list`, `show`, `create`, `update`, `move` и `close` работают с копией и пишут в amoCRM. `close lost`
  принимает причину отказа по названию. `deals delete` нет: API v4 не умеет удалять сделку.
- `people`, `organizations` и `users` читают аккаунт напрямую. Контакты и компании можно создавать и менять. Тот, кто
  не администратор, видит телефоны и почту клиента другого пользователя не больше 100 раз в день через `show`.
- `session start --client-id <id>` входит через вашу приватную интеграцию по OAuth и сам обновляет токен доступа.
  Redirect URI интеграции: `https://wirecat.dev/webhooks/apps/amo-callback`.
- `account remove` забывает вход и файлы профиля. `--delete-data` еще и удаляет копию аккаунта и отказывает, пока
  тот же аккаунт читает другой профиль (`--dry-run` показывает все это и предупреждает).
- `schedule` запускает `sync` по таймеру.
- `sync` продолжает с середины страницы, когда у запуска кончается бюджет запросов, и читает клиентов только по id,
  которые названы в его сделках. Клиент коллеги, которого нет ни в одной вашей сделке, не попадает в копию, а запись,
  восстановленная из корзины amoCRM, возвращается, в каком бы порядке amoCRM ни перечислял события.

### Изменено — может сломать вызовы

- **Запись в MCP Registry спрашивает, какие профили обслуживать.** Раньше она запускала `mcp serve --profiles all`,
  поэтому клиент, который установил сервер из реестра, получал доступ ко всем аккаунтам на компьютере без выбора
  владельца. Теперь `--profiles` обязательный аргумент с примером `personal`: клиент спрашивает один профиль, список
  через запятую или `all`. Почему: CLI никогда не выбирает аккаунт за владельца
  ([WC-MCP-9](https://github.com/WireCatLabs/cli-base/blob/main/docs/standards/mcp.md#wc-mcp-9--a-server-serves-the-profiles-it-is-told-with-one-connection-for-each)).
  Обратите внимание, что клиент, настроенный по старой записи, сохраняет `--profiles all`, пока его не настроят
  заново. Сервер, добавленный вручную или через `mcp config`, не меняется.

### Исправлено

- Вход через `AMO_TOKEN` и `AMO_HOST` теперь находит своего пользователя: каждая команда спрашивает у аккаунта, чей
  это токен, как это делает `session start`. Поэтому `deals list` и другие чтения копии показывают сделки этого
  пользователя, а не пустой список. Токен нигде не сохраняется. С `--offline` никого не спрашивают, и чтения ничего
  не показывают.
