Заметные изменения в `@wirecat/amo-cli`. По одному разделу на версию, новые сверху.

## 0.5.0 — 25.11.2026

### Добавлено

- **`search all` находит сделки и лиды по смыслу их примечаний, звонков и задач**, другими словами или на другом
  языке, и показывает в результате отрывок примечания. `amo work sync --embed` строит индекс уже скачанной моделью
  (`amo models download embeddinggemma`); пока ее нет, `search all` сообщает, что искал только по словам
  (`@wirecat/cli-core` 0.751.0).
- **`people show` и `organizations show` принимают `person:<id>` и `organization:<id>`, которые дает сделка.**
- **`sync --embed` и `search all` по смыслу** (cli-core 0.751.0). С включенной настройкой `activities` команда
  `sync --embed` индексирует скопированные комментарии и задачи уже скачанной моделью, и тогда `search all` находит
  сделки по тому, что они значат, на русском или любом другом языке, а не только по словам. Навык говорит агенту
  искать по смыслу, прежде чем читать каждое примечание.

### Изменено — может сломать скрипты

- **`synced[].saved` в ответе `sync` считает только изменившиеся строки** (новые, другие, удаленные или вернувшиеся),
  поэтому синхронизация без нового отвечает 0.
- **amo построен на cli-core 1.0 и cli-base 1.0.** После первого запуска хранилище переходит на версию 74, и
  открывают его только инструменты на cli-core 1.0, поэтому обновляйте все CLI WireCat на этом компьютере вместе.
  Миграция сохраняет копию для отката и не запускается, если не может ее записать (`store migrate --no-backup`
  мигрирует все равно).
- **`sync --rescan` больше не дает синхронизации отметить удаленной большую часть записей одного вида.** Он только
  заново перечисляет все. Когда защита придерживает проход, `sync --allow-deletions <count>` разрешает отметить
  удаленными не больше этого числа записей. Этот флаг для владельца в терминале, сервер MCP его не предлагает.
- **Вызов MCP, который называет запрещенную папку, отвечает `permission_error`**, а не `validation_error`.

### Исправлено

- **Сделка, перенесенная в ту же секунду, когда задали правила задач для ее этапа, открывает свою задачу.**
- `search all` показывает после совпавшего имени имя, которое отличается от него одной буквой, и находит латинское
  имя, набранное кириллицей, и русское имя, набранное латиницей, с пометкой `match: corrected`.
- `people show` и `organizations show` принимают `person:<id>` и `organization:<id>`, которые дает сделка.

## 0.4.0 — 24.11.2026

### Изменено — может сломать скрипты

- **`account remove` и проверка второго входа теперь общие CRM-команды cli-core** (`@wirecat/cli-core`
  0.722.0). Причины остаются `account-remove.account-shared` и `session.duplicate`, с теми же подробностями, а пробный
  запуск по-прежнему только предупреждает. Отказ теперь говорит `amoCRM account <host>`.
- **`account remove --delete-data` отказывает, когда amo не может понять, какой аккаунт у другого профиля**
  (`account-remove.account-unknown`, подробность `profile`): у профиля нечитаемый сохраненный вход, и
  `session start` его не запомнил. `--keep-data` по-прежнему удаляет.
- **`session start` отказывает профилю с именем `files` или `foreign-contacts`** (`profile.reserved`): эти папки в
  папке состояния общие для всех аккаунтов.

### Исправлено

- **Инструкция по установке приводит отказ amoCRM для пользователя, который не администратор.** Вход в один клик
  показывает и его аккаунт, но amoCRM отказывает под кнопкой «Разрешить»: «Первичная установка интеграции доступна
  только администраторам аккаунта». Раньше в инструкции было написано, что вход показывает только аккаунты, где
  человек администратор.

## 0.3.0 — 23.11.2026

### Добавлено

- **Вход в один клик: `amo <profile> session start --host https://<subdomain>.amocrm.ru --one-click`.** Браузер
  открывает страницу на connect.wirecat.dev, сервере WireCat в России, до которого достает amoCRM. Человек выбирает
  аккаунт и нажимает «Разрешить», и amoCRM создает в нем интеграцию WireCat. Никто не копирует ID интеграции,
  секретный ключ или токен. amoCRM отправляет секретный ключ интеграции на connect.wirecat.dev, и `amo` забирает его
  один раз. `amo` обменивает код только с аккаунтом, который назван в `--host`, и отказывает, если доступ разрешили в
  другом аккаунте. Вход хранится и продлевается так же, как с `--client-id`. amoCRM разрешает это только
  администратору аккаунта ([amoCRM: кнопка](https://www.amocrm.ru/developers/content/oauth/button)). Пока только для
  аккаунтов amoCRM; Kommo входит по токену.
- **`amo setup` предлагает администратору сначала «Войти через amoCRM»,** а токен вторым. WireCat Desktop показывает
  ссылку, которую нужно открыть, и ждет, пока доступ разрешат.
- **`amo setup` спрашивает, администратор ли вы в аккаунте.** Администратор создает интеграцию, как раньше.
  Пользователь, который не администратор, получает просьбу к администратору о долгосрочном токене, предупреждение, что
  токен несет права администратора, а после подключения подсказку, как синхронизировать свои сделки, а не сделки
  администратора. WireCat Desktop показывает те же шаги. На странице установки тот же путь описан в разделе «Если вы
  не администратор».

### Исправлено

- **Общая справка по CRM больше не упоминает лиды и поля Битрикс24.** В amoCRM нет отдельных лидов: `changes list`,
  `search all` и другие общие команды теперь описывают только сделки.
- Настройка и страница установки больше не говорят, что войти через интеграцию в браузере может любой: по руководству
  amoCRM этот вход доступен только в аккаунтах, где человек администратор
  ([amoCRM: пошагово](https://www.amocrm.ru/developers/content/oauth/step-by-step)).

## 0.2.0 — 19.11.2026

### Добавлено

- **`amo guide` показывает сценарии частых задач**: команды по порядку и зачем нужна каждая. Первая синхронизация и
  доска воронки, обновление копии по расписанию, и как дать агенту менять CRM без сюрпризов.
- README открывается баннером WireCat, а страница установки рассказывает, как подключить `amo` в WireCat Desktop.

## 0.1.1 — 18.11.2026

### Исправлено

- Опубликован из GitHub Actions с подписью npm (provenance), поэтому WireCat Desktop его устанавливает: Desktop
  отказывается ставить выпуск встроенного инструмента, который собрал не workflow его репозитория, а 0.1.0 был
  опубликован с компьютера.
- Документация для пользователей не уступает документации bitrix24-cli: страницы MCP и прав, полная стартовая страница,
  `amo <profile> setup` в быстром старте README, переменные окружения на странице настройки и больше строк в разделе
  решения проблем.

## 0.1.0 — 17.11.2026

### Добавлено

- Начало от `@wirecat/cli-template` 0.24.0.
- Настройка профиля `host` и шаги подключения WireCat Desktop для долгосрочного токена на английском, русском и
  испанском (`amo setup`, `src/setup/`). `session start` тоже сохраняет `host`.
- На cli-core 0.676.0: профиль без интернета читает только сделки своего пользователя из копии, которую сделал другой
  профиль того же аккаунта (администратор по-прежнему читает все), `organizations create|update --email|--phone`
  записывают собственные поля компании или отказывают, если в аккаунте их нет, а
  `pipelines show --since-time|--until-time` показывают воронку за период.
- На cli-core 0.681.0 и cli-base 0.106.0: `setup apply --dry-run` никогда не открывает связку ключей, а части навыка
  отдаются рядом с ним.
- На cli-core 0.683.0: `changes list` и сводка работают на Node 22.16, примечание показывается в `changes list` один
  раз, а `config set crm.amocrm:<host>.self` отклоняется (пользователя копии задает только синхронизация после входа).
- С `config set crm.amocrm:<host>.activities on` команда `sync` копирует задачи, комментарии и звонки по вашим сделкам
  и их клиентам (в первый раз за 90 дней). `activities list` их показывает, `changes list` показывает, что поменялось,
  а `schedule command crm-digest --at 08:30 -- changes list --format report` присылает утреннюю сводку. Задача,
  удаленная в amoCRM, уходит из копии при следующей синхронизации. Звонок не хранит номер телефона и запись, а в
  сводке нет текста примечаний.
- `session start --host <address>` входит в аккаунт amoCRM или Kommo с долгосрочным токеном, который читается скрыто
  или из stdin и хранится в связке ключей вместе с адресом. `session status --check` показывает аккаунт и
  пользователя.
- `api list`, `api show` и `api call` дают доступ к каждой операции справочника amoCRM API v4, у каждой свой ключ
  разрешения, параметры запроса в `--params`, тело в `--body`. Собственное чтение и изменения сделок, контактов и
  компаний разрешены, другое чтение, записи и удаления спрашивают. Беседы, чаты, Salesbot, вебхуки, виджеты, звонки,
  добавление пользователей и запись задач запрещены, пока вы их не разрешите.
- Только администратор аккаунта удаляет, очищает поле, отвязывает записи и читает контакты, компании, примечания и
  события через `api call`, что бы ни говорили разрешения.
- `sync` копирует сделки, где ответственный вы или коллеги, которых выбрал администратор, с их воронками, историей
  этапов и удалениями, и только контакты и компании этих сделок. Если в аккаунте есть дополнение amoCRM с фильтрами
  API, синхронизация сужает с ним запросы.
- `deals list`, `show`, `create`, `update`, `move` и `close` работают с копией и пишут в amoCRM. `close lost`
  принимает причину отказа по названию. `deals delete` нет: API v4 не умеет удалять сделку.
- `people`, `organizations` и `users` читают аккаунт напрямую. Контакты и компании можно создавать и менять. Тот, кто
  не администратор, видит телефоны и почту клиента другого пользователя не больше 100 раз в день через `show`.
- `session start --client-id <id>` входит через вашу приватную интеграцию по OAuth и сам обновляет токен доступа.
  Redirect URI интеграции: `https://wirecat.dev/webhooks/apps/amo-callback`.
- `account remove` забывает вход и файлы профиля. `--delete-data` еще и удаляет копию аккаунта и отказывает, пока
  тот же аккаунт читает другой профиль (`--dry-run` показывает все это и предупреждает).
- `schedule` запускает `sync` по таймеру.
- `sync` продолжает с середины страницы, когда у запуска кончается бюджет запросов, и читает клиентов только по id,
  которые названы в его сделках. Клиент коллеги, которого нет ни в одной вашей сделке, не попадает в копию, а запись,
  восстановленная из корзины amoCRM, возвращается, в каком бы порядке amoCRM ни перечислял события.

### Изменено — может сломать вызовы

- **Запись в MCP Registry спрашивает, какие профили обслуживать.** Раньше она запускала `mcp serve --profiles all`,
  поэтому клиент, который установил сервер из реестра, получал доступ ко всем аккаунтам на компьютере без выбора
  владельца. Теперь `--profiles` обязательный аргумент с примером `personal`: клиент спрашивает один профиль, список
  через запятую или `all`. Почему: CLI никогда не выбирает аккаунт за владельца
  ([WC-MCP-9](https://github.com/WireCatLabs/cli-base/blob/main/docs/standards/mcp.md#wc-mcp-9--a-server-serves-the-profiles-it-is-told-with-one-connection-for-each)).
  Обратите внимание, что клиент, настроенный по старой записи, сохраняет `--profiles all`, пока его не настроят
  заново. Сервер, добавленный вручную или через `mcp config`, не меняется.

### Исправлено

- Вход через `AMO_TOKEN` и `AMO_HOST` теперь находит своего пользователя: каждая команда спрашивает у аккаунта, чей
  это токен, как это делает `session start`. Поэтому `deals list` и другие чтения копии показывают сделки этого
  пользователя, а не пустой список. Токен нигде не сохраняется. С `--offline` никого не спрашивают, и чтения ничего
  не показывают.
