Подключите аккаунт amoCRM или Kommo один раз, и дальше ваш ИИ-агент сможет читать и обновлять ваши сделки. CRM хранит
ваши сделки, контакты и компании в облаке. Администратор amoCRM пускает `amo` одним нажатием в браузере, без своей
интеграции. Для Kommo и для пользователей без прав администратора нужен ключ из приватной интеграции, которую создает
администратор.

После этого агент отвечает, какие сделки открыты, переводит сделку на следующий этап или находит клиента, из
терминала или по MCP, в пределах разрешений, которые вы задали. Те же команды вы запускаете сами или из скрипта.

`amo` это инструмент командной строки WireCat, то есть программа, которую вы или ваш агент запускаете по ее имени.
Он подключается один раз на каждый аккаунт, а `amo work setup` задает вопросы по очереди. Администратор аккаунта
amoCRM входит одним кликом в браузере и ничего не копирует. Токен, который вы вставляете, тоже работает, и это путь
для Kommo и для пользователей, которые не администраторы. Вы сами не администратор? Попросите ключ у
администратора, как показано в разделе [если вы не администратор](#if-you-are-not-an-administrator).

## Установка

Установите `amo` один раз на каждом компьютере, где с ним работаете вы или агент. Нужен Node.js 22.16 или более
поздний 22.x, либо 24 и новее. Node 23 не поддерживается.

```sh
npm install -g @wirecat/amo-cli
amo --version
amo skill install   # the agent skill, for Claude Code, Codex, Gemini CLI and OpenClaw
amo doctor
```

Агент без терминала, например Claude Desktop, работает с `amo` по [MCP](./mcp.md). `amo doctor` не ходит в сеть и не
открывает связку ключей. Он показывает версию, где лежат настройки, какие есть профили и могут ли другие пользователи
компьютера читать настройки.

## Вход через amoCRM

Один клик в браузере, ничего не нужно копировать. Работает для аккаунтов amoCRM на `<subdomain>.amocrm.ru`. Аккаунты
Kommo пока входят по ключу.

```sh
amo work session start --host https://example.amocrm.ru --one-click
```

1. Браузер откроет страницу WireCat с кнопкой amoCRM. Нажмите ее.
2. Выберите аккаунт и нажмите **«Разрешить»** (Allow).
3. amoCRM создаст в аккаунте интеграцию WireCat. `amo` проверит, какой аккаунт и какого пользователя он получил, и
   сохранит вход в связке ключей системы.

Что происходит за этим кликом:

- amoCRM разрешает это только администратору аккаунта
  ([amoCRM: кнопка](https://www.amocrm.ru/developers/content/oauth/button)). Остальным она пишет под кнопкой
  «Разрешить»: «Интеграция не может быть установлена в выбранный аккаунт. Первичная установка интеграции доступна
  только администраторам аккаунта.» Потом интеграция видна в амоМаркете, где
  администратор может ее отключить.
- amoCRM отправляет секретный ключ новой интеграции на connect.wirecat.dev, сервер WireCat в России, до которого
  достают серверы amoCRM. `amo` один раз забирает ключ оттуда, и сервер не хранит копию.
- `amo` обменивает код только с аккаунтом, который вы назвали в `--host`. Если в окне amoCRM вы выбрали другой
  аккаунт, он остановится и назовет этот аккаунт.
- Вы действуете со своими правами, и `amo` сам продлевает вход, как при
  [входе через интеграцию](#sign-in-through-the-integration).

## Создайте интеграцию

Это делает администратор аккаунта, один раз, для ключа или для входа через свою интеграцию. Входу в один клик
интеграция не нужна.

В amoCRM (`<subdomain>.amocrm.ru`):

1. Откройте **амоМаркет**, нажмите **⋯** слева вверху и выберите **«Создать интеграцию»**.
2. Дайте ей название и описание, например *WireCat*.
3. В поле **«Ссылка для перенаправления»** (Redirect URI) укажите `https://wirecat.dev/webhooks/apps/amo-callback`.
   Ключу она не нужна, но с ней та же интеграция работает и для входа в браузере.
4. В разделе **«Предоставить доступ»** отметьте **«Доступ к данным аккаунта»**.
5. **«Контроль дублей»** и **«Множественные источники»** оставьте без отметки и сохраните.

Если аккаунт не помечен как технический, amoCRM сначала просит подписать отказ от технической поддержки для
приватной интеграции. После этого поддержка amoCRM больше не принимает обращения о системных ошибках в аккаунте, и
отказ нельзя отозвать. Прочитайте его, прежде чем подписывать
([amoCRM: интеграции](https://www.amocrm.ru/developers/content/integrations/intro),
[amoCRM: пошаговая инструкция](https://www.amocrm.ru/developers/content/oauth/step-by-step)).

В Kommo (`<subdomain>.kommo.com` или `<subdomain>.amocrm.com`): Settings → Integrations → **Create integration**.
Заполните название, описание и тот же **Redirect URL**. В **Allow access** по умолчанию отмечены все права.
**Duplicate control** и **Multiple sources** оставьте без отметки и сохраните. Kommo отказа не просит
([Kommo: приватная интеграция](https://developers.kommo.com/docs/private-integration)).

## Вход по ключу

Ключ это долгосрочный токен amoCRM. Он действует с правами администратора, который его создал.

1. В интеграции откройте вкладку **«Ключи»** (в Kommo **Keys and scopes**) и нажмите **«Сгенерировать токен»**
   (в Kommo **Generate long-lived token**).
2. Выберите дату окончания, от одного дня до пяти лет.
3. Скопируйте токен. Он показывается только один раз
   ([amoCRM: пошаговая инструкция](https://www.amocrm.ru/developers/content/oauth/step-by-step),
   [Kommo: долгосрочный токен](https://developers.kommo.com/docs/long-lived-token)).
4. Выберите имя профиля для этого аккаунта, например `work`. Запустите команды, подставив адрес своего аккаунта
   вместо `https://example.amocrm.ru` из примера, и вставьте токен, когда `amo` его спросит:

   ```sh
   amo work session start --host https://example.amocrm.ru
   amo work session status --check
   ```

`session start` читает токен, не показывая его, или из stdin. Он проверяет токен на аккаунте и только потом
сохраняет его в связке ключей системы вместе с адресом. С `--credential-storage file` токен хранится в закрытом файле.
`session status --check` показывает аккаунт и пользователя, от имени которого действует токен. Адрес остается таким,
как вы его ввели: `<subdomain>.amocrm.ru`, `<subdomain>.kommo.com` или `<subdomain>.amocrm.com`.

## Вход через интеграцию

Этот вход работает по OAuth: вы разрешаете интеграцию в браузере и действуете со своими правами. amoCRM предлагает
только аккаунты, где вы администратор
([amoCRM: пошаговая инструкция](https://www.amocrm.ru/developers/content/oauth/step-by-step)).

1. На вкладке интеграции **«Ключи»** (в Kommo **Keys and scopes**) скопируйте ID интеграции. Секретный ключ тоже
   держите открытым.
2. Запустите команду, подставив свой адрес и ID интеграции вместо `https://example.amocrm.ru` и
   `0123abcd-4567-89ef-0123-456789abcdef` из примера:

   ```sh
   amo work session start --host https://example.amocrm.ru --client-id 0123abcd-4567-89ef-0123-456789abcdef
   ```

3. Вставьте секретный ключ, когда `amo` его спросит. Он не показывается. Вместо этого его можно передать в
   `AMO_AMOCRM_CLIENT_SECRET`.
4. Браузер откроет amoCRM. Выберите аккаунт и нажмите **«Разрешить»** (Allow).

`amo` хранит токены и сам обновляет токен доступа. Redirect URI интеграции должен быть
`https://wirecat.dev/webhooks/apps/amo-callback`. Новый вход любым способом заменяет прежний вход профиля.

## Что выбрать

- **Вход через amoCRM** самый быстрый: один клик, не нужно создавать интеграцию и ничего копировать. Нужен
  администратор аккаунта amoCRM. Вход действует от его имени, и `amo` продлевает его так же, как вход через интеграцию.
- **Ключ** работает для Kommo и для пользователей, которые не администраторы: одна вставка, без браузера. Он
  действует от имени администратора, который его создал, и перестает работать в дату окончания. Тогда создайте новый и
  снова запустите `session start`.
- **Вход через интеграцию** идет через интеграцию, которую вы создали сами. Он действует от имени администратора,
  который входит, и даты окончания, за которой нужно следить, у него нет. Refresh-токен amoCRM живет 3 месяца, и `amo` получает новый каждый раз, когда обновляет токен доступа. Поэтому
  вход работает, пока `amo` запускается хотя бы раз в 3 месяца. После более долгого перерыва войдите снова
  ([amoCRM: пошаговая инструкция](https://www.amocrm.ru/developers/content/oauth/step-by-step)).

## Если вы не администратор

Это видно по меню слева в amoCRM: если там нет **амоМаркета**, вы не администратор. Создать интеграцию и ее ключ
может только администратор. Вход в один клик покажет и ваш аккаунт, но amoCRM откажет: «Первичная установка
интеграции доступна только администраторам аккаунта». Поэтому вы подключаетесь по ключу, который для вас создает
администратор:

1. Отправьте администратору своего аккаунта ссылку на эту страницу и попросите приватную интеграцию и ее долгосрочный
   токен.
2. Администратор проходит шаги [создайте интеграцию](#create-the-integration) и [вход по ключу](#sign-in-with-a-key)
   и передает вам ключ. Ключ работает как пароль: передавайте его через менеджер паролей, а не через общий чат.
3. Запустите `amo work setup`, ответьте **«Нет, я сотрудник»** и вставьте ключ.

Ключ действует с правами администратора: вы видите и можете менять то же, что и он. Разрешения amo все равно
ограничивают, что меняет агент. Синхронизация сначала копирует сделки администратора, поэтому выберите свои, как
показано в разделе [какие сделки копирует синхронизация](./configuration.md#which-deals-sync-copies).

## Подключение по шагам

`amo work setup` задает вопросы по одному, проверяет ответы и сохраняет их, только если проверка прошла:

1. **Какой аккаунт?** Адрес, по которому вы открываете CRM.
2. **Вы администратор аккаунта?** Администратор выбирает, как войти. Пользователь получает просьбу, которую нужно
   отправить администратору, как в разделе [если вы не администратор](#if-you-are-not-an-administrator).
3. **Как войти?** **«Войти через amoCRM»** ведет в браузер, как в разделе [вход через amoCRM](#sign-in-with-amocrm), а
   затем к последнему шагу. **«Долгосрочным токеном»** ведет дальше по списку.
4. **Создайте приватную интеграцию.** Шаги из раздела [создайте интеграцию](#create-the-integration).
5. **Создайте токен.** Вставьте ключ с вкладки «Ключи» или ключ, который прислал администратор.
6. **Проверка токена.** `amo` спрашивает у аккаунта, кому принадлежит токен, и сохраняет адрес и токен, только если
   аккаунт ответил. Если токен отклонен, вы вернетесь к шагу с токеном.
7. **Подключено.** Профиль готов. Пользователь, который не администратор, видит еще, как выбрать свои сделки.

Вход через свою интеграцию это команда, которая показана в разделе **«Для опытных: вход через интеграцию»** на
последнем шаге.

## Подключение в WireCat Desktop

[WireCat Desktop](https://wirecat.dev/en/docs/desktop) ставит `amo` со страницы «Инструменты», начиная с версии
0.7.1. Его окно задает те же вопросы, что и `amo work setup`, потому что их описывает сам `amo`, и так же проверяет
токен, прежде чем что-то сохранить. **«Войти через amoCRM»** показывает ссылку, которую нужно открыть в браузере, и
окно ждет, пока вы разрешите доступ. Вход через свою интеграцию это команда в разделе
**«Для опытных: вход через интеграцию»** на последнем шаге.

## Выход и отзыв доступа

`amo work session end` забывает вход на этом компьютере. `amo work account remove --keep-data` забывает вход и
файлы профиля, а `--delete-data` еще и удаляет копию аккаунта из хранилища WireCat.

Ни одна из этих команд не сообщает amoCRM. Чтобы остановить ключ в самом аккаунте, например после утечки, откройте
вкладку интеграции **«Выданные доступы»** и нажмите **«Отозвать доступ»**
([amoCRM: пошаговая инструкция](https://www.amocrm.ru/developers/content/oauth/step-by-step)). В Kommo это вкладка
**Authorization** → **Revoke access** ([Kommo: долгосрочный токен](https://developers.kommo.com/docs/long-lived-token)).

## Дальше: первая синхронизация

Скопируйте сделки и их клиентов в WireCat, затем посмотрите открытые:

```sh
amo work sync
amo work deals list status:open
```

Подробнее в разделе [первая синхронизация](./usage.md#the-first-sync).
