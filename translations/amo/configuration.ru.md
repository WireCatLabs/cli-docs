Меняйте, как `amo` работает для одного аккаунта или для всех аккаунтов на этом компьютере, одной командой и смотрите,
откуда взялось каждое значение. Вы меняете только то немногое, что важно вам, а остальное остается по умолчанию.

Вы решаете, чьи сделки копирует `sync`, приходят ли с ними задачи и звонки, какие этапы открывают задачу на вашем
компьютере и что может делать агент. Ослабить разрешение или поменять то, что копирует синхронизация, можете только
вы: агенту, который пытается это сделать, отказывают.

Настройки лежат в одном файле, `config.json`, в папке, которую показывает `amo doctor`. У каждого профиля своя
часть, а `defaults` действуют на все профили. `amo work config show` показывает каждую настройку и откуда она
взялась: из файла, из переменной или по умолчанию.

## Посмотреть и поменять настройку

```sh
amo work config show
amo work config set limit 50
amo work config unset limit
```

## Разрешения

`permissions` решает, что команда может делать для этого профиля: `allow`, `ask`, `readonly` или `deny`, для каждого
ключа разрешения. Через MCP `ask` не спрашивает: запись выполняется. Ключи, их встроенные уровни и то, как оставить
записи агента под вашим контролем, описаны на странице [Разрешения](./permissions.md).

```sh
amo work config set permissions.deals.close deny
```

## Какие сделки копирует синхронизация

По умолчанию `sync` копирует сделки, где ответственный пользователь, который вошел. Администратор может вместо этого
выбрать других пользователей. Найдите их id через `amo work users list`, затем перечислите их вместе со своим id,
потому что список заменяет ваш собственный. Команда использует адрес для примера `example.amocrm.ru` и id для
примера `7001` и `7002`. Подставьте вместо них адрес своего аккаунта и выбранные id:

```sh
amo work config set crm.amocrm:example.amocrm.ru.unassigned 7001,7002
amo work sync
```

Это задаете только вы, потому что запуску агента в этом отказывают. Пользователь, который не администратор, может
выбрать только себя. Ни одна настройка не копирует всю CRM. Любой другой клиент читается напрямую командами `people`
или `organizations`.

## Задачи и звонки

`crm.amocrm:<address>.activities` по умолчанию выключена. Если ее включить, следующий `sync` копирует задачи,
комментарии и звонки по вашим сделкам и их клиентам за последние 90 дней. Команда показана в разделе
[Задачи и что поменялось](./usage.md#tasks-and-what-changed). Как и выбор сделок, ее задаете только вы.

## Задача, когда сделка попадает на этап

`crm.amocrm:<address>.stage-tasks` называет этапы, и каждая сделка, которая переходит на один из них, открывает
задачу на этом компьютере рядом с другими вашими задачами WireCat. Ее открывает синхронизация, которая приносит
перемещение, один раз на перемещение: задача, которую вы закрыли, не вернется, а следующее попадание на тот же этап
откроет новую. Этап называется своим id, который `amo work stages list --json` печатает как `external_id`. Команда
использует адрес для примера `example.amocrm.ru`. Успешный этап amoCRM имеет id `142` в каждой воронке, поэтому это
правило открывает задачу на выигрыш в любой из них:

```sh
amo work config set crm.amocrm:example.amocrm.ru.stage-tasks \
  '{"142":{"title":"Send the closing papers","due_days":2}}'
amo work sync
```

`amo` читает историю этапов аккаунта, поэтому сделка, которая прошла через этап между двумя синхронизациями, все равно
получает задачу этого этапа. Перемещения до первой установки настройки задач не открывают. Это задаете только вы.
Чтобы остановить, выполните `amo work config unset crm.amocrm:example.amocrm.ru.stage-tasks`.

## Записи запусков

Команда, которая завершилась ошибкой, сохраняется как запуск для `amo runs list` и `runs show`. `api call` и
`session status --check` сохраняются и при успехе, если только `record` не `false` (тогда только ошибки) или они не
запущены с `--no-record`. `record_input` решает, хранит ли запуск слова, которые вы набрали: `true` (по умолчанию),
`false` или `failed`, только для неудачных запусков. Секреты скрываются в любом случае, как описано в разделе
[безопасность](./security.md).

## Переменные

Переменная для одной оболочки или одного таймера важнее файла:

- `AMO_PROFILE` называет профиль, и команда может его не указывать.
- `AMO_READ_ONLY=1` запрещает все записи, что бы ни говорили разрешения.
- `AMO_TOKEN` вместе с `AMO_HOST` входит с долгосрочным токеном только на этот запуск, без связки ключей. `AMO_HOST`
  это адрес аккаунта, а `AMO_TOKEN` без него дает ошибку.
- `AMO_AMOCRM_CLIENT_SECRET` передает секретный ключ интеграции в `session start --client-id`.
- `AMO_CONFIG_DIR` и `AMO_STATE_DIR` переносят настройки и состояние в другие папки. Вход, сделанный с ними, хранится
  отдельно от вашего обычного.
