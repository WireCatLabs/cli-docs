Найдите сделку, передвиньте ее или посмотрите, что поменялось за ночь, одной короткой командой, той же, которую
запускает ваш агент. API amoCRM говорит на языке id воронок, этапов и полей, а `amo` вместо них принимает
названия этапов и полей.

Ваш агент отвечает, какие сделки стоят на этапе, как выглядит воронка в этом месяце и какие задачи просрочены. По
вашей просьбе он двигает сделку, закрывает ее с причиной или обновляет клиента, а каждое утро может присылать сводку
того, что поменялось.

Каждая команда начинается с профиля, то есть имени, которое вы дали аккаунту. `sync` копирует ваши сделки и их
клиентов в локальное хранилище WireCat на вашем компьютере, и большинство чтений отвечает оттуда, в том числе без
интернета. Эта страница считает, что вы уже вошли в профиль, как показано в разделе
[установка и подключение](./installation.md).

## Сначала профиль

Профиль это имя, которое вы выбираете для одного аккаунта. Это первое слово каждой команды, которой нужен аккаунт:

```sh
amo work config show
```

`AMO_PROFILE=work` делает то же самое для одного сеанса оболочки. Профиль никогда не подставляется сам, даже
единственный. Команда без него останавливается с кодом выхода 2 и показывает профили на этом компьютере.

## Вход

Создайте приватную интеграцию аккаунта и войдите в профиль, как описано в разделе
[установка и подключение](./installation.md): по токену или через интеграцию в браузере.
`amo work session status --check` показывает аккаунт и пользователя, от имени которого действует профиль.

## Первая синхронизация

`sync` копирует в локальное хранилище воронки, сделки, где ответственный вы, и только те контакты и компании, что есть
в этих сделках. Администратор может выбрать коллег, чьи сделки она тоже копирует, как показано в разделе
[настройки](./configuration.md#which-deals-sync-copies). Команды вроде `deals list` потом читают эту копию без
интернета:

```sh
amo work sync
amo work deals list status:open
```

Других клиентов читают напрямую командами `people` или `organizations`. Запустите `sync` снова, чтобы обновить копию:
она читает только то, что поменялось с прошлого раза. Синхронизация, которую остановил `--max-pages`, в следующий раз
продолжит с того же места. Так копия обновляется по таймеру:

```sh
amo work schedule command crm --every 1h -- sync
amo work store status            # how far each kind is, and how many are stored
amo work sync --rescan           # everything again, every id too
```

## Читайте свои сделки

```sh
amo work deals list stage:"Quote sent"
amo work deals show deal:12
amo work pipelines show Sales --since-time 30d
```

`deals list` принимает условия вида поле:значение, например `status:open` или `stage:"Quote sent"`, и
`--format csv` для таблицы. `deals show` показывает одну сделку с ее этапом, суммой и людьми в ней. `pipelines show`
показывает воронку доской и воронкой конверсии: сколько сделок стоит на каждом этапе и на какую сумму, сколько дошло
до этапа и пошло дальше, и долю выигранных.

Контакты и компании читаются напрямую из аккаунта:

```sh
amo work people list "Anna"
amo work organizations show "Example LLC"
```

Контакт из ваших собственных сделок приходит с телефонами и почтой. Пользователь, который не администратор, видит
телефоны и почту не больше 100 других контактов и компаний в день. Счет ведется на этом компьютере.

## Измените сделку

```sh
amo work deals move deal:12 "Negotiation"
amo work deals close deal:12 lost --reason "Example: chose another supplier"
amo work deals update deal:12 --amount 18000 --dry-run
```

Этап называется своим названием в воронке. `close` отмечает сделку успешной или проигранной так, как это делает
сама CRM, с причиной. `--field` задает одно из собственных полей аккаунта по его названию, как их печатает
`amo work fields list deals`. Должность контакта тоже одно из таких полей. Каждое изменение отвечает `operation_id`,
а `--dry-run` показывает, что оно сделало бы и какие разрешения проверяет, и ничего не отправляет. В amoCRM нет
вызова, который удаляет сделку, поэтому вместо удаления закройте ее как проигранную. Файлы в сделках и контактах
пока не поддерживаются.

Если ответ на запись потерялся, ошибка говорит `outcome_unknown`, и `amo` не отправляет запись снова. amoCRM могла
сделать изменение, поэтому запустите `sync`, посмотрите сделку через `deals show` и пишите снова, только если
изменения там нет.

## Задачи и что поменялось

Задачи, комментарии и звонки по умолчанию выключены. Чтобы копировать их, включите настройку activities, подставив
адрес своего аккаунта вместо `example.amocrm.ru` из примера:

```sh
amo work config set crm.amocrm:example.amocrm.ru.activities on
amo work sync
amo work activities list overdue:true
```

Следующий `sync` копирует задачи, комментарии и звонки по вашим сделкам и их клиентам за последние 90 дней. То, что
относится к сделке коллеги, никогда не сохраняется, а звонок хранит только направление, но не номер телефона и не
запись.

`changes list` показывает, какие изменения увидели синхронизации: созданные, перемещенные, выигранные, проигранные и
переданные другому ответственному сделки, добавленные и выполненные задачи, добавленные контакты. Это расписание
делает утреннюю сводку за последний день:

```sh
amo work changes list "at>=1d"
amo work schedule command crm-digest --at 08:30 -- changes list --format report
```

Сводка приходит уведомлением на рабочем столе. С `--deliver-to` она уходит еще и в чат Telegram или в почтовый ящик
через ваши собственные `tg` или `mail` от WireCat, а `amo help schedule command` показывает, как записать маршрут.
Сводка называет названия сделок, суммы, имена контактов и темы задач, но никогда не текст примечания, и скрывает
номера телефонов и адреса почты. Ее читает каждый, кто читает этот маршрут.

## Вызов API

`amo work api list` перечисляет все операции amoCRM API v4 с именами вида `<HTTP verb> <path>`, их ключами
разрешений и страницами справки. `api call` отправляет одну операцию, параметры запроса и тело передаются в JSON:

```sh
amo work api call "GET /api/v4/leads" --params '{"limit":5,"with":"loss_reason"}'
amo work api call "PATCH /api/v4/leads/42" --body '{"price":1000}' --dry-run
```

`--dry-run` показывает все разрешения, которые проверяет вызов, и ничего не отправляет. Задачи и примечания пишутся
так, когда их ключи это разрешают. `api call` никогда не предлагается через MCP.

## Вывод для скриптов

Каждая команда, кроме `mcp serve` на stdin и stdout, принимает `--json` и печатает в stdout одно значение JSON.
Ошибки идут в stderr тоже в JSON, с кодом, по которому можно ветвиться. Коды перечислены в
[справочнике команд](./commands.md).

## Агенты

`amo skill install` кладет навык инструмента туда, где его ищут Claude Code, Codex, Gemini CLI и OpenClaw.
`amo skill install --for hermes` еще и добавляет эту папку в настройки Hermes Agent, а простой `skill install`
Hermes не трогает. Агент с навыком запускает те же команды, что и вы. `amo guide` показывает сценарии частых задач:
команды по порядку и зачем нужна каждая.

Приложение без терминала, например Claude Desktop, ChatGPT или Claude в браузере, подключается к `amo` по MCP, как
показано в разделе [MCP](./mcp.md). Прежде чем это сделать, решите, что оно может менять, как показано в разделе
[разрешения](./permissions.md#agents-and-mcp): через MCP на вопрос ответить некому, поэтому запись на уровне `ask`
выполняется.
