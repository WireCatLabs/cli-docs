Каждый сценарий описывает частую задачу по шагам: какие команды выполнить, зачем нужна каждая и на что смотреть в ответе. Те же сценарии есть в терминале: `amo guide` показывает список, а `amo guide <name>` выводит один сценарий.

Команды, которые работают с аккаунтом, начинаются с профиля, то есть имени, которое вы дали аккаунту при входе: `amo <profile> …`.

<a id="first-sync" />

## Первая синхронизация и доска воронки

Скопируйте свои сделки и их клиентов в локальное хранилище и посмотрите, на какой стадии каждая сделка.

1. ```sh
   amo setup
   ```

   адрес аккаунта и долгосрочный токен вашей приватной интеграции; оба проверяются в аккаунте, прежде чем что-то сохранится

2. ```sh
   amo session status --check
   ```

   аккаунт и пользователь, от имени которого действует токен, и является ли он администратором

3. ```sh
   amo sync
   ```

   копирует воронки, сделки, где ответственный вы, и только контакты и компании этих сделок; следующая синхронизация берет только изменения

4. ```sh
   amo pipelines show Sales
   ```

   воронка в виде доски и воронки продаж: сколько сделок стоит на каждой стадии и сколько до нее дошло

5. ```sh
   amo deals list status:open
   ```

   открытые сделки со стадией, суммой и ответственным, из хранилища, в том числе без интернета

На что смотреть:

- пользователя в session status: токен коллеги копирует его сделки, а не ваши
- предупреждения в ответе sync, например страницу, которую аккаунт не отдал
- стадию, на которой ждет больше всего сделок

`Sales` здесь означает одну из ваших воронок, их названия покажет `amo <profile> pipelines list`. Администратор может
копировать и сделки коллег, по их id пользователей: `amo <profile> users list`, затем настройка `unassigned` на
странице настроек. Ни одна настройка не копирует всю CRM, а любого другого клиента можно прочитать прямо из аккаунта
через `people` или `organizations`.

В терминале: `amo guide first-sync`

## Держать копию свежей

Пусть локальное хранилище само следует за аккаунтом, а искать в нем можно рядом с другими инструментами WireCat.

1. ```sh
   amo schedule command crm --every 1h -- sync
   ```

   таймер на этом компьютере, который запускает sync каждый час; он читает только то, что изменилось

2. ```sh
   amo schedule list
   ```

   расписание, когда оно сработает в следующий раз и как прошел последний запуск

3. ```sh
   amo store status
   ```

   насколько продвинулась синхронизация каждого вида данных, сколько записей сохранено и когда был последний запуск

4. ```sh
   amo search all invoice
   ```

   сохраненные сделки рядом с вашими сообщениями, заметками и встречами из других инструментов WireCat

На что смотреть:

- расписание, последний запуск которого не удался
- вид данных в store status с отметкой partial: следующая синхронизация продолжит его

`amo <profile> sync --rescan` читает все заново, в том числе каждый id, если копия выглядит неверной.

В терминале: `amo guide keep-in-sync`

## Дать агенту менять CRM без сюрпризов

Откройте агенту свою CRM через MCP, а записи, которые доходят до клиентов или которые нельзя отменить, оставьте себе.

1. ```sh
   amo config set permissions.deals.move readonly
   ```

   смена стадии может запустить автоматизацию самого аккаунта, например Salesbot, который пишет клиенту; через MCP ask не спрашивает, поэтому там ask ничего не останавливает

2. ```sh
   amo config set permissions.deals.close deny
   ```

   ни один агент не закроет сделку как успешную или проигранную, о чем бы его ни попросили

3. ```sh
   amo mcp add claude-code --permission people.update=deny --allow-writes
   ```

   добавляет этот профиль в Claude Code; этот сервер еще и отказывает в изменении контактов, а --allow-writes подтверждает записи, которые он все еще предлагает

4. ```sh
   amo config show
   ```

   каждое право с его уровнем и тем, откуда он взялся

5. ```sh
   amo runs list
   ```

   что запускал агент, в том числе отклоненные записи

На что смотреть:

- уровни deals.move, deals.close и people.update в config show
- отклоненные запуски в runs list и какая команда их просила

В терминале `ask` по-прежнему спрашивает перед записью. Через MCP отвечать некому, поэтому запись с уровнем `ask`
выполняется. Задайте `readonly` или `deny` или включите подтверждение `amo_write` в клиенте агента.

В терминале: `amo guide safe-agent-writes`
