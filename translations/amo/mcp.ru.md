Дайте вашу amoCRM или Kommo CRM ИИ-агенту, который не может запускать команды, например Claude Desktop, ChatGPT или
Claude в браузере. MCP (Model Context Protocol) это способ, которым такой агент спрашивает программу, что она умеет,
и потом вызывает ее. `amo` отдает свои команды именно так.

Тогда агент читает ваши сделки, контакты и компании и меняет их в пределах разрешений профиля.

`amo work mcp add` добавляет сервер в Claude Code или Codex, а `amo work mcp config` печатает запись для любого
другого клиента. Агенту с терминалом, например Claude Code или Codex, лучше подходят команды и навык
(`amo skill install`). Нужен профиль, в который вы вошли, и сначала загляните в [Разрешения](./permissions.md):
через MCP запись на уровне `ask` выполняется.

## Подключите amo к агенту

```sh
amo work mcp add claude-code --allow-writes   # or codex
amo work mcp check                            # the handshake and the tool list, as the client sees them
```

`--allow-writes` подтверждает, что вы знаете: профиль предлагает инструменты, которые пишут. Для любого другого
клиента `amo work mcp config` печатает запись, которую нужно вставить в его настройки. Вручную для Claude Code:

```sh
claude mcp add amo -- amo work mcp serve
```

Один сервер может обслуживать несколько профилей: `amo mcp serve --profiles work,sales` или `--profiles all`. Тогда
каждый вызов называет свой профиль, а агент спрашивает вас, если вы не сказали какой.

## Что видит агент

У сервера три инструмента:

- `amo_tools_search` находит команду по словам, с ее аргументами и видом ответа.
- `amo_read` запускает команду, которая только читает: `{ "command": "deals list", "arguments": { "query": "status:open" } }`.
- `amo_write` запускает команду, которая пишет: `{ "command": "deals move", "arguments": { "deal": "deal:12", ... } }`.

Команда называется так же, как в командной строке, без профиля, и проверяет тот же ключ разрешения. Через MCP никогда
не предлагаются `api call`, `session start` и `session end`. Агент просит вас запустить их самостоятельно.

Текст из аккаунта приходит с пометкой `untrusted`: названия сделок, контактов и компаний, названия воронок и этапов,
имена пользователей, значения пользовательских полей, примечания и теги, телефоны, почта и ссылки. Агенту сказано, что
это данные, а не инструкции.

## Записи остаются под вашим контролем

Через MCP в терминале никого нет, чтобы ответить на `ask`, поэтому запись выполняется. Перемещение, закрытие и
изменение сделок, контактов и компаний для нового профиля и так стоят на `allow`. А перемещенная сделка может
запустить собственные триггеры цифровой воронки amoCRM и Salesbot, которые могут написать настоящему клиенту.

Выберите одно до подключения сервера:

- Поставьте `readonly` или `deny` каждой записи, которую агент делать не должен:
  `amo work config set permissions.deals.move readonly`. Полный список есть в
  [Разрешениях](./permissions.md#what-a-new-profile-allows).
- Или включите подтверждение для инструмента `amo_write` в клиенте агента, чтобы клиент спрашивал вас перед каждой
  записью.

Чтобы один сервер был строже профиля, дайте ему свои уровни. Профиль они никогда не ослабляют:

```sh
amo work mcp add claude-code --allow-writes --permission deals.close=deny
amo work mcp serve --permission deals=readonly
```

## ChatGPT и Claude в браузере

Приложение в браузере подключается к серверу по HTTP через ваш собственный туннель, например Tailscale Funnel.
Команда использует адрес для примера `https://laptop.example.ts.net`. Подставьте вместо него адрес своего туннеля:

```sh
amo work mcp serve --http --public-url https://laptop.example.ts.net
```

Сервер слушает только `127.0.0.1`, порт 8765 (`--port` его меняет). Приложение в браузере входит по одноразовому
коду, который печатает команда. `amo work mcp revoke` завершает все входы.

`amo work mcp server start` запускает тот же сервер в фоне. `mcp server status` показывает его порт, код входа и
вошедшие приложения, а `mcp server stop` его останавливает.
