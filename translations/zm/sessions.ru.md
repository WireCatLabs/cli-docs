---
title: "Вход, сеансы и профили"
---

Подключите нужный аккаунт Zoom и проверьте, что подтверждение в браузере дошло до инструмента.
Затем выберите локальный профиль для сохранённых встреч. Разрешения приложения, сеанс OAuth и
профиль — разные вещи: смена метки профиля не выполняет вход под другим пользователем.

## Войти

Возьмите Public Client ID из [существующего или нового приложения Zoom](./zoom-app.md).
Запустите вход в интерактивном терминале компьютера, где будет храниться сеанс:

```sh
zm config set zoom.client_id <public-client-id>
zm personal session start --browser firefox
```

Агентам: запускайте `zm personal session start` в фоне (команда ждёт подтверждения до пяти минут, а инструмент оболочки
ничего не показывает, пока команда не завершится), прочитайте строку `Open this URL to approve Zoom login:` и URL
под ней и передайте URL человеку ссылкой. Браузер, в котором её откроют, должен быть на этом компьютере: ответ
приходит на слушатель здесь. `--quiet` URL не скрывает.

Без `--browser firefox` используется стандартный браузер. Zoom показывает запрошенные разрешения;
войдите в нужный аккаунт и подтвердите. Токены хранятся в системном хранилище секретов, а не в
общедоступном файле настроек. Если хранилище паролей недоступно, вход завершается ошибкой.

Если вы последний раз входили через zm 0.34 или старше, снова выполните `zm <profile> session start`: тот старый вход больше не используется.

## Завершите возврат из браузера

Оставьте терминал работающим. После **Allow** страница `https://wirecat.dev/zoom-callback` передаёт
ответ временному слушателю на вашем компьютере. При успешном получении слушатель закрывается,
команда сообщает `logged_in: true` и выданные разрешения, затем возвращает приглашение терминала.

Если после подтверждения в терминале ничего не появилось:

1. Посмотрите страницу возврата в браузере. Скопируйте показанные параметры `code=…&state=…` или весь URL.
2. Вставьте их в **тот же терминал, который ждёт в `zm personal session start`**, и нажмите Enter. Не запускайте
   другой процесс и не вставляйте значение как новую команду оболочки.
3. Если прошло пять минут, повторите вход и используйте новый ответ. У каждой попытки своё
   состояние и ключ проверки; ответ от старой попытки будет отклонён.

Браузер на другом устройстве, удалённый терминал или ограничения локальных соединений могут
потребовать вставки вручную. Не публикуйте ответ и не отправляйте его агенту: он относится к
активной попытке входа. Подключение завершено только после подтверждения в терминале.

## Проверить сеанс

```sh
zm personal session status --json
```

Проверяется сохранённое состояние без обращения к Zoom и обновления токенов. `state: saved`
означает наличие сохранённых данных, а не проверку на сервере. Список разрешений показывает,
что выдано. Для удалённой проверки добавьте `user:read:user`, подтвердите приложение снова и выполните:

```sh
zm personal session status --check --json
```

Ошибка недостающего разрешения указывает его имя. Владелец добавляет его в приложение и сохраняет,
а пользователь повторяет `zm personal session start`. Одно изменение настроек не расширяет уже выданный токен.

Без терминала вход всё равно печатает URL и ждёт ответа браузера; терминал нужен только для запасного
варианта со вставкой ответа. `--no-input` и CI запрещают вход через браузер. Вход не является инструментом MCP.

## Выбрать локальный профиль

```sh
zm personal meetings list
ZM_PROFILE=personal zm meetings list
```

Первое слово — профиль, как в `tg` и `max`; `ZM_PROFILE` задаёт то же для всей сессии оболочки. Профиль — это один
вход в Zoom и его собственные встречи в хранилище. Профиль никто не выбирает за вас: без профиля команда, которой
нужен аккаунт, завершается ошибкой `validation_error` и перечисляет имеющиеся профили в `details.profiles`. Имя
содержит 1–64 буквы, цифры, точки, подчёркивания или дефисы и начинается с буквы или цифры; слово команды, например
`meetings`, не может быть профилем.

`zm <name> session start` выполняет вход этого профиля и создаёт его. На компьютере, где профиля ещё нет, первый
импорт или загрузка тоже создаёт один, поэтому для настройки только с файлами вход в Zoom не нужен. Если профили
уже есть, импорт или загрузка с неизвестным именем отклоняется до сохранения чего-либо — `zm persnal meetings import …`
завершается ошибкой и перечисляет профили, — поэтому новый аккаунт начинается с его входа;
`zm <name> config set permissions '{}'` тоже создаёт профиль, для того, который только импортирует файлы. Команды чтения лишь ищут
профиль: сначала загрузите или импортируйте данные, чтобы `meetings list` мог его найти.

Для другого пользователя Zoom заведите второй профиль — `zm work session start` — и выберите этого пользователя в
браузере. Вход каждого профиля — отдельная запись хранилища ключей, `<client id>:<profile>`.

`ZM_PROFILE_LOCK=personal` привязывает процесс к одному профилю: первое слово или `ZM_PROFILE` с любым другим
именем отклоняется с `permission_error`. Задайте его там, где работает агент.

`MESSAGING_STORE` выбирает общую базу. Используйте один путь в Zoom, Memo и клиенте MCP для связи
встреч с заметками и проектами. Импорт файлов не продвигает курсор загрузки; при смене источников
может потребоваться более ранний явный `--since-time`.

## Удалить доступ

Команды выхода нет. Чтобы отозвать доступ приложения, удалите или отзовите его в управлении
приложениями Zoom App Marketplace. Чтобы удалить локальный токен, откройте системное
хранилище паролей и удалите запись, у которой служба — `zoom-cli:<configuration directory>` (например,
`zoom-cli:/home/you/.config/zm`; каталог показывает `zm doctor --json`), а аккаунт — `<Public Client ID>:<profile>`. Удаление `zm` не отзывает
разрешение Zoom и не стирает встречи. Перед передачей данных агенту прочитайте [безопасность](./security.md).

Несколько пользователей Zoom на одном компьютере — это несколько профилей: у каждого своя запись в хранилище ключей и свои встречи.

Когда сеанс и профиль готовы, [загрузите или импортируйте первую встречу](./archive.md#pull-hosted-meetings).
