title: "Локальный архив"
---

Сделайте текст встреч доступным для поиска и сохраните записи до окончания срока хранения в Zoom.
Выберите загрузку встреч организатора, импорт готовой расшифровки или архивирование облачного аудио
и видео. Текст в базе и медиафайлы в папке — разные копии; резервная запись не становится автоматически
доступной для поиска в базе.

## Выберите, что сохранить

| Что есть | Команда | Что проверить |
|---|---|---|
| Встречи организатора, доступные приложению | `zm personal meetings sync --lookback-days 7` | Список, расшифровку одной встречи и недостающие части |
| Скачанные VTT-файлы | `zm personal meetings import ./downloaded-transcripts` | Дату и название относительно оригинала |
| Облачные записи | Список или загрузку записей | Манифест папки и контрольные суммы |
| Архивные VTT для поиска | Импорт архива | Подтверждение импорта, затем поиск текста |

Для API подключите приложение с [разрешениями нужной задачи](./zoom-app.md#add-archive-or-management-access).
Импорт файлов и локальная проверка архива не требуют входа в браузере. Начните с одной встречи,
затем настройте повторные загрузки или ежедневную резервную копию.

## Где хранятся встречи

Вход, загрузка записей и удалённые команды работают независимо от базы встреч. Импорт, загрузка,
наблюдение за папкой и чтение используют опубликованный общий адаптер SQLite. Соединения открываются
по необходимости и закрываются до успешного вывода. Данные сохраняются в общей базе WireCat;
`MESSAGING_STORE` задаёт путь. Общая модель, экспорт и обработка — в `@wirecat/cli-core/meetings`.

Общая база называется `wirecat.db`. При её открытии старые файлы `messages.db` и связанные
файлы `-wal`, `-shm` сохраняются. Управляйте хранением старых файлов отдельно от импорта и чтения встреч.

Перед импортом или загрузкой выберите [локальный профиль](./sessions.md#select-a-local-profile).

## Загрузить встречи организатора

Выберите API, загрузите недавний период и проверьте результат:

```sh
zm config set source api
zm personal meetings sync --lookback-days 7
zm personal meetings list --json
zm personal meetings transcript <meeting-id> --json
```

Используйте ID из списка. `zm personal meetings sync` получает встречи организатора и доступных участников,
расшифровки и резюме ИИ. Он не создаёт отсутствующий текст. Если его нет, проверьте
[создание и хранение расшифровок](./zoom-app.md#before-your-first-zm-meetings-sync).

`meetings sync --lookback-days 7` снова проверяет семь дней; `meetings sync --since-time 2026-10-01` позволяет вернуться к
более ранним встречам с поздней расшифровкой. Один курсор не гарантирует повторную проверку.
Загрузки одного аккаунта выполняйте последовательно: одновременные могут создавать события.
Ошибка встречи не меняет курсор, поэтому следующая загрузка повторит её.

## Скачанные расшифровки

Для встречи, где вы были участником, получите VTT у организатора или скачайте его, если разрешено.
Участие не гарантирует доступ. Положите файл прямо в выбранную папку и назовите по дате, времени
и теме, например `2026-10-01_1000_example-planning.vtt`. Переименование не меняет текст внутри.

```sh
zm config set files.timezone Europe/Madrid
zm personal meetings import ./downloaded-transcripts
zm personal meetings list --json
```

Источник читает файлы `.vtt` и `.txt` прямо в папке, без вложенных каталогов. Имена имеют формат
`YYYY-MM-DD_HHMM_topic-slug.vtt` или `.txt`. `.txt` — форма, которую писал zoom-searcher: заголовок
(`Встреча:` название, `Дата:` начало, `Zoom ID:`, `Говорят:` участники), затем строки `[hh:mm:ss] Speaker: text`.
Его название заменяет название из имени файла; его время (как и время в имени файла) — момент окончания записи,
поэтому начало равно этому времени за вычетом смещения последней строки; его Zoom ID становится ключом серии, а
говорящие становятся участниками только этой встречи, по имени — никогда не одним человеком на разных встречах.
`.txt` и `.vtt` с одним именем — одна встреча, и читается `.txt`. ID выводится из времени и нормализованной темы;
UUID Zoom в этих файлах нет. Участники `.vtt` неизвестны: имена говорящих остаются текстом без угадывания
личности. `zm personal meetings import` называет пояс, в котором прочитал время файлов (`timezone`), а
`zm personal meetings import --help` показывает его до запуска. Проверьте дату, название и расшифровку до добавления проекта или людей.

Время в имени файла читается в поясе этого компьютера. `files.timezone` задаёт пояс IANA, в котором созданы имена,
если он отличается, например `Europe/Madrid`; хранение остаётся в UTC. Неоднозначное или несуществующее время перехода на летнее время отклоняется.
Разное содержимое одного нормализованного ключа — ошибка: исправьте конфликт перед повтором.
Неверное имя вызывает явную ошибку, а не незаметный импорт части папки.

## Наблюдать за новыми встречами

`zm personal watch api --lookback-days 7 --jsonl` повторно загружает API. `zm personal watch files [folder]` наблюдает
за папкой расшифровок; без папки используется `files.folder`. Без обоих аргументов действует настроенный
источник. API требует сети, поддерживает `--since-time` и перекрытие 0–31 день. `--since-time` — начальная граница; после успешной записи
курсора используется курсор с перекрытием. При ошибке начальная граница сохраняется. Перекрытие
также вычитается из начального `--since-time`.
`--pause` задаёт паузу между завершёнными циклами. Профиль, источник, файловые настройки и клиент
OAuth фиксируются до начала: после изменений перезапустите наблюдение. Циклы не перекрываются,
закрывают базу до квитанции. Ctrl-C останавливает процесс.

Для папки расшифровок:

```sh
zm personal watch files ./downloaded-transcripts --pause 10s --jsonl
```

Каждый цикл снова просматривает папку, включая исправленные старые файлы. Импорт последовательный,
база закрывается до квитанции; следующий цикл ждёт освобождения вывода. Интервал — от секунды до суток.
Процесс работает в текущем терминале до Ctrl-C. Без интерактивного терминала нужен `--jsonl`;
поток не использует `--json`. Сначала выберите профиль, как для разового импорта.

Если отмена приходит при закрытии базы, завершённой квитанции даётся до секунды на вывод.
Заблокированный канал останавливает этот вывод; новый цикл не начинается.

## Архивировать облачные записи

`zm` сохраняет доступные видео, аудио, расшифровки и чат. Найдите встречу и скачайте файлы в явный каталог:

```sh
zm personal recordings list --since-time 2026-10-01 --until-time 2026-10-10 --json
zm personal recordings show <zoom-occurrence-uuid> --json
zm personal recordings download <zoom-occurrence-uuid> --output-dir ./zoom-archive --json
zm personal recordings archive check ./zoom-archive --offline --json
```

Замените `<zoom-occurrence-uuid>` на UUID из списка записей, а не локальный ID или числовой номер
встречи Zoom. Подтверждение отмечает сохранённые и недоступные файлы. Проверка сравнивает локальные
файлы с манифестом, но не доказывает наличие всех записей в Zoom. При пустом списке проверьте даты,
аккаунт организатора, доступность облачных записей и разрешения, прежде чем расширять период. Без `--until-time` список заканчивается сегодняшним днём в поясе компьютера
или в `--timezone`, а `meta.timezone` называет этот пояс.

Для истории по месяцам:

```sh
zm personal recordings download --since-time 2026-01-01 --until-time 2026-10-10 --output-dir ./zoom-archive --jsonl
```

Даты должны идти по порядку и охватывать не более десяти календарных лет. Запросы выполняются
помесячно, UUID очищаются от повторов, загрузки последовательные. Каждая запись item в JSONL описывает
завершённую встречу; прежние квитанции и файлы остаются при поздней ошибке. Повторите диапазон или
недавний период для новых файлов. Выбранный профиль сохраняет прогресс и очередь записей.
`--recheck-since-time YYYY-MM-DD` повторно проверяет даты, `--checkpoint` задаёт файл состояния.
`--max-pages` и `--max-entries` ограничивают обнаружение. `--jsonl` передаёт подтверждения по мере
готовности; `--json` возвращает ограниченный список после завершения всего диапазона. В конвейере
по умолчанию используется JSON. При ошибке агрегатного запуска частичный JSON не выводится;
готовые файлы и контрольные точки остаются для следующей попытки. ID встречи нельзя сочетать
с датами диапазона; `--file-ids` действует только для одной встречи.

`recordings sync` удалена без псевдонима: используйте `recordings download` с теми же границами дат.
Если в сохранённых разрешениях есть `recordings.sync`, команды останавливаются с подсказкой о переносе.
Проверьте запись и замените её на `recordings.download`, сохранив остальные ограничения. Новый ключ
охватывает и одну встречу, и диапазон. См. [разрешения профиля](./configuration.md#permissions).

Контрольные точки подтверждают прежние загрузки, а не текущую целостность или полноту доступных
записей провайдера. `recordings archive check` проверяет файлы. `--no-resume` заново просматривает
весь диапазон без сохранённого прогресса.

Список записей принимает диапазон до 31 дня. Файлы потоково пишутся на диск, видео не загружается
целиком в память. Предел файла по умолчанию 20 ГиБ, меняется через `--max-bytes`. `--file-ids` выбирает
ID через запятую. Сохраняются только завершённые доступные файлы; прочие перечисляет квитанция.
Доступ зависит от разрешений, срока хранения и функций аккаунта. Запись встречи, где вы участвовали,
не обязательно доступна вашему API.

Манифест содержит метаданные, размеры и SHA-256, без подписанных URL и токенов. Повторная загрузка
проверяет файлы и пропускает совпадающие. Файл с прежним размером и временем изменения после
последней проверки (`.zoom-verified.json`) повторно не хешируется. `recordings archive check` всегда
хеширует все файлы. Ничего не перезаписывается; при несовпадении нужен новый
каталог. Загрузка и синхронизация действуют от профиля, названного первым (`zm personal recordings …`);
архив принадлежит его аккаунту. Проверенные частичные данные сохраняются; продолжение допускается только
при совпадении сильного валидатора и диапазона ответа. Изменённое представление безопасно начинается
заново. `--no-resume` использует временные
части. Завершённые записи манифеста сохраняются при поздней ошибке.

## Блокировки и восстановление

Локальная проверка работает без входа и базы. Одновременные записи в один каталог запрещены.
Загрузка сама забирает блокировку, оставленную завершившимся процессом на этом компьютере.
В остальных случаях просмотрите `recordings archive locks` и план `recordings archive recover`. `--yes`
убирает распознанные блокировки завершившихся процессов этого компьютера; активные, чужие и неизвестные
сохраняются. Убираются только маркеры блокировок. Продолжение может восстановить завершённую публикацию,
если принадлежащий операции журнал, проверенная часть и итоговый файл совпадают. Посторонние файлы защищены.

Если при архивировании сообщается, что процесс потерял блокировку или запись о владельце
изменилась, перед повторной попыткой проверьте каталог и записи блокировок. Проверьте контрольные
суммы готовых файлов: сбой освобождения ресурсов может произойти после сохранения файлов, даже
если команда не вернула успешный результат загрузки.

## Ежедневные копии

Выберите абсолютный каталог и пояс таймера:

```sh
zm personal recordings schedule create --name daily --output-dir /home/AliceExample/zoom-archive --since-time 2026-01-01 --at 03:15 --timezone Europe/Madrid --json
zm personal recordings schedule list --offline --json
zm personal recordings schedule run <schedule-id> --jsonl
zm personal recordings schedule disable <schedule-id> --yes --json
```

Создание сначала показывает план. `--yes` устанавливает пользовательский таймер systemd на Linux;
`--dry-run` важнее. Автоматическая установка только для Linux. Таймер следует поясу IANA, а поиск
записей — датам UTC и по умолчанию повторно проверяет семь дней. Нужен доступный пользовательский
systemd; планы работают и на других платформах. Задание сохраняет профиль, публичный client ID,
каталог и пути запуска и настроек, без секретов. Для выполнения его профиль и клиент должны оставаться
выбранными. Статус описывает последнюю подтверждённую операцию; список и просмотр не опрашивают таймер.
Отключение останавливает таймер, сохраняя задания и файлы.

## Читать и импортировать архивные расшифровки

Облачные файлы имеют хешированные имена, их идентичность находится в манифесте:

```sh
zm personal recordings archive transcript ./zoom-archive --offline --json
zm personal search recordings ./zoom-archive "example plan" --limit 100 --offline --json
```

Обе команды проверяют размер и SHA-256 каждого прочитанного WebVTT до выдачи фрагментов. Поиск
останавливается после одного совпадения сверх лимита; следующие файлы не читает. Вход, настройки
и база не нужны. Чтение расшифровки принимает `--uuid` или `--file-ids` для отбора, а `--max-bytes`
меняет предел 8 МиБ на файл; поиск отклоняет расшифровку больше 8 МиБ.
Поиск нормализует Unicode и регистр текста, не ищет имена говорящих. Лимит 100, максимум 1000.
`has_more` сообщает ещё одно совпадение: увеличьте лимит или сузьте запрос.
Курсора нет. Вывод ограничен `--max-output-bytes`; ошибка проверки не выдаёт успешный результат.

Для импорта в выбранный профиль:

```sh
zm personal recordings archive import ./zoom-archive --offline --jsonl
```

Все выбранные VTT проверяются до открытия базы. Пределы — 8 МиБ на файл и 64 МиБ суммарно;
`--max-bytes` и `--max-total-bytes` меняют их. Выберите `--uuid` или `--file-ids`. Встреча добавляется
атомарно по исходному UUID Zoom, сохраняя другие расшифровки, сводки, участников и курсор загрузки.
Исправления сохраняют старые версии; одинаковые хеши не создают дублей. Если время начала неизвестно,
добавление возможно только в существующую встречу. Квитанции показывают подтверждённые или недоступные
встречи. При поддержке точного результата они показывают создание встречи, вставку, повтор и замещение
из той же транзакции; старые адаптеры не угадывают счётчики. Ранее подтверждённые встречи могут
остаться сохранёнными, если следующее добавление не удалось.

## Расшифровать локальное аудио

Создайте отдельную расшифровку файла для уже сохранённой встречи:

```sh
zm models download parakeet-v3
zm personal meetings transcribe 1 ./AliceExample.m4a --model parakeet-v3 --json
zm personal meetings transcribe 1 ./AliceExample.m4a --model parakeet-v3 --yes --json
```

План проверяет вход и описывает выбранный компонент без его открытия. `--yes` распознаёт уже
установленным локальным компонентом и атомарно добавляет полную расшифровку; `--dry-run` важнее.
Расшифровка никогда не скачивает компонент: `zm models list kind:audio` показывает компоненты, известные этой версии,
а `zm models download <model>` скачивает один в папку, общую для всех CLI WireCat, проверяя sha256 каждого
файла; запустите команду снова, чтобы починить компонент, файлы которого другой версии. PCM16 WAV, моно или
стерео, 16 или 48 кГц читается как есть; всё остальное — MP4 и M4A записи Zoom, другое аудио и видео — сначала
декодирует `ffmpeg`, установленный на этом компьютере, во временную закрытую папку, которая потом удаляется. Один и
тот же файл всегда декодируется в то же аудио, поэтому повторная расшифровка — повтор. `--models-dir` выбирает абсолютный каталог компонента. Размер, время,
число сегментов и объём текста ограничиваются через `--max-bytes`, `--max-duration`, `--max-segments`
и `--max-text-bytes`. Окна до 30 секунд дают приблизительные границы времени. Говорящие неизвестны.
Расшифровки провайдера и история сохраняются; квитанция содержит счётчики транзакции и происхождение.

Распознавание требует установленного поддерживаемого речевого компонента; руководство не предполагает,
что он уже есть. Записи, не являющейся готовым WAV, нужен `ffmpeg` в `PATH`; zm его не устанавливает.
После применения откройте `meetings transcript` и проверьте слова и временные окна перед использованием
как источника. Затем переходите к [поиску и ссылкам](./search.md).
