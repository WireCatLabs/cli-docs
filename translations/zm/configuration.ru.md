title: "Настройки"
---

Измените приложение, источник или локальный профиль и проверьте настройки перед загрузкой или
сеансом агента. Открытые настройки выбирают приложение и пути данных; токены остаются в
системном хранилище секретов. Справочник перечисляет допустимые ключи и значения по умолчанию.

## Параметры

Установите значение через `zm config set <key> <value>`, удалите через `zm config unset <key>`, просмотрите все
настройки через `zm config show`.

| Ключ | Значение |
|---|---|
| `zoom.client_id` | Public Client ID [существующего или нового приложения](./zoom-app.md); изначально не задан, нужен для API |
| `source` | Источник `meetings sync` и `watch`: `api` по умолчанию или `files` |
| `files.folder` | Папка для загрузки/наблюдения файлов; изначально не задана |
| `context.sources` | JSON-массив явно выбранных аккаунтов сообщений, почты или папок документов для этого профиля; по умолчанию пуст ([настройка ниже](#select-communications-for-preparation)) |
| `files.timezone` | Часовой пояс IANA имён файлов, например `Europe/Madrid`; не задан: часовой пояс этого компьютера |
| `record` | `true` сохраняет каждый запуск в [журнале запусков](#run-log), `false` — ни одного, даже неудачного; не задан: только неудачные |
| `keep_runs_for_days` | сколько дней сохранённый запуск хранится до удаления; по умолчанию 30 |

После изменения проверьте `zm config show`. Профиль не настройка: это первое слово каждой команды
([профили](./sessions.md#select-a-local-profile)). Другой ID клиента выбирает другую запись ключей: подтвердите приложение перед API. `ZOOM_CLIENT_ID`
не является настройкой установленной команды `zm`; используйте `zm config set zoom.client_id`,
а не переменную из инструмента разработчика.

Файл хранит эти настройки как `client_id`, `files_folder`, `files_timezone`, `source`, `context_sources`,
`record` и `keep_runs_for_days`, а профили этого компьютера — в `profiles`. Любой другой ключ — проблема в файле.

## Проблемы в файле

Файл с проблемами не мешает `--help`, `--version`, `zm config` и `zm doctor`. Остальные команды останавливаются
на первой проблеме, называют способ её убрать и говорят, сколько проблем ещё. `zm doctor --json` перечисляет их все
в `config.issues`:

```json
{ "kind": "unknown_setting", "file": "/home/you/.config/zm/config.json", "key": "example_setting",
  "what": "setting example_setting is not a setting of zm", "fix": "zm config unset example_setting" }
```

`kind` — это `invalid_json`, `unknown_setting`, `unknown_permission` или `invalid_value`. `what` говорит, каким должно
быть значение, и никогда не показывает сохранённое. `fix` выполняется точно так, как написан; его нет у неверного JSON,
где `line` и `column` указывают, где чтение остановилось. Проблема в разрешениях одного профиля называет и этот
`profile`. Сломанная часть настройки, например одна запись `context_sources`, считается проблемой всей настройки, и
её `fix` убирает настройку целиком. Путь к настройкам, который оказался папкой или не читается, — одна проблема всего
файла, без `fix`. `zm config show` выводит каждую проблему после настроек, которые удалось прочитать, а `zm config set`
и `zm config unset` меняют файл, не трогая остальное.

## Найти файл настроек

`zm config set` создаёт и изменяет `config.json` автоматически. В нём открытые настройки, а не
токены Zoom; файл не скачивается из Marketplace. `zm doctor --json` показывает фактический путь,
не проверяя сохранённый сеанс OAuth.

| Платформа | Стандартные открытые настройки |
|---|---|
| Linux и macOS | `~/.config/zm/config.json` или каталог `zm` внутри `XDG_CONFIG_HOME` |
| Windows | `%APPDATA%\zm\Config\config.json` |
| Явный путь | `config.json` внутри `ZM_CONFIG_DIR` |

Старое расположение macOS больше не переносится автоматически; doctor показывает используемый путь.
Открытые настройки приложения, токены хранилища секретов и база встреч — разные данные.

`zm config set` сохраняет файл так, что читать его можете только вы (`0600`). `zm doctor --json` перечисляет файл и
его папку в `files.problems`, если их могут читать другие пользователи, с найденным и нужным режимом, и выводит в
stderr `chmod`, который это исправит. Сам он ничего не меняет. Windows не проверяется.

## Разрешения

Каждый профиль задаёт в `permissions`, что ему можно: путь команды через точки и уровень.

```sh
zm personal config set permissions '{"remote-meetings": "allow", "recordings": "readonly"}'
```

| Уровень | Действие |
|---|---|
| `deny` | команда отклоняется |
| `readonly` | запускается, только если ничего не меняет, как при `ZM_READ_ONLY` |
| `ask` | изменение в Zoom спрашивает y/N в терминале; без терминала нужен `--yes` (иначе код выхода 7) |
| `allow` | запускается; изменение в Zoom применяется без `--yes` |

Побеждает самый точный ключ (`remote-meetings.cancel` важнее `remote-meetings`). Встроенный уровень
`remote-meetings` — `ask`; более широкий ключ владельца его не ослабляет, ключ той же глубины ослабляет.
`--yes` лишь отвечает на `ask`: он никогда не снимает `deny` и `readonly`. В терминале настройки, вход, справка и
MCP-сервер не ограничиваются этими ключами. Ключ, не называющий команду, или уровень не из этих четырёх
отклоняется при установке; уже сохранённый останавливает все команды, пока
`zm <profile> config unset permissions.<key>` его не уберёт. `ZM_READ_ONLY` действует поверх любого уровня.

Настройки, установка навыка, обновление программы и изменение архивных таймеров через MCP требуют
`mcp.authority` со значением `allow` или `ask`. По умолчанию — `deny`. Задайте его из терминала
в карте `permissions`, сохранив остальные ограничения, затем перезапустите сервер MCP. Агент MCP не может менять разрешения
профиля. Подробности — в [руководстве MCP](./mcp.md#the-mcp-server).

## Журнал запусков

`zm` сохраняет неудачную команду как запуск: слова команды, профиль, чем она закончилась и по одному событию на
каждый запрос к Zoom с методом, путём (каждый ID скрыт как `:id`), статусом и длительностью. Аргументы, содержимое
встреч, имена, адреса почты и токены не сохраняются никогда. `--record` сохраняет и успешный запуск, `--no-record` —
ничего для этой команды, а настройка `record` меняет поведение по умолчанию. `zm runs list`, `zm runs show <run-id>`
и `zm runs path <run-id>` читают журнал без профиля; `meta.run_id` в ответе — это ID, который принимает `runs show`.

## Переменные среды

| Переменная | Действие |
|---|---|
| `ZM_CONFIG_DIR` | меняет каталог настроек и службу хранилища секретов для входа |
| `ZM_STATE_DIR` | меняет каталог записанных запусков (`runs/`) |
| `ZM_CACHE_DIR` | меняет каталог кеша |
| `ZM_READ_ONLY` | `1` запрещает менять Zoom, вход, настройки и то, что вы добавили (отказ с кодом 5); чтение и синхронизация из Zoom продолжают работать ([безопасность](./security.md#what-agents-can-do)) |
| `WIRECAT_STATE_DIR` | переносит папку WireCat, общую для всех CLI WireCat: базу и модели распознавания речи |
| `MESSAGING_STORE` | явный путь к общей базе для импорта, загрузки, наблюдения, чтения встреч и MCP |
| `OPENAI_API_KEY` | для явно выбранного OpenAI endpoint поиска по смыслу ([руководство](./topic-search.md)) |

Иначе каталоги следуют правилам платформы. Стандартная база — `wirecat.db`
(`~/.local/share/WireCat/wirecat.db`, в Windows `%LOCALAPPDATA%\WireCat\Data\wirecat.db`)
([хранение встреч](./archive.md#where-meetings-are-stored)). Передавайте одинаковое окружение
в терминале и MCP; иначе они могут видеть разные профили или базы. В [сеансах](./sessions.md)
проверьте авторизацию отдельно от открытых настроек.

## Выберите источники для подготовки

Подготовка может искать в аккаунтах и папках, уже импортированных в общую базу. Сначала выберите
локальный профиль Zoom, затем сохраните до восьми источников для него. У каждого должны быть ID,
тип kind, провайдер provider и аккаунт account. Для сообщений и почты нужны точные сохранённые
значения провайдера и аккаунта: скопируйте их из настроек исходного инструмента или его ссылок
на источники. Отображаемое имя не заменяет идентификатор аккаунта.

```sh
zm research config set context.sources '[{"id":"project-notes","kind":"document","provider":"local","account":"notes:5"}]'
zm config show
```

В примере вымышленный ID папки. Выполните `memo folders list` и подставьте ID выбранной папки и её провайдер:
`local` для обычной папки, `obsidian` для хранилища Obsidian.
`notes:5` находит её сохранённый идентификатор; команда не создаёт и не импортирует папку.
Источник документов охватывает одну папку, сообщений — один аккаунт мессенджера, почты — один
почтовый аккаунт. Разрешение распространяется на весь выбранный аккаунт или папку: ограничений
по отдельному чату, отправителю или пути пока нет. Выбирайте только подходящую для вашей задачи область.

Настройка заменяет источники текущего профиля и сохраняет настройки остальных. Значение `[]`
отзывает выбор для текущего профиля. Повторяющиеся ID и идентификаторы, неизвестные поля и более
восьми записей отклоняются. В JSON-файле массив хранится в `context_sources`, с полем `profile`
у каждой записи. Меняйте его через `config set`, чтобы не редактировать этот формат вручную.

Только явно запрошенные источники разрешаются и просматриваются при подготовке. Недоступный
источник, который вы не запросили, не мешает остальным. Обычное чтение встреч не получает доступа
к другим аккаунтам. MCP-сервер сохраняет определения источников при запуске и закрепляет
идентификатор каждого запрошенного источника при первом использовании. После изменения или
отзыва выбора перезапустите сервер. Отсутствующий или несовпадающий идентификатор приводит к
ошибке; автоматического выбора источников нет.
