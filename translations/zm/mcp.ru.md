---
title: "MCP и инструкции для агента"
---

Дайте агенту читать сохранённые встречи и отвечать с источниками. Выберите инструкции для
терминального агента или MCP для приложения, запускающего локальные инструменты. Skill — файл
инструкций; MCP — протокол вызовов. Ни один способ не выполняет вход и не загружает встречи.
[Сначала импортируйте или загрузите встречу](./installation.md#first-run), затем задавайте вопросы.

## Выберите подключение

| Ваш агент | Подключение | Результат |
|---|---|---|
| Codex или Gemini CLI на этом компьютере | `zm skill install --for agents` | Инструкции для команд |
| Claude Code на этом компьютере | `zm skill install --for claude` | Его инструкции для CLI |
| Локальное приложение с MCP | Добавить запись сервера ниже и перезапустить | Чтение сохранённых встреч |

Терминальный агент может выполнять полный набор команд, включая запись по вашим инструкциям.
MCP даёт более узкий набор для чтения. Это разные варианты доступа.

## Инструкции для агента

`zm skill show` показывает инструкции из пакета. `zm skill install` явно записывает копию с меткой
версии в `~/.claude/skills/zoom-cli/` для Claude Code и `~/.agents/skills/zoom-cli/` для Codex и Gemini CLI.
`--for claude` или `--for agents` выбирает одну группу; по умолчанию обе. При запуске обычной команды
инструкции автоматически не устанавливаются.

## MCP-сервер

`zm serve --mcp` использует stdio и предлагает восемь инструментов только для чтения: список и просмотр
встреч, расшифровки, сводки, экспорт, поиск слов, участников и источников по названиям проектов. Обнаружение инструментов не открывает
базу. Каждое чтение использует выбранный аккаунт и закрывает соединение до ответа; вызывающий не может
сменить аккаунт. Запись файлов экспорта и удалённые изменения не доступны как инструменты.

MCP-клиент запускает `zm` с `["serve", "--mcp"]`. Для формата `mcpServers` в
[конфигурации Claude Desktop](https://modelcontextprotocol.io/docs/develop/connect-local-servers):

```json
{
  "mcpServers": {
    "zoom": { "command": "zm", "args": ["serve", "--mcp"] }
  }
}
```

Приложение может не видеть `PATH` вашего терминала; stdio-сервер наследует только часть среды
([отладка MCP](https://modelcontextprotocol.io/docs/tools/debugging)). Если сервер не запускается,
используйте полный путь из `command -v zm` на Linux/macOS или `where.exe zm` на Windows. Если заданы `ZM_CONFIG_DIR` или `MESSAGING_STORE`, передайте
те же значения через `env`, иначе сервер прочитает другой профиль или базу.

Оставьте stdout для протокола: не добавляйте `--json` и `--jsonl`. `--max-output-bytes`
ограничивает результат каждого инструмента; ноль снимает ограничение. Перед чтением выберите профиль
и импортируйте или загрузите данные. Обнаружение инструментов доступно и без данных.

`meeting_people` ищет сохранённые имена и адреса участников в аккаунте, выбранном сервером.
`limit`, `scan_limit`, `max_read_bytes` и `cursor` ограничивают чтение. Поля отчёта `item.page`
и шаг `item.next` сохраняют продолжение, даже если текущая страница не содержит совпадений.
`identity_id` обозначает наблюдаемую идентичность; совпадающие имена не создают связи с человеком.
`meetings_list` принимает запрос метаданных `query` (например, `started_at:[2026-09-12 TO 2026-10-12]`)
вместо прежних `since` и `until` и возвращает общую сущность встречи и стандартную оболочку списка.

`meeting_project_evidence` принимает существующее имя/ключ/псевдоним проекта и общий запрос отбора,
а также limit, cursor и max_read_bytes. Возвращает один зарегистрированный элемент с проектом,
найденным названием, совпадениями с источниками, покрытием и неподтверждённым статусом связи.
Каждый вызов читает одну страницу названия из существующего индекса без его обновления. Следуйте
шагу next на верхнем уровне, даже если совпадений нет; возвращённые даты фиксированы для продолжения.
Инструмент не создаёт псевдонимы и не подтверждает принадлежность к проекту.

## Проверьте подключение

После установки инструкций начните новый сеанс агента, если он их не обнаружил. После настройки
MCP перезапустите приложение и проверьте наличие инструментов Zoom. Попросите:

```text prompt
Покажи сохранённые встречи. Открой последнюю, покажи дату, доступную расшифровку и отрывок, подтверждающий главное решение. Скажи, если данных недостаточно.
```

Сравните выбранную встречу с `zm meetings list --json` в терминале. Если инструменты есть, а данных
нет, проверьте тот же профиль и путь, затем загрузите или импортируйте. Если команда не запускается,
найдите её через `where.exe zm` на Windows или `command -v zm` на Linux/macOS и укажите полный путь
в настройке. Веб-чат не запускает локальную команду без поддерживаемого соединения с компьютером.

## Формат ответа

Успешные ответы инструментов используют те же оболочки элемента/списка, что CLI, с ключами
snake_case и `meta.run_id` / `meta.duration_ms`. Подробные отчёты контекста, участников и
смыслового поиска находятся в `item`; списки встреч, расшифровок, резюме и словесных совпадений —
в `items` и `page`. Текстовая и структурированная части содержат один полный ответ. Каждый
инструмент объявляет строгую схему успеха/ошибки. Неизвестные аргументы отклоняются обработчиком
до открытия хранилища: `validation_error` называет поле. Аккаунт выбирает сервер.

## Дополнительные инструменты

Флаги дополняют стандартный набор: `--meeting-context` добавляет фрагменты с цитатами, источники, контекст человека и
предложения задач; `--meeting-preparation` — `meeting_prepare` с удалённым расписанием и сохранённым контекстом с источниками; `--meeting-project-candidates` — `meeting_project_candidates` для сопоставления
одной сохранённой встречи с общими названиями, ключами и псевдонимами проектов; `--unified-search` — общий поиск только по встречам; `--semantic --model <model>` —
поиск `search_meetings` по существующим векторам через `by_meaning`. Для удалённого компонента нужны `--base-url` и `--dims`.
Сервер фиксирует компонент при запуске, профиль — при первом чтении. Перезапустите его, чтобы сменить
выбор; клиенты не могут это сделать. Генерация векторов и создание задач не являются MCP-инструментами.

Для контекста по проектам, заметкам и документам перейдите к
[поиску и источникам](./search.md#notes-tags-and-memories-with-memo); при необходимости подключите Memo отдельно.

С `zm serve --mcp --meeting-inventory` агент вызывает `meeting_series_inventory` для одной
страницы серий аккаунта, выбранного при запуске. Необязательные ISO `after`/`until`, `limit`,
`max_read_bytes`, `bytes` и `cursor` управляют чтением; выбрать аккаунт нельзя. По умолчанию окно
от текущего момента до семи дней спустя. Продолжайте `item.page.next_cursor` с возвращённым
абсолютным окном. Названия и старые начальные даты — подсказки, не проверка будущего события;
полнота календаря неизвестна. Это отдельное явное разрешение на удалённое чтение; нужны
`meeting:read:list_meetings` и сеть, `--offline` отклоняет запуск. База не открывается, записей
нет. Передайте выбранный ID в `meeting_prepare` для проверки ближайшего события. См.
[поиск серии](./usage.md#find-a-scheduled-meeting-series).

С `zm serve --mcp --meeting-project-candidates` агент может вызвать
`meeting_project_candidates` с родительской ссылкой `ref` на встречу и необязательными `limit`,
`cues`, `bytes`, `max_read_bytes` и `cursor`. Инструмент сопоставляет выбранную встречу с общим
каталогом названий, ключей и псевдонимов проектов, поэтому включается отдельно. Он открывает
существующее хранилище только для чтения, работает без сети и не сохраняет связи с проектами.
Сохраняйте неоднозначность и сведения о полноте кандидатов и доказательств; продолжайте через
`item.evidence.coverage.next_cursor` с той же `ref`. Пределы и проверка описаны в разделе
[предложений проектов для встречи](./search.md#suggest-projects-for-one-meeting).

С `zm serve --mcp --meeting-preparation` агент вызывает `meeting_prepare`, передавая `series_id`,
необязательный `project`, необязательные даты ISO `after`, `until`, `history_after` и ограничения `meetings`, `cues`,
`context_limit`, `max_read_bytes`, `bytes`. Сервер выбирает аккаунт и читает расписание Zoom;
нужно разрешение `meeting:read:meeting`. Инструмент недоступен с `--offline`, не меняет приложение
Zoom, не загружает отсутствующие расшифровки и не принимает найденные сведения. Элемент
`meeting_preparation` сохраняет цитируемые фрагменты, ограниченные связанные встречи через явные
связи с людьми/подтверждёнными проектами и явное покрытие. Принятые факты о людях/проектах находятся
в `knowledge`, со ссылками на факты и явными ограничениями проверки доказательств и других источников.
Заметки и комментарии владельца возвращаются отдельно в `notes`, со ссылками `note:`, номерами
редакций и явными ограничениями источников и покрытия. Встроенное хранилище использует выборку
`owner-written-meeting/person/project-notes` и ссылку `meeting` на включённый прошлый созвон либо null.
Заметкам с основным предметом-встречей нужна связь с включённым созвоном; одного общего проекта
недостаточно. Документы, почта и сообщения не запрашиваются, если вы явно не выбрали настроенные ID источников.
Связанные данные читаются только
в выбранном аккаунте и временном окне, без записи. В разделе
[подготовки](./usage.md#prepare-for-an-upcoming-meeting) описаны состав, непроверенные источники и проверка результата.

Необязательный `project` выбирает один существующий проект по названию, ключу или псевдониму.
`project_evidence` возвращает до четырёх ограниченных страниц поиска слов в этом аккаунте
и временном окне. Совпавшие названия, ссылки на фрагменты/встречи и исходные заголовки сохраняются
отдельно от подтверждённых связей с проектами; новая связь не создаётся. Повторённые ссылки
у разных названий — то же доказательство.
`project_evidence.continuation` задаёт аргументы существующего `meeting_project_evidence`:
сохраните `project`, зафиксированный `query`, `limit`, `max_read_bytes` и `cursor`, если он не null;
при null опустите `cursor`. Поле `command` называет эквивалент CLI, это не аргумент MCP.
Продолжайте и после пустой страницы, если покрытие показывает дополнительные результаты.
На каждой странице словарь и совпадения читаются отдельно в пределах `max_read_bytes`;
добавляется не более восьми таких чтений. Индекс не обновляется. Не выбранный явно проект
не выводится из заголовков, имён участников или фрагментов. Общее ограничение покрытия проектов
сохраняется, поскольку выбран лишь один проект.

Параметр подготовки `bytes` ограничивает элемент ответа после отображения скрытых символов,
которое может занимать больше места, чем CLI JSON. Сначала сокращаются дополнительные страницы совпадений проекта, затем заметки, затем принятые
факты, связанные созвоны и история выбранной серии. Проверяйте `meta.truncated` и покрытие разделов.
Поле `content_bytes` считает байты показанных MCP-клиенту фрагментов с видимыми управляющими
символами. Если не помещаются сами метаданные, возвращается `validation_error`: увеличьте `bytes`
или уменьшите выбранный контекст.

## Выбранные источники в подготовке встречи

[Настройте источники](./configuration.md#select-communications-for-preparation) перед запуском
`zm serve --mcp --meeting-preparation`. Список инструментов показывает только ID, сохранённые для
выбранного профиля при запуске, не открывая базу. Если источники не настроены, поле communications
не предлагается. После изменения или отзыва выбора перезапустите сервер.

Например, передайте такой запрос `meeting_prepare`:

```json
{
  "series_id": "123456789",
  "communications": {
    "sources": [{ "id": "project-notes" }],
    "query": "launch"
  }
}
```

Необязательные `communications.after` и `communications.before` принимают ISO-время с часовым поясом.
У каждого источника может быть `cursor` из предыдущего покрытия. Для продолжения явно задайте оба
предела из возвращённого окна, даже если сначала использовали значения по умолчанию: новое окно
не совпадёт со старым курсором. Общий обработчик проверяет неизвестные поля и ID до доступа к
учётным данным, открытия базы и запросов Zoom. Проверяйте `communications.coverage` вместе с
отрывками; подробнее — [пределы и продолжение](./usage.md#include-selected-messages-mail-and-documents).
