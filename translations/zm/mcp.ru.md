---
title: "MCP и инструкции для агента"
---

Дайте агенту читать сохранённые встречи и отвечать с источниками. Выберите инструкции для
терминального агента или MCP для приложения, запускающего локальные инструменты. Skill — файл
инструкций; MCP — протокол вызовов. Ни один способ не выполняет вход и не загружает встречи.
[Сначала импортируйте или загрузите встречу](./installation.md#first-run), затем задавайте вопросы.

## Выберите подключение

| Ваш агент | Подключение | Результат |
|---|---|---|
| Codex или Gemini CLI на этом компьютере | `zm skill install --for agents` | Инструкции для команд |
| Claude Code на этом компьютере | `zm skill install --for claude` | Его инструкции для CLI |
| Локальное приложение с MCP | Добавить запись сервера ниже и перезапустить | Чтение сохранённых встреч |

Терминальный агент может выполнять полный набор команд, включая запись по вашим инструкциям.
MCP даёт более узкий набор для чтения. Это разные варианты доступа.

## Инструкции для агента

`zm skill show` показывает инструкции из пакета. `zm skill install` явно записывает копию с меткой
версии в `~/.claude/skills/zoom-cli/` для Claude Code и `~/.agents/skills/zoom-cli/` для Codex и Gemini CLI.
`--for claude` или `--for agents` выбирает одну группу; по умолчанию обе. При запуске обычной команды
инструкции автоматически не устанавливаются.

## MCP-сервер

`zm serve --mcp` использует stdio и предлагает семь инструментов только для чтения: список и просмотр
встреч, расшифровки, сводки, экспорт, поиск текста и участников. Обнаружение инструментов не открывает
базу. Каждое чтение использует выбранный аккаунт и закрывает соединение до ответа; вызывающий не может
сменить аккаунт. Запись файлов экспорта и удалённые изменения не доступны как инструменты.

MCP-клиент запускает `zm` с `["serve", "--mcp"]`. Для формата `mcpServers` в
[конфигурации Claude Desktop](https://modelcontextprotocol.io/docs/develop/connect-local-servers):

```json
{
  "mcpServers": {
    "zoom": { "command": "zm", "args": ["serve", "--mcp"] }
  }
}
```

Приложение может не видеть `PATH` вашего терминала; stdio-сервер наследует только часть среды
([отладка MCP](https://modelcontextprotocol.io/docs/tools/debugging)). Если сервер не запускается,
используйте полный путь из `command -v zm` на Linux/macOS или `where.exe zm` на Windows. Если заданы `ZM_CONFIG_DIR` или `MESSAGING_STORE`, передайте
те же значения через `env`, иначе сервер прочитает другой профиль или базу.

Оставьте stdout для протокола: не добавляйте `--json`, `--jsonl` и `--fields`. `--max-output-bytes`
ограничивает результат каждого инструмента; ноль снимает ограничение. Перед чтением выберите профиль
и импортируйте или загрузите данные. Обнаружение инструментов доступно и без данных.

`meeting_people` ищет сохранённые имена и адреса участников в аккаунте, выбранном сервером.
`limit`, `scan_limit`, `max_read_bytes` и `cursor` ограничивают чтение. Поля отчёта `item.page`
и шаг `item.next` сохраняют продолжение, даже если текущая страница не содержит совпадений.
`identity_id` обозначает наблюдаемую идентичность; совпадающие имена не создают связи с человеком.
`meetings_list` принимает запрос метаданных `query` (например, `started_at:[2026-09-12 TO 2026-10-12]`)
вместо прежних `since` и `until` и возвращает общую сущность встречи и стандартную оболочку списка.

## Проверьте подключение

После установки инструкций начните новый сеанс агента, если он их не обнаружил. После настройки
MCP перезапустите приложение и проверьте наличие инструментов Zoom. Попросите:

```text prompt
Покажи сохранённые встречи. Открой последнюю, покажи дату, доступную расшифровку и отрывок, подтверждающий главное решение. Скажи, если данных недостаточно.
```

Сравните выбранную встречу с `zm meetings list --json` в терминале. Если инструменты есть, а данных
нет, проверьте тот же профиль и путь, затем загрузите или импортируйте. Если команда не запускается,
найдите её через `where.exe zm` на Windows или `command -v zm` на Linux/macOS и укажите полный путь
в настройке. Веб-чат не запускает локальную команду без поддерживаемого соединения с компьютером.

## Формат ответа

Успешные ответы инструментов используют те же оболочки элемента/списка, что CLI, с ключами
snake_case и `meta.run_id` / `meta.duration_ms`. Подробные отчёты контекста, участников и
смыслового поиска находятся в `item`; списки встреч, расшифровок, резюме и словесных совпадений —
в `items` и `page`. Текстовая и структурированная части содержат один полный ответ. Каждый
инструмент объявляет строгую схему успеха/ошибки. Неизвестные аргументы отклоняются обработчиком
до открытия хранилища: `validation_error` называет поле. Аккаунт выбирает сервер.

## Дополнительные инструменты

Флаги дополняют стандартный набор: `--meeting-context` добавляет фрагменты с цитатами, источники, контекст человека и
предложения задач; `--unified-search` — общий поиск только по встречам; `--semantic --model <model>` —
поиск `search_meetings` по существующим векторам через `by_meaning`. Для удалённого компонента нужны `--base-url` и `--dims`.
Сервер фиксирует компонент при запуске, профиль — при первом чтении. Перезапустите его, чтобы сменить
выбор; клиенты не могут это сделать. Генерация векторов и создание задач не являются MCP-инструментами.

Для контекста по проектам, заметкам и документам перейдите к
[поиску и источникам](./search.md#notes-tags-and-memories-with-memo); при необходимости подключите Memo отдельно.
