Новые записи переведены ниже; ранняя история сохранена на исходном английском. Названия команд и ограничения относятся к указанным версиям.

## 0.71.0 — 09.11.2026

### Добавлено

- **Pull request добавляет свои записи в историю изменений фрагментом `changes/<branch>.md`.** Открытые pull request больше не
  конфликтуют под `## Unreleased`. `pnpm docs:check` проверяет каждый фрагмент, а `bin/release` собирает их в раздел
  версии. Запись под `## Unreleased` на время перехода тоже работает.

### Изменено — может нарушить совместимость

- **У `zm search all` больше нет `--max-meetings`.** Команда читает встречи профиля через их поисковый
  индекс, ранжирует их вместе с сообщениями, почтой и заметками, даёт не больше 3 результатов на встречу и листает с `--page`. Она больше не
  просматривает 100 самых новых встреч. Результат из расшифровки содержит `cue_ref` для `meetings passage`. Общий поиск никогда
  не строит индекс: когда `missing` называет аккаунт, его строит `zm <profile> search meetings`.
- **cli-core 0.619.0.** `meetings link` от агента теперь открывает предложение для владельца, а не связывает человека.

### Исправлено

- **Собственные `meetings link --yes` и `meetings update --yes` владельца применяются сразу.** zm теперь сообщает cli-core, кто запускает
  команду: владелец за терминалом связывает человека сразу, а терминал агента или запуск через MCP только
  предлагает связь. Без этого cli-core 0.619.0 считал бы каждую связь связью от агента.

## 0.70.0 — 08.11.2026

### Добавлено

- **`zm <profile> session end`** удаляет сохранённый вход Zoom профиля из хранилища ключей и из закрытого файла.
  Сохранённые встречи остаются.
- **`zm <profile> account remove --keep-data|--delete-data`** удаляет профиль с этого компьютера: удаляет
  его вход, забывает профиль в настройках и его точки синхронизации, а с `--delete-data` удаляет его
  встречи из хранилища. С `--keep-data` они остаются доступными для поиска. Другие профили не меняются. Расписание архива,
  которое ещё работает для профиля, останавливает удаление: сначала выключите его командой `recordings schedule disable`. zm не
  отзывает вход в Zoom, он только забывает его здесь.

## 0.68.0 — 08.11.2026

### Добавлено

- **`zm meetings sync` останавливается до своего `--timeout` и продолжает в следующий раз.** Он читает встречи от старых к новым. Запуск,
  которому не хватило времени, сохраняет то, что успел, отвечает `stopped` и `remaining`, а следующая синхронизация начинается с первой
  встречи, до которой он не дошёл. Из cli-core 0.601.0 (был 0.600.0).
- **`zm meetings sync --rescan`** снова читает последние 30 дней, а не начинает с места, где остановилась прошлая синхронизация.
- **`zm meetings export` работает при `ZM_READ_ONLY` и через инструмент чтения MCP.** Без `--output` он только печатает.
  С ним он только добавляет новый файл и отклоняет уже существующий.
- **`zm app` печатает, что вводить при создании приложения Zoom**: тип приложения (General app, User-managed, Public
  Client OAuth), URL возврата и список разрешённых адресов, каждое разрешение, которое запрашивает zm, и страницу Marketplace, в виде нумерованного
  списка для проверки или в JSON с `--json`.
- **`zm <profile> session start --json --answer-stdin` спрашивает Public Client ID, когда приложение Zoom не задано**:
  строка `needs` с полем `client_id`, ответ на которую идёт через stdin. Вход продолжается с ним и после успеха сохраняет его
  как `zoom.client_id`, как `--client-id`.

### Изменено — может нарушить совместимость

- **Через MCP `meetings export` больше не принимает `--output`**: агент получает экспорт в ответе и не
  выбирает, куда на ваш диск он попадёт.
- **Поиск имён в cli-core считает ё и е одной буквой** (`Алена` находит `Алёна`). Имя, которое точно совпадало с одним,
  теперь может совпасть с двумя. Такое имя отклоняется с обоими вариантами.
- **Хранилище переходит на схему 55.** Другим WireCat CLI, которые с ним работают, нужна версия, которая её понимает.
- **Вход без приложения Zoom завершается с причиной `zoom.client-id-missing`** вместо общей причины ошибки конфигурации,
  поэтому вызывающий код проверяет причину, а не сообщение.

### Исправлено

- cli-core обновлён до 0.604.0.

## 0.67.0 — 05.11.2026

### Добавлено

- **`zm personal stats meetings history --by day|week|series`** считает встречи, минуты, средние минуты и встречи
  с расшифровкой, всего и по дням, неделям или сериям, с теми же фильтрами, что `stats meetings show`. Команда читает
  только сами встречи, поэтому у неё нет предела строк расшифровки. Встреча без конца считается встречей, но не в минутах.
  Из cli-core 0.570.0.
- **`zm config migrate` записывает каждую настройку, которой нет в файле, со значением по умолчанию, и каждая запись zm
  в файл тоже их добавляет**: `source`, `record`, `record_input`, `keep_runs_for_days`, `keep_successful_runs_for_days` и
  `runs_size_limit_mb`. Затем вы находите и меняете их в `config.json` без документации. Ваши значения, их порядок и
  ключи, которых zm не знает, остаются; `config unset` не возвращает удалённое, а простое чтение никогда не переписывает
  файл (cli-core 0.563.0).
- **`zm config show` перечисляет каждую из них в `settings`** со значением, значением по умолчанию, тем, задаёт ли её
  файл, и тем, что она делает.
- **`zm <profile> session start --client-id <id>` входит через это приложение Zoom** и после успешного входа сохраняет
  его как `zoom.client_id`, чтобы следующие команды нашли сделанный им вход.
- **`ZM_ZOOM_CLIENT_ID` называет приложение Zoom** и важнее `zoom.client_id`; `--client-id` важнее обоих
  (WC-SECR-25). У WireCat по-прежнему нет приложения Zoom, поэтому для входа через API нужно одно из трёх.

### Изменено — может нарушить совместимость

- **`zm doctor --json` сообщает `oauth_client` как `{ client, source }`**: `{ "client": "own", "source": "env" }` или
  `"config"`, а без приложения `{ "client": null, "source": null, "reason": "WireCat has no Zoom app yet; …" }`. Раньше
  было `{ "client": "own" }` или `{ "client": null, "error": "zoom.client_id is not set" }`. Из cli-core 0.566.0
  (было 0.563.0) и cli-base 0.77.1 (было 0.75.0).
- **Коды ошибок включают `conflict`, код завершения 15** (cli-base 0.76.0), в справочнике команд и в списке ошибок
  инструментов MCP. zm пока его не выдаёт.

## 0.61.0 — 31.10.2026

### Изменено — может нарушить совместимость

- **`mcp` и `doctor` — общие команды cli-core** (cli-core 0.503.0, было 0.491.0; cli-base 0.67.0, было 0.65.0), как в
  `mail`, `gcal` и `drive`, поэтому `zm` больше не отличается от них в этих местах.
  - `mcp serve` получает `--http`, `--port`, `--public-url` и `--permission <key=level>`, а `mcp` — `revoke`,
    `server start|stop|status`, `config`, `add` и `check`. Через HTTP сервер следует WC-MCP-12: он слушает
    `127.0.0.1`, браузерное приложение входит с одноразовым кодом, а запись подчиняется разрешениям профиля.
    `--permission` только делает уровень строже; уровень, который ослабил бы его или не называет ни одной команды,
    отклоняется при запуске.
  - `zm mcp serve --profiles all` на компьютере без профилей завершается с кодом 3 (ошибка настроек), а не 2.
  - Через MCP `search meetings` — чтение: вызывайте его через `zm_read`, а не `zm_write`. `complete` теперь
    предлагается как инструмент. `config unset permissions…` отклоняется через MCP, как уже отклонялся `config set permissions`.
  - В `doctor --json` теперь есть `paths`, `store`, `oauth_client`, `read_only`, `profile_lock` и `runtime.platform`.
    В нём больше нет `authentication` и `database`, и он больше не проверяет хранилище секретов; `oauth_client` сообщает
    `own` или `zoom.client_id is not set`.
  - Отказ по разрешениям профиля или по `ZM_READ_ONLY` называет команду: `profile work denies meetings.list`,
    `this process is read-only (ZM_READ_ONLY) — it cannot run remote-meetings create`.

## 0.57.0 — 27.10.2026

### Изменено — может нарушить совместимость

- **cli-core 0.469.0 и cli-base 0.65.0.** cli-core 0.469 принимает только cli-base 0.65, поэтому обе версии меняются вместе.
  cli-base 0.65 знает глаголы `serve` и `revoke`, поэтому их записи в базовом списке линтера убраны, а его `cli-dev bundle`
  находит сервер, запущенный с флагом перед `mcp serve`. Начиная с cli-core 0.468, сервер MCP предлагает команду, которая
  только загружает данные в хранилище, через свой инструмент чтения.
- **`zm mcp serve` называет, что обслуживает (WC-MCP-9).** Без профиля он больше не обслуживает все профили:
  он останавливается с `validation_error` (код 2) и перечисляет профили на этом компьютере. Обслуживайте один через `zm <profile> mcp serve`,
  несколько через `zm mcp serve --profiles work,personal` или все через `zm mcp serve --profiles all`; замените запись
  клиента MCP `["mcp", "serve"]` на `["mcp", "serve", "--profiles", "all"]`. Профиль вместе с
  `--profiles`, имя, которое здесь не профиль, или `all` внутри списка отклоняются с `validation_error`; при
  `ZM_PROFILE_LOCK` в `--profiles` можно назвать только закреплённый профиль (`permission_error`, код 5). При запуске
  сервер называет в stderr профили, которые обслуживает. Запись в MCP Registry теперь запускает `zm mcp serve --profiles all`.

### Исправлено

- **`zm` запускается примерно вдвое быстрее: пакет работает из сборки.** Раньше команда загружала около тысячи файлов
  модулей, прежде чем что-то сделать; теперь она загружает несколько десятков с тем же кодом, собранных `cli-dev bundle`
  из cli-base. Прогретый `zm meetings list --help` ускорился с 422 до 186 мс, `zm --version` — с 38 до 19 мс. Вывод не
  изменился. Запущенный `zm mcp serve` загружает весь свой код вскоре после старта, поэтому обновление `zm` на месте его
  не ломает. Пакет стал больше: 2,8 МБ для загрузки вместо 0,26 МБ.

## 0.56.0 — 27.10.2026

### Изменено — может нарушить совместимость

- **cli-core 0.467.0 и cli-base 0.64.0.** cli-core принимает только cli-base 0.64, поэтому обе версии меняются вместе.
- **Каждое попадание поиска отмечает текст, написанный кем-то другим (cli-core 0.464.0).** `zm search all`, `search meetings` и
  доказательства встреч проекта несут `untrusted` у каждого попадания (`["title", "excerpt"]`, у попадания в сообщениях или почте ещё
  `sender_name`), чтобы агент читал этот текст как данные. Вызывающий код, который проверяет попадания по старой строгой копии
  их формы, отклонит новое поле.
- **Сервер MCP теперь `zm <profile> mcp serve`; `zm mcp` только показывает справку (cli-core 0.463.0).** Каждый CLI WireCat
  теперь называет свой сервер одинаково. Замените записи клиентов MCP `["personal", "mcp"]` на
  `["personal", "mcp", "serve"]`, а также `claude mcp add zm -- zm personal mcp serve`. Без профиля `zm mcp serve`
  обслуживает все профили, как делал `zm mcp`. Запись в MCP Registry и образ Docker запускают `zm mcp serve`. У Zoom
  нет HTTP-сервера, поэтому нет и `mcp revoke`.
- **Общая база переходит на версию 35 (cli-core 0.463.0).** Первая команда `zm` после обновления добавляет
  столбец для календарных серий. Другим CLI WireCat, открывающим ту же базу, затем нужна версия, которая её понимает; `zm`
  сообщает об этом один раз и называет `<cli> upgrade`.

  - `watch --since` and `meetings context --since` → `--since-time`
  - `meetings evidence --after` → `--cursor`
  - `meetings task-proposal --kind` → `--type`
  - `remote-meetings create|update --topic` → `--title`
- **One meeting search, `zm search meetings <query>`, that indexes on its own.** It replaces four commands, which
  stop working:
  - `meetings search` and `meetings search-page`: their filters all move over, including `--event-id` and
    `--series-id`; `--since`/`--until` are `--since-time`/`--until-time` and `--after` is `--cursor`.
  - `meetings search-index`: gone. The search indexes what was stored since the last search before it reads.
  - `meetings semantic`: `search meetings <query> --model <model>` (with `--base-url`, `--dims`,
    `--max-chunks`, `--max-rows`, `--max-text-bytes`; `--after-chunk-id` is `--cursor`). It first builds the
    vectors that are missing for that model.
  - `recordings archive search <directory> <query>`: `search meetings <query> --archive <directory>` (with
    `--uuid`, `--file-ids`, `--max-bytes`).
  - MCP: `meetings_search`, `meeting_search_page` and `meeting_semantic_search` are one tool,
    `search_meetings`. With `serve --semantic`, `by_meaning: true` ranks existing vectors; MCP never builds
    them.
- Value names in help now say what they hold: `--limit <n>`, `--model <model>`, `--max-read-bytes <bytes>`,
  `--max-text-bytes <bytes>`; every argument has a description and long summaries are shorter.
