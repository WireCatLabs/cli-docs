Эта страница поможет подключить Memo к приложению ИИ без терминала, например к Claude Desktop или Cursor.
MCP (Model Context Protocol, протокол контекста модели) — это способ, которым такие приложения
используют программу на вашем компьютере. После подключения приложение может читать ваши сообщения,
почту, заметки и архивные встречи, а также то, что Memo знает о человеке. Ещё оно может сохранять память, записывать
факты и предлагать действия. Новые предложения ждут проверки; для решений по предложениям проекта
действуют отдельные разрешения, описанные ниже.

## Что приложение может делать через MCP

| Приложение может | Приложение не может |
|---|---|
| Искать и читать сохранённые сообщения, почту и заметки | Отправить сообщение или письмо |
| Читать контекст человека или проверять ожидающие выводы проекта | Изменить ваши заметки, почту или сообщения |
| Добавлять, показывать списком, открывать и искать память | Подтвердить запись памяти |
| Добавлять, показывать списком и открывать факты | Напрямую принять уже предложенный факт |
| Предлагать действия и показывать их списком | Одобрить или отклонить действие |
| Проверять предложения проекта и, если разрешено, принимать решения по процитированным фактам и поручениям с указанием причины | Подтвердить пакет выводов встречи |
| Читать журнал агентов | Удалить исходные сообщения, почту или заметки |
| Находить проекты, теги и темы по названию и видеть, какие задачи готовы | Создавать или изменять произвольные задачи |

`memories_add`, `facts_add`, `actions_add`, `meeting_actions_add` и `project_actions_add` сохраняют предложения.
По умолчанию `project_actions_confirm` и `project_actions_reject` могут принимать решения по предложениям проекта за вас
с сохранением причины. Подтверждение может создать принятые факты и нумерованные задачи или подтвердить
ключевой документ. Задайте [`agent_decisions: false`](./configuration.md#agent_decisions), чтобы решения
по предложениям проекта принимал только владелец; чтение и подготовка предложений останутся доступны.
Выводы встреч по-прежнему проверяет владелец. Предложенное через `actions_add` действие Memo никогда не отправляет.

Остальные инструменты не меняют исходные записи; поиск по встречам и сбор контекста проекта могут
обновлять локальные текстовые индексы. Подключайте Memo только к приложению, которому доверяете читать
ваши сообщения, почту и заметки.

## Подключите приложение

Добавьте Memo в настройки MCP приложения. Большинство приложений используют такой файл:

```json
{ "mcpServers": { "memo": { "command": "memo", "args": ["mcp"] } } }
```

Добавьте запись `memo` рядом с серверами, которые уже есть в файле:

| Приложение | Файл настроек |
|---|---|
| Cursor | `~/.cursor/mcp.json` |
| Claude Desktop, macOS | `~/Library/Application Support/Claude/claude_desktop_config.json` |
| Claude Desktop, Windows | `%APPDATA%\Claude\claude_desktop_config.json` |

Сохраните файл и перезапустите приложение. Memo должен быть установлен на том же компьютере, что и
приложение. Если приложение не находит `memo`, замените `"memo"` полным путём. Его покажет команда
`which memo` (macOS и Linux) или `where.exe memo` (Windows).

Затем проверьте:

```text prompt
Используй инструменты memo, чтобы показать записи памяти, которые ждут моей проверки.
```

## Инструменты

| Инструмент | Действие |
|---|---|
| `search_all` | Поиск сообщений всех мессенджеров, почты и заметок вместе; только чтение |
| `search_messages`, `search_mail`, `search_notes` | Поиск одного вида источников со всеми полями; только чтение |
| `search_meetings`, `meeting_passage` | Поиск по сохранённым встречам в одном явно выбранном аккаунте-источнике и чтение процитированных фрагментов расшифровки |
| `meeting_prepare` | Собрать сохранённую историю серии и связанный контекст, при необходимости с явно выбранными аккаунтами сообщений и почты; время следующей встречи не проверяет |
| `project_context` | Ключевые документы, ожидающие связи, факты и выводы встреч, а также открытые нумерованные задачи |
| `project_evidence` | Ссылки с цитатами о проекте из сохранённых сообщений, почты, расшифровок встреч и папок заметок, найденные по его названиям, дополнительным словам и людям; только чтение |
| `project_actions_add`, `project_actions_list`, `project_actions_confirm`, `project_actions_reject` | Подготовить процитированные факты и поручения по проекту, проверить их вместе с доказательствами и контекстом и решить те, в которых вы уверены, с указанием причины |
| `project_annotations_snapshot`, `project_annotations_preview` | Прочитать выбранные псевдонимы, факты и обычные связи или проверить явные соответствия в подготовленном назначении; восстановление доступно владельцу через CLI |
| `meeting_actions_add`, `meeting_actions_show`, `meeting_actions_list` | Предложить и просмотреть процитированные факты и поручения со встреч; никогда их не подтверждает |
| `person_context` | Человек в мессенджерах и почте, со связанными заметками и задачами; только чтение |
| `memories_add`, `memories_list`, `memories_show`, `search_memories` | Запись и чтение памяти |
| `facts_add`, `facts_list`, `facts_show` | Запись и чтение фактов |
| `actions_add`, `actions_list`, `actions_show` | Предложение и чтение действий |
| `agents_log` | Чтение журнала агента |
| `vocabulary_list`, `vocabulary_show`, `vocabulary_check` | Просмотр проектов, тегов и тем; только чтение |
| `vocabulary_inspect` | Проверить два выбранных тега перед объединением: счётчики, пересечения и ограниченные примеры; ничего не объединяет |
| `tasks_relations`, `tasks_status`, `tasks_list` | Зависимости задач; только чтение |

Предложения сохраняются под именем агента `memo-mcp`. Проверяйте предложенные записи памяти и факты командой `memo memories list status:proposed` и командами со страницы
[Память и факты](./memories.md).

## Журнал агентов

Каждый вызов приложения записывается в журнал агентов:

```sh
memo agents log agent:memo-mcp --limit 20
```

Журнал показывает инструмент, результат и время, но никогда не показывает, что отправило приложение.

О доказательствах из встреч см. [поиск по встречам](./search.md#search-stored-meetings). Попросите агента прочитать
фрагменты через `meeting_passage`, а затем подготовить пакет через `meeting_actions_add`. Передайте один `account`
в виде `example:work` и объект `input` с `schema_version: 1`, `key`, `extractor` и `findings`, с теми же полями,
что в `memo meetings actions add --help`. Каждому выводу нужны точные ссылки на реплики, отпечатки и
подтверждённая связь с проектом. Неизвестные даты и исполнители остаются пустыми; выведенные поручения
помечаются как выведенные. Точный повтор использует тот же ключ; изменённым входным данным нужен новый ключ.

`meeting_actions_show` и `meeting_actions_list` принимают явный `source`. Пакеты проверяет только владелец через
`memo meetings actions confirm` или `reject`. Подготовка пакета не создаёт ни фактов, ни нумерованных задач.

`project_actions_add` готовит процитированные факты и поручения по одному проекту: каждая ссылка — это ссылка
`msg:` или `document:` с `fingerprint`, который выдал `project_evidence`; текст, изменившийся с тех пор, отклоняется
как устаревший. `project_actions_list` постранично показывает предложения по проекту — предложенные ключевые
документы (`key:<n>`) и пакеты выводов — каждое с доказательствами: изменился ли текст (`state`), сам текст и
соседние сообщения, если не указан `brief`; для процитированных документов добавлены соседние абзацы. Изменение текста после подготовки пакета мешает подтвердить только выводы, которые на него ссылаются. Решайте те, в которых вы уверены, через `project_actions_confirm`
(ID выводов, которые нужно создать) или `project_actions_reject`, всегда с `reason`, которая сохраняется вместе с
решением; об остальных спросите владельца. Пакету нужен его `fingerprint`. Если владелец задал
`agent_decisions: false`, решения отклоняются и решает только владелец через `memo projects actions confirm` или `reject`.

У предложений ключевых документов нет сохранённого отпечатка текста: они возвращают `state: "untracked"`.
Перечитайте их перед решением. Выводы сохраняют собственные отпечатки источников для обнаружения изменений.

`project_evidence` принимает параметры `memo projects evidence` в snake_case и требует `source`: записи аккаунтов,
вид, `group:<name>` или `all`. Он ищет по названию проекта, его ключу, каждому сохранённому псевдониму и каждому
`alias`, каждому `context_query` и каждому `contact` отдельно и объединяет найденное; `since_time` по умолчанию `60d`.
Необязательный `before_time` задаёт исключаемый конец как метку времени ISO 8601 с `Z` или смещением UTC. Дни назад
отсчитываются от этого момента; явная дата начала тоже использует его как конец. Сохраняйте то же значение при
продолжении. Он фиксирует окно, но не исходные данные и не зарегистрированные псевдонимы и аккаунты.
Поддерживаются аккаунты встреч: зарегистрированный профиль, например `zm:work`, выбирает сохранённые
и индексированные фрагменты расшифровок этого аккаунта. Результат сохраняет точные ссылки на фрагменты
`meeting:` и использует дату начала встречи (`time_kind: "meeting-start"`). Заменённые и удалённые
расшифровки исключены. Отсутствующие расшифровки и неполные архивы остаются неизвестными; Memo не
скачивает записи. Для индексации расшифровок используется существующий процесс инструмента встреч;
описанное ниже обновление индекса почты и документов не индексирует расшифровки.
Перед поиском новые письма и документы индексируются; `catch_up: false` читает индекс как есть. Каждый
найденный текст сообщения содержит `around`: `before_n` и `after_n` соседних сообщений чата
(по умолчанию 2) как контекст, а не дополнительные совпадения. `mentions` перечисляет другие проекты,
теги и темы, упомянутые в текстах, со ссылками; упоминание не означает принадлежность. У элемента, найденного только
по имени контакта, стоит `context: "person-only"`. Источники, которые не удалось прочитать, перечисляются, а
`completeness` остаётся `unknown`. Если он возвращает `checkpoint`, вызовите его снова с теми же аргументами и
`cursor`, равным этому значению.
Он не создаёт факты, задачи или связи с проектами; описанное выше обновление индекса может менять локальные поисковые индексы.

Используйте `project_context` с ключом проекта, точным названием или псевдонимом, чтобы проверить ожидающие выводы вместе.
Предпросмотры встреч читают не больше пяти пакетов из каждого из восьми связанных аккаунтов встреч; команды
покрытия и продолжения называют остальные или недостающие записи. Предпросмотр содержит только нерешённые
выводы этого проекта. Прочитайте пакет целиком перед проверкой: в нём могут быть выводы и для другого проекта.

`project_annotations_snapshot` возвращает `snapshot` версии 2, его `fingerprint`, покрытие и ограниченные
счётчики чтения для существующего проекта. Тела источников исключены, предложенное состояние сохраняется.
Передайте снимок в `project_annotations_preview` с явными `target_store`, проектом назначения `project:<id>`
и `bindings`, сопоставляющими каждую внешнюю ссылку и проект. `max_read_bytes` может уменьшить бюджет
чтения в 4 МиБ. Назначение должно уже существовать, а источники, ключ и название проекта — совпадать.
Инструмент сообщает о конфликтах и возвращает отпечаток без восстановления. Оба инструмента отклоняют
неизвестные аргументы; после проверки схемы выполняются общие проверки графа и содержимого.

Заметки, специальные связи встреч с проектами, задачи, память, теги и выводы исключены: это формат выбранных
записей, а не полная копия проекта. Инструмента MCP для восстановления нет; владелец использует
[перенос выбранных записей](./recipes.md#keep-selected-project-annotations). Читающие инструменты
доступны с `MEMO_READ_ONLY=1`; вызовы по-прежнему создают обычную запись в журнале агента.

Дальше: [проверьте, что сохранило приложение](./memories.md).
