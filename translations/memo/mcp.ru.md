Эта страница поможет подключить Memo к приложению ИИ без терминала, например к Claude Desktop или Cursor.
MCP (Model Context Protocol, протокол контекста модели) — это способ, которым такие приложения
используют программу на вашем компьютере. После подключения приложение может читать ваши сообщения,
почту, заметки и архивные встречи, а также то, что Memo знает о человеке. Ещё оно может сохранять память, записывать
факты и предлагать действия. Новые предложения ждут проверки; для решений по предложениям проекта
действуют отдельные разрешения, описанные ниже.

Для приложений в браузере или на телефоне используйте [руководство удалённого подключения](./remote.md). Те же три инструмента доступны через HTTP с входом по коду и вашим HTTPS-туннелем.

## Команды и разрешения

Memo использует общий интерфейс MCP из cli-core. В нём три инструмента:

| Инструмент | Действие |
|---|---|
| `memo_tools_search` | Найти команды по словам, посмотреть аргументы и форму ответа; без запроса показывает весь каталог с текущей доступностью |
| `memo_read` | Выполнить команду чтения по её пути в CLI |
| `memo_write` | Выполнить команду записи по её пути в CLI; разрешения проверяются до выполнения |

Например, найдите чтение заметки через `memo_tools_search {"query":"notes show"}`, затем вызовите
`memo_read {"command":"notes show","arguments":{"note":"note:12"}}`.
Аргументы используют позиционные имена CLI и параметры в snake_case. Неизвестные аргументы отклоняются.
Команды выполняют сам CLI в этом же процессе, с теми же сервисами, ответами и ошибками.

Задайте `permissions` в [настройках](./configuration.md#permissions), чтобы ограничить действия приложения.
Ключ — путь через точку, например `notes.edit`; родительский ключ `notes` действует на все его команды.
`deny` помечает команду как недоступную, `readonly` разрешает чтение, `ask` и `allow` разрешают запись.
Через MCP `ask` выполняется без вопроса в терминале; запрос согласия зависит от клиентского приложения. Для записи без сохранённого уровня используется `ask`.
Для `mail delete` и `mail restore` также нужно `yes: true`, как `--yes` в CLI.

Изменение папок-источников и почтовых правил требует `mcp.authority`, по умолчанию `deny`.
Решения по выводам встреч (`meetings.actions.confirm` и `meetings.actions.reject`) и
`projects.annotations.restore` тоже имеют `deny`: владелец должен явно разрешить каждую операцию.
Сохраните разрешения в настройках: поиск команд и следующий вызов прочитают текущие уровни.
Разрешения и общий предел WireCat «только чтение» проверяются при каждом вызове.

`memo mcp --permission notes.edit=deny` ужесточает разрешение для одного сервера; повторите параметр для других ключей.
Он не может ослабить сохранённые разрешения, включая более конкретные ключи.
`MEMO_READ_ONLY=1` помечает все команды записи как недоступные и запрещает запись в уже открытом соединении.
Поиск сохраняет заблокированные команды с текущим `availability` и причиной, как в cli-core.

Исключения только для CLI: `mcp`, `upgrade`, `skill install`, `jobs start` и `jobs stop`. Они запускают
другой сервер, заменяют выполняемую программу, устанавливают инструкции в другие приложения или управляют таймером.

`memories add`, `facts add`, `actions add`, `meetings actions add` и `projects actions add` сохраняют предложения.
По умолчанию `projects actions confirm` и `projects actions reject` могут решать предложения проекта с сохранением
причины. [`agent_decisions: false`](./configuration.md#agent_decisions) оставляет решения владельцу через CLI и MCP. Memo никогда не отправляет сообщения или почту.

## Откройте процитированный источник

Передайте `ref` результата поиска в `notes show` как `note`, а ссылку на сообщение или письмо — в
`messages show` как `message`. `notes show` возвращает всю заметку; `messages show` — сохранённое сообщение
или письмо, а с `full: true` весь извлечённый текст вложений. `mail inspect` читает заголовки явно выбранного
аккаунта, `tags list` перечисляет теги. Для сообщений используется аккаунт и чат из ссылки;
к провайдеру обращений нет.

## Подключите приложение

Добавьте Memo в настройки MCP приложения. Большинство приложений используют такой файл:

```json
{ "mcpServers": { "memo": { "command": "memo", "args": ["mcp"] } } }
```

Добавьте запись `memo` рядом с серверами, которые уже есть в файле:

| Приложение | Файл настроек |
|---|---|
| Cursor | `~/.cursor/mcp.json` |
| Claude Desktop, macOS | `~/Library/Application Support/Claude/claude_desktop_config.json` |
| Claude Desktop, Windows | `%APPDATA%\Claude\claude_desktop_config.json` |

Сохраните файл и перезапустите приложение. Memo должен быть установлен на том же компьютере, что и
приложение. Если приложение не находит `memo`, замените `"memo"` полным путём. Его покажет команда
`which memo` (macOS и Linux) или `where.exe memo` (Windows).

Затем проверьте:

```text prompt
Используй инструменты memo, чтобы показать записи памяти, которые ждут моей проверки.
```

Предложения сохраняются под именем агента `memo-mcp`. Проверяйте предложенные записи памяти и факты командой `memo memories list status:proposed` и командами со страницы
[Память и факты](./memories.md).

## Журнал агентов

Каждая команда, дошедшая до исполнителя Memo, записывается в журнал агентов, включая отказы по разрешениям и проверке аргументов:

```sh
memo agents list agent:memo-mcp --limit 20
```

Журнал показывает команду с подчёркиваниями в имени, результат и время, но не аргументы.
Поиск команд и отказы общего протокола происходят до исполнителя команд.

О доказательствах из встреч см. [поиск по встречам](./search.md#search-stored-meetings). Попросите агента прочитать
фрагменты через `meetings passage`, а затем подготовить пакет через `meetings actions add`. Передайте один `account`
в виде `example:work` и объект `input` с `schema_version: 1`, `key`, `extractor` и `findings`, с теми же полями,
что в `memo meetings actions add --help`. Каждому выводу нужны точные ссылки на реплики, отпечатки и
подтверждённая связь с проектом. Неизвестные даты и исполнители остаются пустыми; выведенные поручения
помечаются как выведенные. Точный повтор использует тот же ключ; изменённым входным данным нужен новый ключ.

`meetings actions show` и `meetings actions list` принимают явный `source`. Владелец проверяет пакеты через
`memo meetings actions confirm` или `reject`, либо явно разрешает соответствующие инструменты MCP. Подготовка пакета не создаёт ни фактов, ни нумерованных задач.

`projects actions add` готовит процитированные факты и поручения по одному проекту: каждая ссылка — это ссылка
`msg:` или `document:` с `fingerprint`, который выдал `projects evidence`; текст, изменившийся с тех пор, отклоняется
как устаревший. `projects actions list` постранично показывает предложения по проекту — предложенные ключевые
документы (`key:<n>`) и пакеты выводов — каждое с доказательствами: изменился ли текст (`state`), сам текст и
соседние сообщения, если не указан `brief`; для процитированных документов добавлены соседние абзацы. Изменение текста после подготовки пакета мешает подтвердить только выводы, которые на него ссылаются. Решайте те, в которых вы уверены, через `projects actions confirm`
(ID выводов, которые нужно создать) или `projects actions reject`, всегда с `reason`, которая сохраняется вместе с
решением; об остальных спросите владельца. Пакету нужен его `fingerprint`. Если владелец задал
`agent_decisions: false`, решения отклоняются и решает только владелец через `memo projects actions confirm` или `reject`.

У предложений ключевых документов нет сохранённого отпечатка текста: они возвращают `state: "untracked"`.
Перечитайте их перед решением. Выводы сохраняют собственные отпечатки источников для обнаружения изменений.

`projects evidence` принимает параметры `memo projects evidence` в snake_case и требует `source`: записи аккаунтов,
вид, `group:<name>` или `all`. Он ищет по названию проекта, его ключу, каждому сохранённому псевдониму и каждому
`alias`, каждому `context_query` и каждому `contact` отдельно и объединяет найденное; `since_time` по умолчанию `60d`.
Необязательный `before_time` задаёт исключаемый конец как метку времени ISO 8601 с `Z` или смещением UTC. Дни назад
отсчитываются от этого момента; явная дата начала тоже использует его как конец. Сохраняйте то же значение при
продолжении. Он фиксирует окно, но не исходные данные и не зарегистрированные псевдонимы и аккаунты.
Поддерживаются аккаунты встреч: зарегистрированный профиль, например `zm:work`, выбирает сохранённые
и индексированные фрагменты расшифровок этого аккаунта. Результат сохраняет точные ссылки на фрагменты
`meeting:` и использует дату начала встречи (`time_kind: "meeting-start"`). Заменённые и удалённые
расшифровки исключены. Отсутствующие расшифровки и неполные архивы остаются неизвестными; Memo не
скачивает записи. Для индексации расшифровок используется существующий процесс инструмента встреч;
описанное ниже обновление индекса почты и документов не индексирует расшифровки.
Перед поиском новые письма и документы индексируются; `no_catch_up: true` читает индекс как есть. Каждый
найденный текст сообщения содержит `around`: `before_n` и `after_n` соседних сообщений чата
(по умолчанию 2) как контекст, а не дополнительные совпадения. `mentions` перечисляет другие проекты,
теги и темы, упомянутые в текстах, со ссылками; упоминание не означает принадлежность. Читается и каждое сообщение чата,
подтверждённого как чат проекта (`memo relationships add
chat:<provider>/<account>/<chat> project:<id>`), если
`source` включает его аккаунт: у таких элементов `context: "linked-chat"`, они ничего не называют, у их линии
`query: null` и задан `chat`. У каждой записи `linked_chats` есть `items` (новые элементы за этот запуск) и `capped`:
за один запуск из каждого чата берётся не больше доли лимита элементов, а `cursor` читает остальное из ограниченного
чата. Связанный чат вне `source` указан в `unread_sources` и не читается. Каждый человек, подтверждённый как участник проекта
(`person:<id>` `member-of` `project:<id>`), читается как контакт `person:<id>` ниже, без его псевдонимов и
без явной передачи: линия отправителя и элементы с `context: "sender"`. Человек, переданный ещё и как контакт, читается один раз.
Core берёт не больше 16 линий, поэтому участники, которые не поместились, в фиксированном порядке перечислены в `unread_sources` с
`kind: "member"` и `reason: "member-limit"`; у участника без сохранённой идентичности `reason: "no-identity"`. У элемента,
найденного только по имени контакта, стоит `context: "person-only"`. Для контакта `person:<id>` читается всё, что
написали сохранённые идентичности этого человека в `source` (линия `kinds: ["sender"]`, `query: null`, задан
`senders`; у элементов `context: "sender"`, они могут ничего не называть), а искать будут только по псевдонимам,
которые дал владелец, а не по отображаемому имени в мессенджере. `people` перечисляет, кто написал сообщения и письма
этого запуска, по сохранённым контактам, никогда по именам в тексте: одна запись на сохранённого человека
(`person: "person:<id>"`, `name`, каждая встреченная запись `identities` `{provider, account, id}`, так что Telegram и
WhatsApp одного человека считаются вместе) или на идентичность, не связанную ни с кем (`person: null`), с `items` и
`contexts` (элементы по `context`). Собственные сообщения владельца не учитываются. Сначала те, у кого больше элементов, не больше 20;
`people_omitted` считает остальных. Счёт относится только к этому вызову: складывайте его по вызовам с `cursor`. Источники, которые не удалось прочитать, перечисляются, а
`completeness` остаётся `unknown`. Если он возвращает `checkpoint`, вызовите его снова с теми же аргументами и
`cursor`, равным этому значению.
Он не создаёт факты, задачи или связи с проектами; описанное выше обновление индекса может менять локальные поисковые индексы.

Используйте `projects context` с ключом проекта, точным названием или псевдонимом, чтобы проверить ожидающие выводы вместе.
Предпросмотры встреч читают не больше пяти пакетов из каждого из восьми связанных аккаунтов встреч; команды
покрытия и продолжения называют остальные или недостающие записи. Предпросмотр содержит только нерешённые
выводы этого проекта. Прочитайте пакет целиком перед проверкой: в нём могут быть выводы и для другого проекта.

`projects annotations show` возвращает `snapshot` версии 2, его `fingerprint`, покрытие и ограниченные счётчики чтения
для существующего проекта. Тексты источников опущены, предложенное состояние сохраняется. Сохраните снимок в закрытый локальный JSON-файл,
затем вызовите `projects annotations check` с этим `file`, явным `target_store`, целевым `project:<id>` и JSON-файлом `bindings`,
сопоставляющим каждую внешнюю ссылку и проект. `max_read_bytes` может уменьшить бюджет чтения 4 МиБ.
Цель должна уже существовать и иметь совпадающие источники и ключ/имя проекта. Команда сообщает конфликты и отпечаток, ничего не восстанавливая.
Обе команды отклоняют неизвестные аргументы. После проверки схемы выполняются общие проверки графа и содержимого.

Заметки, специальные связи встреч с проектами, задачи, память, теги и выводы исключены: это формат выбранных
записей, а не полная копия проекта. Владелец использует
[перенос выбранных записей](./recipes.md#keep-selected-project-annotations) либо явно разрешает
`projects.annotations.restore` для сгенерированного инструмента. Читающие инструменты
доступны с `MEMO_READ_ONLY=1`; вызовы по-прежнему создают обычную запись в журнале агента.

Дальше: [проверьте, что сохранило приложение](./memories.md).
