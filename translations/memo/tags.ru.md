Эта страница поможет помечать ваши заметки, письма, сообщения, людей и проекты, а затем находить всё с
нужной меткой. Тег — это короткое слово, которое вы выбираете сами, например `work`, `family` или
`follow-up`. Теги хранятся в локальном хранилище: ваши файлы, ярлыки Gmail и почтовый ящик остаются
как есть.

## Добавьте тег

**Проще всего попросить агента.**

```text prompt
Use memo CLI to tag the notes about the Harbour budget with follow-up.
Show me which notes you tagged.
```

**Или выполните команды сами.** Сначала найдите ссылку на источник того, что хотите пометить, например
с помощью `memo search notes budget`. Затем:

```sh
memo tags add follow-up --note document:3
memo tags add work follow-up --note note:12      # two tags at once
```

Тег содержит от 1 до 32 символов: буквы a–z, цифры и дефисы. Заглавные буквы не учитываются,
поэтому `Work` и `work` — это один и тот же тег. Если добавить тег, который уже стоит, ничего не
изменится.

## Что можно пометить

| Что | Как это указать |
|---|---|
| Заметку, которую вы написали | `--note note:12` |
| Файл из папки заметок | `--note document:3` |
| Все заметки в папке или в одной из вложенных папок | `--folder 1` или `--folder 1 --subfolder Projects` |
| Сообщение или письмо | `--message 'msg:telegram/1/77/42'` (полная ссылка на источник) |
| Чат или цепочку писем | `--chat 77 --account telegram:1` |
| Контакт в одном аккаунте | `--contact 101 --account telegram:1` |
| Человека, чьи аккаунты вы связали | `--person PERSON_UID` |
| Организацию, проект или задачу | `--organization 2`, `--project 1`, `--task HRB-1` |
| Встречу | `--meeting 5 --account zoom:ACCOUNT` |

ID папки можно узнать через `memo folders list`. Тег на папке действует на каждую заметку в ней на любой
глубине, включая заметки, которые вы добавите позже.

Чат, контакт и встреча принадлежат одному аккаунту, поэтому для них нужен `--account`.
Человек, организация, проект или задача принадлежат вам, поэтому аккаунт для них не нужен.

## Теги в ваших файлах

Теги, записанные в файлах заметок, импортируются вместе с заметками:

- В обоих форматах — поле `tags:` в начале файла.
- В папке Obsidian — ещё и `#tags` в тексте.

Если вы удалите тег из файла, он будет снят с заметки при следующем импорте, если только вы не добавили
тот же тег ещё и в Memo. `memo tags list` показывает `(file)` рядом с тегами, которые пришли из файла.

## Найдите по тегу

```sh
memo tags list tag:follow-up               # everything with this tag
memo search notes 'budget' --filter 'tag:work'  # notes with the tag that contain a word
memo search all 'tag:follow-up'             # messages, mail and notes with the tag
memo tags list                              # every tag, up to 100
```

`memo tags list` показывает по 100 тегов за раз; чтобы увидеть больше, добавьте `--limit 500`.
`type:note` или `type:person` показывает только один вид.

## Снимите тег

```sh
memo tags remove follow-up --note document:3
```

Если снять тег, заметка, сообщение или человек остаются как есть. Если снять тег, которого нет, ничего не
изменится. Тег, пришедший из файла, снимают, редактируя файл.

## Проверьте дубли тегов

Попросите агента найти вероятные дубли тегов и показать доводы, прежде чем менять метки:

```text prompt
Проверь наши теги на вероятные синонимы. Сначала покажи канонические имена и псевдонимы. Для каждой
пары, которую я выберу, посмотри их назначения и пересечения. Не создавай псевдонимы и ничего не объединяй.
```

`memo vocabulary check --limit 20 --json` предлагает совпадения по написанию. Похожие имена — это
кандидаты на проверку, а не доказательство того, что два понятия одинаковы. Существующие псевдонимы —
это другие имена одной канонической записи, поэтому используйте их, прежде чем создавать ещё один тег.

Выполните `memo vocabulary list --json`, чтобы прочитать канонические ID и текущий отпечаток. Затем явно
выберите две записи **тегов**. Ниже замените `FINGERPRINT` отпечатком из этого списка без фильтров,
`tag:1` — дублем, который проверяете, а `tag:2` — именем, которое оставите:

```sh
memo vocabulary inspect tag:1 tag:2 --fingerprint FINGERPRINT --limit 5 --json
```

Команда показывает назначения каждого тега по типу цели, общие цели, псевдонимы, автоматические
присвоения и общие чаты, а также связи в обе стороны. В примерах назначений есть ID источников и авторов.
Она не читает тексты расшифровок и не обращается к модели. Она не меняет ни метки, ни псевдонимы.
`--limit` ограничивает примеры в каждой таблице, а не полные счётчики. `coverage.samples_complete`
говорит, были ли примеры обрезаны; `preview_fingerprint` и тогда покрывает все проверенные строки.

По умолчанию чтение ограничено 5 000 строками зависимостей и 1 МиБ входных данных. `--max-rows`
принимает до 20 000; `--max-read-bytes` — до 16 МиБ; `--limit` — до 100 примеров на таблицу. У каталога
отдельный лимит. Слишком большие зависимости проваливают весь предпросмотр, а не возвращают неполный
счёт. Осторожная оценка размера может отказать раньше, чем будет достигнут настоящий лимит JSON.
Если словарь изменился, получите список заново и выберите пару снова; не используйте устаревший отпечаток.

`coverage.inspected_tables` называет четыре охваченные таблицы: назначения, псевдонимы, автоматические
присвоения и связи. Текст сохранённых поисков, история предложений и произвольные сериализованные ссылки
в этот предпросмотр не входят. `coverage.apply_supported` равно false: это помощь в проверке, а не
исполняемый план слияния. Темы и проекты команда не принимает. Команды применения нет, и отпечаток
предпросмотра не даёт права на слияние. Команды псевдонимов, которые проверяет владелец, остаются отдельными.

## Теги в tg и max

tg и max читают те же теги: `tg search messages 'tag:follow-up'` находит помеченные сообщения Telegram, а `memo search mail 'tag:follow-up'` — письма. Теги контактов доступны через `tg tags` и `max tags`.
