title: "Поиск"
---

Эта страница поможет найти то, что вы написали или получили, в ваших заметках, почте или сообщениях
Telegram и MAX, и передать агенту источники, на которых основан ответ. Каждый результат называет свой
источник, поэтому вы можете открыть оригинал и проверить его. Пустой результат означает, что этот
поиск не вернул совпадений. Выбор источников, импортированная история или индекс поиска могут быть неполными.

## Попросите агента

```text prompt
Используй memo CLI, чтобы найти договорённости о бюджете Harbour в моих заметках, почте и сообщениях.
Приведи совпавший текст, покажи источник каждого результата и скажи, где не удалось поискать.
```

Агент выбирает поиск, читает подходящий текст и показывает вам источники. Каждый из них можно проверить
через `memo notes show` или в исходном приложении.

## Выберите, где искать

| Где это | Команда |
|---|---|
| Вы не знаете | `memo search all 'budget'` |
| В ваших заметках и файлах | `memo search notes 'budget'` |
| В вашей почте | `memo search mail 'budget'` |
| В сообщениях Telegram или MAX | `memo search messages 'budget'` |
| В сохранённых расшифровках и сводках встреч | `memo search meetings 'budget' --source zoom:work` |

`search all` ищет сразу в сообщениях, почте и заметках. Он не ищет встречи, людей, память, проекты и
задачи; для них используйте `memo context`, `memo search memories` и `memo tasks list`. Если вы знаете,
где что-то лежит, лучше использовать отдельный поиск по этому месту: он понимает больше слов для поиска.

## Слова для поиска

Поиск находит результаты, в которых есть **каждое** введённое вами слово, включая другие формы слова
(`meeting` находит и `meetings`).

| Что найти | Запрос |
|---|---|
| Все слова | `budget venue` |
| Точная фраза | `"budget review"` |
| Одно из слов | `budget OR invoice` |
| Без слова | `budget NOT cancelled` |
| С тегом | `tag:follow-up` |
| За день или начиная с даты | `date:2026-10-08`, `date:[2026-09-01 TO *]` |
| От кого или кому (почта и сообщения) | `from:kai`, `to:kai@example.com` |
| Тема или папка письма | `subject:invoice`, `mailbox:important` |
| Внутри вложения (сообщения и почта) | `content:invoice`, `filename:*.pdf` |

`content:` сужает поиск до текста файлов, `filename:` — до имён: `memo search messages 'content:invoice'`. Текст доступен после обработки файла tg или max (`tg personal attachments extract`) либо записи агентом.

Заключайте запрос поиска в одинарные кавычки, чтобы терминал передал его в Memo без изменений:
`memo search notes '"budget review" NOT cancelled'`. `--exact` находит слова только в том виде, в котором
они написаны.

## Сузьте поиск по заметкам

```sh
memo search notes 'budget' --filter 'tag:work'          # only notes with a tag
memo search notes 'budget' --source notes:2              # only one folder, by the id a hit shows
memo search notes 'budget source:internal'               # only notes you wrote in Memo
memo search notes 'budget' --filter 'date:2026-10-08'    # and a second condition
```

`source:file` показывает только заметки из файлов. Поле запроса `source:` обозначает источник самой заметки; параметр `--source` выбирает папки для поиска. Выдаётся по 20 результатов; `--page 2` открывает следующую страницу, а `page.next_page` указывает её номер.

## Поиск в почте

```sh
memo search mail 'from:kai subject:invoice'
memo search mail 'mailbox:important budget'
memo search mail 'budget' --source email:you@example.com
```

`mailbox:` находит почтовую папку или ярлык Gmail, например `inbox`, `important` или `starred`. Без
`--source` Memo ищет во всех почтовых аккаунтах; `--source email:work,email:personal` ищет в этих двух. Текст внутри вложений тоже ищется
(`filename:` и `content:`).

## Поиск по сохранённым встречам

Когда Zoom заархивировал ваши встречи в общее хранилище, Memo может локально находить подходящие фрагменты
расшифровок, названия встреч, сводки и текст чата. Он не обращается к Zoom и не отправляет текст модели.
Вместо `zoom:work` укажите имя вашего сохранённого аккаунта. `--source zoom` тоже работает, если в хранилище
ровно один аккаунт Zoom; при неоднозначном выборе Memo перечислит аккаунты:

```sh
memo search meetings 'budget' --source zoom:work --project HRB --since-time 2026-10-01 --limit 10 --json
memo meetings passage 'meeting:1/42/3/0' --source zoom:work --before-n 2 --after-n 2 --json
```

Скопируйте `ref` найденной записи в команду для фрагмента. У попадания в расшифровке есть ссылка на реплику,
например `meeting:1/42/3/0`, ссылка на родительскую встречу и `offset_ms`. Попадание в названии, сводке или чате
указывает на встречу; для чтения фрагмента нужна реплика расшифровки. Фрагмент включает соседние реплики, метки
говорящих, ревизию и отпечатки, чтобы агент мог точно сослаться на прочитанное. Пустого говорящего считайте
неизвестным; одна метка не устанавливает личность человека.

`--project` принимает ключ, название или записанный псевдоним проекта и выбирает подтверждённые связи встреч.
Инструмент MCP `search_meetings` также принимает `tag` и `topic` с существующими метками и их псевдонимами.
Слово о проекте в расшифровке не связывает встречу с проектом. Чтобы найти несвязанные встречи, ищите разные
названия проекта по отдельности без `--project`, затем просмотрите совпадения. `identity_id` и `person_id` в MCP
выбирают встречи с замеченными участниками; они не ограничивают результаты репликами этого человека.

Поиск по встречам использует собственный запрос из слов и свои флаги; поля запросов для почты и сообщений выше
к нему не относятся. Параметры дат и проектов показывает `memo search meetings --help`; в MCP есть также
селекторы событий и серий. JSON-ответы имеют стандартные `items`, `page`, `next` и `meta.accounts`; используйте
возвращённый курсор с тем же аккаунтом и фильтрами. Поле `missing` сообщает о неизвестной полноте архива. Даже
когда индексация готова, пустой результат не доказывает, что встречи не обсуждали тему. Если фрагменты изменились
во время индексации, повторите поиск, как подсказывает следующий шаг. Неархивированную или отсутствующую
расшифровку сначала нужно получить через Zoom.

Дальше: [превратите процитированные фрагменты встреч в выводы для проверки](./recipes.md#review-a-meetings-decisions-and-follow-ups).

## Собрать контекст встреч по проекту

Готовясь к обсуждению проекта, найдите его разные названия в выбранных аккаунтах. Так находятся
фрагменты расшифровок даже до того, как встреча связана с проектом. Попросите агента:

```text prompt
Используй memo CLI, чтобы собрать основания о проекте Harbour из моего рабочего аккаунта встреч
и Telegram. Ищи за последние 60 дней по сохранённым псевдонимам проекта. Покажи фрагменты со
ссылками, отдели сообщённые факты от предложенных следующих действий и укажи отсутствующие
источники или расшифровки. Не подтверждай выводы и не создавай задачи.
```

Для прямого запуска замените ключ проекта и названия аккаунтов своими:

```sh
memo projects evidence HRB --source zoom:work,telegram:1 --since-time 60d --json
```

Чтобы сравнивать запуски за одно и то же окно времени, задайте точный исключаемый конец через `--before-time`:

```sh
memo projects evidence HRB --source zoom:work,telegram:1 --since-time 60d --before-time 2026-10-01T12:00:00Z --json
```

Дни назад отсчитываются от этой метки времени. Явная дата начала в `--since-time` тоже сохраняет этот конец;
начало включается, конец исключается. Используйте настоящую метку времени с `Z` или смещением UTC, а не одну дату.
Текстовый вывод печатает точную границу. При `--cursor` не меняйте `--before-time` и остальные параметры.
Фиксированное окно не замораживает содержимое источников, зарегистрированные псевдонимы и выбор аккаунтов:
последующие импорты, правки и удаления всё ещё могут изменить найденное.

Каждое название или псевдоним задаёт отдельный поиск: все его слова должны встретиться в одном тексте, в любом
порядке, как целые слова; совпадения объединяются. Читается и каждое сообщение чата, подтверждённого как чат
проекта, если `--source` включает его аккаунт. Такие элементы помечены `linked-chat`: они ничего не называют, они
принадлежат чату. Связанный чат вне `--source` указан как непрочитанный. `--contact person:<id>` читает все
сообщения и письма, которые написали сохранённые идентичности этого человека в `--source`, с пометкой `sender`
(совпадение по автору, а не по словам), и ищет по псевдонимам, которые вы им дали; отображаемое имя в мессенджере
не ищется, потому что в текстах его редко пишут. Буквальный `--contact "<name>"` ищется как слова.
Результат встречи сохраняет точную ссылку на фрагмент и использует дату начала встречи: старая
встреча, импортированная сегодня, остаётся старой. Прочитайте фрагмент и соседние реплики через
`memo meetings passage`, прежде чем делать выводы. Сбор не создаёт связей с проектом, не устанавливает
состав участников и не сохраняет извлечённые факты и задачи.

Совпадение в документе включает короткие абзацы вокруг первого абзаца со словом из запроса.
Они помогают найти фрагмент, но не доказывают вывод. Если `oversized` перечисляет документ,
сбор не прочитал его текст: при необходимости откройте возвращённую ссылку через `memo notes show`.
Сохраните непрочитанный источник в результате вместо утверждения, что доказательств нет.

Если `units` сообщает об ожидающем индексе встреч, выполните `memo search meetings` для того же
аккаунта по [сценарию поиска встреч](#search-stored-meetings), затем повторите сбор. Обновление
индекса почты и документов не индексирует фрагменты расшифровок. Отсутствующие расшифровки сначала
должен сохранить инструмент встреч; даже завершённый обход страниц оставляет полноту архива неизвестной.

Продолжите ограниченный запуск с полученной контрольной точкой, теми же параметрами и `--cursor`.
Проверьте, продвигается ли чтение источников: повторные пустые страницы с тем же состоянием ошибки
не означают полного покрытия. Укажите оставшиеся непроверенными источники в ответе вместо бесконечных повторов.

Для фактов и следующих действий по сохранённым сообщениям, импортированной почте или файлам
[проверьте предложения проекта вместе с доказательствами](./recipes.md#review-project-facts-and-follow-ups).
Ссылки на реплики расшифровок используют отдельную
[проверку выводов встречи](./recipes.md#review-a-meetings-decisions-and-follow-ups), которой нужны
подтверждённые связи встречи с проектом. Сам сбор не создаёт ни одного из этих видов предложений.

## Поиск по смыслу

Если модель поиска есть на вашем компьютере, Memo также ищет по смыслу, поэтому по слову `holiday` может
найтись заметка об отпуске. tg или max скачивает модель один раз:

```sh
memo models text download e5-small
```

Модель работает на вашем компьютере. После скачивания выполните `memo sync`, чтобы подготовить заметки
к поиску по смыслу. Каждый результат сообщает, как он найден: по словам, по смыслу или обоими способами.
Без модели Memo пишет "Searched by words only" и ищет сохранённые заметки по словам.

## Что показывает результат

Для заметки результат показывает файл и первую подходящую строку. Под результатами Memo перечисляет
заметки и людей, на которых ссылаются результаты:

```text
Projects/Budget.md
  # Budget review

Linked from these notes
  Kai Sample  (nobody by that name yet)  (1)
```

`nobody by that name yet` означает, что заметка ссылается на имя, которое пока не принадлежит ни одному
известному человеку в локальном хранилище. Добавьте `--json`, чтобы получить ссылку на источник каждого
результата, его ссылки и то, как он был найден.

## Передайте агенту источники

`memo ask` собирает источники для вопроса, чтобы агент мог ответить и сослаться на них:

```sh
memo ask 'What is the Harbour budget?' 'Harbour budget' --all
```

Слова после вопроса задают поиск. Без них Memo ищет весь вопрос, и каждое слово должно совпасть. `--all` ищет во всех аккаунтах; `--source telegram:1` выбирает один. Ответ перечисляет источники с ссылками и текстом, область поиска и пропуски. Memo сам не отвечает на вопрос и не сохраняет ответ.

Memo может также отправить источники настроенному вами провайдеру ИИ и вернуть его ответ: добавьте
`--analyze`, а для провайдера за пределами вашего компьютера — ещё и `--allow-remote`. См.
[настройки](./configuration.md#environment-variables). Ответ провайдера — это сгенерированный текст:
сверьте его с источниками.

## Область чтения встреч

Memo и zm используют общие селекторы и парсеры cli-core: ID встречи, личности, человека, события и серии;
проект, тег и тему; границы времени, курсор и бюджет чтения. Например:

```sh
memo search meetings "draft" --source zoom:work --topic finance --meeting-id 12
```

Выбор аккаунта отличается: Memo требует один сохранённый `--source provider:account`, а zm выбирает аккаунт
аргументом профиля. `meetings passage` в Memo использует общую грамматику фрагментов, а `meetings prepare` —
общий сборщик контекста и схему ответа. Доказательства и покрытие JSON сохраняют общую форму;
текстовые сводки описывают фактическое чтение каждого инструмента.

Memo читает сохранённые архивы. Подготовка не проверяет время следующей встречи, поскольку не читает календарь
провайдера. zm может проверить расписание через соединение выбранного провайдера. zm также добавляет
необязательный поиск по смыслу и настройки удалённых эмбеддингов к общей грамматике. Поиск встреч в Memo
читает сохранённый текст по словам. Для тех параметров нужен отдельный процесс эмбеддингов;
в текущий модуль чтения встреч Memo они не входят. `search notes` и `search all` по-прежнему используют
общую локальную модель поиска по смыслу для заметок и почты.
