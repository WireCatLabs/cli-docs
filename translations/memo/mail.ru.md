Эта страница поможет добавить вашу почту в Memo. Тогда письма будут рядом с заметками и сообщениями:
в поиске, в контексте человека и в источниках, которые читает ваш агент. Memo читает почту через
[Himalaya](https://github.com/pimalaya/himalaya) — почтовую программу, которую нужно настроить заранее.
Ваш почтовый ящик открывается только для чтения: Memo никогда не отправляет, не перемещает и не удаляет
письма и не отмечает их как прочитанные.

## Перед началом

Настройте свой почтовый аккаунт в Himalaya. Для Gmail используйте аккаунт IMAP с
[паролем приложения](https://myaccount.google.com/apppasswords) Gmail (это отдельный пароль для одной
программы; его можно отозвать в любой момент). Прежде чем продолжить, проверьте, что Himalaya показывает
список ваших писем.

```text prompt
Help me set up Himalaya for my Gmail account with an app password, and check that it lists my inbox.
Then add the account to Memo's config and import the last 30 days of mail.
```

## Добавьте аккаунт в Memo

Укажите аккаунт в [файле настроек](./configuration.md#mail) Memo, `~/.config/cli-memo/config.json`.
`name` — это имя аккаунта в Himalaya; `address` — ваш адрес электронной почты:

```json
{ "mail": { "accounts": [{ "name": "work", "address": "you@example.com" }] } }
```

По умолчанию используется Gmail. Для другого почтового сервиса добавьте `"mode": "imap"` и папки, которые
нужно читать:

```json
{ "mail": { "accounts": [{ "name": "home", "address": "me@example.org", "mode": "imap", "folders": ["INBOX", "Archive"] }] } }
```

## Синхронизация почты

```sh
memo sync --account work --since-time 2026-09-01
```

`work` — это `name` аккаунта в настройках; можно указать и адрес. Без `--account` Memo читает все настроенные аккаунты и называет каждый в отчёте. При неверном имени показывает известные аккаунты.

- Без `--since-time` Memo читает последние 30 дней. Можно указать дату, время ISO 8601 или `30d` назад.
- Каждый запуск читает до 200 новых писем на аккаунт (лимит меняет `--limit`). Повторный запуск продолжает с места остановки: перечисляется только почта, не завершённая предыдущими запусками, без повторного обхода большого ящика.
- Полный обход отмечает удалённую у источника почту и обновляет ярлыки и состояние прочтения. Он выполняется не реже раза в день, после изменения правил и с `--rescan`; окно меньше 5000 писем обходится целиком каждый раз.
- `memo sync` и таймер читают все аккаунты из настроек.

Проверьте прогресс импорта без обращения к ящику:

```sh
memo mail status work
```

Первая строка описывает самое широкое когда-либо импортированное окно, например всё с 2004 года, и показывает «complete», только когда оно целиком сохранено. Более узкий последующий запуск, например 30 дней таймера, показан отдельно как последний запуск. Он не считается полным ящиком.

## Выбор почты для импорта

В большом ящике много рассылок и уведомлений. Перед первым большим импортом проверьте состав:

```sh
memo mail probe work
```

Команда читает только заголовки (около 1 КБ на письмо) и группирует почту по отправителю и рассылке: число писем, объём, доля непрочитанного и массовых рассылок, годы и писали ли вы отправителю. Для групп от 20 писем, где не менее 80% — массовая почта и вы не писали отправителю, предлагается `skip`.

Каждая группа также получает **оценку** сходства со спамом, мошенничеством или роботом и список составляющих признаков. Gmail уже фильтрует большую часть спама, поэтому высокая оценка обычно указывает на поддельного отправителя или робота, ещё не охваченного правилом:

| Признак | Баллы | Основание |
|---|---:|---|
| `spam_folder` | 4 | Большая часть писем группы в папке Спам Gmail |
| `dmarc_fail` | 3 | Проверка DMARC в Gmail не прошла при получении (`Authentication-Results: mx.google.com`) |
| `brand_spoof` | 3 | Бренд в имени отправителя, например PayPal или Apple, с другого домена |
| `young_domain` | 3 | Домену отправителя было меньше 180 дней при первом письме |
| `reply_to_elsewhere` | 2 | Ответы направляются на другой домен |
| `disposable_domain` | 2 | Домен одноразовой почты |
| `bulk_never_replied` | 1 | Не менее 80% массовой почты; вы не писали отправителю |
| `replied` | −5 | Вы писали отправителю |

Для `young_domain` нужна дата регистрации домена. memo запрашивает её только с `--domain-age`:

```sh
memo mail probe work --domain-age
```

Команда обращается через RDAP к реестру домена отправителя каждой показанной группы по списку IANA, не чаще одного домена в секунду, и сохраняет ответ на компьютере бессрочно. **Каждый запрос сообщает реестру имя домена**: реестр узнаёт, что кто-то проверяет почту с него. Крупные провайдеры вроде gmail.com и отправители, которым вы писали, не запрашиваются. У большинства национальных доменов, включая .ru, .de, .es и .io, нет RDAP: возраст остаётся неизвестным и баллов не добавляет. Без `--domain-age` используются только сохранённые даты.

Решение принимаете вы:

```sh
memo mail rules add work --domain shop.example --do envelope --reason 'newsletters'
memo mail rules add work --domain spam.example --do skip
memo mail rules add work --sender orders@shop.example --do keep
memo mail rules list work
```

`--do` правила задаёт одно из трёх действий:

- `skip`: `memo sync` не читает и не сохраняет письмо, учитывая его как пропущенное.
- `envelope`: `memo sync` сохраняет отправителя, дату, размер, ярлыки и id Gmail, без текста и вложений. Тема сохраняется в метаданных, поэтому письмо не попадает в результаты поиска. `memo mail rules list` показывает число и объём писем каждого правила, позволяя оценить очистку. Конверт не требует от Gmail больше данных, чем пропуск: поля уже есть в списке.
- `keep`: импортирует письмо, даже если оно подходит под правило пропуска или конверта.

Сохранение важнее конверта, конверт — пропуска. После удаления правила конверта или замены его на сохранение следующая синхронизация прочитает эти письма целиком. Почта, сохранённая до правила, не меняется.

Письма, сохранённые целиком до правила конверта, остаются полными до явного сокращения:

```sh
memo mail rules apply work        # says how many emails and how much text each rule would cut
memo mail rules apply work --yes  # cuts them to envelopes
```

Команда читает заголовки аккаунта из ящика, как `memo sync`: у писем, сохранённых до поддержки List-Id, этого поля нет. У подходящего письма удаляются текст, вложения и поисковые записи; отправитель, дата, размер, ярлыки и тема остаются в метаданных. Письма, подходящие только под пропуск, не меняются. Ящик не изменяется; после смены правила на сохранение следующая синхронизация снова прочитает письма целиком.

Правила находятся в локальном хранилище рядом с почтой; `memo mail rules list` считает письма каждого правила одним запросом. Каждый конверт помнит правило, по которому сохранён. Для проверки, резервной копии или переноса правил:

```sh
memo mail rules export work > rules.json
memo mail rules import work rules.json   # a rule with the same sender, domain or list is replaced
```

До 0.32.0 правила находились в `config.json`. Первая команда memo, читающая правила, переносит их в хранилище, проверяет перенос и лишь затем убирает из настроек. Рядом остаётся прежний файл `config.json.<time>.before-rules-in-store`, доступный только вам; memo один раз сообщает об этом в stderr. Правило сохранения с причиной «never remove» становится защищённым: очистка не может сокращать или удалять подходящую почту.

## Старая почта из Google Takeout

Gmail ограничивает дневную загрузку через IMAP; многолетнюю почту быстрее загрузить из экспорта Mail в [Google Takeout](https://takeout.google.com/). Добавьте файл вторым аккаунтом с тем же адресом, чтобы его письма и письма Gmail были одним набором:

```json
{ "name": "archive", "address": "you@example.com", "mode": "mbox", "path": "~/Takeout/Mail/All mail Including Spam and Trash.mbox" }
```

```sh
memo sync --account archive --since-time 2000-01-01 --limit 5000
```

Файл читается, только если указать этот аккаунт; каждый запуск читает его целиком. Импорт только добавляет почту: отсутствующие в файле письма не удаляются из хранилища, Спам и Корзина пропускаются.

## Найдите свою почту

```sh
memo search mail 'invoice'
memo search mail 'from:kai subject:budget'
memo search mail 'mailbox:starred' --account you@example.com
memo search all 'budget'
```

Ярлыки Gmail, например «Входящие», «Важные», «Помеченные» и ваши собственные ярлыки, становятся
почтовыми папками, поэтому `mailbox:important` находит такие письма. См. [Поиск](./search.md#search-mail).

## Что сохраняется

- Отправитель, получатели (To, CC и BCC), тема, дата и текст каждого письма.
- Прочитано ли письмо и помечено ли оно звёздочкой — так, как это показывает ваш почтовый ящик.
- Текст вложений, которые можно прочитать. Он ищется вместе с письмом. Для вложений PDF и Word нужны
  [дополнительные модули чтения](./notes.md#files-memo-can-read). После их установки запустите
  `memo sync --account work --retry-attachments`, чтобы прочитать пропущенные вложения.
- До 1 000 000 символов каждого письма и до 200 000 символов каждого вложения
  ([как изменить ограничения](./configuration.md#mail)).

Почта готовится к поиску по смыслу, если модель поиска есть на вашем компьютере; `--no-embed`
пропускает этот шаг.

## Если письмо удалено

Если вы удалите письмо в почтовом ящике, его текст исчезнет из локального хранилища при следующем
импорте. Письма, перемещённые в спам, считаются удалёнными. Чтобы защитить вас от ошибок:

- первые два дня периода не проверяются на удаление;
- если при запуске окажется, что пропала необычно большая часть почты, Memo ничего не удаляет и сообщает
  вам об этом.
