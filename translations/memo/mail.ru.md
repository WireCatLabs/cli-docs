Эта страница поможет добавить вашу почту в Memo. Тогда письма будут рядом с заметками и сообщениями:
в поиске, в контексте человека и в источниках, которые читает ваш агент. Путь для этого — отдельная
программа [mail](https://github.com/WireCatLabs/mail-cli): `mail` копирует ваш ящик в общее хранилище
WireCat, а Memo ищет и показывает то, что в нём лежит. `mail` только читает ваш ящик. Memo никогда не отправляет
письма.

Memo пока умеет импортировать почту и через Himalaya. Этот старый путь работает сейчас и будет удалён в одной из
следующих версий; он описан в разделе [Старый импорт через Himalaya](#older-import-through-himalaya-legacy).

## Добавьте почту через mail

Установите `mail` и добавьте свой ящик. В его [документации](https://github.com/WireCatLabs/mail-cli/blob/main/docs/index.md) перечислены шаги для каждого
провайдера, например настройка IMAP и пароль приложения (это отдельный пароль для одной программы; его можно
отозвать в любой момент).

```sh
npm install -g @wirecat/mail-cli
mail ya session start --address me@example.com
mail ya sync
mail ya status
```

`ya` — имя профиля, которое вы выбираете для одного ящика. `session start` выполняет вход, `sync` читает последние
30 дней в общее хранилище, а `status` показывает, как далеко продвинулся большой ящик. Чтобы получить новую почту,
снова запустите `mail ya sync`. Для такой почты в Memo ничего настраивать не нужно: он читает то же хранилище.

`mail` сохраняет текст и заголовки каждого письма, но не вложения. Что он сохраняет и как поддерживать ящик в
актуальном состоянии, см. в его [документации](https://github.com/WireCatLabs/mail-cli/blob/main/docs/index.md).

## Ищите и читайте почту в Memo

```sh
memo search mail 'invoice'
memo messages show <ref>
```

`<ref>` — это `ref` найденного результата. `memo search all` находит эту почту вместе с заметками и сообщениями.
Больше слов для поиска — в разделах [Найдите свою почту](#find-your-mail) и [Поиск](./search.md#search-mail).

## Команды memo mail

`memo mail inspect`, `rules`, `delete` и `restore` пока остаются. Они берут аккаунт из списка
`mail.accounts` в Memo, который `memo mail add` заполняет из аккаунта Himalaya, поэтому для аккаунта, добавленного
только через `mail`, они не работают.

Когда `mail` синхронизирует аккаунт, который есть и в `mail.accounts`, задайте ему `"import": false`, например
`{ "name": "personal", "address": "you@gmail.com", "import": false }`. Тогда `memo sync` и таймер пропускают его импорт
через Himalaya, а `memo sync --source email:personal` сообщает, что импорт передан `mail`. Четыре команды выше
продолжают работать, и каждая синхронизация по-прежнему исправляет HTML-текст, оценивает отправителей и строит
эмбеддинги для почты, уже лежащей в хранилище. Только дозагрузка заголовков нуждается в Himalaya, поэтому она
останавливается.

| Команда | Что нужно | Что делает |
|---|---|---|
| `memo mail inspect <account>` | Аккаунт Himalaya в настройках Memo | Читает заголовки из ящика и группирует почту по отправителям ([Выбор почты для импорта](#choose-what-to-import)) |
| `memo mail rules ...` | То же | Хранит и меняет правила того, что сохраняет импорт. `rules apply` тоже читает заголовки из ящика |
| `memo mail delete <account>` | То же и `--yes` | Перемещает выбранные письма Gmail в корзину Gmail ([Очистите Gmail](#clean-up-gmail)) |
| `memo mail restore <account>` | То же и `--yes` | Возвращает из корзины письма записанного запуска |

`memo mail delete` — единственное место, где Memo изменяет ящик. Сам `mail` этого никогда не делает.

## Старый импорт через Himalaya (legacy)

Этот импорт будет удалён в одной из следующих версий. Для новых аккаунтов используйте
[mail](#bring-mail-in-with-mail). Здесь Memo читает почту через [Himalaya](https://github.com/pimalaya/himalaya) —
почтовую программу, которую нужно настроить заранее. Импорт читает ваш ящик, не изменяя его и не отмечая письма
прочитанными.

### Перед началом

Настройте свой почтовый аккаунт в Himalaya. Для Gmail используйте аккаунт IMAP с
[паролем приложения](https://myaccount.google.com/apppasswords) Gmail. Memo работает с Himalaya 2.x (`himalaya --version`).

Himalaya читает свои аккаунты из `~/.config/himalaya/config.toml` (`HIMALAYA_CONFIG` или `-c` указывают
другое место). Аккаунт Gmail с именем `work` выглядит так; пароль берётся из команды, здесь из связки ключей
Linux, поэтому в файле он никогда не записан:

```toml
[accounts.work]
email = "you@example.com"
imap.server = "imaps://imap.gmail.com:993"
imap.sasl.plain.username = "you@example.com"
imap.sasl.plain.password.command = "secret-tool lookup service himalaya account work"
```

`himalaya account list` показывает аккаунты, которые он прочитал. Прежде чем продолжить, проверьте, что
Himalaya показывает список ваших писем.

```text prompt
Help me set up Himalaya for my Gmail account with an app password, and check that it lists my inbox.
Then add the account to Memo's config and import the last 30 days of mail.
```

### Добавьте аккаунт в Memo

Укажите имя аккаунта Himalaya и его настроенный адрес явно:

```sh
memo mail add work you@example.com
memo mail check work
```

`add` запрашивает список аккаунтов Himalaya, сверяет `email` (или `from`) выбранного аккаунта в TOML-файле,
затем добавляет его в [настройки](./configuration.md#mail) Memo. Аккаунт Himalaya по умолчанию не выбирается.
Без имени команда перечисляет доступные имена и ничего не меняет. Несовпадающий адрес или уже существующее
имя/адрес отклоняются. Если `email` не задан, сначала укажите его у выбранного аккаунта в Himalaya.
`check` повторяет локальные проверки настроек без изменений Memo и без подключения к ящику; это не проверка входа.

Для другого провайдера IMAP выберите вид и папки:

```sh
memo mail add home me@example.org --kind imap --folder INBOX --folder Archive
```

По умолчанию используется Gmail. Эти команды работают с одним файлом настроек Himalaya, выбранным через
`HIMALAYA_CONFIG` или обычное расположение. Сохраняйте то же окружение при импорте. Объединённый список файлов
требует ручной настройки. Google Takeout `mbox` по-прежнему использует настройку `mode: "mbox"`, описанную ниже.

### Синхронизация почты

```sh
memo sync --source email:work --since-time 2026-09-01
```

`work` — это `name` аккаунта в настройках; можно указать и адрес. Несколько аккаунтов разделяйте запятыми. Без `--source` Memo читает все настроенные аккаунты и называет каждый в отчёте. При неверном имени показывает известные аккаунты.

- Без `--since-time` Memo читает последние 30 дней. Можно указать дату, время ISO 8601 или `30d` назад.
- Каждый запуск читает до 200 новых писем на аккаунт (лимит меняет `--limit`). Повторный запуск продолжает с места остановки: перечисляется только почта, не завершённая предыдущими запусками, без повторного обхода большого ящика.
- Полный обход отмечает удалённую у источника почту и обновляет ярлыки и состояние прочтения. Он выполняется не реже раза в день, после изменения правил и с `--rescan`; окно меньше 5000 писем обходится целиком каждый раз.
- `memo sync` и таймер читают все аккаунты из настроек.

Чтобы узнать, как далеко продвинулась синхронизация ящика через `mail`, запустите `mail <profile> status`. У импорта
через Himalaya сейчас нет команды состояния.

## Выбор почты для импорта

Это работает с аккаунтом импорта через Himalaya.

В большом ящике много рассылок и уведомлений. Перед первым большим импортом проверьте состав:

```sh
memo mail inspect work
```

Команда читает только заголовки (около 1 КБ на письмо) и группирует почту по отправителю и рассылке: число писем, объём, доля непрочитанного и массовых рассылок, годы и писали ли вы отправителю. Для групп от 20 писем, где не менее 80% — массовая почта и вы не писали отправителю, предлагается `skip`.

Каждая группа также получает **оценку** сходства со спамом, мошенничеством или роботом и список составляющих признаков. Gmail уже фильтрует большую часть спама, поэтому высокая оценка обычно указывает на поддельного отправителя или робота, ещё не охваченного правилом:

| Признак | Баллы | Основание |
|---|---:|---|
| `spam_folder` | 4 | Большая часть писем группы в папке Спам Gmail |
| `dmarc_fail` | 3 | Проверка DMARC в Gmail не прошла (`Authentication-Results: mx.google.com`), без действительной подписи DKIM, у отправителя без успешных проверок DMARC, у письма от 2022 года или новее; учитывается только вместе с другим признаком мошенничества |
| `brand_spoof` | 3 | Бренд в имени отправителя, например PayPal или Apple, с другого домена |
| `young_domain` | 5 | Домену отправителя было меньше 180 дней при первом письме |
| `reply_to_elsewhere` | 1 | Ответы направляются на другой домен |
| `never_opened` | 2 | Вы не открыли ни одного письма группы |
| `dkim_not_passed` | 2 | Проверка DKIM в Gmail не прошла для большинства писем группы |
| `disposable_domain` | 2 | Домен одноразовой почты |
| `bulk_never_replied` | 1 | Не менее 80% массовой почты; вы не писали отправителю |
| `replied` | −5 | Вы писали отправителю |

`brand_spoof`, `young_domain`, `disposable_domain` и `dmarc_fail` указывают на поддельного отправителя или мошенника. Одна только неудачная проверка DMARC чаще означает настоящего отправителя с ошибкой в настройках или письмо, пришедшее через пересылку или рассылку. Остальные признаки часто встречаются в обычной массовой почте, в том числе в счетах и бронированиях: оценка 3 только от `never_opened` и `bulk_never_replied` — это рассылка, которую вы не читаете, а не мошенничество, и многие компании отвечают с домена службы поддержки. Платформа, которая передаёт письма от чужого имени, не подделка: «Google via LinkedIn» с домена LinkedIn, курс Coursera или пространство Quora с названием компании. Неудачные проверки DMARC до 2022 года не учитываются: тогда их не проходили многие настоящие отправители.

Для `young_domain` нужна дата регистрации домена. Каждая синхронизация, которая оценивает отправителей, не чаще раза в день запрашивает недостающие даты для отправителей, которым вы не писали и от которых были письма за последние два года: домен более старого отправителя мог истечь или сменить владельца. `memo mail inspect work --domain-age` запрашивает даты для показанных групп. Домен, заново зарегистрированный после письма, для этого письма не считается молодым.

memo обращается через RDAP к реестру самого домена по списку IANA, не чаще одного домена в секунду, и сохраняет ответ на компьютере бессрочно. **Каждый запрос сообщает реестру имя домена**: реестр узнаёт, что кто-то проверяет почту с него. Крупные почтовые сервисы вроде gmail.com не запрашиваются. У большинства национальных доменов, включая .ru, .de, .es и .io, нет RDAP: возраст остаётся неизвестным и баллов не добавляет.

Решение принимаете вы:

```sh
memo mail rules add work --domain shop.example --do envelope --reason 'newsletters'
memo mail rules add work --domain spam.example --do skip
memo mail rules add work --sender orders@shop.example --do keep
memo mail rules list work
```

Основные действия `--do` перечислены ниже; защита и теги описаны в следующем разделе:

- `skip`: `memo sync` не читает и не сохраняет письмо, учитывая его как пропущенное.
- `envelope`: `memo sync` сохраняет отправителя, дату, размер, ярлыки и id Gmail, без текста и вложений. Тема сохраняется в метаданных, поэтому письмо не попадает в результаты поиска. `memo mail rules list` показывает число и объём писем каждого правила, позволяя оценить очистку. Конверт не требует от Gmail больше данных, чем пропуск: поля уже есть в списке.
- `keep`: импортирует письмо, даже если оно подходит под правило пропуска или конверта.

Сохранение важнее конверта, конверт — пропуска. После удаления правила конверта или замены его на сохранение следующая синхронизация прочитает эти письма целиком. Почта, сохранённая до правила, не меняется.

### Дополнительные условия, теги и защита

Помимо `--sender`, `--domain` и `--list-id`, правило принимает запрос `--filter` и `--kind`.
Все заданные условия должны выполняться:

| В `--filter` | Какие письма подходят |
|---|---|
| `from:<address>`, `from:<domain>` | от одного отправителя либо из домена и его поддоменов |
| `from:<word>` | адрес или отображаемое имя отправителя содержит слово без учёта регистра |
| `to:<address>` | адрес есть в To или Cc |
| `subject:<word>` или отдельное слово | тема содержит каждое такое слово без учёта регистра |
| `older:<n>d` | получены более n дней назад |
| `larger:<size>` | размер у источника больше `5MB`, `300KB` или числа байтов |
| `has:attachment` | отправлены как `multipart/mixed`: предположение о вложениях по заголовку |
| `label:<name>` | с ярлыком Gmail, например `label:Promotions` или `label:"Two words"` |
| `is:unread` | ни разу не открывались |
| `is:bulk` | массовые: есть List-Id, List-Unsubscribe или `Precedence: bulk` |
| `score:<n>` | оценка отправителя из таблицы выше не меньше n |

`--do` принимает одно действие и любое число тегов через запятую: `skip`, `envelope`, `keep` или
`protect`, а также `tag:<name>`.

```sh
memo mail rules add work --filter 'label:Promotions older:365d' --do envelope
memo mail rules add work --domain shop.example --do keep,tag:shopping
memo mail rules add work --domain tax.gov.example --do protect
memo mail rules list work protected:true
```

- **`tag:<name>`** ставит тег Memo каждому подходящему письму независимо от правила, определяющего действие.
  Синхронизация помечает сохраняемые письма или конверты; `memo mail rules apply` — уже сохранённую почту.
  Если хранилище отклоняет тег из-за слишком похожей существующей метки, используется та метка и правило
  обновляется (`tags_reused` в `--json`). Если заменить тег нечем, он пропускается, письмо сохраняется,
  а список правил показывает `tags skipped` (`tags_skipped`). Отклонённый тег не останавливает синхронизацию.
- **`protect`** сохраняет письмо целиком и исключает из любой очистки независимо от других правил и видов почты.
  Защищённое правило важнее остальных: `memo mail rules apply` не сокращает его письма, а последующая очистка
  ящика должна отказываться их менять. Подходит для государственной, налоговой и банковской почты.
  `memo mail rules list` показывает защищённые правила первыми с отметкой `PROTECTED`.
- **`score:` и `--kind`** оценивают отправителя по почте текущего списка: если синхронизация перечисляет только
  новые письма, оценка строится по ним.

### Виды почты

`--kind` выбирает встроенный вид почты по отправителю и способу отправки, а не по вашему списку отправителей:

| Вид | Что подходит |
|---|---|
| `social` | уведомления социальных сетей |
| `newsletters` | рассылки с List-Id и List-Unsubscribe и сервисы рассылок |
| `developer` | уведомления хостинга кода, CI, пакетов и систем ошибок |
| `shopping` | магазины и почта, которую Gmail относит к Promotions |
| `alerts` | уведомления мониторинга и доступности |

В конце `memo mail inspect` показывает, сколько почты подходит каждому виду. До добавления правила ничего не применяется:

```sh
memo mail rules add work --kind social --do envelope
```

Почта от человека, которому вы писали, никогда не подходит виду; явное правило важнее правила `--kind`.

### Фильтры Gmail

Экспорт Mail из Google Takeout содержит фильтры Gmail в `Mail/User settings/Filters.json`.
Memo предлагает правило для каждого фильтра, который может выразить:

```sh
memo mail rules import work Filters.json --format gmail        # shows the proposed rules and the skipped filters
memo mail rules import work Filters.json --format gmail --yes  # adds them
```

Сначала добавляемые фильтром ярлыки Gmail сопоставляются с метками Memo: то же имя в другом регистре
используется повторно, а похожая метка предлагается вместо новой. План показывает замены как `label … → …`.

Фильтр, пропускающий входящие, отмечающий прочтение или удаляющий, становится правилом конверта;
добавляющий только ярлык — правилом сохранения с тегом. Несколько отправителей или получателей
(`from:a from:b`, `from:(a OR b)`) превращаются в отдельные правила: одно письмо не может прийти от обоих.
Слова фильтра становятся словами темы: Gmail искал во всём письме, Memo — только в теме; это указано
в причине правила. Фильтры с исключением слов или неподдерживаемыми полями (`list:`, `size:`) пропускаются
и перечисляются. Читаются Takeout `{"filter": [{query, labelsToAdd, labelsToRemove}]}`, форма Gmail API
(`criteria` и `action`) и плоские свойства экспорта настроек (`from`, `shouldArchive`, `label`).
Если ярлык задан только ID Gmail, этот ID используется как тег.

Письма, сохранённые целиком до правила конверта, остаются полными до явного сокращения:

```sh
memo mail rules apply work        # says how many emails and how much text each rule would cut
memo mail rules apply work --yes  # cuts them to envelopes
```

Команда читает заголовки аккаунта из ящика, как `memo sync`: у писем, сохранённых до поддержки List-Id, этого поля нет. У подходящего письма удаляются текст, вложения и поисковые записи; отправитель, дата, размер, ярлыки и тема остаются в метаданных. Письма, подходящие только под пропуск, не меняются. Ящик не изменяется; после смены правила на сохранение следующая синхронизация снова прочитает письма целиком.

Правила находятся в локальном хранилище рядом с почтой; `memo mail rules list` считает письма каждого правила одним запросом. Каждый конверт помнит правило, по которому сохранён. Для проверки, резервной копии или переноса правил:

```sh
memo mail rules export work > rules.json
memo mail rules import work rules.json   # a rule with the same sender, domain or list is replaced
```

Прежние настройки содержали правила в `config.json`. Первая команда memo, читающая правила, переносит их в хранилище, проверяет перенос и лишь затем убирает из настроек. Рядом остаётся прежний файл `config.json.<time>.before-rules-in-store`, доступный только вам; memo один раз сообщает об этом в stderr. Правило сохранения с причиной «never remove» становится защищённым: очистка не может сокращать или удалять подходящую почту.

## Очистите Gmail

Это работает с аккаунтом импорта через Himalaya. Это единственное место, где Memo изменяет ящик: он перемещает письма
в корзину Gmail, а Gmail окончательно удаляет корзину через 30 дней.

`memo mail delete` перемещает в корзину Gmail письма, для которых вы решили сохранять только заголовки. Gmail хранит их там 30 дней, затем удаляет окончательно.

```sh
memo mail delete work                  # says what would move, per rule, and what stays and why
memo mail delete work --yes            # a first run moves at most 100, to check by hand in Gmail's Trash
memo mail delete work --yes            # later runs move up to 5,000, oldest first (--limit changes it)
memo mail delete work --yes --since-time 2012-01-01   # only mail from 2012 on; older mail stays for now
memo mail runs list work                   # each run: how much moved, and until when it can be restored
memo mail restore work --run <id> --yes   # moves a run back, to the inbox if it was there, with its labels
```

Команда заново проверяет каждое письмо по текущим правилам и данным последней синхронизации. Перед перемещением она читает в Gmail актуальные ярлыки и отметки только выбранных писем. Письмо остаётся, если подходит правило защиты или сохранения, вы когда-либо отвечали отправителю, письмо отмечено звездой или как важное, отправлено вами, является черновиком, имеет ваш ярлык, который правило не добавляет, либо ему меньше 30 дней. `--since-time` оставляет более старую почту на месте.

Без `--yes` команда показывает план. Первый запуск с `--yes` перемещает не более 100 писем для проверки в корзине Gmail; следующие — до 5 000, начиная со старых, если не задан другой `--limit`. Требуется проверенная резервная копия хранилища моложе 8 дней: скрипт резервного копирования записывает `backups/last.json` рядом с хранилищем. Экспорт Google Takeout `mbox` рекомендуется для сохранения полного текста, но не обязателен; предварительный просмотр и `memo doctor` показывают, импортирован ли он.

Перед каждой порцией идентификаторы Gmail, ярлыки и отметки записываются в журнал восстановления `mail-trash/<account>/<run>.jsonl` в папке состояния Memo. Корзина убирает письмо из «Вся почта» и снимает ярлык входящих; остальные ярлыки сохраняются. memo mail runs list показывает запуски и срок восстановления. memo mail restore без `--yes` показывает план, а с ним возвращает письма выбранного запуска из корзины с прежними ярлыками, включая входящие, если они там были. Восстановление охватывает и порцию, которую Gmail переместил без подтверждения.

Перемещённое письмо отмечается удалённым в хранилище; после восстановления следующая синхронизация загружает его по текущим правилам. Таймер очистку не запускает.

## Старая почта из Google Takeout

Gmail ограничивает дневную загрузку через IMAP; многолетнюю почту быстрее загрузить из экспорта Mail в [Google Takeout](https://takeout.google.com/). Добавьте файл вторым аккаунтом с тем же адресом, чтобы его письма и письма Gmail были одним набором:

```json
{ "name": "archive", "address": "you@example.com", "mode": "mbox", "path": "~/Takeout/Mail/All mail Including Spam and Trash.mbox" }
```

```sh
memo sync --source email:archive --since-time 2000-01-01 --limit 5000
```

Файл читается, только если указать этот аккаунт. Незавершённый импорт сканирует его снова; завершённый снимок пропускается, пока не изменятся размер или время изменения файла. `--rescan` запускает новое сканирование. Импорт только добавляет почту: отсутствующие в файле письма не удаляются из хранилища, Спам и Корзина пропускаются.

## Найдите свою почту

```sh
memo search mail 'invoice'
memo search mail 'from:kai subject:budget'
memo search mail 'mailbox:starred' --source email:work
memo search mail 'trip NOT mailbox:bulk'
memo search all 'budget'
```

Массовая почта — рассылки, уведомления и письма с List-Id, List-Unsubscribe или `Precedence: bulk` — попадает в папку `bulk` (`memo:bulk`). Условие `NOT mailbox:bulk` убирает её из поиска. По умолчанию она остаётся: счета и бронирования используют те же заголовки. Memo помечает такую почту при чтении заголовков аккаунта с правилами; полный обход, не реже раза в день, помечает уже сохранённые письма. `--source email:<account>` принимает имя аккаунта или адрес; `--source email:work,email:personal` ищет в обоих.

Каждый sync также оценивает всех отправителей по уже сохранённой почте, не чаще раза в день, так же, как `memo mail inspect` оценивает группу. Результат поиска от оценённого отправителя содержит `sender_score` в `--json` с оценкой и её признаками. Письма от отправителя, у которого признаки мошенничества в сумме дают 3 или больше, идут после остальных результатов страницы в `memo search mail` и `memo search all`, а его `sender_score` содержит `demoted: true`; ничего не убирается. Свои отправители никогда не сдвигаются: домен, на адреса которого вы хоть раз писали, домен вашего ящика и отправитель, которого сохраняет правило защиты. `--plain-order` оставляет такие письма там, где их ставят слова запроса, чтобы их найти:

```sh
memo search mail 'invoice' --plain-order
```

Ярлыки Gmail, например «Входящие», «Важные», «Помеченные» и ваши собственные ярлыки, становятся
почтовыми папками, поэтому `mailbox:important` находит такие письма. См. [Поиск](./search.md#search-mail).

`memo messages show <msg:email/…>` показывает письмо целиком. Для почты из импорта через Himalaya он добавляет извлечённый текст каждого вложения, например PDF-счёта: первые 4 000 символов, либо весь текст с `--full`. Если текста нет, выводится причина, например `needs-agent` для сканированной страницы. У почты, синхронизированной через `mail`, текста вложений нет.

## Что сохраняется

Этот список относится к импорту через Himalaya. Почта, синхронизированная через `mail`, сохраняет только текст и
заголовки: без вложений, а значит и без текста вложений.

- Отправитель, получатели (To, CC и BCC), тема, дата и текст каждого письма.
- Прочитано ли письмо и помечено ли оно звёздочкой — так, как это показывает ваш почтовый ящик.
- Для импорта через Himalaya: текст вложений, которые можно прочитать. Он ищется вместе с письмом ([файлы, которые читает Memo](./notes.md#files-memo-can-read)).
  Модули чтения PDF и Word поставляются с Memo. Если вложение осталось непрочитанным из-за отсутствующего модуля
  (`engine-missing`, в старом Memo или при повреждённой установке), `memo sync --source email:work --retry-attachments`
  повторно читает по id Gmail только такие письма, до `--limit` писем. Список ящика не запрашивается, поэтому это
  быстро; повторный запуск продолжает оставшиеся.
- До 1 000 000 символов каждого письма и до 200 000 символов каждого вложения
  ([как изменить ограничения](./configuration.md#mail)).

Почта готовится к поиску по смыслу, если модель поиска есть на вашем компьютере; `--no-embed`
пропускает этот шаг.

## Если письмо удалено

Если вы удалите письмо в почтовом ящике, его текст исчезнет из локального хранилища при следующем
импорте через Himalaya. Письма, перемещённые в спам, считаются удалёнными. Чтобы защитить вас от ошибок:

- первые два дня периода не проверяются на удаление;
- если при запуске окажется, что пропала необычно большая часть почты, Memo ничего не удаляет и сообщает
  вам об этом.

## Телефоны и ссылки в почте

Memo находит телефоны, адреса электронной почты, ссылки, имена и почтовые адреса в каждом сохранённом письме, заметке и документе. Посмотрите их список и укажите, что это:

```sh
memo mentions list kind:phone --source email:personal
memo mentions show 40 --source email:personal
memo mentions confirm 40 person:7 --source email:personal
memo mentions reject 41 --source email:personal
```

`--source` указывает, что читать, одинаково во всех инструментах WireCat: `email:personal` — один ящик, `email:personal,email:work` — несколько, `mail` — все ящики (ответ перечисляет, какие), `notes` — заметки memo, `documents` — импортированные документы, `group:<name>` — сохранённая группа. `show` перечисляет отправителей, которым может принадлежать телефон, но ничего не связывает, пока вы не подтвердите.
