title: "Настройки"
---

Используйте этот справочник, чтобы найти собственные настройки и переменные окружения Memo.
Редактировать файл вручную приходится редко.
`memo folders add` добавляет папку, а `memo jobs start` включает таймер за вас. Вручную задаются
файлы, которые нужно пропускать, и место для экспортированных заметок.

Файл находится здесь: `~/.config/cli-memo/config.json`. Это файл JSON: сохраняйте кавычки, запятые и
фигурные скобки так, как в примере.

`memo config show` перечисляет каждую настройку с её значением, значением по умолчанию и тем, задаёт ли её файл. `memo config
migrate` записывает каждую настройку, которой нет в файле, с её значением по умолчанию, чтобы вы видели и правили их все в файле.
Ваши значения, их порядок и ключи, которых memo не знает, остаются как есть. `notes.embed` добавляется, только если в
файле уже есть `notes`. Любая запись memo в файл, например `memo folders add`, тоже добавляет их.

Файл с проблемой останавливает все команды, кроме `memo doctor` и `memo config unset`. Отказ называет первую
проблему и команду, которая её убирает; `memo doctor` перечисляет все, у каждой — её строка или её `memo config unset
<key>`. `config unset` удаляет настройку по пути через точку, в том числе ту, которую Memo не знает, например
`memo config unset notes.colour` или `memo config unset permissions.notes.edit`. Файл, который не является
корректным JSON, исправляется вручную в строке и столбце, которые называет `memo doctor`.

```json
{
  "notes": {
    "folders": [{ "id": "1", "path": "/path/to/vault", "format": "obsidian" }],
    "ignore": ["Journal/Private.md", "Archive", "**/Private*"],
    "embed": true,
    "export": { "dir": "/path/to/vault/memo", "format": "obsidian" }
  },
  "auto": { "enabled": true, "every": "5m" }
}
```

## `notes`

| Ключ | Значение |
|---|---|
| `folders` | Ваши папки с заметками. У каждой есть `id`, который ей присвоило локальное хранилище, `path` на этом компьютере и `format`: `obsidian` (по умолчанию) или `markdown`. `memo folders add` добавляет запись; запись без `id` импорт отклоняет. См. [Markdown или Obsidian](./notes.md#markdown-or-obsidian). |
| `ignore` | Файлы и папки, которые импорт пропускает: путь внутри папки, папка или шаблон, например `**/Private*`. `--ignore` добавляет правила на один запуск. |
| `embed` | `false` исключает заметки из поиска по смыслу. |
| `export` | `dir` и `format` для `memo notes export` и `--export`, когда вы не указываете папку. |

`id` папки одинаковый на всех компьютерах, а `path` на каждом свой. См.
[одни и те же заметки на другом компьютере](./notes.md#use-the-same-notes-on-another-computer).

## `mail`

Больше не используется. Memo больше не импортирует почту: CLI [mail](./mail.md#bring-mail-in-with-mail) синхронизирует каждый
почтовый ящик в общее хранилище со своими собственными настройками. Старый конфиг, в котором ещё есть `mail`, загружается,
но этот раздел никто не читает. `memo doctor` называет почтовые ящики, перечисленные в нём, а `memo config unset mail` удаляет его.

## `auto`

| Ключ | Значение |
|---|---|
| `enabled` | `true`, если таймер импорта включён. |
| `every` | Частота: `90s`, `5m`, `1h`; интервал не меньше минуты. |
| `places` | Переменные путей memo и хранилища (`MEMO_CONFIG_DIR`, `MESSAGING_STORE`…), сохранённые при `memo jobs start`; передаются каждому запуску таймера. |

`memo jobs start` и `memo jobs stop` записывают эти значения. Если вы измените их вручную, таймер учтёт
это при следующем запуске. См. [импорт по таймеру](./archive.md#import-on-a-timer-linux).

## `sources`

```json
"sources": { "reader": "ollama", "model": "llama3.2:latest" }
```

Читатель, которому `memo sources suggest` отправляет текст источника, и его модель. `memo sources readers set <reader>
[--model <model>]` записывает оба значения. Если не задано ни одно, `sources suggest` отказывает. Claude Code и Codex
используют свою модель, когда `model` не задан, а Ollama и читателям API модель нужна.
[Читатель предлагает факты](./sources.md#have-a-reader-propose-facts) перечисляет читателей.

## `update_check`

`false` отключает ежедневную проверку новой версии memo. `MEMO_NO_UPDATE_CHECK=1` делает то же для одной оболочки.

## `record`, `record_input` и `keep_runs_for_days`

Memo сохраняет запись запуска каждой команды: команду в том виде, как вы её ввели, как она закончилась, а также
запросы, которые она сделала, с их временем и кодами ответа.
Секрет в команде (параметр с именем токена, пароля или ключа API, пароль в URL, длинная непрозрачная строка) и номер телефона записываются как `[redacted]`.
То, что команда прочитала или записала, не сохраняется никогда: ни заметка, ни текст письма, ни имя папки, до которых она добралась.
`memo runs list` показывает записи, `memo runs show <run-id>` — одну из них.

| Ключ | Значение |
|---|---|
| `record` | `false` сохраняет только неудачные запуски. Если не задан или `true`: каждый запуск. `--record` всё равно сохраняет запись одной команды, `--no-record` не сохраняет для неё ничего. `memo mcp serve` и другие команды, которые работают до остановки, сохраняют успешный запуск только с `--record`. |
| `record_input` | `false` записывает каждое введённое значение, которое может быть содержимым, как `[redacted]` и оставляет только слова команды, имена параметров, числа, даты и варианты выбора. `"failed"` делает это в успешном запуске, а в неудачном оставляет слова. По умолчанию `true`: команда сохраняется как введена, секреты скрыты. |
| `keep_runs_for_days` | Сколько дней хранится неудачный запуск. По умолчанию 30. |
| `keep_successful_runs_for_days` | Сколько дней хранится успешный запуск. По умолчанию 7. |
| `runs_size_limit_mb` | Сколько самое большее может занимать папка запусков; первыми удаляются самые старые успешные запуски. По умолчанию 200. |

Меняйте ключи в `config.json` вручную (`memo config migrate` записывает их в файл); `memo config unset <key>` удаляет один из них.

## `agent_decisions`

По умолчанию подтверждаете или отклоняете предложение (факт, запись памяти, действие,
[предложение проекта](./recipes.md#review-project-facts-and-follow-ups)) только вы. Попытку агента Memo отклоняет.
Установите верхнеуровневый ключ `agent_decisions` в `true`, чтобы агент мог решать за вас и записывал причину
решения. Предложение, которое внёс его собственный бот, он не решает никогда:

```json
{
  "agent_decisions": true
}
```

У выводов встреч свои разрешения, что бы ни говорил этот ключ.

Добавьте ключ в существующий конфиг, не заменяя настройки заметок и таймера этим коротким
примером. Если ключа нет или он равен `false`, CLI и MCP отклоняют каждое решение агента. Чтение и подготовка предложений работают.
Решения владельца по-прежнему доступны в терминале. В терминале агента `--as-owner` спрашивает y/N в терминале,
прежде чем решение будет засчитано как ваше. Настройка не меняет отдельное разрешение на подтверждение выводов
встречи и не заменяет другие проверки разрешений инструмента.

## Переменные окружения

| Переменная | Значение |
|---|---|
| `MEMO_CONFIG_DIR` | Папка, в которой лежит `config.json`. |
| `MEMO_STATE_DIR` | Папка состояния Memo: как выглядела каждая папка при последнем импорте. |
| `MEMO_MODELS_ANALYSIS_PROVIDER`, `MEMO_MODELS_ANALYSIS_MODEL` | Провайдер ИИ и идентификатор модели (имя, под которым её знает провайдер), к которым обращается `memo answers create --analyze`. |
| `MEMO_MODELS_ANALYSIS_BASE_URL` | Необязательно: адрес провайдера. |
| `MEMO_MODEL_API_KEY` | Ключ провайдера. |
| `MEMO_READ_ONLY` | Любое значение, кроме `0`, отклоняет каждое изменение с `permission_error` (код выхода 5): запись в хранилище, в ваши файлы, в почту у провайдера, в таймер, в файлы навыка, `upgrade` и `answers create --allow-remote`. Чтение, `memo sync`, `tasks link` по-прежнему работают (связь только предлагается, а связывание двух задач запрещено); `reminders claim` запрещён; `memo mcp serve` помечает команды записи как недоступные. |

Memo обращается к провайдеру за пределами вашего компьютера, только когда у `memo answers create` указаны и
`--analyze`, и `--allow-remote`. См. [передайте агенту источники](./search.md#give-your-agent-the-sources).

## `permissions`

Пути команд через точку ограничивают инструменты MCP. Ключ действует на команду и её подкоманды;
побеждает самый конкретный сохранённый ключ. `deny` помечает команды как недоступные, `readonly` разрешает чтение,
`ask` и `allow` разрешают запись. Через MCP `ask` выполняется без вопроса в терминале: запросы согласия определяет
клиентское приложение. Если уровень не сохранён, для записи используется `ask`.

```json
{
  "permissions": {
    "notes": "readonly",
    "mail.delete": "deny",
    "mcp.authority": "deny"
  }
}
```

`mcp.authority` по умолчанию имеет `deny` для изменения папок-источников.
`meetings.actions.confirm`, `meetings.actions.reject`, `messages.reset` и `projects.annotations.restore` тоже имеют `deny`;
явно задайте нужному ключу `ask` или `allow`, чтобы делегировать операцию владельца.
Пока `agent_decisions` не равен `true`, решения по предложениям проекта запрещены. Общий предел WireCat
«только чтение» и `MEMO_READ_ONLY` ограничивают любое разрешение.

`search all` показывает агенту бизнес-данные только в пределах разрешённых списков. С `"invoices": "deny"` (или
`invoices.list`, `payments.list`, `orders.list`) он не выводит эти результаты и сообщает об этом в поле issues ответа.
`business.list`, ключ, который не называет никакой команды, со значением `deny` убирает их все: счета, платежи,
заказы, договоры, подписки, товары и кошельки.
Сделки и лиды так же следуют `deals.list` и `leads.list`, а `crm.list` со значением `deny` убирает весь раздел CRM.
`events.list` со значением `deny` отклоняет `memo events list` и убирает события календаря и телефонные звонки из
`search all`.

`memo show` отклоняет ссылку, если ключ запрещает её собственную команду. С `"invoices": "deny"` (или `invoices.show`)
`memo show invoice:4` от агента даёт `permission_error`, так же как `memo invoices show invoice:4`. То же верно для
заметок, людей (`context`), организаций, проектов, задач, фактов, записей памяти, сообщений, платежей, заказов, сделок,
лидов, воронок, товаров, договоров, подписок, кошельков, операций и событий (`events.show`).

Изменённые разрешения действуют при следующем поиске команд и вызове, в том числе в открытых соединениях.
`memo mcp serve --permission notes.edit=deny` ужесточает один ключ для сервера без изменения файла;
переопределение, ослабляющее сохранённый ключ, отклоняется.
