Asterisk пишет строку о каждом звонке в журнал звонков и хранит аудиозапись разговора как звуковой файл. Но ИИ-агенту
он их прочитать не даёт. Сервисы, которые превращают аудиозаписи в текст, обычно отправляют их в облако. `pbx` —
инструмент командной строки WireCat. Он читает журнал и аудиозаписи там, где их хранит Asterisk, и ничего не меняет
на АТС. Текст из аудиозаписей он делает на вашем компьютере. Облачную расшифровку вы включаете сами, для каждого
профиля отдельно. Профиль — это имя, которое вы даёте подключению к одной АТС.

После подключения спросите агента, кто звонил по заказу на прошлой неделе и о чём договорились. Вы найдёте все
звонки с одного номера. Вы увидите звонки человека рядом с его перепиской, почтой и карточкой в CRM.

`pbx` хранит каждый звонок в локальном хранилище WireCat на вашем компьютере. Там звонок находит поиск любого
инструмента WireCat, вместе с остальными вашими данными. Там же его находит Memo: через него агент спрашивает об одном
человеке сразу по звонкам, переписке и почте. Подключите `pbx` один раз к каждой АТС. Ему нужен доступ на
чтение к журналу звонков: к файлу или к базе данных под пользователем, которому можно только читать. Если нужен текст
звонков, ему нужен ещё доступ к папке с аудиозаписями. WireCat Desktop ставит `pbx` сам и подключает его через
форму. В терминале хватит нескольких команд.

<a id="how-asterisk-keeps-calls"></a>

## Как Asterisk хранит звонки

Asterisk — это АТС: через неё работают телефонные номера компании и телефоны сотрудников. FreePBX, Issabel и VitalPBX
— это Asterisk с веб-панелью для администратора. Звонки они хранят так же.

- **Внутренние номера.** У телефона каждого сотрудника есть короткий внутренний номер, например `101`. Группа вызова
  (`600`) звонит на несколько телефонов сразу. Очередь (`700`) держит звонящего на линии, пока кто-то не освободится.
- **Записи о звонках (CDR).** Когда звонок заканчивается, Asterisk пишет о нём запись: кто кому звонил, когда, сколько
  длился разговор и ответил ли кто-нибудь. Такие записи называют CDR (call detail records). Они попадают в файл
  `Master.csv`, в таблицу базы данных или в оба места. FreePBX хранит их в своей базе MySQL `asteriskcdrdb`.
- **Один звонок, несколько записей.** Группа вызова пишет по записи о звонке на каждый телефон, на который звонила.
  Перевод звонка пишет по записи на каждую его часть. `pbx` собирает их обратно в один звонок и пишет, чем он
  закончился: ответили, голосовая почта, занято или не ответили. Ещё он пишет, кто ответил, сколько звонящий ждал и
  сколько говорил.
- **Аудиозаписи.** Когда запись разговоров включена, Asterisk сохраняет по звуковому файлу на звонок, обычно в
  `/var/spool/asterisk/monitor`. `pbx` находит файл каждого звонка по имени и связывает его со звонком. Сам файл он
  никогда не копирует, не перемещает и не меняет.

`pbx` только читает. Вам не нужно менять dialplan (правила, по которым АТС ведёт звонки). Не нужен аккаунт Asterisk
Manager Interface (AMI) или REST Interface (ARI): через эти интерфейсы программы управляют Asterisk. На АТС ничего не
ставится.

<a id="what-you-need"></a>

## Что нужно

- **Asterisk 1.8 или новее** либо система на его основе: FreePBX, Issabel, VitalPBX. Поля записей о звонках — из
  [спецификации CDR](https://docs.asterisk.org/Configuration/Reporting/Call-Detail-Records-CDR/CDR-Specification/).
- **Записи о звонках**, которые можно прочитать с компьютера, где работает `pbx`:

  | У вас | Где записи о звонках | Что нужно |
  |---|---|---|
  | Обычный Asterisk, включён `cdr_csv` | `Master.csv`, обычно `/var/log/asterisk/cdr-csv/Master.csv` | доступ на чтение к файлу |
  | FreePBX, Issabel, VitalPBX | MySQL или MariaDB (`cdr_mysql`, `cdr_adaptive_odbc`) | пользователь базы только для чтения |
  | Записи в PostgreSQL | PostgreSQL (`cdr_pgsql`) | пользователь базы только для чтения |

  Не уверены? Выполните на АТС `asterisk -rx "cdr show status"`. Команда покажет модули, которые пишут записи о
  звонках.
- **Аудиозаписи**, если нужен текст звонков. Подойдёт папка, которую видит этот компьютер, или папка, подключённая
  только для чтения. Ещё можно читать папку самой АТС по SFTP: так файлы читают через SSH, защищённый удалённый вход
  на сервер. `pbx` находит файлы WAV, wav49 (`.WAV`), GSM, MP3, Ogg, Opus, FLAC и M4A.

<a id="install"></a>

## Установка

WireCat Desktop ставит `pbx` сам. Переходите к разделу [Подключение в WireCat Desktop](#connect-in-wirecat-desktop).

В терминале поставьте `pbx` один раз на каждый компьютер, где с ним работаете вы или агент. Нужен Node.js 22.16 или
более новый 22.x, либо 24 и новее. Node 23 не поддерживается. Чтобы превращать в текст аудиозаписи WAV и GSM, нужна
ещё программа для работы со звуком `ffmpeg` в `PATH`.

```sh
npm install -g @wirecat/asterisk-cli
pbx --version
pbx doctor
```

Команда называется `pbx`, а `wcat-pbx` — тот же инструмент. Ни одно имя не совпадает с `asterisk`. Поэтому `pbx`
можно запускать и на самой АТС: он не заслонит собственную программу Asterisk. `pbx doctor` не ходит в сеть и не
открывает связку ключей (место, где система хранит пароли). Он показывает версию, папку с настройками и профили. Ещё
он показывает, могут ли настройки читать другие пользователи компьютера.

<a id="connect-in-wirecat-desktop"></a>

## Подключение в WireCat Desktop

1. На странице **Инструменты** нажмите **Установить** рядом с Asterisk, затем **Управление**.
2. В разделе **Аккаунты** добавьте аккаунт с именем для этой АТС, например `office`, и нажмите **Войти здесь**.
3. В вопросе **Где записи о звонках?** выберите **Файл Master.csv**, **MySQL или MariaDB** или **PostgreSQL**:
   - для **Файл Master.csv** укажите **Путь к Master.csv** на этом компьютере: копию файла или общую папку, где он
     лежит;
   - для базы заполните **Сервер базы данных**, **Имя базы**, **Пользователь** и **Пароль пользователя базы**.
     **Порт (необязательно)** оставьте пустым для обычного порта. Включите **Шифрованное соединение**, если база не в
     вашей собственной сети.
4. **Папка с записями (необязательно)** — папка с аудиозаписями звонков на этом компьютере. Звонки придут и без неё.
5. В разделе **Страны ваших телефонных линий** выберите страны. Форма объясняет: «Звонящих связывают с контактами по
   номеру телефона. Asterisk часто пишет номер без кода страны, поэтому выберите страны, которые обслуживают ваши
   линии. Звонки из других стран и так приходят с кодом через +.»
6. Начните вход. `pbx` прочитает звонки за последний час, чтобы проверить настройки, и ничего не изменит. Пароль
   базы сохраняется только после успешной проверки. Затем синхронизация загрузит звонки за последние 30 дней вместе с
   аудиозаписями.

Часовой пояс записей о звонках и имена файлов аудиозаписей — на странице **Настройки** аккаунта. Как превратить
аудиозаписи в текст, описано в разделе [Расшифровка](#transcribe).

<a id="connect-from-the-terminal"></a>

## Подключение из терминала

Профиль — это имя, которое вы даёте одной АТС, например `office`. Это первое слово каждой команды, которая читает
звонки этой АТС. Выберите, где лежат записи о звонках, и настройте профиль. Затем запустите `session start`. Команда
проверит настройки: прочитает последние звонки.

<a id="mastercsv"></a>

### Master.csv

```sh
pbx office config set cdr_csv_path /var/log/asterisk/cdr-csv/Master.csv
pbx office config set cdr_timezone Europe/Moscow
pbx office session start
```

У `Master.csv` нет строки с названиями столбцов. Какие в нём столбцы, зависит от `loguniqueid`, `loguserfield` и
`newcdrcolumns` в `cdr.conf` (раздел `[csv]`). `pbx` различает их по числу полей в каждой строке. Поэтому строки,
записанные после включения параметра, читаются рядом со старыми. Включите `loguniqueid` и `newcdrcolumns`, если
можете. Без `uniqueid` аудиозапись не найти по имени. Без `linkedid` и `sequence` записи одного звонка собираются
только по содержимому. Если `pbx` угадал столбцы неверно, назовите их сами:

```sh
pbx office config set cdr_csv_columns "accountcode,src,dst,dcontext,clid,channel,dstchannel,lastapp,lastdata,start,answer,end,duration,billsec,disposition,amaflags,uniqueid"
```

Время в `Master.csv` — местное время АТС, если не включено `usegmtime=yes`. Укажите в `cdr_timezone` часовой пояс
АТС. Если `usegmtime` включён, укажите `UTC`. Без этой настройки берётся часовой пояс этого компьютера.

Если `pbx` работает на другом компьютере, читайте `Master.csv` по [SFTP](#files-on-the-pbx-over-sftp). Ещё можно
подключить папку журнала только для чтения, например `sshfs pbx:/var/log/asterisk/cdr-csv ~/pbx-cdr -o ro`.

<a id="a-cdr-database"></a>

### База CDR

Создайте пользователя, который может только читать таблицу записей о звонках. В MySQL или MariaDB:

```sql
CREATE USER 'wirecat_reader'@'10.0.0.%' IDENTIFIED BY 'a long random password';
GRANT SELECT ON asteriskcdrdb.cdr TO 'wirecat_reader'@'10.0.0.%';
```

В PostgreSQL:

```sql
CREATE ROLE wirecat_reader LOGIN PASSWORD 'a long random password';
GRANT SELECT ON cdr TO wirecat_reader;
```

Затем настройте профиль и войдите. `pbx` спросит пароль, не показывая его на экране, и проверит его до того, как
сохранить:

```sh
pbx office config set cdr_source mysql
pbx office config set db_host 10.0.0.5
pbx office config set db_name asteriskcdrdb
pbx office config set db_user wirecat_reader
pbx office config set cdr_timezone Europe/Moscow
pbx office session start
```

`cdr_source postgres` читает PostgreSQL. `db_port` меняет порт (3306 для MySQL, 5432 для PostgreSQL), `db_table` —
таблицу (`cdr`). `db_tls true` включает шифрованное соединение с проверкой сертификата. Сеанс с базой открывается
только для чтения. Единственный запрос — `SELECT` записей о звонках, начавшихся после прошлой синхронизации,
страницами по 5000.

<a id="a-database-behind-the-phone-systems-ssh"></a>

### База за SSH самой АТС

База FreePBX слушает только на самой АТС. Не открывайте её в сеть. `pbx` подключается к ней через SSH-туннель: это
соединение с базой через SSH-вход АТС, то есть через её защищённый удалённый вход. `pbx` открывает туннель на каждую
команду и закрывает в конце. Туннель только передаёт данные к базе. Он не запускает команд на АТС и не открывает
портов на вашем компьютере.

На FreePBX создайте пользователя базы на самой АТС, как в разделе выше, но для `localhost`:

```sql
CREATE USER 'wirecat_reader'@'localhost' IDENTIFIED BY 'a long random password';
GRANT SELECT ON asteriskcdrdb.cdr TO 'wirecat_reader'@'localhost';
```

Затем укажите в `db_host` адрес базы так, как его видит сама АТС, и задайте SSH-сервер:

```sh
pbx office config set cdr_source mysql
pbx office config set db_host 127.0.0.1
pbx office config set db_name asteriskcdrdb
pbx office config set db_user wirecat_reader
pbx office config set db_ssh_host pbx.example.lan
pbx office config set db_ssh_user wirecat
pbx office config set db_ssh_key_path ~/.ssh/wirecat_pbx     # or leave it out to sign in with a password
pbx office session start
```

`db_ssh_port` меняет порт SSH (22). Пользователю SSH не нужна командная оболочка. Хватит аккаунта, которому можно
только пробросить порт. Первый `session start` подключается только до того места, где виден ключ SSH-сервера, и
останавливается. Он показывает отпечаток ключа (короткую строку, по которой узнают сервер) и команду, которая этот
ключ закрепляет (`config set db_ssh_host_key SHA256:…`). Перед этой командой сравните отпечаток с отпечатком самой
АТС. Его покажет `ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub`, если выполнить её на АТС.

Если файла ключа нет, `session start` спросит два пароля: сначала пароль пользователя базы, потом пароль
пользователя SSH. Если передаёте их через конвейер, пишите по одному в строке, в том же порядке:

```sh
printf '%s\n%s\n' "$DB_PASSWORD" "$SSH_PASSWORD" | pbx office session start
```

`pbx` проверит оба пароля: прочитает последние записи о звонках. Потом он сохранит их в одной записи связки ключей
для этого профиля.

<a id="recordings"></a>

### Аудиозаписи

```sh
pbx office config set recordings_path /var/spool/asterisk/monitor
```

Аудиозапись звонка ищется в таком порядке:

1. столбец `recordingfile` записи о звонке, который заполняет FreePBX, в папке даты `YYYY/MM/DD` или в самой папке;
   имя, которое ведёт за пределы `recordings_path`, не учитывается;
2. файл, в имени которого есть `uniqueid` звонка, сначала в `{yyyy}/{mm}/{dd}/`, затем в самой папке.

Если ваш dialplan называет файлы иначе, задайте свой шаблон с `{uniqueid}`, `{linkedid}`, `{yyyy}`, `{mm}`, `{dd}`
и `*`:

```sh
pbx office config set recordings_pattern "calls/{yyyy}-{mm}-{dd}/*{linkedid}*"
```

Файл, изменённый за последние две минуты, может ещё записываться. Поэтому он ждёт следующей синхронизации. Звонок без
аудиозаписи загружается всё равно. Если папка на АТС, читайте её по [SFTP](#files-on-the-pbx-over-sftp). Ещё можно
подключить её только для чтения, например `sshfs pbx:/var/spool/asterisk/monitor ~/pbx-monitor -o ro`, и указать эту
папку в `recordings_path`.

<a id="files-on-the-pbx-over-sftp"></a>

### Файлы на АТС по SFTP

`files_from sftp` читает `Master.csv` и аудиозаписи на самой АТС через её SSH-сервер. Ничего не копируется в
отдельную папку, и ничего не пишется на АТС. Создайте пользователя, который может только читать эти папки, например в
группе `pbx`. Затем настройте профиль:

```sh
pbx office config set files_from sftp
pbx office config set sftp_host pbx.example.lan
pbx office config set sftp_user wirecat
pbx office config set sftp_key_path ~/.ssh/wirecat_pbx      # or leave it out to sign in with a password
pbx office session start
```

Первый `session start` подключается только до того места, где виден ключ сервера, и останавливается. Он показывает
отпечаток ключа и команду, которая ключ закрепляет. Сравните отпечаток с отпечатком самой АТС. Его покажет
`ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub`, если выполнить её на АТС. Только потом выполните эту команду
(`config set sftp_host_key SHA256:…`). `pbx` не отправляет пароль или ключ серверу, чей ключ не закреплён. Сервер,
у которого ключ сменился, `pbx` отклоняет. Затем `session start` спросит пароль SFTP, если файла ключа нет. Он
проверит пароль, прочитав последние записи о звонках, и сохранит его в связке ключей.

Пути указывайте такие, как на АТС: `cdr_csv_path /var/log/asterisk/cdr-csv/Master.csv`, `recordings_path
/var/spool/asterisk/monitor`. Профиль может читать записи о звонках из базы, а аудиозаписи — по SFTP
с паролем. Тогда он спросит оба пароля, сначала пароль базы. Если есть ещё SSH-туннель, порядок такой: пароль базы,
пароль пользователя SSH, пароль пользователя SFTP. Оборванное соединение открывается снова, и файл читается дальше с
того места, где чтение остановилось. Неверный пароль, сменившийся ключ или отсутствующий файл `pbx` не повторяет.

<a id="numbers-directions-and-people"></a>

## Номера, направления и люди

- `phone_region` — страна номеров, записанных без `+`, например `ru` для `89161234567`. Тогда номера хранятся как
  `+79161234567`. Так их хранят и другие инструменты WireCat, поэтому звонящий — один и тот же человек в звонках и в
  переписке. Без этой настройки международными становятся только номера, записанные с `+` или `00`.
- Если офис принимает звонки из нескольких стран, перечислите их: `es,ru`. Номер читается в той стране, к которой
  подходит. Бывает, что номер подходит к двум странам: `612345678` подходит к Испании, Германии и Франции. Такой номер
  остаётся как написан и ни с кем не связывается: с ошибкой в стране звонящий попал бы в чужой контакт.
  `meetings sync` сообщает, сколько звонящих так осталось. Указывайте только страны, которые обслуживают ваши линии.
  Звонок из другой страны придёт с `+` или `00`.
- `extension_pattern` — регулярное выражение (шаблон текста) для ваших внутренних номеров. По умолчанию это
  `^\d{2,5}$`: номера из двух — пяти цифр. Сторона звонка внутренняя, если шаблону подходит её канал (`PJSIP/101-…`)
  или её номер.
- Звонок **входящий**, если внешний номер дозвонился на внутренний или пришёл через контекст `from-trunk`,
  `from-pstn` или `from-did`. Звонок **исходящий**, если внутренний номер звонил на внешний. Звонок **внутренний**,
  если он между двумя внутренними номерами. В остальных случаях направление остаётся пустым.
- Люди звонка — это внешний номер как `client`, с именем из caller ID (имя звонящего, которое передала АТС), и
  внутренние номера как `manager`: тот, что звонил, и каждый, что ответил. Скрытый номер (`anonymous`, `Restricted`)
  или служебное имя из dialplan, например `s`, человеком не считается.
- Группа вызова или очередь дозванивается до своих участников через каналы `Local/<extension>@…`. Ответивший
  участник — это внутренний номер в этом канале, а не номер группы.

<a id="import-the-history-then-keep-it-current"></a>

## Загрузите историю и держите её свежей

```sh
pbx office meetings sync --since-time 2024-01-01T00:00:00Z   # once: everything since then
pbx office meetings sync                                     # later: what is new
```

Каждая синхронизация заново читает шесть часов до прошлой синхронизации. Причина в том, что звонок попадает в записи
только когда заканчивается. Уже загруженный звонок обновляется и никогда не дублируется. Запись о звонке, которую не
удалось прочитать, пропускается, и `pbx` считает такие записи в stderr (потоке ошибок терминала). Остальные
загружаются. Запускайте синхронизацию вручную или по расписанию: из cron или таймером systemd.

<a id="transcribe"></a>

## Расшифровка

```sh
pbx models download gigaam-v3       # Russian; models list shows the others
pbx office meetings transcribe --max-meetings 50
```

Распознавание речи идёт на этом компьютере, и аудиозаписи никуда не отправляются. Уже расшифрованная аудиозапись не
читается снова, если файл не изменился. `--replace` расшифровывает заново. Аудиозапись с АТС копируется по SFTP во
временный файл, который можете читать только вы. Файл живёт, пока аудиозапись читается, и потом удаляется.

Аудиозапись может длиться до часа. Файл WAV, GSM или M4A может быть любого размера. Файл MP3, Ogg или FLAC — до
64 МБ, это больше часа при обычном телефонном качестве. Если звонок не удалось расшифровать, `pbx` показывает его с
причиной и продолжает с остальными. Для WAV, GSM и M4A нужен `ffmpeg`.

Каждая строка расшифровки может называть, кто это сказал. Ваш dialplan пишет две стороны звонка либо одной общей
дорожкой (моно), либо на два канала (стерео). В стереозаписи каналы остаются раздельными, в любом формате. Скажите
`pbx`, какая сторона на первом канале:

```sh
pbx office config set recordings_channels employee,caller    # or caller,employee
pbx office meetings transcribe --replace
```

Тогда в каждой строке будет звонящий с именем и номером, например `Ivan Testov +79000000001`, или сотрудник с
внутренним номером и именем, например `101 Oleg Operatorov`. Без этой настройки в строках будет `Channel 1` и
`Channel 2`. Чтобы узнать, какая сторона на каком канале, расшифруйте один звонок и прочитайте его. Запись в моно даёт
текст без имён. В звонке между двумя внутренними номерами остаются `Channel 1` и `Channel 2`: внешнего звонящего у
него нет.

<a id="cloud-transcription"></a>

### Облачная расшифровка

Профиль может отправлять аудиозаписи в сервис OpenAI, который превращает речь в текст, вместо локальной модели. Эта
функция выключена, пока вы не включите её для этого профиля. Настройка в общих `defaults` её не включает.

```sh
pbx office config set transcribe_engine openai
pbx office config set transcribe_model gpt-transcribe        # optional; gpt-transcribe when not set
OPENAI_API_KEY="$(secret-tool lookup service openai)" pbx office meetings transcribe
```

Ключ OpenAI передаётся только на этот запуск и читается из вашей связки ключей. Поэтому он не попадает в историю
команд терминала. На macOS ключ читает `security find-generic-password -s openai -w` вместо `secret-tool`. Храните
ключ под тем именем, которое принято в вашей связке ключей.

С вашего компьютера уходит речь из каждой аудиозаписи, кусками не длиннее десяти минут. Она уходит на
`api.openai.com`. Если другой инструмент WireCat задал адрес общей ИИ-модели WireCat, совместимый с OpenAI, речь
уходит туда. Номер звонка, имена, время и имя файла не отправляются. Перед первым куском запуск пишет в stderr, куда
уходит звук. Текст возвращается и хранится в локальном хранилище, так же как локальная расшифровка.

Запуску всё равно нужна одна скачанная локальная модель речи (`pbx models download gigaam-v3`). С ней приходит
детектор голоса, который режет речь на куски. Без ключа запуск останавливается до того, как прочитает аудиозапись.
`PBX_READ_ONLY=1` запрещает облачную расшифровку. Её запрещает и общий переключатель WireCat «только локально», если
он включён. Запись звонка и отправка в сервис могут требовать согласия его участников, см.
[безопасность](./security.md#recordings-and-consent). `config set transcribe_engine local` снова выключает облачную
расшифровку.

<a id="search-the-calls-with-everything-else"></a>

## Ищите звонки вместе со всем остальным

Звонки лежат в хранилище WireCat, которое читает каждый инструмент WireCat. Агент с `memo` спрашивает об одном
человеке сразу по звонкам, переписке и почте. `search all` в любом CLI WireCat ищет по всему этому вместе. Что
дальше: [работа с инструментом](./usage.md) — как устроены команды и как агент читает звонки.
