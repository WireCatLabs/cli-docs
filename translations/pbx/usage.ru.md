Вы [подключили Asterisk](./installation.md), и звонки лежат в локальном хранилище WireCat. Эта страница показывает,
какую повседневную работу со звонками команда может отдать ИИ-агенту.

Агент подготовит вас к перезвону, найдет звонки, на которые никто не ответил, и соберет отчет за неделю. Для каждой
задачи есть запрос, который можно скопировать и отправить агенту.

Агент берет ответы из локального хранилища и показывает звонок, на котором основан каждый ответ. Раздел
[По расписанию](#run-it-on-a-schedule) показывает, как запускать эту работу каждый день без вас.

<a id="what-you-get-from-each-call"></a>

## Что вы получаете о каждом звонке

Группа обзвона (номер, который звонит на несколько телефонов сразу), очередь или перевод пишут несколько записей об
одном звонке. Вы видите один звонок, и у него есть:

- **Итог:** ответили, голосовая почта, занято или не ответили. Итог записан одной фразой, которую читает агент:

  ```text
  Incoming call to 600: answered by 101 Анна Смирнова after 0:03, talk 0:24. 102 Борис Кузнецов did not answer.
  Incoming call to 600: went to voicemail after ringing 101 Анна Смирнова, 102 Борис Кузнецов.
  ```

- **Люди:** звонящий, сотрудник, который позвонил, и каждый, кто ответил. Имена сотрудников берутся из caller ID
  (имени, которое АТС показывает при звонке) их исходящих звонков. `memo context` и WireCat Desktop показывают у
  каждого звонка направление, сотрудника и номер звонящего.
- **Один человек везде:** если мобильный номер звонящего есть в CRM или в переписке, это тот же человек и там.
  Поэтому его звонки лежат рядом с его сделками, сообщениями и почтой. Городской номер только предлагается как
  совпадение: одним номером офиса пользуются многие.
- **Что сказали:** аудиозапись, превращенная в текст на вашем компьютере. Аудиозапись уходит в сервис, только если
  вы включили [облачную расшифровку](./installation.md#cloud-transcription) для профиля. Профиль — это имя, которое
  вы дали подключению к АТС.

<a id="ask-your-agent"></a>

## Попросите агента

Агенту с терминалом, например Claude Code или Codex, запрос начинается с «Используй pbx CLI». Если приложение
подключено по [MCP](#agents) (способу, которым приложения подключают инструменты), назовите в запросе подключенный
инструмент.

**Перед перезвоном клиенту.** Агент читает звонки клиента, что в них сказали и что клиент писал в переписке или
почте:

```text prompt
Используй pbx CLI и memo. Зачем +7 916 123-45-67 звонил нам в этом месяце, что мы ему пообещали и писал ли он нам
где-то еще? Процитируй звонки и сообщения, на которые опираешься.
```

**Звонки, на которые никто не ответил.** Агент находит входящие звонки, которые ушли на голосовую почту или остались
без ответа. Каждый он сверяет со звонками после него:

```text prompt
Используй pbx CLI. Покажи сегодняшние входящие звонки, на которые никто не ответил или которые ушли на голосовую
почту, с номером и временем. Для каждого скажи, перезвонили ли мы на этот номер или он дозвонился до кого-то позже.
Перечисли те, что еще не закрыты.
```

**День по сотрудникам.** Агент считает по итогу каждого звонка:

```text prompt
Используй pbx CLI. По вчерашним звонкам дай каждому сотруднику: сколько звонков он принял, сколько звонков ему
звонило без ответа, общее время разговоров и самое долгое ожидание, прежде чем он взял трубку. Покажи таблицей.
```

**О чем был звонок.** Агент читает расшифровку и пишет краткое содержание:

```text prompt
Используй pbx CLI. Прочитай расшифровку самого длинного звонка с Ольгой Новиковой на этой неделе. Кратко напиши, что
она просила, о чем договорились и что мы ей еще должны.
```

Каждый ответ берется из локального хранилища, и агент может показать звонок за каждой строкой. Если у звонка еще нет
расшифровки, агент так и скажет и может ее [сделать](./installation.md#transcribe).

<a id="a-report-of-the-week"></a>

## Отчет за неделю

`stats calls show` считает сохраненные звонки: по направлению и итогу, по сотрудникам, по часам и по дням. Еще он
показывает пропущенные входящие звонки и то, перезвонил ли кто-то клиенту в течение суток. Команда читает только
локальное хранилище. Поэтому она работает быстро, и связь с АТС ей не нужна.

```sh
pbx office stats calls show --since-time 7d --timezone Europe/Moscow
```

`--timezone` задает часовой пояс, в котором считаются часы и дни. Без него берется пояс этого компьютера.
`--within 2h` меняет срок: перезвон в пределах этого срока считается ответом на пропущенный звонок.

```text prompt
Используй pbx CLI. Сделай отчет о звонках за прошлую неделю по pbx office stats calls show: звонки по дням, доля
отвеченных, принятые звонки и время разговоров каждого сотрудника, самые загруженные часы и пропущенные звонки, на
которые никто не перезвонил, с номером и временем. Покажи все таблицами, затем назови три вещи, которые надо
исправить в первую очередь.
```

<a id="find-calls-by-what-was-meant"></a>

## Найти звонки по смыслу

`search meetings` находит звонок по словам, которые в нем сказали. С `--model` он находит звонок и по смыслу.
Например, запрос «клиент недоволен доставкой» найдет звонок, где клиент сказал «курьер приехал на три дня позже».
Общих слов у них нет. Текстовая модель (программа, которая сравнивает смысл фраз) работает на этом компьютере,
поэтому расшифровки его не покидают.

Один раз скачайте текстовую модель и подготовьте данные для поиска по звонкам, которые у вас уже есть:

```sh
pbx models download embeddinggemma
pbx office meetings embed            # shows what it would do, and changes nothing
pbx office meetings embed --yes      # builds one batch; run it again until nothing is left
pbx office search meetings "a client unhappy with the delivery" --model embeddinggemma
```

Каждый найденный звонок показывает, как его нашли, по словам или по смыслу, и цитирует нужное место расшифровки.
Поиск с `--model` сам готовит данные для звонков, расшифрованных после последнего `meetings embed`. Поэтому новый
звонок он не пропустит. Но поиск идет быстрее, если [расписание](#run-it-on-a-schedule) запускает
`meetings embed --yes`.

```text prompt
Используй pbx CLI. Найди звонки этого месяца, где клиент был недоволен доставкой. Ищи по смыслу с
--model embeddinggemma. Для каждого звонка дай дату, номер клиента, что пошло не так, его словами, и обещали ли мы
что-нибудь. Процитируй место звонка, на котором основана каждая строка.
```

<a id="mark-every-call-about-refunds"></a>

## Отметить тегом все звонки о возвратах

`tags add` ставит тег на звонки. С `--matching` он ставит тег на каждый звонок, который находит поиск. С `--meeting`
он ставит тег на звонки, которые вы назвали. `--matching` принимает те же слова, что и `search meetings`, а варианты
разделяются через `OR`.

```sh
pbx office tags add refund --matching "refund OR возврат"
pbx office tags add vip --meeting 42
pbx office tags list tag:refund
pbx office search meetings "delivery" --tag refund
```

Второй запуск ставит тег только на звонки, которые появились после первого, а ответ показывает, что изменилось. Тег
остается, если звонок расшифровать заново. Memo и другие инструменты WireCat видят те же теги.
`tags remove refund --meeting 42` снимает тег.

```text prompt
Используй pbx CLI. Отметь тегом refund каждый звонок о возврате денег, через tags add --matching. Затем покажи
отмеченные звонки этой недели: клиент, сумма, если он ее назвал, и согласовали ли возврат.
```

<a id="run-it-on-a-schedule"></a>

## По расписанию

Звонки остаются свежими, если синхронизация, расшифровка и теги запускаются сами. Например, каждые пятнадцать минут
из cron, планировщика задач в Linux и macOS:

```sh
*/15 * * * * pbx office meetings sync && pbx office meetings transcribe --max-meetings 20 && pbx office tags add refund --matching "refund OR возврат" && pbx office meetings embed --yes
```

Каждый шаг работает с тем, что появилось после прошлого запуска: с новыми звонками, аудиозаписями и расшифровками.
`meetings embed --yes` сохраняет поиск по смыслу быстрым. Если вы ищете только по словам, этот шаг можно убрать.

Запрос из раздела [Попросите агента](#ask-your-agent) тоже можно запускать по расписанию. Для этого нужен агент,
который умеет выполнять задачи по таймеру. Например, каждый вечер он присылает список звонков, на которые не
перезвонили, а каждый понедельник — неделю по сотрудникам. WireCat Desktop синхронизирует звонки по таймеру и без
cron: включите **Синхронизировать по расписанию** у аккаунта.

<a id="find-and-read-calls-yourself"></a>

## Найти и прочитать звонки самому

Профиль — это имя, которое вы дали АТС. Оно идет первым словом в каждой команде. Профиль никогда не подставляется
сам, даже если он единственный. Команда без профиля останавливается и показывает профили на этом компьютере.
`PBX_PROFILE=office` задает профиль на один сеанс терминала.

```sh
pbx office meetings sync                                  # import what is new
pbx office meetings list "started_at>=2026-11-01"          # newest first
pbx office meetings list "title:*79161234567*"             # the calls of one number
pbx office meetings show 42                                # times, people, recording
pbx office meetings transcript 42                          # what was said
pbx office meetings export 42 --format vtt --output call-42.vtt
```

Название звонка — это его две стороны, `+79161234567 → 101`. `pbx office meetings list --help` показывает поля,
по которым можно искать. `meetings export` сохраняет звонок в Markdown или его расшифровку в WebVTT (формат
субтитров).

<a id="output-for-scripts"></a>

## Вывод для скриптов

Каждая команда, кроме `mcp serve` на stdin и stdout, принимает `--json`. Тогда она печатает одно значение JSON в
стандартный вывод (stdout). `meetings list --jsonl` печатает по одному звонку в строке, с его описанием, чтобы их
читала другая система. Ошибки приходят в JSON в поток ошибок (stderr). В ошибке есть код и причина, и скрипт может
выбрать по ним, что делать дальше. Коды перечислены в [справочнике команд](./commands.md).

<a id="agents"></a>

## Агенты

`pbx skill install` кладет навык инструмента туда, где его ищут Claude Code, Codex, Gemini CLI и OpenClaw. Навык —
это файл с инструкциями, по которому агент узнает команды. `pbx skill install --for hermes` еще добавляет эту папку
в настройки Hermes Agent. Простой `skill install` Hermes не трогает.

`pbx office mcp serve` отдает команды профиля по MCP через stdin и stdout:

```sh
claude mcp add pbx -- pbx office mcp serve
```

Сервер предлагает все команды, кроме `session start` и `session end`. Что запускается, решают разрешения профиля:
см. [настройки](./configuration.md#permissions). Текст из звонка (расшифровка, имя звонящего, номер) доходит до агента
с пометкой «недоверенные данные». Поэтому слова, сказанные в звонке, не могут командовать агентом.

Для ChatGPT и Claude в браузере команда
`pbx office mcp serve --http --public-url https://laptop.example.ts.net` работает на `127.0.0.1` (порт 8765 или
`--port`) за вашим собственным туннелем. Приложение в браузере входит по одноразовому коду, который печатает команда.
`pbx office mcp revoke` завершает все входы.
