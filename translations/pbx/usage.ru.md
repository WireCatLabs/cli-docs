## Что вы получаете о каждом звонке

Группа, очередь или перевод пишут несколько записей об одном звонке. Вы видите один звонок, и у него есть:

- **Итог:** ответили, голосовая почта, занято или не ответили — одной фразой, которую читает агент:

  ```text
  Incoming call to 600: answered by 101 Анна Смирнова after 0:03, talk 0:24. 102 Борис Кузнецов did not answer.
  Incoming call to 600: went to voicemail after ringing 101 Анна Смирнова, 102 Борис Кузнецов.
  ```

- **Люди:** звонящий, сотрудник, который звонил, и каждый, кто ответил. Имена сотрудников берутся из caller ID их
  исходящих звонков.
- **Один человек везде:** звонящий, чей мобильный есть в CRM или в переписке, — тот же человек и там, поэтому его
  звонки лежат рядом с его сделками, сообщениями и почтой. Городской номер только предлагается как совпадение: одним
  номером офиса пользуются многие.
- **Что сказали:** запись, превращённая в текст на вашем компьютере. Записи никуда не отправляются.

<a id="ask-your-agent"></a>

## Попросите агента

Просьбы начинаются с «Use pbx CLI» для агента с терминалом, например Claude Code или Codex. В приложении, подключённом
по [MCP](#agents), назовите вместо этого подключённый инструмент.

**Перед перезвоном клиенту.** Агент читает звонки клиента, что в них сказали и что клиент писал в переписке или
почте:

```text prompt
Используй pbx CLI и memo. Зачем +7 916 123-45-67 звонил нам в этом месяце, что мы ему пообещали и писал ли он нам
где-то ещё? Процитируй звонки и сообщения, на которые опираешься.
```

**Звонки, на которые никто не ответил.** Агент находит входящие звонки, которые ушли на голосовую почту или остались
без ответа, и сверяет каждый со звонками после него:

```text prompt
Используй pbx CLI. Покажи сегодняшние входящие звонки, на которые никто не ответил или которые ушли на голосовую
почту, с номером и временем. Для каждого скажи, перезвонили ли мы или дозвонился ли он позже, и перечисли те, что ещё
не закрыты.
```

**День по сотрудникам.** Агент считает по итогам звонков:

```text prompt
Используй pbx CLI. По вчерашним звонкам дай каждому сотруднику: сколько звонков он принял, сколько звонило ему без
ответа, общее время разговоров и самое долгое ожидание, прежде чем он взял трубку. Покажи таблицей.
```

**О чём был звонок.** Агент читает расшифровку и пишет краткое содержание:

```text prompt
Используй pbx CLI. Прочитай расшифровку самого длинного звонка с Ольгой Новиковой на этой неделе. Кратко: что она
просила, о чём договорились и что мы ей ещё должны.
```

Каждый ответ берётся из локального хранилища, и агент может показать звонок за каждой строкой. Если у звонка ещё нет
расшифровки, агент так и скажет и может её [сделать](./installation.md#transcribe).

<a id="run-it-on-a-schedule"></a>

## По расписанию

Звонки остаются свежими, если синхронизация и расшифровка запускаются сами, например каждые пятнадцать минут из cron:

```sh
*/15 * * * * pbx office meetings sync && pbx office meetings transcribe --max-meetings 20
```

Просьбу из раздела [Попросите агента](#ask-your-agent) тоже можно запускать по расписанию в агенте, который умеет
выполнять задачи по таймеру: каждый вечер — список звонков, на которые не перезвонили, каждый понедельник — неделя по
сотрудникам. WireCat Desktop синхронизирует по таймеру и без cron: **Синхронизировать по расписанию** у аккаунта.

## Найти и прочитать звонки самому

Профиль — это имя, которое вы дали АТС, первое слово каждой команды. Профиль никогда не подставляется сам, даже если
он единственный: команда без профиля останавливается и показывает профили на этом компьютере. `PBX_PROFILE=office`
задаёт его для одного сеанса оболочки.

```sh
pbx office meetings sync                                  # import what is new
pbx office meetings list "started_at>=2026-11-01"          # newest first
pbx office meetings list "title:*79161234567*"             # the calls of one number
pbx office meetings show 42                                # times, people, recording
pbx office meetings transcript 42                          # what was said
pbx office meetings export 42 --format vtt --output call-42.vtt
```

Название звонка — его две стороны, `+79161234567 → 101`. `pbx office meetings list --help` показывает поля, по
которым можно искать, а `meetings export` сохраняет звонок в Markdown или его расшифровку в WebVTT.

<a id="output-for-scripts"></a>

## Вывод для скриптов

Каждая команда, кроме `mcp serve` на stdin и stdout, принимает `--json` и печатает одно значение JSON в stdout, а
`meetings list --jsonl` печатает по звонку в строке, с его описанием, чтобы его читала другая система. Ошибки — JSON
в stderr, с кодом и причиной, по которым можно ветвиться. Коды перечислены в [справочнике команд](./commands.md).

## Агенты

`pbx skill install` кладёт навык инструмента туда, где его ищут Claude Code, Codex, Gemini CLI и OpenClaw.
`pbx skill install --for hermes` ещё добавляет эту папку в настройки Hermes Agent, поэтому простой `skill install`
Hermes не трогает. `pbx office mcp serve` отдаёт команды профиля по MCP через stdin и stdout:

```sh
claude mcp add pbx -- pbx office mcp serve
```

Сервер предлагает все команды, кроме `session start` и `session end`. Что запускается, решают разрешения профиля:
см. [настройки](./configuration.md#permissions). Текст из звонка — расшифровка, имя звонящего, номер — доходит до
агента помеченным как недоверенные данные, поэтому слова, сказанные в звонке, не могут командовать агентом.

Для ChatGPT и Claude в браузере
`pbx office mcp serve --http --public-url https://laptop.example.ts.net` работает на `127.0.0.1` (порт 8765 или
`--port`) за вашим собственным туннелем. Приложение в браузере входит по одноразовому коду, который печатает команда,
а `pbx office mcp revoke` завершает все входы.
