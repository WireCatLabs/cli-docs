title: "Настройки"

Иногда нужно проверить или поменять, как инструмент работает с вашей АТС: где он берёт записи о звонках, где ищет
аудиозаписи, как расшифровывает звонки и что разрешено его командам. Каждая настройка стоит в таблице со своим
значением по умолчанию и коротким пояснением.

Настройки хранятся в одном файле, `config.json`, в папке, которую показывает `pbx doctor`. У каждого профиля (это
имя, которое вы даёте подключению к одной АТС) своя часть файла. Значения из `defaults` действуют для всех
профилей. Три команды в примере показывают настройки, меняют одну из них и убирают её.

**На этой странице:**

1. Источник
2. Расшифровка
3. Разрешения
4. Записи запусков

```sh
pbx office config show
pbx office config set cdr_csv_path /var/log/asterisk/cdr-csv/Master.csv
pbx office config unset cdr_csv_path
```

`config show` показывает каждую настройку и откуда взято её значение: из файла, из переменной окружения или по
умолчанию.

<a id="the-source"></a>

## Источник

Что значит каждая настройка, описано на странице [установка и подключение](./installation.md).

| Настройка | По умолчанию | Что это |
| --- | --- | --- |
| `cdr_source` | `csv` | `csv`, `mysql` или `postgres` |
| `cdr_csv_path` | — | путь к `Master.csv` |
| `cdr_csv_columns` | по числу полей | имена столбцов CSV через запятую |
| `db_host`, `db_port`, `db_name`, `db_user` | —, 3306 или 5432 | база записей о звонках (CDR); пароль сохраняет `session start` |
| `db_table` | `cdr` | таблица записей о звонках |
| `db_tls` | `false` | шифрованное соединение с проверкой сертификата |
| `db_ssh_host`, `db_ssh_port`, `db_ssh_user` | —, 22, — | SSH-сервер, через который инструмент доходит до базы, если база слушает только на самой АТС |
| `db_ssh_key_path` | — | файл закрытого ключа для этого SSH-сервера; без него `session start` спрашивает пароль SSH |
| `db_ssh_host_key` | — | проверенный вами отпечаток ключа этого SSH-сервера, `SHA256:…`; пока он не задан, подключения нет |
| `recordings_path` | — | папка с аудиозаписями |
| `recordings_pattern` | как в FreePBX, затем `*{uniqueid}*` | как по имени аудиозаписи найти звонок |
| `recordings_channels` | — | кто говорит на каждом канале стереозаписи: `caller,employee` или `employee,caller` |
| `cdr_timezone` | пояс этого компьютера | часовой пояс времени в записях о звонках |
| `phone_region` | — | страна для номеров без `+`, например `ru`, или несколько: `es,ru` |
| `extension_pattern` | `^\d{2,5}$` | какие номера считаются внутренними |
| `files_from` | `local` | `local` или `sftp`, чтобы читать `Master.csv` и аудиозаписи на АТС |
| `sftp_host`, `sftp_port`, `sftp_user` | —, 22, — | SSH-сервер АТС для `files_from sftp` |
| `sftp_key_path` | — | файл закрытого ключа; без него `session start` спрашивает пароль SFTP |
| `sftp_host_key` | — | проверенный вами отпечаток ключа сервера, `SHA256:…`; пока он не задан, подключения нет |

<a id="transcription"></a>

## Расшифровка

Эти две настройки читаются только из части файла самого профиля. Значение в `defaults` не отправляет аудиозаписи
ни одного профиля за пределы компьютера. Подробнее в разделе
[облачная расшифровка](./installation.md#cloud-transcription).

| Настройка | По умолчанию | Что это |
| --- | --- | --- |
| `transcribe_engine` | `local` | `local` — расшифровка на этом компьютере, или `openai` — речь уходит в OpenAI |
| `transcribe_model` | `gpt-transcribe` | модель речи сервиса, для `transcribe_engine openai` |

<a id="permissions"></a>

## Разрешения

`permissions` решает, что команде можно делать в этом профиле: `allow`, `ask`, `readonly` или `deny`. Разрешение
задаётся для пути команды, то есть для её слов через точку: `meetings.sync`, `meetings.transcribe`, `tags.add`.
Через MCP (протокол, по которому агент вызывает команды) спросить некого, поэтому `ask` пропускает команду.
`PBX_READ_ONLY=1` отклоняет каждую команду, которая меняет ваш вход или настройки.

```sh
pbx office config set permissions.meetings.transcribe deny
```

<a id="run-records"></a>

## Записи запусков

Запись запуска — это то, что инструмент сохранил о выполненной команде. Команда, которая завершилась ошибкой,
сохраняется как запуск. Его покажут `pbx runs list` и `runs show`. `meetings sync`, `meetings
transcribe` и `session status --check` работают внутри запуска. Поэтому с `--record` сохраняются и их успешные
запуски. `record_input` решает, хранит ли запуск слова, которые вы набрали. Секреты скрываются в любом случае, см.
[Безопасность](./security.md).
