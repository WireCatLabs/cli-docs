---
title: "Если что-то пошло не так"
---

Найдите симптом, выполните проверку, затем повторите команду. Для обращения в поддержку сохраните код ошибки и имя
профиля.

| Симптом | Что делать |
| --- | --- |
| Непонятно, что настроено | Запустите `gcal doctor`. Он не читает хранилище ключей и не обращается к сети. |
| `gcal` не найден | Откройте новый терминал и проверьте, что глобальная папка npm есть в `PATH`. |
| «name a profile» | Поставьте профиль первым словом, как в `gcal personal config show`, или задайте `GCAL_PROFILE`. |
| Файл настроек не читается | `doctor` перечисляет все проблемы файла в `config.issues`. Выполните `config unset`, который предлагается для каждой, или исправьте файл вручную. |
| `doctor` показывает `files.problems` | Другие пользователи компьютера могут читать `config.json` или заходить в его папку. Выполните каждую команду `chmod`, которую `doctor` выводит после «to make it private:». Сам `doctor` права файлов не меняет. |
| «no Google OAuth client is set up» | Передайте `--client-file` с JSON клиента типа Desktop app или задайте `GCAL_GOOGLE_CLIENT_ID` и `GCAL_GOOGLE_CLIENT_SECRET`. См. [свой клиент Google](./configuration.md#your-own-google-client). |
| `doctor` показывает `oauth_client.client: null` | В окружении нет клиента. Профиль, вошедший с `--client-file`, продолжает работать: его вход хранит клиент. Клиент нужен только для нового `session start`. |
| «the client file can be read by other users» | Выполните `chmod 600` из сообщения и войдите снова. |
| `sign-in.scope-missing` | На странице согласия Google можно снять галочку с Календаря. Снова запустите `session start` и оставьте её. |
| `profile.wrong-account` или `profile.same-account` | У каждого аккаунта Google один профиль. Используйте профиль, который уже есть у этого аккаунта, или новое имя профиля для нового аккаунта. |
| `oauth.expired` через неделю после входа | Приложение Google в режиме Testing выдаёт входы, которые истекают через 7 дней ([пояснение Google](https://developers.google.com/identity/protocols/oauth2#expiration)). Снова запустите `session start` или опубликуйте приложение в Google Cloud Console. |
| `oauth.not-saved` | `gcal` хранит вход в системном хранилище ключей, а этот процесс не смог до него добраться: хранилище заблокировано, служба хранилища ключей не запущена или у процесса нет сеанса D-Bus (оболочка агента, `ssh`, `cron`). Не работает и терминал, открытый до перезапуска шины сообщений рабочего стола: его `DBUS_SESSION_BUS_ADDRESS` всё ещё указывает на старую шину (`guid=…`); откройте новый терминал. Сам вход никуда не делся. Запустите команду снова с `--debug`, чтобы увидеть причину от хранилища ключей, затем выполните её из терминала рабочего стола или разблокируйте хранилище. Там, где хранилище ключей не работает, войдите через `session start --credential-storage file`. |
| Запись отклонена | Её запрещают разрешения профиля или `GCAL_READ_ONLY`; см. [настройки](./configuration.md#permissions). |

Никогда не вставляйте в обращение в поддержку токен, пароль или личное содержимое.
