---
title: "Установить"
---

Установите `gcal` один раз на каждый компьютер, где с ним работаете вы или агент. Нужен Node.js 22.16 или более новый 22.x либо 24 и новее; Node 23 не поддерживается.

```sh
npm install -g @wirecat/gcal-cli
gcal --version
```

Проверьте установку, затем выберите имя профиля для своего аккаунта, например `personal`:

```sh
gcal doctor
```

`doctor` не обращается к сети и не открывает хранилище ключей. Он показывает версию, где лежат настройки, какие профили
есть и могут ли другие пользователи компьютера читать настройки.

## Подключите аккаунт Google

`gcal` входит через приложение Google, которое называют клиентом OAuth. Через это приложение Google спрашивает вас,
какой доступ дать `gcal`. Получить его можно двумя способами.

**Приложение WireCat.** Пакет `gcal` может содержать собственное приложение Google от WireCat. В текущих выпусках его
пока нет, поэтому сейчас каждый пользователь создаёт своё приложение. Проверьте командой `gcal doctor --json`: если
`oauth_client.client` равно `wirecat`, приложение в пакете есть, и вы входите без своего проекта Google Cloud:

```sh
gcal personal session start
```

Пока Google не закончил проверку приложения WireCat, сначала может появиться страница «unverified app» (непроверенное
приложение). Чтобы продолжить, нажмите на ней ссылку, ведущую дальше к приложению, затем разрешите чтение Календаря.
Google ограничивает непроверенное приложение 100 новыми пользователями всего; когда приложение WireCat дойдёт до этого
предела, используйте своё приложение, как описано ниже. См.
[страницу Google о непроверенных приложениях](https://support.google.com/cloud/answer/7454865).

**Своё приложение.** Если `oauth_client.client` равно `null`, в пакете нет приложения WireCat, и `session start` нужно
ваше. [Создайте своё приложение Google](#make-your-own-google-app) один раз, это займёт около десяти минут, затем
передайте его файл:

```sh
gcal personal session start --client-file ~/client_secret.json
```

Ваше приложение важнее приложения WireCat, даже если оно есть в пакете: передайте `--client-file` или задайте
`GCAL_GOOGLE_CLIENT_ID` и `GCAL_GOOGLE_CLIENT_SECRET`.

## Создайте своё приложение Google

Это делается один раз в [Google Cloud Console](https://console.cloud.google.com/), под тем аккаунтом Google, с которым
вы будете работать в `gcal`. Это бесплатно. Приложение только ваше: через него больше никто не входит. Если какой-то
шаг не получился, см. [проблемы со входом](./troubleshooting.md#sign-in-problems).

### 1. Выберите проект

Откройте [выбор проекта](https://console.cloud.google.com/projectselector2/home/dashboard). Выберите проект, который у
вас уже есть, или нажмите **New project**, дайте ему имя, например `gcal`, и нажмите **Create**. Держите этот проект
выбранным в верхней панели на всех следующих шагах.

### 2. Включите Google Calendar API

Откройте [страницу Google Calendar API](https://console.cloud.google.com/apis/library/calendar-json.googleapis.com) и
нажмите **Enable**. Если пропустить этот шаг, вход всё равно пройдёт, но первая команда, которая читает Календарь,
завершится ошибкой «the Google Calendar API is turned off for this OAuth project».

### 3. Branding

Откройте **Google Auth platform → [Branding](https://console.cloud.google.com/auth/branding)**. Если на странице есть
кнопка **Get started**, нажмите её. Для себя достаточно заполнить только эти поля:

- **App name**: любое понятное вам имя, например `My gcal`. Google показывает его при входе.
- **User support email**: ваш адрес.
- **Audience**: **External**. **Internal** подходит только аккаунту в организации Google Workspace и только для
  пользователей этой организации.
- **Contact information**: снова ваш адрес.

Согласитесь с правилами Google о данных пользователей и нажмите **Create**. Логотип, домашнюю страницу и ссылку на
политику конфиденциальности можно оставить пустыми. Все поля описаны в
[руководстве Google по экрану согласия](https://developers.google.com/workspace/guides/configure-oauth-consent).

### 4. Audience

Откройте **Google Auth platform → [Audience](https://console.cloud.google.com/auth/audience)**. Тип пользователей —
**External**, статус публикации сначала **Testing**.

В разделе **Test users** нажмите **Add users**, введите аккаунт Google, под которым будете входить, и сохраните. Пока
приложение в режиме Testing, Google пускает только тестовых пользователей.

Затем выберите, сколько длится вход:

| Статус публикации | Что происходит |
| --- | --- |
| **Testing** | Вход заканчивается через 7 дней после согласия. После этого команды завершаются ошибкой, и вы снова запускаете `session start`. Входить могут только тестовые пользователи, не больше 100. |
| **In production** | Ограничения в 7 дней нет. При каждом входе Google может показать страницу «unverified app», и вы проходите её. У непроверенного приложения может быть не больше 100 пользователей, и вы один из них. |

Для приложения, которым пользуетесь только вы, мы советуем **In production**. Нажмите **Publish app**, подтвердите и
после этого войдите. Проверка Google не нужна: Google не требует её для приложения для личного использования, у
которого меньше 100 пользователей, и разрешает этим пользователям пройти предупреждение. Оставайтесь в **Testing**, если
не хотите видеть предупреждение и готовы входить заново каждую неделю.

Страницы Google об этом:

- [Срок действия refresh-токена](https://developers.google.com/identity/protocols/oauth2#expiration): 7 дней для
  приложения External в режиме Testing, которое просит больше, чем имя, адрес почты и профиль; доступ к Календарю —
  больше.
- [Аудитория приложения](https://support.google.com/cloud/answer/15549945): Testing, тестовые пользователи, In
  production.
- [Непроверенные приложения](https://support.google.com/cloud/answer/7454865): страница предупреждения и предел в 100
  пользователей.
- [Когда проверка не нужна](https://support.google.com/cloud/answer/13464323): личное использование.

### 5. Data Access

Откройте **Google Auth platform → [Data Access](https://console.cloud.google.com/auth/scopes)**. Для своего приложения
этот шаг необязателен: `gcal` в любом случае запрашивает свои области доступа при входе. Google пишет, что область, не
добавленная здесь, приводит к странице непроверенного приложения
([доступ приложения к данным](https://support.google.com/cloud/answer/15549135)), а ваше приложение и так её
показывает. Если добавить области, они будут перечислены на странице согласия, и вы увидите, что разрешаете.

Чтобы добавить их, нажмите **Add or remove scopes**, вставьте области в **Manually add scopes**, нажмите **Add to
table**, **Update**, затем **Save**:

| Область | Когда `gcal` её запрашивает |
| --- | --- |
| `openid`, `email` | Всегда: `gcal` узнаёт, какой аккаунт вошёл. |
| `https://www.googleapis.com/auth/calendar.readonly` | Всегда: чтение ваших календарей и событий. |
| `https://www.googleapis.com/auth/calendar.events` | С `--grant write`: создание, изменение и удаление событий и ответы на приглашения. |
| `https://www.googleapis.com/auth/calendar.acls` | С `--grant sharing`: просмотр и изменение того, кто видит календарь. |

`--grant` добавляет области к области чтения и никогда её не заменяет.

### 6. Создайте клиент и скачайте его файл

Откройте **Google Auth platform → [Clients](https://console.cloud.google.com/auth/clients)** и нажмите **Create
client**. В поле **Application type** выберите **Desktop app**, дайте любое имя и нажмите **Create**.

В появившемся окне нажмите **Download JSON**. Сделайте это сразу: полный секрет клиента Google показывает только один
раз, при создании ([управление клиентами OAuth](https://support.google.com/cloud/answer/15549257)). Если окно уже
закрыто, откройте клиент, добавьте новый секрет и скачайте файл снова.

Имя файла начинается с `client_secret_`. Перенесите его в домашнюю папку как `client_secret.json` и сделайте доступным
для чтения только вам. `gcal` отказывается работать с файлом клиента, который могут читать другие пользователи
компьютера.

```sh
mv ~/Downloads/client_secret_*.json ~/client_secret.json
chmod 600 ~/client_secret.json
```

Не создавайте клиент **Web application**: `gcal` входит через локальный адрес на вашем компьютере, а его разрешает
только клиент Desktop app. См.
[руководство Google по учётным данным Desktop app](https://developers.google.com/workspace/guides/create-credentials#desktop-app).

### 7. Войдите

Выберите имя профиля для этого аккаунта Google, например `personal`, и войдите:

```sh
gcal personal session start --client-file ~/client_secret.json
```

Так `gcal` получает доступ на чтение. Чтобы он мог ещё создавать, изменять и удалять события, попросите об этом при
входе:

```sh
gcal personal session start --client-file ~/client_secret.json --grant write
```

Вместо файла можно задать `GCAL_GOOGLE_CLIENT_ID` и `GCAL_GOOGLE_CLIENT_SECRET` — значения `client_id` и
`client_secret` из него. `--client-file` важнее этих переменных.

`gcal` хранит клиент вместе со входом, в системном хранилище ключей. Следующие команды и каждое обновление входа файл
больше не читают, поэтому его можно убрать в надёжное место. Он нужен только для нового `session start`.

### 8. Что Google показывает в браузере

`session start` открывает в браузере страницу входа Google. Дальше:

1. Выберите аккаунт Google, с которым будете работать в этом профиле.
2. Google может сообщить, что не проверял приложение. Это ваше приложение, поэтому нажмите на странице ссылку, ведущую
   дальше к нему.
3. Google перечисляет, что просит `gcal`, у каждого пункта есть галочка. Оставьте отмеченным **Calendar**. С
   `--grant write` оставьте отмеченным и доступ к событиям. Если снять галочку, `gcal` отклонит вход и попросит снова
   запустить `session start`.
4. Нажмите **Continue**. Браузер напишет «Sign-in received; you can close this tab», а `gcal` выведет аккаунт, под
   которым вы вошли.

`gcal` ждёт 5 минут, пока вы закончите в браузере. Результат можно проверить командой `gcal personal session status`.
