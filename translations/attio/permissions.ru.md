title: "Разрешения"
---

Пусть ИИ-агент работает с вашим пространством Attio через `attio`, а решение о том, что он меняет, остается за вами.
Токен доступа читает все пространство, а с правами на запись и меняет его, поэтому без ваших собственных ограничений
агент мог бы сделать все, что разрешает токен.

Для каждого профиля, то есть имени, которое вы дали входу в одно пространство, вы решаете, что агент может только
читать, что сначала спрашивает вас и что выполняется сразу. Одной строкой вы можете закрыть от агента любую запись и
знаете, какие проверки действуют, что бы ни говорили настройки.

У каждой команды есть ключ разрешения, ее имя, например `deals.list` или `api.notes-create`, или группа, например
`api`, и более длинный ключ побеждает. У каждого ключа есть уровень: `deny`, `readonly`, `ask` или `allow`. Уровни
задаются через `attio work config set`, а `--dry-run` показывает, какие ключи проверяет команда.

## Уровни

| Уровень | Что происходит |
|---|---|
| `deny` | Команда отклоняется, чтение тоже. |
| `readonly` | Чтение работает. Запись отклоняется. |
| `ask` | Запись сначала спрашивает в терминале. Без терминала она отклоняется, если не указан `--yes`. **Через MCP она выполняется.** |
| `allow` | Команда выполняется без вопроса. |

```sh
attio work config set permissions.api readonly   # every api operation reads, none writes
attio work config set permissions.people deny    # no live reads of people on this profile
attio work config show                           # each key with its level and where it came from
```

Отказ это `permission_error` (код выхода 5), и он называет ключ. Он не значит, что вход сломан.

Агент не может ослабить разрешение: `config set` или `config unset`, которые сняли бы ограничение, отклоняются, если
их не запускаете вы сами в терминале.

## Что задано, пока вы ничего не меняли

| Ключ | Встроенный уровень | Почему |
|---|---|---|
| `api.<operation>`, которая удаляет, например `api.objects-records-delete` | `ask` | Удаление нельзя отменить. Оно также проверяет `attio.delete`. |
| `attio.delete` | `ask` | Один ключ для любого удаления. Поставьте `deny`, чтобы остановить их все. |
| `deals.create`, `deals.update`, `deals.move`, `deals.close`, `deals.delete` | `ask` | Каждая меняет сделку, которую видят коллеги. |
| `people.create`, `people.update` | `ask` | Каждая меняет человека, которого видят коллеги. |
| `activities.create`, `activities.close` | `ask` | Заметку, задачу и задачу, отмеченную выполненной, видят коллеги. |
| `api.<operation>`, которая пишет, например `api.objects-records-create` | `ask` | Каждая меняет то, что видят коллеги. |
| `crm.assign-others` | `deny` | Передать сделку другому участнику пространства можно только после вашего разрешения. Новая сделка без `--owner` достается вам. У человека в Attio нет ответственного, поэтому `people create` и `update` не принимают `--owner`. |
| Любая другая команда | `allow` | |

Запись сделки, человека, заметки или задачи проверяет и ключ `api` той операции Attio, которую она отправляет,
например `api.objects-records-replace` или `api.notes-create`, поэтому `readonly` на `api` тоже ее останавливает.
Команды воронок, этапов, изменений, полей и поиска только читают, как и команды компаний и пользователей.

## Закройте от агента любую запись

`--dry-run` называет каждый ключ, который проверяет команда, с его уровнем, и ничего не отправляет:

```sh
attio work api objects-records-delete --object deals --record-id 0d7d1c2e-0000-4000-8000-000000000000 --dry-run
```

Id записи в этой команде придуман. Записи останутся под вашим контролем с любым из этих способов:

- **Права на чтение у токена.** Создайте токен только с тремя правами на чтение из раздела
  [установка](./installation.md). Тогда Attio сам отклоняет любую запись.
- **`api` на `readonly`.** `attio work config set permissions.api readonly`. Любое чтение продолжает работать, а
  любая запись отклоняется: команды сделок и людей отправляют запись через те же операции.
- **Без удалений.** `attio work config set permissions.attio.delete deny` останавливает любое удаление, а другие
  записи оставляет как есть.

## Агенты и MCP

Через MCP в терминале никого нет, чтобы ответить, и сервер не показывает форму, поэтому запись на уровне `ask`
выполняется. Это касается и встроенных уровней: агент с токеном, у которого есть права на запись, может удалять
записи. Прежде чем подключить приложение, выберите одно:

- Поставьте `permissions.api` на `readonly`, как в разделе выше.
- Или оставьте уровни и включите подтверждение для инструмента `attio_write` в клиенте агента, чтобы клиент
  спрашивал вас перед каждой записью.

`mcp serve --permission api=readonly` и `mcp add … --permission …` делают уровень строже для одного этого сервера.
Профиль они никогда не ослабляют. См. [MCP](./mcp.md#keep-writes-yours).

## Проверки, которые действуют независимо от разрешений

- **`WCATTIO_READ_ONLY=1`** отклоняет любую запись в этой оболочке или в приложении, которое его задает.
- **Права токена.** Attio отклоняет то, что не разрешают права токена, что бы ни говорил профиль.
- **Текст из Attio это данные.** Названия сделок, имена и значения атрибутов приходят агенту с пометкой
  `untrusted`, поэтому агент не принимает их за инструкции.
