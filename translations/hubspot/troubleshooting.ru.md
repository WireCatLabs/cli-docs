title: "Если что-то пошло не так"
---

Верните `hubspot` к работе по сообщению, которое он показывает. У отозванного ключа, пропущенного scope и
исчерпанного дневного лимита свое сообщение и свое решение.

Найдите свой симптом в таблице и выполните проверку рядом с ним. Ваш агент может сделать то же самое: каждая ошибка
называет свою причину, например `session.expired`, и агент понимает, что произошло. Начните с `hubspot doctor`: он
показывает, что настроено, и ему не нужна сеть.

## Симптомы и что делать

| Симптом | Что делать |
| --- | --- |
| Непонятно, что настроено | Запустите `hubspot doctor`. Он не читает связку ключей и не ходит в сеть. |
| `hubspot` не находится | Откройте новый терминал и проверьте, что глобальная папка npm есть в `PATH`. Слово `hubspot` может занимать другой инструмент, например собственный Agent CLI от HubSpot: запустите `wcat-hubspot`. |
| «name a profile» | Поставьте профиль первым, как в `hubspot work config show`, или задайте `WCHUBSPOT_PROFILE`. |
| Файл настроек не читается | `doctor` перечисляет каждую проблему в файле в `config.issues`. Выполните `config unset`, который предлагается для каждой, или исправьте файл вручную. |
| `doctor` показывает `files.problems` | Другие пользователи компьютера могут читать `config.json` или заходить в его папку. Выполните каждую команду `chmod`, которую `doctor` печатает после «to make it private:». Сам `doctor` права файлов не меняет. |
| «HubSpot refused the token» (`session.expired`) | Ключ удалили, заменили или ввели с ошибкой. Создайте новый и снова запустите `hubspot work session start`, как показывает [установка и подключение](./installation.md#make-a-key). |
| «the token lacks the … scope» (`hubspot.scope-missing`) | Добавьте ключу в HubSpot scope, который назван в ошибке. Ключ продолжает работать, входить заново не нужно. |
| `WCHUBSPOT_TOKEN needs WCHUBSPOT_ACCOUNT` (`account.id-missing`) | Рядом с токеном задайте `WCHUBSPOT_ACCOUNT`, id аккаунта. `hubspot work session status --check` с одним токеном печатает его как `account`. |
| `WCHUBSPOT_ACCOUNT names account …, but the token belongs to account …` (`account.mismatch`) | Это id другого аккаунта. Задайте `WCHUBSPOT_ACCOUNT` равным id, который назван в ошибке. Ничего не записано. |
| `run hubspot <profile> sync once with WCHUBSPOT_TOKEN first` (`account.unchecked`) | Команде, которая с `WCHUBSPOT_TOKEN` читает только локальную копию, сначала нужна проверенная команда. Запустите `hubspot work sync`. |
| «already signs in to HubSpot account» (`session.duplicate`) | Этот аккаунт уже читает другой профиль. Пользуйтесь им или сначала завершите его сеанс. |
| «spent its daily API allowance» (`hubspot.daily-limit`) | Все приложения аккаунта делят один дневной лимит. Он возвращается в полночь по часовому поясу аккаунта, и ошибка говорит, через сколько часов. `api` с `WCHUBSPOT_TOKEN` не знает часового пояса: его ошибка предлагает повторить после времени в UTC, самого раннего, когда лимит может вернуться. |
| `owner:me` ничего не находит | Ключ не называет пользователя. Возьмите id ответственного из `hubspot work users list` и фильтруйте по нему, например `owner:51234567`. |
| Запись отклоняется | Ее останавливают разрешения профиля или `WCHUBSPOT_READ_ONLY`, как показывает страница [разрешения](./permissions.md). |

## Как попросить помощи

Сохраните код ошибки и имя профиля. `hubspot doctor reports create` записывает отчет о проблеме в файл и говорит,
куда его отправить. Откройте issue в [репозитории hubspot-cli](https://github.com/WireCatLabs/hubspot-cli/issues).

Никогда не вставляйте в запрос о помощи ключ, пароль или личное содержимое.
