---
title: "Если что-то пошло не так"
---

Начните с симптома, выполните проверку, затем повторите команду. Сохраните код ошибки и имя профиля для обращения в
поддержку.

| Симптом | Что делать |
| --- | --- |
| Не уверены, что настроено | Выполните `mail doctor`. Он не читает связку ключей и не использует сеть. |
| `mail` не найден | Откройте новый терминал и проверьте, что глобальная папка npm есть в `PATH`. |
| "name a profile" | Поставьте профиль первым, как в `mail personal folders list`, или задайте `MAIL_PROFILE`. |
| Файл настроек не читается | `doctor` перечисляет все проблемы файла в `config.issues`. Выполните `config unset`, который он указывает для каждой, или исправьте файл вручную. |
| `doctor` показывает `files.problems` | Другие пользователи компьютера могут читать `config.json` или входить в его папку. Выполните каждый `chmod`, который `doctor` печатает после "to make it private:". Сам `doctor` права на файлы никогда не меняет. |
| `doctor` показывает `changes.unfinished` или `changes.expiring` | Запуск изменений остановился на полпути, либо письма, которые запуск переместил в корзину Gmail, скоро будут удалены оттуда. Выполните `messages restore --run <id> --yes`, который печатает `doctor`, с профилем этого ящика, либо повторите первую команду, чтобы довести дело до конца. |
| "no app password for profile" | Выполните `mail <profile> session start` или задайте `MAIL_PASSWORD` для одного запуска. |
| "the mail server refused the login" | Пароль приложения неверен, либо IMAP и пароли приложений выключены. Шаги для каждого провайдера описаны в [подготовке почтового ящика](./providers.md). Яндексу после создания нового пароля приложения нужно ещё 2–3 часа. Затем снова `session start`. |
| `rate_limited` | Две причины. **Сервер ограничивает аккаунт:** команда завершается ошибкой «the mail server is limiting this account»; подождите и выполните её снова. **`sync` израсходовал собственный бюджет запросов:** `sync` не завершается ошибкой. Он отвечает `state: partial` с `stopped: "requests"`, а в `meta.issues` есть `rate_limited` с причиной `budget.requests`; выполните `sync` снова, чтобы продолжить, или увеличьте `--max-pages`. В обоих случаях уже сохранённая почта пропускается. |
| "could not reach the OS keyring" | Хранилище ключей заблокировано или не запущена служба секретов. Пароль сохранён вместо этого в закрытом файле (`credential_storage: "file"`). Разблокируйте связку ключей и снова выполните `session start`, чтобы вернуть его туда. |
| "refused the OAuth token from this sign-in" | Вход в браузере прошёл, но почтовый сервер отклонил новый токен. В Outlook.com IMAP по умолчанию выключен: откройте Settings (шестерёнка), "Mail", "Forwarding and IMAP", включите "Let devices and apps use IMAP", нажмите "Save", затем снова `session start`. В Microsoft 365 IMAP может быть выключен для ящика; обратитесь к администратору. |
| "refused the OAuth token even after a refresh" | Вход был отозван (смена пароля, выход из сессий или удаление приложения). Снова выполните `mail <profile> session start`. |
| Microsoft пишет, что приложение должен одобрить администратор, или `AADSTS90094` | Ваша организация разрешает только одобренные приложения. Попросите администратора дать согласие ([ссылка и шаги](./outlook.md#work-or-school-account-microsoft-365)) или зарегистрировать собственное приложение организации ([шаги](./oauth-microsoft.md)) и сообщить вам его id. |
| "Microsoft refused the OAuth login for sending" | Чтение работает, а отправка нет: для ящика Microsoft 365 выключен "Authenticated SMTP", часто из-за настроек безопасности по умолчанию. Администратор включает его для каждого ящика. |
| Gmail через OAuth перестаёт работать через неделю | Приложение Google всё ещё в режиме Testing, где Google завершает входы через 7 дней. Опубликуйте его ([шаги](./oauth-google.md#4-publish-the-app-production-without-verification)), затем снова `session start`. `mail doctor` предупреждает с 6-го дня. |
| Запись отклонена | Её останавливают разрешения профиля или `MAIL_READ_ONLY`; см. [настройки](./configuration.md#permissions). |

Никогда не вставляйте токен, пароль или личное содержимое в обращение в поддержку.
