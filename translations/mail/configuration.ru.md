Настройки лежат в одном файле, `config.json`, в папке, которую показывает `mail doctor`. У каждого профиля своя
часть, а `defaults` действуют для всех профилей. Здесь описано, как их посмотреть и изменить.

```sh
mail personal config show
mail personal config set limit 50
mail personal config unset limit
```

Профиль, созданный командой `session start`, хранит и данные ящика: `address`, `login` (если он не совпадает с адресом), `imap_host`,
`imap_port`, `imap_security` (`tls` или `starttls`), `auth` (`app-password`; профиль, сохранённый без него, тоже входит
по паролю приложения) и `folders` (папки, которые читает `sync`). `smtp_host`, `smtp_port` и `smtp_security` задают
сервер, на который отправляет `messages send`; задавайте их только для провайдера, которого нет во [встроенном списке](./providers.md). Пароль приложения не
входит в настройки: он лежит в связке ключей или в `MAIL_PASSWORD` для запуска без связки ключей. Вход через OAuth тоже не
настройка: его токены тоже лежат в связке ключей.

`read_attachments` (по умолчанию `true`) и `max_attachment_mb` (по умолчанию 10) решают, читает ли `sync` текст вложений в поисковый
индекс и какой самый большой файл он читает. Сами файлы не сохраняются. `sync --no-attachments`, `--attachments` и
`--max-attachment-mb` переопределяют их для одного запуска; `messages show` читает вложения одного письма независимо от них.

`microsoft_client_id` — приложение Microsoft, через которое входят в Outlook.com и Microsoft 365, если вы используете своё, а не
приложение WireCat. Задайте его один раз для всех профилей командой `config set --defaults microsoft_client_id` с id приложения. Как получить
id, описано в [регистрации приложения Microsoft](./oauth-microsoft.md). `google_client_id` делает то же для Gmail через OAuth; его
секрет берётся из `MAIL_GOOGLE_CLIENT_SECRET`, но не из файла. `MAIL_MICROSOFT_CLIENT_ID` и `MAIL_GOOGLE_CLIENT_ID` важнее обеих
настроек для одного запуска, а `--client-file` важнее всего для Gmail. Профиль, который уже вошёл, продолжает обновлять токен
через то приложение, с которым вошёл. `mail doctor` показывает приложение каждого профиля в `oauth_client`.

Агент по MCP, у которого есть `mcp.authority`, может менять настройки через `config set`, но никогда не эти: настройки
ящика выше, которые решают, куда уходит пароль приложения, `microsoft_client_id` и `google_client_id`, которые решают, в какое
приложение вы входите, и `permissions.messages.send.others`, позволяющую агенту писать другим людям. Их меняете только вы, в терминале.

`config show` перечисляет каждую настройку и показывает, откуда она взялась: из файла, из переменной или по умолчанию.

`config set` также перечисляет настройки поиска, речи и эмбеддингов (`embedding_*`, `speech_model`, `picture_search` и
другие). Этот список общий для всех CLI WireCat. `mail` их игнорирует.

## Разрешения

`permissions` определяет, что команда может делать для этого профиля: `allow`, `ask`, `readonly` или `deny`, отдельно для
каждого ключа разрешения. Через MCP спросить некого, поэтому `ask` разрешает выполнение команды. `MAIL_READ_ONLY=1`
отклоняет любую запись, что бы ни говорили разрешения, кроме одной: `rules add --sender` или `--list-id` с
`--do envelope` для отправителя или рассылки, у которых еще нет правила. Ее выполняет плановый разбор почты в memo.
Такая запись помечается `source: agent` (`rules list source:agent`). Замена правила, `--domain`, `--filter`, `--kind`,
любое другое действие и тег по-прежнему отклоняются, как и `rules remove`, `rules import` и `rules apply`.

Ключ команды — её путь: `messages.move`, `folders.delete`. Изменение, которое можно отменить, по умолчанию выполняется сразу
(флаги, перемещение, копирование, создание и переименование папок, сохранение черновиков), а эти спрашивают:
`messages.delete`, `folders.delete`, `drafts.delete` и `messages.bulk`, через который проходит и каждое изменение более
чем 20 писем или выбранное через `--filter`. В терминале
`ask` — вопрос y/N, по умолчанию «нет». Вместо него отвечает флаг: `--allow-dangerous` для `drafts delete`, потому что удалённый
черновик не возвращается, и `--yes` для любого другого изменения, включая `messages delete`, потому что корзина и
`messages restore` возвращают письма. Без терминала и без флага команда останавливается с `confirmation_required`
(код выхода 7) и ничего не меняет.

У отправки два ключа. `messages.send` и `messages.forward` — сами команды, они выполняются сразу, если письмо уходит только
вам. Письмо, которое доходит до кого-то ещё, проходит и `messages.send.others`, который по умолчанию спрашивает;
поставьте `allow`, чтобы отправлять без вопроса, или `readonly`, чтобы этот профиль писал только вам. Агент по MCP, где
ответить на вопрос некому, пишет только вам, пока вы сами не зададите `messages.send.others` в настройках (`ask` или
`allow`); `mcp serve --permission` его открыть не может. Каждый получатель учитывается в `sends_per_hour` (по умолчанию 30).

```sh
mail personal config set permissions.messages readonly      # no flag, move, deletion or send on this profile
mail personal config set permissions.messages.bulk deny     # one message at a time only
mail personal config set permissions.messages.send.others allow   # send to others without the question, agents too
```

Каждая попытка изменить ящик или отправить письмо попадает в журнал отправок профиля с ключом, числом писем и итогом,
но никогда не с темой, адресом или текстом.

## Записи запуска

Команда, которая завершилась ошибкой, сохраняется как запуск, его можно посмотреть через `mail runs list` и `runs show`.
`record_input` решает, сохраняет ли запуск слова, которые вы набрали; значение `true`, пока вы не поставите `false`.
Секреты скрываются в любом случае; см. [Безопасность](./security.md).
