Здесь объясняется, как устроена команда и как инструментом пользуется агент. Прочитайте это перед первой командой.

## Сначала профиль

Профиль — имя, которое вы выбираете для одного аккаунта. Это первое слово каждой команды, которая работает с
аккаунтом:

```sh
mail ya folders list
```

`MAIL_PROFILE=ya` делает то же для одного сеанса оболочки. Профиль никогда не подставляется сам, даже единственный:
команда без профиля останавливается с кодом выхода 2 и показывает профили на этом компьютере.

## Подключить почтовый ящик

Сначала подготовьте ящик: включите IMAP и создайте пароль приложения. Шаги для каждого провайдера описаны в
[подготовке почтового ящика](./providers.md), их же печатает `session start`.

```sh
mail ya session start --address me@example.com # new profile: finds the server, shows the steps, asks for the app password
mail ya session start                 # an existing profile: asks for the app password again (checked, kept in the keyring)
mail ya account check                 # logs in and lists what the server supports
mail ya folders list                  # folders with role and counts
mail ya sync --since-time 2026-10-01  # reads new mail into the shared store; stored mail is skipped
```

`session start` для нового профиля ищет адрес во встроенной таблице (Yandex, Gmail, iCloud, Mail.ru, Fastmail,
Outlook), затем запись MX, затем ISPDB Thunderbird и собственный файл autoconfig домена. Передайте `--host`, `--port`
и `--security`, чтобы задать сервер вручную, или `--provider yandex` (любое имя из таблицы), когда поиск ничего не
нашёл; в терминале вместо этого он спросит, какой это провайдер, а при отсутствии `--address` спросит адрес. Профиль
сохраняется только после того, как сервер принял пароль приложения. Без терминала ничего не спрашивается: отсутствие
`--address` или пароля — ошибка проверки, а пароль читается из `MAIL_PASSWORD`. Outlook принимает для IMAP только OAuth,
поэтому `session start` пока его отклоняет. Существующий профиль лишь снова спрашивает пароль; чтобы сменить его сервер,
используйте `config set` или новое имя профиля.

`session start` берёт пароль из терминала или `MAIL_PASSWORD`, но никогда не из параметра или ссылки. Он сохраняется только после того, как
сервер его принял, в хранилище ключей; если хранилище ключей не работает, в закрытом файле, о чём один раз сообщается в
stderr и ничего не спрашивается (`--credential-storage file` выбирает файл, не рекомендуется). Если пароля нет ни там, ни там, `mail` читает запись, оставленную Himalaya (`secret-tool`, служба
`himalaya`, аккаунт — имя профиля), так что существующей настройке новый пароль не нужен.

`sync` читает INBOX и папку Sent, если `--folder` или `folders` профиля не говорят иначе, сначала самые новые,
берёт `--limit` за запуск, а `--rescan` заново перечисляет всё окно. Он сохраняет только текст и заголовки: вложения не хранятся.

Синхронизация большого ящика не помещается в один запуск. Она тратит бюджет запросов, рассчитанный на её срок (15 минут
в терминале, 45 секунд через MCP; `--timeout` меняет срок, `--max-pages` уменьшает бюджет), сохраняет после каждой
части и отвечает `state: partial` с той же командой в `next`; выполните её снова, чтобы продолжить. `mail <profile> status`
показывает, как далеко она ушла. На сервере, который не выдаёт id сообщения (Yandex), список содержит только UID, флаги,
дату и размер, а каждое новое сообщение скачивается один раз: сохранённая почта пропускается по UID, так что повторный
запуск ничего не читает заново. Такой запуск не замечает почту, удалённую на сервере, и изменённые флаги у пропущенных
сообщений; `--rescan` перечисляет всё с заголовками и учитывает и то и другое. Сообщение, на котором сервер даёт сбой (Yandex отвечает так на некоторые с `NO [UNAVAILABLE]`), запрашивается ещё раз в конце
запуска, и если сбой повторяется, оно учитывается в `unreadable` и остаётся до следующего запуска. Когда сервер закрывает
соединение, синхронизация переподключается через 1, 3 и 10 секунд (с разбросом), проверяет, что UIDVALIDITY прежний, и продолжает с
неудавшегося запроса, пока позволяют бюджет и срок; при сбое собственный код транспорта сохраняется как
`cause_code`, и `mail runs show` его показывает.

## Вывод для скриптов

Каждая команда, кроме `mcp serve` на stdin и stdout, принимает `--json` и печатает одно значение JSON в stdout. Ошибки — JSON в stderr, с кодом, по которому можно ветвиться. В
[справочнике команд](./commands.md) коды перечислены.

## Агенты

`mail skill install` кладёт навык инструмента туда, где его ищут Claude Code, Codex, Gemini CLI и OpenClaw.
`mail skill install --for hermes` также добавляет эту папку в собственные настройки Hermes Agent, поэтому простая
`skill install` Hermes не затрагивает. `mail personal mcp serve` отдаёт команды профиля по MCP, через stdin и stdout:

```sh
claude mcp add mail -- mail personal mcp serve
```

Сервер предлагает все команды, в том числе те, что пишут. Что выполнится, решают разрешения профиля; см.
[настройки](./configuration.md#permissions).

Для ChatGPT и Claude в браузере
`mail personal mcp serve --http --public-url https://laptop.example.ts.net` работает на `127.0.0.1` (порт 8765 или
`--port`) за вашим собственным туннелем. Браузерное приложение входит по одноразовому коду, который печатает команда;
`mail personal mcp revoke` завершает все входы. `mail personal mcp server start` запускает тот же
сервер в фоне, `mcp server status` показывает его порт, код входа и вошедшие приложения, а
`mcp server stop` его останавливает.
