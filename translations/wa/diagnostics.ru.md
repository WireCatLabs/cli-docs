Используйте эту страницу, когда команда завершается неудачно, зависает или выполняется слишком долго, и вы хотите понять, почему. Вы сможете наблюдать за операциями команды по мере их выполнения, вести учет выполнения, проверять установку и отправлять отчет о проблеме, не содержащий текста сообщения.

Несколько слов, которые используются на этой странице:

- **run** – это один вызов `wa` от начала до выхода.
- **Запись о выполнении** — это папка, в которой хранится то, что было выполнено при каждом запуске: его командная строка, его результат и одна строка для каждой операции. Эти строки никогда не содержат текст сообщений, имена или заголовки чатов. Что запись хранит от набранной вами командной строки, описано в разделе [Что вы набрали](#what-you-typed).
- **`wa personal doctor`** проверяет установку: версию, профиль, настройки, локальное хранилище и собственные части WhatsApp — движок, ключи устройства и блокировку.
– **Отчет о проблеме** — это один файл JSON, созданный на основе `wa personal doctor`, и неудачный запуск. Вы прикрепляете его к проблеме.

## Что можно сделать

| Задача | Команда | Сохраняет что-нибудь? |
|---|---|---|
| Смотрите каждую операцию, как она происходит | `wa --trace …` | нет, печатает только в stderr |
| Смотрите весь провал | `wa --debug …` | нет, печатает только в stderr |
| Найти запуск позже | `wa personal runs list` | каждый запуск сохраняется сам по себе |
| Не сохранять один запуск | `wa personal --no-record …` | ничего |
| Сохранять только неудачные запуски | `wa personal config set record false` | неудачные запуски |
| Проверьте установку | `wa personal doctor`, `wa personal doctor --online` | нет |
| Сообщить о проблеме | `wa personal doctor reports create` | да, один файл вы отправите |

## Покажите это: `--trace` и `--debug`

```sh
wa personal --trace messages send 100000000000001@lid "test"
wa personal --debug chats mark-read 100000000000001@lid
```

`--trace` печатает каждую операцию на stderr по мере ее возникновения: что было запрошено, что вернулось, с идентификаторами, счетчиками, длительностью и кодом ошибки, если таковой был. stdout не меняется, поэтому канал по-прежнему получает только данные. Даже в этом случае собственный журнал движка остается отключенным: в нем указаны идентификаторы WhatsApp, а идентификатор номера телефона — это номер телефона.

`--debug` заменяет однострочную ошибку всей записью об ошибке — ее причиной и стеком — в stderr.

## Сохраните: `--record`

```sh
wa personal --record chats list
wa personal runs list              # recorded runs, newest first
wa personal runs show 20261001T080000Z-process-000001     # one run: its outcome, and one line per operation
wa personal runs path 20261001T080000Z-process-000001     # the folder that holds it
```

Идентификатор запуска, указанный выше, составлен; `runs list` показывает настоящие.

Запись запуска — это папка под `runs/<day>/` в папке состояния. Его имя – время и команда. Он содержит два файла:

- `run.json` — команда, профиль, версия `wa`, узел и система, когда она началась и закончилась, результат и код ошибки;
- `events.jsonl` — те же операции, что и `--trace`, по одной в строке. Под каждой операцией — запросы, которые она сделала, с пометкой `"level": "wire"`: к движку WhatsApp (`"transport": "wa-engine"`, имя запроса движка, например `send` или `older`) или к Graph API Meta для команд `bot` (`"transport": "http"`, метод и путь, где идентификаторы заменены на `:id`). У каждого есть длительность, результат и код ошибки. Запрос к движку хранит идентификатор сообщения, если он есть, и никогда — идентификатор чата: в нём номер телефона. Загрузка медиафайла не хранит адрес вовсе.

## Сохраняется каждый запуск

Каждый запуск сохраняется без `--record`, в том числе успешный. Неудачный запуск сохраняется для каждой команды и каждой ошибки: плохой вариант, неизвестная команда, проверка перед любой работой, отказ, потому что другая команда удерживает устройство. Что запись хранит от командной строки, описано в разделе [Что вы набрали](#what-you-typed); запуск, у которого не загрузились настройки, скрывает каждое набранное значение, которое может быть текстом.

Каждый запуск записывается, в том числе успешный, поэтому к отчету о проблеме всегда есть что прикрепить. `--no-record` не сохраняет ничего для одного запуска; `"record": false` в настройках сохраняет только неудачные запуски.

Успешные поиски сохраняют свою собственную историю, помимо записей о запусках: см. [поиск](./search.md).

## Когда сохранять только неудачные запуски

```sh
wa personal config set record false         # profile "personal": failed runs only
wa personal --no-record chats list          # this run: nothing at all
```

Успешный запуск хранит идентификаторы прочитанных вами чатов и, если включён `record_input`, то, что вы набрали (отправленное сообщение, чат, названный по заголовку). Он хранится только на этом компьютере, читаем только вам, 7 дней. Установите `record` в `false`, если не хотите хранить его совсем.

## Как долго он живет

Успешный запуск живёт **7 дней** (`keep_successful_runs_for_days`), неудачный — **30 дней** (`keep_runs_for_days`). Папка запусков также остаётся меньше **200 МБ** (`runs_size_limit_mb`): при превышении сначала удаляются самые старые успешные запуски. Старые запуски удаляются только тогда, когда сохраняется новый, целым днём, по имени папки, поэтому для принятия решения ничего открывать не нужно.

## Чего никогда нет в записи

События запуска и `--trace` содержат имя операции, идентификаторы, количество, продолжительность и коды ошибок. Они никогда не несут:

- текст сообщения;
- заголовок чата или имя человека;
- номер телефона, код сопряжения или ключи устройства.

### Что вы набрали

`run.json` также хранит командную строку. Что именно, зависит от версии `wa`:

- **Версия, у которой `record_input` есть в `wa personal config show`**, хранит командную строку как вы её набрали — название чата, поиск, текст сообщения, — чтобы можно было прочитать, что вы запускали. Секрет всегда `[redacted]`: значение опции, названной по токену, паролю, парольной фразе, секрету, учётным данным, cookie, авторизации или ключу API; пароль внутри URL; длинная строка, похожая на токен. Чтобы снова скрыть каждое набранное значение, которое может быть текстом:

  ```sh
  wa personal config set record_input false
  ```

- **Более старая версия** хранит слова команды и названия опций, такие как `messages send --md`. Каждое значение, которое может быть текстом, например то, что вы набрали как `<chat>`, — `[redacted]`.

Отчёт о проблеме, составленный по запуску, скрывает эти набранные значения в любой версии.

## Проверьте установку: `wa doctor`

```sh
wa personal doctor            # connects to nothing
wa personal doctor --online   # also connects once and reads the account; sends nothing
```

Помимо версии, среды выполнения, профиля, файла конфигурации и локального хранилища, `doctor` считывает с диска три вещи WhatsApp, ничего не запуская:

- **`engine`** — есть ли программа движка для запуска и путь к ней. Когда он отсутствует, подсказка говорит, что делать: переустановить `wa` с включенными дополнительными пакетами, установить `WA_ENGINE` или при проверке исходного кода запустить `pnpm engine:build`.
- **`device`** — существуют ли ключи устройства, и могут ли `private.db`, его файлы `-wal` и `-shm` или их папка быть прочитаны другими пользователями этой машины. К каждому такому файлу прилагается команда `chmod`, которая его исправляет. `doctor` никогда не открывает ключи и никогда не меняет режим файла сам. Windows не проверяется.
- **`lock`** — кто последним удерживал одно соединение устройства (`serve (pid 4242)`), и выполняется ли этот процесс. Движок никогда не очищает имя, поэтому держатель считается запущенным только до тех пор, пока работает его процесс.

**`config.issues`** перечисляет все проблемы файла конфигурации: некорректный JSON (со строкой и столбцом, где чтение остановилось), настройку или ключ разрешения, которых `wa` не знает, значение неверного типа. Каждая проблема говорит, каким должно быть значение, но никогда не показывает само значение. Все, кроме некорректного JSON, приходят с командой `config unset`, которая их удаляет (`fix`). `doctor` всё равно отвечает, с кодом выхода `0`.

**`files`** называет каждый приватный файл или папку, которые могут читать другие пользователи этой машины: файл конфигурации (нужно `0600`) и его папку (`0700`), хранилище с файлами `-wal` и `-shm`, журнал отправок и папку запусков. Каждая проблема — это `{ path, mode, want }`, а stderr печатает исправляющую её команду `chmod`: `to make it private: chmod 600
'<path>'`. Без имени профиля или когда настройки отклонены, `files` проверяет только файл конфигурации и его папку. `doctor` никогда не меняет режим файла сам. Windows не проверяется.

`--online` подключается один раз. Во время работы `serve` вместо этого используется соединение `serve` ([одно соединение на устройство](./sessions.md#one-connection-per-device)).

## Отчет о проблеме

```sh
wa personal doctor reports create              # about the newest failed run
wa personal doctor reports create --run 20261001T080000Z-process-000001   # a made-up run id
```

Он записывает файл JSON — то, что показывает `wa personal doctor` плюс запуск — и говорит, куда его отправить: новая проблема на [github.com/WireCatLabs/whatsapp-cli/issues](https://github.com/WireCatLabs/whatsapp-cli/issues/new). Прочтите его, прежде чем отправить. Он не содержит текста сообщения. Только `wa doctor reports show` показывает, что будет содержать отчет, и ничего не пишет.

Если неудачных запусков не сохранилось, запустите неудачную команду еще раз; его неудача сохраняется сама собой.

## Что делать с запусками

Записи имеют формат JSON, поэтому `jq` отвечает на вопросы о них. `wa personal runs list --json` отвечает на `{ items, page, meta }`, а `items` — это `run.json` серий, сначала самые новые:

```sh
wa personal runs list --limit 100 --json | jq '[.items[] | select(.status == "failed") | {command, error_code}]'
wa personal runs list --limit 100 --json | jq '[.items[] | .duration_ms] | add / length'
```

## Ошибки поиска и частичные запуски

```sh
wa personal search runs error_code:authentication_error --json
wa personal search runs status:partial 'started_at>=2026-10-01' --json
```

`search runs` ищет буквальный диагностический текст в записях. Условия запроса, например `operation:messages.download`, `profile:work`, `error_code:timeout`, `status:failed`, а также сравнения и диапазоны `started_at:`, сужают поиск вместе с `--limit` и `--page`; каждая страница вмещает до 100 запусков. Команда читает только записи и никогда не подключается.
