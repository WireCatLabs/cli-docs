Подключите Яндекс Диск один раз, и дальше ИИ-агент находит на нем любой документ по тому, что в нем написано.
Яндекс пускает программу к Диску только по токену OAuth, ключу, который Яндекс выдает для вашего собственного
аккаунта. Получить токен можно минут за пять, один раз.

После этих шагов ваш Диск подключен под именем профиля, которое вы выбрали, и первый поиск работает. Все это можно
сделать в [WireCat Desktop](https://wirecat.dev/en/docs/desktop), приложении, которое устанавливает инструменты за вас, или в
терминале через npm.

## В WireCat Desktop

1. Получите токен, как показано в разделе [получите токен Яндекса](#get-a-yandex-token).
2. На странице **Инструменты** нажмите **Установить** в строке Яндекс Диска.
3. Нажмите **Управление**, введите имя аккаунта, например `personal`, и нажмите **Войти здесь**.
4. Вставьте токен. Затем выберите папки для копирования.

Desktop еще и дает вашим ИИ-агентам навык инструмента, так что шаги в терминале не нужны.

## Установите инструмент

Нужен Node.js 22.16 или новее в ветке 22.x либо версия 24 и новее. Node 23 не поддерживается. Версию покажет команда
`node --version`. Если Node.js нет или он старее, скачайте его на [nodejs.org](https://nodejs.org/).

```sh
npm install -g @wirecat/yandex-disk-cli
ydisk --version
ydisk doctor
```

`doctor` не использует сеть и не открывает связку ключей. Он показывает версию, где лежат настройки и локальное
хранилище, какие профили есть и могут ли другие пользователи компьютера читать настройки. Чтобы попробовать инструмент
без установки, выполните `npx @wirecat/yandex-disk-cli --help`.

## Получите токен Яндекса

Токен Яндекс выдает приложению, которое вы регистрируете для себя. Приложение здесь только название и список прав в
вашем аккаунте Яндекса. Ничего не публикуется. Шаги повторяют собственные инструкции Яндекса:
[регистрация приложения для доступа к API](https://yandex.ru/dev/id/doc/en/register-api) и
[быстрый старт API Диска](https://yandex.ru/dev/disk-api/doc/en/concepts/quickstart). Страницы Яндекса на русском,
поэтому названия из интерфейса даны в шагах как есть.

1. Откройте [oauth.yandex.ru/client/new](https://oauth.yandex.ru/client/new/) и войдите в Яндекс с аккаунтом, Диск
   которого хотите использовать. Если Яндекс предложит выбрать тип приложения, выберите **Для доступа к API или
   отладки** («Для доступа к API или отладки»).
2. Введите любое название приложения («Название вашего сервиса»), например `My laptop`, и свою почту
   («Контактная почта»).
3. В разделе «Доступ к данным» добавьте права Яндекс Диска, которые нужны инструменту:
   - `cloud_api:disk.read`: чтение всего Диска («Чтение всего Диска»).
   - `cloud_api:disk.info`: информация о Диске («Доступ к информации о Диске»). По ней инструмент проверяет, чей это
     токен.
   - `cloud_api:disk.write`: запись в любом месте Диска («Запись в любом месте на Диске») для загрузки, переноса,
     удаления и публичных ссылок. Для токена только на чтение не добавляйте его. Тогда любое изменение завершится
     ошибкой.
4. Создайте приложение («Создать приложение»). На его странице будет **ClientID**, строка из букв и цифр. Скопируйте
   ее.
5. Откройте в браузере этот адрес, дописав ClientID в самый конец, после `client_id=`:
   `https://oauth.yandex.ru/authorize?response_type=token&client_id=`
6. Яндекс спросит, разрешить ли приложению доступ к вашему Диску. Разрешите, и Яндекс покажет токен на странице.
   Скопируйте его.

Прежде чем разрешить создание приложений, Яндекс может попросить подтвердить личность. Без подтверждения он показывает
предупреждение и ограничивает число приложений, но для этих шагов это не помеха. Подробности на
[странице Яндекса](https://yandex.ru/dev/id/doc/en/confirm-account).

Храните токен как пароль. Тот, у кого он есть, может работать с вашим Диском с теми правами, которые вы выбрали.

## Войдите

Выберите имя профиля для этого аккаунта, например `personal`, и войдите под ним. Инструмент спросит токен скрытым
вводом. Вставьте его и нажмите Enter.

```sh
ydisk personal session start
```

Сначала инструмент проверяет токен у Яндекса и сохраняет его, только если Яндекс его принял. Токен лежит в системной
связке ключей (Keychain в macOS, Credential Manager в Windows, Secret Service в Linux). Токен никогда не передается
аргументом команды и не попадает ни в вывод, ни в журнал.

`session start` читает токен и из stdin, так что скрипт может передать его из менеджера паролей. У второго аккаунта
будет свой профиль: `ydisk work session start`.

## Проверьте, что все работает

```sh
ydisk personal session status --check
ydisk personal folders browse
```

`session status --check` спрашивает Яндекс, чей это токен, и показывает аккаунт. `folders browse` показывает папки
верхнего уровня вашего Диска. Обе команды отвечают по данным Яндекса, так что рабочий ответ значит, что вход
выполнен.

Яндекс держит токен действующим месяцами и продлевает его, пока им пользуются
([Яндекс ID](https://yandex.ru/dev/id/doc/en/concepts/ya-oauth-intro)). Когда Яндекс перестанет его принимать,
команды завершатся с кодом выхода 4: получите новый токен так же и снова выполните `session start`.

`ydisk personal session end` удаляет токен с этого компьютера. Сам токен остается действующим у Яндекса. Чтобы
отозвать его, откройте [«Доступ к данным»](https://id.yandex.ru/personal/data-access) в Яндекс ID и удалите
приложение, для которого выдан токен. Смена пароля Яндекса или «Выйти на всех устройствах» тоже отзывает его вместе
со всеми другими токенами аккаунта ([Яндекс ID](https://yandex.ru/dev/id/doc/en/tokens/token-invalidate)).

## Компьютер без связки ключей

На сервере или в контейнере без связки ключей инструмент хранит токен в закрытом файле, который читаете только вы, и
говорит об этом. Чтобы обойтись без связки ключей намеренно:

```sh
ydisk personal session start --credential-storage file
```

## Обновление

```sh
ydisk upgrade
```

`ydisk upgrade --check` только сообщает, есть ли новая версия. После обновления снова выполните `ydisk skill install`,
чтобы инструкции вашего агента соответствовали новой версии.

## Удаление

Чтобы забыть один аккаунт на этом компьютере, удалите его профиль:

```sh
ydisk personal account remove --keep-data
```

Команда удаляет токен профиля и его настройки. Выберите, что будет со скопированным текстом: `--keep-data`
оставляет его в хранилище, где его по-прежнему находит поиск, а `--delete-data` удаляет его вместе со списком папок,
которые вы выбрали для копирования. На Диске ничего не меняется. В терминале команда сначала спрашивает. В скрипте `--yes`
отвечает «да» за вас, а `--dry-run` перечисляет, что будет удалено, ничего не удаляя. Токен остается действующим у
Яндекса: отзовите его в [«Доступ к данным»](https://id.yandex.ru/personal/data-access) в Яндекс ID.

`ydisk personal session end` забывает только токен и оставляет профиль. Чтобы удалить сам инструмент:

```sh
npm uninstall -g @wirecat/yandex-disk-cli
```

Настройки и локальное хранилище остаются в папках, которые показал `ydisk doctor`, для других инструментов WireCat,
которые делят это хранилище. Если они вам больше не нужны, удалите их вручную.
