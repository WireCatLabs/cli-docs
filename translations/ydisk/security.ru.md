Узнайте, что `ydisk` хранит на вашем компьютере, что отправляет и кому, и как это удалить. Что общего у всех CLI
WireCat, то есть связка ключей, разрешения, MCP и то, что никогда не попадает в лог, описано на
[общей странице о безопасности](https://wirecat.dev/en/docs/security). Здесь только то, что свойственно `ydisk`.

## Что остается на вашем компьютере

| Что | Где | Как удалить |
| --- | --- | --- |
| Токен Яндекса | Связка ключей системы, а где ее нет, закрытый файл | `ydisk personal session end` |
| Текст файлов в выбранных папках, с их именами, путями, размерами, датами и контрольными суммами MD5 | Локальное хранилище `wirecat.db`, общее с другими инструментами WireCat | `folders remove` с id папки из `folders list`, затем `sync` |
| Ваши теги, заметки и записи памяти о документах | Локальное хранилище | `tags remove`, `notes remove` |
| Настройки и записи запусков | Папки, которые показывает `ydisk doctor` | `ydisk runs list` показывает их. Они удаляются через столько дней, сколько указано в [настройках](./configuration.md#run-records) |

Сами файлы остаются на Диске. Копия файла сохраняется, только когда вы запускаете `files download --output`.
Публичные ссылки (`public_url`) синхронизация не хранит. В WireCat ничего не уходит: сервера WireCat нет, и аккаунта
у нас тоже.

## Что уходит по сети

`ydisk` хранит настройки в `config.json`, а состояние в папках, которые показывает `ydisk doctor`. Он обращается к
одному сервису, API Яндекс Диска по адресу `cloud-api.yandex.net`. `session start` сохраняет токен OAuth Яндекса в
связке ключей системы, а где она не работает, в закрытом файле. Токен уходит только в заголовок Authorization запроса к
`cloud-api.yandex.net` и никогда не попадает в адрес, ответ, запись запуска или журнал отправок. Скачивание и загрузка
идут по ссылке, которую выдает Яндекс (`downloader.disk.yandex.ru`, `*.disk.yandex.net`, `*.storage.yandex.net`), без
токена, и эти ссылки никогда не печатаются.

Кроме Яндекса, `ydisk` раз в день спрашивает у реестра npm, есть ли новая версия, если только `update_check` не равен
`false`. Текст уходит к провайдеру ИИ, только если вы его настроили: например, `embedding_provider` со значением
`openai` или `memories extract`. По умолчанию поиск по смыслу работает на вашем компьютере.

## Агенты и MCP

По MCP агент читает текст файла через `files download`, но не может сохранить его по пути: `--output` есть только у
владельца. `files upload` отказывается загружать файлы с учетными данными, профили браузеров и папки WireCat, пока
владелец не добавит `--allow-any-file`. `files delete`, `--replace` и команды публичных ссылок в терминале сначала
спрашивают. По MCP их останавливает только `deny`, поэтому задайте `files.delete=deny` и `files.share=deny` для
агента, которому это не нужно, и `files.upload=deny` для того, кто не должен класть на Диск ни одного локального
файла.

`ydisk personal mcp serve --http` слушает только `127.0.0.1`, для приложений в браузере, которые подключаются через
ваш собственный туннель. Каждое приложение входит по одноразовому коду, а сервер хранит хеш каждого выданного входа в
папке состояния, читаемой только вами. `ydisk personal mcp revoke` забывает их все.

## Записи запусков

Запись запуска хранит командную строку так, как вы ее набрали, поэтому `ydisk runs show` показывает, что запускалось.
Секрет при этом сохраняется как `[redacted]`: параметр с именем вроде token или password, пароль в ссылке, длинная
непрозрачная строка. Номер телефона заменяется на `[redacted]` внутри набранного вами слова, в том числе в тексте
сообщения: записанный с «+» и кодом страны или 11–15 цифр подряд, так что длинный id такой длины тоже скрывается. Чтобы
не хранить ни одного набранного слова, выполните `ydisk personal config set record_input false`.

Секрет находится и по внешнему виду, в записи запуска и в сохраненном тексте ошибки: токен в известном формате
(GitHub, OpenAI, Slack, AWS, Stripe, npm и подобные), учетные данные `Bearer`, случайная на вид строка из 20 и более
символов и случайная на вид последовательность из 20 и более строчных шестнадцатеричных символов, например
шестнадцатеричный ключ или полный хеш коммита. Значение после имени секрета тоже скрывается, идет ли оно после `=`,
`:` или пробела: `password=`, `API_TOKEN=`, `password hunter2`, `pin 1234`. Некоторые секреты выглядят как обычные
слова и остаются: значение из одних букв после имени секрета и пробела (`pin this message` остается), шестнадцатеричный
ключ в верхнем регистре, короткий хеш коммита или UUID, короткий пароль без имени секрета перед ним и секрет внутри
ссылки или пути к файлу, если он не в известном формате и не после имени секрета.

## Права на файлы

`config.json` сохраняется читаемым только вами (`0600`), а его папка создается только для вас (`0700`). Файл или
папка, созданные старой версией, могут быть открыты другим пользователям компьютера: `ydisk doctor` перечисляет
каждый такой в `files.problems` и печатает `chmod`, который это исправляет. Windows не проверяется. Об уязвимости
сообщите так, как описано в [SECURITY.md](https://github.com/WireCatLabs/ydisk-cli/blob/main/SECURITY.md).
