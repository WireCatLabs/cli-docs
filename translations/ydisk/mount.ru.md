Смотрите свой Яндекс Диск в файловом менеджере, рядом со своими папками. Открывайте PDF в своей программе просмотра,
смотрите видео, ищите по папке через `grep` или открывайте файл в любой программе, ничего не скачивая заранее и
ничего не устанавливая. Папка доступна только для чтения: ни программа, ни скрипт, ни случайное движение руки не
изменят, не переименуют и не удалят файл на Диске через нее.

```sh
ydisk personal files serve /Documents
```

## Подключите папку

Укажите профиль, затем папку на Диске. Без папки команда показывает весь Диск:

```sh
ydisk personal files serve             # the whole Disk
ydisk personal files serve /Documents  # one folder
ydisk personal files serve /Photos --port 8090
```

Команда печатает адрес вроде `http://127.0.0.1:41234/Xy…/` и способ подключить его в вашей системе, а затем
продолжает работать. Не закрывайте ее, пока пользуетесь папкой. Ctrl-C останавливает ее, и папка пропадает. Каждый
запуск создает новый адрес, поэтому после перезапуска подключите папку снова. `--port` сохраняет порт между запусками,
остальная часть адреса все равно меняется.

Команда использует вход, который вы сделали через `ydisk personal session start`. Другой пароль, пароль приложения и
платный тариф не нужны.

## Linux

GNOME Files и другие файловые менеджеры на основе GIO подключают папку одной командой:

```sh
gio mount dav://127.0.0.1:41234/Xy…/
```

Затем папка появляется на боковой панели файлового менеджера, а программы находят ее по пути
`/run/user/$(id -u)/gvfs/dav:host=127.0.0.1,port=…,ssl=false/<secret>/`. Программа, которая записывает туда файл,
может сообщить об успехе, но на Диск ничего не попадает: слой GNOME теряет отказ, когда файл закрывается.
`gio mount -u dav://…` отключает папку. В файловом менеджере можно также ввести адрес `dav://…` в разделе «Другие
места» > «Подключиться к серверу».

## macOS

В Finder выберите «Переход» > «Подключение к серверу» (Cmd+K), вставьте адрес `http://127.0.0.1:…/` и нажмите
«Подключить». Папка появится в разделе «Места» и в `/Volumes/`. Извлекайте ее как любой диск.

## Windows

Windows подключает папку своей службой WebClient, которую `net use` обычно запускает сам (`sc start webclient`
запускает ее вручную):

```bat
net use * http://127.0.0.1:41234/Xy…/
```

Windows называет букву диска, которую выбрала. `net use Z: /delete` отключает папку. Клиент WebDAV в Windows
отказывается от файлов больше примерно 50 МБ, если не увеличить его настройку `FileSizeLimitInBytes`, как описано на
странице Microsoft о
[WebDAV Redirector](https://learn.microsoft.com/en-us/iis/publish/using-webdav/using-the-webdav-redirector).

## Почему только чтение

Папка с правом записи позволила бы любой программе на вашем компьютере или ошибочному `rm -rf` сразу удалить файлы на
Диске. [Зеркала](./mirrors.md) защищают от этого корзиной, прежними версиями и остановкой при массовом удалении, а
подключенная папка обошла бы все эти защиты. Поэтому подключение только читает: оно отвечает на просмотр и чтение и
отказывает в сохранении, переименовании, перемещении, удалении, создании папок и блокировках. Программа, которая
пытается сохранить файл, получает ошибку, а Диск остается нетронутым.

Чтобы менять файлы, используйте `ydisk personal files …` или [зеркало](./mirrors.md).

## Кто может к ней обратиться

- Она слушает 127.0.0.1, только этот компьютер. Ничто в вашей сети или в интернете до нее не дотянется.
- В адресе есть случайный секрет, новый при каждом запуске. Программа на этом компьютере без адреса получает «not
  found». Пока команда работает, берегите адрес как пароль.
- Веб-страница до нее не доберется, даже если заставит браузер обратиться к 127.0.0.1: запросы, где указан другой
  сайт, отклоняются.
- В адресе нет токена. Ваш вход в Яндекс остается в связке ключей и отправляется только в API Яндекса.
- Агенты никогда не получают `files serve` по MCP: команда работает, пока ее не остановят, а вызов агента должен
  завершаться.
- Профиль, у которого `files.download` стоит в `deny`, тоже не может подключить папку, потому что подключение читает
  каждый файл, который показывает.

## Скорость и ограничения

- Список папки хранится 10 секунд, поэтому файловый менеджер, который много раз смотрит в папку, спрашивает Диск один
  раз. Файл, измененный на Диске, появится после этого.
- Открытие файла читает его с Диска. Видеоплеер или программа просмотра, которая прыгает по файлу, запрашивает его
  части. В документации Яндекса не сказано, отдают ли его ссылки для скачивания части файла, поэтому прыжок может
  читать файл с начала.
- Папка больше чем с 10 000 элементов показывает первые 10 000, по имени, и команда предупреждает об этом.
- Каждый просмотр списка расходует тот же лимит, что и другие команды `ydisk` этого профиля. Когда Яндекс просит
  притормозить, файловый менеджер на мгновение получает «service unavailable», а команда продолжает работать.

### Почему не собственный WebDAV Яндекса

У Яндекса есть сервер WebDAV на `webdav.yandex.ru`, но в его
[документации](https://yandex.ru/dev/disk/doc/ru/concepts/quickstart) сказано, что он работает только с тарифом
Яндекс 360, а файловый менеджер входит в него с паролем приложения, который может и записывать, и удалять.
`files serve` работает на любом тарифе, использует вход, который у вас уже есть, и не может ничего записать.
