## Сначала профиль

Профиль: имя, которое вы выбираете для одного аккаунта. Это первое слово каждой команды, которой нужен аккаунт:

```sh
ydisk personal status
```

`YDISK_PROFILE=personal` делает то же самое для одного сеанса оболочки. Профиль никогда не подставляется сам, даже
единственный. Команда без него останавливается с кодом выхода 2 и показывает профили на этом компьютере.

## Выберите папки

`folders browse` показывает Диск по одному уровню, вживую, так что папку можно найти по ее пути:

```sh
ydisk personal folders browse
ydisk personal folders browse --folder /Documents
ydisk personal folders add /Documents/Contracts
```

Выбранная папка забирает все, что в ней лежит, вместе с вложенными папками. `folders list` показывает выбранные
папки, а `folders remove` убирает одну из них. Следующая синхронизация удалит ее документы из копии.

Выбирайте несколько папок с документами, а не весь Диск. Яндекс Диск не сообщает инструменту, что изменилось, поэтому
каждая синхронизация заново перечисляет все выбранные папки и их подпапки. Папка с фотографиями добавляет время на
перечисление и не добавляет текста для поиска.

## Синхронизация

```sh
ydisk personal sync
ydisk personal status
```

`sync` скачивает файлы, которые появились или изменили содержимое с прошлой синхронизации, и читает их текст. Файл,
перенесенный внутри выбранных папок, сохраняет свои теги и заметки.

Файл, который синхронизация больше не находит на Диске, пропадает из списков и поиска, но его текст остается в копии
с пометкой, что он больше не виден. Диск не говорит синхронизации, удален ли файл, перенесен ли за пределы папок или
пропал вместе с общим доступом, поэтому синхронизация никогда не считает его удаленным. Когда файл снова появится, он
вернется таким, каким был.

Одна синхронизация читает до 200 файлов (`--limit`) и перечисляет до 10 000 элементов, а потом запоминает, где
остановилась. Большая папка обрабатывается за несколько запусков: запускайте `sync` снова, пока `status` не покажет,
что работы не осталось. Остановка ничего не теряет, следующая синхронизация продолжит с того места, где закончила
предыдущая.

Запускайте `sync`, когда хотите обновить копию, например перед вопросом агенту о свежих файлах. В фоне ничего не
работает. `sync --rescan` читает все выбранные папки с начала. Выполните его один раз и дальше возвращайтесь к обычной
команде `sync`.

Выбранную папку, которую вы переименовали или перенесли на Диске, инструмент больше не находит, и ее документы
уходят из копии. Добавьте ее снова под новым путем.

## Что хранит копия

| На Диске | В копии |
| --- | --- |
| PDF с текстовым слоем, Word `.docx`, Excel `.xlsx`, CSV, TSV, обычный текст, Markdown | Текст, имя, путь, размер и даты |
| Отсканированный PDF или картинка | Имя, путь и даты. Текста для чтения нет |
| Любой другой файл и любой файл больше 50 МБ | Имя, путь и даты |

`status` перечисляет каждый файл, сохраненный только по имени, с причиной. Сами файлы остаются на Диске, а копия
хранит их текст. Время хранится и показывается в UTC.

## Читайте синхронизированный документ

```sh
ydisk personal documents list
ydisk personal documents show 1a2b3c --json
ydisk personal documents export 1a2b3c --output ./contract.md
```

`documents show` выводит весь текст одного документа, который вы находите по id из `search` или `documents list`. Id
выше только пример. `documents export` записывает документ в новый файл Markdown. Теги, заметки и воспоминания
остаются при документе и никогда не попадают на Диск. Смотрите [поиск документа](./search.md).

## Прежние версии и что изменилось

```sh
ydisk personal documents history 1a2b3c
ydisk personal documents history 1a2b3c --revision 2
ydisk personal changes --since 7d
ydisk personal changes --since 1d --event unavailable
```

Каждая синхронизация сохраняет текст, заголовок и front matter документа, прежде чем он изменится или уйдет из копии.
`documents history` перечисляет эти версии, а `--revision` показывает одну из них. `changes` перечисляет, что
добавилось, изменилось, перестало быть видно, ушло из выбранных папок или вернулось, новые сверху. Обе команды читают
только копию, поэтому работают без интернета и через MCP. Версии и журнал изменений хранятся
`keep_versions_for_days`, по умолчанию один год.

## Работа с файлами вживую

Команды `files` работают с Диском напрямую, синхронизация им не нужна. Пути это пути на Диске, например
`/Documents/plan.pdf`.

```sh
ydisk personal files list --folder /Documents
ydisk personal files show /Documents/plan.pdf
ydisk personal files download /Documents/plan.pdf --json
ydisk personal files download /Documents/plan.pdf --output ./plan.pdf
ydisk personal files upload ./notes.md --folder /Documents
ydisk personal files copy /Documents/plan.pdf --folder /Archive
ydisk personal files move /Documents/old.pdf --folder /Archive
ydisk personal files create /Projects/2026
ydisk personal files delete /Documents/old.pdf
ydisk personal files restore trash:/old.pdf
ydisk personal files update /Notes/plan.md --text "# Plan" --expected-fingerprint <sha256>
ydisk personal files sheets show /Work/budget.xlsx "Sheet1!A1:C10"
ydisk personal files documents show /Work/report.docx
ydisk personal files history /Notes/plan.md
ydisk personal files publish /Documents/plan.pdf
ydisk personal files unpublish /Documents/plan.pdf
```

- `files download` без `--output` отвечает текстом файла, до 200 000 символов, так что агент читает файл вне
  выбранных папок, не сохраняя его. Более длинный текст обрезается на этом месте, а в ответе стоит `truncated: true`.
  Никогда не записывайте обрезанный текст обратно в файл: остальная часть файла пропадет.
- `files show` и `files list` дают для каждого файла `md5` и `sha256`, так что агент видит, изменился ли файл
  после того, как он его прочитал. `files download` дает `sha256` только вместе со всем текстом файла. У обрезанного
  текста и у текста, извлеченного из PDF, .docx или .xlsx, стоит `sha256: null`, поэтому агенту нечем записать его
  обратно.
- `files delete` переносит файл в корзину Диска, а `files restore` возвращает его по пути в корзине.
- `files publish` создает публичную ссылку, которую может открыть любой, у кого она есть. `files unpublish` закрывает
  ее.
- `--replace` при загрузке, копировании или переносе перезаписывает файл, который уже лежит по этому пути.

В терминале инструмент спрашивает перед удалением, перезаписью, правкой и публичной ссылкой. Через MCP спросить некого, поэтому
задайте эти разрешения для агента. Смотрите [настройки](./configuration.md#permissions). Добавьте `--dry-run` к любому
изменению, чтобы увидеть, что оно сделает, и ничего не менять.

Каждая операция API Диска Яндекса тоже есть как команда: `ydisk personal api list` перечисляет их, а
`ydisk personal api show resources-list` показывает параметры одной операции, не обращаясь к Яндексу.

## Правка файла на Диске

Правка заменяет файл, только если его содержимое осталось таким, каким его прочитали. Сначала прочитайте `sha256`
файла и передайте его как `--expected-fingerprint`. Файл проверяется прямо перед записью, а то, что правка заменила,
сохраняется на этом компьютере, в папке состояния профиля. Если файл изменился после чтения, ответом будет
`conflict` с командой, которая прочитает его заново, и ничего не загружается. У Диска нет условной загрузки, поэтому
изменение, которое попадет в короткий промежуток между последней проверкой и загрузкой, не будет замечено. Замененное
содержимое все равно сохраняется.

| Команда | Что она меняет |
| --- | --- |
| `files update <path> --text <text>` (или текст через stdin) | весь текст обычного текстового файла, например `.md`, `.txt` или `.csv`. Новому файлу отпечаток не нужен |
| `files sheets update <path> <range> --values <json>` | ячейки `.xlsx`, из `files sheets show`. Остальная книга остается как есть |
| `files documents update <path> --payload <json>` | абзацы `.docx`, по индексам, которые дает `files documents show` |
| `files restore <path> <version>` | возвращает версию, которую показывает `files history` |

`files update` отклоняет `.pdf`, `.docx` и `.xlsx`: их текст извлекается, и запись его обратно заменила бы документ.
`sheets update` записывает текст как текст, даже если он начинается с `=`, и не перезаписывает формулу без
`--replace`. `documents update` отклоняет абзац с исправлением в режиме рецензирования, полем, картинкой,
комментарием, ссылкой или сноской и объясняет причину. Каждая правка спрашивает так же, как `files.delete`.
`files history` перечисляет, что заменили правки этого профиля, новые в конце. Каждая `version` это sha256
замененного содержимого, а `available` говорит, сохранено ли оно еще. Смотрите
[отредактируйте файл с агентом](./recipes.md#edit-a-file-with-your-agent).

## Вывод для скриптов

Каждая команда, кроме `mcp serve`, принимает `--json` и печатает одно значение JSON в stdout. Ошибки идут в stderr
тоже как JSON, с полем `code`, по которому можно ветвиться, а у каждого вида сбоя свой код выхода. Их перечисляет
[справочник команд](./commands.md).
