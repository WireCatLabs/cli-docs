# Plan: the CLI portal, version 1

## Goal

One public docs site for the owner's command-line tools, starting with `max` (max-cli) and `tg`
(tg-cli). People read it in a browser; agents read it as Markdown. Static, on Cloudflare Pages.

## Decisions already made

- ✅ One shared site, a portal that will grow to more tools — owner, 2026-10-01.
- ✅ Its own public repository, `leemour/cli-docs`.
- ✅ Fumadocs, chosen for the agent features it ships itself: `llms.txt`, a Markdown copy of every
  page, "copy as Markdown" and "open in Claude/ChatGPT" buttons
  ([Fumadocs: AI & LLMs](https://fumadocs.dev/docs/integrations/llms)).
- ✅ Static first. The docs MCP server is step 2, not this plan — owner, 2026-10-01.
- ✅ Portal languages: English (default), Russian, Spanish. The first visit follows the browser's
  language. max pages stay Russian only for now — owner, 2026-10-01.
- ✅ Pages are pulled from each tool's repository at its **latest release tag**, never `main`: `main`
  can describe what is not released yet (max-cli `8b978aa` had to take such a page back).

## How it works

### The build, in order

1. `scripts/sync.ts` reads `tools.json` (one entry per tool: repository, which files, language,
   order) and, for each tool, finds the newest `v*` tag with `git ls-remote --tags` — sorted as
   versions, not as text (as text, `v0.9.0` comes after `v0.21.0`), skipping the `^{}` entries — and
   fetches only the listed files at that tag (shallow, sparse clone into a temp directory).
2. The same script turns each file into a Fumadocs page in `content/docs/<tool>/`:
   - title from the first `# heading` into frontmatter, heading removed;
   - HTML comments removed;
   - links to sibling `.md` files rewritten to site paths; links into `docs/dev/` or elsewhere in
     the repository rewritten to GitHub at the same tag;
   - images copied to `public/<tool>/`.
   Pages are written as `.md`, not `.mdx`, if Fumadocs reads `.md` as plain Markdown — then a stray
   `<команда>` or `{` in a generated page cannot break the build. To be confirmed in the spike.
   `content/docs/` is generated and git-ignored; nobody edits it.
3. `next build` with `output: 'export'` writes the static site to `out/`.
4. Cloudflare Pages serves `out/`.

### Languages

- Fumadocs i18n with `en` (default), `ru`, `es` — interface strings, navigation, landing page,
  in all three.
- A page with no translation falls back to the default page (the Fumadocs loader does this:
  [Source API](https://www.fumadocs.dev/docs/headless/source-api)). So `/ru/tg/…` and `/es/tg/…`
  show the English tg page, and `/en/max/…` and `/es/max/…` show the Russian max page.
- **Decided by the spike:** max pages stay in the default slot (see "What the spike found").
  The question was where max pages are stored. Stored in the default
  slot, every language finds them — but they may then be indexed with the English search tokenizer
  (Russian words not found) and built three times, once per language. The other way is to store
  them as Russian and handle the other two languages ourselves.
- max pages Each one carries
  "this page is in Russian" in the reader's interface language, and `lang="ru"` on the article so
  browsers offer translation.
- The first visit to `/` picks the language from the browser (`navigator.languages`) in a few lines
  on the client, then remembers the choice. A static site has no server to read `Accept-Language`
  on; this is the price of static, and it is invisible after the first page.
- Every address carries its language, `/en/max/usage` included: hiding the default language needs
  the Next.js middleware, which a static export does not have.

### For agents

- `/llms.txt` — the index; `/llms-full.txt` — every page in one file; both built statically.
  **Each source page appears once**, in its own language — never once per site language, which
  would triple max in both files.
- A Markdown copy of every page. Fumadocs serves these through a Next.js rewrite from `page.md` to
  a route — **rewrites do not exist in a static export**. Instead the build writes the Markdown
  files straight to `out/…/page.md` after `next build`. Cloudflare serves them as plain files.
- "Copy as Markdown" and "Open in Claude / ChatGPT" on every page.
- The agent skills that ship in each package (`skills/max-cli`, `skills/tg-cli`) are linked from
  each tool's start page, so an agent reading the docs finds the skill.

### Rebuilding

- One GitHub Actions workflow in `cli-docs` builds and deploys with `wrangler pages deploy`. It
  starts on a push to `main`, on a daily schedule (a backstop in case a release signal is lost), and
  on a `repository_dispatch` sent by each tool's release workflow as its last step.
- So everything lives in one file, and the Cloudflare Pages Git integration is not needed. Each
  tool's release workflow needs one secret: a GitHub token allowed to send that signal to
  `cli-docs`.
- To check against the GitHub and Cloudflare docs before it is built; nothing here has been tried.

## The page structure

Every tool follows [STRUCTURE.md](../STRUCTURE.md): the same pages at the same addresses, the
sidebar in the tool's own `docs/meta.json` — owner, 2026-10-01. tg-cli gets its pages written to
it before the portal goes live; max-cli adds `index.md`, `meta.json` and splits `archive.md` out of
`usage.md`.

## Checks

One set of checks for the docs, run the same way in every repository: the portal and each tool.
What max-cli and tg-cli already do is kept and shared, not rewritten.

### Already there, kept

- **Links and anchors** — `docsProblems` in cli-core (`src/release/markdown.ts:125`): every link to
  a file and to a heading, Russian anchors included; no correction marks, struck-out text or
  internal ids on user pages. max-cli calls it; tg-cli still runs its own older copy
  (`scripts/docs-check.ts`) and switches to cli-core's.
- **Secrets** — gitleaks, the binary with a pinned version and checksum, over the whole history in
  CI and over staged changes in the lefthook pre-commit hook; `.gitleaks.toml` for the project's
  own shapes. Copied as it is from max-cli's `ci.yml`.
- **Generated pages are current** — `pnpm generate` then `git diff --exit-code`, as max-cli does.

### New, in cli-core next to `docsProblems`

- **Structure** — the rules in [STRUCTURE.md](../STRUCTURE.md#rules-a-check-enforces): every
  `meta.json` page exists and every page is listed, the required pages are there, one `# heading`
  per page, `meta.json` uses only Fumadocs' keys. One implementation; each repository calls it.

### New, off the shelf

Picked after running each on max-cli's 29 doc files.

- **Spelling — cspell**, English + Russian (+ Spanish later) dictionaries. The only checker that
  found Russian typos; typos and codespell skip Cyrillic. Today it reports 144 words on max-cli,
  mostly names and project words (pymax, опкод, вебхук) and one real typo (`limitt`). The
  reviewed list becomes a shared word list in cli-core; then it blocks.
- **Markdown form — rumdl** (markdownlint's rules, faster, fixes what it finds). Line length off:
  1815 of its 1830 reports today were that one rule. Blocks after one `rumdl fmt` pass.
- **Prose — Vale**, with our own rules: words the house style bans, sentence length, internal ids.
  Rules written with `\p{L}`, not `\w` — with `\w` they silently match no Russian. Warnings only
  at first; it blocks once the rules are tuned.
- **Links outside the site — lychee**, weekly and on release, never blocking a pull request: a
  site being down is not a defect in the change.

Not added: typos and codespell (English only; cspell covers English), Harper (English only),
alex (no release since 2022), LanguageTool (heavy, a Java server; maybe later, by hand),
markdown-link-check (lychee and `docsProblems` cover it).

### How they run

- **One command, `pnpm docs:check`**, in every repository, runs all of the above; CI already calls
  it in max-cli and tg-cli, so the CI files barely change.
- The configurations (cspell word list, rumdl and Vale settings, Vale's rules) ship in cli-core, so
  three repositories do not keep three copies. Each repository may add its own words.
- Vale and gitleaks are single binaries, downloaded in CI with a pinned version and checksum, the
  way max-cli already fetches gitleaks.
- lefthook runs spelling and rumdl on the staged Markdown files; the whole-repository run is CI's.

### Borrowed from max-cli and tg-cli for `cli-docs` itself

pnpm, Biome with the same settings, lefthook (Biome + gitleaks on commit, typecheck on push),
Vitest, GitHub Actions pinned to commits with dependabot moving the pins, the pull-request
template with cli-messaging's review checklist, `CLAUDE.md` and `HANDOFF.md`.

## What the spike found (2026-10-01)

Two real pages (max `usage`, tg `usage`), three languages, `output: 'export'`, built from the
`+next+fuma-docs-mdx+static` template of `create-fumadocs-app`:

- ✅ **Every page is built once per language** (`/en/…`, `/ru/…`, `/es/…`): the interface differs,
  the text is the same. So max pages stay in the default slot, and every language shows them.
- 🔴 **`llms.txt` and `llms-full.txt` list every page three times**, once per language. They get
  their own routes that list the default language only.
- ✅ **Russian search works from every interface language**: a Russian word on the max page is found
  with the English, Russian and Spanish indexes alike, with or without a Russian tokenizer on the
  client. Nothing to do.
- ✅ **`.md` is read as plain Markdown**: `<команда>` and `{` in the text render as text, an HTML
  comment is dropped. The sync script only adds the title to the frontmatter.
- ✅ **The Markdown copy of each page is static already**: the template writes
  `/llms.mdx/docs/<page>/content.md` once per page. Nothing is written after the build.
- ✅ **The first visit picks the language** with a few lines of script on `/`.
