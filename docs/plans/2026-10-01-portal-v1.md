# Plan: the CLI portal, version 1

## Goal

One public docs site for the owner's command-line tools, starting with `max` (max-cli) and `tg`
(tg-cli). People read it in a browser; agents read it as Markdown. Static, on Cloudflare Pages.

## Decisions already made

- ✅ One shared site, a portal that will grow to more tools — owner, 2026-10-01.
- ✅ Its own public repository, `leemour/cli-docs`.
- ✅ Fumadocs, chosen for the agent features it ships itself: `llms.txt`, a Markdown copy of every
  page, "copy as Markdown" and "open in Claude/ChatGPT" buttons
  ([Fumadocs: AI & LLMs](https://fumadocs.dev/docs/integrations/llms)).
- ✅ Static first. The docs MCP server is step 2, not this plan — owner, 2026-10-01.
- ✅ Portal languages: English (default), Russian, Spanish. The first visit follows the browser's
  language. max pages stay Russian only for now — owner, 2026-10-01.
- ✅ Pages are pulled from each tool's repository at its **latest release tag**, never `main`: `main`
  can describe what is not released yet (max-cli `8b978aa` had to take such a page back).

## How it works

### The build, in order

1. `scripts/sync.ts` reads `tools.json` (one entry per tool: repository, which files, language,
   order) and, for each tool, finds the newest `v*` tag with `git ls-remote --tags` — sorted as
   versions, not as text (as text, `v0.9.0` comes after `v0.21.0`), skipping the `^{}` entries — and
   fetches only the listed files at that tag (shallow, sparse clone into a temp directory).
2. The same script turns each file into a Fumadocs page in `content/docs/<tool>/`:
   - title from the first `# heading` into frontmatter, heading removed;
   - HTML comments removed;
   - links to sibling `.md` files rewritten to site paths; links into `docs/dev/` or elsewhere in
     the repository rewritten to GitHub at the same tag;
   - images copied to `public/<tool>/`.
   Pages are written as `.md`, not `.mdx`, if Fumadocs reads `.md` as plain Markdown — then a stray
   `<команда>` or `{` in a generated page cannot break the build. To be confirmed in the spike.
   `content/docs/` is generated and git-ignored; nobody edits it.
3. `next build` with `output: 'export'` writes the static site to `out/`.
4. Cloudflare Pages serves `out/`.

### Languages

- Fumadocs i18n with `en` (default), `ru`, `es` — interface strings, navigation, landing page,
  in all three.
- A page with no translation falls back to the default page (the Fumadocs loader does this:
  [Source API](https://www.fumadocs.dev/docs/headless/source-api)). So `/ru/tg/…` and `/es/tg/…`
  show the English tg page, and `/en/max/…` and `/es/max/…` show the Russian max page.
- **Unsettled, decided by the spike (item 0):** where max pages are stored. Stored in the default
  slot, every language finds them — but they may then be indexed with the English search tokenizer
  (Russian words not found) and built three times, once per language. The other way is to store
  them as Russian and handle the other two languages ourselves.
- max pages Each one carries
  "this page is in Russian" in the reader's interface language, and `lang="ru"` on the article so
  browsers offer translation.
- The first visit to `/` picks the language from the browser (`navigator.languages`) in a few lines
  on the client, then remembers the choice. A static site has no server to read `Accept-Language`
  on; this is the price of static, and it is invisible after the first page.
- Every address carries its language, `/en/max/usage` included: hiding the default language needs
  the Next.js middleware, which a static export does not have.

### For agents

- `/llms.txt` — the index; `/llms-full.txt` — every page in one file; both built statically.
  **Each source page appears once**, in its own language — never once per site language, which
  would triple max in both files.
- A Markdown copy of every page. Fumadocs serves these through a Next.js rewrite from `page.md` to
  a route — **rewrites do not exist in a static export**. Instead the build writes the Markdown
  files straight to `out/…/page.md` after `next build`. Cloudflare serves them as plain files.
- "Copy as Markdown" and "Open in Claude / ChatGPT" on every page.
- The agent skills that ship in each package (`skills/max-cli`, `skills/tg-cli`) are linked from
  each tool's start page, so an agent reading the docs finds the skill.

### Rebuilding

- One GitHub Actions workflow in `cli-docs` builds and deploys with `wrangler pages deploy`. It
  starts on a push to `main`, on a daily schedule (a backstop in case a release signal is lost), and
  on a `repository_dispatch` sent by each tool's release workflow as its last step.
- So everything lives in one file, and the Cloudflare Pages Git integration is not needed. Each
  tool's release workflow needs one secret: a GitHub token allowed to send that signal to
  `cli-docs`.
- To check against the GitHub and Cloudflare docs before it is built; nothing here has been tried.

## Test plan

- `pnpm test` — the sync rewrites, on fixtures.
- `pnpm build` passes, and a link checker over `out/` finds no broken internal link (this is the
  test for the link rewriting on real pages).
- By hand, on the preview address:
  - `/` with the browser in Russian, Spanish, German → `/ru`, `/es`, `/en`;
  - `/llms.txt` lists every page; one `.md` page opens as plain text;
  - search finds a Russian word on a max page and an English word on a tg page;
  - the copy button puts Markdown on the clipboard.
