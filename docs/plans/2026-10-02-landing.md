# Plan: the WireCat landing page

## Goal

`wirecat.dev` opens on a page that says in five seconds what this is, why it suits agents, which
tools there are, and how to connect one. Today it is a heading and two cards.

## Decisions already made

- ✅ The name is **WireCat**; the tagline **AI Messaging with CLI tools for agents** — owner,
  2026-10-02. The header, the browser tab and search results say WireCat.
- ✅ All of the landing page in one go: hero, "built for agents", tool cards, "connect your agent",
  footer — owner asked for this plan, 2026-10-02.
- ✅ `www.wirecat.dev` answers 301 to `wirecat.dev`, path and query kept — a Cloudflare redirect
  rule, done 2026-10-02.
- ✅ Content comes from the tools' repositories or from the program; the portal does not keep a
  second copy of a fact.

## Where things stand

- `app/[lang]/(home)/page.tsx` — the heading, one line, and a card per tool from `tools.json`.
- `lib/words.ts` — the interface words, in English, Russian and Spanish.
- `lib/shared.ts` — `appName = "CLI tools"`.
- `/en/docs` — a short page listing the two tools; it repeats the landing page.
- `scripts/sync.ts` knows each tool's release tag but does not keep it.

## The page, top to bottom

### 1. Hero

- **WireCat**, and under it the tagline.
- One sentence: "Your Telegram and MAX accounts, from the terminal — for you, your scripts and your
  AI agents."
- A terminal block showing what an agent sees, so the point is made without reading: a command and
  its answer, real output shape, invented content.

  ```text
  $ tg inbox --json --limit 2
  {"items":[{"chat":{"title":"Book club"},"from":{"name":"Anna"},"text":"Are we still on for Friday?"},
            {"chat":{"title":"Team"},"from":{"name":"Oleg"},"text":"Release is green"}],
   "limit":2,"hasMore":true}
  ```

  The exact fields are copied from a real `tg inbox --json` run on the test profile before the page
  ships, with every value replaced; the block is static text, not a live call.
- Two buttons: **Get started** (to the first tool's start page) and **GitHub**.

### 2. Built for agents

Three short blocks, an icon each:

- **One call, one answer.** One operation per call; one JSON value on stdout; a fixed exit code for
  every kind of failure. Errors go to stderr, so an empty answer is never a refusal in disguise.
- **Limits you set.** Allowed recipients, a cap on sends per hour, read-only profiles. Nothing is
  sent, marked read or deleted unless the command asked for it.
- **Agents connect themselves.** An MCP server and an agent skill come with each tool; every page is
  plain Markdown for a model (`/llms.txt`).

### 3. The tools

One card per tool, from `tools.json`:

- name and summary (as now);
- **the version** of the release the pages come from — `pnpm sync` writes the tags it used to
  `content/docs/versions.json`, and the card reads it;
- **three things it does** — a new `highlights` field in `tools.json`, three short lines per
  language;
- the install command with a copy button;
- links: Docs · GitHub · npm · Changelog.

### 4. Connect your agent

Tabs, one command each, shown for `tg`; a switch picks the tool:

- **Claude Code, Codex, Gemini CLI** — `tg skill install`
- **Claude Desktop, Cursor and other MCP clients** — `tg mcp config`, which prints the entry to paste
- **Any model** — `https://wirecat.dev/llms.txt`

### 5. Footer

GitHub · licence · the language switch (already in the header) · "Docs as Markdown: /llms.txt".

## The rest of the site

- **Name** — `appName` becomes `WireCat`; the browser tab reads "<page> · WireCat".
- **`/[lang]/docs`** — no page of its own any more: it redirects to the landing page. A static site
  cannot answer with a 301, so the page renders a link and a `refresh` to `/[lang]`; the docs index
  file in `content/docs/` goes.
- **The tool's version on its pages** — a line under the sidebar's tool switch: "v0.22.0 ·
  Changelog".

## Languages

Every new word on the landing page — tagline, the three "built for agents" blocks, the highlights,
tab labels — is written in English, Russian and Spanish in `lib/words.ts` and `tools.json`. The
interface words are short, so they are written here, not by the translation agent; the tools' pages
are still translated later.
