# WhatsApp 0.8.0 reviewed publication

Readers can preview a group or channel invite without joining, list their linked devices, read custom WhatsApp Lists
and the community comments their device received, and see every command in MCP discovery with its availability. Guides
and examples use the canonical shared command names that replaced the 0.6 ones without aliases. The portal targets
published wa 0.8.0 (cli-core 0.411.0). Reviewer: Claude.

## Sources and boundaries

- [Release tag v0.8.0](https://github.com/WireCatLabs/whatsapp-cli/releases/tag/v0.8.0) and the npm package
  `@wirecat/whatsapp-cli@0.8.0`, captured by `pnpm docs:contracts` with network and keyring sockets blocked.
- Claims were checked against the installed package and its contract, not inferred from prose:
  - `chats inspect`, `account sessions list`, `chats folders list|show`, `messages comments`, `search runs`
    (`started_at`, `status`, `error_code`, `operation`, `profile` fields), `bot templates list name:…`,
    `models list kind:audio` and `inbox kind:` exist in the contract with these query fields.
  - `dist/messenger.js` lists `endOtherSessions` and `removeContact` as `never` (hidden: no `account sessions end` or
    `contacts remove` in the contract) and `createFolder`, `updateFolder`, `deleteFolder`, `addContact`,
    `renameContact`, `importContacts` as `lacks` (listed, refused at run time); `channelComments: false`,
    `readsComments: true`.
  - cli-core 0.411 `mcp/server.js` builds the catalogue with `includeUnavailable: true` and `exclude: [["bot"]]`;
    `toolsFromCommands` drops `mcp: false` and any command with a `lifetime`. That leaves `session`, `setup`,
    `complete`, `mcp`, `watch` and `serve` as the only never-offered personal commands. `mcp.authority` and `bot.api`
    default to `deny` in `sends/permissions.js`; `upgrade` is authority-gated.
  - `watch --jsonl` writes `{ "type": "item", "data": … }` records (`cli/messenger/watch-command.js`).
  - Old-file download is still a limitation: the v0.8.0 attachments guide documents it, `dist/reasons.js` keeps
    `media.retry-failed`, the 0.7.0/0.8.0 changelogs claim no fix, and `git log v0.6.0..v0.8.0 -- engine` has no
    media-retry change.

Incoming anchors from v0.6.0 are kept for the renamed command-reference entries (removed commands resolve to their
group) and for the renamed people-guide heading. The retired roadmap "In progress" section is not kept.

The native index and installation pages changed (comparison link, npm 12 `--allow-scripts`), but the portal shows its
own overview and installation pages for wa; the site-owned installation already covers blocked install scripts.
`translations/wa/index.*` and `translations/wa/installation.*` are never read for that reason and were left as they were.

The native 0.8.0 changelog repeats four 0.7.0 entries (invite preview, sessions list, Lists, community comments) and
two fixes; that is upstream text and is published as released.

No live WhatsApp action was performed for this publication. The new read commands were not run against an account.
