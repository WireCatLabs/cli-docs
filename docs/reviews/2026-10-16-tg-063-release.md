# tg 0.63.0 shared category file review

Reviewer: Claude. Portal base: `be4796a`; final rebase recorded in the PR.
Reviewed runtime: tg `v0.63.0`, commit `d8628cfebf028e92a62f62b2a084402b475a86ec`,
Core `0.298.0`, Base `0.40.0`. Compared native guides, skill and changelog against `v0.62.0`
(Core `0.296.0`). Other runtime pins are unchanged: MAX `v0.56.0` (Core `0.296.0`) and Memo
`v0.45.0` (Core `0.293.0`) do not read the shared file, so the shared pages say that only `tg` does.

Readers can now change the task category list in one shared settings file, see where `tg` reads
it from, and know what happens to a list saved in the store and to `max` and `memo` when `tg`
moves it. Changed native prose was translated in RU/ES (the native guides are English); the
shared Tasks and How tasks work pages were revised in EN/RU/ES.

## Evidence

- tg tagged diff `v0.62.0..v0.63.0`: `CHANGELOG.md` (0.63.0 entry), `docs/groups.md` (one new
  paragraph and JSON example after the `tasks add` block), `skills/tg-cli/SKILL.md` (one comment
  line; the portal does not import skills), `package.json` (Core 0.298.0). `docs/commands.md` and
  `docs/roadmap.md` unchanged.
- cli-core `CHANGELOG.md` 0.297.0 (mail only) and 0.298.0; `docs/dev/tasks-plan.md` "Categories
  and labels"; `src/store/shared-config.ts` (path rule, edits applied on the base list, refusal
  with path, reread on change); `src/cli/store-settings.ts` (a store-saved list is turned into
  edits and dropped from the store on the next `config set`/`unset`; `config show` `from`).
- cli-base 0.40.0 `src/paths.ts`: XDG layout on Linux and macOS, `%APPDATA%\WireCat\Config` on
  Windows.
- npm `@wirecat/tg-cli@0.63.0` run with `env -i` and a throwaway HOME: `config set
  task_categories.garden`, `config unset task_categories.religion` wrote
  `<tmp>/.config/WireCat/config.json` with `scope: "shared"` and `file`; `config show` marked
  `garden` with `from: <file>` and defaults with `from: "default"`; a non-string value was refused
  with exit 3 and the file path; `config unset task_categories` dropped only the section.
  `tasks categories` needs a profile and was not run; its `file` field is from the source above.

## Remaining native source discrepancy

- tg `docs/groups.md` and `CHANGELOG.md` 0.63.0 call the file one that "tg, MAX and memo share".
  At the current pins only `tg` reads it (MAX 0.56.0 is on Core 0.296.0; no newer MAX is released).
  The translations follow the native text; the shared pages state the boundary. Owner: tg-cli; no
  portal correction was added.
- Not changed: the generated data model describes `store_settings` generally ("shared by all
  profiles, tg and MAX") and does not mention the category list; owner cli-core `docs/storage/schema.md`.
- Probable site inconsistency, not verified on a Mac: `content/docs/configuration*.mdx` gives
  `~/Library/Preferences/tg-cli/config.json` for macOS, while tg's tagged `docs/configuration.md` and
  cli-base 0.40.0 `paths.ts` use `~/.config/tg-cli/config.json` on Linux and macOS.
