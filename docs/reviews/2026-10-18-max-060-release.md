# MAX 0.60.0 release review: task rules, `tasks scan`, assignees, no default profile, `mcp --permission` only tightens

Reviewer: Claude. Portal base: `6e31928`.
Reviewed runtime: MAX `v0.60.0`, commit `c41c9ea05df2de66132f6edb7ba87f8704f59855`, Core `0.326.0`, Base `0.43.5`.
Compared native guides and changelog against the previous pin `v0.58.0`, so this review covers 0.59.0–0.60.0.
Other runtime pins are unchanged.

Readers of the MAX pages now learn that tasks open only where something was asked of them, that `tasks apply` is
`tasks scan` and a task has an assignee, that a profile is never assumed and `default_profile` is no longer read,
that `mcp --permission` only narrows a profile, that an agent never deletes for everyone, and what 0.59.0 and 0.60.0
changed. The shared Tasks pages describe MAX's task rules as they are at this pin.

- MAX tagged diff `v0.58.0..v0.60.0`: `CHANGELOG.md` (0.59.0, 0.60.0), `docs/commands.md` (generated: profile
  introduction without `defaultProfile`, `tasks scan`, `--assignee` on `tasks add` and `tasks plan`,

  gone), `docs/mcp.md`, `docs/permissions.md`, `docs/remote.md` (`--permission` only tightens; startup commands no

  changed but is not a portal page.
- The `v0.60.0` tag commit differs from `3e7a09e3` (the commit the Tasks claims were checked against in this PR)
  only by max#720: the cli-base 0.43.0 → 0.43.5 bump, the lockfile and one test line. No source or docs change.
- cli-core `v0.326.0` `src/sends/permissions.ts:469`: a `--permission key=level` that would loosen the profile's
  level is refused.
