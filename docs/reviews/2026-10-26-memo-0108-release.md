# Memo 0.108.0 release review

A reader of the configuration page now learns from Memo's own text that run keys are added by hand and that
`memo config unset <key>` removes one, and the release notes describe the 0.108.0 mail-parsing fix and the faster
`memo --version`. This review moves the site from Memo 0.107.0 to 0.108.0.

## Source and scope

`@wirecat/cli-memo@0.108.0`), built on cli-core 0.431.0 and cli-base 0.57.1 (the package's exact dependencies;
cli-base moved from 0.57.0). Between `v0.107.0` and `v0.108.0` cli-memo changed one guide line

## Portal correction retired

The 0.107.0 review added a `before-translation` correction for `configuration.md`, which said "Memo has no `config`
command". cli-memo fixed the sentence at the source in 0.108.0, so the correction no longer matches and is removed
from `scripts/docs-corrections.json`. The RU/ES pages now translate the native sentence.

## Runtime evidence

`pnpm docs:contracts` captured the 0.108.0 command tree with the network disabled. On the packed release
(`npm pack @wirecat/cli-memo@0.108.0`), with HOME, XDG folders and the store pointed at an empty scratch folder
(no owner data):

- `memo --version` prints `0.108.0` and exits 0 in about 0.07 s, against about 0.5 s for `memo --help`;
  `memo --version --help` also prints the version.
- `memo config --help` lists `unset` as the only subcommand, matching the new configuration sentence.
- A synthetic config with `default_profile` was refused with `configuration_error` naming
  `memo config unset default_profile`; that command removed the key and left the file `0600`.

Not run: the postal-mime 4.1.4 parsing change. It is stated from the changelog and the package's exact
`postal-mime` dependency; the portal has no page that describes malformed-message parsing.
