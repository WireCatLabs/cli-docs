# tg 0.71.0 release review: watched groups, bot MCP tools, `mcp --permission` only tightens

Reviewer: Claude. Portal base: `559141e`.
Reviewed runtime: tg `v0.71.0`, commit `6bdf8bd9bdc2e04aa8ca94ce97d3377cf8ba8ceb`, Core `0.326.0`, Base `0.43.0`.
Compared native guides and changelog against the previous pin `v0.68.0` (#292), so this review covers 0.69.0–0.71.0.
Other runtime pins are unchanged; MAX `v0.58.0` (Core `0.315.0`) still accepts a looser `--permission` level.

Readers of the tg pages now learn that in a `watch-tasks` group any member's reply closes a question and a later
message that does not reply closes nothing, that `mcp --permission` only narrows a profile, that an agent never
deletes for everyone, and that the bot's MCP tools take the commands' own arguments.

  records and what closes it, `tags remove`), `docs/commands.md` (generated: no `defaultProfile` in the introduction,
  `contacts link … me`, `--transcribe` wording, `default_profile` gone from `config set`, `--permission` tightens),
  `docs/bot.md` (bot MCP tools are the commands), `docs/mcp.md`, `docs/permissions.md`, `docs/remote.md`,
  `docs/configuration-reference.md` (`--permission` only tightens; examples no longer pass `messages.send=allow`).
  `docs/roadmap.md` unchanged (fingerprint `978bfe80…`).
- cli-core `v0.326.0` `src/sends/permissions.ts:469`: a `--permission key=level` that would loosen the profile's
  level is refused ("it only tightens — change the profile's permissions to loosen it").
- MAX `v0.58.0` released `remote.md` and `permissions.md` still use `--permission messages.send=allow`.
