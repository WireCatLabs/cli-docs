# Спорные предложения по документации

Это предложения для отдельного обзора. Они не внедрены в исходные руководства. Ссылки ведут
на локальное превью; перед публикацией изменения нативных страниц проходят проверку в
репозитории соответствующего инструмента.

## 1. Обновить техническую архитектуру поиска целиком

[Как устроен поиск](http://localhost:3000/ru/docs/search-architecture).

**До:** «Нечёткий поиск, близость слов, веса и интервалы отвергаются явной ошибкой».

**Предлагаемый вариант:** «В строгом языке запросов поддерживается определённый набор
операторов. Поиск с опечатками и поиск обсуждений по смыслу используют отдельные режимы;
их доступность и ограничения перечислены в руководстве вашего мессенджера».

**Почему спорно:** исходные ссылки описывают старый срез `cli-messaging`, а вводная часть уже
ссылается на новые релизы. Прежде чем менять формулировку, нужно сопоставить каждый режим
с реализацией TG v0.37 / MAX v0.36, затем обновить всю карту исходников. Простая замена
одного предложения может скрыть важную границу между строгим и прежним режимом.

## 2. Перенести статус проверки из начала нативного удалённого подключения

[MAX: удалённое подключение](http://localhost:3000/ru/docs/max/remote).

**До:** «Статус: HTTP и права проверены локально. Владелец подтвердил чтение и отправку
через Claude web в Telegram 07.10.2026…».

**Предлагаемый вариант:** «Подключите MAX к ChatGPT или Claude на другом устройстве.
Вы получите адрес подключения, войдёте в приложение и проверите доступ запросом к своим
чатам». Свидетельства проверки перенести в блок «Что проверено» после шагов.

**Почему спорно:** статус содержит полезные границы доказательства. Их нужно сохранить,
а не превращать проверку Telegram в обещание проверенного поведения MAX. Общая инструкция
и переход к ней уже улучшены; сам статус источника пока сохранён.

## 3. Перестроить большие руководства по использованию вокруг задач

[Telegram: использование](http://localhost:3000/ru/docs/tg/usage),
[MAX: использование](http://localhost:3000/ru/docs/max/usage).

**До, Telegram:** «Каждая команда выполняет одно действие…»; далее идут вход, профили,
указание чата, чтение и длинный список отдельных операций.

**Предлагаемый вариант:** «Выберите задачу: прочитать переписку, найти сообщение,
сохранить файл или подготовить ответ. Для каждой ниже есть запрос агенту и результат,
который можно проверить. Точный синтаксис раскрывается отдельно».

**Почему спорно:** эти страницы одновременно служат руководством и справкой для агентов.
Для перестройки нужны сохранение всех старых якорей и проверка Markdown-потребителей.
Уже есть понятные общие задачи и лёгкий индекс команд; дробить руководство на множество
новых страниц без проверки необходимости не предлагается.

## 4. Заменить оценочные заголовки проверки людей

[Telegram: люди](http://localhost:3000/ru/docs/tg/people),
[MAX: люди](http://localhost:3000/ru/docs/max/people).

**До, MAX:** «Бот, фейк или спамер: `contacts check`».

**Предлагаемый вариант:** «Проверить признаки аккаунта: что известно и чего недостаточно
для вывода».

**Почему спорно:** команда возвращает признаки, а не достоверный вердикт о человеке.
Тело уже объясняет ограничения; название нужно согласовать с публичным описанием команды
и сохранить входящие якоря. Назначение страницы и ссылка к понятной задаче уже добавлены.

## 5. Дать отчётам об активности один полный пример с неполными данными

[Отчёты Telegram](http://localhost:3000/ru/docs/tg/rankings),
[отчёты MAX](http://localhost:3000/ru/docs/max/rankings).

**До, MAX:** «Статистика расположена в `stats → ресурс → вид`…».

**Предлагаемый вариант:** «Проверьте, какие вопросы группы требуют внимания. Отчёт должен
показать вопросы, исходные сообщения и охваченный период. Если часть переписки отсутствует,
он перечисляет пробелы, а не делает вывод о работе человека».

**Почему спорно:** новые метрики используют разные выборки, наблюдения и правила полноты.
Нужен проверенный искусственный пример с отсутствующей историей и счётчиками, чтобы текст
не обещал единый показатель полноты для всех отчётов. В общей странице администраторов
уже есть запрос и проверка результата.

## 6. Не обещать одинаковую мобильную поддержку для всех приложений

[ChatGPT, Claude в браузере](http://localhost:3000/ru/docs/browser-apps).

**Сейчас:** «В Claude подключёнными инструментами можно пользоваться и в мобильном приложении».

**Возможное расширение:** «Используйте подключение из браузера или мобильного приложения
ChatGPT/Claude».

**Почему не применено:** мобильный Claude прямо описан в [официальной инструкции](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp).
[Проверенная инструкция OpenAI](https://developers.openai.com/plugins/quickstart) показывает
личный MCP-плагин в ChatGPT Work на вебе. Это недостаточно, чтобы обещать одинаковые
настройки и доступность такого подключения в каждом мобильном клиенте и аккаунте.

## 7. Подробный вариант постоянно работающего сервера

[Подключение без включённого ноутбука](http://localhost:3000/ru/docs/browser-apps#подключение-без-постоянно-включённого-ноутбука).

**Сейчас:** «Настройте автоматический запуск после перезагрузки: и программа мессенджера,
и публичный доступ должны работать постоянно».

**Предлагаемый вариант:** отдельный проверенный раздел со службой автозапуска, системным
пользователем, доступом к хранилищу ключей и проверкой после перезагрузки.

**Почему спорно:** точные шаги зависят от ОС сервера и хранения авторизации. Пока добавлен
понятный вариант и проверка с выключенным ноутбуком. Универсальная команда автозапуска без
проверки окружения могла бы дать обещание постоянной работы при недоступных данных входа.

## 8. Отделить пояснение источников от технического отчёта оценивания

[Безопасность](http://localhost:3000/ru/docs/security#как-проверяют-работу-ассистента).

**До прохода:** «Что показывают evals» с отчётом об искусственных сценариях, контекстах,
preview, evidence и ограничениях SDK.

**Возможный следующий вариант:** короткий пользовательский блок «Проверяйте источники,
полноту истории и выполненные действия», а полный протокол оценки — по ссылке на техническую
страницу или в раскрываемом блоке.

**Почему спорно:** сведения добавлены недавним обзором на main и важны для оценки заявлений
о поведении агента. Сейчас сохранён отчёт, объяснено назначение проверок и убран лишний
английский жаргон; перемещение всего раздела требует отдельного обзора его роли.
