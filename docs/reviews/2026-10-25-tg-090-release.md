# Telegram 0.90.0 reviewed publication

Readers find the bot's history import under its new name, `bot messages sync`, filter a person's activity
with `scope:` and `at:` queries, and search diagnostic runs with `started_at:` instead of a time flag. A banned
account is reported as a permission error. The portal targets published tg 0.90.0 with Core 0.412.0.
Reviewer: Claude.

- Claims checked in the installed 0.90.0 package (`dist/`), not inferred from prose:
  - `bot messages sync` exists with `--limit`, `--page-size`, `--pause`, `--since-time`, `--last` and
    `--until-id`; `bot store` and `bot store fetch` are gone. Core `cli/moved.js` maps the old path to the new

  - `USER_DEACTIVATED_BAN` maps to `permission_error` (exit code 5 in the contract's `exit_codes`).
  - `contacts events` takes a query with `scope:` (personal, work) and `at:` (term, phrase, range) and has
    only `--limit` and `--cursor`; `search runs` has only `--limit` and `--page`, with a `started_at:` field.
  - Never-offered commands are unchanged from 0.88: `mcp: false` or a `lifetime` on `session`, `setup`,

    drops any command with a `lifetime`. The contract still has no `chats delete` or `chats clear`.
  - The `grantsAuthority` call sites in Core 0.412.0 are identical to Core 0.408.0; `upgrade` is wrapped
    (`upgrade --check` exempt).
  - `commands info bot messages sync` reports permission `bot.messages`; `DEFAULT_PERMISSIONS` has no
    `ask` entry for it, so it has no ask-by-default key of its own.

## Upstream issues still open in 0.90.0

- BUG-391 (MCP never-offered and authority lists) and BUG-392 (empty **Returns** field list for
  `messages send` and other union outputs in the generated reference) were fixed on tg-cli main after
  v0.90.0 was cut. BUG-391 stays covered by the portal correction. BUG-392 is generated output and is not
  hand-edited; the 0.90.0 reference still has 41 such lines, among them `**Returns:** message send — ;`.
- `docs/bot.md` names the start option `--from`; the contract has `--until-id`. Two package errors in
  `telegram/bot-history.js` also still say `--from`.
- `docs/mcp.md` lists `bot messages sync` among commands with their own ask-by-default keys; the package
  gates it with `bot.messages`. The 0.90.0 changelog tells readers to rename a saved key to
  `permissions.bot.messages.sync`, but `levelFor(…, "bot.messages")` ignores that child key, so a renamed
  `deny` may not block the command: Core's early refusal and command availability both look up
  `keyForCommand`, which gives `bot.messages`. Read from the code, not verified by running the command.
