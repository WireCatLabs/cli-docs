# Telegram 0.92.0 reviewed publication

Readers can now repair a broken settings file from `tg doctor`, which lists every problem with the command that
removes it, and see when other users of the computer can read their settings. Permission keys for history sync
(`messages.sync`, `bot.messages.sync`) are documented and honoured, and the retired `default_profile` and
`analysis_*` settings are gone from every guide. The portal targets published tg 0.92.0 (covering 0.91.0) with
Core 0.428.0 and Base 0.57.0. Reviewer: Claude.

## Sources and boundaries

- [Published release](https://github.com/WireCatLabs/tg-cli/releases/tag/v0.92.0) and
  [npm package](https://www.npmjs.com/package/@wirecat/tg-cli/v/0.92.0) (integrity
  `sha512-WZ23xLvyI58BeVhPfdRSiYt/HzId/pzqgZpQ1pFRviqmABdIQzI6CUCgEwabViGhT00nh/0JMTeuEtzexl3LNw==`).
- The exact command contract was captured by `pnpm docs:contracts` (isolated home, network and keyring sockets
  blocked). Behaviour below was run against the installed 0.92.0 package in a throwaway home with a fictional
  profile `work`, no login and the network blocked; nothing touched a real account.
- Run, not inferred:
  - `config set` writes `config.json` as `0600` in a `0700` folder. After `chmod 644`/`755`, `doctor --json`
    reports both under `files.problems` as `{ path, mode, want }`, and stderr prints
    `to make it private: chmod 600 '<path>'` (and `chmod 700` for the folder), also with no profile named.
  - A file with `limt`, `default_profile`, `analysis_provider` and `permissions.chats.bogus`: `doctor --json`
    exits 0 and lists four `config.issues` (`unknown_setting` ×3, `unknown_permission`), each with `what` and
    `fix` (`tg work config unset limt`, `tg config unset default_profile`, …). `search messages` on that file
    exits 3 with `…config.json: setting limt is not a setting of tg — remove it with \`tg work config unset limt\`
    (and 1 more problem — \`doctor\` lists them all)`. `config show` still runs and warns per problem;
    `config unset` removes each one. Broken JSON gives one `invalid_json` issue with `line` and `column`.
  - `config set permissions.messages.bogus` is refused (exit 2) and lists the known `messages.*` keys, including
    `messages.sync`. A saved `permissions.messages.sync: deny` stops `messages sync`, and a saved
    `permissions.bot.messages.sync: deny` stops `bot messages sync`, both with `permission_error` (exit 5) before
    connecting.
  - `search mail` is an unknown command; `search all --only mail` is refused with a pointer to `memo search mail`.
  - `skill status` reports `claude` and `agents` targets; `runs list` records `cli_command`, `argv` and `agent`.
- Checked in the package (`dist/`): the contract marks `setup`, `watch`, `serve`, `bot watch` with a `lifetime`
  and `complete`, `mcp`, `bot mcp`, `bot auth` with `mcp: false`; Core `mcp/agent.js` drops both from the
  catalogue. `upgrade` (not `--check`) and `attachments jobs install|start|stop|uninstall` are wrapped in
  `grantsAuthority`. `DEFAULT_PERMISSIONS` has no `ask` default for `bot.messages.sync`, and the contract still
  has no `chats delete` or `chats clear`. `skill show --for <agents>` and `store tables list` exist; `--full` is a
  global option.
