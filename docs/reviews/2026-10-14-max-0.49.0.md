# MAX 0.49.0 release review

Reviewer: Claude. Reader task: keep using max after the update — name a profile in every account command, find the archive in the WireCat folder, download history with `messages sync`, read search excerpts, schedule commands or a read-only agent and track tasks — in English, Russian and Spanish.

## Sources and scope

Reviewed max-cli v0.45.5, v0.46.0, v0.47.0, v0.48.0 and v0.49.0 from the `CHANGELOG.md` and `docs/` diff between tags `v0.45.4` and `v0.49.0` of [WireCatLabs/max-cli](https://github.com/WireCatLabs/max-cli/compare/v0.45.4...v0.49.0). The release builds on `@wirecat/cli-messaging` 0.259.0 and `@wirecat/cli-base` 0.24.0. The command contract was captured from the published npm package with network and keyring blocked (`pnpm docs:contracts`).

Runtime changes that reach reader pages:

- **No implicit profile.** A command that needs an account and has no profile word, `MAX_PROFILE` or `defaultProfile` stops with exit code `2` and lists the profiles, even when there is one. Every native command example now names a profile (`max personal …`, `max work …`).
- **`store fetch` is `messages sync`**, with the same arguments and JSON; the old name is hidden.
- **Shared archive and speech models move to the WireCat folder** (`~/.local/share/WireCat/`, Windows `%LOCALAPPDATA%\WireCat\Data\`); `WIRECAT_STATE_DIR` replaces `CLI_COMMON_CACHE_DIR`; two different copies stop the run with exit code `3`. macOS uses the Linux folders since 0.46.0.
- **One error object** `{"error":{"code","reason","message","details"}}`; code `1` is `internal_error`; `--debug` prints the whole failure record.
- **Search:** hits carry `excerpt` instead of `text` (`--full` for the whole text), `--brief`/`--full` on every command, account groups in `--source`, `date:>=` comparisons, mail filters, and a cross-account server-search fix.
- **New commands:** `max schedule` (timer-driven command or read-only agent), `tasks plan/link/agenda`, `MAX_READ_ONLY=1`.

Native guide bodies changed on every page except `permissions` and `roadmap`. Most of the change is the profile word and the `messages sync` rename inside commands; prose changed in sessions, profiles, usage, recipes, bot, people, troubleshooting, archive, groups, search, cli-contract, configuration, configuration-reference, query-language, commands and changelog.

## Corrections

- Updated the `before`/`after` text of the sessions and usage corrections (QR login steps, token lifetime, harness-neutral setup, shell exit status, message link) to the profile-named commands. Their problems are still present in v0.49.0, so they stay.
- Removed the two `installation` corrections: the page is site-owned, `localize` writes it before any correction applies, so they could no longer take effect.

## Remaining source discrepancies

- The native installation table still lists `~/Library/…` for macOS settings, state and cache, while the 0.46.0 changelog moved macOS to the Linux folders. Owner: max-cli `docs/installation.md`.
- Site-owned pages and the homepage demo still show profile-less `max` commands (`max chats list`, `max messages send`, `max serve` in shared guides, landing fixtures and architecture diagrams). These are not part of a release import and need their own pass.
