# WhatsApp 0.10.0 reviewed publication

Readers learn that `wa` now saves its settings file readable by them only, that `wa doctor` lists every problem in that
file with the command that removes it and names private files other users can read, that `chats mute` and
`chats unmute` have separate permission keys, and that old setting names are refused. The reference gains
`skill status`, `skill show --for` and `store tables list`. The portal targets published wa 0.10.0 (cli-core 0.428.0,
cli-base 0.57.0); 0.9.0 is covered by the same update. Reviewer: Claude.

## Sources and boundaries

- [Release tag v0.10.0](https://github.com/WireCatLabs/whatsapp-cli/releases/tag/v0.10.0) and the npm package
  `@wirecat/whatsapp-cli@0.10.0`, captured by `pnpm docs:contracts` with network and keyring sockets blocked.
- `git diff v0.8.0 v0.10.0 -- docs` touches only `commands.md`, `configuration-reference.md`, `diagnostics.md` and
  `permissions.md` (plus `docs/dev/`, which the portal does not publish) and `CHANGELOG.md`. The roadmap is unchanged.
- Contract checks: `skill status`, `skill show --for <claude|agents>`, `store tables list [query]` (entity
  `store_table`), and `conversations links rebuild --model|--base-url` exist as documented; `config set|unset` list no
  `analysis_*` or `default_profile`.
- Package checks: cli-base `config.js` writes the file `0o600` and creates its folder `0o700`; cli-core
  `messenger/doctor-command.js` and `private-files.js` build `files` from the config file and folder, the store with
  `-wal`/`-shm`, the send journal, the flood file and the runs folder, and return `checked: false` on win32;
  `config-issues.js` emits `invalid_json` (no `fix`), `unknown_setting`, `unknown_permission`, `missing_setting`,
  `invalid_value`.
- Runtime probes with `scripts/cli-sandbox.ts` (temporary HOME, network disabled, a synthetic `personal` profile, no
  device linked):
  - a new config file is `0600` in a `0700` folder; after `chmod 644`/`755`, `doctor --json` lists both in
    `files.problems` and stderr prints `to make it private: chmod 600 '<path>'`; `config set` restores the file to `0600`
    and leaves the folder at `0755`;
  - with `default_profile`, `analysis_provider` and an unknown permission key in the file, `doctor` exits 0 with three
    `config.issues`, each with a `fix`; `wa personal chats list` exits 3 naming the first problem and "2 more problems";
    `config show` still runs and names each ignored key; each printed `fix` (`wa config unset default_profile`,
    `wa personal config unset permissions.no.such.key`) runs and leaves `config.issues` empty. The profile-scoped form
    `wa personal config unset default_profile` is refused (exit 2), so the file-level `fix` is the one to run;
  - invalid JSON gives `invalid_json` with line and column and no `fix`;
  - `permissions.chats.mute readonly` refuses `chats mute` (exit 5) and does not refuse `chats unmute`, which stops
    later only because no device is linked;
  - `skill status` reports both install targets as `missing`; `store tables list --json` lists tables with `kind` and
    `rows`.

## Reader-path review

Each row covers EN/RU/ES. Code fences, literals, link destinations and heading structure were checked by
`pnpm docs:translation check`; the changed prose was read in full.

| Pages | Result and review |

| configuration-reference | `default_profile` sentence and the three `analysis_*` rows gone; `WA_ANALYSIS_*` gone from the variables; new paragraphs on the `0600`/`0700` modes and on what a file with problems stops. RU wording limits "keeps it so" to the file, matching the probe. |
| diagnostics | New `config.issues` and `files` paragraphs. The Windows erratum now covers the new `files` sentence too. RU/ES: the `engine` item had been glued to the paragraph before it and did not render as a list item; fixed in the translation and in the correction that quotes it. |

No old setting name remains outside the changelogs in `content/docs/wa` (3 locales), `lib/`, `components/` or
`tests/`. The wa pages carry no anchor alias for a renamed heading or command.

## Errata re-checked

- Old files (roadmap and usage, kept): the roadmap and the attachments guide are unchanged, `dist/reasons.js` still
  carries `media.retry-failed`, and the 0.9.0/0.10.0 changelogs claim no fix.
- MCP "Commands kept in the terminal" (kept): the 0.10.0 contract marks `session`, `setup`, `complete` and `mcp` as
  `mcp: false` and gives `watch` and `serve` a persistent lifetime; cli-core 0.428 `mcp/server.js` still uses
  `includeUnavailable: true` and excludes `bot`.
- The other wa corrections sit on pages that 0.10.0 did not change, and each still matches exactly once.

## Not verified

- No live WhatsApp action; nothing ran against a linked device.
- The `files` check of the store, send journal and runs folder was read in the source, not probed with loose modes.
- A `fix` is also omitted for a key or profile name a shell would split, and for `missing_setting`; the native page
  says "all but invalid JSON". Left as released: the difference does not change a reader's next step.
