# MAX 0.76.0 reviewed publication

Readers find every problem in their settings file with `max doctor --json` (`config.issues`, each with a runnable
`config unset` fix) and see whether other users can read `config.json` or its folder (`files`). `config set` now writes
the file owner-only (`0600`). Old and unknown settings and permission keys stop commands until removed, and
`config show|set|unset` still work to repair the file. New commands: `skill status`, `skill show --for`,
`store tables list`. The portal targets published max 0.76.0 (0.75.0 and 0.76.0 both covered) with Core 0.428.0 and
Base 0.57.0; the previous pin was v0.74.0. Reviewer: Claude.

## Sources and boundaries

- [Published release](https://github.com/WireCatLabs/max-cli/releases/tag/v0.76.0), commit
  `d8c2911072aa259c89e1d375ae36345c3f4367a7` (annotated tag object `c677912…`). npm tarball integrity
  `sha512-0HPEOHGMu2w7…zyo+ow==`.
- Exact npm discovery was captured by `pnpm docs:contracts` with an isolated home and blocked network/keyring sockets.
  Behavior was checked by running the installed 0.76.0 package in a scratch sandbox (temporary `HOME`, `XDG_*`,
  `MAX_*_DIR`, network blocked by `scripts/discovery-offline.mjs`) against synthetic `config.json` files:
  - A file with `default_profile`, `sendsPerHour`, `allow`, `analysis_provider`, `permissions.messages.stats` and an
    invented permission key: `doctor --json` exits 0 and lists six `config.issues` (`unknown_setting`,
    `unknown_permission`), each with a `fix` such as `max config unset --defaults sendsPerHour`. `chats list` stops with
    `configuration_error` naming the first key and "(and 4 more problems — `doctor` lists them all)". `config show`
    still answers. Running each `fix` as written emptied `config.issues`.
  - Invalid JSON gives `kind: invalid_json` with `line` and `column`, no `fix`.
  - A `0644` file in a `0755` folder gives `files.problems` with `want` `0600`/`0700` and stderr lines
    `to make it private: chmod 600 '<path>'`. `config set` and `config unset` rewrote the file as `0600`; the folder
    mode was left unchanged. With no file, `doctor` answers `config.found: false` and creates nothing.
  - `permissions.messages.sync: deny` stops `messages sync --dry-run` with `permission_error` naming `messages.sync`.
  - `skill status --json` lists both install targets with `state`; `skill show --for` takes `claude` or `agents`;
    `store tables list` exists with `name`/`kind` query fields; `max --help` names `max account list`.
  - The installer reads only `MAX_INSTALL_AGENT` (`dist/install/postinstall.js`). cli-base `config.js` writes with
    `0o600` and creates folders `0o700`.

## Old names

Native pages other than the changelog no longer name `default_profile`, `analysis_*`, `MAX_ANALYSIS_*`, camelCase
settings, the old `allow` setting or the mail hint; the EN/ES translations follow. The portal's shared pages name only
`MAX_INSTALL_AGENT` for max. The security page keeps one sentence that a config file from an earlier version can stay
`0644` until it is rewritten: that is a file mode, not an old name, and `doctor` reports it.
