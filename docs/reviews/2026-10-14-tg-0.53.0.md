# tg 0.53.0 release review

Reviewer: Claude. Reader task: keep using tg after the update — name a profile in every account command, download
history with `messages sync`, find the local store in the WireCat folder, read search excerpts, schedule commands or
a read-only agent and track tasks with plans and an agenda — in English, Russian and Spanish.

## Sources and scope

Reviewed tg-cli 0.47.0, 0.48.0, 0.48.1, 0.49.0, 0.50.0, 0.51.0, 0.52.0 and 0.53.0 from the `CHANGELOG.md` and `docs/`
diff between tags `v0.46.3` and `v0.53.0` of
[WireCatLabs/tg-cli](https://github.com/WireCatLabs/tg-cli/compare/v0.46.3...v0.53.0). The release builds on
`@wirecat/cli-core` 0.262.0 (the new name of `@wirecat/cli-messaging`) and `@wirecat/cli-base` 0.26.0. The command
contract was captured from the published npm package with network and keyring blocked (`pnpm docs:contracts`).

Runtime changes that reach reader pages:

- **No implicit profile** (0.52.0). An account command with no profile word, `TG_PROFILE` or `defaultProfile` stops
  with exit code `2` and lists the profiles, even when there is one. Measured in an empty sandbox with the released
  package: `tg chats list` answers `{"error":{"code":"validation_error","reason":"input.invalid","message":"name a
  profile: …"}}`. `--help`, `--version`, `commands`, `skill show`, `account list`, `config show`, `complete`,
  `upgrade` and `config set … --defaults` run without one; `doctor`, `setup`, `mcp config` and `mcp doctor` need one.
- **`store fetch` is `messages sync`**, same arguments and JSON; the old name is hidden. `bot store fetch` keeps its name.
- **Local store and speech models move to the WireCat folder** (`~/.local/share/WireCat/`, Windows
  `%LOCALAPPDATA%\WireCat\Data\`); `WIRECAT_STATE_DIR` replaces `CLI_COMMON_CACHE_DIR`; two different copies stop the
  run with exit code `3`. macOS uses the Linux folders since 0.48.0 (cli-base `resolvePaths` uses XDG on macOS).
- **One error object** `{"error":{"code","reason","message","details"}}`; exit code `1` is `internal_error`;
  `--debug` prints the whole failure record. Machine output keys are snake_case (0.53.0).
- **Search:** hits carry `excerpt` instead of `text` (`--full` for the whole text), `--brief`/`--full` on every
  command, account lists and groups in `--source`, `date:>=` colon comparisons, HTML read as main text.
- **New commands:** `tg schedule` (timer-driven command or read-only agent), `tasks plan/link/agenda` with the
  `follow-ups` skill, `TG_READ_ONLY=1`.

Every native guide changed except `compare`, `permissions` and `roadmap`. Most of the change is the profile word and
the `messages sync` rename inside commands; prose changed in changelog, commands, troubleshooting, sessions,
profiles, configuration, usage, groups, search, people, mcp, security, query-language, rankings and installation.

The portal's "How commands work" block already states the explicit-profile rule for tg and max (since #189); its
global options (`--json`, `--dry-run`, `--offline`, `--yes`) match the 0.53.0 contract, so it is unchanged.

Copyable tg commands on the shared guides now name the profile: agents, browser apps, configuration, drafts, email,
first tasks, group admins, MCP, people, search, search architecture, security, and the report example in
`lib/report-tasks.ts`. Descriptive mentions of the `tg mcp` server process stay. Profile-free commands stay as they
are (`tg config show`, `tg config set … --defaults`). The search architecture and prompting pages now name
`messages sync` for both messengers.

## Corrections

- Updated to the profile-named commands, problems still present in 0.53.0: shell exit status (`if !`), invite-link
  flags, unknown command (exit code `2`, re-measured: the JSON example now has the `code/reason/message` shape and
  exit `1` is `internal_error`), sessions profile explanation (`personal` instead of `default`).
- Kept unchanged, still needed: `--unanswered [hours]` (the contract takes a duration), registration estimate,
  bot joins, decline accounting, topic repeat safety, anchors.
- Added the `tg-store-fetch` anchor to the renamed `tg messages sync` entry.
- Added one correction: the tg search guide names `memo sync --mail`, which does not exist in the pinned memo 0.21.0.
  There mail and notes are imported with `memo import --mail` and `memo import --notes`. Drop it when the memo pin moves.
- Removed the two `installation` corrections: the page is site-owned since #197, so `localize` never applies them.

## Remaining source discrepancies

- The generated `search mail` description in the command reference still says `memo sync --mail` brings mail in,
  in all three languages; it is the program's own help text. Same memo pin gap as above.
- The native installation table still lists `~/Library/…` for macOS settings, state and cache, while 0.48.0 moved
  macOS to the Linux folders. Owner: tg-cli `docs/installation.md`.
- The homepage demo fixtures (`lib/landing/*.json`, `lib/editorial/*.json`, `components/landing/*.tsx`) still show
  profile-less `tg` commands and need their own pass, as for max.

## Validation

Source fingerprints were accepted only after the page check passed and the changed prose was read. Command
contracts, strict documentation checks, localization, release-note and roadmap checks, unit tests, typecheck and the
browser cases that cover tg pages are recorded in the PR; deployment runs the full export, link, SEO and browser suite.
