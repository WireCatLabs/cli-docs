# Memo 0.107.0 release review

A reader whose Memo settings file has a mistake now gets every problem and the command that removes it, can
remove a setting with `memo config unset`, sees which of Memo's files other users can read, and can look up
failed runs. Project evidence also says who wrote the items and reads the project's confirmed members. This
review moves the site from Memo 0.97.0 to 0.107.0 and covers every release in between.

## Portal correction

`configuration.md` at v0.107.0 ends its new `record` section with "Memo has no `config` command: add the keys to
`config.json` by hand." The same release adds `memo config unset`, its only subcommand (`memo config --help` on
the released package). A `before-translation` correction in `scripts/docs-corrections.json` replaces it with
"Add these keys to `config.json` by hand: `memo config` only removes settings." The RU/ES pages translate the
corrected sentence. The correction should be retired when cli-memo fixes the sentence.

## Runtime evidence

`pnpm docs:contracts` captured the 0.107.0 command tree with the network disabled. On the installed release,
with a temporary HOME, config, state and store (no owner data):

- `memo doctor --json` returns `config: { path, found, issues }` and `files: { checked, ok, problems }`, exit 0.
- A synthetic config with an unknown key, a wrong type and an invalid permission produced three
  `config.issues` (`unknown_setting`, `invalid_value`), each with a `fix` of `memo config unset <key>`; a `0644`
  config file and a `0775` folder were listed in `files.problems` with `want` `0600`/`0700`, and the two
  `to make it private: chmod …` lines went to stderr.
- Another command on that file was refused with the first problem, its fix and "(and 2 more problems — `memo
  doctor` lists them all)".
- `memo config unset default_profile` removed the key and left the file `0600`.
- `memo sync --help` has `--source` for mailboxes and no `--account`.

Read from `dist/`, not run: the member lane limit (`CORE_LIMIT = 16`, `member-limit`, `no-identity` in
`knowledge/project-gathering.js`), the 20-person `people` cap (cli-core `services/project-gathering.js`),
`applySupported: true` (cli-core `store/sqlite/tag-consolidation.js`) and "kept by drive"
(`notes/folders-command.js`). The `people_omitted` JSON name is from the source docs and changelog; the code
holds `peopleOmitted` before output.

## Remaining source issues

- The released changelog has no 0.102.0 section, although tag `v0.102.0` exists (cli-memo).
- `docs/configuration.md` says Memo has no `config` command (cli-memo; corrected here, see above).
- `content/docs/desktop/logs.mdx` (EN/RU/ES) says Memo keeps no run logs the app can read. Memo 0.104.0 keeps run
  logs and its changelog says Desktop's Logs page reads `memo runs list … --json`. Whether a released Desktop
  does is not verified here, so the Desktop page is left for its owner.
