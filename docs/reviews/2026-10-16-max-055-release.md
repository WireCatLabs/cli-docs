# MAX shared flag vocabulary review

Reviewer: Claude. Portal base: `5125677`; final rebase recorded in the PR.
Reviewed runtime: MAX `v0.55.0`, commit `18d615d83f05841142d2b959c5821765ed565ff3`,
Core `0.288.0`, Base `0.33.0`. Compared native guides and generated command reference
against `v0.54.0`. Other runtime pins remain unchanged.

Readers can follow the existing archive, bot, group-work, people, search and reply-rule paths with
the released syntax. Changed prose and examples were reviewed in EN/ES (the native guides are
Russian) and in RU for the English-described command reference. Unchanged historical changelog
prose and unchanged command sections retain the previous review; this is a release-delta review,
not a fresh editorial audit of every historical sentence.

## Evidence and corrections

- MAX tagged `docs/*.md`, `CHANGELOG.md` and `package.json`: shared flag names with no aliases,
  `tasks related` and `tasks duplicates defer`, query fields for the agenda and duplicate review,
  envelope-only `--json` answers. Roadmap unchanged between the two tags.
- `max --help` of the npm `0.55.0` package, run with a throwaway HOME, lists `tasks related`,
  `duplicates defer`, `add --into`, `claim --lease`, agenda fields `category:`/`tag:`/`claimed:`,
  `decision:unsure`, `contacts context --sync-first` and `search conversations --catch-up`.
- Preserved the removed `max-tasks-similar` and `max-tasks-duplicates-unsure` anchors at their
  replacement command sections in every locale.
- Removed the shared-page notes that said `max` still used the earlier task and refresh names
  (Tasks, People, search architecture; EN/RU/ES).
- The report task's member audit now uses `--max-pages` for both messengers.
- Memo `0.47.0` (Core `0.294.0`) has categories, task tags, agenda fields and the duplicate check in
  `tasks add`, but no `tasks claim`, `related`, `duplicates` or `merge`; the Tasks and How tasks
  work openings now say so instead of listing Memo with every feature.
