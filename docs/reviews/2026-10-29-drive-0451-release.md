# Drive 0.45.1 reviewed publication

Readers start drive's MCP server with `drive <profile> mcp serve` (stdio, or `--http`), forget browser logins with
`mcp revoke`, and serve several profiles from one server only when they say so: `mcp serve --profiles work,personal`
or `--profiles all`. The configuration page names the new run-retention settings, because every run is now kept. The
portal targets published Drive 0.45.1 (covering 0.41.1 to 0.45.0), Core 0.473.0 and Base 0.65.0. Reviewer: Claude.

## Behavior checked on the released package

`pnpm docs:cli drive …` on the captured 0.45.1 install, with a temporary home and the network disabled:

- `drive --version` printed `0.45.1`.
- `drive personal mcp --help` lists `serve`, `revoke` and `server` and nothing else; `mcp` itself has no options.
- `drive personal mcp serve --help` lists `--tools`, `--http`, `--port`, `--public-url` and `--profiles <names|all>`.
- `drive personal mcp revoke --help` takes `--profiles`.
- `drive personal mcp server status --json` exited 0 with `running: false` and no clients.
- `drive mcp serve --json` with no profile exited 3: no profile exists yet on an empty home.
- `drive personal mcp serve --profiles all` exited 2: "name one profile or --profiles, not both".
- `drive mcp serve --profiles all,work` exited 2: `all` must stand alone.

Not checked: a server started behind a tunnel, a multi-profile server with real profiles, Windows.
