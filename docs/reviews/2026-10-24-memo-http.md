# Memo HTTP MCP documentation review

A browser or phone AI app cannot start Memo on the owner's computer. The new remote guide explains how to
reach the same command server through an HTTPS tunnel, complete access-code login, limit commands and revoke
access. Local stdio setup remains in its existing guide.

## Source and scope

Reviewer: Codex. Site worktree starts at `85cf6304`, which already published the reviewed Memo 0.93.0 migration.

- [Core #1905](https://github.com/WireCatLabs/cli-core/pull/1905) exports existing public-origin/port validation,
  fixes duplicate positional/flag emission found by note creation, and refuses credential-bearing public URLs.
- Memo's HTTP command uses Core's existing `serveOverHttp`, `MCP_PATH` and `revokeAll`; the same
  `createMemoServer` supplies the three discovery/read/write tools to stdio and HTTP.
- Core's concurrent contract rollout is separate work. The Memo HTTP candidate is also tested on its adoption
  branch; shell differences are explicit reviewed declarations rather than silently editing shared defaults.
- [Funnel reference](https://tailscale.com/docs/reference/tailscale-cli/funnel) and
  [Cloudflare Quick Tunnel limits](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/) were
  checked on 2026-10-24. Quick Tunnels do not support the server's SSE responses. No app-plan or pricing claim
  is added, and no live tunnel or provider-specific account setup is claimed tested.

## Runtime evidence

Synthetic real-loopback tests cover legacy and modern MCP clients, access-code OAuth login, private token hash
storage, note creation/search, permission changes in an existing connection, read locks, stricter server
permissions, revocation against the running server, login persistence across restart, shutdown and invalid
startup options. They do not use the owner's data, credentials or tunnel. The
release, on registry cli-core 0.414.0, passes the full release check with 660 tests, including 12 HTTP cases.
The shared Core fix passes 34 targeted tests and every TG/MAX/WA and wording parity check against their mains.

The implementation initially exposed a shared runner bug: one text field emitted both a positional argument
and its --text alternative, causing note creation to fail on both transports. The Core fix retains one field
and positional requiredness, with real Commander regression coverage. Memo's shell declaration records the
HTTP flags and their conflicts explicitly under the new Core contract guard.
