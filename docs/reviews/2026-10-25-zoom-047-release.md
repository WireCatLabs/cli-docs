# Zoom 0.47.0 reviewed publication

Readers can remove a setting with `zm config unset`, read every config problem and its fix from `zm doctor --json`,
see when the config file is readable by other users, and read `zm runs`. Anyone last signed in with zm 0.34 or
earlier is told to sign in again. The portal targets published Zoom 0.47.0 (Core 0.430.0, Base 0.57.0).
Reviewer: Claude (release update session, 25 October).

## Sources and boundaries

- Release: tag [v0.47.0](https://github.com/WireCatLabs/zoom-cli/releases/tag/v0.47.0); npm `@wirecat/zoom-cli@0.47.0`
  depends on `@wirecat/cli-core` 0.430.0 and `@wirecat/cli-base` 0.57.0.
- The 0.43–0.47 guides ship the corrections that zoom-cli#245 made after 0.42. The four 0.42 portal errata (security,
  search, usage, roadmap) and the erratum that removed the MCP "Upgrading from 0.34" note no longer match and are
  retired.
- Kept: the search erratum that names `--since-time`/`--until-time` without the list options they replaced.
- New `before-translation` errata:
  - configuration: drop the sentence that keeps the old provider value `folder`, so the guide names one value.
  - installation (update step) and sessions (login step): add that anyone last signed in with zm 0.34 or earlier
    runs `zm <profile> session start` again. The 0.46.0 changelog states this; 0.47.0 guides no longer mention it.

## Runtime evidence

The released package was installed with `--ignore-scripts` into a scratch directory and run with `env -i`, a scratch
`HOME` and no D-Bus session, so no keyring or Zoom account was reachable.

| Claim | Evidence |
| --- | --- |
| `config unset`, `runs list/show/path`, `skill status`, `skill show --for`, `store info` exist; `serve` does not | `zm commands --json` |
| `zm config set` writes `config.json` as `0600` | `stat` after `zm personal config set files.timezone Europe/Madrid` |
| Old keys and an unknown permission key are `config.issues` with a runnable `fix` | `account_profile`, `clientId`, `filesFolder`, `permissions.recordings.sync` in the file → four issues; `zm config unset account_profile` and `zm personal config unset permissions.recordings.sync` ran and removed them |
| Other commands refuse the file by its first problem and the count of the rest | `zm personal meetings list --json` → `configuration_error`, exit 3 |
| `zm config show` prints problems after the settings that load | output after the unset |
| A readable file is reported under `files.problems`, with `chmod` on stderr | file at `0644` → `{ path, mode: "0644", want: "0600" }` |
| Doctor answers when the config path is a folder | exit 0, one `invalid_value` issue, no `fix` |
| Help shows `doctor` without a profile | `zm doctor --help` → `Usage: zm doctor [options]` |
| A login saved by 0.34 or earlier is no longer moved to a profile | source only: 0.42.0 `dist/config.js` reads `account_profile`; 0.47.0 `dist` has no such code. Not run against a keyring. |

## Open issues

- The released troubleshooting and installation guides give the run folder as `~/.local/share/zm/runs`. Both 0.46.0
  and 0.47.0 write runs to `~/.local/share/zoom-cli/runs` (`ZM_STATE_DIR` still overrides it). The native guides need
  a fix in zoom-cli; this PR does not add an erratum for it.
- The 0.46.0 changelog lists `files.problems` entries as `{ path, mode, want, fix }`; the 0.47.0 output has no
  `fix` field and prints the `chmod` on stderr. The guide text matches the output.
