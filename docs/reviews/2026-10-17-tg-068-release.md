# tg 0.68.0 release review: where tasks open, `watch-tasks`, assignees, `tasks scan`, no default profile

Reviewer: Claude. Portal base: `f740c01`; final rebase recorded in the PR.
Reviewed runtime: tg `v0.68.0`, commit `fcd2b23860d5e0a0c578cf646f0e172412b3802f`, Core `0.320.0`, Base `0.40.4`.
Compared native guides, skill and changelog against the previous pin `v0.67.0` (Core `0.315.0`, Base `0.40.2`;
reviewed in #287, `2026-10-17-security-releases.md`), so this review covers 0.68.0 only. Other runtime pins are
unchanged: MAX `v0.58.0` (Core `0.315.0`) and Memo `v0.58.0` (Core `0.311.0`) have none of the Core 0.317–0.320 task
changes below, so the shared pages name `tg` for them.

Readers can now see where the rules open tasks (one-to-one chats, only what is addressed to them in groups, nothing
in channels or Saved Messages), tag a group `watch-tasks` to get every question, record who should do a task and
list what others owe them, and use `tasks scan` in place of `tasks apply`. tg pages no longer offer
`default_profile`.

## Corrected earlier claims

The shared pages said only `tg` held back history tasks on a first sync, skipped quiet chats, had `tasks apply`,
compared by message send time and named a closed task's follow-up. MAX moved to v0.58.0 (Core 0.315.0) in #287; those
features came in Core 0.304.0–0.311.0, and MAX's released reference and changelog list `tasks apply` and the first-pass
setting. The pages now say `tg` and `max` for them and give MAX's command name (`tasks apply`, MCP `tasks_apply`).
That is why `tasks apply` still appears on the Tasks pages, only as MAX's name.
