# tg 0.66.0 release review: tasks from history, `tasks apply`, comparison by message time

Reviewer: Claude. Portal base: `b0baf39`; final rebase recorded in the PR.
Reviewed runtime: tg `v0.66.0`, commit `a0282d61b677bb8d7af55af5866bcd2fa0fe4498`, Core `0.311.0`,
Base `0.40.2`. Compared native guides, skill and changelog against the previous pin `v0.63.0`
(Core `0.298.0`), so this review covers 0.64.0, 0.65.0 and 0.66.0. Other runtime pins are unchanged:
MAX `v0.56.0` (Core `0.296.0`) has none of the task changes below, and Memo `v0.58.0` (Core `0.311.0`)
has no `tasks apply`, no `task_first_pass_per_chat` and no `tasks categories` in its released command
contract, so the shared pages name `tg` only.

Readers can now understand why a first sync opens no tasks from their history, ask their agent which
tasks a chat's history would open, open them after they agree, and change how many tasks a first sync
may open. The duplicate check is described as comparing tasks by when their messages were sent.

## Remaining items

- The shared Mentions page (EN/RU/ES) does not yet describe names of unknown people, street addresses or
  `mentions places`. That work is in PR #281, which waited for this pin; it is not part of this change.
- tg `docs/groups.md` says every tool on cli-core 0.298.0 or newer reads the shared category file, with release
  numbers. A portal correction (`scripts/docs-corrections.json`, tg/groups EN/RU/ES) now calls it a settings file
  WireCat tools share, not one profile's, and names no tools or versions.
- Open question, not settled here: memo v0.58.0 (Core 0.311.0) probably reads the shared file too. Its
  `tasks agenda`, `plan`, `show` and `link` come from cli-core's `tasksCommand` (cli-memo `src/tasks/shared.ts`),
  and Core's store passes the shared config path to `store.tasks.categories()` (cli-core `src/store/store.ts:152`,
  `src/store/sqlite/tasks.ts:132`). It has no `tasks categories` or `tasks add --category`, and a runtime check
  needs a messenger task, so it was not run. The shared Tasks and How tasks work pages still say only `tg` reads
  the file and that memo has the earlier seven categories; that needs a memo-focused review (owner: cli-docs,
  with cli-memo).
- tg `docs/installation.md` gives a pnpm install line with `minimumReleaseAgeExclude`; the portal's tg
  installation page shows npm only and was not changed.
