# Telegram 0.104.0 and MAX 0.84.0 reviewed publication, with the `mcp serve` guides

Readers start the MCP server with `<cli> <profile> mcp serve` (stdio, or `--http`); `mcp` alone prints help.
Browser logins are forgotten with `mcp revoke`, `mcp server start|stop|status` runs the HTTP server in the
background, and a bot's server is `bot mcp serve`. tg serves only the profile it names, or `--profiles a,b` /
`--profiles all`; max 0.84.0 has no `--profiles` and serves every profile when none is named. The portal targets
published tg 0.104.0 (Core 0.473.0) and max 0.84.0 (Core 0.469.0). The pins and the shared guides move in one change:
each alone fails the strict example check against the other. Reviewer: Claude.

## Sources and boundaries

- [tg v0.104.0](https://github.com/WireCatLabs/tg-cli/releases/tag/v0.104.0) and
  [max v0.84.0](https://github.com/WireCatLabs/max-cli/releases/tag/v0.84.0), captured by `pnpm docs:contracts`
  (isolated home, network and keyring sockets blocked).
- Run with `pnpm docs:cli` in a throwaway home with a fictional profile `work`, no login, no network:
  - tg: `--version` → `0.104.0`. `work mcp --help` lists `serve` and `revoke` (and `server`). `work mcp serve` answers
    an MCP `initialize` on stdin with `serverInfo` `tg 0.104.0`. `work mcp revoke --json` →
    `{"item":{"revoked":true,"profile":"work"}}`. `work mcp server status --json` → `running: false`.
    `mcp serve` with no profile → `validation_error`, exit 2. `work mcp serve --profiles work` → `validation_error`
    ("name one profile or --profiles, not both"). `mcp serve --profiles all,work` → `validation_error`.
    `work bot mcp --help` lists `serve` and `config`.
  - max: `--version` → `0.84.0`. `work mcp --help`, `work mcp revoke --json`, `work mcp server status --json` and
    `work bot mcp --help` as for tg. `mcp serve --profiles all` → `unknown option '--profiles'`. `work mcp serve --help`
    says that with no profile, `max mcp serve` serves every profile.
