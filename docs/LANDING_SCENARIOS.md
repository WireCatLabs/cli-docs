# Сценарии WireCat

Банк сценариев для лендинга и будущих материалов. Переписки и результаты команд здесь иллюстрируют работу агента. Команды в макете не выполняются.

## Выбранный порядок на лендинге

1. Контекст к созвону
2. Утренняя сводка
3. Вопросы без ответа
4. Напоминания и отправка
5. Рекомендованный контакт
6. Все документы по теме
7. Бот для клиентов

## Выбранные диалоги

### 1 Контекст к созвону

Основные команды: tg chats list → tg review

**Пользователь:** Завтра созвон по Atlas. Собери, что решили, что тормозит запуск и какие вопросы мне нужно задать.

```sh
tg chats list --search "Atlas"
```

```sh
tg review --chat "Atlas · команда" --since-time 7d
```

**Агент:**

#### Уже решили


- **Запуск:** пятница, объём первой версии зафиксирован.
- **Тексты:** Анне нужна финальная версия до четверга.

#### Блокирует запуск

**Том:** ждёт доступ к стенду для проверки оплаты.



#### К созвону

Назначить ответственного за доступ и срок проверки. Нашёл также группу дизайна — могу проверить её и личные договорённости участников.

**Пользователь:** Посмотри ещё дизайн и мою личку с Томом. Он мог прислать результат туда.

```sh
tg review --chat "Atlas · дизайн" --since-time 7d
```

```sh
tg messages search "Atlas" --chat "Том"
```

**Агент:**

#### Контекст из других чатов


- **Дизайн:** макет готов; тексты остаются последней зависимостью.
- **Том, личная переписка:** тестовую оплату проверил. Доступ нужен именно к боевому стенду.

#### Уточнённый риск

Не вся проверка оплаты заблокирована — осталась проверка в боевой среде. На созвоне стоит обсуждать её, а не начинать с нуля.

**Пользователь:** Сделай повестку на 20 минут: риски, ответственные и сроки. Ничего не отправляй.

```sh
tg messages context "Том" 48210 --before-n 2 --after-n 2
```

**Агент:**

#### Повестка на 20 минут


- **0–7:** боевой стенд — кто выдаёт доступ и когда Том завершит проверку.
- **7–12:** финальные тексты — кто передаёт Анне до четверга.
- **12–17:** если не успеваем — сокращаем объём или переносим запуск?
- **17–20:** зафиксировать владельца и срок каждого решения.Черновик готов. Учтены проектная группа, дизайн и личная переписка с Томом. Ничего не отправлено.

### 2 Утренняя сводка

Основные команды: tg inbox → tg review

**Пользователь:** Доброе утро. Что требует моего внимания и какие новости из подписок стоит прочитать?

```sh
tg inbox
```

```sh
tg review --chat "Новости технологий" --since-time 1d --all
```

**Агент:**

#### Сегодня нужно вам


- **До 11:00 — Марко:** подтвердить бюджет, чтобы команда продолжила работу.
- **Вечером — Анна:** встречу перенесли на 19:30, ждёт подтверждения.
- **Без срока — мама:** голосовое, 0:42.

#### Новости из подписок


- **Инструменты для кода:** обновление рабочего процесса.
- **Поиск:** практический разбор с примерами.Подробности и исходные сообщения доступны по каждому пункту. Могу сузить новости до рабочих тем.

**Пользователь:** Добавь канал про ИИ, объедини повторы и оставь только полезное для нашей команды.

```sh
tg review --chat "Новости ИИ" --since-time 1d --all
```

**Агент:**

#### Для команды разработчиков


- **Обновление инструмента:** повтор из двух каналов объединил; сохранил оба источника.
- **Разбор поиска:** практический материал, можно применить к нашей задаче.

#### Можно отложить

Анонс модели: пока есть заявления о возможностях, но нет проверки на нашем проекте.

**Пользователь:** Что первым сделать за ближайшие 15 минут?

```sh
tg messages context "Марко" 48210 --before-n 2 --after-n 2
```

**Агент:**

#### Первые 15 минут


- **Сначала бюджет:** открыть запрос Марко и принять решение — он блокирует подрядчика.
- **Затем встреча:** подтвердить Анне 19:30.
- **После этого:** прослушать голосовое или попросить расшифровку.Новости оставил отдельным списком на потом: срочных действий по ним нет.

### 3 Вопросы без ответа

Основные команды: tg review --unanswered

**Пользователь:** Посмотри все чаты: кому я должен ответить, что обещал и от кого мы сами ждём результата. Подготовь черновики.

```sh
tg review --since-time 7d --all --unanswered
```

```sh
tg review --since-time 7d --all
```

**Агент:**

#### Вы должны


- **Анна:** счёт до пятницы — сегодня.
- **Марко:** решение по бюджету.
- **Клиент:** подтверждение доставки.

#### Ждёте от других

**Том:** макет обещан к среде. Проверю другие чаты перед напоминанием.



#### Можно закрыть сейчас

Дата доставки уже согласована. Для бюджета нужно ваше решение; его не буду придумывать.

**Пользователь:** Проверь личку Тома и сделай драфты: клиенту про доставку, Анне про счёт, Тому про макет.

```sh
tg messages search "макет" --chat "Том"
```

**Агент:**

#### Клиенту

Доставка остаётся на пятницу, как согласовали. Если есть ограничения по времени, подскажите, пожалуйста.



#### Анне

Анна, привет! Счёт пришлю сегодня, как договорились.



#### Тому

Том, спасибо за первый вариант! Подскажи, когда сможешь прислать финал после комментариев?

Макет уже есть в личке, поэтому напоминание «ты ничего не прислал» было бы неверным. Все три ответа — черновики.

**Пользователь:** Покажи сначала бюджет и больше ничего пока не отправляй.

```sh
tg messages context "Марко" 48210 --before-n 3 --after-n 3
```

**Агент:**

#### Что нужно решить

**Дополнительная аналитика:** обсуждали объём, но финальной цены нет.



#### Предлагаемый следующий шаг

Марко, пришли финальную оценку подрядчика: стоимость и влияние на срок. После этого подтвержу бюджет.

Без оценки не считаю бюджет согласованным. Подготовленные ответы сохранены в диалоге; отправки не было.

### 4 Напоминания и отправка

Основные команды: tg messages send --at-time

**Пользователь:** В понедельник в 10 созвон по Atlas. Напомни мне за час, а в 18:00 — проверить, закрыли ли вопросы. Всё по Мадриду.

```sh
tg messages send me "В 10:00 созвон по Atlas: открой повестку" --at-time 2026-10-05T09:00+02:00
```

```sh
tg messages send me "Atlas: проверь решения, ответственных и сроки после созвона" --at-time 2026-10-05T18:00+02:00
```

**Агент:**

#### Ваши напоминания

Когда | Что |
09:00 | Открыть повестку за час до созвона |
18:00 | Проверить решения и открытые вопросы |
Понедельник, 5 октября. Время Мадрида. Оба сообщения запланированы в «Избранное».

**Пользователь:** Анне отправь в 9:30 просьбу принести финальные тексты. Тому в 9:45 — статус проверки оплаты. Лично каждому.

```sh
tg messages send "Анна" "Привет! К созвону в 10:00 по Atlas принеси, пожалуйста, финальные тексты" --at-time 2026-10-05T09:30+02:00
```

```sh
tg messages send "Том" "Привет! К созвону в 10:00 по Atlas подготовь, пожалуйста, статус проверки оплаты" --at-time 2026-10-05T09:45+02:00
```

**Агент:**

#### Личные сообщения участникам


- **Анна, 09:30:** просьба принести финальные тексты.
- **Том, 09:45:** просьба подготовить статус проверки оплаты.

#### Итого

Четыре сообщения в разное время: два вам и по одному каждому участнику. Telegram отправит их по расписанию, даже если ноутбук будет выключен.

### 5 Рекомендованный контакт

Основные команды: tg chats list → tg messages search

**Пользователь:** Мне нужен бухгалтер для ИП с международными платежами. Кто-то советовал человека в чатах про фриланс или бизнес — найди контакт.

```sh
tg chats list --search "Фриланс"
```

```sh
tg messages search "бухгалтер" --chat "Фриланс · сообщество"
```

**Агент:**

#### Нашёл подходящую рекомендацию

**София → Елена:** ИП и международные платежи. В сообщении есть контакт.



#### Где ещё проверить

Нашёл отдельный чат «Фриланс · налоги». Могу сверить отзывы там и поискать рекомендации в бизнес-чате.

Цена и текущая доступность Елены пока неизвестны.

**Пользователь:** Проверь налоги и бизнес. Мне важны евро, доллары и ведение под ключ.

```sh
tg messages search "Елена" --chat "Фриланс · налоги"
```

```sh
tg chats list --search "Бизнес"
```

**Агент:**

#### Что подтвердилось в обсуждениях


- **Ведение под ключ:** участник налогового чата это упоминает.
- **Валютные платежи:** есть положительный отзыв.

#### Ещё нужно уточнить

Евро и доллары отдельно не названы. Нашёл «Бизнес · рекомендации» — проверю, нет ли там другого кандидата.

**Пользователь:** Сравни с альтернативой и подготовь первое сообщение, не отправляй.

```sh
tg messages search "бухгалтер" --chat "Бизнес · рекомендации"
```

**Агент:**

#### Кого выбрать для первого контакта


- **Елена:** ближе к задаче — ИП, валютные платежи, ведение под ключ.
- **Ольга:** рекомендована для разовых консультаций; постоянное сопровождение не подтверждено.

#### Черновик Елене

Елена, здравствуйте! София рекомендовала вас в чате «Фриланс». Я работаю как ИП, получаю платежи в евро и долларах и ищу ведение под ключ. Берёте ли новых клиентов и какие условия?

Контакт найден. Отзывы участников не заменяют подтверждение условий самой Еленой. Ничего не отправлено.

### 6 Все документы по теме

Основные команды: tg chats list → tg messages search

**Пользователь:** Собери все документы по Atlas: договор, счета и презентацию. Их могли присылать в проектную группу или в личку.

```sh
tg chats list --search "Atlas"
```

```sh
tg messages search "договор OR счёт OR презентация" --chat "Atlas · команда"
```

**Агент:**

#### В проектной группе


- **Презентация:** версия v2.
- **Счёт:** за первый этап.
- **Договор:** предварительная версия.

#### Перед сборкой комплекта

Нужно проверить личку Анны и группу дизайна — там могли остаться более новые файлы.

**Пользователь:** Посмотри личку Анны и дизайн. Оставь последние версии, но не теряй старые.

```sh
tg messages search "договор" --chat "Анна"
```

```sh
tg messages search "презентация" --chat "Atlas · дизайн"
```

**Агент:**

#### Актуальный комплект

Документ | Версия | Где найден |
Договор | Финальный | Личка Анны |
Счёт | Первый этап | Atlas · команда |
Презентация | v3 | Atlas · дизайн |


#### История версий

Предварительный договор и презентация v2 сохранены отдельными пунктами. Ничего не удаляю.

**Пользователь:** Проверь, есть ли ещё счета, и составь список для отправки клиенту.

```sh
tg messages search "счёт" --chat "Анна"
```

**Агент:**

#### Можно подготовить клиенту


- Финальный договор от Анны.
- Счёт за первый этап.
- Презентацию v3 из группы дизайна.

#### Не включаю

Счёт за второй этап: его ещё не выставляли. Старые версии оставлены в истории, но в актуальный комплект не входят.

Список готов. Для отправки нужно выбрать найденные вложения и подтвердить получателя.

### 7 Бот для клиентов

Основные команды: tg bot list → tg bot mcp

**Пользователь:** Хочу бота для клиентов: учитывать историю заказа, отвечать на вопросы, а спорные случаи передавать мне. Начнём с одного клиента.

```sh
tg bot list
```

```sh
tg sales bot recipients list
```

**Агент:**

#### Пилот на одном клиенте


- **Бот:** sales.
- **Получатель:** Анна — уже в списке разрешённых чатов.
- **Контекст:** только доступная история её заказа.

#### Правила

Вопросы по истории — черновик ответа. Изменение сроков, цены и компенсации — сначала вам. Если данных нет, уточнение вместо догадки.

**Пользователь:** Покажи на двух вопросах: когда доставка и можно ли перенести её на завтра.

```sh
tg messages search "доставка" --chat "Анна · клиент"
```

**Агент:**

#### Когда доставка?

В переписке согласовали доставку на пятницу. Адрес подтверждён.



#### Можно перенести на завтра?

Уточню у команды, возможен ли перенос на завтра, и вернусь с подтверждением.



#### Вам на проверку

Запрос на изменение даты. Бот не обещает перенос, пока команда его не подтвердит.

**Пользователь:** Настрой подтверждение каждого ответа. И покажи, как потом проверить его действия.

```sh
tg sales config set permissions.messages.send ask --bot
```

```sh
tg sales bot mcp config --confirm-send
```

**Агент:**

#### Подтверждение отправки

Настройки и конфигурация MCP подготовлены для проверки ответов перед отправкой. Пилот остаётся на одном разрешённом клиенте.



#### История действий

Можно смотреть журнал попыток отправки и записанные запуски: статусы, время и ID получателя.

Следующий шаг — подключить конфигурацию к агенту и проверить первый вопрос в пилоте.

## Все предыдущие варианты

Полные предыдущие диалоги сохранены для дальнейшего развития и сравнения.

### 1 Контекст к созвону

Основные команды: tg review

**Пользователь:** Собери контекст по проекту перед завтрашним созвоном.

```sh
tg review --chat "Project Alpha" --since-time 7d
```

**Агент:**

#### Уже решили


- **Запуск:** в пятницу, дату подтвердили в проектной группе.
- **Анна:** ждёт финальные тексты до четверга.
- **Том:** ждёт доступ к стенду.

#### Нужно решить

Кто проверяет оплату и когда. Без этой проверки запуск остаётся под вопросом.

Собрал контекст за последние 7 дней. Могу раскрыть историю каждого решения.

**Пользователь:** А что именно нужно решить на встрече?

```sh
tg messages context "Project Alpha" 48210 --before-n 3 --after-n 3
```

**Агент:**

#### Три решения к созвону


- **Проверка оплаты:** назначить ответственного и время проверки.
- **Тексты:** подтвердить, что **Анна** получит финальную версию до четверга.
- **Доступ:** выяснить, кто выдаст Тому доступ к стенду.По дате запуска разногласий в последней переписке нет. Основной риск — проверка оплаты до пятницы.

**Пользователь:** Составь повестку на 20 минут, сначала риски.

```sh
tg messages context "Project Alpha" 48211 --before-n 3 --after-n 3
```

**Агент:**

#### Повестка


- **0–7 минут:** проверка оплаты — владелец, доступ и срок.
- **7–12:** готовность текстов и макета.
- **12–17:** зависимости перед запуском.
- **17–20:** зафиксировать, кто что делает и когда.Добавил к каждому пункту, из какого обсуждения он возник. Можно отправить повестку команде.

**Пользователь:** Пока не отправляй. Добавь вопрос, что переносим, если не успеем.

```sh
tg messages context "Project Alpha" 48212 --before-n 3 --after-n 3
```

**Агент:**

#### По переписке

Добавил в первый пункт: **«Если проверка оплаты не закончится в четверг, переносим запуск или сокращаем объём?»**

Повестка готова как черновик. В конце оставил место для решений, ответственных и сроков — после встречи их можно сравнить с исходными договорённостями.

### 2 Последняя договорённость

Основные команды: tg messages search

**Пользователь:** О чём мы в итоге договорились с Анной?

```sh
tg messages search "правки" --chat "Анна"
```

**Агент:**

#### Последняя договорённость


- **Вы:** присылаете правки до четверга.
- **Анна:** возвращает макет в пятницу.

#### Что изменилось

Первоначальный срок «среда» перенесли. **Анна** подтвердила новый срок: Да, тогда макет отдам в пятницу.

Время в пятницу и состав этой итерации ещё стоит уточнить.

**Пользователь:** Почему ты считаешь четверг последним сроком?

```sh
tg messages context "Анна" 48212
```

**Агент:**

Порядок сообщений такой:


- **Понедельник, 10:15:** вы предложили прислать правки в среду.
- **Вторник, 18:20:** попросили перенести на четверг.
- **18:24:** **Анна** ответила: «Да, тогда макет отдам в пятницу».Поэтому четверг — подтверждённый перенос, а не предположение. Более поздних изменений в этой переписке не нашёл.

**Пользователь:** А что осталось неопределённым?

```sh
tg messages context "Анна" 48211 --before-n 3 --after-n 3
```

**Агент:**

#### По переписке

Время в пятницу не указано. Неясно также, входит ли мобильная версия в эту итерацию: вы упоминали её раньше, но в финальном согласовании она не названа.

Предлагаю уточнить оба вопроса одним сообщением.

**Пользователь:** Напиши коротко, по-человечески.

```sh
tg messages context "Анна" 48212 --before-n 3 --after-n 3
```

**Агент:**

#### Черновик сообщения

Анна, привет! Правки пришлю в четверг, как договорились. Подскажи, к какому времени в пятницу ждать макет? И мобильная версия входит в эту итерацию?

Это черновик. Можно отправить после вашего подтверждения.

### 3 После отпуска

Основные команды: tg review

**Пользователь:** Что изменилось в проекте, пока я был в отпуске?

```sh
tg review --chat "Project Alpha" --since-time 14d
```

**Агент:**

#### Пока вас не было


- **Запуск:** команда предложила новую дату.
- **Дизайн:** новый вариант согласован.
- **Подрядчик:** подключился и предложил дополнительную работу.

#### Ждут вашего решения

Подтверждение бюджета, затем — даты запуска. Остальные сообщения можно посмотреть позже.

Период обзора — две недели.
