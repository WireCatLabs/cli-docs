title: Install and set up WireCat Desktop
description: The app for macOS, Windows and Linux that installs, updates and checks the WireCat tools, connects them to your AI agents and signs you in, with no terminal. A walkthrough of every screen.
---

WireCat Desktop is an app for people who want their AI agent to work with their messages, meetings,
documents and notes, but do not want to install and maintain command-line tools by hand. It installs the
WireCat tools, gives your AI agents the instructions to use them, opens each tool's sign-in and shows what
the tools keep on your computer. This page follows the app in the order you meet it: install, first start,
then each page of the window. The app is optional: every tool still installs and works from a terminal
without it.

## Download and install

[Download WireCat Desktop](/en/download) for macOS (Apple silicon and Intel), Windows (64-bit) or Linux
(AppImage, .deb or .rpm). The download page picks the file for your computer. The macOS app is signed and
checked by Apple. The Windows installer is signed with an Open Source Developer certificate from Certum, and
Windows names Open Source Developer Viacheslav Ptsarev as its publisher. Windows may still ask you to confirm the
first start; the [first-start steps](/en/download#first-launch) show where to click.

The app itself needs nothing else. The tools run on <DocTerm term="nodejs" lang="en" label="Node.js" />
22.16 or later within 22.x, or 24 or later, with npm. If Node.js is missing, too old, or npm needs
administrator rights to install, the app offers to set up its own copy of Node.js in your user folder.
It does not need administrator rights for that, and your existing Node.js stays as it is.

## The first start

The first start opens a setup in the app's window. Its steps are listed at the left: **Welcome**,
**Your computer**, **Choose tools**, **Install**, **Agents**, **Sign in** and **Done**. **Continue** goes to
the next step and **Back** to the one before. **Set up later** closes the setup; **Finish setup** in the
sidebar opens it again at the step you reached.

1. **Welcome:** a short note on what WireCat does. The tools keep your messages, mail, meetings and files
   in storage on this computer, not in a WireCat cloud. Each tool is an open command-line tool from npm;
   the app installs it and runs its own commands. **Get started** begins.
2. **Your computer:** the app checks the system, Node.js and npm. **Check again** repeats the check after
   you fix something.
3. **Choose tools:** pick the services your agent should reach: Telegram, MAX, WhatsApp, Zoom,
   Google Drive, Memo or Email. You can add or remove tools later on the **Tools** page.
4. **Install:** each tool is installed from npm and checked that it starts. One install runs at a time.
   A bar shows the progress: looking up packages, downloading, unpacking, setting up and checking that the
   tool starts, with the time so far and an estimate of what is left. A tool usually takes a minute or
   two, longer on a slow connection. While you wait, short tips show what each tool is for. The installs
   keep going if you move to the next step, and each one is also shown on the **Tools** page with its full log.
   Each install first runs the same storage check as the [Tools](#tools) page, and a warning waits in the tool's
   row for your answer.
5. **Agents:** the app gives each AI agent it finds the tool's <DocTerm term="skill" lang="en" label="skill" />:
   a short guide to the tool's commands. It knows where Claude Code, Codex, Cursor, Gemini CLI, OpenCode,
   Hermes Agent and OpenClaw read skills. With a skill you ask your agent in plain words, for example
   "What did Anna send me yesterday?", and the agent knows which tool can answer.
6. **Sign in:** signing in connects a tool to your account, so your agent can reach it. The app does it in its
   own window for Telegram (a QR code or your phone number), MAX and WhatsApp (a QR code), and opens your browser for
   Zoom and Google Drive. Where a tool has no sign-in window, **Open terminal to sign in** opens a terminal
   that runs the tool's own setup. Email asks for your mail address in its own window. For a Microsoft account it
   then opens Microsoft's sign-in in your browser. For Gmail and other mail servers it asks for an app password, a
   password made only for this program; [Prepare the mailbox](../mail/providers.md) shows how each provider makes one.
   Memo needs no sign-in.
7. **Done:** the app lists what is installed and offers three next steps: let ChatGPT or Claude use a tool,
   see which agents use the tools, or try your first guide. **Coming in the next WireCat Desktop release:** each
   tool you set up gets a folded card, "What you can do with" the tool. Open it for the next steps, each of which
   opens the right place in the app: **Add another account**, **Start a sync**, **Keep it running in the
   background**, **Give your agents its skill**, **Connect ChatGPT or Claude in the browser**, **See what it ran** and
   **Read its documentation**. A card lists only what its tool supports.

## What you can do in the app

The sidebar lists the pages in this order: **Tools**, **Agents**, **Search**, **Tasks**, **Guides**,
**Memory** and **Analytics**. **Storage**, **Logs** and **Settings** sit below, apart, because they are about
data and the app itself. The top of the window has **Report a problem**, **Notifications** (security fixes,
updates and news from WireCat) and **Help**; when a new version is ready, an update button joins them.
**Help** also holds **Privacy**, **About WireCat** and the settings of the Node.js that WireCat set up.

### Tools

You use this page to install the tools and to connect each one to your account.
Every tool has a status lamp. Green means installed and current, amber means an update is ready, red means installed
but it does not start, and a hollow ring means not installed. Each row has one button:
**Install**, **Update to** a version, **Fix** or **Manage**.

All tools keep your messages and notes in one shared storage, and a new version of a tool can move it to a newer
format. Before **Install** or **Update to**, the app checks this. When another installed tool needs its own new
version to keep reading the storage, the app updates that tool too, right after the one you chose, and the progress
line says so. A warning appears only when that other tool has no such version yet, or when the new version cannot
open your storage. Then you choose **Not now** or **Update anyway**. A tool that does not say which format it reads,
such as Zoom, is left out of the check.

**Manage** opens the tool's details:

- **Accounts:** add an account by name, such as `personal` or `work`, and sign in with **Sign in here** or
  **Open terminal**. The app never picks an account for you.
- **Check health:** runs the tool's own health check for the profile and explains each problem in plain words.
  When the tool's settings file is broken, such as a missing comma, **Repair the file** asks the tool to mend it.
  The tool keeps the file as it was, and changes nothing it cannot fix safely.
- **Sync now:** copies the new messages, files or meetings of a profile to this computer.
- **Permissions:** what agents may do with each group of commands, set per profile: **Allow**, **Ask first**,
  **Read only** or **Block**.
- **Background service** (Telegram, MAX and WhatsApp): the tool gets new messages only while its service runs.
  Each account shows whether it runs and whether it starts when you log in. **Start and keep running** starts it
  and sets it to start at login, **Stop** stops it, and **Stop starting at login** removes it from login. When it
  fails, one sentence says why and offers one fix, such as **Sign in**. WhatsApp also needs your
  phone online.
- **MCP server (or connect web):** lets ChatGPT or Claude in the browser use the tool. The
  [Tailscale Funnel](./tailscale-funnel.mdx) guide publishes the server, or you use a Cloudflare tunnel.
- **Run on a schedule** (Email only): starts Memo's mail agent. It reads new mail every 5 minutes and proposes
  tasks, invoices, orders and facts for you to accept, and it never sends anything. It needs Memo and Claude Code.
- **Uninstall:** removes the tool. Its data stays on this computer until you delete it, and the dialog
  offers **Uninstall and delete data**.

### Memory

You use this page to decide what your agents may remember about you and the people you talk to. An agent
connected to WireCat saves what it learns, such as "Kai prefers Friday calls", with the messages that show it.
Nothing it writes counts, and nothing it proposes happens, until you approve it. Memo keeps the memory.

The tabs are **Review**, **In use**, **Rejected** and **All**. Each entry shows the messages and notes it rests on. For each entry you can:

- **Approve** it, or **Reject** it.
- **Edit** it, with the pencil or from **More**. Your correction is saved as yours and approved; the agent's
  version stays under **Rejected**.
- Take back what you decided. **More** has the undo that fits the entry: **Reject**, **No longer true** or
  **Undo approval**. **Undo approval** works for a decision and for a fact an agent wrote, which goes back to
  **Review**. A fact you wrote yourself has **Edit** and **Erase…** instead.
- **Erase…** it, also in **More**. WireCat erases it from this computer, and agents stop finding it. The
  messages, notes and meetings it rests on stay, and a backup made before still holds it.

### Storage

You use this page to see how much space the tools take and to clean up. It shows each tool's folders as

  The page shows how to restore a copy.

- **Delete:** removes a tool's folders once no installed tool uses them. **Delete all leftover data** removes

## Add your own tool

**Coming in the next WireCat Desktop release:** everything in this section. The current release shows WireCat's own
tools only.

You use this to add a tool that WireCat does not make: your own, a colleague's, or one from a private repository. The
Tools page can show three kinds of tool:

| Kind | Where it comes from | Badge |
| --- | --- | --- |
| WireCat's own | Built into the app | none |
| Community | A list that WireCat reviews and signs | **Community** |
| Your own | Added by you, by its npm name | **Not verified** |

The second and third kinds are off by default. Settings has one switch for each, side by side on a wide window:
**Enable community tools** and **Allow tools WireCat has not checked**. **Enable community tools** takes effect at the
next start, and the page offers **Restart now**. **Allow tools WireCat has not checked** takes effect at once.

### Community tools

Turn on **Enable community tools**. The app then reads the list that WireCat signs and shows its tools with the
**Community** badge. Install one with its **Install** button, like any tool. The app installs a release only when npm
built it from the tool's own repository. The review checks how a tool is built and released, not everything it does.
No community tool is listed yet. Makers ask for a listing as
[List your tool in WireCat](../build-list-tool.md) says.

The signed list is valid for 30 days, and the app fetches a new one every day. If it cannot, a notice at the top of
the app says when the list runs out, once seven days or fewer are left. When the list is out of date, the notice says
"The list of community tools is out of date, so community tools cannot be installed or updated. Installed ones keep
working." Until a new list arrives, the row of a community tool says why its **Install** or **Update** does not work.
Uninstall still works. Your own tools and WireCat's own tools do not use the list. The notice shows only while
community tools are on.

### Add a tool by its npm name

1. In Settings, turn on **Allow tools WireCat has not checked**. A warning opens: a tool you add this way runs as you
   on this computer, so it can read everything WireCat keeps, add only tools whose authors you trust completely, and
   WireCat takes no responsibility for what they do. Confirm it with **Allow**.
2. On the Tools page, click **Add your own tool**, at the top next to **Check again**. Type the npm name, such as
   `@scope/name`, and click **Check package**. WireCat only reads npm. Nothing is installed, and no code of the
   package runs.
3. Read the review screen (below), then click **Add**.
4. WireCat asks "Check `@scope/name` before you install it?" and offers your AI agent first. There is one
   **Check it with** button for each agent it can open, such as **Check it with Claude Code** or **Check it with
   Codex**. The agent opens in a terminal with a prepared request: download exactly the package file you reviewed,
   check its sha512, read the code, compare it with the repository at the release commit, and report the servers it
   contacts, what it reads and writes on this computer, and anything suspicious. It never installs or runs the
   package. **What your agent is asked** shows the whole request. With no agent found, click **Copy the check** and
   paste it into yours. Read the agent's report, then click **Continue to install**, or **Skip and install** without
   the check.
5. A second question asks: "Install and run `@scope/name`? Its install scripts and first run use your permissions."
   Only **Install and run** installs the package. **Back** returns to the review.
6. After the install, WireCat checks that the program describes itself as the review showed. The tool is on the Tools
   page at once, with the **Not verified** badge. No restart is needed.

Only some packages work. The package must have a scope (`@scope/name`, not `@wirecat/`), be written in TypeScript on
[cli-base](https://github.com/WireCatLabs/cli-base), and ship its manifest `contracts/wirecat.json`: a file that
describes the tool's commands to WireCat. A program on your PATH or a package without a scope cannot be added. A maker
builds such a tool as [Create your CLI](../build-create-cli.md#make-it-addable-in-wirecat-desktop) shows.

### The review screen

Nothing is installed yet when it opens. From the top:

- **Not verified**, beside the tool's name.
- **A red warning**, true for every tool you add: it runs as you on this computer, so it can read everything WireCat
  keeps (your messages, mail, notes and files). For a tool built on cli-core, WireCat's own library, the warning adds
  that it opens that data directly. Add it only if you trust its authors completely.
- **Published by**, **Repository**, **Version** and **Where npm built it**. Each is a link that opens in your
  browser: the publisher's npm profile, the repository, the version's page (**On npm**), and, when npm recorded where
  it built the package, **Release commit**, **Release workflow run** and **Transparency-log entry**. "No record of
  where npm built it" means nothing ties the package to public source code.
- **Things to check**: each item with one sentence on why it matters. They come from npm (first published less than
  30 days ago, few versions, one npm account publishes it, no record of where npm built it), from its GitHub
  repository (created recently, no change for a long time, archived, few stars, workflows that do not run WireCat's
  standard checks), from the WireCat libraries it uses or does not use, and from its code (it opens network
  connections, names servers it does not declare, can start other programs, hides calls, or ships native `.node` or
  `.wasm` files). When GitHub cannot be reached or is out of checks, the item says "Couldn't check its GitHub
  repository", and the other checks still apply. With nothing to show it says "Nothing stood out. That does not make
  it safe."
- **Servers it contacts**: the servers the tool declares, "It says it contacts no servers", or "It does not say".
  A server you choose, such as your own mail server, is named too.
- **What it says it does**: a table of the data the tool works with (Contact, Deal…), with its fields where the
  tool names them. For each, **With** the service and **On this computer**: **Reads**, **Changes** or **Saves**, or
  **Nothing**. Then what its sync copies into WireCat's store, and **WireCat's standard commands** in plain words
  (signs in, checks that it works, installs instructions for your AI agents…). The exact commands are folded under
  **Commands**; click it to open the list.

What the screen means:

- **Things to check are flags, not a verdict.** None of them stops you from adding the tool, and an empty list does
  not make it safe. What WireCat reads in the package's code is "found in the code, not proved": the libraries the
  package bundles are skipped, and code can be written to hide from such a reading.
- **"Where npm built it" is not a safety check.** npm records which repository built the package. That shows where
  the code came from, not that it is safe.
- **"What it says it does" is what the tool says about itself.** WireCat cannot prove that a tool does only that.
- **Installing runs its code.** npm runs the package's install scripts with your permissions. That is why the AI
  check comes first, and why there are two confirmations.

### Update it

The tool's **Update to** button opens the review again for the new version, every time. It also lists what changed
since the version you confirmed: the repository, where npm built it, the publishers, new commands, new write access,
and new or changed parts. When anything changed, or the tool does not describe what it asks for, tick
**I accept these changes** before you can go on. The AI check and the second question follow, as for a new tool.

### Remove it

- **Remove from WireCat**, in the tool's details (click its name), deletes the tool's entry, and the tool leaves the
  Tools page at once. No restart is needed. When the program is installed, the question offers **Uninstall it
  first**; otherwise the program stays installed, and the Tools page says what stays on the computer.
- **Uninstall** removes the program. **Uninstall and delete data** also deletes the tool's own data folders: only the
  folders named after its package (`@scope/name` → `scope-name`). It never deletes the store your other tools share.
  A folder with that name that already existed before you added the tool is listed with "This folder existed before
  WireCat added the tool, so WireCat leaves it alone", and is never deleted.

### Without the internet

Checking a package, adding it and updating it read npm, so they need the internet. Without it the dialog says
"Couldn't reach npm". A tool you already added stays on the Tools page offline: WireCat keeps its entry on this
computer and does not ask npm again at start. Whether the tool itself works offline depends on the tool and its
service.

## The tools stay command-line tools

The app installs the same npm packages as `npm install -g @wirecat/tg-cli` and runs the tools' own
commands for versions, health checks, sign-in and sync. A tool installed by the app also works in a
terminal and for any agent, and a tool you installed yourself shows up in the app. The app never picks
an account or profile for you: a command that needs one uses the one you chose.

Your data stays where the tools keep it, on this computer. The app goes online to install tools from
npm, to download Node.js when it sets one up, to check GitHub for its own new version and to send a bug
report when you send one.

## Updates and removal

On macOS, Windows and with the AppImage, the app updates itself: it offers a new version at the top of
the window, then installs it and restarts. A .deb or .rpm copy downloads the new package
itself and opens your system's installer, and also shows the `apt` or `dnf` command. **Open in terminal** runs
that command in your terminal: type your password there, then restart WireCat when the install ends. Your accounts and data
will not be deleted. [Updates](/en/download#updates) and [uninstall](/en/download#uninstall) on the download page give the
steps for each system. Removing the app leaves the tools and their data in place.

Prefer a terminal? [Install a tool by hand or with your agent](../installation.mdx).

## Common issues

Find the message you see, then follow the fix. If none fits, [Report a problem](#report-a-problem) in the app collects what the support team needs.

### Windows says "Windows protected your PC"

The installer is signed, but SmartScreen trusts a signed app only after enough people have installed it, and the certificate is new, so Windows may still ask you to confirm the first start. Select **More info**, check that the publisher is **Open Source Developer Viacheslav Ptsarev**, then select **Run anyway**. If the publisher is different or missing, do not run the file: download it again from the [download page](/en/download). **Smart App Control** lets an app with a valid signature run; an older, unsigned version of WireCat is blocked when it is on. The [first-start steps](/en/download#first-launch) show where to click.

### The AppImage says "AppImages require FUSE to run"

The AppImage needs FUSE 2. Install it with `sudo apt install libfuse2t64` on Ubuntu 24.04 and later, or `sudo apt install libfuse2` on older Ubuntu and Debian, then open the file again. The [first-start steps for Linux](/en/download#first-launch) say the same.

### "Node.js is needed to install WireCat tools", "Node.js is too old" or "npm needs administrator rights"

The tools run on Node.js 22.16 or later within 22.x, or 24 or later, with npm. WireCat Desktop itself runs without it. Select **Set up Node.js for me**: WireCat downloads Node.js, checks it against the checksums Node.js publishes and unpacks it in your user folder, without administrator rights. Your own Node.js stays as it is. If you prefer to install it yourself, choose **I'll install it myself** and select **Check again** afterwards.

### An installed tool is not found in a terminal or an AI app

Terminals and AI apps that were open before the install see the new tools only after you restart them. If a new terminal still does not find the tool and WireCat set up Node.js for you, open the Node.js entry under **Your computer** and select **Add to PATH**, then open a new terminal. For a shell that WireCat does not edit, the same dialog shows a line to add to the shell's startup file yourself. **Remove from PATH** undoes it.

### Installing a tool fails with "Could not reach the npm registry"

WireCat installs tools from npm, so it needs the internet. Check your connection or proxy and select **Try again**. An install that takes longer than 15 minutes is stopped; the same check applies. If the message says the release "could not be confirmed as built by WireCat", nothing on your computer changed: try again later.

### A tool shows "Installed, but it does not start"

The tool's lamp is red and its button says **Fix**. **Fix** opens **Fix with an AI agent**: WireCat writes what went wrong into a prompt and opens Claude Code, Codex or Gemini CLI with it in a terminal. The agent explains what it finds and asks before it changes anything. When it says the problem is fixed, select **Try again**. If WireCat finds no agent, copy the prompt into your own agent. On macOS, if Terminal does not open, allow WireCat under System Settings, Privacy & Security, Automation. A second copy of the same tool can also cause trouble: **Manage** lists the copies and how to remove the extra one.

### Sign-in does not finish

**Sign in here** waits for you to finish in the browser or on the phone. A code or QR code expires after a few seconds, and a new one appears by itself; use the latest one. A messenger can take a minute to send its history: keep it open on the phone, or select **Stop and keep what came**. If the message says the version "cannot sign in here yet", update the tool on the Tools page or use **Open terminal**. If WireCat finds no terminal program, run the command it shows yourself, then select **Check sign-in**.

### Check health reports a broken settings file

A missing or extra comma, a comment, single quotes or an unclosed bracket in a tool's settings file stops the tool from reading its settings. Under **Manage**, **Check health** names the problem; select **Repair the file**. The tool keeps the file as it was, says what it changed, and changes nothing it cannot fix safely. If it refuses, the message points at the line to correct by hand in a text editor.

### A tool "can't read storage"

Another WireCat tool moved the shared storage to a newer format than this tool reads. Update the tool on the Tools page; [Storage](#storage) lists which tools need it. If no newer version is out yet, the page says so. The app checks this before it installs or updates a tool, so you usually see this only after **Update anyway**, or after a tool was updated outside the app, for example with npm in a terminal.

### "The update could not be installed"

Select **Try again**, or get WireCat from the [download page](/en/download). If the message says the download "did not match WireCat's signature", WireCat did not open it and saved nothing. A .deb or .rpm copy opens your system's installer, which asks for your password. A copy that WireCat cannot recognize cannot update itself: install the new version the way you installed this one. Your accounts and data will not be deleted. More in [Updates and removal](#updates-and-removal).

### "The list of community tools is out of date"

**Coming in the next WireCat Desktop release.** The list of [community tools](#community-tools) that WireCat signs has
run out, and the app could not fetch a new one. Until it does, community tools cannot be installed or updated.
Installed ones keep working, and your own tools are not affected. Check your internet connection or proxy. The app
tries again every day, and the notice goes away once a new list arrives.

### WireCat refuses a tool you add

When you [add your own tool](#add-your-own-tool), the dialog names the problem in a headline, such as **Tool not
found**, then says what went wrong and what to do. **Try again** returns to the name field with the name kept and
selected, so you can correct it. When npm could not be reached, the package is too large or something unexpected went
wrong, **Try again** reads the same name again. Nothing is installed before the second question, except in the last
two rows.

| The dialog says | What to do |
| --- | --- |
| Tool not found: npm has no package named … | Check the spelling, including the scope: `@scope/name`. |
| Only scoped package names work here, such as @scope/name. | Ask the tool's author for its full npm name. |
| This name belongs to WireCat's own tools. | WireCat's own tools are already on the Tools page. Install them there. |
| This tool does not describe itself to WireCat. | Paste its `desktop` object from the tool's documentation into the field below the message, and click **Check with this object**. Or ask its author to publish a version with a manifest. |
| What the tool tells WireCat has a problem in "…": … | The quotes name the part, then the rule it breaks. Ask the tool's author to fix it and publish a new version. |
| … already uses this tool's name, program or data folder. | Two tools cannot share them. Ask the tool's author to rename it. |
| …, on WireCat's community list, already uses this tool's name or folders. | This tool is now listed. Remove your own entry to use the listed one. |
| npm says it was built by …, but the package names …. | Do not add it. Tell the tool's author. |
| WireCat could not reach npm. | Check your internet connection or proxy, then try again. |
| The … is larger than WireCat reads. | Ask the tool's author to make the package smaller. |
| Something went wrong reading npm: … | Try again. If it happens again, report a problem. |
| WireCat could not show this tool: … | Ask the tool's author to fix it and publish a new version. |
| The package is installed, but WireCat did not add it. | The program does not match the review. Click **Uninstall it**. |
| bun installed this tool, and bun cannot be told which registry your own tools come from. | Shown when you update a tool you added that bun installed. Uninstall it, then add it again: WireCat installs it with npm. |
