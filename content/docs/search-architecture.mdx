Learn how to find an exact message, locate a discussion by topic and check its sources. To try it now, open the **[Telegram](./tg/search.md)** or **[MAX](./max/search.md)** search guide for commands and examples. Below we explain word forms, typo handling and when semantic search helps.

## Choose the right path

Use message search for words, people, dates and file filters. Use topic search when you remember the subject rather than the wording. Open the original messages before relying on either result. A forum topic, an inferred conversation and neighbouring messages are different objects.

## 1. Archive and identity

The tool saves messages under their provider, account and chat, so equal numeric identifiers do not mix different sources. Search uses the saved copy; an index or vector does not prove the whole chat has been fetched. Choose chats and a period, fetch history, then check the reported coverage. Native server search can supply candidates separately; counts and conversation analysis still depend on saved data.

## 2. Strict message search

Strict message search parses the query, resolves people and chats within its scope, selects candidates from the word/file indexes and checks the requested fields. Results carry message locators for opening the source. A phrase, prefix, date filter and exact-word match are different conditions; the [Telegram](./tg/query-language.md) and [MAX](./max/query-language.md) references define their syntax and limits.

<ArchitectureDiagram name="strictSearch" lang="en" />

### Word forms

Search can match word forms: “invoice” can find “invoices”. If the spelling is approximate, ask the agent to allow typos: “Use tg CLI to find messages about the presentaion; account for misspellings.” Replace `tg` with `max` for MAX. The agent chooses the appropriate mode; you do not need to remember its name.

<details>
<summary>When entering commands yourself</summary>

`messages search` uses strict Lucene by default. It matches word forms but does not correct typos. Add `--language legacy` for typo correction; use `exact:` or `--exact` for literal forms where supported. Syntax: [Telegram](./tg/query-language.md) and [MAX](./max/query-language.md).

</details>

### Server search beside the archive

A messenger can search its own server even when part of the history is absent locally. Which fields and modes it supports differs between Telegram and MAX. Check the selected backend and scope in the [Telegram search guide](./tg/search.md) or [MAX search guide](./max/search.md); do not treat a remote candidate as proof that all local analysis has complete history.

## 3. Reconstruct discussions with a message graph

The stored reply and mention relationships help reconstruct discussions. A discussion may span messages far apart in time; nearby messages may be unrelated. Missing parents, stale links and incomplete history affect the result. Read the linked chain and surrounding messages before interpreting the graph as an agreement.

## 4. Pieces and vectors

Conversation text is split into pieces and can be represented by numeric vectors. A local model uses your computer; an explicitly configured external provider receives the text needed for its operation. Build conversations first, then prepare vectors for the chosen model. Missing vectors and another model’s vectors are not interchangeable with a ready meaning-search index.

### Measurements

Historical benchmark below: measured on 2 October 2026, with its original version and hardware. It remains useful for understanding costs; it is not a measurement of the current release.

<details>
<summary>Historical measurements</summary>

100,000 messages in three languages, 5–40 words each, as one chat; AMD Ryzen AI 9 HX 470 (24 threads), 30 GB RAM, Linux, Node 24 and Bun 1.3; measured 2 October 2026 ([benchmark](https://github.com/leemour/cli-messaging/blob/v0.148.2/bench/embeddings/README.md)).

| Step | Runtime | Time | Peak memory |
| --- | --- | --- | --- |
| `conversations build` | Node | 3.3 s | 331 MB |
| `conversations embed`, 1 worker | Node | 1,371 s (31 pieces/s) | 1.2 GB |
| `conversations embed`, 3 workers | Node | 1,240 s (34 pieces/s) | 2.6 GB |
| `conversations embed`, 1 worker | Bun | 1,329 s (32 pieces/s) | 3.2 GB |
| `conversations embed`, 3 workers | Bun | 1,279 s (33 pieces/s) | 2.7 GB |

The run made 42,417 pieces and grew the store by 292 MB. Three workers gave only 1.1× on Node and 1.04× on Bun: one session already uses 8 threads, and three workers share about the same number. A search, once the vector scan reads each page by its key: about 0.35 s in a process that keeps the model open (the MCP server), about 1.4 s for a one-shot command, of which loading the model is about 1 s.

</details>

## 5. Hybrid conversation retrieval

Topic search combines matches by words with matches by meaning where prepared vectors are available. Ranking gives candidates, not a verified answer. Inspect the matched piece, full conversation and source messages. Model, account, chat and time scope determine which data can participate.

## 6. Freshness

New messages, edits and deletions can change an index, graph or piece. Refresh the history and the derived data needed by your query. Inspect freshness and missing-data fields rather than assuming one successful build made every chat current. [Archive preparation](./tg/archive.md) and [MAX archive](./max/archive.md) explain capture and recovery.

## 7. Evidence and context for an agent

Keep the locator, chat, author, date and relevant surrounding text for an important claim. Distinguish a literal match, a semantic candidate, a graph relationship and the assistant’s own conclusion. The report example in [group administration](./group-admins.md) shows why complete relationships between saved messages do not imply complete history.

## 8. What the playground demonstrates

The [search playground](./search-playground.mdx) demonstrates filtering and checking context on synthetic data. It does not run the production vector model, download your history or reproduce every query operator. Use it to learn how to inspect a source, then use the messenger guides for a real archive.
