Conecta la información que quieres que use tu agente de IA: mensajes, notas, correo, documentos
o reuniones. Elige una herramienta, instálala donde tu agente pueda ejecutarla y comprueba un
resultado pequeño. No necesitas una cuenta de mensajería para empezar con archivos locales o
una transcripción descargada.

¿Ya está instalado y conectado? [Conecta tu agente](./agents.mdx) y
[prueba una primera tarea](./index.mdx#prueba-una-petición). Una búsqueda vacía suele requerir
comprobar los datos disponibles antes de volver a instalar.

¿Prefieres no usar la terminal? [WireCat Desktop](/es/download) es una aplicación para macOS, Windows y
Linux. Instala y actualiza estas herramientas, instala Node.js si falta, da a tus agentes las skills de
las herramientas y abre el inicio de sesión de cada una. [Qué hace la aplicación](./desktop/index.mdx).

JSON del cliente de tu propia aplicación de Google. Sigue la guía elegida: no hay un archivo
de credenciales común para todas las herramientas.

## Configura con tu agente

Usa un <DocTerm term="local-agent" lang="es" label="agente de IA" /> con acceso a la terminal en este ordenador, como Claude Code, Codex, Cursor o Gemini
CLI. Indica la herramienta y la fuente elegidas y copia esta petición:

```text prompt
Ayúdame a configurar la herramienta WireCat elegida siguiendo su guía. Comprueba primero Node.js y npm.
Conecta solo la cuenta o carpeta elegida; yo aprobaré el acceso.
Instala las instrucciones para mi agente y prepara unos pocos datos.
Prueba una pregunta de solo lectura, muestra su fuente e indica los datos que faltan.
Explica dónde se guardan los datos y cómo detener el trabajo en segundo plano que inicies.
```

El agente prepara los programas y explica el siguiente paso. Tú apruebas el acceso en el inicio
de sesión del propio servicio. Cuando el agente inicia la sesión, te pega en el chat el código QR o el
enlace de acceso: consulta [cuando el agente inicia la sesión](./agents.mdx#agent-login). Sigue la guía
para el consentimiento en el navegador o el token de un bot; no pegues contraseñas, tokens ni respuestas
de autorización en el chat habitual.

Para un agente sin terminal, usa [MCP](./mcp.mdx) o [el acceso web y móvil](./browser-apps.mdx).
La herramienta sigue necesitando un ordenador que controlas.

## Configura a mano

1. **Elige el ordenador.** Lo más sencillo es empezar en tu equipo con Windows, macOS o Linux.
   Un servidor sirve para tareas recurrentes, pero sus sesiones y archivos se guardan allí.
   Una carpeta del portátil no aparece automáticamente en el servidor. No necesitas ambos.
2. **Comprueba el entorno** con los comandos de abajo. Después usa el comando de instalación
   de la guía elegida. Una herramienta de línea de comandos, o CLI, es un programa que el agente
   ejecuta mediante una terminal.
3. **Conecta la fuente.** Sigue sus pasos de acceso o importación. Instalar un paquete no autoriza
   una cuenta; iniciar sesión tampoco descarga todos sus datos.
4. **Conecta tu agente.** [Instala el skill o configura MCP](./agents.mdx). El skill da instrucciones
   a un agente con terminal; MCP expone capacidades a un agente compatible.
5. **Prepara los primeros datos y compruébalos.** Usa las comprobaciones siguientes antes de añadir fuentes.

## Node.js, npm y cómo encontrar el comando

<DocTerm term="nodejs" lang="es" label="Node.js" /> ejecuta las herramientas; npm las instala.
Las líneas compatibles son **22.16+ dentro de 22.x, o 24+**; tg necesita **22.19+** dentro de 22.x.
Consulta otras opciones de ejecución en la guía de la herramienta. En Terminal o PowerShell, ejecuta:

```sh
node --version
npm --version
```

Si falta alguno o la versión es antigua, pide al agente que prepare el entorno:

<NodeSetupPrompt lang="es" />

Tras instalar, comprueba la versión de la herramienta **en el mismo entorno que usa el agente**.
La instalación global pone los comandos en PATH, las carpetas donde la terminal busca programas.
Abre de nuevo la terminal o reinicia un agente que ya estuviera ejecutándose si no encuentra el comando.

<a id="npm-install-scripts" />

### El aviso de npm sobre scripts de instalación

npm 11.17 y posteriores avisan tras la primera instalación global de `tg`, `max` o `memo`:
`install scripts not yet covered by allowScripts`. El aviso nombra el script de configuración de la
herramienta y su controlador de base de datos. Con npm 11 ambos scripts se ejecutan igualmente y la
herramienta funciona, así que puedes ignorar el aviso. npm 12, en cambio, los bloquea. Ejecuta el
comando `npm install -g --allow-scripts=…` que npm muestra bajo el aviso: permite solo los paquetes
que nombra, una vez.

<a id="what-the-windows-installer-changes" />

<a id="windows-y-acceso-al-comando" />

### Windows y visibilidad del comando

Si PowerShell bloquea `npm.ps1`, usa `npm.cmd`. Quizá también necesites el lanzador `.cmd` de la
herramienta; consulta sus pasos para Windows. Telegram y MAX ofrecen además un instalador que
configura PATH y las instrucciones del agente. No supongas que sirve para todas las herramientas.
Usa los pasos de [Telegram](./tg/installation.md), [MAX](./max/installation.md),
[Drive](./drive/installation.md) o [Zoom](./zm/installation.md).

## Comprueba el primer resultado útil

Pide al agente que compruebe la cuenta o carpeta elegida, recupere un periodo pequeño o importe
una carpeta pequeña y responda una pregunta con una fuente:

- **Mensajes:** mostrar algunos chats, recuperar el periodo necesario y encontrar un mensaje conocido.
  [Historial de Telegram](./tg/archive.md) · [historial de MAX](./max/archive.md).
- **Archivos o correo:** importar una carpeta elegida o un buzón configurado y buscar una frase conocida.
  [Memo](./memo/index.md) · [correo](./email.mdx).
- **Drive:** importar una carpeta elegida y abrir el documento del resultado.
  [Primera importación de Drive](./drive/usage.md).
- **Reuniones:** recuperar o importar una transcripción y leer un fragmento citado.
  [Primer resultado de Zoom](./zm/installation.md#check-your-first-result).

El resultado funciona cuando el comando está disponible, la fuente correcta está conectada, hay
datos útiles guardados y el agente puede citarlos. Comprueba fechas y archivos ausentes o ilegibles
antes de interpretar una respuesta vacía. El inicio de sesión, el skill o MCP por sí solos no lo demuestran.

<a id="datos-permisos-y-trabajo-en-segundo-plano" />

## Datos, actualizaciones y trabajo en segundo plano

Las sesiones y los datos locales se guardan donde se ejecuta la herramienta. El agente puede
enviar contenido consultado a su proveedor de IA según sus ajustes. Revisa [seguridad y flujo de datos](./security.mdx)
y [permisos](./permissions.mdx) antes de permitir cambios.

Instalar no inicia sincronización continua ni respuestas automáticas. Las tareas recurrentes
necesitan un proceso o una programación; pide al agente cómo detener lo que inicie. Cerrar su chat
no detiene necesariamente un proceso separado. Consulta [tareas recurrentes](./prompting.mdx#recurring-tasks).

Para actualizar o desinstalar, sigue la guía de la herramienta. Quitar un paquete, borrar datos
locales y revocar el acceso a una cuenta son acciones distintas. Cuando funcione la primera
comprobación, [elige la siguiente tarea](./index.mdx#prueba-una-petición).
