Ask your browser assistant to search Telegram or MAX, summarise conversations or draft replies.
Both `tg` and `max` provide HTTP MCP with OAuth; **Tailscale is a separate program** that gives
that server a public HTTPS address. Install it on the computer running the messenger CLI.
Your browser device needs no Tailscale installation.


## Before starting

- Install and log into [Telegram or MAX](./installation.mdx) under your normal OS user.
  Setup without a local agent is `tg setup --agent none` or `max setup --agent none`.
- Install [Tailscale](https://tailscale.com/download) and sign in. Enable MagicDNS, HTTPS
  certificates and [Funnel](https://tailscale.com/docs/features/tailscale-funnel) in your tailnet.
  The first Funnel command can print a link to approve this configuration.
- Keep the computer awake and both terminal windows open while using the connector.
- Your app or workspace must support custom MCP servers. See the current
  [OpenAI plugin guide](https://developers.openai.com/plugins/quickstart) or
  [Claude connector guide](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp).

## Start the tunnel and messenger server

Choose your operating system below. **The first code block goes in window 1; the second in
window 2.** Copy the real HTTPS origin printed by Funnel when window 2 asks. Do not append
`/mcp` here. Keep a public port such as `:8443` if Funnel prints one.
The commands grant sending for this process; read the permission explanation below.

<PlatformSetupTabs>

<Tab value="Windows">

**Windows · PowerShell**

Install the Windows Tailscale app and sign in through its tray menu. Open fresh PowerShell
windows after installing Node.js, the CLI and Tailscale so they see the updated PATH.
Use `.cmd` CLI shims to avoid PowerShell execution-policy errors; initial setup is
`tg.cmd setup --agent none` or `max.cmd setup --agent none`.

Run **window 1 as Administrator** for Funnel. `&` handles the space in the default installation
path; adjust it if Tailscale is installed elsewhere. Run **window 2 as your normal user**,
who logged into the messenger.

```powershell
& "$env:ProgramFiles\Tailscale\tailscale.exe" funnel 8765
```

```powershell
$mcpPublicUrl = Read-Host 'HTTPS origin from Funnel (no /mcp)'
tg.cmd mcp --http --port 8765 --public-url $mcpPublicUrl --permission messages.send=allow
```

For MAX, replace `tg.cmd` with `max.cmd` in window 2. Run both processes in native Windows.
WSL has separate paths and loopback networking; do not mix its server with this Windows setup.

</Tab>

<Tab value="macOS">

**macOS · Terminal (zsh or bash)**

Install the Tailscale app and sign in. Its [bundled CLI](https://tailscale.com/docs/reference/tailscale-cli?tab=macos)
works even when `tailscale` is absent from PATH. Use two ordinary Terminal windows.

```sh
TAILSCALE_BE_CLI=1 /Applications/Tailscale.app/Contents/MacOS/Tailscale funnel 8765
```

```sh
printf 'HTTPS origin from Funnel (no /mcp): '
IFS= read -r mcpPublicUrl
tg mcp --http --port 8765 --public-url "$mcpPublicUrl" --permission messages.send=allow
```

For MAX, replace `tg` with `max` in window 2.

</Tab>

<Tab value="Linux">

**Linux · Terminal (bash or zsh)**

Install Tailscale using the [Linux instructions](https://tailscale.com/download/linux)
and sign in with `sudo tailscale up`. Only the tunnel in window 1 needs `sudo`.
Window 2 must run as your normal user, so it finds the session you set up.

```sh
sudo tailscale funnel 8765
```

```sh
printf 'HTTPS origin from Funnel (no /mcp): '
IFS= read -r mcpPublicUrl
tg mcp --http --port 8765 --public-url "$mcpPublicUrl" --permission messages.send=allow
```

For MAX, replace `tg` with `max` in window 2. Do not run the messenger server with `sudo`.

</Tab>

</PlatformSetupTabs>

The server listens on `127.0.0.1:8765` and prints a one-time login code. A named profile goes
before the command, for example `tg work mcp`; on Windows, `tg.cmd work mcp`.

## Choose what the assistant may do

The examples above allow sending for this running server with `--permission messages.send=allow`.
Your saved settings stay the same. The app controls its own approval prompts. Over MCP,
`ask` does not force a server confirmation. For a connection that only reads, use a read-only profile.

The app's approval and the server's permission checks are separate. If you always allow a tool in the
app and the server permits it, another call can send without asking again. Ask for a draft when
you want to review the text first. Recipient restrictions and hourly limits still apply.
See [permissions](./permissions.md) for examples and how to change access.

## Add it to Codex / ChatGPT web or Claude

Use the Funnel origin **with `/mcp` appended** as the connector URL. Each messenger gets its
own connector. Choose OAuth, not a manually copied token.

**Codex / ChatGPT web:** open **Plugins → + Add custom MCP server**, create a plugin, and
enter the `/mcp` URL and OAuth. Choose dynamic client registration (DCR) when offered;
the server advertises DCR and S256. Connect using the terminal code, install the plugin,
then enable it in a Work chat or mention it with `@`.
Local Codex `config.toml` configures the local client, not this web connection.
Follow the [OpenAI instructions](https://developers.openai.com/plugins/quickstart) and
[OAuth requirements](https://developers.openai.com/plugins/build/auth).

**Claude:** add a custom connector in **Customize → Connectors → + Add**, paste the `/mcp` URL,
and connect with the code printed by the messenger server.
Follow [Claude's current instructions](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp).

Before entering the code, check that the login page names your intended app as the destination.
Codes work once for 10 minutes. Five wrong codes lock login until the server restarts.

## Try reading first

Start a chat with the plugin or connector enabled:

```text prompt
List my five most recent Telegram chats with their unread counts.
```

Then ask for a draft or, when you intend to send, name the recipient and exact text.
[Writing requests](./prompting.md) explains how to ask for review before sending.

## It worked before, but stopped

A browser connection needs the messenger computer, its server and the HTTPS tunnel to be running. After sleep or a restart, use this order:

1. Wake the computer and check the account in a terminal with `tg account show` or `max account show`. Use `tg.cmd` or `max.cmd` in PowerShell. If this fails, follow the login guide for [Telegram](./tg/sessions.md) or [MAX](./max/sessions.md).
2. Restart the tunnel and server using the two windows above. Use the same profile and check that the HTTPS address still matches the connector. If it changed, update the server's public URL and the connector URL.
3. Retry the five-chat request. If the app asks you to connect again, use the new one-time code printed by the running server.

Success means the assistant lists the expected account’s chats. If it still fails, the checks below help distinguish a local account problem from a tunnel or app problem. Files need one additional step: a path on this computer does not give a browser agent the file. See file transfer for [Telegram](./tg/remote.md) or [MAX](./max/remote.md).

## Run both messengers

Use separate local ports and public HTTPS endpoints. For example: Telegram on local `8765`
and public `443`; MAX on local `8766` and public `8443`. For the second tunnel, use your OS's
Tailscale invocation with `funnel --https=8443 8766`, and add `--port 8766` to MAX.
Copy its printed HTTPS origin including `:8443` into MAX's startup command and append `/mcp`
for its connector. Funnel's permitted public ports are `443`, `8443` and `10000`
([reference](https://tailscale.com/docs/reference/tailscale-cli/funnel)).

## Stop, restart or revoke

- **Stop:** Ctrl-C in both foreground windows stops that server and tunnel.
- **Restart:** repeat the commands with the same profile and public URL. Browser logins survive
  ordinary restarts; they expire after 30 days without renewal.
- **Background Funnel:** if you used `--bg`, Ctrl-C does not disable it. Check
  `tailscale funnel status`, then disable only that route with `tailscale funnel --https=443 off`
  (or `8443` for the second server). Use your OS's executable path and elevation above.
  Avoid `funnel reset` if you have another route: it clears them all.
- **Revoke app access:** run `tg mcp --revoke` or `max mcp --revoke`; use `tg.cmd` / `max.cmd`
  in PowerShell. Apps must log in again. Your messenger account stays logged in.

## Troubleshooting

- **No connection:** append `/.well-known/oauth-protected-resource/mcp` to the origin and open
  it in a browser. You should see JSON. Otherwise check Funnel, its approval and the local port.
- **Reads work, sending fails after app approval:** check the startup permissions and the
  effective permission. Use `deny` or `readonly` to refuse server-side changes; check the app's own approval settings.
- **PowerShell refuses scripts:** use `tg.cmd` or `max.cmd`. If the command is missing, reopen
  PowerShell and check the CLI installation; do not change machine-wide execution policy.
- **No tools:** `tg mcp doctor` or `max mcp doctor` checks the local handshake, not the tunnel or
  messenger login. An explicit `account show` command checks that account connection.
- **Port occupied:** use another local port and point Funnel at the same number. For simultaneous
  servers, also give each route a distinct public HTTPS port as above.
