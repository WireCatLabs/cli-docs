Use Telegram and MAX directly from a **ChatGPT or claude.ai chat in your browser**: find a message, gather context or draft a reply. Setup takes a few commands and adding an address in your chat settings. After setting it up in the browser, use the connection in the mobile ChatGPT or Claude app too: sign into the same account, enable the connected tool in your chat and make the same request.

This guide connects your chosen messenger and checks it with a request for your own chats. A program on your computer talks to the messenger; ChatGPT or Claude reaches that program <DocTerm term="public-address" lang="en" label="through a public address" />. <DocTerm term="mcp" lang="en" label="MCP" /> is the way these tools connect to an assistant. Below, we will obtain the address and add it to the app.

## Before starting

- Install the [command-line tool for Telegram or MAX](./installation.mdx) and sign into your account. A local agent is unnecessary for browser use: `tg setup --agent none` or `max setup --agent none`.
- Use the computer running the tool for initial setup, and keep it awake while connected. The end of this page explains an always-on server option.
- Your ChatGPT or Claude account needs an option for adding a custom connection. If it is missing in a work account, check with your administrator. The [OpenAI instructions](https://developers.openai.com/plugins/quickstart) and [Claude instructions](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp) show current options.

We will install the additional program for the public address in the next step, with instructions for what to click.

## 1. Prepare a public address

We use **Tailscale**, a program that makes the connection on your computer reachable over the internet. You do not need it on the phone or other device where you open your chat.

### Install Tailscale and sign in

1. Open the [download page](https://tailscale.com/download) and choose Windows, macOS or Linux.
2. On Windows or macOS, download and run the installer, then open the app. Select the Tailscale icon near the Windows clock or in the macOS menu bar, then **Log in**. For Linux, follow the [installation and login instructions](https://tailscale.com/download/linux).
3. Sign in or create a Tailscale account in the browser that opens, and approve connecting your computer. It should appear in the [device list](https://console.tailscale.com/admin/machines).

### Enable the secure address

1. Open the [DNS page in the Tailscale console](https://console.tailscale.com/admin/dns).
2. Under **MagicDNS**, select **Enable MagicDNS** if disabled. This gives the computer a name for its address.
3. Under **HTTPS Certificates**, select **Enable HTTPS** and accept the displayed notice. This enables secure addresses; see the [Tailscale instructions](https://tailscale.com/docs/how-to/set-up-https-certificates).
4. The first command in the next step may show an approval link for **Funnel**, the public-access feature. Open it, sign into the same account and approve enabling it. Tailscale prepares the certificate and permission automatically. If access is refused, an administrator can use **Access controls → Funnel → Add Funnel to policy**: [Funnel instructions](https://tailscale.com/docs/features/tailscale-funnel).

## 2. Get the address and start the connection

Choose your operating system and <DocTerm term="terminal" lang="en" label="open two terminal windows" />. **Paste the first block into window 1**: it prints an address such as `https://computer.network.ts.net`. If it first shows an approval link, complete item 4 above and return here.

**Paste the second block into window 2** and supply the printed HTTPS address when asked, without `/mcp`. Keep `:8443` if the address contains it. Leave both windows open. These commands allow sending while the connection runs; [choosing permissions](#choose-what-the-assistant-may-do) is explained below.

## 3. Add the connection to ChatGPT or Claude

Append **`/mcp` to the HTTPS address**. For example, `https://computer.network.ts.net` becomes `https://computer.network.ts.net/mcp`. This is the connection address, not the Telegram or MAX website. Create a separate connection for each messenger.

### ChatGPT

1. Open **Plugins → + Add custom MCP server**, give it a name such as “My Telegram”, and paste the address with `/mcp`.
2. Choose <DocTerm term="oauth" lang="en" label="OAuth" />. Choose automatic registration (**DCR**) if offered. Sign in with the one-time code from window 2.
3. Install the plugin, open a **Work** chat and select it with `@`. Then write ordinary requests. [Official OpenAI instructions](https://developers.openai.com/plugins/quickstart).

### Claude

1. In claude.ai, open **Customize → Connectors → + Add → Add custom connector**. Enter a name and the `/mcp` address, then select **Continue**.
2. Choose to sign in and select **Register automatically** if offered. Finish adding the connector and connect using the code from window 2.
3. In your chat, use **+ → Connectors** to enable it. It also works in mobile Claude. An administrator may need to add it first for a work account: [official Claude instructions](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp).

Before entering the code, check the app name on the sign-in page. The code works once for 10 minutes; five incorrect attempts require restarting the server.

## Try reading first

Start a chat with the plugin or connector enabled:

```text prompt
List my five most recent Telegram chats with their unread counts.
```

Then ask for a draft or, when you intend to send, name the recipient and exact text.
[Writing requests](./prompting.mdx) explains how to ask for review before sending.

## Choose what the assistant may do

The examples above allow sending for this running server with `--permission messages.send=allow`.
Your saved settings stay the same. The app controls its own approval prompts. Over MCP,
`ask` does not force a server confirmation. For a connection that only reads, use a read-only profile.

The app's approval and the server's permission checks are separate. If you always allow a tool in the
app and the server permits it, another call can send without asking again. Ask for a draft when
you want to review the text first. Recipient restrictions and hourly limits still apply.
See [permissions](./permissions.mdx) for examples and how to change access.

## It worked before, but stopped

A browser connection needs the messenger computer, its server and the HTTPS tunnel to be running. After sleep or a restart, use this order:

1. Wake the computer and check the account in a terminal with `tg account show` or `max account show`. Use `tg.cmd` or `max.cmd` in PowerShell. If this fails, follow the login guide for [Telegram](./tg/sessions.md) or [MAX](./max/sessions.md).
2. Restart the tunnel and server using the two windows above. Use the same profile and check that the HTTPS address still matches the connector. If it changed, update the server's public URL and the connector URL.
3. Retry the five-chat request. If the app asks you to connect again, use the new one-time code printed by the running server.

Success means the assistant lists the expected account’s chats. If it still fails, the checks below help distinguish a local account problem from a tunnel or app problem. Files need one additional step: a path on this computer does not give a browser agent the file. See file transfer for [Telegram](./tg/remote.md) or [MAX](./max/remote.md).

## Run both messengers

Use separate local ports and public HTTPS endpoints. For example: Telegram on local `8765`
and public `443`; MAX on local `8766` and public `8443`. For the second tunnel, use your OS's
Tailscale invocation with `funnel --https=8443 8766`, and add `--port 8766` to MAX.
Copy its printed HTTPS origin including `:8443` into MAX's startup command and append `/mcp`
for its connector. Funnel's permitted public ports are `443`, `8443` and `10000`
([reference](https://tailscale.com/docs/reference/tailscale-cli/funnel)).

## Stop, restart or revoke

- **Stop:** Ctrl-C in both foreground windows stops that server and tunnel.
- **Restart:** repeat the commands with the same profile and public URL. Browser logins survive
  ordinary restarts; they expire after 30 days without renewal.
- **Background Funnel:** if you used `--bg`, Ctrl-C does not disable it. Check
  `tailscale funnel status`, then disable only that route with `tailscale funnel --https=443 off`
  (or `8443` for the second server). Use your OS's executable path and elevation above.
  Avoid `funnel reset` if you have another route: it clears them all.
- **Revoke app access:** run `tg mcp --revoke` or `max mcp --revoke`; use `tg.cmd` / `max.cmd`
  in PowerShell. Apps must log in again. Your messenger account stays logged in.

## Troubleshooting

- **No connection:** append `/.well-known/oauth-protected-resource/mcp` to the origin and open
  it in a browser. You should see JSON. Otherwise check Funnel, its approval and the local port.
- **Reads work, sending fails after app approval:** check the startup permissions and the
  effective permission. Use `deny` or `readonly` to refuse server-side changes; check the app's own approval settings.
- **PowerShell refuses scripts:** use `tg.cmd` or `max.cmd`. If the command is missing, reopen
  PowerShell and check the CLI installation; do not change machine-wide execution policy.
- **No tools:** `tg mcp doctor` or `max mcp doctor` checks the local handshake, not the tunnel or
  messenger login. An explicit `account show` command checks that account connection.
- **Port occupied:** use another local port and point Funnel at the same number. For simultaneous
  servers, also give each route a distinct public HTTPS port as above.

## Connect without keeping your laptop awake

You can install `tg` or `max` on a separate server that stays running, and connect ChatGPT or Claude to its address. You can then use your messenger from the chat while your laptop is off.

Install the tool on the server, sign into the chosen account, start its MCP connection and provide a public HTTPS address. Configure automatic startup after a reboot: both the messenger program and public access must remain running. The server needs its own account login; your laptop installation does not connect it automatically.

Try this after the connection works on your computer. See remote setup for [Telegram](./tg/remote.md) and [MAX](./max/remote.md). Repeat the five-chat request after setup: if it works with your laptop off, the server is providing the connection.

<details>
<summary>Linux server: keep the connection running after logout and reboot</summary>

1. Use one ordinary Linux user for installation, messenger login and the service. Install Node.js, the CLI and Tailscale, then log into the messenger as that user. First verify the five-chat request using the foreground commands above.
2. Run `tg mcp config` or `max mcp config`. Take the absolute Node path from `command` and the CLI entry path from `args`; preserve a named profile if present. Do not put account passwords or bot tokens in the service file.
3. Create `~/.config/systemd/user/wirecat-mcp.service`. Replace the two paths and public address in this template with the actual values. Use the same configuration/state directories as your successful login:

```ini
[Unit]
Description=WireCat messenger connection

[Service]
Type=simple
WorkingDirectory=%h
ExecStart=/absolute/path/to/node /absolute/path/to/cli-entry.js mcp --http --port 8765 --public-url https://server.tailnet.ts.net
Restart=on-failure
RestartSec=10

[Install]
WantedBy=default.target
```

4. Enable the service with the commands below. An administrator must also enable lingering for that user, for example `loginctl enable-linger wirecat`, so user services can run without an active login. See [systemd services](https://www.freedesktop.org/software/systemd/man/latest/systemd.service.html) and [lingering](https://www.freedesktop.org/software/systemd/man/latest/loginctl.html).

```sh
systemctl --user daemon-reload
systemctl --user enable --now wirecat-mcp.service
systemctl --user status wirecat-mcp.service
```

5. On the server, start the public address in the background with `tailscale funnel --bg 8765`, using the elevation required by your installation. The [Funnel reference](https://tailscale.com/docs/reference/tailscale-cli/funnel#effects-of-rebooting-and-restarting) explains how it resumes after reboot. Its port must match the MCP service.
6. Check that the service can access the same login and unlocked keyring. A running HTTP endpoint does not prove the messenger account is accessible. If login fails after reboot, restore the user’s keyring access; do not solve it by copying credentials into the unit.
7. Close the SSH session, turn your laptop off and retry the chat request from the app. Repeat after a server reboot. Both the account access and the public address should work without a manual terminal launch.

To stop or disable automatic startup:

```sh
systemctl --user stop wirecat-mcp.service
systemctl --user disable wirecat-mcp.service
```

`journalctl --user -u wirecat-mcp.service -n 30` helps diagnose startup. It can include the one-time app connection code; use that code for your own sign-in and do not publish the full log. Other server platforms use their own service manager with the same account/path checks.

</details>
