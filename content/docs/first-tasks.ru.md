После [установки и входа](./installation.mdx) попросите агента разобрать входящие, найти сообщение
или собрать контекст к встрече. Если агент ещё не видит CLI, [подключите его](./agents.md).
Вы задаёте цель обычными словами; агент выбирает команды и аргументы.

Вход в аккаунт не скачивает всю переписку. Для поиска по прошлым сообщениям может понадобиться
загрузить историю выбранного чата. Агент должен объяснить, какие данные уже доступны и чего не хватает.

## Начните со входящих

Скопируйте запрос своему агенту. Для MAX замените `tg cli` на `max cli`.

```text prompt
Используй tg cli: покажи пять рабочих чатов и скажи, в каких входящих от меня ждут ответа.
Только читай; ничего не отправляй и не отмечай прочитанным.
```

В ответе полезны краткий список дел и сообщения-основания. Непрочитанное сообщение не обязательно
требует ответа: агенту нужно отличить вопрос к вам от новости или уже решённого обсуждения.

Для первых шагов доступны `chats list` и `inbox`. В Telegram и MAX отдельные возможности различаются;
подробности — в [использовании Telegram](./tg/usage.md) и [MAX](./max/usage.md).
Ниже разобраны примеры для Telegram. Имена, сообщения и ID вымышлены; команды показывают возможный
путь агента. В вашей переписке он должен брать ID из результатов CLI.

## Найти договорённость в истории

**Вы:**

```text prompt
Используй tg cli: в «Atlas · команда» найди, какую сумму за аналитику мы согласовали в сентябре.
Покажи оценку и подтверждение. Если истории не хватает, скажи, какой период нужно загрузить.
Ничего не отправляй.
```

Агент находит нужный чат и проверяет локальную историю:

```sh
tg chats list --search "Atlas" --json
tg store status 101 --json
```

**Агент:** «Нашёл проектную группу. В локальном архиве пока нет сентябрьской переписки;
пустой поиск не покажет, обсуждали ли сумму. Можно загрузить историю этого чата с 1 сентября?»

**Вы:**

```text prompt
Да, только этот чат с 1 сентября, не больше 500 сообщений. Сначала покажи оценку объёма.
```

```sh
tg store fetch 101 --since-time 2026-09-01T00:00:00+02:00 --limit 500 --estimate --json
tg store fetch 101 --since-time 2026-09-01T00:00:00+02:00 --limit 500 --json
tg messages search "аналитика after:2026-09-01 before:2026-10-01" --chat 101 --json --language legacy
tg messages context 101 201 --before-n 3 --after-n 3 --json
```

Оценка строится по уже имеющимся данным и может быть приблизительной. Лимит 500 ограничивает этот
запуск загрузки; он не гарантирует, что весь нужный период поместится в него.

**Агент:** «Марко предложил 1500 евро без НДС 5 сентября, а вы подтвердили сумму 6 сентября.
Основания — сообщения 200 и 201. Архив всё ещё отмечен как неполный, поэтому позднее изменение
цены за весь сентябрь пока исключить не могу».

**Вы:** «Проверь, были ли другие оценки после подтверждения. Если достигнешь лимита истории,
скажи, что осталось непроверенным».

Следующий шаг зависит от результата: проверить последующие сообщения, обработать курсор или
предложить ограниченное продолжение загрузки. Если нужный период уже есть в архиве, скачивать
его повторно не требуется. Для короткого свежего окна бывает достаточно `messages list` с датами.
[Как устроены поиск и архив](./tg/archive.md).

## Подготовиться к созвону

**Вы:**

```text prompt
Используй tg cli: собери контекст по Atlas за неделю — решения, текущие риски и вопросы.
Проверь проектные группы и мою личку с участниками, чтобы не обсуждать уже решённое.
Ничего не отправляй.
```

Агент находит группы проекта и читает относящиеся к задаче сообщения:

```sh
tg chats list --search "Atlas" --json
tg review --chat 101 --since-time 7d --json
tg review --chat 102 --since-time 7d --json
```

**Агент:** «Макет готов, тексты ещё не согласованы. Вчера Том написал в группе, что ему нужен
доступ к production для проверки оплаты. Проверю его личку перед тем, как включать это в риски».

```sh
tg chats list --search "Том" --kind dialog --json
tg messages list 501 --after-time 7d --limit 50 --json
```

**Агент:** «Сегодня Том подтвердил: доступ получил, оплату проверил. Этот блокер снят.
Открытым осталось согласование текстов. В группе дизайна указан срок “до четверга” — точную дату
стоит уточнить. Проверены две группы и личка Тома; отдельные договорённости с другими участниками
в эти выводы пока не входят».

**Вы:**

```text prompt
Сделай повестку на 20 минут. Для каждого вопроса укажи, кого спросить и какое решение нужно получить.
```

**Агент:**

| Время | Вопрос | Результат |
|---|---|---|
| 0–8 минут | Анна: какие тексты осталось утвердить? | Ответственный и точная дата |
| 8–15 минут | Можно ли запускаться после утверждения текстов? | Критерий готовности и дата запуска |
| 15–20 минут | Том: где зафиксирована проверка production? | Ссылка на результат и обновлённый статус для команды |

Если список сообщений обрезан, агент должен учитывать `more`/`hasMore`, продолжить чтение или
ограничить вывод доступным окном. [Входящие и review](./tg/usage.md#reading).

## Проверить обещания и подготовить ответ

**Вы:**

```text prompt
Используй tg cli: проверь, кому я обещал ответить за неделю и от кого сам жду результат.
Сделай черновики. Перед напоминанием Тому проверь, не прислал ли он макет в личку.
```

```sh
tg review --since-time 7d --all --json
tg chats list --search "Том" --kind dialog --json
tg messages list 501 --after-time 7d --limit 50 --json
```

**Агент:** «Анне обещан счёт, клиенту — подтверждение доставки. Том уже прислал первый вариант
макета в личке; финал обещал после комментариев. Для него предлагаю такой ответ»:

> Том, спасибо за первый вариант! Подскажи, когда сможешь прислать финал с учётом комментариев?

**Вы:**

```text prompt
Оставь ответы черновиками. По Тому покажи сообщение с первым вариантом и договорённость о финале.
```

Агент показывает найденные сообщения и при необходимости проверяет их окружение:

```sh
tg messages context 501 510 --before-n 3 --after-n 3 --json
```

**Агент:** «Первый вариант получен, поэтому напоминание “ты ничего не прислал” было бы неверным.
Срок финала ещё нужно уточнить. Ответы остались черновиками».

Черновик и разрешение на отправку — разные шаги. Если позже захотите отправить ответ, укажите
точного адресата и согласованный текст. [Отправка сообщений](./tg/usage.md#sending).

## Выберите следующую задачу

| Задача | Что добавить к запросу | Где посмотреть возможности |
|---|---|---|
| Новости из каналов | Каналы, период, темы и ссылки на источники | [Telegram](./tg/usage.md) |
| Рекомендованный контакт | Нужные услуги и критерии сравнения | [Примеры запросов](./prompting.md#найти-рекомендованный-контакт) |
| Актуальные документы | Проект, типы файлов, согласованные версии | [Примеры запросов](./prompting.md#собрать-актуальные-документы) |
| Голосовое | Отправитель/сообщение и нужный результат | [Telegram](./tg/usage.md) |
| Напоминания | Дата, время, часовой пояс и адресат | [Примеры запросов](./prompting.md#поставить-напоминания) |
| Локальный экспорт | Период, папка и запрет сети | [Архив Telegram](./tg/archive.md) |
| Клиентский бот | Бот, доступный контекст и правила эскалации | [Боты MAX](./max/bot.md), [Telegram](./tg/bot.md) |

В [«Как формулировать запросы»](./prompting.md) — копируемые примеры и пояснения, какие детали
помогают получить точный ответ. Если задача упёрлась в подключение, вернитесь к
[настройке агента](./agents.md) или [решению проблем Telegram](./tg/troubleshooting.md).

Чтобы воспроизвести поиск с фактическим выводом на контролируемом наборе, откройте [подготовку к встрече](./meeting-brief.md).
