Memo ayuda a tu agente a encontrar información repartida entre archivos, notas, correo y
mensajes. Usa esta guía cuando quieras encontrar una decisión anterior o reunir contexto
antes de una conversación. Explica cómo instalar Memo, elegir las fuentes y comprobar los resultados.

Después de seguir la guía, podrás:

- conectar una carpeta de archivos de texto o una bóveda de Obsidian y buscar en su contenido;
- añadir correo y usarlo junto al historial de mensajes descargado;
- pedir un resumen con fuentes a tu agente y reconocer qué datos faltan.

## Antes de empezar

Usa un <DocTerm term="local-agent" lang="es" label="agente de IA local" /> en el ordenador donde
están tus archivos. Puedes empezar con una sola carpeta de notas. El correo y el historial
son opcionales; para incluir mensajes, [conecta Telegram o MAX](./installation.mdx) y descarga
el historial necesario. Memo lee ese historial local; no lo descarga por sí mismo.

<a id="pruébalo-con-tu-agente" />

## Instala Memo

**La forma más fácil: pídeselo a tu agente.** Copia esta petición en Claude Code, Codex, Cursor,
Gemini CLI o Hermes, igual que para instalar Telegram o MAX:

```text prompt
Ayúdame a instalar Memo en este ordenador con npm install -g @leemour/cli-memo.
Comprueba primero Node.js y npm y ayúdame a configurarlos si hace falta.
Lee memo --help y https://wirecat.dev/es/docs/memo para conocer las órdenes.
Comprueba que memo --help funciona en tu terminal y ayúdame a conectar la carpeta que elija.
```

El agente instala la <DocTerm term="cli" lang="es" label="CLI" /> y comprueba la orden `memo`.
Memo no tiene un paso de inicio de sesión en el mensajero; tú eliges las carpetas y configuras
el correo por separado. El navegador muestra las instrucciones; la instalación ocurre en tu ordenador.

## Añade tus notas

### Elige una carpeta

Una carpeta es un directorio de tu ordenador que contiene archivos. Memo lee la carpeta elegida
**y sus subcarpetas**: puede trabajar con carpetas de proyectos, de notas o bóvedas de Obsidian.
Puedes registrar más de una carpeta.

Una <DocTerm term="vault" lang="es" label="bóveda de Obsidian" /> es una carpeta de notas que
Obsidian abre como un espacio de trabajo. Sus notas son archivos
<DocTerm term="markdown" lang="es" label="Markdown" />; Memo los lee directamente, sin necesitar
que Obsidian esté abierto. No hace falta usar Obsidian para usar Memo.

### Archivos que Memo puede leer

| Archivos | Extensiones habituales | Qué esperar |
| --- | --- | --- |
| Texto y notas Markdown | `.txt`, `.md`, `.markdown` | Texto legible, incluidas las notas de Obsidian. |
| Tablas y hojas de cálculo | `.csv`, `.tsv`, `.xlsx`, `.ods` | Texto y valores de celdas, con ubicaciones de origen cuando estén disponibles. |
| Documentos, diapositivas y libros | `.odt`, `.pptx`, `.epub` | Texto legible extraído, sin el diseño original. |
| PDF y documentos Word | `.pdf`, `.docx` | Necesitan lectores opcionales: `unpdf` para PDF y `mammoth` para DOCX. |

Un PDF escaneado contiene imágenes de páginas; necesita reconocimiento de texto antes de
importar su contenido. Los antiguos `.doc` y `.xls` no son compatibles; conviértelos a un formato
admitido. La importación indica los archivos ilegibles o lectores que faltan, en vez de darlos por buscados.

### Importa la carpeta que elijas

Sustituye `/path/to/notes` por la ruta completa de una **carpeta existente** en tu ordenador.
Para carpetas normales, elige el formato Markdown:

```sh
memo folders add /path/to/notes --format markdown
memo notes import --no-embed
```

Para una bóveda de Obsidian, sustituye `/path/to/vault` por su ruta y elige el formato Obsidian:

```sh
memo folders add /path/to/vault --format obsidian
memo notes import --no-embed
```

El formato indica cómo interpretar los enlaces y etiquetas de las notas. Markdown usa enlaces
como `[label](other-note.md)`; Obsidian también entiende `[[Note]]`. Obsidian es el predeterminado
si omites `--format`.

El registro muestra un ID de carpeta. La importación copia el contenido legible al almacén local
sin cambiar los archivos originales. Omite carpetas ocultas como `.obsidian`.
`--no-embed` limita esta primera importación a la búsqueda por palabras, por lo que no necesitas
un modelo de búsqueda para empezar. Repite `memo notes import --no-embed` después de editar o añadir archivos.

### Encuentra información en tus archivos

Dile a tu agente qué tema quieres encontrar:

```text prompt
Usa Memo para encontrar notas y archivos sobre el presupuesto en las carpetas que he importado.
Muestra el texto coincidente y el archivo de origen de cada resultado útil. Indica qué archivos no se han podido leer.
```

Para buscar manualmente:

```sh
memo notes search 'budget' --json
```

Los resultados identifican el archivo, una referencia de origen y la primera línea coincidente.
Abre el archivo para comprobar el detalle. Si no hay resultados, prueba una palabra que sepas
que está en un archivo y revisa el informe de importación: un archivo sin importar no aparece en la búsqueda.

## Añade correo

Memo lee correo a través de [Himalaya](https://github.com/pimalaya/himalaya), un programa de
correo independiente. Tu cuenta se configura allí; Memo usa su nombre y dirección sin necesitar
otra copia de la contraseña. Pide ayuda a tu agente:

```text prompt
Ayúdame a conectar la cuenta de correo que elija a través de Himalaya y añadirla a Memo.
Explica la configuración de la cuenta e importa el correo desde la fecha que elija.
Muestra el resultado e indica si hace falta otra ejecución para terminar ese periodo.
```

La cuenta debe funcionar en Himalaya antes de que Memo pueda importar el correo. Para configurarlo manualmente:

Añade `mail.accounts` a la configuración de Memo, conservando los ajustes existentes. Rutas predeterminadas:

| OS | Archivo de configuración |
| --- | --- |
| Linux | `~/.config/cli-memo/config.json` |
| macOS | `~/Library/Preferences/cli-memo/config.json` |
| Windows | `%APPDATA%\cli-memo\Config\config.json` |

`MEMO_CONFIG_DIR` cambia el directorio; en Linux, `XDG_CONFIG_HOME` también afecta a la ruta predeterminada.
El ejemplo usa una cuenta de Himalaya llamada `gmail`; sustituye el nombre y la dirección por los tuyos.

```json
{
  "mail": {
    "accounts": [{ "name": "gmail", "address": "you@example.com" }]
  }
}
```

Gmail es el modo predeterminado e importa All Mail. Para otro proveedor IMAP, añade
`"mode": "imap"` y `"folders": ["INBOX", "Archive"]` a la cuenta, con los nombres reales
de las carpetas de tu buzón.

```sh
memo mail import --account gmail --since 2026-09-01 --json
```

Elige la fecha inicial que quieras incluir. Cada ejecución lee hasta 200 mensajes nuevos
por defecto; repítela para continuar si el resultado indica que la importación está incompleta.
El buzón se abre solo para lectura: importar no envía correo ni lo marca como leído.
El correo importado se almacena localmente; repetir la importación puede eliminar del almacén
el texto de los mensajes que hayan desaparecido de la fuente.

Vincula explícitamente una dirección de correo con su identidad de mensajería mediante
`tg contacts link` o `max contacts link`; los nombres coincidentes no identifican a la misma persona.
Consulta la guía para [trabajar con personas](./people.md).

## Pide el contexto que necesitas

Cuando hayas conectado las fuentes, pide contexto sobre una persona. Sustituye el nombre:

```text prompt
Usa Memo para reunir contexto sobre Rin Example antes de la reunión: mensajes recientes,
correo, notas vinculadas y tareas abiertas. Incluye las fuentes e indica qué datos faltan.
```

Para asociar una nota de archivo importada a una persona, sustituye el nombre y la ruta:

```sh
memo note telegram:"Rin Example" /path/to/notes/people/Rin.md
```

El archivo debe estar ya importado. Un nombre en texto normal no crea un enlace; asocia la nota
explícitamente o usa un enlace compatible como `[[Rin Example]]` en Obsidian.

El agente puede reunir contexto de una persona o buscar en las fuentes importadas:

```sh
memo context telegram:"Rin Example" --json
memo search 'budget' --all --json
```

`--all` incluye explícitamente todas las cuentas almacenadas y las notas importadas. Revisa las
referencias y la cobertura antes de confiar en una respuesta. El historial que falta, el correo
fuera del periodo importado o los enlaces de notas sin resolver pueden dejar un resultado incompleto.
Añade `--account <id>` a `context` si hay varias cuentas almacenadas del mismo proveedor.

También puedes guardar una nota propia sobre la persona:

```sh
memo notes add 'Prefers morning meetings' --about telegram:'Rin Example'
memo notes list --about telegram:'Rin Example' --json
```

Estas notas viven en el almacén local. Escribirlas no cambia un archivo importado;
`memo notes export` es una acción explícita y separada para escribir archivos.

## Comprueba el resultado

Una respuesta útil identifica los archivos, mensajes o correos detrás de cada detalle importante.
Abre una fuente para comprobar un acuerdo o fecha. El agente debe explicar las carencias, como
un periodo de correo sin importar, archivos ilegibles o un enlace a una persona sin resolver.
Un resultado ausente no demuestra que no hubiera un acuerdo.

## Si falta algo

- **Orden no encontrada:** comprueba `memo --help` en el terminal del agente y vuelve a abrirlo tras la instalación.
- **No hay notas:** comprueba `memo folders list`, repite `memo notes import --no-embed` y revisa el resultado.
- **No hay cuenta de correo:** comprueba que `mail.accounts` nombra una cuenta configurada en Himalaya.
- **Persona incorrecta o nombre ambiguo:** usa el proveedor y el ID exacto; vincula las identidades explícitamente.
- **Contexto incompleto:** importa las notas y el correo pertinentes y descarga el historial que falta con tg o max.

Cuando las fuentes estén disponibles, continúa con [preparar una reunión](./meeting-brief.mdx).
Consulta las opciones con `memo --help` o el `--help` de una suborden.
La [documentación de órdenes de Memo](https://github.com/leemour/cli-memo#readme)
también describe tareas, relaciones, etiquetas, recordatorios locales y conjuntos de fuentes.
