Tus contratos, informes y notas están en Yandex Disk, y un agente de IA en tu ordenador no puede leerlos a menos que
descargues cada archivo y lo pegues en el chat. La herramienta de línea de comandos `ydisk` copia a tu ordenador el
texto de las carpetas del Disk que elijas. Después tu agente encuentra el archivo que menciona un presupuesto, un
cliente o una fecha, lo cita y te da su ruta en el Disk, incluso sin internet. Cuando lo necesitas, la misma
herramienta lista, descarga, sube, mueve y comparte archivos en el Disk.

Para empezar necesitas Node.js 22.16 o un 22.x posterior, o 24 o posterior, y un token OAuth de Yandex: una clave con la que la herramienta usa
tu Disk. Esta página explica cómo funciona la copia, cómo conseguir el token y cómo conectar tu primera carpeta.

<a id="how-it-works"></a>

## Cómo funciona

- **Una copia del texto en tu ordenador.** `ydisk` lee las carpetas que eliges y guarda el texto de sus archivos en el
  almacén local, un archivo de base de datos en tu ordenador que comparten todas las herramientas de WireCat. La
  búsqueda lee esta copia, no el Disk.
- **Solo las carpetas que eliges.** Añade unas pocas carpetas, no todo el Disk. Yandex Disk no le dice a la
  herramienta qué cambió, así que cada sincronización vuelve a listar todas las carpetas elegidas y sus subcarpetas, y
  descarga solo los archivos que cambiaron.
- **Texto, no copias de archivos.** La herramienta lee Markdown, texto plano, PDF con capa de texto, Word `.docx`,
  Excel `.xlsx`, CSV y TSV. Los demás archivos, como las fotos, se guardan solo por su nombre. Los archivos se quedan
  en el Disk.
- **Un perfil por cuenta.** Un perfil es el nombre que eliges para una cuenta de Yandex, como `personal` o `work`.
  Cada comando que usa una cuenta empieza por él: `ydisk personal search budget`.
- **Los comandos `files` cambian el Disk.** Trabajan directamente con Yandex. Borrar mueve el archivo a la papelera del
  Disk. En una terminal la herramienta pregunta antes de borrar, sobrescribir o crear un enlace público. Por MCP no hay
  a quién preguntar, así que pon esos permisos en `deny` para un agente que no deba hacerlo.

<a id="install-and-sign-in"></a>

## Instalar e iniciar sesión

**Muy pronto.** `ydisk` aún no está en npm. El comando lo instalará cuando salga su primera versión.

1. Instala la herramienta desde npm y compruébala:

```sh
npm install -g @wirecat/yandex-disk-cli
ydisk --version
ydisk doctor
```

2. Consigue un token. Yandex se lo da a una aplicación que registras, y lo recibes abriendo un enlace
   ([guía de Yandex](https://yandex.ru/dev/id/doc/en/tokens/debug-token)):
   - Registra una aplicación en [oauth.yandex.com](https://oauth.yandex.com/client/new/). En el paso "App
     platforms", elige "Web services" e introduce el Redirect URI `https://oauth.yandex.ru/verification_code`.
   - Dale los accesos `cloud_api:disk.read`, `cloud_api:disk.info` y, para cambiar archivos, `cloud_api:disk.write`.
   - Abre `https://oauth.yandex.com/authorize?response_type=token&client_id=<ClientID>` con el ClientID de tu
     aplicación, pulsa Allow y copia el token de la página.

3. Inicia sesión con un nombre de perfil que elijas. La herramienta pide el token sin mostrarlo, lo comprueba con
   Yandex y lo guarda en el llavero del sistema, o en un archivo privado donde no hay llavero.

```sh
ydisk personal session start
ydisk personal session status --check
```

Cuando Yandex deje de aceptar el token, vuelve a ejecutar `session start` con uno nuevo.

<a id="copy-a-folder-and-search-it"></a>

## Copia una carpeta y busca en ella

`folders browse` muestra el Disk nivel a nivel, para que elijas una carpeta por su ruta:

```sh
ydisk personal folders browse
ydisk personal folders add /Documents
ydisk personal sync
ydisk personal search "quarterly budget"
```

Una sincronización lee hasta 200 archivos (`--limit`), recorre hasta unos 10.000 elementos y guarda dónde se detuvo. Vuelve a ejecutarla para continuar, y
más tarde para traer lo que cambió. `ydisk personal status` muestra la última sincronización y el trabajo pendiente.
`documents show` muestra el texto completo de un archivo encontrado.

<a id="connect-your-agent"></a>

## Conecta tu agente

Un agente de terminal como Claude Code recibe la skill de la herramienta:

```sh
ydisk skill install
```

Después pide con palabras normales:

```text prompt
Usa ydisk CLI con el perfil personal. Busca el contrato con Harbour Ltd en mis carpetas del Disk.
Cita las condiciones de pago y dame la ruta del archivo en el Disk. No cambies ningún archivo.
```

El agente busca primero en la copia local. Un archivo fuera de las carpetas elegidas lo lee en directo del Disk. Una
aplicación que se conecta a servidores MCP recibe los mismos comandos con `ydisk personal mcp serve`.

<a id="work-with-files-on-the-disk"></a>

## Trabaja con archivos en el Disk

```sh
ydisk personal files list --folder /Documents
ydisk personal files download /Documents/plan.pdf --output ./plan.pdf
ydisk personal files upload ./notes.md --folder /Documents
ydisk personal files move /Documents/old.pdf --folder /Archive
ydisk personal files delete /Documents/old.pdf
ydisk personal files publish /Documents/plan.pdf
```

`files delete` mueve el archivo a la papelera del Disk, y `files restore` lo devuelve. `files publish` crea un enlace
que puede abrir cualquiera que lo tenga. En una terminal la herramienta pregunta antes de borrar, de sobrescribir con
`--replace` o de crear un enlace público. Por MCP no hay a quién preguntar, así que para un agente que no debe hacerlo,
pon los permisos `files.delete=deny` y `files.share=deny`. `YDISK_READ_ONLY=1` rechaza cualquier cambio.

<a id="limits"></a>

## Límites

- Los PDF escaneados y las imágenes no tienen texto que buscar.
- Una carpeta elegida que renombras o mueves en el Disk deja de sincronizarse y sus copias salen del almacén. Vuelve a
  añadirla con su nueva ruta.
- El inicio de sesión es con un token pegado. Todavía no hay inicio de sesión en el navegador.
