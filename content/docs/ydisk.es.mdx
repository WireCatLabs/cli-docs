Encuentra cualquier documento de tu Yandex Disk por lo que dice y deja que tu agente de IA lo lea, lo archive y lo
comparta por ti. La herramienta de línea de comandos `ydisk` copia a tu ordenador el texto de las carpetas del Disk
que elijas, así que una búsqueda de «contrato de alquiler» encuentra el PDF aunque se llame `scan_0042.pdf`, e incluso
sin internet.

Pregunta a tu agente dónde está el contrato con un cliente y qué condiciones de pago tiene. Te responde con la cita y
la ruta del archivo en el Disk. Pídele que mueva las facturas del año pasado a un archivo o que cree un enlace para un
colega, y lo hace en el Disk, preguntándote antes de borrar o de crear un enlace público.

`ydisk` funciona con Claude Code, Codex y otros agentes que ejecutan comandos, con Claude Desktop y Cursor por MCP, y
con ChatGPT y Claude en el navegador a través de tu propio túnel. Necesita Node.js y un token OAuth de Yandex: una
clave de tu propia cuenta de Yandex con la que la herramienta usa tu Disk.

<a id="how-it-works"></a>

## Cómo funciona

- **Una copia del texto en tu ordenador.** `ydisk` lee las carpetas que eliges y guarda el texto de sus archivos en el
  almacén local, un archivo de base de datos en tu ordenador que comparten todas las herramientas de WireCat. La
  búsqueda lee esta copia, no el Disk, y encuentra otras formas de una palabra en ruso y en inglés.
- **Solo las carpetas que eliges.** Yandex Disk no dice a la herramienta qué cambió, así que cada sincronización vuelve
  a listar todas las carpetas elegidas con sus subcarpetas y descarga solo los archivos cuyo contenido cambió. Elige
  carpetas con documentos, no todo el Disk.
- **Texto, no copias de archivos.** La herramienta lee Markdown, texto plano, PDF con capa de texto, Word `.docx`,
  Excel `.xlsx`, CSV y TSV. Las fotos y los demás archivos se guardan solo por su nombre. Los archivos se quedan en el
  Disk.
- **Un perfil por cuenta.** Un perfil es el nombre que eliges para una cuenta de Yandex, como `personal` o `work`.
  Cada comando que usa una cuenta empieza por él: `ydisk personal search budget`.
- **Los comandos `files` cambian el Disk.** Trabajan directamente con Yandex. Borrar mueve el archivo a la papelera del
  Disk. En una terminal la herramienta pregunta antes de borrar, sobrescribir o crear un enlace público.

<a id="install-and-sign-in"></a>

## Instalar e iniciar sesión

1. Instala la herramienta desde npm y compruébala. Necesitas Node.js 22.16 o un 22.x posterior, o 24 o posterior.

```sh
npm install -g @wirecat/yandex-disk-cli
ydisk --version
ydisk doctor
```

2. Registra una aplicación en Yandex para obtener un token. La aplicación es solo un nombre y una lista de permisos en
   tu cuenta, y no se publica nada. Las páginas de Yandex están en ruso, así que sus textos se dan también en ruso
   ([guía de Yandex](https://yandex.ru/dev/disk-api/doc/ru/concepts/quickstart)):
   - Abre [oauth.yandex.ru/client/new](https://oauth.yandex.ru/client/new/) e inicia sesión con la cuenta cuyo Disk
     quieres usar. Si Yandex pregunta el tipo de aplicación, elige «Для доступа к API или отладки» (para acceso a la
     API o depuración).
   - Escribe cualquier nombre y tu correo. En «Доступ к данным» (acceso a los datos) añade los permisos de Yandex Disk
     `cloud_api:disk.read`, `cloud_api:disk.info` y, para cambiar archivos, `cloud_api:disk.write`.
   - Crea la aplicación y copia su **ClientID** de la página de la aplicación.

3. Abre `https://oauth.yandex.ru/authorize?response_type=token&client_id=` añadiendo tu ClientID al final, permite el
   acceso y copia el token de la página. Guárdalo como una contraseña.

4. Inicia sesión con el nombre de perfil que elijas. La herramienta pide el token con entrada oculta, lo comprueba
   con Yandex y lo guarda en el llavero del sistema, o en un archivo privado donde no hay llavero.

```sh
ydisk personal session start
ydisk personal session status --check
```

Yandex mantiene válido el token durante meses mientras se usa. Cuando Yandex deje de aceptarlo, consigue uno nuevo
igual y vuelve a ejecutar `session start`.

`ydisk personal session end` quita el token de este ordenador.

<a id="copy-a-folder-and-search-it"></a>

## Copia una carpeta y busca en ella

`folders browse` muestra el Disk un nivel cada vez, para elegir una carpeta por su ruta:

```sh
ydisk personal folders browse
ydisk personal folders add /Documents
ydisk personal sync
ydisk personal search "presupuesto trimestral"
```

Una sincronización lee hasta 200 archivos (`--limit`), recorre hasta unas 10 000 entradas y recuerda dónde se detuvo.
Ejecútala otra vez para seguir y, más adelante, para traer lo que cambió. Nada se sincroniza en segundo plano.
`ydisk personal status` muestra la última sincronización, el trabajo pendiente y los archivos guardados solo por su
nombre. `documents show` imprime el texto completo de un archivo encontrado por la búsqueda.

La búsqueda por significado encuentra un documento que responde a una pregunta con otras palabras. Necesita un modelo de
texto que se descarga una vez con [Memo](./memo/installation.md), `memo models download embeddinggemma`, y después
`ydisk personal sync --embed`.

<a id="connect-your-agent"></a>

## Conecta tu agente

Un agente de terminal como Claude Code o Codex recibe la guía de la herramienta:

```sh
ydisk skill install
```

Después pídele las cosas con palabras normales:

```text prompt
Usa ydisk CLI con el perfil personal. Busca en mis carpetas del Disk el contrato con Harbour Ltd.
Cita las condiciones de pago y dame la ruta del archivo en el Disk. No cambies ningún archivo.
```

El agente busca primero en la copia local. Un archivo fuera de las carpetas elegidas lo lee en directo del Disk.

Para añadir la herramienta como servidor MCP, `ydisk personal mcp add claude-code --allow-writes` (o `codex`) lo hace
con un solo comando. Para Claude Desktop, Cursor y otras aplicaciones MCP, `ydisk personal mcp config` imprime la
entrada que debes pegar en los ajustes de la aplicación. Para ChatGPT y Claude en el navegador, mira las
[aplicaciones del navegador](./browser-apps.mdx).

<a id="work-with-files-on-the-disk"></a>

## Trabaja con archivos en el Disk

```sh
ydisk personal files list --folder /Documents
ydisk personal files download /Documents/plan.pdf --output ./plan.pdf
ydisk personal files upload ./notes.md --folder /Documents
ydisk personal files move /Documents/old.pdf --folder /Archive
ydisk personal files delete /Documents/old.pdf
ydisk personal files publish /Documents/plan.pdf
```

`files delete` mueve el archivo a la papelera del Disk, y `files restore` lo devuelve. `files publish` crea un enlace
que puede abrir cualquiera que lo tenga. En una terminal la herramienta pregunta antes de borrar, de sobrescribir con
`--replace` o de crear un enlace público. Por MCP no hay a quién preguntar, así que para un agente que no debe hacerlo,
cierra esos permisos:

```sh
ydisk personal config set permissions.files.delete deny
ydisk personal config set permissions.files.share deny
```

`YDISK_READ_ONLY=1` rechaza cualquier cambio. `--dry-run` en cualquier cambio muestra lo que haría sin hacerlo.

<a id="limits"></a>

## Límites

- Los PDF escaneados y las imágenes no tienen texto que buscar. Los archivos de más de 50 MB se guardan solo por su
  nombre.
- Una carpeta elegida que renombras o mueves en el Disk deja de sincronizarse y sus copias salen del almacén. Vuelve a
  añadirla con su nueva ruta.
- El inicio de sesión es con un token pegado de una aplicación que registras tú. Todavía no hay inicio de sesión en el
  navegador.

<a id="if-something-goes-wrong"></a>

## Si algo no funciona

- **«refused the token», código de salida 4.** El token es incorrecto, está revocado o caducó. Consigue uno nuevo y
  vuelve a ejecutar `session start`.
- **Un cambio falla con el código de salida 5.** El token se creó sin `cloud_api:disk.write`, o los permisos del perfil
  rechazan el cambio.
- **La búsqueda no encuentra un archivo que sabes que está.** Comprueba que su carpeta aparece en `folders list`,
  ejecuta `sync` hasta que `status` no muestre trabajo pendiente y mira si `status` lo lista como guardado solo por su
  nombre.
- **«the OS keyring did not answer» en Linux.** Cierra la sesión y vuelve a entrar, o inicia sesión con
  `ydisk personal session start --credential-storage file`.

`ydisk doctor` muestra lo que está configurado sin conectarse, y `ydisk personal doctor --online` comprueba el token.
Hay más casos en la [página de problemas](https://github.com/WireCatLabs/ydisk-cli/blob/main/docs/troubleshooting.md).
