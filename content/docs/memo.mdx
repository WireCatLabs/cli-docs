Memo helps your agent find information spread across files, notes, email and messages. Use
this guide when you want to find a past decision or gather context before a conversation.
It explains how to install Memo, choose the sources to include and check what your agent finds.

After following the guide, you will be able to:

- connect a folder of text files or an Obsidian vault and search its contents;
- add email and use it alongside downloaded messenger history;
- ask your agent for a brief with source references and recognise missing data.

## Before you start

Use a <DocTerm term="local-agent" lang="en" label="local AI agent" /> on the computer where your
files are stored. You can start with a folder of notes alone. Email and messenger history are
optional; to include messages, [connect Telegram or MAX](./installation.mdx) and download the
history you need. Memo reads that local history; it does not download it itself.

## Install Memo

**The easiest way: ask your agent.** Copy this request into Claude Code, Codex, Cursor,
Gemini CLI or Hermes, as you would when installing Telegram or MAX:

```text prompt
Help me install Memo on this computer with npm install -g @leemour/cli-memo.
Check Node.js and npm first and help me set them up if needed.
Read memo --help and https://wirecat.dev/en/docs/memo to learn how to use it.
Check that memo --help works in your terminal, then help me connect a folder I choose.
```

The agent installs the <DocTerm term="cli" lang="en" label="CLI" /> and checks that the
`memo` command works. Memo itself has no messenger login step; you choose folders and configure
mail separately. The browser shows these instructions; installation happens on your computer.

## Add your notes

### Choose a folder

A folder is a directory on your computer containing files. Memo reads the selected folder
**and its subfolders**, so it can work with ordinary project folders, a folder of notes or an
Obsidian vault. You can register more than one folder.

An <DocTerm term="vault" lang="en" label="Obsidian vault" /> is simply a folder of notes that
Obsidian opens as one workspace. Its notes are <DocTerm term="markdown" lang="en" label="Markdown" />
files; Memo reads those files directly, without requiring Obsidian to be open. You do not need
to use Obsidian to use Memo.

### Files Memo can read

| Files | Common extensions | What to expect |
| --- | --- | --- |
| Text and Markdown notes | `.txt`, `.md`, `.markdown` | Readable text, including Obsidian notes. |
| Tables and spreadsheets | `.csv`, `.tsv`, `.xlsx`, `.ods` | Text and cell values, with source locations where available. |
| Documents, slides and ebooks | `.odt`, `.pptx`, `.epub` | Extracted readable text, rather than the original layout. |
| PDF and Word documents | `.pdf`, `.docx` | Require optional readers: `unpdf` for PDF and `mammoth` for DOCX. |

A scanned PDF contains page images; it needs text recognition before its contents can be
imported. Older `.doc` and `.xls` files are not supported; convert them to a supported format.
Import reports unreadable files or missing readers rather than silently treating them as searched.

### Import the folder you choose

Replace `/path/to/notes` with the full path to an **existing folder** on your computer. For
ordinary folders, select the Markdown format:

```sh
memo folders add /path/to/notes --format markdown
memo notes import --no-embed
```

For an Obsidian vault, replace `/path/to/vault` with its folder path and select Obsidian's format:

```sh
memo folders add /path/to/vault --format obsidian
memo notes import --no-embed
```

The format tells Memo how to understand links and tags in your notes. Markdown uses links such
as `[label](other-note.md)`; Obsidian also understands `[[Note]]` links. Obsidian is the default
if you omit `--format`.

Registration prints a folder ID. Import copies readable content into the local store without
changing the source files. Hidden folders such as `.obsidian` are skipped. `--no-embed` keeps
this first import to word search, so you do not need a search model to get started. Repeat
`memo notes import --no-embed` after editing or adding files.

### Find something in your files

Tell your agent which topic you want to find:

```text prompt
Use Memo to find notes and files about the budget in the folders I imported.
Show the matching text and source file for each useful result. Tell me if any files were not read.
```

For a manual search:

```sh
memo notes search 'budget' --json
```

The results identify the matching file, a source reference and the first matching line. Open
the file to check the detail. If no result appears, try a word you know is in one of your files
and inspect the import report; a file that was not imported cannot appear in the search.

## Add email

Memo reads email through [Himalaya](https://github.com/pimalaya/himalaya), a separate mail
program. Your mail account is configured there; Memo uses its name and address without needing
a separate copy of the mail password. Ask your agent to help:

```text prompt
Help me connect the mail account I choose through Himalaya and add it to Memo.
Explain the account setup, then import mail from the date I choose.
Show the import result and tell me whether I need another run to finish that period.
```

The account must work in Himalaya before Memo can import its mail. For manual configuration:

Add `mail.accounts` to Memo's configuration, keeping any existing settings. Default file locations:

| OS | Configuration file |
| --- | --- |
| Linux | `~/.config/cli-memo/config.json` |
| macOS | `~/Library/Preferences/cli-memo/config.json` |
| Windows | `%APPDATA%\cli-memo\Config\config.json` |

`MEMO_CONFIG_DIR` overrides the directory; on Linux, `XDG_CONFIG_HOME` also affects the default.
The example uses a Himalaya account named `gmail`; replace the name and address with yours.

```json
{
  "mail": {
    "accounts": [{ "name": "gmail", "address": "you@example.com" }]
  }
}
```

Gmail is the default mode and imports All Mail. For another IMAP provider, configure
`"mode": "imap"` and `"folders": ["INBOX", "Archive"]` in the account entry, using your
mailbox's actual folder names.

```sh
memo mail import --account gmail --since 2026-09-01 --json
```

Choose the first date you want to include. Each run reads at most 200 new messages by default;
run it again to continue if the result says the import is incomplete. The mailbox is read-only:
import does not send email or mark it read. Imported mail is stored locally; rerunning import
can remove the stored text of mail that has disappeared from the source.

Link an email address to its messenger identity explicitly with `tg contacts link` or
`max contacts link`; matching names alone do not identify the same person. See
[working with people](./people.md) for messenger contact tasks.

## Ask for the context you need

Once your sources are connected, ask for context about a person. Replace the name:

```text prompt
Use Memo to gather context about Rin Example before our meeting: recent messages, email,
linked notes and open tasks. Include the sources and tell me what data is missing.
```

To associate an imported file note with a person, replace the name and file path:

```sh
memo note telegram:"Rin Example" /path/to/notes/people/Rin.md
```

The file must already be imported. A name mentioned in ordinary text does not create a link;
associate the note explicitly or use a supported link such as `[[Rin Example]]` in Obsidian.

The agent can use these commands to gather person context or search across imported sources:

```sh
memo context telegram:"Rin Example" --json
memo search 'budget' --all --json
```

`--all` explicitly searches every stored account and imported notes. Check the returned source
references and coverage before relying on an answer. Missing history, mail outside the imported
window or unresolved note links can leave the result incomplete. Add `--account <id>` to
`context` when several accounts of that provider exist.

You can also save your own note about the person:

```sh
memo notes add 'Prefers morning meetings' --about telegram:'Rin Example'
memo notes list --about telegram:'Rin Example' --json
```

These notes live in the local store. Writing them does not change an imported file;
`memo notes export` is a separate, explicit action to write files.

## Check the result

A useful answer names the source files, messages or email behind each important detail. Open
a source to verify an agreement or date. The agent should explain gaps such as a mail period
that has not been imported, unreadable files or an unresolved person link. A missing result
does not prove there was no agreement.

## If something is missing

- **Command not found:** check `memo --help` in the agent's terminal and reopen it after installation.
- **No notes found:** check `memo folders list`, rerun `memo notes import --no-embed` and inspect the import result.
- **No mail account:** check that `mail.accounts` names an account configured in Himalaya.
- **Wrong or ambiguous person:** use the provider and exact ID; link identities explicitly.
- **Incomplete context:** import the relevant notes and mail, and download missing messenger history through tg or max.

When the sources are present, continue with [preparing a meeting brief](./meeting-brief.mdx).
For command options, run `memo --help` or a subcommand's `--help`.
The [Memo command documentation](https://github.com/leemour/cli-memo#readme)
also covers tasks, relationships, tags, local reminders and evidence bundles.
