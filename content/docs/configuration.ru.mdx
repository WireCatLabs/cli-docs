Сохраните настройки инструментов командной строки, чтобы не повторять одни и те же параметры при каждом запуске, например число результатов. Узнайте, где хранятся настройки, как их проверить и изменить и где каждый мессенджер перечисляет все доступные настройки. Большинству подходят значения по умолчанию; меняйте настройку, когда раз за разом повторяете один и тот же параметр или хотите разные значения для разных аккаунтов.

Два понятия. **Файл настроек** (`config.json`) хранит эти значения на вашем компьютере. <DocTerm term="profile" lang="ru" label="Профиль" /> — именованный набор настроек подключения аккаунта или бота, например `work`; значения из `defaults` действуют для всех профилей. Данные входа в этом файле не хранятся, а то, что можно делать агенту, задаётся в разделе [Права](./configuration.mdx#права).

## Где лежит файл

Инструмент создаёт файл с обычными значениями при первом запуске команды, читающей настройки. Существующий файл он не трогает.

| Система | Telegram | MAX |
|---|---|---|
| Linux | `~/.config/tg-cli/config.json` | `~/.config/max-cli/config.json` |
| macOS | `~/.config/tg-cli/config.json` | `~/.config/max-cli/config.json` |
| Windows | `%APPDATA%\tg-cli\Config\config.json` | `%APPDATA%\max-cli\Config\config.json` |

`config show` выводит фактический путь — он другой, если на компьютере выбран свой каталог. В PowerShell пишите `tg.cmd` или `max.cmd`.

## Проверить и изменить настройку

```sh
tg config show
tg personal config set limit 50
tg work config set limit 10
tg config set sends_per_hour 10 --defaults
tg personal config unset limit
```

`config show` перечисляет все настройки, их значения и откуда взялось каждое значение. `config set` сохраняет значение для текущего профиля, для профиля с именем, например `work`, или с `--defaults` — для всех профилей. Значение проверяется до записи, поэтому опечатка не сохранится, а вернёт ошибку. `config unset` удаляет значение, и снова действует значение по умолчанию. Для MAX пишите `max` вместо `tg`. Файл можно править и вручную.

## Какое значение побеждает?

Параметр команды вроде `--limit 5` (<DocTerm term="flag" lang="ru" label="флаг" />) меняет только этот запуск. Он сильнее переменной окружения, затем идёт значение профиля в файле, затем `defaults`, затем встроенное значение. Не у каждой настройки есть параметр или переменная; какие есть, указано в справочнике мессенджера.

## Пример

```json
{
  "defaults": { "limit": 20, "sends_per_hour": 30 },
  "profiles": { "work": { "limit": 50 } }
}
```

`tg work chats list` покажет 50 результатов, другие профили — 20, а `--limit 5` — пять для одной команды.

<details id="full-example" className="docs-disclosure">
<summary>Пример подробнее: профили, боты и права</summary>

```json
{
  "defaults": { "limit": 20, "keep_runs_for_days": 14, "update_check": true },
  "profiles": {
    "personal": { "limit": 50, "color": true },
    "work": { "limit": 10, "record": true, "permissions": { "messages": "readonly" } }
  },
  "personal": { "defaults": { "sends_per_hour": 30 } },
  "bot": { "profiles": { "shop": { "sends_per_hour": 200 } } }
}
```

- `defaults` действуют для всех профилей, `profiles.<имя>` — для одного.
- `personal` действует только для команд вашего аккаунта, `bot` — только для команд `tg <имя> bot …` и `max <имя> bot …`.
- `work` записывает каждый запуск и может только читать сообщения.

</details>

## Все настройки Telegram и MAX

Большинство настроек у двух инструментов общие: `limit`, `sends_per_hour`, `record`, `permissions` и другие. Некоторые есть только у одного: например, `proxy` у Telegram и `serve` у MAX. Запуски, которые сохраняет `record`, показывает WireCat Desktop: [Поиск по логам в WireCat Desktop](./desktop/logs.mdx). Каждый мессенджер описывает свои настройки:

- **MAX:** [руководство по настройкам MAX](./max/configuration.md) · [все настройки MAX, значения по умолчанию и переменные окружения](./max/configuration-reference.md).

## Профили и боты

Используйте профили, если у вас несколько аккаунтов, бот или разные права для агентов. Профиль — именованный набор настроек подключения аккаунта или бота на этом компьютере, со своими данными входа и разрешениями. Здесь вы научитесь выбирать нужный профиль и отличать команду бота от команды личного аккаунта.

### Выбрать профиль

Поставьте имя перед командой:

```sh
tg work config show
drive personal sync
```

Называйте профиль в каждой команде и запросе агенту: `tg work …` или `TG_PROFILE=work` на всю
сессию (`tg` читает `TG_PROFILE`, `max` читает `MAX_PROFILE`; `zm` берёт настройку `account.profile`; `memo` и `drive` не читают переменную профиля, поэтому называйте профиль в команде). Профиль никогда не выбирается за вас.
Команда, которой нужен профиль, без него останавливается с ошибкой и списком профилей на этом
компьютере. `profiles.work` задаёт значения
для этого профиля; `defaults` дополняет отсутствующие. Профиль не является отдельным
пользователем ОС: полный доступ агента к файлам может дать ему доступ и к другим данным.

### Переключиться на бота

Поставьте `bot` после имени:

```sh
tg support bot api get-me --json
max support bot api get-my-info --json
```

Для этих команд нужен уже подключённый профиль бота. Его аккаунт и права определяет
мессенджер, а не ваш личный аккаунт. [Боты](./bot-api.mdx) объясняет подключение и примеры.

Для входа используйте инструкции [Telegram](./tg/sessions.md) или [MAX](./max/sessions.md), либо [подключите Google Drive](./drive/installation.md).

## Права

Выберите, что агенту можно делать: читать сообщения, отправлять ответы или менять группу. Здесь вы настроите доступ для нужного аккаунта или бота и проверите ограничения перед задачей. Права относятся к <DocTerm term="profile" lang="ru" label="профилю" /> — именованному набору настроек аккаунта или бота; [Профили](./configuration.mdx#профили-и-боты) объясняют, как его выбрать.

### Выбрать уровень доступа

| Уровень | Что происходит |
|---|---|
| `deny` | Действие запрещено, включая чтение. |
| `readonly` | Читать можно, изменять нельзя. |
| `ask` | Изменение требует подтверждения в терминале. |
| `allow` | Действие может выполниться без нового вопроса. |

Отказ означает, что нужно проверить действие и настройки. Это не признак неисправного
подключения. Не просите агента снять ограничение ради завершения задачи.

### Разрешить одно действие

```sh
tg work config set permissions.messages.send ask
max work config set permissions.messages.send ask
```

Замените `work` своим профилем. Чтобы по умолчанию разрешить чтение сообщений и запретить изменения:

```sh
tg work config set permissions.messages readonly
max work config set permissions.messages readonly
```

Более точные ключи имеют приоритет. Сохранённое `permissions.messages.send ask` разрешает отправку;
задайте ему `readonly`, чтобы запретить её. Проверьте остальные исключения через `config show`.

Это права на сообщения. Реакции и управление чатами имеют отдельные ключи. Полные примеры
профиля только для чтения — в справочниках прав [Telegram](./tg/configuration-reference.md#what-a-profile-may-do) и [MAX](./max/configuration-reference.md#права-доступа).

### Права бота

Права и лимиты бота задаются в разделе бота. Для вопроса перед отправкой в терминале:

```sh
tg support config set permissions.bot.messages.send ask --bot
max support config set permissions.bot.messages.send ask --bot
tg support config set sends_per_hour 30 --bot
max support config set sends_per_hour 30 --bot
```

### Ограничить получателей и повторные отправки

Список получателей ограничивает чаты, куда профиль может отправлять. Лимит в час помогает
остановить цикл отправок. Эти проверки действуют и для разрешённой команды.
Команды управления — в безопасности [Telegram](./tg/security.md) и [MAX](./max/security.md).

### Временно изменить права MCP-сервера

Добавьте `--permission messages.send=deny` к запуску сервера, чтобы запретить отправку
этому процессу. Сохранённые настройки не меняются. Флаг только ужесточает: переопределение, которое ослабило
бы уровень профиля, отклоняется при запуске, поэтому, чтобы разрешить больше, измените права профиля. Через MCP уровень `ask` не требует формы подтверждения на сервере:
приложение управляет своими подтверждениями и может разрешить вызов без нового вопроса.
Чтобы запретить изменения, используйте `deny` или `readonly`.
[Настройка браузера](./browser-apps.mdx) объясняет подключение целиком.

### Запретить изменения на весь запуск

Каждый инструмент также читает переменную окружения, которая запрещает изменения на весь запуск, что бы
ни разрешали сохранённые права. Отказ завершается кодом 5. Задайте её агенту, который должен только читать.

| Инструмент | Переменная | Что запрещено |
|---|---|---|
| tg, max | `TG_READ_ONLY=1`, `MAX_READ_ONLY=1` | Отправка и другие изменения; агент может читать и готовить текст ответа. |
| Zoom | `ZM_READ_ONLY=1` | Изменения в Zoom, входе, настройках и в том, что вы добавили; чтение и синхронизация из Zoom работают. |
| Google Drive | `DRIVE_READ_ONLY` (любое значение, кроме `0` или пустого) | Любые изменения, на этом компьютере или в Google, как с `--read-only`. |
| Google Calendar | `GCAL_READ_ONLY` (любое значение, кроме `0` или пустого) | Любые изменения в Google Календаре и в настройках; чтение и `gcal sync` работают. |
| Memo | `MEMO_READ_ONLY` (любое значение, кроме `0`) | Любые изменения; чтение, `memo sync` и `tasks link` агента по расписанию работают. `memo mcp serve` сохраняет команды записи в каталоге, но отказывает в их выполнении. |

### Ограничения и подробные правила

Агент с доступом к файлам настроек или неограниченному терминалу может изменить эти права.
Перед выдачей такого доступа прочитайте [Безопасность](./security.mdx).
Вложенные права и точные ключи команд описаны в справочниках [Telegram](./tg/configuration-reference.md#what-a-profile-may-do) и [MAX](./max/configuration-reference.md#права-доступа).
