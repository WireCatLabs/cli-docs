Find any document on your Yandex Disk by what it says, and let your AI agent read it, file it and share it for you.
The `ydisk` command-line tool copies the text of the Disk folders you choose to your computer, so a search for
"lease" finds the PDF even when its file name is `scan_0042.pdf`, and even without the internet.

Ask your agent where the contract with a client is and what its payment terms are. It answers with the quote and the
file's path on the Disk. Ask it to move last year's invoices to an archive or to make a link for a colleague, and it
does that on the Disk, asking first before a delete or a public link.

`ydisk` works with Claude Code, Codex and other agents that run commands, with Claude Desktop and Cursor through MCP,
and with ChatGPT and Claude in the browser through your own tunnel. It needs Node.js and a Yandex OAuth token, a key
from your own Yandex account that lets the tool use your Disk.

## How it works

- **A copy of the text on your computer.** `ydisk` reads the folders you choose and saves the text of their files in
  the local store, one database file on your computer that every WireCat tool shares. Search reads this copy, not the
  Disk, and finds other forms of a word in Russian and English.
- **Only the folders you choose.** Yandex Disk does not tell a tool what changed, so each sync lists every chosen
  folder and its subfolders again and downloads only the files whose content changed. Choose the folders with
  documents, not the whole Disk.
- **Text, not copies of files.** The tool reads Markdown, plain text, PDF with a text layer, Word `.docx`, Excel
  `.xlsx`, CSV and TSV. Photos and other files are kept by name. The files themselves stay on the Disk.
- **A profile for each account.** A profile is a name you choose for one Yandex account, such as `personal` or `work`.
  Every command that uses an account names it first: `ydisk personal search budget`.
- **Live commands change the Disk.** `files` commands go to Yandex directly. Deleting moves a file to the Disk's trash.
  At a terminal the tool asks before it deletes, overwrites or makes a public link.

## Install and sign in

1. Install the tool from npm and check it. You need Node.js 22.16 or a later 22.x, or 24 or later.

```sh
npm install -g @wirecat/yandex-disk-cli
ydisk --version
ydisk doctor
```

2. Register an app in Yandex to get a token. The app is only a name and a list of rights in your account, and nothing
   is published. Yandex's pages are in Russian, so their labels are given in Russian too
   ([Yandex's guide](https://yandex.ru/dev/disk-api/doc/en/concepts/quickstart)):
   - Open [oauth.yandex.ru/client/new](https://oauth.yandex.ru/client/new/) and sign in with the account whose Disk
     you want to use. If Yandex asks for the app type, choose «Для доступа к API или отладки» (for API access or
     debugging).
   - Enter any name and your email. Under «Доступ к данным» (data access) add the Yandex Disk rights
     `cloud_api:disk.read`, `cloud_api:disk.info` and, to change files, `cloud_api:disk.write`.
   - Create the app and copy its **ClientID** from the app's page.

3. Open `https://oauth.yandex.ru/authorize?response_type=token&client_id=` with your ClientID added at the very end,
   allow access and copy the token from the page. Keep it like a password.

4. Sign in under a profile name you choose. The tool asks for the token with hidden input, checks it with Yandex and
   keeps it in the system keyring, or in a private file where there is no keyring.

```sh
ydisk personal session start
ydisk personal session status --check
```

Yandex keeps a token valid for months while it is used. When Yandex stops accepting it, get a new one the same way
and run `session start` again.

`ydisk personal session end` removes the token from this computer.

## Copy a folder and search it

`folders browse` shows the Disk one level at a time, so you can pick a folder by its path:

```sh
ydisk personal folders browse
ydisk personal folders add /Documents
ydisk personal sync
ydisk personal search "quarterly budget"
```

One sync reads up to 200 files (`--limit`), walks up to about 10,000 entries and saves where it stopped. Run it
again to go on, and later to bring in what changed. Nothing syncs in the background. `ydisk personal status` shows the
last sync, the pending work and the files kept by name only. `documents show` prints the whole text of one file found
by search.

Search by meaning finds a document that answers a question in other words. It needs a text model downloaded once
with [Memo](./memo/installation.md), `memo models download embeddinggemma`, and then `ydisk personal sync --embed`.

## Connect your agent

A terminal agent such as Claude Code or Codex gets the tool's skill:

```sh
ydisk skill install
```

Then ask in plain words:

```text prompt
Use ydisk CLI with profile personal. Find the contract with Harbour Ltd in my Disk folders.
Quote the payment terms and give me the file's path on the Disk. Do not change any files.
```

The agent searches the local copy first. A file outside the chosen folders it reads live from the Disk.

To add the tool as an MCP server, `ydisk personal mcp add claude-code --allow-writes` (or `codex`) does it in one
command. For Claude Desktop, Cursor and other MCP apps, `ydisk personal mcp config` prints the entry to paste into
the app's settings. For ChatGPT and Claude in the browser, see [browser apps](./browser-apps.mdx).

## Work with files on the Disk

```sh
ydisk personal files list --folder /Documents
ydisk personal files download /Documents/plan.pdf --output ./plan.pdf
ydisk personal files upload ./notes.md --folder /Documents
ydisk personal files move /Documents/old.pdf --folder /Archive
ydisk personal files delete /Documents/old.pdf
ydisk personal files publish /Documents/plan.pdf
```

`files delete` moves the file to the Disk's trash, and `files restore` brings it back. `files publish` makes a link
that anyone who has it can open. At a terminal the tool asks before a delete, an overwrite with `--replace` or a public
link. Over MCP there is no one to ask, so for an agent that must not do these, set the permissions:

```sh
ydisk personal config set permissions.files.delete deny
ydisk personal config set permissions.files.share deny
```

`YDISK_READ_ONLY=1` refuses every change. `--dry-run` on any change shows what it would do without doing it.

## Limits

- Scanned PDFs and pictures have no text to search. Files over 50 MB are kept by name only.
- A chosen folder that you rename or move on the Disk stops syncing and its copies leave the store. Add it again under
  its new path.
- Sign-in is by a pasted token from an app you register. There is no sign-in in the browser yet.

## If something goes wrong

- **"refused the token", exit code 4**: the token is wrong, revoked or expired. Get a new one and run `session start`
  again.
- **A change fails with exit code 5**: the token was made without `cloud_api:disk.write`, or the profile's permissions
  refuse the change.
- **Search does not find a file you know is there**: check that its folder is in `folders list`, run `sync` again
  until `status` shows no pending work, and check whether `status` lists the file as kept by name only.
- **"the OS keyring did not answer" on Linux**: log out and back in, or sign in with
  `ydisk personal session start --credential-storage file`.

`ydisk doctor` shows what is set up without connecting, and `ydisk personal doctor --online` checks the token. More
cases are on the [troubleshooting page](https://github.com/WireCatLabs/ydisk-cli/blob/main/docs/troubleshooting.md).
