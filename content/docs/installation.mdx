Three steps, about five minutes: **install** the CLI, **log in** with your phone, **check** that it works.

You need:

- a computer with Windows, macOS or Linux;
- your phone, with Telegram or MAX open on the account you want to connect.

Pick your system and messenger on the tabs below. The page remembers your choice.

### Log in with your phone

Logging in adds your computer as a new device on your account, the same way Telegram Desktop or
MAX on the web does. Your phone approves it. Run the command in **your own terminal**, not in the
agent chat: codes and passwords should only go into the terminal.

<Tabs groupId="messenger" persist items={["Telegram", "MAX"]}>
<Tab value="Telegram">

```sh
tg setup
```

The terminal asks you, in this order:

1. **Phone number** — in international format, for example `+34600111222`.
2. **Code from Telegram for my.telegram.org** — Telegram sends it as a message in the Telegram
   app (from the chat called *Telegram*), not by SMS. Type it in the terminal. The CLI uses it to
   register itself with Telegram for you; this happens only on the first login.

   <Screenshot alt="the Telegram app showing the message with the my.telegram.org login code" width={360} />

3. **QR code** — the terminal shows a QR code. On your phone, open
   **Settings → Devices → Link Desktop Device** and scan it with that scanner (not the camera app).

   <Screenshot alt="the terminal showing the Telegram login QR code" />
   <Screenshot alt="Telegram on the phone: Settings → Devices → Link Desktop Device" width={360} />

4. **Two-step verification password** — only if you set one in Telegram. The characters stay
   hidden while you type.
5. **Which agent you use** — setup teaches it the commands. Then it shows
   `Logged in as <your name>` and checks five of your chats.

<Accordions>
<Accordion title="Why does Telegram need a code for my.telegram.org?">

Telegram asks every program that connects to an account to be registered first. The registration
gives the program two values: an **app ID** and an **app hash**. They only identify the program;
they give no access to your messages on their own. Telegram allows one registration per phone
number, so if you have one already, the CLI reuses it.

The code in step 2 lets the CLI fill in that registration form on
[my.telegram.org](https://my.telegram.org) for you. The QR scan in step 3 is the actual login.

</Accordion>
<Accordion title="Why scan a QR code?">

The QR code links the CLI to your account as a new device, like Telegram Desktop. Your phone
proves it is you, so the CLI never needs your password. After login the CLI shows up in
**Settings → Devices**, where you can end it at any time.

</Accordion>
<Accordion title="Automatic registration failed? Register the app in your browser">

Run:

```sh

```

The command opens [my.telegram.org](https://my.telegram.org). Then:

1. Enter your phone number. Telegram sends a code to the Telegram app. Enter it on the site.

   <Screenshot src="/screenshots/telegram/my-telegram-login.png" alt="my.telegram.org login form with phone number and confirmation code" />

2. Open **API development tools**.

   <Screenshot src="/screenshots/telegram/my-telegram-api-tools.png" alt="my.telegram.org menu with API development tools highlighted" />

3. If you have no app yet, fill in the form: any title and short name, platform **Desktop**.
   Skip this if the page already shows an app.

   <Screenshot alt="my.telegram.org form to create a new application, filled in" />

4. Copy **App api_id** and **App api_hash** into the terminal when it asks. The hash stays hidden

   <Screenshot src="/screenshots/telegram/my-telegram-credentials.png" alt="my.telegram.org App configuration page with api_id and api_hash highlighted" />

5. Continue with the QR code from step 3 above.

Logging in does not download your message history. You choose which chats and how much history to
fetch later, when a task needs it.

## What the CLI and your agent can do with this login

The login gives the CLI **the same access you have in the app**: read your chats, send, edit and
delete messages, manage groups and contacts. Your agent gets that access when it runs `tg` or
`max` commands.

- **It acts only when a command asks.** Reading does not mark messages as read, and nothing is sent
  unless a command sends it.
- **By default, sending is allowed**, up to 30 messages per hour. Deleting messages needs an extra
  confirmation.
- **You decide what an agent may do.** Each account connection (a *profile*) has its own rules:

| You want | Set up | Read more |
|---|---|---|
| The agent only reads, never changes anything | a read-only profile | [Telegram](./tg/configuration.md#what-a-profile-may-do) · [MAX](./max/security.md#preventing-sends-to-the-wrong-place) |
| A question before each send | the `ask` level for sending | [Telegram](./tg/configuration.md#a-question-before-a-change) |
| Sends only to chats you chose | a recipient list | [Telegram](./tg/security.md#the-send-guard) · [MAX](./max/security.md#preventing-sends-to-the-wrong-place) |
| Fewer messages per hour | `sendsPerHour` | [Telegram](./tg/security.md#the-send-guard) · [MAX](./max/security.md#preventing-sends-to-the-wrong-place) |

**Your login is saved on this computer.** Treat the saved session like a password: whoever copies
it can use your account. To log out, run `tg session end` or `max session end`, or end the device
in **Settings → Devices** on your phone. What is stored where:
[Telegram security](./tg/security.md) · [MAX security](./max/security.md).

## Next: ask your agent

Setup has already taught your agent the commands. Open your agent and paste:

```text prompt
Summarise my unread messages by chat and tell me who needs an answer. Read only: don't send anything.
```

Then continue with [first tasks](./first-tasks.md). If your agent does not know the `tg` or `max`
command, see [Connect your agent](./agents.md).

## Troubleshooting

<Accordions>
<Accordion title="What the Windows installer changes" id="what-the-windows-installer-changes">

npm puts the `tg` or `max` command in its global folder. Windows finds commands only in folders
listed in PATH, and npm does not always add its folder there. The installer:

- installs the npm package;
- adds npm's folder to your user PATH, keeping existing entries, and updates the open PowerShell;
- teaches your agents the commands (`-Agent codex|cursor|claude|gemini|all|none`, default `all`);
- checks that `tg` or `max` runs by name.

It does not change PowerShell's execution policy. An agent that was already running when you
installed must restart, or refresh its own PATH, before it can find the command.

</Accordion>
<Accordion title="Install without the Windows installer">

```powershell
npm.cmd install -g @leemour/tg-cli
```

If `tg` is then not found, run `npm.cmd prefix -g`, add that folder to your user PATH, and open a
new terminal. Use `max-cli` and `max` for MAX.

</Accordion>
