This page is about the settings of the `tg` and `max` command-line tools: the values a command uses when you do not give them, such as how many results to show. By the end, you will know where your settings are stored, how to check and change them, and where each messenger lists every available setting. The defaults work for most people; change a setting when you keep repeating the same option or want different values for different accounts.

Two terms help here. The **settings file** (`config.json`) keeps these values on your computer. A <DocTerm term="profile" lang="en" label="profile" /> is a named account or bot, such as `work`, with its own values; values under `defaults` apply to every profile. Login data is never stored in this file, and what your assistant may do is set in [Permissions](./permissions.mdx).

## Where the file is

The tool creates the file with common defaults the first time a command reads settings, and keeps an existing file as it is.

| System | Telegram | MAX |
|---|---|---|
| Linux | `~/.config/tg-cli/config.json` | `~/.config/max-cli/config.json` |
| macOS | `~/Library/Preferences/tg-cli/config.json` | `~/Library/Preferences/max-cli/config.json` |
| Windows | `%APPDATA%\tg-cli\Config\config.json` | `%APPDATA%\max-cli\Config\config.json` |

`config show` prints the actual path, which differs if your computer uses a custom directory. In PowerShell, type `tg.cmd` or `max.cmd`.

## Check and change a setting

```sh
tg config show
tg config set limit 50
tg work config set limit 10
tg config set sendsPerHour 10 --defaults
tg config unset limit
```

`config show` lists every setting with its value and where that value came from. `config set` saves a value for the current profile, for a named profile such as `work`, or with `--defaults` for every profile. It checks the value before writing, so a typo is refused instead of saved. `config unset` removes a value so the default applies again. For MAX, write `max` instead of `tg`. You can also edit the file by hand.

## Which value wins?

A command option such as `--limit 5` (a <DocTerm term="flag" lang="en" label="flag" />) changes only that run. It wins over an environment variable, then the profile's value in the file, then `defaults`, then the built-in value. Some settings have no option or environment variable; each messenger's reference says which ones exist.

## An example

```json
{
  "defaults": { "limit": 20, "sendsPerHour": 30 },
  "profiles": { "work": { "limit": 50 } }
}
```

`tg work chats list` shows 50 results, other profiles show 20, and `--limit 5` shows five for one command.

<details id="full-example" className="docs-disclosure">
<summary>A fuller example with profiles, bots and permissions</summary>

```json
{
  "defaultProfile": "personal",
  "defaults": { "limit": 20, "keepRunsForDays": 14, "updateCheck": true },
  "profiles": {
    "personal": { "limit": 50, "color": true },
    "work": { "limit": 10, "record": true, "permissions": { "messages": "readonly" } }
  },
  "personal": { "defaults": { "sendsPerHour": 30 } },
  "bot": { "profiles": { "shop": { "sendsPerHour": 200 } } }
}
```

- `defaultProfile` is used when a command names no profile.
- `defaults` apply to every profile; `profiles.<name>` to one profile.
- `personal` applies only to commands for your own account; `bot` only to `tg <name> bot …` and `max <name> bot …` commands.
- `work` keeps a record of every run and may only read messages.

</details>

## All settings for Telegram and MAX

The two tools share most settings, such as `limit`, `sendsPerHour`, `record` and `permissions`. Some exist in only one of them: for example, `proxy` in Telegram and `serve` in MAX. Each messenger documents its own:

- **Telegram:** [Telegram configuration guide](./tg/configuration.md) · [every Telegram setting, default and environment variable](./tg/configuration-reference.md).
- **MAX:** [MAX configuration guide](./max/configuration.md) · [every MAX setting, default and environment variable](./max/configuration-reference.md).

## Profiles and bots

Put a profile's name before the command, such as `tg work config show`. Add `bot` after it to work as a bot rather than your personal account. [Profiles and bots](./profiles.md) explains choosing and switching them.
