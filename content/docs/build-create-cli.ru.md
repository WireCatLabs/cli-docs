Вы можете быстро собрать свой инструмент командной строки для любого сервиса или API — с нашим шаблоном и вашим
ИИ-агентом. Пользуетесь CRM, трекером задач или приложением для заметок, которое WireCat пока не поддерживает?
Добавьте его сами.

Эта страница показывает, что для этого нужно, что вы получите и с чего начать. Руководства после неё проводят по
каждой части.

## Два варианта

Оба начинаются с одного шаблона и получают одну и ту же основу. Разница только в том, насколько вы связываете
инструмент с остальными.

- **Отдельный инструмент.** Вам нужен быстрый инструмент командной строки для одного сервиса, и больше ничего. Шаблон
  с первого дня даёт основу: данные сервиса хранятся на вашем компьютере, по ним работает быстрый поиск, есть память
  для того, что узнал агент, сервер для ИИ-агентов и безопасный вход. Другие инструменты WireCat не нужны.
- **Часть WireCat.** Вы также пользуетесь WireCat для чатов, почты или встреч и хотите искать по всему сразу. Тогда
  свяжите свой инструмент с остальными: то, что он сохраняет, окажется рядом со всем остальным, и один вопрос найдёт
  это. Для этого нужно несколько дополнительных шагов, они описаны на странице
  [Добавить источник](./build-concepts.md#добавить-источник).

Можно начать с первого варианта и связать инструмент позже.

## Как его собрать, вкратце

1. **Начните с шаблона.** Одна команда создаёт работающий инструмент, где всё уже настроено. Вы не начинаете с пустой
   папки.
2. **Скажите ИИ-агенту, какой сервис подключить.** В шаблоне есть инструкции для агента. Он задаст вам несколько
   простых вопросов о сервисе — что в нём хранится, как в него входят — и напишет код.
3. **Проверьте на своём аккаунте.** Запустите инструмент, посмотрите, что он нашёл, и попросите агента исправить то,
   чего не хватает.
4. **Поделитесь, если хотите.** Встроенные проверки скажут, когда инструмент готов к публикации для других людей.

Чтобы начать, не нужно знать, как WireCat устроен внутри. Руководства ниже объясняют каждую часть, когда она вам
понадобится.

## Что WireCat даёт вашему инструменту

- **Данные на вашем компьютере и быстрый поиск.** То, что сохраняет инструмент, лежит в локальном файле. Поиск
  находит слова в любой форме на русском, английском и испанском, а если включить — и по смыслу.
- **Память для агента.** Агент может сохранить то, что узнал, — итог, предпочтение — и найти это позже.
- **Один поиск по всем инструментам,** если вы связали свой: то, что он сохраняет, лежит рядом с сообщениями,
  письмами, встречами и документами из других инструментов.
- **Работа с ИИ-агентами.** Каждая команда вашего инструмента готова для агента, а что агенту можно менять, решаете вы.
- **Аккаунты не смешиваются.** Вы всегда указываете, с каким аккаунтом работает команда, поэтому ничего не уйдёт не
  туда.
- **Вход и пароли под защитой.** Ключи хранятся в связке ключей вашего компьютера и никогда не появляются в выводе.
- **Проверки, которые сохраняют работоспособность.** Шаблон приносит те же проверки, что запускает каждый инструмент
  WireCat, поэтому ваш инструмент продолжает работать, пока WireCat растёт.

## Что понадобится

- **Аккаунт в сервисе** и способ, которым программы до него достучатся. Большинство сервисов выдают API-ключ в
  настройках или позволяют приложению войти за вас. Ссылка на документацию сервиса для разработчиков очень помогает
  агенту.
- **ИИ-агент для кода, который умеет запускать команды**: Claude Code, Codex, Cursor, Gemini CLI или похожий.
- **Node.js, pnpm и git** на вашем компьютере.

## Начните с шаблона

[cli-template](https://github.com/WireCatLabs/cli-template) — это то, с чего начинается каждый новый инструмент. Эта
команда задаёт несколько коротких вопросов о сервисе и создаёт инструмент `acme` в папке `acme-cli`:

```sh
npx @wirecat/cli-template new acme-cli --command acme --package @example/acme-cli --owner example
```

Проверьте, что новый инструмент запускается:

```sh
cd acme-cli && pnpm install && pnpm build
node dist/bin/acme.js personal doctor
```

`personal` — это профиль: имя одного из ваших аккаунтов. Теперь откройте папку `acme-cli` в вашем ИИ-агенте.

## Что дальше

1. **Скажите агенту, чего вы хотите.** Назовите сервис, дайте ссылку на документацию для разработчиков и скажите, что
   нужно сделать. Например: «Подключи acme к API Acme CRM. Документация — https://example.com/api. Я хочу видеть
   список своих сделок и находить сделку по названию».
2. **Ответьте на его вопросы.** Агент спросит, как входить в сервис, что в нём хранится и что нельзя сохранять никогда.
   Коротких ответов достаточно.
3. **Проверьте каждую команду на своём аккаунте.** Агент собирает команды по одной, например команду со списком
   сделок. Запускайте их и говорите агенту, что не так или чего не хватает.
4. **Сделайте данные доступными для поиска.** Попросите агента сохранять ответы сервиса в WireCat, чтобы поиск и ваши
   агенты находили их рядом с чатами и почтой. Как это сделать — на странице
   [Добавить источник](./build-concepts.md#добавить-источник).
5. **Поделитесь, если хотите.** Когда встроенные проверки проходят, опубликуйте инструмент в npm. Другие установят его
   через npm в терминале или добавят в WireCat Desktop по имени в npm:
   [Подготовьте его для WireCat Desktop](#подготовьте-его-для-wirecat-desktop).

## Если что-то не получается

- Запустите `node dist/bin/acme.js personal doctor` в папке инструмента. Он проверяет установку, настройки и профили.
- Попросите агента ещё раз прочитать инструкции шаблона. В них описаны частые проблемы.
- Задайте вопрос или сообщите об ошибке в [cli-template](https://github.com/WireCatLabs/cli-template/issues). Не
  прикладывайте ключи, пароли и личные данные.

## Покажите его на wirecat.dev

Инструмент вне WireCatLabs может появиться здесь в группе «Инструменты сообщества». Откройте pull request в
[cli-docs](https://github.com/WireCatLabs/cli-docs), который добавляет его в `tools.json` с `"community": true`. Его
страницы затем копируются из его репозитория на проверенном теге релиза, как наши.
[Список проверки](https://github.com/WireCatLabs/cli-docs/blob/main/docs/REVIEWING.md#community-tools) говорит, что
мы проверяем. Инструмент сообщества публикуется в своём пространстве имён npm: `@wirecat` и название «WireCat»
остаются нашими. Инструмент из списка с записью `desktop` появляется и в WireCat Desktop, с меткой **Сообщество**, у
тех, кто включил **Включить инструменты сообщества**. Пока его нет в списке, любой может добавить его по имени в npm
как непроверенный инструмент.
[Добавьте свой инструмент в WireCat](./build-list-tool.md) описывает все шаги, от pull request до WireCat Desktop.

## Подготовьте его для WireCat Desktop

WireCat Desktop умеет добавлять инструмент, который WireCat не проверял, по его имени в npm
([Добавить свой инструмент](./desktop/index.mdx#добавить-свой-инструмент); появится в следующем выпуске WireCat
Desktop). Прежде чем что-то установить, он читает из npm три вещи: сведения о пакете, запись о том, где npm его
собрал, и файл `contracts/wirecat.json` из самого пакета. Чтобы узнать, что это за инструмент, он никогда не запускает
пакет. Поэтому инструменту нужны этот файл, папка данных с именем по пакету и выпуск, который npm может связать с
вашим репозиторием.

### Манифест

`contracts/wirecat.json` — это манифест: то, что инструмент сообщает о себе WireCat. В нём перечислены команды с тем,
что каждая читает и пишет, и команды, которыми Desktop проверяет, настраивает, синхронизирует и подключает инструмент.
Нужен `@wirecat/cli-base` 0.81.0 или новее.

- **Его генерируют, а не пишут руками.** `cli-dev manifest` пишет его по собранной программе и экспортированному
  вами описанию. Вы пишете только то, чего код знать не может: `tagline` (не длиннее 55 символов), тексты входа
  `signIn.gives` и `signIn.asks` и, если есть команда `sync`, `syncs` (что она копирует, не длиннее 40 символов).
- **Его коммитят и публикуют.** Закоммитьте файл и добавьте `contracts/wirecat.json` в `files` в `package.json`,
  чтобы он попал в пакет в npm.
- **CI следит, чтобы он был свежим.** `cli-dev manifest … --check` падает, когда файл больше не совпадает с
  программой.
- **В нём нет версии.** Desktop берёт версию из npm, так что выпуск файл не меняет.

cli-template 0.18.0, текущий выпуск, этого пока не настраивает. В инструменте, созданном из него, сделайте это один
раз:

1. Экспортируйте описание для манифеста в новом файле `src/wcat.ts`:

   ```ts
   import type { ManifestIdentity } from "@wirecat/cli-base/wcat/manifest"
   import { IDENTITY } from "./identity.js"

   export const WCAT: ManifestIdentity = {
     ...IDENTITY,
     docs: "https://github.com/leemour/acme-crm-cli#readme",
     tagline: "Your Acme CRM deals, searchable on your computer",
     signIn: { gives: "your Acme CRM contacts and deals", asks: "an Acme CRM API token" },
   }
   ```

2. Начните bin с `wcatStart`, до загрузки программы, и передайте ему `WCAT`, чтобы они никогда не расходились:

   ```ts
   import { wcatStart } from "@wirecat/cli-base/wcat/start"
   import { WCAT } from "../wcat.js"

   const { code } = await wcatStart(WCAT)
   if (code !== undefined) process.exitCode = code
   else {
     // the bin's existing start
   }
   ```

3. Назовите программу `wcat-<команда>` в `package.json`, например
   `"bin": { "wcat-acme-crm": "dist/bin/acme-crm.js" }`. `cli-dev lint` предупреждает об имени без `wcat-`.
4. Пишите файл после каждой сборки и проверяйте его в CI:

   ```sh
   pnpm exec cli-dev manifest --program dist/program.js --identity dist/wcat.js
   pnpm exec cli-dev manifest --program dist/program.js --identity dist/wcat.js --check
   ```

Когда файл есть в пакете, `wcat-acme-crm --wcat-describe` отвечает в формате 2: имя, версия, описание и ссылка на
документацию с `"wcat_describe": 2`, а также часть `desktop` из файла и `manifest_sha256` — хеш файла. После установки
Desktop запускает эту команду один раз и отказывает инструменту, если хеш не совпадает с файлом, который он показал
на экране проверки. Точный формат — в
[правиле cli-base WC-CMD-29](https://github.com/WireCatLabs/cli-base/blob/main/docs/standards/commands.md#wc-cmd-29--answer---wcat-describe-and-take-no-name-wirecat-reserves).

### Папка данных

**Удалить вместе с данными** в Desktop стирает только папки с именем инструмента, поэтому это имя должно
принадлежать вашему инструменту. Для пакета `@<scope>/<name>` значение `appName` в описании, в нижнем регистре, равно
`<scope>-<name>` или начинается с `<scope>-<name>-`. Каждая `.` и `_` имени пакета становится `-`, а всё имя — не
длиннее 64 символов: `@leemour/acme-crm-cli` → `leemour-acme-crm-cli`. cli-template 0.18.0 пишет `appName` без
области имён (`acme-crm-cli`), поэтому исправьте его в `src/identity.ts` до первого выпуска. Desktop отказывает
манифесту, который нарушает это правило.

### Публикация в своей области имён

Публикуйте пакет в своей области имён npm, например `@leemour/acme-crm-cli`. Область `@wirecat`, название «WireCat»
и имена, которые WireCat бережёт для своих инструментов, например `tg`, `mail` или `wcat`, остаются нашими.

1. **Сделайте репозиторий открытым.** Для пакета из закрытого репозитория npm не записывает, где он его собрал, а
   WireCat Desktop показывает эту запись на экране проверки.
2. **Опубликуйте первую версию сами** командой `bin/release --local`. npm позволяет настроить доверенного издателя
   только для пакета, который уже есть.
3. **Настройте доверенного издателя** на npmjs.com, как сказано на странице npm
   [Trusted publishing](https://docs.npmjs.com/trusted-publishers): ваш владелец и репозиторий на GitHub, файл
   процесса `release.yml` (регистр важен) и окружение `npm`. Доверенной публикации нужен npm 11.5.1 или новее.
4. **Дальше выпускайте через `bin/release`.** Он запускает `release.yml`, который публикует без токена npm, а npm
   записывает, где собрал каждую версию.

### Добавьте в Desktop, потом попросите о списке

1. **Добавьте инструмент на своём компьютере.** В WireCat Desktop включите в настройках **Разрешить инструменты,
   которые WireCat не проверял**, затем на странице «Инструменты» нажмите **Добавить свой инструмент** и введите имя
   в npm. Инструмент появится с меткой **Не проверен**. Инструмент из закрытого репозитория можно добавить только
   так.
2. **Попросите включить его в список,** если хотите, чтобы его нашли все. Инструмент из списка виден на wirecat.dev
   и, с меткой **Сообщество**, в WireCat Desktop. Список — для одобренных издателей: шаги и что мы проверяем — на
   странице [Добавьте свой инструмент в WireCat](./build-list-tool.md).

## Весь путь на примере

Здесь создаётся `@leemour/acme-crm-cli` — выдуманный инструмент для выдуманной Acme CRM: имена — только пример,
такого пакета нет. Используйте свою область имён и свой сервис.

1. **Создайте инструмент.**

   ```sh
   npx @wirecat/cli-template new acme-crm-cli --command acme-crm --package @leemour/acme-crm-cli --owner leemour
   cd acme-crm-cli && pnpm install
   ```

2. **Добавьте команду с агентом.** Откройте папку с ИИ-агентом и попросите: «Добавь `deals list`: она показывает мои
   сделки из API Acme CRM, документация — https://example.com/api. Она только читает». Проверьте на своём аккаунте
   после `pnpm build`: `node dist/bin/acme-crm.js personal deals list`.
3. **Подготовьте его для Desktop.** Настройте один раз, как сказано в разделе
   [Подготовьте его для WireCat Desktop](#подготовьте-его-для-wirecat-desktop), с `appName`, равным
   `leemour-acme-crm-cli`.
4. **Сгенерируйте и проверьте.** `pnpm generate` собирает инструмент и переписывает контракты его команд. Затем
   запишите манифест и закоммитьте его вместе с контрактами:

   ```sh
   pnpm generate
   pnpm exec cli-dev manifest --program dist/program.js --identity dist/wcat.js
   git add contracts && git commit -m "feat: deals list"
   ```

5. **Опубликуйте.** В первый раз — `bin/release --local`, затем настройте доверенного издателя и выпускайте через
   `bin/release`, как сказано в разделе [Публикация в своей области имён](#публикация-в-своей-области-имён).
6. **Добавьте его в Desktop.** Включите **Разрешить инструменты, которые WireCat не проверял**, нажмите **Добавить свой
   инструмент**, введите `@leemour/acme-crm-cli`, прочитайте проверку, затем **Добавить** и **Установить и
   запустить**. После **Перезапустить** нажмите **Управление** в его строке, добавьте профиль `personal` и войдите.
7. **Подключите агента.** На странице «Агенты» кнопка **Подключить** даёт Claude Code навык инструмента. В терминале
   то же самое делает команда:

   ```sh
   wcat-acme-crm skill install --for claude
   ```

8. **Спросите агента.** В Claude Code: «Используй acme-crm с профилем personal: какие мои сделки закрываются в этом
   месяце и кто контакт по каждой?»

## Обновляйтесь

Шаблон продолжает улучшаться. В вашем инструменте, с чистым рабочим деревом git, запустите:

```sh
npx @wirecat/cli-template upgrade
```

Для каждого файла шаблона, который изменился с вашей версии, он спрашивает, что сделать: **apply** вливает изменение в
ваш файл, **replace** берёт файл шаблона, **skip** оставляет ваш, а **diff** сначала показывает изменение. Конфликт
оставляет обычные метки git; разрешите их и запустите `upgrade` снова. Файлы, которые шаблон только положил один раз,
например ваш код и ваши страницы, он никогда не трогает. `--dry-run` показывает, что изменится, и ничего не пишет.

## Подробности о шаблоне

Для случаев, когда вам или агенту нужны точные параметры.

### Семь вопросов

Каждый ответ, кроме языков, — выбор из короткого списка, и каждый также принимает `other:<ваш ответ>`. Без терминала,
например в скрипте или в оболочке агента, передайте ответы флагами. Тогда пропущенный ответ — ошибка со списком
вариантов; ничего не угадывается.

| Вопрос | Флаг | Варианты (несколько — через запятую) |
| --- | --- | --- |
| Что это за инструмент? | `--category` | `messenger`, `mail`, `notes`, `files`, `calendar`, `meetings` |
| На каких языках содержимое? | `--content-lang` | коды языков, можно несколько: `en,ru` |
| Как человек входит в сервис? | `--sign-in` | `oauth`, `token`, `session` (код по телефону, QR), `none` |
| На чём можно строить? | `--api` | `official-client`, `official-docs`, `unofficial` |
| Как люди фильтруют найденное? | `--filters` | несколько из `time`, `person`, `container`, `text`, `status` |
| Что никогда не должно попасть в хранилище, журнал или вывод? | `--never-store` | несколько из `tokens`, `codes`, `secret-links`, `content` |
| Какие недоверенные данные приходят? | `--untrusted` | несколько из `messages`, `files`, `links`, `names`; или `none` отдельно |

Тот же инструмент, созданный без единого вопроса:

```sh
npx @wirecat/cli-template new acme-cli --command acme --package @example/acme-cli --owner example \
  --category notes --content-lang en --sign-in token --api official-docs --filters time,text \
  --never-store tokens --untrusted messages,links
```

### Учитесь у похожего инструмента

В шаблоне нет примера кода. Ваш агент учится у инструмента WireCat, ближайшего к вашему; его выбирает первый ответ:

| Что за инструмент | Образец |
| --- | --- |

### Четыре шага, которые делает человек

`new` выводит их в конце. Последний нужен только инструментам в организации WireCatLabs.

1. Создайте репозиторий и защитите его ветку `main`, как сказано в
   [чек-листе нового CLI](https://github.com/WireCatLabs/cli-base/blob/main/docs/standards/new-cli.md).
2. Опубликуйте первую версию сами командой `bin/release --local`: npm предлагает доверенную публикацию только для
   пакета, который уже есть. Затем настройте в npm доверенную публикацию для вашего пакета с `release.yml` и добавьте
   секреты, если они нужны. Подробности — в разделе [Публикация в своей области имён](#публикация-в-своей-области-имён).
3. Выберите для ежемесячных проверок день месяца, который не занят другими вашими репозиториями. В
   `.github/workflows/monthly.yml` шаблона стоит заглушка, и CI отклоняет её, пока вы её не замените.
4. **Только для инструментов WireCatLabs:** добавьте инструмент в группы сравнения cli-base, в список инструментов
   WireCat в cli-core и в `tools.json` этого сайта.

Инструмент вне WireCatLabs вместо этого держит свой файл групп сравнения и запускает `cli-dev audit --groups <file>`:
так его сравнивают с нашими инструментами без pull request в cli-base.
