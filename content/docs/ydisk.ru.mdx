Находите любой документ на Яндекс Диске по тому, что в нем написано, и поручите ИИ-агенту читать, раскладывать и
отправлять файлы за вас. Инструмент командной строки `ydisk` копирует на ваш компьютер текст выбранных папок Диска.
Поиск по словам «договор аренды» найдет PDF, даже если файл называется `scan_0042.pdf`, и даже без интернета.

Спросите агента, где договор с клиентом и какие в нем условия оплаты. Он ответит цитатой и путем к файлу на Диске.
Попросите перенести прошлогодние счета в архив или сделать ссылку для коллеги, и он сделает это на Диске, а перед
удалением или публичной ссылкой сначала спросит.

`ydisk` работает с Claude Code, Codex и другими агентами, которые запускают команды, с Claude Desktop и Cursor через
MCP, а с ChatGPT и Claude в браузере через ваш собственный туннель. Нужны Node.js и OAuth-токен Яндекса: ключ из
вашего аккаунта Яндекса, который дает инструменту доступ к вашему Диску.

<a id="how-it-works"></a>

## Как это устроено

- **Копия текста на вашем компьютере.** `ydisk` читает выбранные папки и сохраняет текст их файлов в локальном
  хранилище. Это один файл базы данных на вашем компьютере, общий для всех инструментов WireCat. Поиск читает эту
  копию, а не Диск, и находит слово в любой форме: по запросу «договор» найдутся и «договора», и «договоре».
- **Только выбранные папки.** Яндекс Диск не сообщает, что изменилось, поэтому каждая синхронизация заново
  перечисляет все выбранные папки с вложенными и скачивает только файлы, содержимое которых изменилось. Выбирайте
  папки с документами, а не весь Диск.
- **Текст, а не копии файлов.** Инструмент читает Markdown, обычный текст, PDF с текстовым слоем, Word `.docx`, Excel
  `.xlsx`, CSV и TSV. Фото и остальные файлы сохраняются только по имени. Сами файлы остаются на Диске.
- **Профиль для каждого аккаунта.** Профиль означает имя, которое вы даете одному аккаунту Яндекса, например
  `personal` или `work`. Каждая команда для аккаунта начинается с него: `ydisk personal search budget`.
- **Команды `files` меняют Диск.** Они работают с Яндексом напрямую. Удаление переносит файл в корзину Диска. В
  терминале инструмент спрашивает перед удалением, перезаписью или публичной ссылкой.

<a id="install-and-sign-in"></a>

## Установка и вход

1. Установите инструмент из npm и проверьте его. Нужен Node.js 22.16 или новее в ветке 22.x либо 24 и новее.

```sh
npm install -g @wirecat/yandex-disk-cli
ydisk --version
ydisk doctor
```

2. Зарегистрируйте приложение в Яндексе, чтобы получить токен. Приложение здесь означает только название и список
   прав в вашем аккаунте, ничего не публикуется ([инструкция Яндекса](https://yandex.ru/dev/disk-api/doc/ru/concepts/quickstart)):
   - Откройте [oauth.yandex.ru/client/new](https://oauth.yandex.ru/client/new/) и войдите в аккаунт, с Диском
     которого хотите работать. Если Яндекс спросит тип приложения, выберите «Для доступа к API или отладки».
   - Укажите любое название и свою почту. В разделе «Доступ к данным» добавьте права Яндекс Диска: «Чтение всего
     Диска» (`cloud_api:disk.read`), «Доступ к информации о Диске» (`cloud_api:disk.info`) и, чтобы менять файлы,
     «Запись в любом месте на Диске» (`cloud_api:disk.write`).
   - Создайте приложение и скопируйте его **ClientID** со страницы приложения.

3. Откройте адрес `https://oauth.yandex.ru/authorize?response_type=token&client_id=`, добавив ClientID в самый
   конец, разрешите доступ и скопируйте токен со страницы. Храните его как пароль.

4. Войдите под именем профиля, которое выберете сами. Инструмент спросит токен скрытым вводом, проверит его у Яндекса
   и сохранит в системной связке ключей, а там, где ее нет, в закрытом файле.

```sh
ydisk personal session start
ydisk personal session status --check
```

Яндекс продлевает токен на месяцы, пока им пользуются. Когда Яндекс перестанет его принимать, получите новый так же
и снова выполните `session start`.

`ydisk personal session end` удаляет токен с этого компьютера.

<a id="copy-a-folder-and-search-it"></a>

## Скопируйте папку и ищите по ней

`folders browse` показывает Диск по одному уровню, чтобы выбрать папку по ее пути:

```sh
ydisk personal folders browse
ydisk personal folders add /Documents
ydisk personal sync
ydisk personal search "договор аренды"
```

Одна синхронизация читает до 200 файлов (`--limit`), проходит примерно до 10 000 элементов и запоминает, где
остановилась. Запустите ее снова, чтобы продолжить, а позже, чтобы получить изменения. В фоне ничего не
синхронизируется. `ydisk personal status` показывает последнюю синхронизацию, оставшуюся работу и файлы, которые
сохранены только по имени. `documents show` выводит весь текст одного найденного файла.

Поиск по смыслу находит документ, который отвечает на вопрос другими словами. Для него один раз скачайте текстовую
модель через [Memo](./memo/installation.md) командой `memo models download embeddinggemma`, а затем выполните
`ydisk personal sync --embed`.

<a id="connect-your-agent"></a>

## Подключите агента

Терминальный агент, например Claude Code или Codex, получает навык инструмента:

```sh
ydisk skill install
```

Дальше просите обычными словами:

```text prompt
Используй ydisk CLI с профилем personal. Найди в моих папках на Диске договор с Harbour Ltd.
Процитируй условия оплаты и назови путь к файлу на Диске. Ничего не меняй в файлах.
```

Сначала агент ищет в локальной копии. Файл вне выбранных папок он читает прямо с Диска.

Чтобы подключить инструмент как MCP-сервер, выполните `ydisk personal mcp add claude-code --allow-writes` (или
`codex`). Для Claude Desktop, Cursor и других MCP-приложений `ydisk personal mcp config` выводит запись, которую нужно
вставить в настройки приложения. Для ChatGPT и Claude в браузере смотрите [браузерные приложения](./browser-apps.mdx).

<a id="work-with-files-on-the-disk"></a>

## Работа с файлами на Диске

```sh
ydisk personal files list --folder /Documents
ydisk personal files download /Documents/plan.pdf --output ./plan.pdf
ydisk personal files upload ./notes.md --folder /Documents
ydisk personal files move /Documents/old.pdf --folder /Archive
ydisk personal files delete /Documents/old.pdf
ydisk personal files publish /Documents/plan.pdf
```

`files delete` переносит файл в корзину Диска, а `files restore` возвращает его. `files publish` создает ссылку,
которую может открыть любой, у кого она есть. В терминале инструмент спрашивает перед удалением, перезаписью с
`--replace` и публичной ссылкой. По MCP спросить некого, поэтому для агента, которому это нельзя, закройте эти права:

```sh
ydisk personal config set permissions.files.delete deny
ydisk personal config set permissions.files.share deny
```

`YDISK_READ_ONLY=1` запрещает любые изменения. `--dry-run` у любого изменения показывает, что оно сделает, и ничего
не меняет.

<a id="limits"></a>

## Ограничения

- В сканированных PDF и картинках нет текста для поиска. Файлы больше 50 МБ сохраняются только по имени.
- Выбранная папка, которую вы переименовали или перенесли на Диске, перестает синхронизироваться, и ее копии уходят из
  хранилища. Добавьте ее снова по новому пути.
- Вход только по вставленному токену от приложения, которое вы регистрируете. Входа через браузер пока нет.

<a id="if-something-goes-wrong"></a>

## Если что-то не работает

- **«refused the token», код выхода 4.** Токен неверный, отозван или истек. Получите новый и снова выполните
  `session start`.
- **Изменение не проходит, код выхода 5.** Токен выдан без права `cloud_api:disk.write`, или изменение запрещают права
  профиля.
- **Поиск не находит файл, который точно есть.** Проверьте, что его папка есть в `folders list`, запускайте `sync`,
  пока `status` не покажет, что работы не осталось, и посмотрите, не сохранен ли файл в `status` только по имени.
- **«the OS keyring did not answer» в Linux.** Выйдите из системы и войдите снова или войдите в инструмент командой
  `ydisk personal session start --credential-storage file`.

`ydisk doctor` показывает, что настроено, без подключения к сети, а `ydisk personal doctor --online` проверяет токен.
Другие случаи описаны на [странице о неполадках](https://github.com/WireCatLabs/ydisk-cli/blob/main/docs/troubleshooting.md).
