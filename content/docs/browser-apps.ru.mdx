Используйте Telegram и MAX из AI-чата в браузере или мобильном приложении: находите сообщения, собирайте контекст и готовьте ответы. Подключение настраивается несколькими командами и добавлением адреса в настройках чата. Устанавливать приложения ChatGPT или Claude на компьютер не обязательно. Приложение должно поддерживать удалённый MCP по HTTP и вход OAuth, совместимый с этим сервером; ниже выберите своё приложение.

По этой инструкции вы подключите выбранный мессенджер и проверите его запросом к своим чатам. Схема простая: программа на вашем компьютере обращается к мессенджеру, а ваш AI-чат получает доступ к ней <DocTerm term="public-address" lang="ru" label="через публичный адрес" />. <DocTerm term="mcp" lang="ru" label="MCP" /> — способ такого подключения инструментов к агенту. Ниже получим адрес и добавим его в приложение. Компьютер должен оставаться включённым, а MCP-сервер инструмента командной строки и HTTPS-туннель — работать всё время подключения. Приложение мессенджера для компьютера не требуется.

## До начала

- Установите [инструмент командной строки для Telegram или MAX](./installation.mdx) и войдите в свой аккаунт. Для работы из браузера локальный агент не нужен: `tg setup --agent none` или `max setup --agent none`.
- Для первой настройки нужен компьютер, на котором работает инструмент. Оставьте его включённым во время работы. В конце страницы есть вариант с постоянно включённым сервером.
- В вашем AI-чате должен быть доступен пункт добавления своего подключения. Если его нет в рабочем аккаунте, проверьте доступ у администратора; [инструкция OpenAI](https://developers.openai.com/plugins/quickstart) и [инструкция Claude](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp) показывают актуальные варианты.

Дополнительную программу для получения публичного адреса установим в следующем шаге. Ниже описано, куда нажимать.

## 1. Подготовить публичный адрес

Для адреса используем **Tailscale** — программу, которая делает подключение на вашем компьютере доступным через интернет. Устанавливать её на телефон или другое устройство, где вы открываете чат, не нужно.

### Установить Tailscale и войти

1. Откройте [страницу загрузки](https://tailscale.com/download), выберите Windows, macOS или Linux.
2. В Windows или macOS скачайте установщик, установите программу и откройте её. Нажмите значок Tailscale рядом с часами в Windows или в верхней панели macOS, затем **Log in**. Для Linux используйте [инструкцию установки и входа](https://tailscale.com/download/linux).
3. В открывшемся браузере войдите или создайте аккаунт Tailscale и подтвердите подключение компьютера. В [списке устройств](https://console.tailscale.com/admin/machines) должен появиться ваш компьютер.

### Разрешить защищённый адрес

1. Откройте [раздел DNS в панели Tailscale](https://console.tailscale.com/admin/dns).
2. В блоке **MagicDNS** включите **Enable MagicDNS**, если он выключен. Так компьютер получит имя для адреса.
3. В блоке **HTTPS Certificates** нажмите **Enable HTTPS** и подтвердите показанное уведомление. Это включает защищённые адреса; [инструкция Tailscale](https://tailscale.com/docs/how-to/set-up-https-certificates) объясняет настройку.
4. Первый запуск команды в следующем шаге может показать ссылку для включения **Funnel** — функции публичного доступа. Откройте ссылку, войдите в тот же аккаунт и подтвердите включение. Tailscale подготовит сертификат и разрешение автоматически. Если доступ не разрешён, администратор может открыть **Access controls → Funnel → Add Funnel to policy**: [инструкция Funnel](https://tailscale.com/docs/features/tailscale-funnel).

## 2. Получить адрес и запустить подключение

Выберите свою ОС. <DocTerm term="terminal" lang="ru" label="Откройте два окна терминала" />. **Первый блок вставьте в окно 1**: он выдаст адрес вида `https://имя-компьютера.имя-сети.ts.net`. Если сначала появилась ссылка для разрешения доступа, выполните пункт 4 выше и вернитесь сюда.

**Второй блок вставьте в окно 2** и, когда он спросит адрес, скопируйте выданный HTTPS-адрес без `/mcp`. Если адрес содержит `:8443`, сохраните эту часть. Оставьте оба окна открытыми. Эти команды разрешают отправку сообщений на время работы подключения; [как выбрать права](#выбрать-права-ассистента) описано ниже.

## 3. Добавить подключение в ваш AI-чат

Добавьте **`/mcp` к полученному HTTPS-адресу**. Например, из `https://имя-компьютера.имя-сети.ts.net` получится `https://имя-компьютера.имя-сети.ts.net/mcp`. Это адрес подключения, а не адрес Telegram или MAX. Для каждого мессенджера создайте отдельное подключение.

<Tabs items={["ChatGPT", "Claude", "Gemini", "DeepSeek"]}>

<Tab value="ChatGPT" keepMounted>

### ChatGPT

1. Откройте **Plugins → + Add custom MCP server**, задайте понятное имя, например «Мой Telegram», и вставьте адрес с `/mcp`.
2. Выберите <DocTerm term="oauth" lang="ru" label="вход OAuth" />, а не вручную скопированный токен. Если есть выбор регистрации клиента, выберите автоматическую регистрацию **DCR**: сервер поддерживает DCR и проверку S256, которых требуют [правила OAuth OpenAI](https://developers.openai.com/plugins/build/auth). Для входа используйте одноразовый код из окна 2.
3. Установите созданный плагин, откройте чат **Work** и выберите его через `@`. Далее пишите обычные запросы. [Официальная инструкция OpenAI](https://developers.openai.com/plugins/quickstart).

Так же подключение добавляется для Codex в браузере. Локальный `config.toml` Codex настраивает только локальный клиент Codex, а не это подключение.

</Tab>

<Tab value="Claude" keepMounted>

### Claude

1. В claude.ai откройте **Customize → Connectors → + Add → Add custom connector**. Укажите имя и адрес с `/mcp`, нажмите **Continue**.
2. Выберите вход в аккаунт и автоматическую регистрацию клиента (**Register automatically**), если предлагается. Завершите добавление и подключитесь с кодом из окна 2.
3. В чате нажмите **+ → Connectors** и включите подключение. Оно доступно и в мобильном Claude. Для рабочего аккаунта подключение может сначала добавлять администратор: [официальная инструкция Claude](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp).

</Tab>

<Tab value="Gemini" keepMounted>

### Gemini

1. В [gemini.google.com](https://gemini.google.com) откройте **Settings → Connected Apps**. Если этого пункта нет, загляните в **Personal Intelligence → Connected Apps**.
2. В разделе **Custom apps** нажмите **Add a custom app**, вставьте адрес с `/mcp` и нажмите **Next**.
3. Завершите подключение с одноразовым кодом из окна 2. В чате наберите `@` и выберите подключение. После настройки им можно пользоваться и в мобильном Gemini.

Если раздела Custom apps нет: сейчас Google предоставляет эту функцию пользователям от 18 лет в США, с личным аккаунтом, включённой историей **Keep Activity** и английским языком. [Требования и инструкция Google](https://support.google.com/gemini/answer/17209137?hl=en).

</Tab>

<Tab value="DeepSeek" keepMounted>

### DeepSeek

Для работы с вашими инструментами у DeepSeek есть [Harness](https://www.deepseek.com/en/harness/) — отдельный клиент с веб-интерфейсом и поддержкой MCP. Это другой способ подключения, а не настройка обычного чата chat.deepseek.com.

Если хотите пользоваться моделью DeepSeek, проще выбрать клиент с поддержкой этой модели и MCP. На компьютере с `tg` или `max` добавьте локальное подключение по [инструкции MCP](./mcp.mdx); публичный адрес для этого не нужен, поэтому шаги 1 и 2 на этой странице пропустите. Для Harness есть [инструкция по подключению MCP](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/mcp/mcp-client/README.md).

</Tab>

</Tabs>

Перед вводом кода проверьте, что страница входа называет приложение, которое вы подключаете. Код одноразовый и действует 10 минут; после каждого входа сервер печатает новый код. После пяти неверных кодов вход закрыт, пока вы не перезапустите сервер.

## Сначала проверить чтение

Включите плагин или коннектор в чате и попросите:

```text prompt
Покажи пять последних чатов Telegram и число непрочитанных сообщений в них.
```

Потом попросите черновик, а когда хотите отправить — назовите получателя и точный текст.
[Как писать запросы](./prompting.mdx) объясняет, как попросить проверку перед отправкой.

## Выбрать права агента

Команды выше разрешают отправку этому процессу через `--permission messages.send=allow`.
Сохранённые настройки не меняются. Приложение управляет собственными подтверждениями.
Через MCP уровень `ask` не требует подтверждения сервера. Для подключения только на чтение выберите профиль с такими правами и уберите из команды запуска `--permission messages.send=allow`.

Настройки подтверждения в приложении и проверки прав на сервере — разные ограничения. Если инструмент разрешён
в приложении, а сервер разрешает отправку, следующий вызов может отправить без нового вопроса. Просите черновик,
если хотите сначала проверить текст. Список разрешённых получателей и лимит в час действуют.
Примеры настройки доступа — в разделе [Права](./permissions.mdx).

## Раньше работало, теперь не подключается

Для подключения из браузера должны работать компьютер с установленным инструментом командной строки, его MCP-сервер и HTTPS-туннель. После сна или перезапуска проверьте их по порядку:

1. Включите компьютер и проверьте аккаунт в терминале: `tg account show` или `max account show`. В PowerShell используйте `tg.cmd` или `max.cmd`. Если проверка не проходит, откройте инструкцию по входу для [Telegram](./tg/sessions.md) или [MAX](./max/sessions.md).
2. Повторите запуск туннеля и сервера в двух окнах по инструкции выше. Используйте тот же профиль и проверьте, что HTTPS-адрес совпадает с адресом коннектора. Если адрес изменился, обновите публичный адрес сервера и адрес коннектора.
3. Снова попросите показать пять чатов. Если приложение предлагает подключиться заново, используйте новый одноразовый код из окна работающего сервера.

Подключение восстановлено, когда агент показывает чаты нужного аккаунта. Если ошибка осталась, проверки ниже помогут отличить проблему входа от проблемы туннеля или приложения. Для файлов нужен ещё один шаг: путь на этом компьютере не передаёт файл агенту в браузере. Передача файлов описана для [Telegram](./tg/remote.md) и [MAX](./max/remote.md).

## Оба мессенджера одновременно

Используйте разные локальные порты и публичные адреса HTTPS. Например, Telegram: локальный
`8765`, публичный `443`; MAX: локальный `8766`, публичный `8443`. Второй туннель запускается
командой Tailscale вашей ОС с `funnel --https=8443 8766`; MAX получает `--port 8766`.
Вставьте его HTTPS-адрес вместе с `:8443` в команду MAX, а для коннектора добавьте `/mcp`.
Допустимые публичные порты Funnel: `443`, `8443`, `10000`
([справочник](https://tailscale.com/docs/reference/tailscale-cli/funnel)).

## Остановить, запустить заново или отозвать вход

- **Остановить:** Ctrl-C в обоих окнах переднего плана завершает этот сервер и туннель.
- **Запустить заново:** повторите команды с тем же профилем и адресом. Входы приложений переживают
  обычный перезапуск; без продления истекают через 30 дней.
- **Funnel в фоне:** при `--bg` Ctrl-C его не выключает. Проверьте `tailscale funnel status`,
  затем выключите только нужный маршрут: `tailscale funnel --https=443 off`
  (или `8443` для второго сервера). Используйте путь и повышение прав вашей ОС выше.
  Не используйте `funnel reset`, если есть другой маршрут: он сбрасывает все.
- **Отозвать входы приложений:** `tg mcp --revoke` или `max mcp --revoke`; в PowerShell
  используйте `tg.cmd` / `max.cmd`. Приложениям придётся войти заново; сеанс мессенджера останется.

## Если не работает

- **Нет подключения:** добавьте к полученному HTTPS-адресу `/.well-known/oauth-protected-resource/mcp`.
  Должен появиться JSON. Иначе проверьте Funnel, разрешение и локальный порт.
- **Чтение работает, отправка падает после подтверждения:** проверьте права запуска
  и эффективные права. `deny` и `readonly` запрещают изменения на сервере; проверьте также подтверждения приложения.
- **PowerShell запрещает скрипты:** используйте `tg.cmd` или `max.cmd`. Если команда не найдена,
  откройте новое окно и проверьте установку CLI; менять политику выполнения всей системы не нужно.
- **Нет инструментов:** `tg mcp doctor` или `max mcp doctor` проверяет локальный handshake,
  а не туннель и вход в аккаунт. Явный `account show` проверяет подключение к аккаунту.
- **Порт занят:** смените локальный порт и направьте Funnel на тот же номер. Для двух серверов
  выберите также разные публичные порты, как показано выше.

## Подключение без постоянно включённого ноутбука

Можно установить `tg` или `max` на отдельный сервер, который постоянно работает, и подключить к его адресу свой AI-чат. Тогда вы сможете пользоваться мессенджером из чата, даже когда ваш ноутбук выключен.

На сервере нужно установить инструмент, войти в нужный аккаунт, запустить MCP-подключение и обеспечить публичный HTTPS-адрес. Настройте автоматический запуск после перезагрузки: и MCP-сервер инструмента командной строки, и его HTTPS-туннель должны работать постоянно. Серверу нужен собственный вход в аккаунт; установка на ноутбуке сама по себе его не подключает.

Этот вариант удобен после проверки на своём компьютере. Подробности подключения — для [Telegram](./tg/remote.md) и [MAX](./max/remote.md). После настройки повторите запрос к пяти чатам: если он работает при выключенном ноутбуке, подключение обслуживает сервер.

<details>
<summary>Linux-сервер: работа после выхода и перезагрузки</summary>

1. Используйте одного обычного пользователя Linux для установки, входа в мессенджер и службы. Установите Node.js, CLI и Tailscale, затем войдите в мессенджер от этого пользователя. Сначала проверьте запрос к пяти чатам с обычным запуском в двух окнах выше.
2. Выполните `tg mcp config` или `max mcp config`. Возьмите абсолютный путь Node из `command`, а путь запуска CLI — из `args`; сохраните имя профиля, если оно есть. Пароли аккаунта и токены бота в файл службы не помещайте.
3. Создайте `~/.config/systemd/user/wirecat-mcp.service`. В шаблоне замените оба пути и публичный адрес на свои. Каталоги настроек и состояния должны совпадать с теми, где вы успешно вошли:

```ini
[Unit]
Description=WireCat messenger connection

[Service]
Type=simple
WorkingDirectory=%h
ExecStart=/absolute/path/to/node /absolute/path/to/cli-entry.js mcp --http --port 8765 --public-url https://server.tailnet.ts.net
Restart=on-failure
RestartSec=10

[Install]
WantedBy=default.target
```

4. Включите службу командами ниже. Администратор также должен разрешить работу служб этого пользователя без активного входа, например командой `loginctl enable-linger wirecat`. Это называется lingering. Справка: [службы systemd](https://www.freedesktop.org/software/systemd/man/latest/systemd.service.html) и [работа без активного входа](https://www.freedesktop.org/software/systemd/man/latest/loginctl.html).

```sh
systemctl --user daemon-reload
systemctl --user enable --now wirecat-mcp.service
systemctl --user status wirecat-mcp.service
```

5. На сервере запустите публичный адрес в фоне: `tailscale funnel --bg 8765`, с повышением прав, если ваша установка его требует. [Справка Funnel](https://tailscale.com/docs/reference/tailscale-cli/funnel#effects-of-rebooting-and-restarting) объясняет восстановление после перезагрузки. Порт должен совпадать с портом MCP-службы.
6. Проверьте, что служба видит тот же вход и разблокированное хранилище ключей. Работающий HTTP-адрес ещё не доказывает доступ к аккаунту. Если вход после перезагрузки не работает, восстановите доступ пользователя к ключнице; не копируйте данные входа в файл службы.
7. Закройте SSH-сеанс, выключите ноутбук и повторите запрос к чатам из приложения. Повторите после перезагрузки сервера. И доступ к аккаунту, и публичный адрес должны работать без ручного запуска терминала.

Чтобы остановить службу или отключить автозапуск:

```sh
systemctl --user stop wirecat-mcp.service
systemctl --user disable wirecat-mcp.service
```

`journalctl --user -u wirecat-mcp.service -n 30` поможет разобраться с запуском. В нём может быть одноразовый код подключения приложения: используйте его для своего входа и не публикуйте весь журнал. На других платформах используйте их менеджер служб с такими же проверками аккаунта и путей.
