Ищите сообщения, пересказывайте переписку и готовьте ответы из браузера. И `tg`, и `max`
поддерживают HTTP MCP с OAuth. **Tailscale устанавливается отдельно** на компьютер с CLI;
он даёт серверу публичный адрес HTTPS. На устройстве с браузером Tailscale не нужен.


## До начала

- [Установите Telegram или MAX](./installation.mdx) и войдите от обычного пользователя ОС.
  Настройка без локального агента: `tg setup --agent none` или `max setup --agent none`.
- Установите [Tailscale](https://tailscale.com/download) и войдите. В вашей сети включите
  MagicDNS, сертификаты HTTPS и [Funnel](https://tailscale.com/docs/features/tailscale-funnel).
  Первый запуск Funnel может напечатать ссылку для разрешения этих настроек.
- Компьютер должен быть включён; оставьте оба окна терминала открытыми.
- Нужна поддержка собственных MCP-серверов в приложении или рабочем пространстве:
  [инструкция OpenAI](https://developers.openai.com/plugins/quickstart),
  [инструкция Claude](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp).

## Запустить туннель и сервер

Выберите ОС ниже. **Первый блок — в окно 1, второй — в окно 2.** Когда второе окно спросит,
вставьте настоящий HTTPS origin из Funnel без `/mcp`. Если адрес содержит публичный порт,
например `:8443`, сохраните его. Команды разрешают отправку этому процессу; права описаны ниже.

<Tab value="Windows">

**Windows · PowerShell**

Установите приложение Tailscale и войдите через меню в трее. После установки Node.js, CLI
и Tailscale откройте новые окна PowerShell, чтобы обновился PATH. Суффикс `.cmd` обходит ошибку
политики выполнения для npm-команд. Первоначальная настройка: `tg.cmd setup --agent none`
или `max.cmd setup --agent none`.

**Окно 1 — PowerShell от администратора** для Funnel. Оператор `&` обрабатывает пробел в
стандартном пути установки; замените путь, если установили иначе.
**Окно 2 — обычный пользователь**, который вошёл в мессенджер.

```powershell
& "$env:ProgramFiles\Tailscale\tailscale.exe" funnel 8765
```

```powershell
$mcpPublicUrl = Read-Host 'HTTPS origin from Funnel (no /mcp)'
tg.cmd mcp --http --port 8765 --public-url $mcpPublicUrl --permission messages.send=allow
```

Для MAX замените `tg.cmd` на `max.cmd` в окне 2. Оба процесса запускайте в Windows.
WSL имеет отдельные пути и loopback: не смешивайте его сервер с этой настройкой Windows.

</Tab>

<Tab value="macOS">

**macOS · Terminal (zsh или bash)**

Установите приложение Tailscale и войдите.
[Встроенный CLI](https://tailscale.com/docs/reference/tailscale-cli?tab=macos) работает,
даже если `tailscale` нет в PATH. Используйте два обычных окна Terminal.

```sh
TAILSCALE_BE_CLI=1 /Applications/Tailscale.app/Contents/MacOS/Tailscale funnel 8765
```

```sh
printf 'HTTPS origin from Funnel (no /mcp): '
IFS= read -r mcpPublicUrl

```

Для MAX замените `tg` на `max` в окне 2.

**Linux · Terminal (bash или zsh)**

Установите Tailscale по [инструкции Linux](https://tailscale.com/download/linux)
и войдите через `sudo tailscale up`. Только туннель в окне 1 требует `sudo`.
Окно 2 запускайте от обычного пользователя, чтобы CLI нашёл ваш сеанс.

```sh
sudo tailscale funnel 8765
```

```sh
printf 'HTTPS origin from Funnel (no /mcp): '
IFS= read -r mcpPublicUrl
tg mcp --http --port 8765 --public-url "$mcpPublicUrl" --permission messages.send=allow
```

Для MAX замените `tg` на `max` в окне 2. Не запускайте сервер мессенджера с `sudo`.

Сервер слушает `127.0.0.1:8765` и печатает одноразовый код входа. Имя профиля ставится перед
командой: например, `tg work mcp`, а в Windows — `tg.cmd work mcp`.

## Выбрать права ассистента

Команды выше разрешают отправку этому процессу через `--permission messages.send=allow`.
Сохранённые настройки не меняются. Приложение управляет собственными подтверждениями.
Через MCP уровень `ask` не требует подтверждения сервера. Для подключения только на чтение
выберите профиль с такими правами.

Подтверждение в приложении и на сервере — разные вопросы. Если инструмент постоянно разрешён
в приложении и на сервере, следующий вызов может отправить без нового вопроса. Просите черновик,
если хотите сначала проверить текст. Список разрешённых получателей и лимит в час действуют.
Примеры настройки доступа — в разделе [Права](./permissions.md).

## Подключить Codex / ChatGPT web или Claude

Для коннектора добавьте **`/mcp` к origin Funnel**. Каждому мессенджеру нужен свой коннектор.
Выберите OAuth, вручную копировать токен не нужно.

**Codex / ChatGPT web:** откройте **Plugins → + Add custom MCP server**, создайте плагин,
укажите адрес `/mcp` и OAuth. Если предложен выбор регистрации, используйте DCR;
сервер объявляет DCR и S256. Подключите кодом из терминала, установите плагин и включите его
в Work-чате или упомяните через `@`. Локальный `config.toml` Codex не настраивает web-подключение.
См. [инструкцию OpenAI](https://developers.openai.com/plugins/quickstart) и
[требования OAuth](https://developers.openai.com/plugins/build/auth).

**Claude:** добавьте свой коннектор в **Customize → Connectors → + Add**, вставьте адрес `/mcp`
и подключите кодом из терминала сервера.
См. [актуальную инструкцию Claude](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp).

Перед вводом кода проверьте, что страница входа называет нужное приложение получателем.
Код действует один раз и 10 минут. Пять неверных кодов закрывают вход до перезапуска сервера.

## Сначала проверить чтение

Включите плагин или коннектор в чате и попросите:

```text prompt
Покажи пять последних чатов Telegram и число непрочитанных сообщений в них.
```

Потом попросите черновик, а когда хотите отправить — назовите получателя и точный текст.
[Как писать запросы](./prompting.md) объясняет, как попросить проверку перед отправкой.

## Раньше работало, теперь не подключается

Для подключения из браузера должны работать компьютер с мессенджером, его сервер и HTTPS-туннель. После сна или перезапуска проверьте их по порядку:

1. Включите компьютер и проверьте аккаунт в терминале: `tg account show` или `max account show`. В PowerShell используйте `tg.cmd` или `max.cmd`. Если проверка не проходит, откройте инструкцию по входу для [Telegram](./tg/sessions.md) или [MAX](./max/sessions.md).
2. Повторите запуск туннеля и сервера в двух окнах по инструкции выше. Используйте тот же профиль и проверьте, что HTTPS-адрес совпадает с адресом коннектора. Если адрес изменился, обновите публичный адрес сервера и адрес коннектора.
3. Снова попросите показать пять чатов. Если приложение предлагает подключиться заново, используйте новый одноразовый код из окна работающего сервера.

Подключение восстановлено, когда ассистент показывает чаты нужного аккаунта. Если ошибка осталась, проверки ниже помогут отличить проблему входа от проблемы туннеля или приложения. Для файлов нужен ещё один шаг: путь на этом компьютере не передаёт файл агенту в браузере. Передача файлов описана для [Telegram](./tg/remote.md) и [MAX](./max/remote.md).

## Оба мессенджера одновременно

Используйте разные локальные порты и публичные адреса HTTPS. Например, Telegram: локальный
`8765`, публичный `443`; MAX: локальный `8766`, публичный `8443`. Второй туннель запускается
командой Tailscale вашей ОС с `funnel --https=8443 8766`; MAX получает `--port 8766`.
Вставьте его HTTPS origin вместе с `:8443` в команду MAX, а для коннектора добавьте `/mcp`.
Допустимые публичные порты Funnel: `443`, `8443`, `10000`
([справочник](https://tailscale.com/docs/reference/tailscale-cli/funnel)).

## Остановить, запустить заново или отозвать вход

- **Остановить:** Ctrl-C в обоих окнах переднего плана завершает этот сервер и туннель.
- **Запустить заново:** повторите команды с тем же профилем и адресом. Входы приложений переживают
  обычный перезапуск; без продления истекают через 30 дней.
- **Funnel в фоне:** при `--bg` Ctrl-C его не выключает. Проверьте `tailscale funnel status`,
  затем выключите только нужный маршрут: `tailscale funnel --https=443 off`
  (или `8443` для второго сервера). Используйте путь и повышение прав вашей ОС выше.
  Не используйте `funnel reset`, если есть другой маршрут: он сбрасывает все.
- **Отозвать входы приложений:** `tg mcp --revoke` или `max mcp --revoke`; в PowerShell
  используйте `tg.cmd` / `max.cmd`. Приложениям придётся войти заново; сеанс мессенджера останется.

## Если не работает

- **Нет подключения:** откройте origin с `/.well-known/oauth-protected-resource/mcp`.
  Должен появиться JSON. Иначе проверьте Funnel, разрешение и локальный порт.
- **Чтение работает, отправка падает после подтверждения:** проверьте права запуска
  и эффективные права. `deny` и `readonly` запрещают изменения на сервере; проверьте также подтверждения приложения.
- **PowerShell запрещает скрипты:** используйте `tg.cmd` или `max.cmd`. Если команда не найдена,
  откройте новое окно и проверьте установку CLI; менять политику выполнения всей системы не нужно.
- **Нет инструментов:** `tg mcp doctor` или `max mcp doctor` проверяет локальный handshake,
  а не туннель и вход в аккаунт. Явный `account show` проверяет подключение к аккаунту.
- **Порт занят:** смените локальный порт и направьте Funnel на тот же номер. Для двух серверов
  выберите также разные публичные порты, как показано выше.
