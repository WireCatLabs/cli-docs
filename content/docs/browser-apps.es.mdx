Busca mensajes, resume conversaciones y prepara respuestas desde el navegador. Tanto `tg` como
`max` ofrecen MCP por HTTP con OAuth. **Tailscale se instala por separado** en el ordenador
que ejecuta el CLI y da al servidor una dirección HTTPS pública. El dispositivo del navegador
no necesita Tailscale.


## Antes de empezar

- [Instala Telegram o MAX](./installation.mdx) e inicia sesión con tu usuario habitual del SO.
  Para configurar sin agente local: `tg setup --agent none` o `max setup --agent none`.
- Instala [Tailscale](https://tailscale.com/download) e inicia sesión. Activa MagicDNS,
  certificados HTTPS y [Funnel](https://tailscale.com/docs/features/tailscale-funnel) en tu red.
  El primer comando Funnel puede imprimir un enlace para autorizar esta configuración.
- Mantén el ordenador despierto y ambas ventanas de terminal abiertas mientras uses el conector.
- Tu app o espacio de trabajo debe admitir servidores MCP personalizados. Consulta las
  [instrucciones de OpenAI](https://developers.openai.com/plugins/quickstart) o de
  [Claude](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp).

## Iniciar el túnel y el servidor

Elige tu SO abajo. **El primer bloque va en la ventana 1; el segundo en la ventana 2.**
Cuando la segunda ventana lo pida, pega el origen HTTPS real que imprime Funnel, sin `/mcp`.
Conserva el puerto público, como `:8443`, si aparece. Los comandos permiten enviar durante
este proceso; lee la explicación de permisos de abajo.

<Tab value="Windows">

**Windows · PowerShell**

Instala la app Tailscale e inicia sesión desde su icono en la bandeja. Tras instalar Node.js,
el CLI y Tailscale, abre ventanas nuevas de PowerShell para actualizar PATH. Usa `.cmd` para
los comandos npm y evitar errores de la política de ejecución. Configuración inicial:
`tg.cmd setup --agent none` o `max.cmd setup --agent none`.

Ejecuta **la ventana 1 como Administrador** para Funnel. `&` gestiona el espacio de la ruta
predeterminada; cambia la ruta si instalaste Tailscale en otro lugar.
Ejecuta **la ventana 2 con tu usuario habitual**, que inició sesión en el mensajero.

```powershell
& "$env:ProgramFiles\Tailscale\tailscale.exe" funnel 8765
```

```powershell
$mcpPublicUrl = Read-Host 'HTTPS origin from Funnel (no /mcp)'
tg.cmd mcp --http --port 8765 --public-url $mcpPublicUrl --permission messages.send=allow
```

Para MAX, cambia `tg.cmd` por `max.cmd` en la ventana 2. Ejecuta ambos procesos en Windows.
WSL tiene rutas y red loopback propias; no mezcles su servidor con esta configuración de Windows.

</Tab>

<Tab value="macOS">

**macOS · Terminal (zsh o bash)**

Instala la app Tailscale e inicia sesión. Su [CLI integrado](https://tailscale.com/docs/reference/tailscale-cli?tab=macos)
funciona aunque `tailscale` no esté en PATH. Usa dos ventanas normales de Terminal.

```sh
TAILSCALE_BE_CLI=1 /Applications/Tailscale.app/Contents/MacOS/Tailscale funnel 8765
```

```sh
printf 'HTTPS origin from Funnel (no /mcp): '
IFS= read -r mcpPublicUrl
tg mcp --http --port 8765 --public-url "$mcpPublicUrl" --permission messages.send=allow
```

Para MAX, cambia `tg` por `max` en la ventana 2.

</Tab>

<Tab value="Linux">

**Linux · Terminal (bash o zsh)**

Instala Tailscale según las [instrucciones de Linux](https://tailscale.com/download/linux)
e inicia sesión con `sudo tailscale up`. Solo el túnel de la ventana 1 necesita `sudo`.
La ventana 2 debe usar tu usuario habitual para encontrar la sesión configurada.

```sh
sudo tailscale funnel 8765
```

```sh
printf 'HTTPS origin from Funnel (no /mcp): '
IFS= read -r mcpPublicUrl
tg mcp --http --port 8765 --public-url "$mcpPublicUrl" --permission messages.send=allow
```

Para MAX, cambia `tg` por `max` en la ventana 2. No ejecutes el servidor del mensajero con `sudo`.

</Tab>

El servidor escucha en `127.0.0.1:8765` e imprime un código de acceso de un solo uso.
El perfil precede al comando: `tg work mcp` o, en Windows, `tg.cmd work mcp`.

## Elegir qué puede hacer el asistente

Los comandos permiten enviar durante este proceso con `--permission messages.send=allow`, sin
cambiar los ajustes guardados. La app controla sus aprobaciones. Por MCP, `ask` no fuerza una
confirmación del servidor. Para solo leer, elige un perfil con permisos de lectura.

La aprobación de la app y la del servidor son preguntas distintas. Si siempre permites una herramienta
en la app y el servidor, otra llamada puede enviar sin volver a preguntar. Pide un borrador para revisar
el texto antes. Siguen activos los destinatarios permitidos y el límite por hora.
Consulta los ejemplos de [permisos](./permissions.md).

## Conectar Codex / ChatGPT web o Claude

Para el conector, **añade `/mcp` al origen Funnel**. Cada mensajero necesita su propio conector.
Elige OAuth; no copies un token manualmente.

**Codex / ChatGPT web:** abre **Plugins → + Add custom MCP server**, crea un plugin y escribe
la URL `/mcp` y OAuth. Elige DCR si se ofrece una elección de registro; el servidor anuncia
DCR y S256. Conecta con el código de la terminal, instala el plugin y actívalo en un chat Work
o menciónalo con `@`. El `config.toml` local de Codex no configura esta conexión web.
Consulta las [instrucciones de OpenAI](https://developers.openai.com/plugins/quickstart) y sus
[requisitos OAuth](https://developers.openai.com/plugins/build/auth).

**Claude:** añade un conector personalizado en **Customize → Connectors → + Add**, pega la URL
`/mcp` y conecta con el código impreso por el servidor del mensajero.
Consulta las [instrucciones actuales](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp).

Antes de introducir el código, comprueba que la página de acceso nombra la app deseada como
destino. Los códigos funcionan una vez durante 10 minutos. Cinco errores bloquean el acceso
hasta reiniciar el servidor.

## Probar primero la lectura

Con el plugin o conector activado en el chat, pide:

```text prompt
Muéstrame mis cinco chats recientes de Telegram y sus recuentos de mensajes sin leer.
```

Después pide un borrador o, cuando quieras enviar, indica el destinatario y el texto exacto.
[Cómo escribir peticiones](./prompting.md) explica cómo pedir una revisión antes de enviar.

## Ambos mensajeros a la vez

Usa puertos locales y direcciones HTTPS públicas distintos. Por ejemplo: Telegram en local
`8765` y público `443`; MAX en local `8766` y público `8443`. Para el segundo túnel, usa el
comando Tailscale de tu SO con `funnel --https=8443 8766` y añade `--port 8766` a MAX.
Copia su origen HTTPS con `:8443` al comando de MAX y añade `/mcp` para el conector.
Funnel admite los puertos públicos `443`, `8443` y `10000`
([referencia](https://tailscale.com/docs/reference/tailscale-cli/funnel)).

## Detener, reiniciar o revocar

- **Detener:** Ctrl-C en ambas ventanas de primer plano detiene ese servidor y túnel.
- **Reiniciar:** repite los comandos con el mismo perfil y URL. Las sesiones de las apps
  sobreviven a reinicios normales; caducan tras 30 días sin renovación.
- **Funnel en segundo plano:** con `--bg`, Ctrl-C no lo desactiva. Consulta `tailscale funnel status`
  y desactiva solo esa ruta con `tailscale funnel --https=443 off` (o `8443` para el segundo servidor).
  Usa la ruta y elevación de tu SO arriba. Evita `funnel reset` si tienes otra ruta: las borra todas.
- **Revocar acceso de apps:** `tg mcp --revoke` o `max mcp --revoke`; en PowerShell, usa
  `tg.cmd` / `max.cmd`. Las apps deben volver a entrar; la sesión del mensajero se mantiene.

## Si algo falla

- **No conecta:** abre el origen con `/.well-known/oauth-protected-resource/mcp` añadido.
  Debe mostrar JSON. Si no, comprueba Funnel, su autorización y el puerto local.
- **Lee pero no envía tras aprobar en la app:** comprueba los permisos de inicio y el permiso
  efectivo. `deny` y `readonly` impiden cambios en el servidor; revisa también las aprobaciones de la app.
- **PowerShell rechaza scripts:** usa `tg.cmd` o `max.cmd`. Si no encuentra el comando, abre una
  ventana nueva y comprueba la instalación del CLI; no cambies la política de ejecución de todo el sistema.
- **Sin herramientas:** `tg mcp doctor` o `max mcp doctor` verifica el handshake local, no el
  túnel ni el acceso al mensajero. Un `account show` explícito verifica esa cuenta.
- **Puerto ocupado:** cambia el puerto local y apunta Funnel al mismo número. Para dos servidores,
  asigna también puertos HTTPS públicos distintos, como arriba.
