Usa Telegram y MAX directamente desde un **chat de ChatGPT o claude.ai en el navegador**: busca mensajes, reúne contexto o prepara respuestas. Se configura con unos comandos y añadiendo una dirección en los ajustes del chat. En Claude también puedes usar la conexión desde la [aplicación móvil](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp).

Esta guía conecta el mensajero que elijas y lo comprueba con una petición sobre tus chats. Un programa en tu ordenador accede al mensajero; ChatGPT o Claude llega a ese programa <DocTerm term="public-address" lang="es" label="mediante una dirección pública" />. <DocTerm term="mcp" lang="es" label="MCP" /> es el modo de conectar estas herramientas al asistente. A continuación obtendremos la dirección y la añadiremos a la aplicación.

## Antes de empezar

- Instala la [herramienta de línea de comandos de Telegram o MAX](./installation.mdx) e inicia sesión en tu cuenta. No necesitas un agente local para usar el navegador: `tg setup --agent none` o `max setup --agent none`.
- Haz la configuración inicial en el ordenador que ejecuta la herramienta y mantenlo encendido durante el uso. Al final explicamos la opción de un servidor siempre encendido.
- Tu cuenta de ChatGPT o Claude debe permitir añadir una conexión propia. Si no aparece esa opción en tu cuenta de trabajo, consulta al administrador. Las [instrucciones de OpenAI](https://developers.openai.com/plugins/quickstart) y de [Claude](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp) muestran las opciones actuales.

En el siguiente paso instalaremos el programa para obtener la dirección pública y explicaremos dónde hacer clic.

## 1. Preparar una dirección pública

Usaremos **Tailscale**, un programa que hace accesible por internet la conexión de tu ordenador. No hace falta instalarlo en el móvil ni en otro dispositivo donde abras el chat.

### Instalar Tailscale e iniciar sesión

1. Abre la [página de descarga](https://tailscale.com/download) y elige Windows, macOS o Linux.
2. En Windows o macOS, descarga y ejecuta el instalador y abre la aplicación. Pulsa el icono de Tailscale junto al reloj en Windows o en la barra superior de macOS, y elige **Log in**. Para Linux, sigue las [instrucciones de instalación y acceso](https://tailscale.com/download/linux).
3. En el navegador que se abre, inicia sesión o crea una cuenta de Tailscale y confirma la conexión del ordenador. Debe aparecer en la [lista de dispositivos](https://console.tailscale.com/admin/machines).

### Habilitar la dirección segura

1. Abre la [sección DNS de Tailscale](https://console.tailscale.com/admin/dns).
2. En **MagicDNS**, pulsa **Enable MagicDNS** si está desactivado. Así el ordenador tendrá un nombre para su dirección.
3. En **HTTPS Certificates**, pulsa **Enable HTTPS** y acepta el aviso mostrado. Esto habilita direcciones seguras; consulta las [instrucciones de Tailscale](https://tailscale.com/docs/how-to/set-up-https-certificates).
4. El primer comando del siguiente paso puede mostrar un enlace para activar **Funnel**, la función de acceso público. Ábrelo, entra con la misma cuenta y confirma la activación. Tailscale prepara automáticamente el certificado y el permiso. Si no tienes acceso, un administrador puede abrir **Access controls → Funnel → Add Funnel to policy**: [instrucciones de Funnel](https://tailscale.com/docs/features/tailscale-funnel).

## 2. Obtener la dirección e iniciar la conexión

Elige tu sistema operativo y <DocTerm term="terminal" lang="es" label="abre dos ventanas de terminal" />. **Pega el primer bloque en la ventana 1**: mostrará una dirección como `https://ordenador.red.ts.net`. Si primero muestra un enlace de autorización, completa el punto 4 anterior y vuelve aquí.

**Pega el segundo bloque en la ventana 2** e introduce la dirección HTTPS cuando la pida, sin `/mcp`. Conserva `:8443` si aparece. Deja ambas ventanas abiertas. Estos comandos permiten enviar durante la conexión; [cómo elegir los permisos](#elegir-qué-puede-hacer-el-asistente) se explica abajo.

```powershell
$mcpPublicUrl = Read-Host 'HTTPS origin from Funnel (no /mcp)'
tg.cmd mcp --http --port 8765 --public-url $mcpPublicUrl --permission messages.send=allow
```

Para MAX, cambia `tg.cmd` por `max.cmd` en la ventana 2. Ejecuta ambos procesos en Windows.

El perfil precede al comando: `tg work mcp` o, en Windows, `tg.cmd work mcp`.

## 3. Añadir la conexión a ChatGPT o Claude

Añade **`/mcp` a la dirección HTTPS**. Por ejemplo, `https://ordenador.red.ts.net` pasa a ser `https://ordenador.red.ts.net/mcp`. Es la dirección de la conexión, no la web de Telegram o MAX. Crea una conexión distinta para cada mensajero.

### ChatGPT

1. Abre **Plugins → + Add custom MCP server**, ponle un nombre como «Mi Telegram» y pega la dirección con `/mcp`.
2. Elige <DocTerm term="oauth" lang="es" label="OAuth" />. Si se ofrece, selecciona el registro automático (**DCR**). Usa el código de un solo uso de la ventana 2 para entrar.
3. Instala el plugin, abre un chat **Work** y selecciónalo con `@`. Después escribe peticiones normales. [Instrucciones oficiales de OpenAI](https://developers.openai.com/plugins/quickstart).

### Claude

1. En claude.ai, abre **Customize → Connectors → + Add → Add custom connector**. Introduce el nombre y la dirección con `/mcp`, y pulsa **Continue**.
2. Elige iniciar sesión y **Register automatically**, si se ofrece. Termina de añadir el conector y conecta con el código de la ventana 2.
3. En el chat, pulsa **+ → Connectors** para activarlo. También funciona en Claude móvil. En una cuenta de trabajo puede tener que añadirlo primero el administrador: [instrucciones oficiales de Claude](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp).

Antes de introducir el código, comprueba el nombre de la aplicación. El código funciona una vez durante 10 minutos; cinco intentos incorrectos requieren reiniciar el servidor.

## Probar primero la lectura

Con el plugin o conector activado en el chat, pide:

```text prompt
Muéstrame mis cinco chats recientes de Telegram y sus recuentos de mensajes sin leer.
```

Después pide un borrador o, cuando quieras enviar, indica el destinatario y el texto exacto.
[Cómo escribir peticiones](./prompting.mdx) explica cómo pedir una revisión antes de enviar.

## Elegir qué puede hacer el asistente

Los comandos permiten enviar durante este proceso con `--permission messages.send=allow`, sin
cambiar los ajustes guardados. La app controla sus aprobaciones. Por MCP, `ask` no fuerza una
confirmación del servidor. Para solo leer, elige un perfil con permisos de lectura.

La aprobación de la app y la del servidor son preguntas distintas. Si siempre permites una herramienta
en la app y el servidor, otra llamada puede enviar sin volver a preguntar. Pide un borrador para revisar
el texto antes. Siguen activos los destinatarios permitidos y el límite por hora.
Consulta los ejemplos de [permisos](./permissions.mdx).

## Antes funcionaba y ahora no conecta

La conexión del navegador necesita que estén funcionando el ordenador del mensajero, su servidor y el túnel HTTPS. Después de suspender o reiniciar, sigue este orden:

1. Activa el ordenador y comprueba la cuenta en un terminal con `tg account show` o `max account show`. En PowerShell usa `tg.cmd` o `max.cmd`. Si falla, sigue la guía de acceso de [Telegram](./tg/sessions.md) o [MAX](./max/sessions.md).
2. Reinicia el túnel y el servidor en las dos ventanas indicadas arriba. Usa el mismo perfil y comprueba que la dirección HTTPS coincide con la del conector. Si cambió, actualiza la dirección pública del servidor y la del conector.
3. Repite la petición de cinco chats. Si la aplicación pide conectar de nuevo, usa el nuevo código de un solo uso que muestra el servidor en ejecución.

La conexión funciona cuando el asistente muestra los chats de la cuenta esperada. Si sigue fallando, las comprobaciones de abajo distinguen problemas de cuenta, túnel o aplicación. Los archivos requieren otro paso: una ruta en este ordenador no entrega el archivo al agente del navegador. Consulta la transferencia para [Telegram](./tg/remote.md) o [MAX](./max/remote.md).

## Ambos mensajeros a la vez

Usa puertos locales y direcciones HTTPS públicas distintos. Por ejemplo: Telegram en local
`8765` y público `443`; MAX en local `8766` y público `8443`. Para el segundo túnel, usa el
comando Tailscale de tu SO con `funnel --https=8443 8766` y añade `--port 8766` a MAX.
Copia su origen HTTPS con `:8443` al comando de MAX y añade `/mcp` para el conector.
Funnel admite los puertos públicos `443`, `8443` y `10000`
([referencia](https://tailscale.com/docs/reference/tailscale-cli/funnel)).

## Detener, reiniciar o revocar

- **Detener:** Ctrl-C en ambas ventanas de primer plano detiene ese servidor y túnel.
- **Reiniciar:** repite los comandos con el mismo perfil y URL. Las sesiones de las apps
  sobreviven a reinicios normales; caducan tras 30 días sin renovación.
- **Funnel en segundo plano:** con `--bg`, Ctrl-C no lo desactiva. Consulta `tailscale funnel status`
  y desactiva solo esa ruta con `tailscale funnel --https=443 off` (o `8443` para el segundo servidor).
  Usa la ruta y elevación de tu SO arriba. Evita `funnel reset` si tienes otra ruta: las borra todas.
- **Revocar acceso de apps:** `tg mcp --revoke` o `max mcp --revoke`; en PowerShell, usa
  `tg.cmd` / `max.cmd`. Las apps deben volver a entrar; la sesión del mensajero se mantiene.

## Si algo falla

- **No conecta:** abre el origen con `/.well-known/oauth-protected-resource/mcp` añadido.
  Debe mostrar JSON. Si no, comprueba Funnel, su autorización y el puerto local.
- **Lee pero no envía tras aprobar en la app:** comprueba los permisos de inicio y el permiso
  efectivo. `deny` y `readonly` impiden cambios en el servidor; revisa también las aprobaciones de la app.
- **PowerShell rechaza scripts:** usa `tg.cmd` o `max.cmd`. Si no encuentra el comando, abre una
  ventana nueva y comprueba la instalación del CLI; no cambies la política de ejecución de todo el sistema.
- **Sin herramientas:** `tg mcp doctor` o `max mcp doctor` verifica el handshake local, no el
  túnel ni el acceso al mensajero. Un `account show` explícito verifica esa cuenta.
- **Puerto ocupado:** cambia el puerto local y apunta Funnel al mismo número. Para dos servidores,
  asigna también puertos HTTPS públicos distintos, como arriba.

## Conectar sin mantener encendido el portátil

Puedes instalar `tg` o `max` en un servidor que esté siempre en marcha y conectar ChatGPT o Claude a su dirección. Así podrás usar tu mensajero desde el chat aunque el portátil esté apagado.

Instala la herramienta en el servidor, inicia sesión en la cuenta elegida, arranca la conexión MCP y proporciona una dirección HTTPS pública. Configura el inicio automático tras un reinicio: tanto el programa del mensajero como el acceso público deben seguir funcionando. El servidor necesita su propio inicio de sesión; la instalación del portátil no lo conecta automáticamente.

Prueba esta opción después de que funcione en tu ordenador. Consulta la conexión remota para [Telegram](./tg/remote.md) y [MAX](./max/remote.md). Repite la petición de cinco chats: si funciona con el portátil apagado, el servidor mantiene la conexión.
