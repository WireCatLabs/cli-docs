You can use drafts in two ways: review and send them yourself in your messaging app, or ask your agent to send text you have approved. Use a template when an auto-reply rule should answer for you. A draft lets you decide about one message; a template gives a rule reusable reply text.

- **A draft** is an unsent reply you can review and edit. In Telegram and in mail your agent saves it as a draft in the app, so you check it there and send it yourself.
- **A template** is reusable text for an auto-reply rule. The background server fills it in when the rule matches. Its audience, sending permissions and limits control whether a reply is sent. Liquid provides placeholders such as a sender's name.

| | Draft | Template |
|---|---|---|
| Who writes the text | your agent prepares a reply; you can edit it | you write reusable text, with an optional AI-generated part |
| Who decides to send | you, for this message and chat | the rule, within its audience, permissions and limits |
| Where you review it | the draft in Telegram or your mail app, or your agent chat | the rule's template and its test results |

## Review drafts in your messaging app

Your agent can save a reply as a draft right where you will send it. In Telegram the text appears in the chat's message box, and in mail a letter appears in your Drafts folder. Saving a draft sends nothing.

1. Ask your agent to prepare a reply and save it as a draft in that chat.
2. Open the chat in Telegram, or the Drafts folder in your mail app, and check the recipient and wording.
3. Edit the text if needed and send it yourself.

```text prompt
Use tg CLI. Read the recent messages in my chat with Anna and prepare a short reply to her last question. Use only facts from our chat. Save the reply as a draft in that chat, so I can check it in Telegram and send it myself. Send nothing and mark nothing as read.
```

The agent saves it with `tg messages send --draft`, which needs the separate [drafts permission](./tg/permissions.md#saving-a-draft). For mail, ask it to save the letter in Drafts: it uses `mail drafts create`.

MAX, WhatsApp and Slack have no drafts the agent can write to. There, ask the agent to return the chat name and the reply text, and paste the text into the chat yourself. Start the request with the name of your tool, for example "Use max CLI".

### Have your agent send an approved draft

If you prefer to finish in your agent chat, review the proposed text there and approve the exact text and recipient: "Send exactly that reply to Anna's direct chat." Give the full final text if you edited it. The profile's [sending permissions](./configuration.mdx#permissions) still apply. See [more requests for preparing replies](./prompting.mdx#draft-a-reply-then-decide-whether-to-send).

## Templates: rules that answer by themselves

An auto-reply rule says when to answer, for example outside working hours, and its template says
what to send. Before any reply goes out:

- the rule's audience must permit the sender. [Choose who may receive auto-replies](#choose-who-may-receive-auto-replies) before enabling the rule;
- sending must be allowed in the profile's [permissions](./configuration.mdx#permissions) with
  `permissions.replies.send allow`; `ask` counts as no, because the background server has nobody
  to ask;
- every rule has a limit per chat and per person, such as one reply per chat in 12 hours.

`replies test` shows what the rules would have answered in your saved messages. It sends nothing.

### Choose who may receive auto-replies

Ask your agent to restrict the audience to the people you choose and keep sending off while you review the rule. The `replies audience` command shows and changes this audience. `--reply listed` restricts it to allowed people or chats; `--allow-people` replaces the allowed sender list, and deny lists exclude recipients. Review the audience and test the rule before enabling sending.

For the steps and command options, see [Telegram audience settings](./tg/replies.md#conditions-and-audience) or [MAX audience settings](./max/replies.md#редактировать-условия-и-аудиторию).

### What a template can use

| Variable | What it holds |
|---|---|
| `sender.name` | the sender's full name |
| `sender.firstName` | the first word of the sender's name |
| `chat.title` | the chat's title |
| `chat.kind` | the kind of chat, such as `dialog` or `group` |
| `now` | the current time, in the rule's time zone, or UTC when the rule has no working hours |

Standard Liquid filters work, such as `default` for an empty value and `date` for a time:
`{{ now | date: "%H:%M" }}`. Conditions such as `{% if chat.kind == "dialog" %}` work too.

The incoming message's text is never a template variable. An unknown variable or filter makes the
template invalid, and then no reply is sent. A template cannot read files, and its time, memory
and length are limited.

### Examples

An away message:

```liquid
Thanks, {{ sender.firstName | default: "there" }}! I'm away until Monday and will reply then.
```

A reply outside working hours. The hours belong to the rule, not to the template: set them with
`replies edit` and the options `--outside`, `--days` and `--timezone`. Then `now` is in that time zone:

```liquid
Hi {{ sender.firstName | default: "there" }}, it's {{ now | date: "%H:%M" }} here. I answer on weekdays from 9:00 to 19:00.
```

An AI-generated part, with your own text as a fallback:

```liquid
Thanks, {{ sender.firstName | default: "there" }}!
{% ai %}Briefly confirm you got the message; I will answer tomorrow.{% else %}I will answer tomorrow.{% endai %}
```

### AI-generated text

Choose the AI provider and model identifier in your profile's settings. The identifier selects the provider's text-generating component; it does not choose the agent you chat with. The [Telegram settings guide](./tg/replies.md#templates-and-a-model) and [MAX settings guide](./max/replies.md#шаблоны-liquid-и-модель) explain these technical settings.

Only the text inside `{% ai %}…{% endai %}` is generated; everything outside it is your text. The block's body supplies the instruction. The incoming message goes to the configured AI provider separately as data, never as part of that instruction. The result is used as plain text.

The text after `{% else %}` is the fallback. It is sent when AI processing is not configured, consent is missing, the call fails, or the generated answer is refused because it is empty, too long or repeats the incoming message. Without an `else`, that message gets no reply and the reason is recorded. Blocks cannot be nested.

AI processing needs its own consent, separate from the right to send. Consent permits incoming message data to go to the chosen AI provider for the whole profile:

```sh
tg personal replies consents show
tg personal replies consents grant
tg personal replies consents revoke
max personal replies consents show
max personal replies consents grant
max personal replies consents revoke
```

`replies consents deny` with a chat ID keeps that chat's messages away from the AI provider. A new provider or API address needs consent again. `replies test --ai` sends saved messages to the configured provider so you can inspect the generated text; it sends nothing to the messenger.

## Set it up

To create and test an auto-reply rule, follow [Telegram auto-replies](./tg/replies.md) or [MAX auto-replies](./max/replies.md). They cover creating a rule, choosing who may receive replies, configuring AI processing and pausing everything at once.
