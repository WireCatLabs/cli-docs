title: "Drafts and templates"
description: "Review replies in your messaging app and use templates for auto-replies with audience controls."
---

You can use drafts in two ways: review and send them yourself in your messaging app, or ask your agent to send text you have approved. Use a template when an auto-reply rule should answer for you. A draft lets you decide about one message; a template gives a rule reusable reply text.

- **A draft** is an unsent reply you can review and edit. The main workflow below puts the text in the messaging app's message box so you can check the chat and send it yourself.
- **A template** is reusable text for an auto-reply rule. The background server fills it in when the rule matches. Its audience, sending permissions and limits control whether a reply is sent. Liquid provides placeholders such as a sender's name.

| | Draft | Template |
|---|---|---|
| Who writes the text | your agent prepares a reply; you can edit it | you write reusable text, with an optional part written by an AI agent |
| Who decides to send | you, for this message and chat | the rule, within its audience, permissions and limits |
| Where you review it | the message box in your messaging app, or your agent chat | the rule's template and its test results |

## Review drafts in your messaging app

1. Ask your agent to prepare a reply and return the chat name and message text.
2. Open that chat in your messaging app and paste the text into its message box.
3. Check the recipient and wording, edit the text if needed, and press Send yourself when it is ready.

The current personal-account tools can prepare reply text through your agent, but they do not save it directly into the messaging app's draft field. You copy and paste it yourself. Ask for text to review, rather than asking the agent to send it or claiming a draft has already appeared in the app.

```text prompt
Use tg CLI. Read the recent messages in my chat with Anna and prepare a short reply to her last question. Use only facts from our chat. Return the chat name and reply text so I can paste it into the messaging app and review it there. Send nothing and mark nothing as read.
```

Use the name of your messenger tool in the request; for example, use "Use max CLI" for MAX.

### Have your agent send an approved draft

If you prefer to finish in your agent chat, review the proposed text there and approve the exact text and recipient: "Send exactly that reply to Anna's direct chat." Give the full final text if you edited it. The profile's [sending permissions](./permissions.mdx) still apply. See [more requests for preparing replies](./prompting.mdx#draft-a-reply-then-decide-whether-to-send).

## Templates: rules that answer by themselves

An auto-reply rule says when to answer, for example outside working hours, and its template says
what to send. Before any reply goes out:

- the rule's audience must permit the sender. [Choose who may receive auto-replies](#choose-who-may-receive-auto-replies) before enabling the rule;
- sending must be allowed in the profile's [permissions](./permissions.mdx) with
  `permissions.replies.send allow`; `ask` counts as no, because the background server has nobody
  to ask;
- every rule has a limit per chat and per person, such as one reply per chat in 12 hours.

`replies test` shows what the rules would have answered in your saved messages. It sends nothing.

### Choose who may receive auto-replies

Ask your agent to restrict the audience to the people you choose and keep sending off while you review the rule. The `replies audience` command shows and changes this audience. `--reply listed` restricts it to allowed people or chats; `--allow-people` replaces the allowed sender list, and deny lists exclude recipients. Review the audience and test the rule before enabling sending.

For the steps and command options, see [Telegram audience settings](./tg/replies.md#conditions-and-audience) or [MAX audience settings](./max/replies.md#редактировать-условия-и-аудиторию).

### What a template can use

| Variable | What it holds |
|---|---|
| `sender.name` | the sender's full name |
| `sender.firstName` | the first word of the sender's name |
| `chat.title` | the chat's title |
| `chat.kind` | the kind of chat, such as `dialog` or `group` |
| `now` | the current time, in the rule's time zone, or UTC when the rule has no working hours |

Standard Liquid filters work, such as `default` for an empty value and `date` for a time:
`{{ now | date: "%H:%M" }}`. Conditions such as `{% if chat.kind == "dialog" %}` work too.

The incoming message's text is never a template variable. An unknown variable or filter makes the
template invalid, and then no reply is sent. A template cannot read files, and its time, memory
and length are limited.

### Examples

An away message:

```liquid
Thanks, {{ sender.firstName | default: "there" }}! I'm away until Monday and will reply then.
```

A reply outside working hours. The hours belong to the rule, not to the template: set them with
`replies edit` and the options `--outside`, `--days` and `--timezone`. Then `now` is in that time zone:

```liquid
Hi {{ sender.firstName | default: "there" }}, it's {{ now | date: "%H:%M" }} here. I answer on weekdays from 9:00 to 19:00.
```

A part written by an AI agent, with your own text as a fallback:

```liquid
Thanks, {{ sender.firstName | default: "there" }}!
{% ai %}Briefly confirm you got the message; I will answer tomorrow.{% else %}I will answer tomorrow.{% endai %}
```

### A part written by an AI agent

Choose the AI agent used for auto-replies in your profile's AI settings. The [Telegram settings guide](./tg/replies.md#templates-and-a-model) and [MAX settings guide](./max/replies.md#шаблоны-liquid-и-модель) explain the configuration.

An AI agent may write only what is inside `{% ai %}…{% endai %}`; everything outside it is your text.
The block's body is an instruction to the agent. The incoming message goes to the agent separately,
as data, never as part of the instruction. The agent's answer is used as plain text.

The text after `{% else %}` is the fallback. It is sent when no agent is set up, when there is no
consent, when the call fails, or when the agent's answer is refused because it is empty, too long or
repeats the incoming message. Without an `else`, that message gets no reply and the reason is
recorded. Blocks cannot be nested.

Using an AI agent needs its own consent, separate from the right to send. Consent lets incoming message
data go to the AI provider you chose, for the whole profile:

```sh
tg replies consents show
tg replies consents grant
tg replies consents revoke
max replies consents show
max replies consents grant
max replies consents revoke
```

`replies consents deny` with a chat ID keeps that chat's messages away from the agent. A new provider
or endpoint needs consent again. `replies test --ai` sends saved messages to the agent so you can see
its text; it still sends nothing to the messenger.
