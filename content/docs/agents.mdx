Connect your AI agent to your messenger so it can find messages, gather context and prepare replies. This page explains which connection to choose, how to set it up and how to check the result. By the end, you can ask your agent for your first useful task.

## What is an agent, and how does it use the tool?

An **AI agent** is a program that can use tools to carry out your request. For example, it can find messages and turn them into a summary. You describe the task; the agent chooses the actions.

A **CLI** is a command-line tool: a program controlled with text commands. An agent with terminal access runs it on your computer or server, the same way you would in a terminal. A **skill** teaches the agent the commands, so you do not need to memorise them. Apps that cannot run programs have their own route at [the end of this page](#chat-apps-and-remote-agents).

## Choose where you want to use it

- **[I use ChatGPT, Claude or another AI chat in a browser or mobile app](./agents.mdx#use-from-web-or-mobile)** — Follow the browser/mobile connection guide.
- **[I use Codex, Claude Code, Cursor, Gemini CLI, Hermes or OpenClaw with terminal access](#connect-instructions)** — Connect the command-line tool below.
- **[My app cannot run commands, or my agent runs on another computer](#chat-apps-and-remote-agents)** — See the other routes, including an optional MCP connection.
- **[I want to check an existing connection](#check-connection)** — Run the account-and-chats check.
- **[I have not installed the tool or connected my account](./installation.mdx)** — Start with installation and login.

## Connect the instructions

The examples use `tg` for Telegram. For MAX, replace `tg` with `max` and the skill name `tg-cli` with `max-cli`. This applies to all examples and agent notes on this page.

### First setup

Run this once in the terminal on the computer where your agent works. Setup connects your account and adds the agent instructions:

```sh
tg personal setup --agent codex
```

Replace `codex` with `cursor`, `claude` or `gemini` for your agent. Without `--agent`, setup asks you to choose. For Hermes, OpenClaw or another agent, use `none` and follow the relevant note below.

<a id="agent-login" />

### When the agent runs the login

An agent has no terminal to draw a QR code in or to open a browser from, so each tool prints what you need as text, and the agent passes it to you in the chat. Replace `personal` with your profile name.

- **Telegram and MAX:** the agent runs `tg personal session start qr` or `max personal session start qr` in the background, because the command waits for your scan and a shell tool shows nothing until it ends. Without a terminal, the tool prints the QR code as text. The agent pastes it into the chat as a code block, exactly as printed, and you scan it with the Telegram or MAX app on your phone. When Telegram renews the code, the agent pastes the new one and says that the old one expired.
- **MAX codes expire fast:** a MAX QR code lasts about 2 minutes, so the agent pastes it at once. When it expires, the agent runs the command again for a new code.
- **Zoom:** without a terminal, `zm personal session start` prints `Open this URL to approve Zoom login:` and the URL. The agent gives you the URL as a link. Open it in a browser on the same computer, because Zoom returns to a listener there.
- **Google Drive:** `drive personal session start` always prints its Google sign-in URL, and also tries to open a browser. If no browser opens, the agent gives you the printed URL as a link to open on the same computer.
- **Google Calendar:** `gcal personal session start` always prints `Open Google sign-in:` and the URL, and also tries to open a browser. If no browser opens, the agent gives you the URL as a link to open on the same computer. It signs in through WireCat's Google app unless you give it your own client. See [Google Calendar settings](./gcal/configuration.md#your-own-google-client).

A phone-number login, a two-step verification password and the first registration of your Telegram app still need you at a terminal.

### Account already connected

`tg personal setup` with an agent chosen has already installed the skill. If your agent already sees `tg-cli`, you can skip this step. A global npm install of `tg`, `max` or `memo` adds the skill only when `TG_INSTALL_AGENT`, `MAX_INSTALL_AGENT` or `MEMO_INSTALL_AGENT` names an agent (`all`, `claude`, `codex`, `cursor` or `gemini`). The one-command Windows installer for `tg` and `max` adds it unless you pass `-Agent none`. `zm` and `drive` install a skill only when asked: run `zm skill install` or `drive skill install` after `npm install -g`. To add or update the instructions without repeating login:

```sh
tg skill install
```

The **skill** is an instruction file that teaches the agent how to use the tool. It does not contain your messenger login. Start a new agent conversation after installation.

Where each agent looks for the skill file:

- **Codex, Cursor Agent, Gemini CLI**: `~/.agents/skills/tg-cli/SKILL.md`; install only for them with `tg skill install --for agents`.
- **Claude Code**: `~/.claude/skills/tg-cli/SKILL.md`; install only for it with `tg skill install --for claude`.
- **Hermes**: `~/.hermes/skills/tg-cli/SKILL.md`; save the output of `tg skill show`, see [Hermes](#hermes).
- **OpenClaw**: `~/.agents/skills/tg-cli/SKILL.md`; `tg skill install --for agents`, see [OpenClaw](#openclaw).

`~` is your home folder, also on Windows. Without `--for`, `skill install` writes both the
`.agents` and the `.claude` copy. You can also get the skills from a skill directory, such as
ClawHub or skills.sh: [Where to get WireCat skills](./agents.mdx#where-to-get-wirecat-skills).

**After you update the tool, run `tg skill install` again**, so the instructions match the new
version. For Hermes, or any file you saved by hand, save it from `tg skill show` again. When the agent sets
`AI_AGENT` or `CLAUDECODE`, the tool reminds it at most once a day if its copy of the skill is
missing or older than the tool. The reminder goes to stderr, so JSON output stays usable.

## Check whether you are ready

```text prompt
Use tg CLI. Read its instructions with tg skill show, show the connected account and list five recent chats. Only read: do not send anything or mark messages as read.
```

The account and chats should match yours. You can then continue to [First tasks](./first-tasks.md).

### If it does not work

- **The agent cannot find `tg`.** Ask it to run `tg --version`. If that fails, the agent's
  terminal does not see the installed tool. Open a new terminal, or restart the agent or editor
  after installing Node.js and the tool. On Windows, see
  [what the installer changes](./installation.mdx#what-the-windows-installer-changes). More causes:
  [Telegram troubleshooting](./tg/troubleshooting.md) ·
  [MAX troubleshooting](./max/troubleshooting.md#max-не-находится-после-установки).
- **The agent reports "no session".** The tool runs, but it finds no login. Log in with
  `tg personal setup` in the same environment and profile the agent uses: the same computer user, the same
  profile name and the same folder variables such as `TG_CONFIG_DIR`, if you set them. Details: [Telegram](./tg/troubleshooting.md#no-session-for-profile-personal--run-tg-personal-setup-in-a-local-terminal) ·
  [MAX](./max/troubleshooting.md#no-session-for-profile-personal).

### Hermes

**Install the skill.** Hermes Agent reads skills from `~/.hermes/skills`. Ask Hermes to save the exact
output of `tg skill show` into `~/.hermes/skills/tg-cli/SKILL.md`, keeping the frontmatter and UTF-8
text. On macOS or Linux you can do it yourself:

```sh
mkdir -p ~/.hermes/skills/tg-cli
tg skill show > ~/.hermes/skills/tg-cli/SKILL.md
```

Hermes can also install the skill from this site; other sources are in
[Where to get WireCat skills](./agents.mdx#hermes-agent):

```sh
hermes skills install well-known:https://wirecat.dev/.well-known/skills/tg-cli
```

If Hermes stops at a caution from its security scan, don't force the install:
[report it](https://github.com/WireCatLabs/cli-docs/issues) with the finding. Then start a new session and try the check above. Hermes's terminal must have the tool and the
same account login.

**In one step:** `tg skill install --for hermes`. It puts the skill in `~/.agents/skills` and adds
that folder to `skills.external_dirs` in Hermes's settings; if that fails, it saves a copy in
`~/.hermes/skills` instead, and says which it did. Before you run it,
delete the copy you saved in `~/.hermes/skills/tg-cli`, or run `hermes skills uninstall tg-cli` if
you installed it from this site: Hermes prefers that folder, so an old copy would hide the new one.

**If Hermes cannot find `tg`.** Hermes runs commands with the environment of a login `bash`
(`bash -l`), saved when the session starts. That shell reads `~/.bash_profile` if you have one,
otherwise `~/.profile`. It does not read `~/.zshrc`. If you added npm's folder to `PATH` only in
`~/.zshrc`, copy that `export PATH=…` line to the file bash reads, start a new Hermes session and
ask it to run `tg --version`.

**If you talk to Hermes from a chat.** Its gateway lets you message Hermes from Telegram, Discord
and other chats. Anyone the gateway accepts can ask Hermes to run `tg` with your account: read your
chats or send as you. Keep its allowed-users list to yourself, and consider a profile that only
reads: see [Permissions](./configuration.mdx#permissions).
[Hermes skills guide](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills/).

### OpenClaw

**Install the skill.** With its default state folder, OpenClaw also reads `~/.agents/skills`, so
`tg skill install --for agents` is enough. If you moved that folder with `OPENCLAW_STATE_DIR`, ask
OpenClaw to save the exact output of `tg skill show` into `skills/tg-cli/SKILL.md` inside it. Check
that the skill is available to your agent and start a new session. The tool must be installed on
the computer or server where OpenClaw runs.

**If OpenClaw cannot find `tg`.** OpenClaw's background service starts with a short `PATH`, such as
`/usr/local/bin:/usr/bin:/bin` on Linux, and npm's global folder may be missing from it. Find that
folder with `npm prefix -g`; on macOS and Linux the programs are in its `bin` folder. Stop
OpenClaw's gateway, add the folder, then start the gateway again:

```sh
openclaw config set tools.exec.pathPrepend '["/home/you/.npm-global/bin"]' --strict-json
```

Replace the path with yours. The value replaces the whole list, so include any folders you already
set there.

**If you talk to OpenClaw from a chat.** Its channels connect OpenClaw to Telegram, WhatsApp,
Discord and other chats. Anyone a channel accepts can ask OpenClaw to run `tg` with your account:
read your chats or send as you. Accept only yourself in its pairing or allowlist settings, and
consider a profile that only reads: see [Permissions](./configuration.mdx#permissions).
[OpenClaw skills guide](https://docs.openclaw.ai/tools/skills).

## Where to get WireCat skills

A **skill** is an instruction file, `SKILL.md`, that teaches your AI agent the commands of one WireCat
tool. Each tool installs its own skill with `skill install` (see [Connect your AI agent](./agents.mdx#connect-instructions)).
This page lists the skill directories that offer the same skills, for when you prefer to install and
update skills the way your agent does. By the end, your agent has the skill it needs, from the
source you chose.

A skill only teaches. The tool itself must still be installed and logged in on the computer where
your agent runs: see [Installation](./installation.mdx).

## For chat apps and remote agents

Everything above runs the command-line tool directly. For an agent on the same computer, that is
the faster route, and you can run the same command yourself when something looks wrong. **MCP** is
an optional connection for apps that cannot run programs:

- **ChatGPT, Claude or another chat in a browser or phone app:** follow the
  [browser/mobile connection guide](./agents.mdx#use-from-web-or-mobile).
- **A desktop app with MCP settings, such as Claude Desktop:** follow [MCP setup](./agents.mdx#cursor-and-claude-desktop).
- **An agent on another computer:** install the tool and log in there, as described in
  [Another agent](#other-agents). If it can only reach your computer over a connection, use [MCP setup](./agents.mdx#mcp-and-skills).

Login is not an MCP tool: an agent that has only MCP asks you to run the login command yourself.

## MCP and skills

### What MCP is

**MCP (Model Context Protocol)** is an open standard for connecting AI apps to tools. It works like a
universal plug: an app that supports MCP can use a compatible MCP server without a custom integration. The
standard is published at [modelcontextprotocol.io](https://modelcontextprotocol.io/).

Two sides take part:

- The **client** is your AI app, for example Claude Desktop, ChatGPT, Cursor or Gemini CLI. It asks the
  server which tools exist and calls one when your request needs it.
- The **server** is `tg <profile> mcp serve` or `max <profile> mcp serve`, part of the command-line tool. It runs on your computer, or
  on a server that a browser chat reaches over a public HTTPS address.

Through MCP, the AI can use only the tools the server offers, and only within the profile's
[permissions](./configuration.mdx#permissions): a read-only profile cannot send. Connecting MCP does not log in to
your messenger for you; you log in once with the command-line tool. It does not download your whole
archive either.

An agent with a terminal, such as Claude Code or Codex, does not need MCP: it can run `tg` and `max`
commands directly, and a **skill** tells it how. An AI app without a terminal, such as Claude Desktop
or a browser chat, uses MCP. The [comparison below](#cli-skill-or-mcp) helps you choose.

<Callout type="info" title="Using an AI chat in the browser or on your phone?">

ChatGPT, Claude and other web chats connect through a public HTTPS address: follow the [browser and mobile setup guide](./agents.mdx#use-from-web-or-mobile).

</Callout>

### What the MCP server does

Our MCP server gives your agent access to the connected messenger: chats, messages, shared files, searches and reports. You ask for a result; the agent calls the server, which performs the action through the messenger tool.

The server is included in the command-line tool and **must be running while the agent uses it**. A local client can start it on your computer. For a browser or mobile chat, keep it running on a computer or server and connect through a public HTTPS address with authentication. Follow the [browser/mobile setup guide](./agents.mdx#use-from-web-or-mobile) for that connection.

### How the agent finds and runs actions

The server exposes a small set of tools instead of making you choose from hundreds of commands. First the agent finds an action and its arguments; then it runs that action. For example, to find an agreement it discovers message search, executes it and opens the matching messages.

Examples below use Telegram names. For MAX, replace `tg` with `max`, including tool and configuration names.

| Tool | What it does |
|---|---|
| `tg_tools_search` | Finds the command for a task and tells the agent its arguments and effects. This searches available actions, not your messages. |
| `tg_read` | Runs a discovered read action: list chats, search messages, read files or build a report. |
| `tg_write` | Runs a discovered change: send a message, save extracted text or manage a group, within the profile’s permissions. |

### What the skill does

A **skill** is an instruction file for your agent: which tools to use, how to gather context, check sources and prepare a result. MCP provides access to actions; the skill explains how to use them for a task. The skill contains guidance, not your account credentials.

We provide instructions with the installed tool. [Connect your agent](./agents.mdx) explains how to add them; `tg skill show` displays them. An agent with terminal access can use the instructions and run the CLI directly.

### CLI, skill or MCP?

| Connection | What it provides | Choose it when |
|---|---|---|
| CLI | Commands in a terminal, with JSON results | Your agent already has a local terminal |
| Skill + CLI | Instructions for using those commands and workflows | Your agent can run terminal commands, for example Codex, Cursor Agent, Claude Code, Gemini CLI, Hermes or OpenClaw |
| MCP | Named tools and their parameters directly inside your client | Your AI app has no terminal, for example Claude Desktop, or you prefer the client's tool interface |
| MCP over HTTP | The same tools for an AI chat in a browser, such as ChatGPT or Claude, behind your own tunnel | You chat in a browser — [ChatGPT and Claude in the browser](./agents.mdx#use-from-web-or-mobile) |
| Markdown docs | A readable explanation and command reference | You want the agent to look up how something works |

For an agent with a terminal, start with [a skill](./agents.mdx). MCP is optional and follows the
same profile permissions as the CLI. It does not log in for you or download the whole archive.

### Before connecting

[Install and log in](./installation.mdx). Run `tg personal mcp config` or `max personal mcp config`
to print a configuration with the actual Node and CLI paths on your machine. This command prints
settings; it does not edit your client. Desktop clients may have a different PATH from your terminal.

The server serves the profile you name: `tg personal mcp serve`. You can serve several profiles from one server
with `tg mcp serve --profiles personal,work`, or every profile with `--profiles all`; each tool call then says which
profile it is for. max works the same way. Without a profile or `--profiles`, neither starts the server. `tg mcp` or
`max mcp` on its own only shows help.

#### Codex

In a terminal where the installed command works:

```sh
tg personal mcp add codex
codex mcp list
```

Setup uses Codex's own command and leaves other servers intact. By hand, the equivalent is `codex mcp add tg -- tg personal mcp serve`.

Connect only the messengers you use. Codex stores MCP settings in `~/.codex/config.toml`.
For Windows or an IDE with a different PATH, take `command`, `args` and `env` from `mcp config`
and put them into `[mcp_servers.tg]` or `[mcp_servers.max]`; Codex uses TOML, not `mcpServers` JSON.
[Official Codex MCP guide](https://learn.chatgpt.com/docs/extend/mcp?surface=cli).

#### Claude Code

```sh
tg personal mcp add claude-code
claude mcp list
```

By hand, the equivalent is `claude mcp add --scope user tg -- tg personal mcp serve`. If the profile exposes write tools, setup asks you to check its [permissions](./configuration.mdx#permissions) first and then repeat with `--allow-writes`. That flag only confirms the installation; it does not change the permissions.

Use `/mcp` in a session to check status. For full paths, use the values from `mcp config`.
[Official Claude Code MCP guide](https://code.claude.com/docs/en/mcp).

#### Cursor and Claude Desktop

Copy the server entry printed by `tg personal mcp config` or `max personal mcp config` into the client's
`mcpServers` settings, preserving its full paths and environment. Merge it with existing servers.

| Client | Configuration file |
|---|---|
| Cursor, personal | `~/.cursor/mcp.json` |
| Cursor, project | `.cursor/mcp.json` |
| Claude Desktop, macOS | `~/Library/Application Support/Claude/claude_desktop_config.json` |
| Claude Desktop, Windows | `%APPDATA%\Claude\claude_desktop_config.json` |

Restart the client and check that the server's tools are available.
[Official Cursor MCP guide](https://cursor.com/help/customization/mcp).

#### Gemini CLI

```sh
gemini mcp add --scope user tg tg personal mcp serve
gemini mcp list
```

For full paths and environment variables, merge the generated entry into `mcpServers` in
`~/.gemini/settings.json`. [Official Gemini MCP guide](https://geminicli.com/docs/tools/mcp-server/).

#### Hermes

Hermes uses `mcp_servers` in `~/.hermes/config.yaml`. Add `tg` or `max` there with the `command`,
`args` and `env` values from the generated configuration, keeping existing settings. Hermes uses
YAML; do not paste the whole `mcpServers` JSON object into it. Restart Hermes to load the server.
[Official Hermes quickstart](https://hermes-agent.nousresearch.com/docs/getting-started/quickstart/).

### Zoom, Google Drive and Memo

Each tool starts its own server. Connect it with the command your client uses for MCP servers:

- **Zoom:** `zm personal mcp serve`.
- **Google Drive:** `drive personal --read-only mcp serve`.
- **Google Calendar:** `gcal personal mcp serve`.
- **Mail:** `mail personal mcp serve`.
- **Memo:** `memo mcp serve`.

### What the agent can do

MCP covers most everyday CLI operations: read and search chats, inspect people and groups, work with message attachments, prepare reports, send replies and manage groups when permitted.

For full command syntax and MCP-specific availability, use the messenger references:

- [Telegram MCP tools and coverage](./tg/mcp.md#tools) · [Telegram command reference](./tg/commands.md).
- [MAX MCP tools and coverage](./max/mcp.md#инструменты) · [MAX command reference](./max/commands.md).

The available catalogue is determined by the messenger and profile permissions. Ask the agent to discover an action through the search tool; its result provides the supported command and arguments. A read-only profile excludes changes. The server has no confirmation step of its own: approval prompts come from your app, and the server cannot check whether a person accepted them.

After connecting, ask for five recent chats. Continue with [First tasks](./first-tasks.md).

### Documentation for your agent

Try: **“Read https://wirecat.dev/llms.txt, find the Telegram inbox documentation and use it to
summarise my unread messages.”** If your agent cannot fetch URLs, copy the page's Markdown into the chat.

These Markdown pages can be read directly. Give the agent the index or the page it needs; no additional documentation server is required.

If a connection fails, check the full paths, the Node version, and that client and terminal use the
same profile and configuration directories. Each [Telegram](./tg/mcp.md) / [MAX](./max/mcp.md)
MCP reference explains the environment and troubleshooting.

## Use from web or mobile

Use Telegram and MAX from an AI chat in your browser or mobile app: find messages, gather context and prepare replies. Setup takes a few commands and adding an address in your chat settings. You do not need to install the ChatGPT or Claude desktop apps. The app must support remote MCP over HTTP and OAuth sign-in compatible with this server; choose your app below.

This guide connects your chosen messenger and checks it with a request for your own chats. A program on your computer talks to the messenger; your AI chat reaches that program <DocTerm term="public-address" lang="en" label="through a public address" />. <DocTerm term="mcp" lang="en" label="MCP" /> is the way these tools connect to an agent. Below, we will obtain the address and add it to the app. Keep the computer, the CLI’s MCP server and the HTTPS tunnel running while you use the connection. The messenger’s desktop app is not required.

### Before starting

- Install the [command-line tool for Telegram or MAX](./installation.mdx) and sign into your account. A local agent is unnecessary for browser use: `tg personal setup --agent none` or `max personal setup --agent none`.
- Use the computer running the tool for initial setup, and keep it awake while connected. The end of this page explains an always-on server option.
- Your AI chat account needs an option for adding a custom connection. If it is missing in a work account, check with your administrator. The [OpenAI instructions](https://developers.openai.com/plugins/quickstart) and [Claude instructions](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp) show current options.

We will install the additional program for the public address in the next step, with instructions for what to click.

### 1. Prepare a public address

We use **Tailscale**, a program that makes the connection on your computer reachable over the internet. You do not need it on the phone or other device where you open your chat.

In WireCat Desktop, the Start dialog of a tool's MCP server does this step for you: [Set up Tailscale Funnel for WireCat MCP](./desktop/tailscale-funnel.mdx).

#### Install Tailscale and sign in

1. Open the [download page](https://tailscale.com/download) and choose Windows, macOS or Linux.
2. On Windows or macOS, download and run the installer, then open the app. Select the Tailscale icon near the Windows clock or in the macOS menu bar, then **Log in**. For Linux, follow the [installation and login instructions](https://tailscale.com/download/linux).
3. Sign in or create a Tailscale account in the browser that opens, and approve connecting your computer. It should appear in the [device list](https://console.tailscale.com/admin/machines).

#### Enable the secure address

1. Open the [DNS page in the Tailscale console](https://console.tailscale.com/admin/dns).
2. Under **MagicDNS**, select **Enable MagicDNS** if disabled. This gives the computer a name for its address.
3. Under **HTTPS Certificates**, select **Enable HTTPS** and accept the displayed notice. This enables secure addresses; see the [Tailscale instructions](https://tailscale.com/docs/how-to/set-up-https-certificates).
4. The first command in the next step may show an approval link for **Funnel**, the public-access feature. Open it, sign into the same account and approve enabling it. Tailscale prepares the certificate and permission automatically. If access is refused, an administrator can use **Access controls → Funnel → Add Funnel to policy**: [Funnel instructions](https://tailscale.com/docs/features/tailscale-funnel).

<a id="start-the-tunnel-and-messenger-server" />

### 2. Get the address and start the connection

Choose your operating system and <DocTerm term="terminal" lang="en" label="open two terminal windows" />. **Paste the first block into window 1**: it prints an address such as `https://computer.network.ts.net`. If it first shows an approval link, complete item 4 above and return here.

**Paste the second block into window 2** and supply the printed HTTPS address when asked, without `/mcp`. Keep `:8443` if the address contains it. Leave both windows open. The profile's permissions decide what the agent may do; [choosing permissions](#choose-what-the-assistant-may-do) is explained below.

### Choose what the agent may do

The server can do what the profile's saved permissions allow. To narrow them for this running server only, add
`--permission messages.send=deny` or `--permission messages=readonly` to the startup command; the flag only
tightens, and an override that would loosen the profile is refused at startup. To allow sending, change the profile's
permissions. The app controls its own approval prompts. Over MCP, `ask` does not force a server confirmation. For a
connection that only reads, use a read-only profile.

The app's approval settings and the server's permission checks are separate controls. If you always allow a tool in the
app and the server permits it, another call can send without asking again. Ask for a draft when
you want to review the text first. Recipient restrictions and hourly limits still apply.
See [permissions](./configuration.mdx#permissions) for examples and how to change access.

<a id="connection-recovery" />

### It worked before, but stopped

A browser connection needs the computer running the command-line tool, its MCP server and the HTTPS tunnel. After sleep or a restart, use this order:

1. Wake the computer and check the account in a terminal with `tg personal account show` or `max personal account show`. Use `tg.cmd` or `max.cmd` in PowerShell. If this fails, follow the login guide for [Telegram](./tg/sessions.md) or [MAX](./max/sessions.md).
2. Restart the tunnel and server using the two windows above. Use the same profile and check that the HTTPS address still matches the connector. If it changed, update the server's public URL and the connector URL.
3. Retry the five-chat request. If the app asks you to connect again, use the new one-time code printed by the running server.

Success means the agent lists the expected account’s chats. If it still fails, the checks below help distinguish a local account problem from a tunnel or app problem. Files need one additional step: a path on this computer does not give a browser agent the file. See file transfer for [Telegram](./tg/remote.md) or [MAX](./max/remote.md).

### Run both messengers

Use separate local ports and public HTTPS endpoints. For example: Telegram on local `8765`
and public `443`; MAX on local `8766` and public `8443`. For the second tunnel, use your OS's
Tailscale invocation with `funnel --https=8443 8766`, and add `--port 8766` to MAX.
Copy its printed HTTPS origin including `:8443` into MAX's startup command and append `/mcp`
for its connector. Funnel's permitted public ports are `443`, `8443` and `10000`
([reference](https://tailscale.com/docs/reference/tailscale-cli/funnel)).

### Stop, restart or revoke

- **Stop:** Ctrl-C in both foreground windows stops that server and tunnel.
- **In the background:** `tg personal mcp server start --public-url "$mcpPublicUrl"` runs the same server
  without a window. `tg personal mcp server status` shows it and its login code; `tg personal mcp server stop` stops it.
- **Restart:** repeat the commands with the same profile and public URL. Browser logins survive
  ordinary restarts; they expire after 30 days without renewal.
- **Background Funnel:** if you used `--bg`, Ctrl-C does not disable it. Check
  `tailscale funnel status`, then disable only that route with `tailscale funnel --https=443 off`
  (or `8443` for the second server). Use your OS's executable path and elevation above.
  Avoid `funnel reset` if you have another route: it clears them all.
- **Revoke app access:** run `tg personal mcp revoke` or `max personal mcp revoke`; use `tg.cmd` / `max.cmd`
  in PowerShell. Apps must log in again. Your messenger account stays logged in.

### Troubleshooting

- **No connection:** append `/.well-known/oauth-protected-resource/mcp` to the origin and open
  it in a browser. You should see JSON. Otherwise check Funnel, its approval and the local port.
- **Reads work, sending fails after app approval:** check the startup permissions and the
  effective permission. Use `deny` or `readonly` to refuse server-side changes; check the app's own approval settings.
- **PowerShell refuses scripts:** use `tg.cmd` or `max.cmd`. If the command is missing, reopen
  PowerShell and check the CLI installation; do not change machine-wide execution policy.
- **No tools:** `tg personal mcp check` or `max personal mcp check` checks the local handshake, not the tunnel or
  messenger login. An explicit `account show` command checks that account connection.
- **Port occupied:** use another local port and point Funnel at the same number. For simultaneous
  servers, also give each route a distinct public HTTPS port as above.

### Connect without keeping your laptop awake

You can install `tg` or `max` on a separate server that stays running, and connect your AI chat to its address. You can then use your messenger from the chat while your laptop is off.

Install the tool on the server, sign into the chosen account, start its MCP connection and provide a public HTTPS address. Configure automatic startup after a reboot: both the CLI’s MCP server and its HTTPS tunnel must remain running. The server needs its own account login; your laptop installation does not connect it automatically.

Try this after the connection works on your computer. See remote setup for [Telegram](./tg/remote.md) and [MAX](./max/remote.md). Repeat the five-chat request after setup: if it works with your laptop off, the server is providing the connection.

<details>
<summary>Linux server: keep the connection running after logout and reboot</summary>

1. Use one ordinary Linux user for installation, messenger login and the service. Install Node.js, the CLI and Tailscale, then log into the messenger as that user. First verify the five-chat request using the foreground commands above.
2. Run `tg personal mcp config` or `max personal mcp config`. Take the absolute Node path from `command` and the CLI entry path from `args`; keep the profile name before `mcp`, because the server serves only the profile it names. Do not put account passwords or bot tokens in the service file.
3. Create `~/.config/systemd/user/wirecat-mcp.service`. Replace the two paths and public address in this template with the actual values. Use the same configuration/state directories as your successful login:

```ini
[Unit]
Description=WireCat messenger connection

[Service]
Type=simple
WorkingDirectory=%h
ExecStart=/absolute/path/to/node /absolute/path/to/cli-entry.js personal mcp serve --http --port 8765 --public-url https://server.tailnet.ts.net
Restart=on-failure
RestartSec=10

[Install]
WantedBy=default.target
```

4. Enable the service with the commands below. An administrator must also enable lingering for that user, for example `loginctl enable-linger wirecat`, so user services can run without an active login. See [systemd services](https://www.freedesktop.org/software/systemd/man/latest/systemd.service.html) and [lingering](https://www.freedesktop.org/software/systemd/man/latest/loginctl.html).

```sh
systemctl --user daemon-reload
systemctl --user enable --now wirecat-mcp.service
systemctl --user status wirecat-mcp.service
```

5. On the server, start the public address in the background with `tailscale funnel --bg 8765`, using the elevation required by your installation. The [Funnel reference](https://tailscale.com/docs/reference/tailscale-cli/funnel#effects-of-rebooting-and-restarting) explains how it resumes after reboot. Its port must match the MCP service.
6. Check that the service can access the same login and unlocked keyring. A running HTTP endpoint does not prove the messenger account is accessible. If login fails after reboot, restore the user’s keyring access; do not solve it by copying credentials into the unit.
7. Close the SSH session, turn your laptop off and retry the chat request from the app. Repeat after a server reboot. Both the account access and the public address should work without a manual terminal launch.

To stop or disable automatic startup:

```sh
systemctl --user stop wirecat-mcp.service
systemctl --user disable wirecat-mcp.service
```

`journalctl --user -u wirecat-mcp.service -n 30` helps diagnose startup. It can include the one-time app connection code; use that code for your own sign-in and do not publish the full log. Other server platforms use their own service manager with the same account/path checks.

</details>
