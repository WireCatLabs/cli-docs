Эта инструкция объясняет, как WireCat работает с заметками и файлами: агент может искать
в папках текстовых файлов и документов, использовать заметки Obsidian и сохранять ваши
заметки о людях или сообщениях. Она пригодится, когда нужно найти сведения в файлах
или сохранить контекст на будущее.

После чтения вы сможете:

- импортировать папки и искать в файлах с указанием источников;
- создавать, изменять и экспортировать заметки о человеке или сообщении;
- помечать заметки, сообщения и контакты тегами.

Для этих задач WireCat использует Memo. Memo — инструмент на вашем компьютере для импорта
и поиска файлов и ведения заметок, связанных с их предметом. Агент может выполнять его команды за вас.

Для почты есть отдельная инструкция: [подключение и работа с почтой](./email.mdx).
Она использует ту же установку Memo.

## Перед началом

Используйте <DocTerm term="local-agent" lang="ru" label="локального ИИ-агента" /> на компьютере,
где хранятся файлы. Можно начать с одной папки заметок. Почта и история мессенджеров
необязательны; для сообщений [подключите Telegram или MAX](./installation.mdx) и скачайте
нужную историю. Memo читает эту локальную историю, но сам её не скачивает.

Помоги установить Memo на этот компьютер командой npm install -g @leemour/cli-memo.

## Добавьте заметки

### Выберите папку

Папка — это каталог на компьютере, в котором лежат файлы. Memo читает выбранную папку
**и её подпапки**: это может быть обычная папка проекта, папка заметок или хранилище Obsidian.
Можно подключить несколько папок.

<DocTerm term="vault" lang="ru" label="Хранилище Obsidian (vault)" /> — обычная папка заметок,
которую Obsidian открывает как одно рабочее пространство. Заметки в ней — файлы
<DocTerm term="markdown" lang="ru" label="Markdown" />; Memo читает их напрямую, и держать
Obsidian открытым не нужно. Для работы с Memo пользоваться Obsidian необязательно.

### Какие файлы читает Memo

| Файлы | Распространённые расширения | Что ожидать |
| --- | --- | --- |
| Текст и заметки Markdown | `.txt`, `.md`, `.markdown` | Читаемый текст, включая заметки Obsidian. |
| Таблицы | `.csv`, `.tsv`, `.xlsx`, `.ods` | Текст и значения ячеек, с указанием места в источнике, где доступно. |
| Документы, презентации и книги | `.odt`, `.pptx`, `.epub` | Извлечённый читаемый текст, без исходного оформления. |
| PDF и документы Word | `.pdf`, `.docx` | Нужны дополнительные средства чтения: `unpdf` для PDF и `mammoth` для DOCX. |

Сканированный PDF содержит изображения страниц: перед импортом нужно распознать текст.
Старые `.doc` и `.xls` не поддерживаются; преобразуйте их в поддерживаемый формат.
Импорт сообщает о нечитаемых файлах и недостающих средствах чтения, а не считает их проверенными.

### Импортируйте выбранную папку

Замените `/path/to/notes` полным путём к **существующей папке** на компьютере.
Для обычной папки выберите формат Markdown:

```sh
memo folders add /path/to/notes --format markdown
memo notes import --no-embed
```

Для хранилища Obsidian замените `/path/to/vault` путём к его папке и выберите формат Obsidian:

```sh
memo folders add /path/to/vault --format obsidian
memo notes import --no-embed
```

Формат определяет, как Memo понимает ссылки и теги заметок. Markdown использует ссылки
вроде `[label](other-note.md)`; Obsidian также понимает `[[Note]]`. Если не указать `--format`,
используется Obsidian.

Регистрация выводит ID папки. Импорт копирует читаемое содержимое в локальное хранилище,
не меняя исходные файлы. Скрытые папки, например `.obsidian`, пропускаются.
`--no-embed` оставляет для первого импорта поиск по словам: для начала модель поиска не нужна.
Повторяйте `memo notes import --no-embed` после изменения или добавления файлов.

### Найдите сведения в файлах

Скажите агенту, какую тему нужно найти:

```text prompt
Используй Memo, чтобы найти заметки и файлы о бюджете в импортированных папках.
Покажи совпавший текст и исходный файл для каждого полезного результата. Скажи, какие файлы не удалось прочитать.
```

Для поиска вручную:

```sh
memo search notes 'budget' --json
```

В результатах указаны найденный файл, ссылка на источник и первая совпавшая строка.
Откройте файл, чтобы проверить сведения. Если ничего не найдено, попробуйте слово, которое
точно есть в одном из файлов, и изучите отчёт импорта: неимпортированный файл не попадёт в поиск.

## Создавайте свои заметки

Заметки попадают в Memo двумя способами. **Импортированные заметки** берутся из файлов:
измените исходный файл и повторите импорт. **Свои заметки** вы создаёте в локальном хранилище
Memo: о человеке, сообщении, проекте, задаче или другой заметке. Создание заметки ничего
не отправляет контакту и не меняет сообщение, к которому она относится.

Попросите агента добавить заметку о выбранном человеке или сообщении:

```text prompt
Сохрани в Memo заметку, что Rin Example предпочитает утренние встречи, и свяжи её с этим человеком.
Покажи сохранённую заметку и ссылку на неё, чтобы я мог проверить результат.
```

Для работы вручную замените имя и текст своими:

```sh
memo notes add 'Prefers morning meetings' --about telegram:'Rin Example' --json
memo notes list --about telegram:'Rin Example' --json
```

Для заметки о сообщении скопируйте полную ссылку на источник из поиска или контекста.
Числа ниже приведены для примера; замените всю ссылку `msg:telegram/1/77/42` своей:

```sh
memo notes add 'Check the revised budget' --about 'msg:telegram/1/77/42' --json
```

У заметки может быть несколько предметов: повторите `--about` для каждого.
Для другой учётной записи используйте `max:<name or id>` или `email:<address>`.
Сохранённый объект можно указать ссылкой `person:`, `entity:`, `task:` или `note:`.
Он должен существовать в хранилище; совпадение имён само по себе не связывает два аккаунта.

### Прочитайте, измените или удалите заметку

Создание возвращает ID заметки. Замените им `NOTE_ID`; поле `revision` содержит её текущую
редакцию. Прочитайте это значение перед изменением и замените им `1` ниже:

```sh
memo notes show note:NOTE_ID --json
memo notes edit NOTE_ID --revision 1 --text 'Prefers early morning meetings'
```

Проверка редакции не даёт затереть более новое изменение. Если редакция изменилась,
сначала перечитайте заметку. Если созданная вами заметка больше не нужна, её можно удалить:

```sh
memo notes remove NOTE_ID
```

### Экспортируйте заметки в файлы

Экспорт записывает созданные в Memo заметки в выбранную папку:

```sh
memo notes export --to /path/to/exported-notes --format markdown
```

Для Obsidian используйте `--format obsidian`. Файлы экспорта содержат метаданные `memo-id`
и `memo-hash`: при импорте этой папки дубликаты заметок не создаются. Если вы сами изменили
экспортированный файл, экспорт оставит его как есть и сообщит о конфликте.

## Помечайте источники тегами

Тег — короткая метка, которую вы выбираете, например `work` или `follow-up`. Она помогает
находить связанные источники, не переписывая их. Попросите агента пометить выбранные
заметки, сообщения или контакты и показать сохранённые метки.

Используйте ID и ссылки из своих результатов поиска. `NOTE_ID`, `PERSON_UID` и `FOLDER_ID`
ниже — обозначения для замены; числовые ID сообщения, контакта и аккаунта приведены для примера.

| Что пометить | Команда |
| --- | --- |
| Заметку | `memo tags add work --note note:NOTE_ID` |
| Сохранённое сообщение | `memo tags add follow-up --message 'msg:telegram/1/77/42'` |
| Контакт, выбранный через аккаунт | `memo tags add work --contact 101 --provider telegram --account 1` |
| Человека со связанными аккаунтами | `memo tags add work --person PERSON_UID` |
| Заметки в подпапке | `memo tags add project --folder FOLDER_ID --path Projects` |

**Контакт** — учётная запись человека у провайдера; аккаунт выбирает локальные данные, в которых его нужно найти.
**Человек** объединяет явно связанные вами учётные записи. Его идентификатор (UID) находится
в поле `messages.person.uid` ответа `memo context ... --json`; см. [связь аккаунтов](./people.md#link-your-accounts).
Полная ссылка на сообщение включает провайдера, аккаунт, чат и сообщение: такой же числовой
ID в другом аккаунте не выбирает тот же источник.

Теги содержат 1–32 буквы a–z, цифры или дефисы; регистр не учитывается. Метки хранятся
локально и не меняют исходные файлы, флаги почты или ярлыки Gmail. Метки файлов также
импортируются: Obsidian понимает встроенные `#tags` и поле `tags:`, формат Markdown — `tags:`.
В обычном Markdown слово вида `#word` само по себе не становится тегом.

### Найдите и удалите метки

```sh
memo search notes 'budget' --tag work --json
memo search all 'tag:follow-up' --json
memo tags list --tag work --json
memo tags remove work --note note:NOTE_ID
```

Первый запрос ищет заметки с тегом; второй — сообщения, почту и заметки вместе.
Проверьте тип источника и аккаунт в результате. Удаление метки оставляет источник на месте.
Добавление существующей метки или удаление отсутствующей не создаёт повторного изменения.

## Попросите нужный контекст

Импортированная файловая заметка может относиться к человеку, а не просто упоминать его имя.
Укажите связь явно:

```sh
memo note telegram:"Rin Example" /path/to/notes/people/Rin.md
memo notes about telegram:"Rin Example" --json
memo context telegram:"Rin Example" --json
```

Файл уже должен быть импортирован. Имя в обычном тексте не создаёт связь.
`notes about` показывает связанные заметки; `context` также собирает сохранённые сообщения
и почту связанных аккаунтов. См. [связь аккаунтов](./people.md#link-your-accounts) и [Почта](./email.mdx).

## Добавьте почту

Аккаунты почты, импорт писем и связь адреса с человеком описаны в инструкции [Почта](./email.mdx).

## Проверьте результат

У сохранённой заметки должны быть ID, текст и связи с выбранными предметами. В списке тегов
должен быть указан нужный файл, сообщение, контакт или человек. Для импортированных файлов
откройте оригинал и проверьте текст. Если источник не импортирован или связь с человеком
не разрешена, попросите агента объяснить пробел, а не считать результат полным.

## Если чего-то не хватает

Если заметка или тег отсутствует, проверьте точный ID и аккаунт. Для файловых заметок изучите отчёт импорта и повторите импорт после изменений. При конфликте редактирования сначала прочитайте текущую редакцию.

Перейдите к инструкции [Почта](./email.mdx), чтобы импортировать письма и связать адреса с
контактами, или к [работе с людьми](./people.md#link-your-accounts), чтобы связать аккаунты
разных мессенджеров. Точные параметры смотрите в `memo --help` или `--help` подкоманды.
